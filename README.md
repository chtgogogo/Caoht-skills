# Caoht Skills · AI Agent 技能工具箱

一套在真实项目里磨出来的 AI Skill 集合，可跨多种 Agent 框架复用。作者曹灏天（CaoHT）。

每一份 skill 都来自一次具体的踩坑或迭代，不是抄来的提示词。详解页按手册规格写：解决什么故障、每个机制为什么这么设计、和同类方案比强在哪、什么情况下不该用。

## 和提示词收藏夹有什么不一样

| 提示词收藏夹 | 这套 Skill |
|---|---|
| 一堆零散提示词，凑巧才好用 | 有触发词、边界、失败降级的完整规则包 |
| 换个工具就失效 | 与 Agent 框架解耦，只描述规则、流程、边界 |
| 无版本，多份副本互相漂移 | 版本化升级 + 单一事实源，改动可校验 |
| 全靠上下文硬塞 | 索引和常驻卡只放轻量信息，细节按需加载，省 token |

## 快速使用

### 安装，三步，跟具体 Agent 无关

skill 本体就是「规则 + 流程 + 边界」的纯文档（核心是每个文件夹里的 `SKILL.md`），不绑定任何框架。只要你的 Agent 支持 skills 自动发现，就能用。**本仓库里每个 skill 文件夹就是可直接安装的本体**，clone 下来即得。

1. **找到你所用 Agent 的 skills 目录。** 查它的官方文档，或者最直接的办法，问它一句：「你的 skills 目录在哪？」
2. **把整个 skill 文件夹复制进去。** 保留文件夹结构，`SKILL.md` 必须在里面。
3. **重启或新开会话**，说一句该 skill 的触发词，验证是否生效。

几个常见宿主的目录位置，仅作示例，一律以各自官方文档为准：

| 宿主 | skills 目录常见位置 |
|---|---|
| ZCode | `C:\Users\<你>\.zcode\skills\` |
| Claude Code | `~/.claude/skills/` |
| Codex CLI | `~/.codex/skills/` |
| WorkBuddy | `~/.workbuddy/skills/` |
| 通用项目级 | `<项目>/skills/`（若该 Agent 支持项目级加载） |

你的 Agent 不在表里也没关系。只要它有「skills 目录加读取 SKILL.md」这套机制就通用。实在没有，`SKILL.md` 也能当提示词模板直接贴给任何 AI 用。

### 先装哪三个

建议先装基础设施三件套。它们负责回答 Agent 最基础的三个问题：什么时候该调谁（技能调度）、写代码守什么规矩（编码行为准则）、记住了什么该怎么存（记忆纪律）。其余按需选装。

## 命名规则与版本口径

- **A-Cao-** 前缀是基础设施级 skill（调度 / 纪律件 / 记忆），各宿主常驻加载。
- **Cao-** 前缀是应用级 skill（流水线 / 治理 / 检索 / 对策库），按任务触发加载。
- **CHT-** 前缀是作者**私人专用** skill，不入本公开仓库。
- 两个前缀可叠加（`A-Cao-` = 既常驻又自创）。历史上出现过无前缀重复副本造成漂移，已于 2026-09-07 清理。
- skill 的调用键以 `SKILL.md` frontmatter 里的 `name` 字段为准（文件夹名是给人看的中文说明书名）。版本号以 frontmatter 的 `version` 为唯一权威。
- 仓库级体检跑 `py library_check.py`，检查 README 与 docs 覆盖、name 冲突、重复副本、frontmatter 缺字段。

## 新增或修改 skill

任何 Agent 或人向本仓库提交新 skill 之前，必须先读 [CONTRIBUTING.md](CONTRIBUTING.md)。里面规定了文件夹命名、frontmatter 字段、README 收录行格式、docs 详解页模板（含返回目录的双向跳转链接）和提交前自检项。

仓库根目录的 `AGENTS.md` 会让 Agent 进入本仓库时自动加载这条要求。

**权威库与发布源的关系**：本机 `D:\Deepseek-ALL\skills\` 是运行时权威库（单一事实源）；本仓库是**对外发布源**。改 skill 的固定顺序，先改权威库 → 同步复制到本仓库 → 体检 → push。两处版本号必须一致。

## 仓库结构

```text
Caoht-skills/
├── README.md             # 总目录（索引表 → docs/ 详解页）
├── CONTRIBUTING.md       # 新增 / 修改 skill 必读规范
├── CHANGELOG.md          # 迭代留痕（每版：优化了什么 / 新增了什么 / 解决了什么）
├── AGENTS.md             # Agent 进入本仓库自动加载的工作规范
├── library_check.py      # 仓库级体检脚本（提交前必跑）
├── <skill 文件夹>/        # 13 个 skill 本体（SKILL.md + references/ + scripts/）
├── docs/                 # 每个 skill 一篇详解页
├── LICENSE
├── .gitignore
└── 抖音聊天记录导出/        # 私有工具（已 gitignore，不入库）
```

> **2026-09-25 变更**：skill 本体回归本仓库。此前一度全部收归本机权威库、仓库仅存详解页，但公开访客 clone 后无本体可装，经作者拍板恢复「仓库即发布源」形态。权威库仍是本机运行事实源，两处同步关系见上节。

每个 skill 文件夹的结构：

```text
<skill-name>/
├── SKILL.md          # Agent 读取的核心指令
├── references/       # 可选：模板、原理、扩展资料
└── scripts/          # 可选：可执行脚本
```

## 设计原则

**可跨 Agent 复用。** 不绑定单一工具，只描述规则、流程、边界。

**渐进式披露。** 索引和常驻卡只保留轻量信息，细节按需加载。

**证据优先。** 没有验证过就不宣称完成。重要结论要可追溯，也要允许被推翻。

**边界清晰。** 每份 skill 都写明什么时候触发、什么时候不触发、失败怎么降级。

**可维护。** 每次升级保留版本号，避免多份副本漂移。
