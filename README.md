## 为什么这套 skill 不一样

1. **实战出身，不是一次性提示词**：多Agent治理来自真实跑通的天倾游戏项目（决策收敛到 D-01~D-20）；贴身导师来自 2026-07 起的真实学习陪跑；记忆纪律在多个宿主的记忆库里实跑迭代到 v3.2。
2. **渐进披露，token 成本可控**：索引常驻、细节按需加载——所有 skill 都遵守"轻的东西每次读，重的东西命中才读"。
3. **单一事实源，多宿主不漂移**：规则共享一份，各 Agent 的数据（记忆/日志）各自独立；基础设施类 skill 改动要求多副本 sha256 逐字同步。
4. **有生命周期，不是只增不改的日志堆**：决策可撤销、记忆会衰减、结论可修订且留痕。
5. **教训回写机制**：踩过的坑直接改 skill 本身——贴身导师的"存放位置必问"就是一次真实事故的产物。

## 快速使用（任意 Agent 通用）

### 安装：三步，跟具体 Agent 无关

skill 本体是"**规则 + 流程 + 边界**"的纯文档（核心是每个文件夹里的 `SKILL.md`），不绑定任何框架——只要你的 Agent 支持 skills 自动发现机制，就能用。

1. **找到你所用 Agent 的 skills 目录**：查它的官方文档；或者最直接的——直接问它："你的 skills 目录在哪？"
2. **把整个 skill 文件夹复制进去**（保留文件夹结构，SKILL.md 必须在里面）
3. **重启 / 新开会话**，说一句该 skill 的触发词验证生效

常见宿主的目录位置举例（**仅是示例，一律以各自官方文档为准**）：

| 宿主 | skills 目录常见位置 |
|---|---|
| ZCode | `C:\Users\<你>\.zcode\skills\` |
| Claude Code | `~/.claude/skills/` |
| Codex CLI | `~/.codex/skills/` |
| WorkBuddy | `~/.workbuddy/skills/` |
| 通用项目级 | `<项目>/skills/`（若该 Agent 支持项目级加载） |

> 你的 Agent 不在表里？没关系——只要它有"skills 目录 + 读取 SKILL.md"的机制就通用；实在没有，SKILL.md 也可以当提示词模板直接贴给任何 AI 用。

### 先装哪三个

建议优先安装"基础设施三件套"，它们保证 Agent 知道：**什么时候调谁**（技能调度）、**写代码守什么规矩**（编码行为准则）、**记忆怎么留存**（记忆纪律）。其余按需选装。

## 命名规则与版本口径

- **A-Cao-** 前缀：基础设施级 skill（调度/行为准则/记忆纪律），各宿主常驻加载，任一副本改动需整体同步。
- **Cao-** 前缀：应用级 skill（教学/治理/导出/检索），按任务触发加载。
- 无前缀 skill 目录不应存在；历史上出现过无前缀重复副本造成漂移风险，已于 2026-09-07 清理。
- skill 调用键以 SKILL.md frontmatter 的 `name` 字段为准（文件夹名是中文说明书名）；版本号以 frontmatter `version` 为唯一权威。
- 仓库级体检：`py library_check.py`（查 README/docs 覆盖、name 冲突、重复副本、frontmatter 缺字段）。

## 向本仓库新增 / 修改 skill

**任何 Agent 或人**向本仓库提交新 skill 前必须读 [CONTRIBUTING.md](CONTRIBUTING.md)——其中规定了文件夹命名、frontmatter 字段、README 收录行格式（卖点句式）、docs/ 详解页模板（含返回目录的双向跳转链接）与提交前自检。仓库根的 `AGENTS.md` 会让 Agent 在进入本仓库时自动加载这条要求。

## 仓库结构

```text
Caoht-skills/
├── README.md             # 你正在看的总目录（含卖点索引表与跳转锚点）
├── CONTRIBUTING.md       # 新增/修改 skill 必读规范
├── AGENTS.md             # Agent 进入本仓库自动加载的工作规范
├── library_check.py      # 仓库级体检脚本（提交前必跑）
├── docs/                 # 每个 skill 一篇详解页（痛点/优势/对比/上手/战绩/边界，双向跳转）
├── LICENSE
├── .gitignore
└── <skill-name>/
    ├── SKILL.md          # Agent 读取的核心指令
    ├── references/       # 可选：模板、原理、扩展资料
    └── scripts/          # 可选：可执行脚本
```

## 设计原则

1. **可跨 Agent 复用**：不绑定单一工具，只描述"规则 + 流程 + 边界"。
2. **渐进式披露**：索引/常驻卡只保留轻量信息，细节按需加载，省 token。
3. **证据优先**：没有验证前不宣称完成；重要结论可追溯、可推翻。
4. **边界清晰**：每个 skill 都写明"什么时候触发、什么时候不触发、失败怎么降级"。
5. **可维护**：每次升级保留版本号，避免多份副本漂移。
