## 和提示词收藏夹有什么不一样

| 提示词收藏夹 | 这套 Skill |
|---|---|
| 一堆零散提示词，凑巧才好用 | 有触发词、边界、失败降级的完整规则包 |
| 换个工具就失效 | 与 Agent 框架解耦，只描述规则、流程、边界 |
| 无版本，多份副本互相漂移 | 版本化升级 + 单一事实源，改动可校验 |
| 全靠上下文硬塞 | 索引和常驻卡只放轻量信息，细节按需加载，省 token |

## 快速使用

### 安装，三步，跟具体 Agent 无关

skill 本体就是"规则 + 流程 + 边界"的纯文档（核心是每个文件夹里的 `SKILL.md`），不绑定任何框架。只要你的 Agent 支持 skills 自动发现，就能用。

1. **找到你所用 Agent 的 skills 目录。** 查它的官方文档，或者最直接的办法，问它一句："你的 skills 目录在哪？"
2. **把整个 skill 文件夹复制进去。** 保留文件夹结构，`SKILL.md` 必须在里面。
3. **重启或新开会话**，说一句该 skill 的触发词，验证是否生效。

几个常见宿主的目录位置，仅作示例，一律以各自官方文档为准：

| 宿主 | skills 目录常见位置 |
|---|---|
| ZCode | `C:\Users\<你>\.zcode\skills\` |
| Claude Code | `~/.claude/skills/` |
| Codex CLI | `~/.codex/skills/` |
| WorkBuddy | `~/.workbuddy/skills/` |
| 通用项目级 | `<项目>/skills/`（若该 Agent 支持项目级加载） |

你的 Agent 不在表里也没关系。只要它有"skills 目录加读取 SKILL.md"这套机制就通用。实在没有，`SKILL.md` 也能当提示词模板直接贴给任何 AI 用。

### 先装哪三个

建议先装基础设施三件套。它们负责回答 Agent 最基础的三个问题：什么时候该调谁（技能调度）、写代码守什么规矩（编码行为准则）、记住了什么该怎么存（记忆纪律）。其余按需选装。

## 命名规则与版本口径

- **A-Cao-** 前缀是基础设施级 skill（调度 / 行为准则 / 记忆纪律），各宿主常驻加载。任一副本改动，需要整体同步。
- **Cao-** 前缀是应用级 skill（教学 / 治理 / 导出 / 检索），按任务触发加载。
- 不应该存在无前缀的 skill 目录。历史上出现过无前缀重复副本造成漂移，已于 2026-09-07 清理。
- skill 的调用键以 `SKILL.md` frontmatter 里的 `name` 字段为准（文件夹名是给人看的中文说明书名）。版本号以 frontmatter 的 `version` 为唯一权威。
- 仓库级体检跑 `py library_check.py`，检查 README 与 docs 覆盖、name 冲突、重复副本、frontmatter 缺字段。

## 新增或修改 skill

任何 Agent 或人向本仓库提交新 skill 之前，必须先读 [CONTRIBUTING.md](CONTRIBUTING.md)。里面规定了文件夹命名、frontmatter 字段、README 收录行格式、docs 详解页模板（含返回目录的双向跳转链接、以及指向 `references/` `assets/` `scripts/` 的「深入阅读」资料入口）和提交前自检项。

仓库根目录的 `AGENTS.md` 会让 Agent 进入本仓库时自动加载这条要求。

```text
<skill-name>/
├── SKILL.md          # Agent 读取的核心指令
├── references/       # 可选：模板、原理、扩展资料
└── scripts/          # 可选：可执行脚本
```

## 设计原则

**可跨 Agent 复用。** 不绑定单一工具，只描述规则、流程、边界。

**渐进式披露。** 索引和常驻卡只保留轻量信息，细节按需加载。

**证据优先。** 没有验证过就不宣称完成。重要结论要可追溯，也要允许被推翻。

**边界清晰。** 每份 skill 都写明什么时候触发、什么时候不触发、失败怎么降级。

**可维护。** 每次升级保留版本号，避免多份副本漂移。
