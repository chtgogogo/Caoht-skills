# Caoht Skills · AI Agent 技能工具箱

一套在真实项目里磨出来的 AI Skill 集合，可跨多种 Agent 框架复用。作者曹灏天（CaoHT）。

每一份 skill 都来自一次具体的踩坑或迭代，不是抄来的提示词。详解页按手册规格写：解决什么故障、每个机制为什么这么设计、和同类方案比强在哪、什么情况下不该用。

## 快速使用

### 安装，三步，跟具体 Agent 无关

skill 本体就是「规则 + 流程 + 边界」的纯文档（核心是每个文件夹里的 `SKILL.md`），不绑定任何框架。只要你的 Agent 支持 skills 自动发现，就能用。**本仓库里每个 skill 文件夹就是可直接安装的本体**，clone 下来即得。

1. **找到你所用 Agent 的 skills 目录。** 查它的官方文档，或者最直接的办法，问它一句：「你的 skills 目录在哪？」
2. **把整个 skill 文件夹复制进去。** 保留文件夹结构，`SKILL.md` 必须在里面。
3. **重启或新开会话**，说一句该 skill 的触发词，验证是否生效。

几个常见宿主的目录位置，仅作示例，一律以各自官方文档为准：

| 宿主 | skills 目录常见位置 |
|---|---|
| ZCode | `C:\Users\<你>\.zcode\skills\` |
| Claude Code | `~/.claude/skills/` |
| Codex CLI | `~/.codex/skills/` |
| WorkBuddy | `~/.workbuddy/skills/` |
| 通用项目级 | `<项目>/skills/`（若该 Agent 支持项目级加载） |

你的 Agent 不在表里也没关系。只要它有「skills 目录加读取 SKILL.md」这套机制就通用。实在没有，`SKILL.md` 也能当提示词模板直接贴给任何 AI 用。

### 先装哪三个

建议先装基础设施三件套。它们负责回答 Agent 最基础的三个问题：什么时候该调谁（技能调度）、写代码守什么规矩（编码行为准则）、记住了什么该怎么存（记忆纪律）。其余按需选装。

## 命名规则与版本口径

- **本仓库的 skill 目录名 = `SKILL.md` frontmatter 的 `name`**（英文，1–64 字符、小写字母数字加单个连字符）。这是 Agent Skills 开放标准的硬要求（`name` 必须与父目录同名），2026-10-14 起本仓库 17 个技能目录（当日实测计数，新增后以 `py library_check.py` 的「skill 数」为准）全部按此改名，`library_check.py` 也把「目录名 ≠ `name`」从警告升成 🔴 红项。
- **中文展示名三处都在，同出一份权威源**：① frontmatter 的 `metadata.displayName`（唯一权威源）② 上面收录表的「中文名」列（与 ① 逐字相等，体检器机械对账）③ `docs/` 详解页的文件名与页内标题。目录名改成英文，人看的中文名一个没少。
- **`A-Cao-` / `Cao-` / `CHT-` 是作者本机权威库的目录前缀体系**，不是本仓库的目录名：`A-Cao-` = 基础设施级（调度 / 纪律件 / 记忆，各宿主常驻加载）、`Cao-` = 应用级（按任务触发）、`CHT-` = 作者私人专用（不入本公开仓库），两个前缀可叠加（`A-Cao-` = 既常驻又自创）。本机历史上出现过无前缀重复副本造成漂移，已于 2026-09-07 清理。发布时权威库的中文目录名由同步器逐条翻译成这里的英文目录名，映射关系记在权威库侧的 `__SKILL详细名映射表.md`（末列＝发布仓目录名）与《__发布与个人适配约定.md》。
- skill 的调用键以 `SKILL.md` frontmatter 里的 `name` 字段为准。版本号以 frontmatter 的 `version` 为唯一权威。
- 仓库级体检跑 `py library_check.py`（零依赖可跑：装了 PyYAML 用标准 YAML 解析器，没装则自动降级为内置严格子集解析器并在输出里明示「降级模式」，不静默放过）。
  🔴 红项（不通过即退出码 1）：frontmatter 能被 YAML 解析（含拒绝重复键）、`name`/`description`/`version` 存在且是字符串、正文引用的 `scripts/`·`references/`·`assets/` 文件真实存在、README/docs/SKILL.md 里的相对链接不是死链、README 收录表「目录」列与实际技能目录双向一致（缺行／幽灵行／重复行都算红）、README 版本列 = frontmatter 版本、README「中文名」列 = `metadata.displayName`（缺这个字段也算红）、目录名 = `name`、`name` 冲突、`SKILL.md` 逐字重复副本、docs 详解页与回链。
  🟡 警告项（不影响退出码，留给人裁决）：`description` 超 1024 字符、`name` 不合标准格式、版本与本页 `CHANGELOG.md` 最新条目不一致、跨 skill 的 `../` 链接与 `tools/` 引用失效、指向本机绝对路径的链接、`docs/` 里有没被收录表任何一行指向的孤儿页。完整口径见 [CONTRIBUTING.md](CONTRIBUTING.md) 第四节。

## 新增或修改 skill

任何 Agent 或人向本仓库提交新 skill 之前，必须先读 [CONTRIBUTING.md](CONTRIBUTING.md)。里面规定了文件夹命名、frontmatter 字段、README 收录行格式、docs 详解页模板（含返回目录的双向跳转链接）和提交前自检项。

仓库根目录的 `AGENTS.md` 会让 Agent 进入本仓库时自动加载这条要求。

**权威库与发布源的关系**：作者本地那份运行时权威库（本仓库统一记作 `<你的技能库>`）是单一事实源，本仓库是**对外发布源**。改 skill 的固定顺序：先改权威库 → 同步复制到本仓库 → 在仓库侧脱敏 → `py library_check.py` 通过 → push。两处版本号必须一致，仓库版必须脱敏——完整规定见 [CONTRIBUTING.md](CONTRIBUTING.md) 第一节。

## 设计原则

**可跨 Agent 复用。** 不绑定单一工具，只描述规则、流程、边界。

**渐进式披露。** 索引和常驻卡只保留轻量信息，细节按需加载。

**证据优先。** 没有验证过就不宣称完成。重要结论要可追溯，也要允许被推翻。

**边界清晰。** 每份 skill 都写明什么时候触发、什么时候不触发、失败怎么降级。

**可维护。** 每次升级保留版本号，避免多份副本漂移。
