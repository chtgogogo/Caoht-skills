# 多 Agent 团队协作文档治理

> 为多角色（多个 AI agent + 你本人）协作的项目，建立一套**纯文档化**的协作治理机制。

## 痛点

当项目里有多个 AI agent 角色一起干活时，两件事一定会炸：

1. **多人改同一处**：甲在改契约，乙也在改契约，最后互相覆盖。
2. **你被反复追问**：甲问完"用哪个技术栈"，乙又来问一遍——你答了 N 次同一件事。

而大多数 agent 环境**根本没有 agent 之间的实时通信**，靠"拉群开会"不现实。

## 解决方案

本 skill 用**三份治理文件 + 一个信箱文件夹**替代实时沟通，把协作纪律固化成文档：

| 层 | 文件 | 解决什么 |
|---|---|---|
| L1 决策真相源 | `DECISIONS.md` | 所有待拍板/已拍板决策的唯一入口，去重登记 → 你只在一个地方拍板 |
| L2 协作契约 | `团队分工与协作契约.md` | 角色表、文件 ownership、编辑锁规则、冲突裁决 → 谁改哪归谁 |
| L3 异步信箱 | `沟通/<角色>/` | 跨 agent 请求/信息传递，命名 `X对Y.md` → 不依赖实时对话 |
| L4（可选） | `状态看板.md` | 任务进度一览，谁在做哪条 |

默认建 L1~L3；要"更完整/进度透明"再加 L4。

四条核心纪律（写进契约）：
- **编辑锁**：改非自己主责文件，先加 `<!-- EDIT_LOCK ... -->` 标记，改完移除。
- **统一决策入口铁律**：任何需你拍板的事，禁止各自追问，必须登记进 `DECISIONS.md` 并去重。
- **信箱投递**：跨 agent 请求走 `沟通/<接收人>/X对Y.md`。
- **交接原则**：某 agent 陷入瓶颈或判断更适合他人接手时，必须在对话窗口及时告知你并建议切换会话，不原地死磕。

## 一行安装

把 `multi-agent-team-governance/` 整个文件夹复制到 agent 的 skills 目录（如 `~/.workbuddy/skills/`），重启即可；若上架技能市场，可一键安装。

## 真实示例

用户："几个 agent 一起帮我做天倾游戏，别让我分别回他们。"

skill 产出：
- `DECISIONS.md`：D-01~D-20 决策收敛，用户只在「待用户拍板」区一次性回复。
- `团队分工与协作契约.md`：角色表（游戏设计师/技术美术/脚本工程师）+ 各自 ownership + 编辑锁规则。
- `沟通/`：每个角色一个收件箱，agent 间投递 `X对Y.md` 而非实时互扰。
- （可选）`状态看板.md`：进度透明。

> 机制提炼自真实跑通的天倾（Godot 游戏）多 agent 协作项目，契约已转正 v1.0、决策已收敛、信箱已双向投递。

## 核心能力

1. **防重复建设扫描**：生成前先检查项目是否已有同类治理文件，避免两套纪律打架。
2. **三层治理骨架**：决策真相源 + 协作契约 + 异步信箱，开箱即用模板。
3. **编辑锁机制**：用 HTML 注释标记占用，杜绝并发覆盖。
4. **统一决策入口**：所有需拍板事项去重登记，用户一次回复全员生效。
5. **信箱投递规范**：跨 agent 协作请求结构化命名，替代实时沟通。
6. **可选进度看板**：L4 看板让任务状态透明。
7. **交接原则（瓶颈切换）**：agent 卡住或更适合他人时主动告知你切换会话，避免单点死磕、进度失衡。

## 使用前提与常见问题

**使用前提**
- 适用于 WorkBuddy（或任何读取 `SKILL.md` 的 agent 框架）。
- 项目应允许多个 agent 角色 + 用户共同协作。

**常见问题**
- **Q：项目里已经有契约/公约怎么办？** A：skill 会先扫描，发现冲突会提示你二选一并合并，不盲目新建。
- **Q：模板是中文的，有影响吗？** A：无影响，`references/` 下模板为中文，正好适配中文项目。
- **Q：会动我现有文件吗？** A：只在你确认下生成治理文件，不删不改你的业务代码。
