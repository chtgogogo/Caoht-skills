# multi-agent-team-governance · 使用说明

> 给人看的使用门面；AI 执行指令在 `SKILL.md`。

## 这是什么
为多角色（多个 AI agent + 你本人）协作的项目，建立一套**纯文档化**的协作治理机制。不依赖 agent 之间的实时通信，而是用三份治理文件 + 信箱文件夹替代"开会/拉群"，解决两个核心痛点：

1. **多人同时改同一处** → 靠**真实文件锁**（`scripts/edit_lock.py`，跨进程原子抢占 + 租约超时接管）或**单写队列**（各人投件、一人合并）；纯文档小改才退化为文字锁标记。
2. **你被甲问完乙又问同一件事** → 靠「统一决策入口」，你只在一个地方拍板；改判走 `supersedes` / `revoked` 事件，**旧结论原文进历史区，不删**。

## 它包含什么
- `SKILL.md`：调度与纪律总纲（触发、工作流、核心纪律、共享文件写入、决策生命周期、交接原则、体检）。
- `references/契约模板.md`：协作契约骨架（角色表 / ownership / 三档写入机制：真实锁·单写队列·文字锁 / 规模自适应与退役）。
- `references/决策看板模板.md`：DECISIONS.md 结构（已决 / 待拍板 / 分工矩阵 / 执行跟踪 / 历史区留原文 / 生命周期状态）。
- `references/信箱说明.md`：信箱命名约定 + **逐条消息**三元组（消息 ID / 接收方 / 状态）+ 轻量模式单文件信箱 + L4 看板字段。
- `references/示例-最小可运行治理包.md`：陌生项目照抄即可起步的一套最小治理文件，含每条命令的实际输出与「乙必须返回 1」这类验证点。
- `scripts/edit_lock.py`：文件系统级原子锁（acquire / heartbeat / guard / takeover / release / status）+ 单写队列（spool / queue）。
- `scripts/governance_check.py`：治理体检脚本（九项检查 + 检查覆盖率 + 区分「未配置」与「健康」）。
- `personal.local.md`（可选，本机适配层）：把本 skill 对接到项目**已有**的账本 / 决策 / 取号机制上；**它不进发布仓，也不该进**——每个项目各自建，路径与字段按自己现状填。

## 安装
把整个 `multi-agent-team-governance/` 复制到你的 skills 目录，重启即可。

## 多宿主同步提示
如果你在多个 agent 宿主各放了一份，请保持逐字一致；任一改动后整体同步其余副本并跑 `quick_validate.py`。
> 唯一例外是 `personal.local.md`：它天生只属于某一台机器/一个项目，同步时排除它，别把别人的绝对路径当成你的现状。
