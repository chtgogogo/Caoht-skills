## v1.4（2026-10-11）
- **做了什么**：① **信箱判据从「整文件」改为「逐条消息」**——每条消息一个标题，带 `消息 ID / 接收方 / 状态` 三元组，混合状态逐条报积压，认不出的状态按未处理计（宁可多报不漏报），并加**分母闸**（有信件却解析出 0 条 ⇒ 判尺子作废、报警而不是报「干净」）。② **文字锁升级为真实文件锁**：新增 `scripts/edit_lock.py`，`O_CREAT|O_EXCL` 原子抢占 + 临时文件 `os.replace` 写入，租约 + 心跳 + 超时**接管**，接管给**写入代次（generation）+1**，旧写者的 heartbeat/guard/release 一律退出码 6 被拒；并发多人改同一文件改走**单写队列**（`spool` 投件 / `queue --done` 取件），配套文档写明「独立工作区 + 单一集成者合并」。③ **决策生命周期改为「替代即换血、历史不删」**：改判走 `supersedes` / `revoked` 事件，失效条目**原文**进历史区或 `DECISIONS_归档.md`，有效视图由 `--decision-view` 机械生成；幽灵引用与「历史被删」都能机检。④ **体检输出检查覆盖率**（9 项全列 + 未检查项点名），并区分「未配置治理」（退出码 3）与「已配置且健康」——`3` 不是健康。⑤ 新增 `references/示例-最小可运行治理包.md`（陌生项目照抄可起步，含每条命令的实际输出与验证点）与 `personal.local.md`（本机适配层：对接已有的账本/@提及/`next_id` 取号惯例，不另造平行机制）。
- **解决了什么**：外部审查 §二.13 列的 P0 六项——整文件判据会漏报积压（一封信里 5 条已处理 + 1 条待处理 ⇒ 报「无未处理信件」并退 0）；文字锁无原子性，两个 agent 同时 `EDIT_LOCK` 谁都能抢，且「超时接管」后旧写者照样能改；消息没有 ID 就无法逐条追办；改判即删原文导致决策不可追溯（且和"避免幽灵引用"互相打架）；体检只报「没问题」，读者分不清是没问题还是压根没治理文件；文档规矩只写在正文、陌生环境无从起步。**另与 v1.3 正面调和**：v1.3 拍的「抛弃型直接删除、历史区只留一行指针」撤销其**删原文**部分（活跃区瘦身与压缩阈值不变 ⇒ token 成本不变；变的只是失效结论的原文留档位置）。
- **怎么解决的**：脚本层——合成样例**先红后绿**（红证＝旧脚本对混合状态信箱报「无未处理信件」exit 0、对空目录报健康；绿证＝同输入下新脚本报 1 条积压、空目录判「未配置」exit 3），具名断言 63 条全绿；再加**变异探针** 8 组（只改实现不改断言，逐组点名该翻红的那条），首轮 M5 未被抓 ⇒ 查出真缺陷：`takeover` 打印的代次是自己硬算的 `old+1` 而非写回的记录值，修宪后 8/8 全被抓、权威库实现逐字未变。文本层——把「规矩」改写成「机制 + 判据」：三档写入机制（真实锁/单写队列/文字锁）与退出码表进契约模板，逐条三元组与状态取值表进信箱说明，`supersedes` 事件的可解析写法与历史区格式进决策看板模板，示例包在真实临时目录上端到端跑通（读数只剩故意留的那条 pending）。证据：`evidence/卡05/`。

## v1.3（2026-09-18）
- **做了什么**：决策生命周期简化——替代型只登记新结论、禁止「原XX被推翻」历史叙述（用户例：2D 横板格斗→3D 俯视角肉鸽不共存，无需提旧），历史区只留一行指针防「幽灵引用」；抛弃型 grep 确认无引用后直接删除零记录；活跃区状态仅保留 approved/todo；决策压缩（活跃区 >30 条或双周并入 `DECISIONS_归档.md`）；轻量信箱强制升级阈值（>20 条或 7 天）；新人检查单改为按主责 grep 不读全文。
- **解决了什么**：用户质疑「信箱=派工单变体」并拍板四项优化（work-082）——决策与信箱记录越用越肥（历史叙述膨胀、反复消耗 token）。
- **怎么解决的**：三处同步落地（SKILL.md + 决策看板模板 + governance_check.py），体检脚本加 [6] 轻量信箱规模、[7] 决策规模两检查（造 22 信 + 35 决策实测报警 ✓ exit 1）；另确认 E:.某宿主「副本」实为同一文件链接、无需同步。
