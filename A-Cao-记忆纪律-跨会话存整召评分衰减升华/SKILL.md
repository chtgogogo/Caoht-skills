# 记忆纪律（自包含入口）

> 规则正文 **v3.5**（2026-09-01）；本入口封装 **v3.5-sc1.1**（2026-09-23 自包含改造 + 权威库回流）。
> 启发词：`【记忆纪律 v3.1】`——**固定的入口引导卡名（触发词），不随规则版本变动**。
> **自包含承诺：单凭本文件即可正确执行全部核心流程。** 完整规则源 `D:\Deepseek-ALL\记忆规则\`（00–12）只是扩展阅读——存在时可深入，不存在时不影响本文件任何一步。旧指针与本文件冲突时，**以本文件为准**。

## 0. 通用性约定（解耦原则）

1. **规则共享一份**：权威规则源（00–12 文档）所有 agent 共享，**只读不改**；规则里不含任何 agent 专属路径。
2. **记忆 store 各自建立、互不共享**：每个 agent 在自己的存储位置建自己的 store。store 根由你自己的配置决定（看你自己 `AGENTS.md` 里的 `MEMORY_ROOT`、环境变量）；没有就在你习惯的记忆位置新建。**不要在 store 里写死别人家的路径。**
3. **常驻引导卡各自放**：放进你自己 store 的 `MEMORY.md` 顶部（模板见 §9）。
4. **脚本各自复制**：把 `memory_maintain.py` 复制到自己 store 的 `tools/` 下运行（权威源在 `D:\Deepseek-ALL\记忆规则\tools\`；**拿不到脚本时，手工按 §2–§8 执行，脚本后补，不阻塞**）。
5. **双副本同步（权威库保持最优版）**：本 skill 的注册副本与权威库副本（D 盘 `A-Cao-记忆纪律-跨会话存整召评分衰减升华`）必须逐字一致；优化先落注册副本验证，**验证通过后及时回流权威库——权威库永远保持最优版，不得停留在旧版（用户令 2026-09-23）**；patrol 巡检把关漂移。

## 1. store 结构（CORE + 七库）

```
<store根>/
├── CORE.md        ← L0 核心层：每次会话全读，硬上限 150 行（画像摘要+路由表+铁律）
├── PROFILE/       ← L1 画像：用户是谁、偏好、红线        [pinned 永久]
├── WORK/          ← L2 工作：做了什么、做到哪、卡在哪    [fast 7天]
├── DETAIL/        ← L3 细节：事实、参数、环境、非显然结论 [normal 14天]
├── PITFALL/       ← L4 踩坑：症状→根因→解法→验证        [slow 30天]
├── REJECTED/      ← L5 否决：试过证明不行（负知识，高价值）[slow 30天]
├── DECISION/      ← L6 决策：为什么选 A 不选 B           [pinned 永久]
├── TRASH/         ← 确认无用待清理
└── FORGOTTEN/     ← V≤0 归档（索引保留，正文压 1-2 行）
```
每库一个 `index.md`，**一行一条**（上限 80 行/60 条，超了拆子索引）。

## 2. 写入闸门：三记五不记

**三记**（满足任一才写）：
1. 得出了**非显然**结论（模型本来不知道、要推理/调查才得到的）；
2. 用户显式要求记（"记住这个"）；
3. 失败 ≥2 次才解决的问题。

**五不记**：
1. 模型本来就知道的通用知识（记=污染）；
2. 一次性临时信息（"帮我算 23×47"）；
3. 未验证的猜测（可暂存但必须标 `[推测]`，验证后才转正）；
4. 与已有记忆重复（**加固旧记录，不新建**）；
5. 用户随口一提没下文、且 V < 5。

**时机**：对话进行中只做心里标记，段落结束/结论落定再写。判据：**这个结论三个月后还会用到吗？**

## 3. 双轨评分（V + R）

**固有分 V**（0-100，落盘，会衰减），初始分按量表打，不凭感觉：
```
V = 5（基础）
  + 影响范围：本次对话 0 / 单项目 10 / 跨项目通用 20
  + 复发性　：一次性 0 / 可能再遇 5 / 反复遇到 15
  + 获取成本：随手可得 0 / 查了才知道 5 / 踩坑才得到 15
  + 稀缺性　：模型本来就知道 0 / 只有这里才知道 10
  + 用户显式强调（"记住/重要/别忘了"）20
```
V 分层含义：80+ 铁律级（应已升华）｜50-79 核心知识｜20-49 稳定有用｜10-19 边缘｜1-9 垂死｜≤0 归档 FORGOTTEN。

**情境分 R**（0-10，每次检索临时算，**不落盘**）：
```
R = 相关性（触发词精确命中 6 / 语义相关 3 / 弱相关 1）
  + 新近性（7 天内命中过 4 / 30 天内 2 / 更早 0）
```

**排序分 = (V/10) × 0.6 + R × 0.4**　（V 保基本盘，R 让"此刻恰好相关的冷门记忆"翻上来。）

**关键加扣分**（命中除了加分，同时 `strength+1`，上限 10）：

| 事件 | V | 附加 |
|---|---|---|
| 检索命中且真用上 | +2 | 重置衰减计时 |
| 用户主动提起 | +3 | 重置衰减计时 |
| 用户确认有用 | +5 | — |
| **用户纠正**（"不对，应该是X"） | **+8** | **强制改写内容**（最强信号） |
| 同类再现（N≥2） | +5 | **不新建，追加证据** |
| 被证伪/过期 | -50 | 转 superseded 或 REJECTED |

**惰性衰减（读时结算，零进程）**：`应扣 = 周期数 × (1 + ⌊V/25⌋)`；`实际周期 = TTL档 × (1 + strength/10)`——被反复想起的记忆衰减变慢（间隔重复）。

## 4. 检索协议（渐进披露 + 硬预算）

**绝不一次性读完任何库**（唯一例外 CORE.md）。流程：
```
CORE.md（含路由表 ≤30 行）→ 路由直达 1 个分区 index → 挑 ≤3 条
→ 只读 frontmatter + 「一句话结论」（~20 行/条）→ 挑 1 条 → 读全文
```
**硬预算**：寻址 ≤800 + 展开 ≤1200 + **总计 ≤2000 token**；超了强制停，并告知用户"可能有遗漏"。
省 token 三招：单 index >60 条拆子索引；同会话已读条目不重读；先读头部不够再下探。
**路由表**（CORE.md 内 ≤30 行）：触发词 → 分区 index 或热记忆直达文件；V≥50 加直达项，V≥80/升华结论直接进铁律区，V<30 移除。
**触发词三层**（每条 3-8 个，缺一不可）：**现象词**（用户会怎么口头描述，用原话别用术语）+ **实体词**（真实文件/函数/表名，供精确匹配）+ **本质词**（根因类别）+ 同义变体；另配排除词防误触发。

## 5. ⚠️ Probe 纪律（sc1 新增，源自微软 propose-probe-commit 启发）

**原则：记忆落笔那一刻，应该是"核实过、可执行"的，而不是"看起来像对的"。**

- **写前 probe**：
  1. **先取号防撞车**——写库前重读目标库 index 或跑 `tools/next_id.py <store根> <库名>` 取"当前最大号+1"，**以文件系统为准，不沿用会话开头读到的旧号**；
  2. **环境类记忆写入前实地核实**——路径/版本/配置类信息，先 ls/查证一次再落笔；
  3. **指针必须自带降级路径**——引用外部文件时必须同时内嵌"指针失效时按什么执行"（例：完整版见 X；X 不在时按 Y 执行）。裸指针 = 记忆里的悬空引用。
- **用前 probe**：引用记忆里的路径/数字/他人维护文档的口径之前，花一次工具调用核实仍然成立。
- **值不值得 probe**：易漂移的（路径、数字、版本号、别人维护的文件）必核；稳定事实（用户偏好、红线、决策理由）不核。
- **probe 预算**：每条 ≤1 次工具调用；不得借"核实"之名突破 §4 检索预算。
- **失效处理**：发现记忆过期 → 旧条标 `superseded` 不删除 + 写修正版；用户纠正按 +8 强制改写。

## 兄弟 skill：pitfall-log（踩坑日志）——互认与边界

- **它是什么**：跨 agent 共享的踩坑沉淀库（根因层+案例层，根因优先检索）。本机 log-root = `D:\Deepseek-ALL\踩坑日志`，入口索引 `pitfall-log.md`（极轻）。skill 已注册本机（`pitfall-log`）可直接调度；**skill 不可用时直接读该索引文件，功能不中断**。
- **何时去查**：遇到报错 / 反复失败 / 难修 bug，先查本 store PITFALL 库；没命中再去踩坑日志扫「根因索引表」找识别信号。**反复出现 / 连败 3 次的 bug，动手前强制翻一次踩坑日志找灵感。**
- **边界（不重复存储）**：通用 / 跨工具坑的正文记踩坑日志（共享单一事实源）；仅本 agent 环境私有的坑正文记本 store PITFALL；交叉相关时另一方只放一行指针（含根因号/日期），不复制正文。
- **升华回流**：踩坑日志某根因 / 案例 hits≥3 → 按其升华流程写进本 CORE 铁律区（来源注 RT-xxx）。
- **巡检保障**：`tools/patrol_check.py` 会巡检本 skill 与 pitfall-log 的注册状态、双副本一致性与指针存活。

## 6. 冲突与升华

**冲突不删除，只失效**：同主题 + 关键词重合 >60% + 结论方向相反 = 矛盾 → 旧条 `status: superseded` + `valid_until` + `superseded_by` 反向指回；检索只返回 `active`。
**双向写入**：新证据回头修订旧记忆（矛盾→改结论句 V+8；互补→补边界 V+5；新证据→追加 V+5 不新建）。

**升华**（三级形态：用得越多，变成加载成本越低的形态）：
- 触发（任一）：同一根因的坑累计 **≥3 条** / 某条 V ≥ 80 / 用户说"写成规则"。
- 路径：原始记录（≤120 行）→ index 摘要行（命中 ≥2 次时写）→ **铁律 1-2 行进 CORE**（零检索成本，停衰减，转 `pinned`）。
- 产物格式：一句话规则 + 关键约束 + 反例 + 来源指针（pit-xxx 等）。

## 7. 记录模板（自包含版）

```markdown
---
id: pit-003          # 类型前缀+号：pro/work/det/pit/rej/dec
type: pitfall        # profile|work|detail|pitfall|rejected|decision
title: <一句话标题>
triggers: [现象词..., 实体词..., 本质词..., 同义变体...]
exclude: [误触发词...]
score: 45            # V，按 §3 量表
strength: 0          # 0-10，命中+1
ttl: slow            # pinned|slow|normal|fast
created: 2026-09-23
last_hit: 2026-09-23
valid_until: null    # 非空=已失效（不删除）
status: draft        # draft(检索降权50%,第2次命中转正)|active|superseded|promoted|archived
superseded_by: null
promoted_to: null
links: []            # 相关记忆 id
evidence: 1
confidence: high     # high|medium|low（低=标[推测]）
---
## 一句话结论        ← 必须放最前（性能设计：先读 20 行就能决策）
## 适用边界          ← ✅ 什么情况适用 / ❌ 什么情况不适用
## 本质（根因/规律）
## 细节（完整过程、数据、判断依据）
## 证据链
```

**index 行格式**：`| ID | 触发词 | 一句话结论 | 分 | 状态 |`
**CORE.md 结构**：用户画像摘要（≤5 行）→ 铁律区（R-xxx 永久不衰减）→ 路由表（≤30 行）→ 系统状态（≤8 行，只留指针）。

## 8. 收尾与体检

- **会话收尾**：跑 `py <store根>/tools/memory_maintain.py <store根> check` + 更新 CORE「系统状态」。
- **定期体检**（每 10 次会话或 30 天）：①去重 ②冲突检测 ③容量红线（CORE 150 行/index 80 行/单条 120 行）④升华候选 ⑤遗忘区二次判定 ⑥**漂移抽查（sc1 新增：抽 3 条环境类记忆实地核实，过期即按 §5 处理）**。

### 8.1 三个工具（本 skill 自带，复制到 store 的 `tools/` 使用）

| 工具 | 干什么 | 何时用 |
|---|---|---|
| `memory_recall.py` | **排序召回**：只读索引，按当前任务上下文排 top-K，吐出命中路径；默认不读正文（省 token），加 `--print` 才读 | **每次要检索记忆时先用它**，不要整库读 |
| `memory_organize.py` | **整理体检**：查断链 / 孤儿 / 重复行 / 容量超限 / 冷记忆；默认 dry-run，`--apply` 只做「移除断链 + 合并重复」，**只移不删** | 每 10 次会话或 30 天 |
| `patrol_check.py` | **体系巡检**：注册状态 / 双副本一致 / 指针存活 / 容量红线 / 踩坑日志活性 | 收尾或怀疑漂移时 |

```bash
py <store根>/tools/memory_recall.py "本次任务上下文" --root <store根> --top 5
py <store根>/tools/memory_organize.py --root <store根>            # dry-run
py <store根>/tools/memory_organize.py --root <store根> --apply    # 执行安全修复
py tools/patrol_check.py                                          # 体系巡检（路径已内置）
```

> **两种 store 结构都支持**：单索引型（`MEMORY.md`，Engramory/WorkBuddy/DSH 实际在用）与七库型（`CORE.md` + 各库 `index.md`）。
> **召回排序**：`类型权重 ×1.0 + 关键词命中率 ×2.0 + 新近度 ×0.5`；语料优先读正文 `triggers` 字段，没有则回退 `name + description + 索引 hook`。
> **分词用中文二元组**（不用逐字）——逐字会把「不知道怎么办」拆成 6 个噪音 token，稀释命中率。

## 9. 冷启动（新 agent 第一次用）

1. store 根建 `MEMORY.md`，顶部放常驻引导卡（模板见下）。
2. 建各库空 index。
3. 第一条记 PROFILE（用户是谁）。
4. 复制 `memory_maintain.py` 到 store 的 `tools/`（脚本拿不到先手工跑，见 §0.4）。

**常驻引导卡模板**：
```markdown
## 记忆纪律 v3.1 常驻引导卡
> 启发词：【记忆纪律 v3.1】。回答任何消息前先确认本卡在上下文中；上下文压缩后重读本文件。
7 条核心：①写入先取号+三记五不记+三层触发词 ②V/R 打分（见 skill §3）③排序分 ④检索走路由表+≤2000 token 预算 ⑤命中 V+2~8、strength+1 ⑥同型≥3 次升华铁律进 CORE ⑦收尾跑 check+更新系统状态
（完整规则：本 agent 的 memory-scoring-lifecycle skill——自包含，单独可执行）
```
