# 模式判定（启动路由的判定依据）

> 主 skill 启动时：**先 `resume` 读权威记录**（有未完成项目就照它续，不重新问档），
> 无未完成项目才走本文件定档。
> **先给推荐+理由，再让用户拍板**——但"拍板"只在判不出来的时候才发生（见 §三）。
> 定档不是人肉印象分：计分规则写死在 `scripts/pipeline_state.py` 的 `decide_tier()`，可复算、可被探针打红。

**判据唯一真源＝脚本**：信号键集合（`KNOWN_SIGNALS`）、计分红线（`decide_tier`）、步骤集合（`TIER_STEPS`）、
流程产物（`TIER_FILES`）、前置依赖（`PRE_EXEC_DEPS`）、点亮规则（`enabled_steps`）以代码为准；
本文件与脚本冲突时以脚本为准——改判据先改脚本，当次会话回写本文件（铁律 10）。
依据分级：**A**＝脚本代码与 selftest 断言（唯一判据）／**B**＝联网复核过的业界资料（本稿暂无）／
**C**＝通识启发（仅助理解，不作判据；本稿业界对标均为 C——检索通道受限未复核，明细见 §九）。

## 一、三档＋一条路由

| 档／路由 | 适用信号 | 走的步骤（`TIER_STEPS` 原样） | 建的文件 |
|---|---|---|---|
| 轻量 | 改 bug / 小功能 / 单文件改动 / 用户说"快改一下" | ①③⑥⑧⑬⑫ | `state.json` + `台账.md`（**不建任务板/卡库/选型等空文件**；文档层六件骨架照搭，**三份大计划骨架不搭**） |
| 标准 | 新功能 / 新模块 / "做一个 XX"且范围可控 | ①②③④⑤⑦⑥⑧⑩⑪⑬⑫ | 同轻量基础 + `任务板.md`（**有卡才建，无卡不建空看板**）+ init 搭三份大计划骨架（设计纪要/技术选型记录/PRD） |
| 企业 | 全新项目 / 多模块 / 多人或多分身协作 / 长周期 | 全步骤＝`STEP_ORDER` 全集（①②③④⑤⑦⑥⑧⑨⑩⑪⑬⑭⑫；历史名"十二步"沿用，编号不重排） | 同标准（复杂＝企业的别名） |
| 跳步优化 D | **已有项目**："帮我优化/检查/升级"而非从零开发 | 见 §五 | 按勾选到的阶段建账（档位记 `标准`） |

别名口径：`轻/标/企/复杂/跳步优化` 都能接受，落账归一到 轻量/标准/企业 三档之一（脚本 `ALIASES`）——
`state.json` 的 `mode` 只有这三个值，**"跳步优化"是路由不是档位**（`--set 跳步优化` 合法，落账＝标准；
它决定"先扫缺口再选阶段"，不决定步骤集合）。

产物口径三条（与脚本逐字对齐，防"轻量＝什么都不建"的误读）：

1. 档位管的是**流程产物**（`TIER_FILES`：轻量＝state.json＋台账；标准/企业再加任务板）与步骤集合；
   文档层六件（AGENTS.md/CONTEXT.md/权威源表/小白手册/故障对照表/上下文体检）是**全档默认骨架**（L0），
   `init --docs-tier none` 才免——且 none 只豁免这六件，**不豁免三份计划骨架**（那是流程档的事）。
2. 轻量档两处显式豁免：① 不强制设计纪要（索引原文"一句话版"）；③ 只要求 `docs/pipeline/PRD.md` 本体在盘、
   `specs/*/spec.md` 豁免（**PRD 本体任何档都要**——产物清单硬闸的 all 档）。
3. 骨架（scaffold）与产物（artifact）是两回事：init 不搭骨架 ≠ 该阶段不要产物；清单硬闸按档位查盘上实物。

## 二、信号表（只有这些键参与判定）

`py scripts/pipeline_state.py mode --decide --signal 键=值 --signal 键=值 …`

**A. 定档信号**（进 `decide_tier()` 计分；共 8 键，引号内＝代码 why 行原话）

| 键 | 值与缺省 | 该键直接参与的红线 |
|---|---|---|
| `files_touched` | 整数：这次动几个文件；未给按 0 | 「涉及文件 ≥4 ⇒ 标准 +2」；≤3 时进入两条轻量判据的与条件（见下） |
| `modules_touched` | 整数：跨几个模块；未给按 0 | 「跨 ≥2 模块 ⇒ 标准 +2」；>4 时命中「模块 >4 或卡数 >8 ⇒ 企业 +2」 |
| `cards` | 整数：预计切几张卡；未给按 0 | 「卡数 ≥2 ⇒ 标准 +1」；>8 时命中「模块 >4 或卡数 >8 ⇒ 企业 +2」 |
| `team_agents` | 整数：几个分身／人协作；**未给按 1** | 「多分身／多人协作 ⇒ 企业 +2」（≥2 才算） |
| `estimated_days` | 整数：预估几天；未给按 0 | 「预估 ≥3 天 ⇒ 企业 +1」 |
| `has_code` | true/false；未给按 false | 只当轻量 +3 的与条件（true 则该判据不成立），**别处不加分** |
| `from_zero` | true/false；未给按 false | 「从零起项目 ⇒ 企业 +2」，且**否掉两条轻量判据**（两条的与条件都含"非从零"） |
| `new_feature` | true/false；未给按 false | 「新功能（非纯改动）⇒ 标准 +2」 |

两条轻量判据（与条件逐字对齐代码，数量键缺省按 0 计入）：

- 「不动代码、非从零、涉及文件 ≤3 ⇒ 轻量 +3」＝`not has_code 且 not from_zero 且 files ≤3`；
- 「单模块单卡 ⇒ 轻量 +2」＝`files ≤3 且 modules ≤1 且 cards ≤1 且 非从零`。

**B. 点亮信号**（不进计分，只决定可选重步骤跑不跑，见 §四；共 6 键）

`deploy` · `public_net` · `compliance` · `eval_set` · `external_claims` · `parallel_cards`

`compliance` 触发面（判定口径）：行业合规义务、数据处理法规、**售欧盟/可能被欧盟用户获得的交付**
（EU CRA 意义上的"投放市场"，收费免费都算）——命中点亮 L3 安检：SBOM 必检＋事件响应承接
（判据=`安全基线检查.md` §四/§十）。触发面是人的判断输入进信号值，脚本不猜。

A 表 8 键＋B 表 6 键＝14＝`KNOWN_SIGNALS` 全集，**没有第三类**。

**C. 不参与计分的键会被点名**

写了不在 A/B 表里的键（拼错、或者以为工具认识），输出里会有一行
`🔴 [不参与计分的信号键] xxx ⇒ 拼错或本尺子不认，别把它们当成已评估的依据`。
判据：**"我给了个信号"和"这个信号被评估了"是两件事**——以前用假键名（`user_says_quick` 之类）跑出来的推荐，看着像评估过，其实整条被忽略；现在必须显式报警，不然假绿比没绿更坏。

**键值归一与收集（该灵活的灵活）**：

- 归一（`_coerce`）：`true/yes/是`⇒真，`false/no/否`⇒假，能转整数就转整数，否则原样字符串；布尔键"给了值"即按真计。同键给多次，**最后一次生效**。
- 收集：工具不限制信号来源——用户原话（"就改两个文件"⇒`files_touched=2`）、仓库实况（diff 统计、模块目录数）都行；只要求**键名合法**。
- 🔴 数量键缺省按 0，两条轻量判据会在 0 上**全中**（例 5 见 §八）：轻则平档问人，重则把不小的活压成轻量档。
  **最小必给键是 `files_touched`**，掂得出模块数/卡数就一并给。

## 三、什么时候才问用户

```
mode --decide 判得出档  → 自动定档，**告知即可，不追问**（退出码 0）
mode --decide 平档同分  → 退出码 1，打印「[自动选档] 判不了（X／Y 同分）⇒ 只在这种平档情形问用户」→ **这时才**把选项摆给用户
mode --decide 一个信号都没给 → 落最低档（轻量），why 行明写「本行是默认值不是判定」，不因此问用户
```

- **平档才问**：只有三档里最高分并列（判据明写"置信度不足"）才交回用户；其余一律自动定档。
  给了信号就至少有一档得分（两条轻量判据的与条件在缺省 0 下几乎总成立），所以"判不了"只会以同分形式出现。
  想强制交回用户看推荐再确认，加 `--ask`（脚本层只改打印口径，停不停由执行窗遵守——编排约定，非机检）。
- **无信号不问你**：没给信号＝落最低档，宁少步骤也不产空文档堆；但输出会明写
  「未收到任何信号 ⇒ 落最低档……**本行是默认值不是判定**」，防止下次有人拿它当"已经评估过了"。
  要问的是"这次改动涉及几个文件"，不是"你要哪个档"。
- **用户显式点了档**（"就要企业档"/"随便快点"）→ `mode --set 企业 --apply`，档位来源记 `user`，自动结果让位。
- 🔴 **固定提问是缺陷不是纪律**：每个阶段开新窗口先问一遍"模式是什么/落盘在哪/要不要并行"＝把已说过、已授权的事再问一遍。要向用户确认的事**先 `answer --id <项> --check`**，答过就直接用（细则=`台账模板.md` §五）。
- **定档来源必留痕**（`mode_source`，三值；三窗实测教训——来源分不清，后续步骤就分不清"能不能改"）：
  - `auto`＝`mode --decide --apply` 写入；**可复核推翻**：拿到新信号可重判，旧自动档让位。
  - `user`＝用户点名（`mode --set X --apply` 或 `init --mode X`）；**不许自动改**——改档必须用户亲口说，再走 `--set`。
  - `default`＝建账时既没判也没点名（`init --mode-source default`）。
  引用档位做后续决策前，先看来源再决定"照办还是可复核"。
- **退出码速查**：判得出＝0；平档＝1；`--signal` 缺 `=`、`--set` 未知档位＝2（参数错）；`--decide --apply` 而无权威记录＝3（先 `init`）。不带 `--apply` 的 `--decide` 是纯探针：不写盘、不需要先建账。
- **复算与查账入口**：`mode`（不带参）＝看当前档与来源；`plan --tier 轻量`＝只打印该档产物清单、步骤集与"跳过的步骤"，不写盘。

## 四、可选重步骤按特征点亮（不全部默认跑）

| 步骤 | 点亮条件 | 不点亮时 |
|---|---|---|
| `security_L1` | **常开**（铁律 10：静态自检＋敏感信息/本机绝对路径泄漏扫描，纯文档项目也跑） | 没有"不跑"这一档 |
| `security_L2` | `deploy` 或 `public_net` | 未部署/不公网 ⇒ 不跑 |
| `security_L3` | 企业档 或 `compliance`（触发面含**售欧盟**，见 §二 B 表） | 非企业档且无合规要求 ⇒ 不跑 |
| `model_eval` | `eval_set` | 无评测集 ⇒ 不跑（**不编基线**） |
| `multi_agent` | `parallel_cards` ≥3 且 `team_agents` ≥2 | 默认接力不并行 |
| `outward_claims` | `external_claims`（有 README/简历/汇报等对外陈述物） | 记 `na` |

**team 外挂声明（多人协作边界，输出面非步骤）**：`team_agents ≥2` 命中时，`mode --decide` 输出末尾
自动追加**外挂声明**三行（selftest A83/A84 机检）——权限/评审流/审计交 GitHub（分支保护四件套：
必需审批数＋必需状态检查＋CODEOWNERS 指到人＋签名提交），本流水线**只保留台账、验收口径与门禁
退出码，不建权限体系**（自建 IAM/评审流=重流程债，违背单人定位；评审8 判决沿用）。审计面声明：
`history.log`（append-only）＋各 gate 的 evidence 落盘＝SOC2 CC7 意义上「控制运行记录」的最小形态，
团队档可直接拿去当审计证据底稿。团队项目 `--who` 用真名或窗口身份映射，映射表放 `personal.local.md`
（不入仓）。

- 轻量档只保留 `security_L1` 与 `outward_claims` 两项，其余一律不跑——**这一条是"轻量档对陌生项目也安全"的落地**：
  小改动不该被拉去建卡库、跑评测、开多代理，更不该留下一堆空文件。轻量过滤发生在点亮计算**之后**：
  就算 `deploy/eval_set/parallel_cards` 全给了，多余项也进"默认不跑"并注明该档步骤集合。
- `--decide --apply` 会把 `model_eval`/`multi_agent`/`outward_claims` 按"点亮/不点亮"落成 `pending`/`na`；
  `security_L1` 从建账起就是 `pending`，唯一出路是 `gate security_L1 passed`——收尾硬闸只认 passed（铁律 10）。

## 五、跳步优化（模式 D）执行法

1. 拿"十二步检查表"逐项扫描当前项目，问自己三个问题：
   - 这个环节的产出物存在吗？（有没有 CHANGELOG？有没有评测集？有没有台账？）
   - 存在的话质量如何？（评测数字新鲜吗？文档与代码一致吗？）
   - 有没有明显的低垂果实（一次小改动就能补的短板）？
2. 产出**缺口清单**（每项：缺什么 / 补了有什么好处 / 大约代价），按性价比排序给用户勾选；
3. 用户勾选的每项 → 按对应阶段的细则直接执行（不重走 ①②③），执行结果照常写进权威记录；
4. 跳步优化只改"从哪几步进"，**不改档位、不改执行顺序规则**：选进来的步骤照样受 §七 的 DAG 前置约束
   （不在档位集合里的步骤记 `na`＝豁免，天然不卡）；要越序必须 `--skip-auth` 留痕（见 §七）。

示例：对一个"有 README 无评测集、CHANGELOG 停更、文档与代码不同步"的项目，缺口清单可能是：
1. 建最小评测集（补量化验收能力，半天）；
2. 修文档与代码的 3 处不一致（防对外演示/评审时穿帮，1 小时）；
3. 补 CHANGELOG 迭代记录（展示工程素养，1 小时）。

## 六、给用户的第一条消息（只在平档时发）

> 查了权威记录，没有未完成的项目。按你描述的改动范围（{复述用户意图}），信号计分是
> 轻量 {n}／标准 {n}／企业 {n}，前两档同分 ⇒ 我判不出，请你拍板：
> - 轻量（只建 state.json + 台账，不建任务板）
> - 标准（切卡 + 任务板 + 双评审）
> - 企业（全十二步）
> - 跳步优化（已有项目只补短板——我先扫缺口清单给你勾选）
> 选哪个？也可以直接告诉我你的顾虑，我重新推荐。

判得出档时**不发这条**：直接一句"按 {X} 档走（理由：{一条计分判据}），要改随时说"，然后开工。

## 七、定档之后：执行顺序由 DAG 管（不是档位管）

定档只决定**步骤集合**（`TIER_STEPS`）；集合内的先后由 `PRE_EXEC_DEPS`（v1.18.0 铺满）决定——
是**有向无环图，不是全线性链**，每步只挡"真依赖它的"（依据分级 A；对标注 C：与 PMBOK 进度网络图
"强制性依赖＋完成到开始"及工作流引擎 DAG 拓扑序同型，见 §九）。

| 步 | 前置（`stage --state doing` 时必须 done/na/skipped） |
|---|---|
| ② | ① |
| ③ | ② |
| ④ | ③ |
| ⑤ | ④ |
| ⑦ | ③ |
| ⑥ | ⑦④⑤（卡没切、验收基线没就绪不许施工） |
| ⑩⑪⑬ | ⑥ |
| ⑫ | ⑬（收尾前先过安检 L1；⑭ 由 outward_claims 门禁管，na 合法） |
| ⑧ | 无（台账是持续动作，不锁前置；⑨ 默认 na） |

- **na/skipped＝显式豁免**：不在本档集合里的步骤自动记 `na`，所以轻量/标准的步骤子集天然跑得通，
  **不需要任何授权**；主动跳过某一步则必须 `stage --id X --state skipped` 留痕，不静默。
- **唯一越序通道**：用户点名单步直调 ⇒ `stage --id X --state doing --skip-auth "授权说明"`——
  前置闸放行并写进 `skip_auths` 留痕（谁点的、什么理由）；口头跳步不算数。
- 对定档的含义：档位定小不会卡死流程（豁免通道在），档位定大也不会自动多跑（集合外步骤是 na）。
  **改档（`--set` 或 `--decide --apply`）不动已 done/doing/skipped 的步骤**——只在 na↔todo 之间搬，做了的功不回退。

## 八、复算示例（照抄可跑，与 selftest A37~A41 同源）

每条给出命令与手算过程；判据改动后这里必须能重新手算对上——对不上＝本表或脚本有一方错了。

```bash
# 1. 改 bug → 轻量（selftest A37）
py scripts/pipeline_state.py mode --decide --signal files_touched=1 --signal has_code=false
#   轻量：+3（≤3 文件、不动代码、非从零）+2（单模块单卡：modules/cards 缺省按 0 计入）＝5；标准 0；企业 0

# 2. 新功能 → 标准（A38）
py scripts/pipeline_state.py mode --decide --signal new_feature=true --signal files_touched=6 --signal modules_touched=2 --signal cards=4
#   轻量 0（files=6，两条轻量判据全灭）；标准：+2(≥4 文件)+2(≥2 模块)+2(新功能)+1(≥2 卡)＝7

# 3. 从零多人 → 企业（A39）
py scripts/pipeline_state.py mode --decide --signal from_zero=true --signal team_agents=3 --signal estimated_days=5 --signal modules_touched=6
#   企业：+2(从零)+2(3 分身)+1(5 天)+2(模块 >4)＝7；标准：+2(≥2 模块)＝2；轻量 0（from_zero 否掉两条）

# 4. 平档 → 退出码 1，摆选项问用户（A41）
```
