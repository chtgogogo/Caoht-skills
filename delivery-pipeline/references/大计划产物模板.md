# 大计划产物模板与盘问决策检查单（阶段①②③ 用）

> **这文件治什么病**（2026-10-15 三平行窗实测：同一规则跑出 11 项与 14 项两种决策覆盖面、一窗漏掉两窗都抓到的高频坑「过去时刻」；产物结构与新鲜度头也随窗漂移）：**问题预设成清单、结构预设成模板**——执行者照单逐项过、照模填空；硬闸验产物在盘。实测详案 → 修订记录·大计划产物模板移出节。
> 本文件是**约定型**规则（本地约定，非外部权威；有效性由"三窗实测差异"自证）。

## §1 盘问决策检查单（12 维底座＋通用增补，磨设计逐项过）

**用法**：磨设计时对下面 12 维底座＋增补维 13 **逐项**给结论——要么写成一条决策（含理由与缺陷），要么写
「经确认：不适用（日期，依据）」。**禁跳项、禁"没想到"**——这正是死角清单的本义：清单里的坑，
不许靠执行者想象力兜底。用户在场逐项问（铁律 15：带推荐的选择题）；用户不在场走 §4 降级协议。

| # | 维度 | 必答的问题 | 高频坑（实测例） |
|---|---|---|---|
| 1 | 对象与状态机 | 核心对象有哪几个状态？谁触发迁移？终态可逆吗？ | 需求只出现两态，执行者自作主张加"进行中/已完成" |
| 2 | **时间边界四问** | ①时钟源（服务器还是客户端）？②**过去时刻允许吗**（能创建/能预约已过去的时间吗）？③边界值含不含等于（"开始后"含开始那一瞬吗）？④时长/频率上下限是多少、含边界吗？ | **「过去时刻」是三窗对比中最高频的漏项**——它同时牵动"演示怎么造出已开始状态"这个坑；时钟源作答须连带交代时区口径（存谁的本地时间、显示用哪个时区），不增问号防与索引名"四问"失配 |
| 3 | 权限与身份 | 谁能读/写/删？无认证时身份从哪来、可伪造吗（如实列缺陷）？ | demo 无登录≠不考虑归属校验——取消权限要落在后端 |
| 4 | 删除/取消语义 | 软删还是硬删？记录保留吗？占用的资源释放吗？谁能操作？何时起不可操作？ | "取消后记录可查"与"显示取消无意义"打架→见 §6 分层裁定 |
| 5 | 冲突与并发 | 同资源双占怎么判？同人双占怎么判？同时提交怎么办（demo 可注明单机无并发）？ | 重叠判定的开闭区间：紧邻（10:00 结束/10:00 开始）算不算冲突 |
| 6 | 数量与容量边界 | 上限怎么校验？超限反馈带不带具体数值？ | "5 人不能约 4 人房"要回显容量数 |
| 7 | 初始数据与空态 | 首次启动播种什么？幂等吗（非空库会不会覆盖）？空列表展示什么？ | 播种覆盖用户数据=重启丢数据的变体 |
| 8 | 展示形态与默认视图 | 默认日期/排序/筛选是什么？展示形态选哪种（表格/时间轴/日历）？为什么？ | 形态选择要给理由，防面试官问"为什么不用 X" |
| 9 | 输入防错 | 自由输入还是档位选择？后端是否重复校验（防绕过前端直调）？ | 从源头防错（档位下拉）+后端硬校验，双保险 |
| 10 | 异常反馈口径 | 错误返回什么结构？人话模板带哪些上下文（对象名/时段/数值）？ | 禁裸 Error/500/堆栈——每类拒绝配具体到对象的中文模板 |
| 11 | 持久化与重置 | 存哪？重启行为？怎么清空重来（删库文件/重置按钮）？ | "数据不能只在内存"是常见硬需求；重置路径要写进用户文档 |
| 12 | 范围裁剪（YAGNI） | 明确不做什么？被面试官/用户问起时的回答口径？ | 裁剪清单显式落盘，把"不做"变成展示点而非短板 |
| 13 | **旧数据与升级兼容**（通用增补） | 存储格式/字段改版后，盘上的旧数据怎么办（迁移升级/拒绝启动/静默丢弃——三选一并写缺陷）？旧版产物还读得动新数据吗？ | 迭代改字段名后旧 data 文件让启动报错或静默丢列——一次性 demo 踩不到，**迭代过一轮的持久化项目必踩**（进底座判据见下） |

> **领域适配**：12 维是通用底座；具体项目在其上追加领域维度（预约类加"资源占用与释放"、
> 交易类加"金额精度与对账"、AI 应用加"评测集与降级路径"…）。追加的维度记进本项目设计纪要，不回改本清单。
> **进底座的判据**（2026-10-15 定）：**任何持久化项目迭代一轮必踩**的才进（维 13 即按此判据增补）；
> 低频或另有归属的不进——国际化/可访问性归维 12 裁剪口径兜底，许可证归技术选型记录缺陷栏，
> 备份恢复 demo 级由维 11 重置路径兜底，密钥/注入/脱敏归《安全基线检查.md》。

## §2 设计纪要骨架（标准/企业档 init 已自动生成——填实后删首行标记）

> v1.16.0 起 `pipeline_state.py init` 会把下面这个结构直接生成到 `docs/pipeline/设计纪要.md`（含骨架标记）；
> 本节代码块与脚本内 `PLAN_STUBS` **一致，改结构两处同步改**。轻量档不自动生成（①一句话版）。
> 骨架行内的「12 维」字样是脚本同步文本、指底座——增补维 13 同属 §3 留痕范围；改这行字样必须连脚本一起改，禁单边动。

```markdown
# 设计纪要 — <项目名>
> 核对日期：YYYY-MM-DD ｜ 对照的事实：<需求源+状态版本>（代码未施工时写明"行为条款为承诺非实现"）
> 产出自交付流水线阶段①。行为条款在 specs/，范围与优先级在 PRD.md，此处不重复抄。

## 1. 交付物定义（铁律 12：谁用/怎么用/第一次交付长什么样，可验证）
## 2. 目的 / 用户 / 约束 / 成功标准
## 3. 盘问决策留痕（§1 检查单 12 维逐项：决策表——每行含 结论/理由/缺陷与翻车场景；推定项标【推定】）
## 4. 核心方案与取舍（含"为什么这样切"）
## 5. 范围裁剪（YAGNI 清单：明确不做的+被问起的回答口径）
## 6. 已知缺陷（如实列出，面试/汇报可主动披露）
## 7. 下一步
```

## §3 PRD 与 spec 骨架（③ 用；PRD 由 init 自动生成，spec 按能力照抄）

> v1.16.0 起 init 也自动生成 `docs/pipeline/技术选型记录.md` 与 `docs/pipeline/PRD.md` 骨架（轻量档除外）；
> 本节 PRD 代码块与脚本 `PLAN_STUBS` 一致，**改结构两处同步改**。`specs/<能力>/spec.md` 的能力名磨设计前未知，
> init 不预生成——按下面的块格式照抄（硬闸只认"文件在盘+无骨架标记"，不管能力叫什么）。

**PRD 骨架**（宪章条数 5–8，C11 硬闸查）：

```markdown
# PRD — <项目名>
> 核对日期：YYYY-MM-DD ｜ 对照的事实：<需求源 + specs 条款号区间> ｜ 行为条款为承诺/实现（择一）

## 项目宪章（5–8 条，每条可判定：带数字/单位/硬词，反例"性能要好"不收；性能阈值按「阈值三件套」＝指标名＋数值＋测量命令，缺测量命令记警——写法见阶段① §3.1）
## 产品定位（一句话）
## 交付物定义（指针指设计纪要 §1，不重抄）
## 核心功能列表（P0/P1/P2；每行：编号｜一句话｜行为条款需求号；P2 无则写「经确认：无（日期，依据）」）
## 用户流程（按用户操作时序）
## 全局验收标准（怎么算做完：机检/测试/走查清单/实测记录，全部指向落盘证据）
## 用户视角走查清单（逐条真点，禁 API 直调代替；铁律 12）
## 技术选型（指针指选型记录，不复述）
```

**spec 骨架**（每能力一目录；块格式=规格层细则 §3，EARS 五型一句一块）：

```markdown
# 主规格 — <能力名>
> 核对日期：YYYY-MM-DD ｜ 对照的事实：<需求节号+推定来源>（代码未施工时写明"行为承诺"）
> 系统当前承诺行为的唯一真源（<域>）。改行为先改这里（走 changes/ 变更包），再动代码。

#### R-<n> | <标题>
<一句 EARS 条款>
- 状态：生效
- 验收：<tests/xxx.py 或 卡号+tests/xxx.py>
- 关键定位：<文件> 的 <标识符>（规划路径；施工后回写真实位置；禁行号）
- 来源：<需求节号 / 推定项出处>

#### 场景：<场景名>            ← 可选增强：多分支行为逐条给；零场景不红（文件聚合警，C15）
- **WHEN** <触发条件>
- **AND** <叠加条件（可选）>
- **THEN** <可观察结果>
```

**需求号纪律**：号发出即不回收（删了也别复用）；新补条款接最大号+1（如 R-23 后补 R-24），
**禁插号重排**——历史卡、证据文件、对话记录都指着旧号。

## §4 自主模式盘问降级协议（用户不在场时）

用户发令"直接做完/别问我"时，盘问不是跳过，是**降级执行**：
1. §1 清单**逐项自答**（底座 12 维＋增补维 13），每条决策照样写结论/理由/缺陷三件套；
2. 凡需求文档没有明文、由 AI 补全口径的，标 **【推定】** 并写"两案对比+选定理由+被否案的缺点"；
3. 推定项汇总进停点文档，请用户下次在场时**逐条复核**（可推翻，推翻走规格变更包）；
4. 恢复点写明"哪些决策是推定待复核"，防止后续窗口把推定当已拍板。
5. **复核回写**（2026-10-15 增补；用户事后复核/推翻时）：结论逐条落盘——设计纪要 §3 的【推定】标记改
   【已复核/已推翻＋日期】，停点清单同步销号；推翻项走变更包落地后按铁律 10 清直接引用面（specs/测试/文档指针）。
   **禁口头推翻不落盘**——不回写，下一个窗口就把旧推定当现行结论（过期情报同款病）。

## §5 新鲜度头（R6 推广到大计划产物）

大计划产物（设计纪要/技术选型记录/PRD/specs 主规格/变更包 proposal）**一律**在文件头部带：

```markdown
> 核对日期：YYYY-MM-DD ｜ 对照的事实：<它依据的需求/状态/代码版本>
```

代码未施工的产物加一句「行为条款为承诺非实现」——防读者把承诺当现状。（原 R6 只挂叙事层，v1.15.0 起推广到大计划产物；沿革 → 修订记录·大计划产物模板移出节。）

## §6 两条配套口径（三窗实测提炼）

1. **矛盾需求分层裁定**：需求两条打架时（例："取消后记录须可查" vs "显示被取消没意义"），
   按层拆——**数据/规格层保留可验证的行为承诺，呈现层从简**；裁定过程留设计纪要或 ADR，不回改需求原文。
2. **证据作废留痕**：实测证据（测试输出/校验输出）发现自身缺陷需要作废时，改名为 `作废-<原名>` 保留在
   evidence/ 并另存新证据——**不删除**（作废证据是"尺子曾经不准"的证词，删了等于掩盖校准历史）。

## §7 结构锚与 README 骨架（v1.17.0）

**结构锚**（脚本 `pipeline_state.py` 的 `STRUCTURE_ANCHORS`）：九件产物（六件＋三份计划产物）各有一组
无节号子串锚（如 AGENTS.md 必含「文档登记表」、故障对照表必含「贴给 AI 的原话」、设计纪要必含「盘问决策」）。
① done 后 `check` 逐件验——**缺锚记「警」不是红**（老项目与刻意自定义结构不炸，但当场点名）。
锚的边界＝只查「在盘且已脱离骨架态」的件、只锚结构块在不在——缺件/仍带骨架标记归硬闸管，
内容对错归语义面（出题验收与 spec_check）；此边界与脚本 `structure_anchor_misses()` 实现逐条对读过（2026-10-15）。
改骨架结构=改 `DOC_STUBS`/`PLAN_STUBS`＋同步改 `STRUCTURE_ANCHORS`＋同步改本文件 §2/§3，三处一致。

**README 骨架**（施工段产物，不随 init 生成——运行命令未定时生成即空头；⑭ 口径检查前按此结构写；
不在 `STRUCTURE_ANCHORS` 九件内——脚本对 README 只在 ⑭ 出「门禁警告」，无锚校验）：

```markdown
# <项目名>

> 一句话：这是什么、给谁用。
> AI 协作披露：本项目由 AI（<工具/模型>）辅助开发，过程记录见 <会话记录位置>。

## 快速开始（3 步内跑起来）
1. <装依赖命令>
2. <启动命令（唯一一条）>
3. 浏览器打开 <地址> → 应看到 <什么>

## 功能一览（对应 PRD 编号）
## 演示动线（面试/汇报用：按序号点，每步预期看到什么）
## 测试与验证（命令＋退出码口径＋证据位置 docs/pipeline/evidence/）
## 常见问题（指向 docs/human/故障对照表.md，不重复抄）
## 技术栈与理由（指针指 docs/pipeline/技术选型记录.md，不复述）
```
