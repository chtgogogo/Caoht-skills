# 阶段⑥ 执行与派遣 + 阶段⑪ 评审

> 两种执行模式，探测环境后自动选，用户可覆盖。产出物：完成的代码 + 更新后的卡状态 + 台账行。
> 🔴 **v1.14.0 开工硬闸**：`stage ⑥ --state doing` 前，⑦④⑤ 必须已 done（na/skipped 算显式豁免）——卡没切、验收基线没就绪不许施工（Qoder 实测：④⑤ 还是 todo 就写完 755 行代码）。顺序硬闸在脚本里，退 4。
> 🔴 **v1.18.0 口径更新——前置已铺满全 DAG**：上句只是旧口径的一格，现在依赖表铺到**每一步**（`PRE_EXEC_DEPS`，见 `scripts/pipeline_state.py`）：⑥ 的前置仍是 ⑦④⑤，另有 ②←①、③←②、④←③、⑤←④、⑦←③、⑩⑪⑬←⑥、⑫←⑬ 等；`--state doing` 逐一验，前置未满退 4，na/skipped 算显式豁免。**本文件不抄整张表**（抄了会过期），开工被拒就现读脚本那张表。
> **单步直调跳步留痕**：用户点名某一步（SKILL.md §一）时，`stage --id X --state doing --skip-auth "授权说明"` 凭点名放行，账上进 `skip_auths`（哪步、凭什么、何时，台账可查）；**批量跑流水线时前置未满就是闸**——不许拿 `--skip-auth` 当万能钥匙，不带它口头说跳步照旧退 4。

## §1 模式探测与选择

| 环境 | 模式 | 说明 |
|---|---|---|
| 当前工具支持派生子代理（某宿主 / Claude Code 等） | **自动子代理模式** | 主会话当项目经理，逐卡派遣，可自主连跑多卡不偏航 |
| 不支持子代理，或用户想亲自控节奏 | **提示词卡模式** | 主会话为每卡生成一张"新窗口提示词卡"，用户复制粘贴到全新对话执行，完成后把结果带回 |

探测方法：尝试调用子代理能力（或查工具说明）；不支持则自动落提示词卡模式并告知用户。**用户随时可说"这张卡我自己开窗口跑"。**
执行模式（子代理/提示词卡）不进 `state.json`——里面的 `mode` 字段存的是流程档（轻/标/企），两回事别混写；可逐卡换模式（有的卡派子代理、有的用户自己开窗），用户覆盖一律以用户说的为准。

## §2 自动子代理模式（superpowers: subagent-driven-development）

每张卡的派遣循环：

1. **装配上下文（最小化铁律）**：只喂给子代理——该卡全文 + PRD 相关章节 + 涉及文件的精确路径 + 全局约束（编码纪律＋**项目宪章那 ≤8 行**，它是每张卡的隐式禁改清单，见 `阶段①磨设计与选型.md` §3.1）+ **模块地图**（项目已有则附路径，执行窗按 §4 三步先读图定向再动手）+ **本卡覆盖的需求号对应的规格条款**（`specs/**` 里那一个块，不是整层规格）。**绝不喂**：其他卡的过程、对话历史、全项目文件。

   **卡类型 → 上下文包对照表**（按卡的*类型*配包，与按*大小*裁档正交：小卡也可以是接口卡；两轴都要过。包的内容仍受铁律 5 约束——**只多不少，宁缺勿滥**）：

   | 卡类型 | 必带（除卡全文外） | 明写不带 | 判据（这卡的验收看什么） |
   |---|---|---|---|
   | **地基卡**（建表/建骨架/首个流程打通） | PRD 的 P0 段＋设计纪要核心方案＋模块地图骨架＋技术选型记录「已定案」列 | 其他卡的过程、历史对话 | 结构能不能立住：启动命令、表存在、最小流程跑得通 |
   | **接口卡**（API/契约/前后端对接） | 该需求号的规格块＋**调用方**文件精确路径＋错误反馈口径（`specs/**` 的不期望行为句式） | 无关模块的实现全文 | 契约：入参出参错误码三类都按规格，返回人话不是 `Error` |
   | **业务规则卡**（校验/状态机/时间判定） | 该需求号的规格块＋**同类规则**已有实现的位置（防第二处重复实现）＋测试与变异验证要求（第 8 节） | UI 层细节、样式文件 | 边界值全绿＋先红后绿＋变异必红 |
   | **界面卡**（页面/组件/交互文案） | 交付物定义（铁律 12）＋需求定位表或用户流程段＋禁用"API 直调作弊"的明写 | 后端实现全文 | 用户视角验收卡：非开发者点得通、文案是人话 |
   | **收尾卡**（文档/地图定稿/对外口径） | 小白版作废登记那一格＋⑫ 收尾清单＋⑭ 口径四件套 | 生产代码 | 证据落盘、说法固定、数字带四件套 |

   五类只是**打包配方**，不是新的角色系统——执行者仍是同一个子代理，别为每类造一个"人设"（角色化派工的坑是把打包复杂度误当成角色数量）。

   **派遣前四查（缺一不派，先补源再派）**：① 卡全文在盘且过了 `plan-review`（卡是派给执行方的**唯一契约**，卡里的洞会被放大成整张卡的返工——SKILL.md「外围交接」）；② 包里每个「必带」都解析成**实际存在的路径**（规格块在 `specs/` 真翻得到、调用方文件在盘、模块地图在盘）——解析不到就回 ⑤ 补卡或补资料，**禁空手派遣**（执行者拿不到东西就会自己编）；③ 卡面【依赖】的前置卡已 done（铁律 6 接力顺序；要并行先问用户）；④ 按档与模式定好评审配置（触发判据见 §2.3 与下文阶段⑪）。
   > 依据（B 级，Anthropic 官方工程博客，2025-06）：子代理指令须含**四要素**——目标、输出格式、可用工具与资料、任务边界；产出直接写盘、只回传**轻量引用**（与铁律 13 同向）。完整对标 → 修订记录·阶段⑥移出节。
2. **派遣执行**：子代理按卡实现；**开工前提问窗口**——执行者对卡面有不明（缺上下文/验收歧义）先提问再动手，不猜。返回按**四值状态**：DONE ／ DONE_WITH_CONCERNS（完成但有隐忧，须列出）／ BLOCKED ／ NEEDS_CONTEXT（缺料要补）——BLOCKED 时主会话按分诊四步处置（补上下文 → 换更强模型 → 拆小卡 → 回⑤改卡），**禁原样重派烧轮次**。返回物三件：改动文件清单 + 验收命令**完整输出** + 一段完成摘要；清单与摘要在对话里走，**验收输出必须落盘**（卡面验收路径或 `<落盘目录>/evidence/`，铁律 13）——对话里说一句"绿了"不算数；子代理只回**输出文件路径**，主会话按 §2.5 过卡链核盘，不转抄内容。**同形批量小活一单派遣**：N 处同构小改（如同一批文案替换）合并一张卡派一次审一次，不逐处开卡。
3. **双评审**（触发判据：企业档，或自动子代理模式——铁律 7 原文口径；两者都不占时只做下文阶段⑪的卡级评审。用户逐卡明说"这张免双评"可豁免，记台账）：评审 A（设计符合·三值结论）＋评审 B（代码质量·三档）的判据、过卡口径与独立性红线**正本在下文阶段⑪卡级评审，此处不重抄**。
4. **阻断处理**：有阻断级问题 → **先全部读懂评审意见再动手**（不懂第 4、5 条时连 1、2、3 也不做——意见之间可能相关，改一半会切断相关性）→ 带评审意见**重派同一子代理任务**（新分身，附：上一轮评审意见全文 + 已改事项清单）→ 再评审。执行者对每条阻断要么修掉、要么书面说明为何不成立（反驳由评审员复核），禁口头认下不改。**最多 2 轮，仍不过就停下升级给用户，不许第 3 轮自作主张**。
5. **过卡链**（顺序自上而下，逐件有验收物；**每一件都要能被下一个窗口核盘复核**——文件在盘、退出码 0、提交号查得到，缺任何一件不算过卡）：
   - **5.1 验收复核**：卡的验收清单逐条过（双评审或卡级评审结论），阻断＝0；对照物是卡面验收与该卡覆盖的规格条款。
   - **5.2 证据落盘**：验收命令完整输出在盘（铁律 13；路径写进卡回执区），改前改后各跑一遍的记录同标准。
   - **5.3 状态与台账**：经脚本把卡标 done——`card --state done --metric <实测数字>`（**metric 为空脚本退 4**，"状态只有实测值"是代码不是规矩，见台账模板.md §命令表）；并推进 `stage ⑥`，阶段四字段（输入版本/产物位置/完成条件/恢复点）写满、登记的产物路径在盘，缺了退 4（铁律 19）。台账"做完"区由 `render` 生成，禁手改（铁律 17）。
   - **5.4 模块地图回写**：用真代码校准本卡【动到的模块】行——补定位/改依赖/摘🔧标记，只动本卡行、不重构全表；缺回写不算过卡（铁律 16；细则=`模块地图.md` §3 防漂移五规则）。
   - **5.5 小白版作废登记**：填「本次改动有没有让小白版某句话变成假的：是（哪页哪句）／否／待查」——填"是"或"待查"就把该页记进 `<落盘目录>/上下文体检.md` 的待对账清单，**别当场通读重写**；它登记的是"哪句要重写"，不是"改了啥"，后者归 ADR 与提交记录（细则=`项目文档与上下文规范.md` §4／§5.1／§6）。这一格是**当场那道**防腐烂机制，第二道是定期出题与对账，两道都要，缺这一格就是没填完。
   - **5.6 变更包归档触发**：本卡是某个变更包的最后一张 done 卡 ⇒ 走 `规格层-主规格变更与归档.md` §5 五步（增量并回主规格 → 整包搬进 `changes/archive/<日期>-<slug>/` → `action --idem-key` 记账 → 跑 `spec_check` **退 0** → 原始输出落盘）；**没归档不算这个变更包做完**（铁律 21③），C09 会一直红着。不是末卡则此件跳过——回执区记一句"非末卡，未触发"，不留空白。
   - **5.7 git 提交**：信息含卡号；提交后核提交号可查（`git log`/`git cat-file`——⑭同款口径，引用不存在的提交号＝阻断）。
   - **5.8 下一卡**：有依赖的按卡面【依赖】依次接力；无依赖的并行先问用户（铁律 6）；每完成约 1/3 卡数 → §4 里程碑回看。

## §3 提示词卡模式（无子代理环境的等价物）

为每张卡生成一段可直接复制到新对话的提示词，内含：

```text
你是本次任务的执行工程师。只做下面这一张卡，做完即停：
【此处粘贴整张卡文件内容】
全局约束：{编码纪律/代码风格一句话}＋{项目宪章 ≤8 行原文，逐条贴，别让新窗口自己去猜}
完成后输出：改动文件清单 + 验收命令的完整输出（落盘到 <evidence 路径>）+ 三句话总结。
规则：卡面有不明先提问再动手；不得再生分身（不派 helper/reviewer，套娃=token 黑洞）。
```

用户带回结果后，主会话按 §2.3-2.5 相同标准验收、更新台账。**用户也可以选择自己亲自执行**——卡模板已按"有判断力的成人"写好。
带回的证据形态同 §2.2：验收输出落盘、主会话核盘。此模式不触发双评审强制（非子代理模式，§2.3 触发判据不命中），卡级评审照做（下文阶段⑪）。

## §4 里程碑回看联动

每完成约 1/3 卡数，暂停派遣，执行 里程碑回看.md（见该文件），再继续。

# 阶段⑪ 代码评审（两层）

## 卡级评审（每次派遣后，轻量）
- 评审 A（设计符合）：对照卡的验收清单与该卡覆盖的规格条款逐条判定，每条只许出三值结论——**过／不过／判不了（判不了按不过算）**，全过才算过；判据是卡面与规格原文，不是评审员品味。
- 评审 B（代码质量）：按三档报，**分档判据可判定、不靠语感**：
  - **阻断**：验收清单有一条不过；踩项目宪章或卡面禁改清单；实现与规格条款行为矛盾（规格说"拒绝"、代码改成"警告"这类机械尺查不到的语义漂移，也在评审面）；**规格沉默≠许可**——规格没写的输入搞坏了程序时，按"合理用户会期待什么"评级，仍可判阻断；安全隐患（与⑬ L1 同级——铁律 10 教训锚点：安全曾整体漏网于卡内验收）。
  - **建议**：能合但该改（命名/重复/边界风格）——不挡卡。
  - **备忘**：只记录不修——不挡卡。
  - **过卡判据＝阻断为 0**。每条阻断给定位：文件＋标识符（禁行号当锚点，行号是快照必漂，铁律 20③ 同口径）。
- 输出：评审意见落盘（卡回执区或 `<落盘目录>/evidence/`）——对话里说"没问题"不算输出。
- 独立性：评审 A/B 用独立子代理（或新窗口），执行者不自评（铁律 20②）。**模型级独立性（v1.25.0）**：碰钱/碰安全/碰对外口径的高危卡，评审 B 强制换不同模型家族执行——上下文独立 ≠ 模型独立，同家族两个子代理共享同一套偏好与盲区（LLM 自偏好实证：NeurIPS 2024 arXiv:2404.13076 一系），「共同误读」双评审会同穿；普通卡维持同家族即可。回执区记一格「评审员家族：同/异」供审计现读。
- 判不了的事项列"Declined to judge"清单交主会话裁决，**禁静默丢弃**。

## 里程碑总评审（每 1/3 进度，企业模式，重量级）
- 跨卡一致性：接口风格、错误处理、命名是否统一
- 架构漂移检查：实现是否还长在设计的样子
- 性能与安全抽查
- 产出：回看报告.md 的评审章节；阻断项回炉（回炉＝§2.4 阻断处理同款：附意见重派，最多 2 轮，仍不过升级用户）。
