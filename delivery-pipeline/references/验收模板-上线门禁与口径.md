# 验收模板 · 上线门禁与对外口径

> **本文件是验收模板**：新项目复制到 `<项目根>/ACCEPTANCE.md`（整份或按节取用）后逐项填写。三节配载：S 安全基线【必选：所有项目收尾前，纯文档项目也跑——静态自检＋敏感信息/本机绝对路径扫描】、K 对外口径【有对外输出（README/简历/汇报/作品集）的项目】、F 收尾推送【要推 GitHub / 交付的项目】。
> **版本锚定**：本表同步至 Cao-交付流水线 v1.28.0 批细则（2026-10-27 核对）。复制到项目时把头部「复制自版本」填成当时的 skill 版本并锁定，skill 升级不追溯已归档项目。
> **同步状态自检（模板过期判据）**：S 节条目编号须与 `references/安全基线检查.md` §二 L1 清单一一对应（S<号>=细则 #<号>，含【追加】项），K 节须与 `references/对外陈述口径检查.md` §二 清单一一对应；对不上＝本模板过期，**以上游细则为准补齐再用**。
> **分工与权威（钉死的口径）**：本文件是**项目侧复制即用清单**（把检查送到项目现场），不是第二套标准——判定标准与报告结构的**权威＝两份上游细则**（⑬＝安全基线检查.md，⑭＝对外陈述口径检查.md，后者 §周边指针 已声明同款规则）；凡本表与细则冲突，**一律以细则为准**；细则增删条目时同步增删本表（编号跟随细则，只追加不顺延）。报告骨架只在细则维护一处、本模板只指针不抄：安检报告结构＝安全基线检查.md §五 六节骨架；口径核查表结构＝对外陈述口径检查.md §六 骨架——结构照抄逐格填、零发挥（「全部无」也要落盘写「经确认：无…（日期，依据）」，禁空白禁「暂无」）。
> **执行方式**：把本文件喂给 AI Agent，逐项给出**三档判定**——「通过 / 阻断 / 不适用」＋证据。判定口径：通过＝按方法查过且不命中阻断标准；阻断＝命中阻断标准；不适用＝该项与本项目形态无关，**必须附一句话依据，禁空跳**。🔴 与 project-acceptance 验收官的五态判定（通过/有条件通过/待确认/不通过/N-A）是两套口径，不混用不换算（SKILL.md 外围交接：外部判定不改写本流水线口径）。证据口径：**文件:标识符（禁行号——行号是快照必漂，铁律 20③）或 命令＋输出摘录**；命令原始输出落 `<落盘目录>/evidence/`、文件名带日期戳（铁律 13）；证据里的 commit/路径/符号须当场一条命令验证（`git cat-file -t`／`test -f`／`grep -n`），引用不存在对象＝阻断。产出双报告落盘：`docs/pipeline/安检报告.md` 与 `docs/pipeline/口径核查表.md`——没有产出物的检查＝空转。工具优先：能用工具的不肉眼，工具只覆盖约一半，其余走查。检完登门禁机器面：`gate --name security_L1 / outward_claims --value passed --evidence <对应报告路径> --apply`（值域四态与硬闸＝`scripts/pipeline_state.py`；复跑改判后必须重登）。
>
> **两节的分工**：S 节管「可被攻击的风险」（漏洞视角），K 节管「说出去的话站不站得住」（第三方核对视角）。两边的阻断项同等效力——不许带着阻断项收尾或投递。

## S 节 · 安全基线 L1（收尾前必检，约 30–45 分钟；触发式加检另计）

> 判定口径与细则同源：每条**不加解释就能判「过/不过」**；不适用写「不适用＋一句话依据」，禁空跳。
> 编号映射：S<号>＝安全基线检查.md §二 L1 #<号>；S13–S15 为细则追加项，本表跟随追加。
> 🔴 工具化六项（S1/S2/S7/S8/S12/S15）先跑 `security_scan.py scan --root <项目根>`（随库脚本，纯标准库）
> 输出落 evidence/ 再人工判级；工具没抓到≠该项通过，人工面照旧（判据=细则 §二 前言）。

| # | 检查项 | 方法 | 阻断标准 | 结果 |
|---|---|---|---|---|
| S1 | 密钥/凭据硬编码 | grep `sk-`、`secret`、`password`、`api_key` 字面量；`git log --all -S <密钥名>` 查历史 | 源码/示例/测试出现可用凭据=阻断；历史残留→确认密钥已在服务商处作废 | ☐ |
| S2 | 配置默认值审计 | 逐个检查安全类配置（密钥/管理员码/库密码）；**弱默认清单＝空值、`secret`/`changeme`/`admin`/`123456`/`test`/`default` 字面量、与项目或框架同名的值**；再查部署面（生产 env/docker-compose/部署脚本）是否显式覆盖 | 安全项为弱默认值且部署文件未覆盖=阻断 | ☐ |
| S3 | DEBUG/开关连坐 | 找所有 `if DEBUG` 分支，确认 DEBUG 不牵动限流/验证/加密等安全行为 | 连坐=阻断，解法=拆独立开关 | ☐ |
| S4 | 鉴权覆盖矩阵 | 列出全部路由逐一标注鉴权方式，找「全挂了唯独它没挂」的 | 存敏感数据的接口无鉴权=阻断 | ☐ |
| S5 | CORS 策略 | 查 `allow_origins` | 生产配置含 `*` 与 credentials 并用=阻断 | ☐ |
| S6 | 授权字段自报 | 搜请求体 role/permission/is_admin 字段，核对服务端是否从已认证身份**派生**而非采信 | 自报可操纵状态=阻断 | ☐ |
| S7 | 注入防御抽查 | SQL 必须参数绑定（禁拼接/f-string）；用户输入进 `eval/exec/shell/反序列化` 的按敌意数据**白名单**校验（类型/长度/格式/取值范围，禁黑名单） | 拼接 SQL 或 eval 用户输入=阻断 | ☐ |
| S8 | 输出编码 | 返回前端的动态内容按场景转义；`v-html`/`innerHTML` 标注来源 | 用户可控内容直插=阻断 | ☐ |
| S9 | 暴力破解面 | 「码/验证码/token 验证」端点有无尝试次数限制；比较是否恒时（compare_digest） | 无限次可穷举=阻断 | ☐ |
| S10 | async 阻塞扫描 | `async def` 路由里有无秒级同步调用（LLM/推理/大 IO） | 有=阻断（改 def 或 to_thread） | ☐ |
| S11 | 死代码扫描 | 未被调用的函数、一运行就崩的文件、前端接线后端不存在的按钮 | 带 AI 协作注释的死文件=阻断（删） | ☐ |
| S12 | 敏感词/临时调试残留 | print 调试、TODO 密钥、注释里的生产地址；**判级：轻度＝失效 print/TODO 注释；重度＝注释或文档里的真实生产地址/邮箱/手机号、TODO 或被注释掉的真实密钥/安全逻辑** | 轻度=建议，重度=阻断 | ☐ |
| S13 | 【追加】水平越权（对象级授权/IDOR） | 列出全部「按标识取/改/删」的接口（路径或查询参数里的 id/编号/单号），逐一核服务端是否校验「该对象属于当前已认证主体」；无用户体系的项目核匿名能否改他人数据 | 换对象标识即可读/改/删不属于自己的数据=阻断 | ☐ |
| S14 | 【追加】错误响应泄漏 | 人为触发一次错误（坏参数/不存在的 id/缺 token）看响应体；grep 全局异常处理与框架 debug 配置 | 生产形态下错误响应含堆栈、内部绝对路径、SQL/框架报错原文=阻断（堆栈只进日志） | ☐ |
| S15 | 【追加】本机绝对路径与隐私数据残留 | grep 契约扫**当前树与暂存区**：`[A-Za-z]:\` 前缀、`/home/`、`/Users/`；隐私真实字面量（姓名/手机号/邮箱/证件号样式）同 S1 扫全历史 | 绝对路径进代码/配置/文档/脚本=阻断（对外一律相对化）；隐私真实字面量=阻断（换合成数据）；**本项证据同时供 F4/F5 与 ⑫ 推前检查引用，同一次扫描不重扫** | ☐ |

**触发式加检**（项目含该特征才检；检了进安检报告 §1 表，判据同上）：

| 触发特征 | 检查项 | 阻断标准 |
|---|---|---|
| 服务端按用户可控 URL 发请求（URL 导入/头像/webhook/预览） | SSRF | 无 scheme+host 白名单直连用户可控 URL=阻断 |
| 有任何文件上传入口 | 上传面 | 类型黑名单／无大小上限／存储目录可执行=阻断 |
| 有 WebSocket/SSE/本地端口等非 HTTP 面 | 非 HTTP 鉴权 | 敏感通道不在 S4 矩阵内=阻断（矩阵必须含它们） |
| 签发 JWT/session 令牌 | 会话令牌失效 | 令牌无过期时间，或登出后旧令牌仍可用=阻断 |
| 项目含 LLM/Agent 调用 | AI 特有面四查（OWASP LLM Top 10:2025） | ① 提示注入面：用户输入不经隔离拼接进系统指令=阻断；② 过权：Agent 工具/写权限超出该功能必需最小集=阻断；③ 输出处理：LLM 输出未经校验直进 eval/exec/shell/HTML=阻断；④ 系统提示泄漏：接口会回显系统提示词=阻断 |

> L2 上线前附加（真机部署时追加）：认证端点限流、请求体护栏、响应脱敏、密码 bcrypt/argon2、HTTPS、审计日志 append-only、容器固定版本非 root、`pip-audit`/`npm audit` 高危处理、安全响应头基线（nosniff/反嵌套/HSTS）、CSRF（仅 Cookie 会话态接口；纯 token-header API 写「不适用」）。L3 企业级（SBOM/事件响应承接/IaC/K8s/许可证扫描/DAST），逐项再判适用性——**售欧盟命中时 SBOM 必检＋事件响应承接必过**（判据=细则 §四/§九/§十：支持期≥5 年声明、SLA 表为「本库约定」、SRP 上报时钟表）；**档位未点亮也要落盘写明**（例：「L2 未点亮：无 deploy/public_net 信号（<日期>，state.json 门禁区）」），禁空白禁「暂无」。安检报告头部含**签核三栏**（签核人/签核日期/异议）——compliance 命中时必填，机检 `security_scan.py check-signoff`（报告结构=细则 §五，本模板不抄）。

## K 节 · 对外陈述口径（有对外输出必检；确无对外物→整节写「经确认：无对外物（日期，依据）」，gate 记 na，不空跑）

**四条核心规则**（可判定口径表、日期取值顺序、正反例全文＝对外陈述口径检查.md §一，权威在彼）：① 任何对外数字必须齐**四件套**（来源命令 / 样本量分母 / 统计口径含置信区间 / 生成日期）；② **过期即禁写**——数字日期早于最后一次评测日期就不许对外写；③ **引用必须可验证**——commit/路径/函数名要能被一条命令证实；④ **AI 协作必须披露**——署名带 AI 标识、README 声明参与范围。

> 编号映射：K<号>＝对外陈述口径检查.md §二 #<号>；K13 为细则追加项，本表跟随追加。

| # | 检查项 | 方法 | 阻断标准 | 结果 |
|---|---|---|---|---|
| K1 | 对外数字齐四件套 | 逐个数字查来源命令/样本量/口径/日期（判定口径见细则 §一 规则 1 表） | 缺任一 → 删除或补齐 | ☐ |
| K2 | 数字不过期 | 比对 `@日期` 与最后一次评测日期（取值顺序见细则 §一 规则 2） | 早于 → 重跑或删除 | ☐ |
| K3 | commit/路径引用有效 | `git cat-file -t <commit>` / `test -f <file>`（或等价命令） | 引用不存在对象 → 阻断（幽灵引用比不写更糟） | ☐ |
| K4 | 比率分母交代 | 查每个百分比的样本量（评测集条数**现数实测**，不抄文档自述） | 未说明 → 阻断；分母 < 30 ⇒ 数字只可与样本量同框出现，禁单独引用 | ☐ |
| K5 | 小样本加不确定性说明 | 样本 < 100 的对外指标 | 无置信区间且用于对外结论 → 阻断 | ☐ |
| K6 | 「训练/微调」有指标落档 | 找 mAP/loss/评测报告 | 声称训练过但无指标 → 不许写「训练」 | ☐ |
| K7 | 权重/数据集可获取 | 查获取路径与许可 | 别人拿不到 → README 说明来源或标「私有」 | ☐ |
| K8 | AI 署名带标识 | `git log --format='%an <%ae>'` 逐个看 | 真人化假名/假企业域名 → 阻断 | ☐ |
| K9 | README 声明 AI 参与范围 | 读 README 披露段（正例格式见细则 §一 规则 4） | 无声明 → 补 | ☐ |
| K10 | 简历/作品集与仓库一致 | 逐条对照主张与仓库事实 | 任一主张无法在仓库验证 → 改简历或改仓库 | ☐ |
| K11 | 无「用考卷练题再考同一张卷」 | 查评测集是否同时用于调参与汇报 | 是 → 必须标注并补独立验证集 | ☐ |
| K12 | 「杜绝/100%/全部」有全量证据 | 查是否为跳过的检查 | 未全量验证 → 降级为「已验证范围：X」 | ☐ |
| K13 | 【追加】同一数字多处同源同值 | 各对外物互相比对＋与单一出口文件比对＋与实测数比对 | 任一处不同值 → 全部改指单一出口或改正（"395 vs 398""49 题 vs 52 条"类矛盾即此项） | ☐ |

## 验收结论

- 放行标准：S 节零阻断 + K 节零阻断（有对外输出时；确无对外物记 na 并留依据）+ F 节全勾（要推送时）。L1 全绿报告是收尾（⑫）的放行凭证。
- 机器面登记：L1 → `gate --name security_L1 --value passed --evidence docs/pipeline/安检报告.md --apply`；K 节 → `gate --name outward_claims --value passed --evidence docs/pipeline/口径核查表.md --apply`（确无对外物记 `na`）。复跑改判后必须重登 gate——报告改了而 gate 没动＝机器面与人写面分叉。
- 阻断项处理：切修复卡修复 → **复跑该节**（留「修复前＋复跑后」两次记录，只写"已修复"不留复跑输出=未修复），全绿放行并重登 gate。改口径四选一：改简历 / 重跑评测 / 补证据 / 删数字。
- 版本锁定：复制到项目时在头部填入「复制自版本」；项目归档即锁定该版本，模板源头升级不追溯本项目。
