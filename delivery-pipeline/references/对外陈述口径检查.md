# 第⑭步 对外陈述口径检查（收尾前必跑）

> **为什么单开一步**：⑬是**漏洞视角**、编码准则是**写码视角**，都不管"**说出去的话**"；而对外陈述（简历、README、汇报、面试口述、作品集）是**唯一会被第三方拿去核对的东西**——核对不过，前面十三步再规范也白做。
>
> **定位**：全局维度，与⑬并列，不属于任何单卡。凡有"对外输出"的项目，收尾（⑫）前必跑。
> **产出物**：`<项目根>/docs/pipeline/口径核查表.md`（没有产出物的检查＝空转；结构照 §六 骨架填）。
> **阻断语义**：本步发现的"口径失实"项，与⑬的 L1 阻断项同等处理——**不许带着失实口径收尾/投递**
> （铁律 11；机器面硬闸：`pipeline_state.py check` 对「已完成但 outward_claims=pending」判红，流转见 §七）。
>
> **周边指针（同一条规矩只在一处，本步只执行不自建）**：
> - 「对外数字**单一出口**」（散落在各对外物里的数字一律视为过期候选）——口径归 `references/项目文档与上下文规范.md` §1，本步照它扫描；
> - README 的**结构骨架**（含「AI 协作披露」行）——`references/大计划产物模板.md` §7，⑭ 前按它写、按它查；
> - 门禁**机器面**（gate 四态值域／证据字段／check 硬闸）——`scripts/pipeline_state.py`，本步 §七 只写操作口径；
> - 项目侧**复制即用清单**——《验收模板-上线门禁与口径.md》K 节（复制件锁版本；判定标准冲突时以本文件为权威）。

## 一、四条核心规则

### 规则 1：数字四件套（缺一不可）

任何一个对外的数字，必须同时具备：

| 要素 | 说明 | 反例 |
|---|---|---|
| **来源命令** | 能复现的一行命令 | "跑过测试" ❌ |
| **样本量 / 分母** | 这个比率是在多少样本上算的 | "拦截率 100%"（分母只有 3 题）❌ |
| **统计口径** | 是 F1 / 准确率 / 召回？含 95% 置信区间 | "控制集 95.5%"（不说是什么指标、不说样本独立性）❌ |
| **生成日期** | 这个数字是哪天跑出来的 | 无日期 → 无法判断是否过期 ❌ |

**填写示例（合格）**：

```
398 tests collected；396 passed / 2 skipped / 0 failed；wallclock 413.84s（6分54秒）
命令：.venv\Scripts\python.exe -m pytest tests -q
日期：2026-09-23
```

**填写示例（不合格）**：

```
全量 13 秒跑完 395 个用例    ← 无命令、无日期、数字与仓库自记（7m37s~9m50s）矛盾
```

**每件的可判定口径**（审的时候照此判，不靠感觉）：

| 要素 | 判定"有"的标准 | 判定"没有"的情形 |
|---|---|---|
| 来源命令 | 一条**在此刻仓库状态（HEAD）下可复跑**的完整命令；原始输出按铁律 13 落盘 | 只说"跑过"；命令缺路径/参数无法复跑；只在对话里说过、没落盘 |
| 样本量/分母 | 写明 N 是什么且**实测过**（评测集条数当场数，不抄文档自述——"49 题"实测 52 条的教训） | 只给比率不给 N；N 抄自另一份文档未经实测 |
| 统计口径 | 指标名＋计算式或口径说明；比率类小样本带置信区间 | 只给百分数不说是哪种指标 |
| 生成日期 | 以**落盘证据件上的日期戳**为准（文件名或文件内首行，如 `*-20261015.txt`） | 无日期；拿文件 mtime 充数（git 操作会改 mtime，不可靠）；口头转述的日期 |

### 规则 2：过期即禁写（时间戳铁律）

**任何数字的"生成日期"早于"最后一次跑评测/测试"的日期 → 不许对外写。**

- 这一条是硬性阻断，不是建议。它一次性能防住"抄历史快照"这类错误。
- 落地方式：给每个对外数字打 `@日期` 标记，投递/发布前扫一遍，凡 `@日期 < 最后一次评测日期` 的，**重跑或删除**。
- **配套要求**：CHANGELOG 里每一条数字记录**必须带日期**（这是规则 2 能执行的前提）。

**两个日期都从固定地方取，比对才可操作**：

- **数字的生成日期**：只认落盘证据件上的日期戳（判定口径见规则 1 表格末行）。
- **"最后一次评测日期"的取值顺序**：① `<落盘目录>/evidence/` 下最新一份**全量**评测/测试原始输出落盘件的日期戳（⑫ 收尾第 1 步的产物）；② 该件缺失时，取 `state.json` ⑫ 阶段四字段里的产物位置与时间；③ 两者都没有 ⇒ 本项目从未跑过全量 ⇒ **一切评测数字禁写**（这不是豁免，是加倍禁写）。
- **扫描范围只认单一出口**：对外数字集中在出口文件（如 `docs/numbers.md`，口径归 `references/项目文档与上下文规范.md` §1）；散落在 README／简历／汇报稿里的数字一律视为过期候选，逐个清出或改成指针。实操：对每件对外物跑一遍数字扫描（`grep -nE '[0-9]+(\.[0-9]+)?%|[0-9]+ *(个|条|题|秒|分|分钟|小时|tests|cases)' <文件>…`，PowerShell 等价 `Select-String`），命中逐个配四件套。

### 规则 3：引用必须可验证

报告、README、简历里出现的每一个 **commit 号 / 文件路径 / 函数名 / 数字**，都必须能被一条命令验证。
**引用不存在的对象 = 阻断**（等同没写，且比不写更糟——它会让整份报告的可信度归零）。

**核查命令模板**（判据＝一条命令、退出码可判；任何 shell 等价实现都算合格）：

```bash
git cat-file -t <commit>   # 提交是否存在（fatal: Not a valid object name = 幽灵引用）
test -f <file>             # 文件是否存在（Windows PowerShell 等价：Test-Path）
grep -n <函数名> <file>     # 符号是否存在（PowerShell 等价：Select-String）
```

**真实教训锚点（2026-09-23）**：一份安检报告三次引用幽灵提交 `dbaf112` 作"密钥已处理"证据，`git cat-file -t` 返回 fatal——**一份安全审查报告引用了不存在的提交，比不写这条更致命**（详案 → 修订记录·对外口径移出节）。

### 规则 4：AI 协作必须披露（署名与范围）

- **Agent 角色卡的署名必须带 AI 标识**：`Agent` / `CaoHT (AI Agent)` 等，**不得使用看起来像真人的姓名 + 企业邮箱**。
  - 反例：`QA Yan <qa@lostfound.local>` —— 昵称是专家人名、域名是不存在的企业域名，对第三方会造成"这是真人协作者"的误判。
  - 影响：会让 `git log` 呈现"团队项目"的观感，与"个人独立项目"的对外表述直接冲突，且**无法在简历里解释工具配置**。
- **README 必须声明 AI 的参与范围**（哪部分是 AI 产出、哪部分由本人主导）。
- **不得把 AI 的贡献写成自己的著作权，也不得把"用 AI"当成需要隐瞒的事**——需要披露的是"范围"，不是"有没有用"。

**合格格式（正例）**：

- 署名＝**可辨标识＋AI 声明＋可归属邮箱**：如 `CaoHT (AI Agent) <本人 GitHub noreply 或自有域名邮箱>`；禁编造企业域名、禁用像真人的裸名字。
- 多作者提交：AI 参与的提交在提交信息尾部加 `Co-authored-by: <AI 标识> <可归属邮箱>`（与正文空行隔开）。
- README 披露段（三行即可，骨架行见 `references/大计划产物模板.md` §7）：

```markdown
> AI 协作披露：本项目由 AI（<工具/模型名>）辅助开发。
> 参与范围：<哪些部分 AI 产出／哪些部分本人主导与拍板>。
> 核实方式：全量测试与验收证据落盘于 docs/pipeline/，可按 README「测试与验证」节自行复跑。
```

**外部对标**（GitHub `[bot]` 后缀惯例、`Co-authored-by` 尾注均为 **B 级**官方文档）→ 修订记录·对外口径移出节；两条只佐证"署名须自带机器身份"的方向，"真人化假名即阻断"的判定线仍是**本库约定**。

## 二、核查表（逐项填，每项记 通过/阻断/不适用 + 证据）

| # | 检查项 | 方法 | 阻断标准 |
|---|---|---|---|
| 1 | 对外数字是否齐四件套 | 逐个数字查来源命令/样本量/口径/日期（判定口径见 §一 规则 1 表） | 缺任一要素 → 删除或补齐 |
| 2 | 数字是否过期 | 比对 `@日期` 与最后一次评测日期（取值顺序见 §一 规则 2） | 早于 → 重跑或删除 |
| 3 | commit / 路径引用是否有效 | `git cat-file -t` / `test -f`（或等价命令） | 引用不存在对象 → 阻断 |
| 4 | 比率的分母是否交代 | 查每个百分比的样本量（评测集条数**现数实测**） | 未说明 → 阻断；分母 < 30 ⇒ 数字只可与样本量同框出现，禁单独引用 |
| 5 | 小样本是否加了不确定性说明 | 样本 < 100 的指标 | 无置信区间且用于对外结论 → 阻断 |
| 6 | "训练/微调"是否有指标落档 | 找 mAP / loss / 评测报告 | 声称训练过但无指标 → 不许写"训练" |
| 7 | 权重/数据集是否可获取 | 查权重获取路径与数据集许可 | 别人拿不到 → README 必须说明来源或改为"私有" |
| 8 | AI Agent 署名是否带标识 | `git log --format='%an <%ae>'` 逐个看 | 真人化假名/假企业域名 → 阻断 |
| 9 | README 是否声明 AI 参与范围 | 读 README 披露段（正例格式见 §一 规则 4） | 无声明 → 补 |
| 10 | 简历/作品集与仓库是否一致 | 逐条对照简历主张与仓库事实 | 任一主张无法在仓库验证 → 改简历或改仓库 |
| 11 | 是否存在"用考卷练题再考同一张卷" | 查评测集是否同时用于调参与汇报 | 是 → 必须标注，并补独立验证集 |
| 12 | 承诺"杜绝/100%/全部"是否有全量证据 | 查是否为"跳过的检查" | 未全量验证 → 降级为"已验证范围：X" |
| 13 | 同一数字在多个对外物中是否同源同值 | 各对外物互相比对＋与出口文件比对＋与实测数（评测集条数/测试总数）比对 | 任一处不同值 → 全部改指单一出口或改正（"395 vs 398""49 题 vs 52 条"类矛盾即此项） |

## 三、执行法（与 D 模式跳步优化兼容）

1. **只做已有对外输出的项目**：没有任何对外物的项目，本步标"不适用"，不要空跑
   （gate 记 `na`；已答事项里有 README/演示类答复时脚本会当场点名，见 §七）。
2. **先扫后改**：先把所有对外数字/引用列成清单（简历、README、汇报、作品集），再逐条过 13 项
   （数字类先并入单一出口再查，扫描命令见 §一 规则 2）。
3. **阻断项 → 切修复卡**：改简历口径 / 重跑评测 / 补证据 / 删数字，四选一，不许"先记着"。
4. **复跑本步**：改完重扫一遍，全绿才允许收尾；复跑后**必须重登 gate**（§七）。
5. **落盘**：`docs/pipeline/口径核查表.md`，结构照 §六 骨架逐格填——结构零发挥，覆盖面才稳定。

## 四、与其它步骤的边界（避免重复劳动）

| 维度 | 归属 | 说明 |
|---|---|---|
| 漏洞、密钥、鉴权、依赖 | 第⑬步 安全基线 | 可被攻击的风险 |
| 代码质量、测试、死代码 | 卡内验收 + 编码准则 | 会不会坏 |
| **说出去的话是否站得住** | **第⑭步（本步）** | **会不会被第三方核对推翻** |
| 数字是"当时为真"还是"现在仍为真" | 第⑫步 收尾（跑全量）+ 本步规则 2 | 收尾负责生成，本步负责时效 |
| 门禁机器面（gate 值流转/证据字段/check 硬闸） | `scripts/pipeline_state.py` | 本步 §七 只写操作口径，不重定义值语义 |
| 项目侧复制即用清单 | 《验收模板-上线门禁与口径.md》K 节 | 复制件锁版本；判定标准冲突时以本文件为权威 |
| 测试证据的形态标准 | 铁律 13（A-Cao-测试纪律） | 本步四件套的证据落盘沿用它，不另立标准 |

## 五、对外物分类与差异化检查（同一把尺，不同重点）

13 项是公共尺；三类对外物的核对重点不同，审之前先归类（一物可属多类，按并集查）：

| 对外物 | 生命周期 | 在公共 13 项之上重点加查 | 理由 |
|---|---|---|---|
| **README／仓库门面** | 长期公开，任何人可核对 | 第 3 项引用有效性全量过；AI 披露段在位（规则 4 正例格式）；权重/数据集获取路径（第 7 项）；数字与出口文件同源（第 13 项） | 第三方随手可验，一条死引用就毁掉全部可信度 |
| **简历／作品集** | 随人走数年，仓库可能已私有 | 每条主张须有仓库锚点（文件名＋标识符，禁行号，铁律 20③ 同款）；量化数字**面试现场须能一行命令复现**，复现不了降级为定性说法；指标口径与评测集独立性（第 11 项）必写清 | 仓库不在手边时，唯一证据是当初留的锚点与口径 |
| **汇报／演示／面试口述** | 时效性最强（以天计） | 所有数字带**当天日期＋现场可复现命令**；演示前一晚在演示分支 HEAD 上重过第 2/3 项；口述口径＝简历口径，禁另造第三套数字 | 汇报失实的最大来源是"抄上次的"——它的保质期最短 |

## 七、机器面登记（gate 流转，与 `scripts/pipeline_state.py` 对齐）

- **值域四态**：`pending`（有对外物待查）→ `passed`（复跑全绿）或 `failed`（有阻断未清）→ 修完复跑再转 `passed`；`na`（确无对外物）只在 init 后未建对外物、或确认真没有时用。
- **硬闸**（脚本 `check`）：项目状态写「已完成」而 `outward_claims=pending` ⇒ 判红，不许收尾（铁律 11 的机器面）。
- **软闸**（脚本 `gate`）：把 outward_claims 置 `na` 时，已答事项里若出现过 README／演示／面试／简历／汇报类答复 ⇒ 当场点名（不拦死，但不许静默跳过）。
- **登记命令**（默认干跑，真落账必须带 `--apply`；证据写核查表路径）：

```bash
py scripts/pipeline_state.py gate --name outward_claims --value passed --evidence docs/pipeline/口径核查表.md --apply
```

- 复跑改判后**必须重登 gate**——核查表改了而 gate 没动＝机器面与人写面分叉（铁律 17：同一信息禁两处各写各的）。

## 八、对标依据与强度

> 依据明细（B 级：GitHub `[bot]` 惯例／`Co-authored-by`／git 对象验证命令；C 级：CHANGELOG 带日期／单一出口；A 级无——对外陈述口径没有规范级标准可直接套用，阻断线全部是**本库约定**，其有效性由 2026-09-23 教训锚点与 13 项判定的可执行性自证）→ 修订记录·对外口径移出节。

> **一句话**：⑫ 保证你收尾那一刻的数字是真的，⑭ 保证你**说出去**那一刻的数字还是真的。
