# 里程碑回看（阶段⑩）

> 触发：**自动**——卡数过阈值即插入（可判定口径见下「触发判定」）；**手动**——用户任何时候说"回看一下/停一下复盘"。
> 产出物：`<落盘目录>/回看报告_YYYYMMDD.md`——没有产出物的回看 = 空转。

## 触发判定（数什么、怎么数，禁止凭感觉）

- **卡数口径**：总卡数 N 与完成数 n 现读 `docs/pipeline/state.json` 的 `cards` 段（N＝全部键数；n＝`state` 为 `done` 的卡数）。禁手写快照，禁数台账视图（那是生成的）。
- **自动触发**：自**上一份回看报告**落盘后，新完成卡数 ≥ ⌈N/3⌉（向上取整）即触发下一次（例：N=10 → 每累计 4 张 done 回看一次）。手动回看落盘同样重置这条基线；同一批完成数不重复出两份报告，先落盘者为准。
- **不自动触发**：N < 3（整条流水线才一两张卡，⑫收尾一次性交代即可）；**轻量档**（无卡库，触发条件不成立——索引表 ⑩ 轻量列为"—"）。轻量档用户**手动**点名回看时照跑本文件，报告照出，不适用的小节写「经确认：不适用（原因，日期）」，禁写光秃秃的"无"（铁律 20①）。

## 回看五问（逐项作答，用实证不用感觉）

1. **验收真相**：已完成的卡，验收是"命令跑出来的"还是"口头宣称的"？有没有卡是评审放水过的？
2. **设计漂移**：现在的实现还长设计（PRD/设计纪要）的样子吗？哪些地方走样了、走样是变好还是变坏？
3. **新需求盘点**：开发过程中冒出了哪些新想法/新需求？（记进 PRD 的 P1/P2 或 backlog，不立即做）
4. **节奏与依赖**：台账里有没有卡在阻塞区超 24 小时？剩余卡的顺序要不要重排？
5. **下一步建议**：继续按序 / 调整卡 / 升降级模式（标准↔企业）/ 建议用户介入什么。

## 发现问题往哪回流（回看只做决定，不在现场改代码）

| 发现 | 回流点 | 机制 |
|---|---|---|
| 设计错/实现与规格行为漂移且不可接受 | ③ | 开规格层变更包（ADDED/MODIFIED/REMOVED），禁绕过规格直接改码——细则=`规格层-主规格变更与归档.md` §5 |
| 卡面有洞/验收判据放水 | ⑤ | 改卡后重过 `plan-review`（外围交接口径），带洞的卡不派工 |
| 已完成卡质量塌方 | ⑥ | 阶段⑥ §2.4 阻断处理同款：附意见重派，2 轮上限，仍不过升级用户 |
| 新需求/新想法 | ③ | 记 PRD P1/P2 或 backlog；涉可观察行为走变更包，不立即做 |
| 节奏堵/依赖悬 | ⑥ | 重排剩余卡顺序；blocked 超 24h 连同原因升级用户 |

## 分工边界（⑩ 与 ⑪、⑫ 各管一段，不重抄不越位）

- **vs ⑪ 评审**：卡级评审每卡都跑（代码质量层）；企业档"里程碑总评审"与 ⑩ 同一时点跑，产出**并入本报告评审汇总节**（阶段⑥已定，判据不重抄）。⑩ 的五问管流程与目标层（验收真实性/设计漂移/需求/节奏），不逐文件重复审码。
- **vs ⑫ 收尾**：⑩ 是中途检查站，只改"接下来的卡"；全量评测、口径检查、CHANGELOG、归档是 ⑫ 的事，⑩ 不做，也不提前做。

**纪律**：回看发现阻断级问题（如设计本身错了、前卡质量塌方）→ 停止派遣，按上表回流转完再继续；回看报告未获用户确认（或报告写明"经确认：无待拍板项"）前，不开新卡。
