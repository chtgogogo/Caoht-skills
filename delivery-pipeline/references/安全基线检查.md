# 第⑬步 安全基线检查（三档：L1 必检 / L2 上线前 / L3 企业级按需）

> 背景：2026-09-23 外部安全拷问在两个已"收尾"项目实锤 11 项（JWT 默认密钥、DEBUG 连坐限流、role 客户端自报、审计接口裸奔等），全部漏网于卡内验收——详案 → 修订记录·安全基线移出节。
> 本步是**全局维度**检查，不属于任何一张功能卡；每项目收尾前必跑 L1，真机上线前必跑 L2。
> 产出物：`<项目根>/docs/pipeline/安检报告.md`——没有产出物的安检 = 空转；**结构照 §五 骨架逐格填，结构零发挥**。
> 工具优先：能用工具的不肉眼（pip-audit / bandit / trufflehog 类 / grep 规则），工具只覆盖约一半，其余人工走查。

## 二、L1 必检（每个项目收尾前，约 30–45 分钟；触发式加检另计）

> 判定口径：每条**不加解释就能判"过/不过"**；不适用写「不适用＋一句话依据」，禁空跳（纯文档项目照跑）。
> 三类硬伤的扫法各归一项：**敏感信息泄漏→#1、危险默认→#2、本机绝对路径/隐私残留→#15**。
> 🔴 **工具化六项（v1.28.0）**：#1/#2/#7/#8/#12/#15 六项先跑随库脚本 `security_scan.py scan --root <项目根>`
> （纯标准库，装了 python 即跑；自带 selftest），输出落 evidence/ 后**人工判级**——命中=嫌疑成立，
> 按下表阻断标准判；工具没抓到 ≠ 该项通过（正则盖不住语义面），人工走查照旧。规则描述文本（含本细则）
> 被扫出关键词字面＝自指命中，判级时区分「违规行为」与「规则描述」。

| # | 检查项 | 方法 | 阻断标准 |
|---|---|---|---|
| 1 | 密钥/凭据硬编码 | grep 契约：`sk-`、`secret`、`password`、`api_key` 字面量；`git log --all -S <密钥名>` 查历史 | 源码/示例/测试出现可用凭据=阻断；历史残留→确认该密钥已在服务商处作废 |
| 2 | 配置默认值审计 | 逐个检查安全类配置项（密钥/管理员码/数据库密码）是否有"可上生产"的默认值；**弱默认清单＝空值、`secret`/`changeme`/`admin`/`123456`/`test`/`default` 字面量、与项目或框架同名的值；再查部署面（生产 env／docker-compose／部署脚本）是否显式覆盖** | 安全项为弱默认值且部署文件未覆盖=阻断 |
| 3 | DEBUG/开关连坐 | 找所有 `if DEBUG` 分支，确认 DEBUG 不牵动任何安全行为（限流/验证/加密） | 连坐=阻断；解法=拆独立开关 |
| 4 | 鉴权覆盖矩阵 | 列出全部路由，逐一标注鉴权方式；找"全挂了唯独它没挂"的 | 存敏感数据的接口无鉴权=阻断 |
| 5 | CORS 策略 | 查 `allow_origins` | 生产配置含 `*` 与 credentials 并用=阻断 |
| 6 | 授权字段自报 | 搜请求体里的 role/permission/is_admin 类字段，核对服务端是否从已认证身份**派生**而非采信 | 自报可操纵状态=阻断 |
| 7 | 注入防御抽查 | SQL 必须参数绑定（禁拼接/f-string 组装）；用户输入到 `eval/exec/shell/反序列化` 的全部按敌意数据校验（白名单校验类型/长度/格式/取值范围，禁黑名单） | 拼接 SQL 或 eval 用户输入=阻断 |
| 8 | 输出编码 | 返回前端的动态内容按场景转义（XSS）；前端 `v-html`/`innerHTML` 标注来源 | 用户可控内容直插=阻断 |
| 9 | 暴力破解面 | 所有"码/验证码/token 验证"端点：有尝试次数限制吗？比较用恒时比较（compare_digest）吗？ | 无限次尝试的可穷举=阻断 |
| 10 | async 阻塞扫描 | `async def` 路由里有无秒级同步调用（LLM/推理/大 IO） | 有=阻断（改 def 或 to_thread） |
| 11 | 死代码扫描 | 未被调用的函数、一运行就崩的文件、前端接了线但后端不存在的按钮 | 带 AI 协作注释的死文件=阻断（删） |
| 12 | 敏感词/临时调试残留 | print 调试、TODO 密钥、注释里的生产地址；**判级：轻度＝失效 print/TODO 注释；重度＝注释或文档里的真实生产地址·真实邮箱·真实手机号、TODO 或被注释掉的真实密钥/安全逻辑** | 轻度=建议，重度=阻断 |
| 13 | 水平越权（对象级授权/IDOR）【追加】 | 列出全部"按标识取/改/删"的接口（路径或查询参数里的 id/编号/单号），逐一核服务端是否校验"该对象属于当前已认证主体"；无用户体系的项目核匿名能否改他人数据 | 换对象标识即可读/改/删不属于自己的数据=阻断 |
| 14 | 错误响应泄漏【追加】 | 人为触发一次错误（坏参数/不存在的 id/缺 token）看响应体；grep 全局异常处理与框架 debug 配置 | 生产形态下错误响应含堆栈、内部绝对路径、SQL/框架报错原文=阻断（堆栈只进日志） |
| 15 | 本机绝对路径与隐私数据残留【追加】 | grep 契约扫**当前树与暂存区**：盘符路径 `[A-Za-z]:\` 前缀、`/home/`、`/Users/`；隐私真实字面量（姓名/手机号/邮箱/证件号样式）同 #1 扫全历史 | 本机绝对路径进代码/配置/文档/脚本=阻断（对外一律相对化）；隐私真实字面量=阻断（换合成数据）；**本项证据同时供 ⑫ 收尾第 7 步推前检查引用，同一次扫描不重扫** |
| 16 | 依赖已知漏洞【追加 v1.25.0】 | 工具写死：Python `pip-audit`（未装先 `py -m pip install pip-audit`，装后跑 `py -m pip_audit`；2026-10-25 本机实测未装时报 No module named——这条安装提示就是为此写进方法列）、Node `npm audit --omit=dev`，原始输出落 evidence/；**新依赖首次引入时核实包名与发布方在官方仓库（PyPI/npm）真实在册**——AI 生成的依赖名有幻觉率，幻觉包名会被攻击者抢注（slopsquatting，正中 AI 高频 install 靶心；USENIX Security 2025 实测幻觉率 38–43% 可复现） | 已知可利用漏洞（Critical/High 且有公开 exploit）不处理=阻断；引用官方仓库查无此包的依赖=阻断（立即下架核实） |

> #13–#16 为追加项（编号只追加不顺延，1–12 原编号与原意不动）：#13 补对象级授权面（OWASP Top 10:2025 A01 连年首位）；
> #14 补异常处理泄漏面；#15 落实模式判定.md §四 对 L1 的既有定义与收尾第 7 步的内容检查；#16 补供应链面
> （OWASP 2025 把供应链失败抬到 A03——依赖漏洞扫描从 L2 前移到 L1：秒级成本，纯开发项目也扫；L2 的依赖扫描条目保留作部署前复扫）。

### 触发式加检（项目含该特征才检；检了就进报告 §1 表，判据同 L1）

| 触发特征 | 检查项 | 阻断标准 |
|---|---|---|
| 服务端按用户可控 URL 发请求（URL 导入/头像/webhook/预览） | SSRF | 无 scheme+host 白名单直连用户可控 URL=阻断 |
| 有任何文件上传入口 | 上传面 | 类型黑名单／无大小上限／存储目录可执行=阻断 |
| 有 WebSocket/SSE/本地端口等非 HTTP 面 | 非 HTTP 鉴权 | 敏感通道不在 #4 鉴权矩阵内=阻断（矩阵必须含它们） |
| 签发 JWT/session 令牌 | 会话令牌失效 | 令牌无过期时间，或登出后旧令牌仍可用=阻断 |
| 项目含 LLM/Agent 调用【追加 v1.25.0】 | AI 特有面四查（OWASP LLM Top 10:2025） | ① 提示注入面：用户输入不经隔离拼接进系统指令=阻断；② 过权：Agent 工具/写权限超出该功能必需最小集=阻断；③ 输出处理：LLM 输出未经校验直进 eval/exec/shell/HTML=阻断（#7/#8 的 LLM 变体）；④ 系统提示泄漏：接口会回显系统提示词=阻断 |

## 三、L2 上线前（真机部署前，约半天）

- 认证端点（登录/注册/验证码）逐个限流；全站基础限流开启
- 请求体大小护栏（框架层或反代层），防资源耗尽
- API 响应脱敏：手机号/身份证/邮箱按规则截断（前3后4 类），不完整返回
- 密码必须不可逆哈希（bcrypt/argon2，禁 MD5/明文）；非密码敏感字段对称加密存储
- HTTPS 强制；日志脱敏（日志保留完整轨迹但敏感字段值掩码化——日志本身是要被保护的数据资产）；生产关 DEBUG 日志
- 审计日志完整性：操作人/时间/内容/IP 全记录，防篡改（append-only），留存 ≥6 个月（如有合规要求）
- 容器：官方基础镜像+固定版本号（禁 latest）、非 root 运行、数据库端口不映射宿主机（或仅 127.0.0.1）、演示种子数据门控默认关闭
- 依赖漏洞扫描：`pip-audit`（Python）/ `npm audit`（前端），高危项处理或书面豁免
- 【追加】安全响应头基线：`X-Content-Type-Options: nosniff` 与反嵌套防护（`X-Frame-Options` 或 CSP `frame-ancestors`）在位，HTTPS 站点加 HSTS；判法 `curl -sI`，两类基础头全缺=阻断
- 【追加】CSRF（仅当改数据接口依赖 Cookie 会话态；纯 token-header API 写「不适用」）：SameSite=Lax/Strict 或 CSRF token 任一在位，都无=阻断

## 四、L3 企业级按需（有对应基础设施才检，否则标注"不适用"）

- **SBOM（v1.28.0 改判：售欧盟命中=必检，不再是"按需"）**：EU CRA（Reg (EU) 2024/2847）要求随附
  常用且**机器可读**格式的 SBOM（至少含顶层依赖），支持期至少 **5 年**（Annex I Part II(1)＋Art 13(8)）。
  **生成外挂现成工具，不自制**：`syft` 或 `cyclonedx-cli` 有则用（`syft <项目根> -o cyclonedx-json=bom.json`）、
  没装则写明降级路径（pip-licenses/npm ls 手工拼顶层依赖清单＋版本＋生成时间戳，机器可读 JSON），禁空白。
  NTIA 最低七要素当内容检查单。**售欧盟命中时收尾检查 bom.json 在盘＋机器可读＋含顶层依赖**；
  随制品分发时附**支持期声明字段**（≥5 年，安全更新上限 10 年）。纯免费未货币化项目写豁免主张＋判据记录
  （铁律 20① 口径：「经确认：不适用（依据=无商业化行为，Art 3(22) 豁免面）」）。非售欧盟的企业档项目
  照旧按需判适用性。制品签名（cosign，有则用）与构建溯源/可复现构建照旧按需。
- 事件响应与上报承接：售欧盟命中时必过 **§十**（触发判据/时钟表/SRP 入口/留证清单）；安检报告 §3 含「事件响应承接」行
- IaC 审计（Terraform/CloudFormation 的开放存储桶/过宽 IAM/未加密库）
- K8s 编排安全（API Server/etcd/网络策略/非 root 工作负载）
- 依赖许可证合规扫描（copyleft 传染风险；**本体系资源红线：NC 协议素材禁入**）
- CI/CD 集成扫描链：SAST（Semgrep/Bandit）+ SCA（Trivy/Grype）+ 密钥检测（TruffleHog）+ 分支保护/签名提交
- 【追加】DAST 基线：对已部署环境跑一次 OWASP ZAP baseline（或等价），原始报告落 `docs/pipeline/evidence/`

## 六、执行法（D 模式兼容）

0. **常驻化前置（v1.28.0）**：走到 ⑬ 时项目通常已在提交时/每卡时层跑过 `security_scan.py`
   （§八 三层）；本步把当次全树复扫一遍（`scan --root <项目根> --append <安检报告路径>`），
   历史层抓过并已修复的项在 §1 表引用对应 evidence，不重修；
1. 按 §一 定点亮档（信号没给的按模式判定.md §四默认值：只跑 L1）；
2. L1 固定项与触发式加检**逐项过**（条数以 §二 清单为准，不抄数），每项记「通过／阻断／不适用＋证据
   （文件:标识符 或 命令输出）」，不适用也要依据；
3. 阻断项 → 切修复卡（对应阶段细则执行），修完**复跑该项**，复跑证据落盘（§五 证据纪律③）；
4. 报告落盘 `docs/pipeline/安检报告.md`，结构照 §五 骨架，含三档结论与遗留风险清单；
5. `gate --name security_L1 --value passed --evidence docs/pipeline/安检报告.md --apply` 落账；复跑改判后必须重登 gate
   （机器面与人写面不分叉）；
6. 收尾（⑫）凭 L1 全绿报告放行（铁律 10：L1 有阻断项不许收尾）。

## 八、常驻化三层（安检从点时走查升级为全生命周期控制）

> 对标 NIST SSDF「安全实践 integrated into each SDLC implementation」与 GitHub Push Protection
> 「推送到达仓库之前拦截，绕过须给理由并自动留告警」——安检不该只在收尾那一刻发生。
> 三层全部挂在**既有步骤时点**（⑥ 过卡链/⑬ 收尾），不新开步号；每层结论落安检报告 §7 追加区，
> 时间序列本身就是控制运行期证明的原料。

| 层 | 时点（既有步骤） | 动作 | 判定 |
|---|---|---|---|
| 提交时 | ⑥ 每卡 git 提交前（过卡链 5.7 之前） | pre-commit 钩子跑六项规则面，命中即拦下本次提交 | 退出码非 0=拦；确要绕过走 `git commit --no-verify` 并在卡回执写明理由（「拦截＋绕过留痕」） |
| 每卡时 | ⑥ 过卡链 5.2 证据落盘（**建议**，非硬闸） | 对改动面跑 `py <skill根>/scripts/security_scan.py scan --root <项目根>`，输出落该卡 evidence/ | 命中当场判级（§二 阻断标准），不带阻断过卡 |
| 收尾时 | ⑬ L1 全清单（既有硬闸） | 六项工具复扫＋十六项人工走查，结论进安检报告 §1 | 铁律 10：L1 有阻断不许收尾 |

- **工具只覆盖形态面**：命中=嫌疑成立，判级与处置按 §二 人工走查；工具没抓到 ≠ 该项通过。
  规则描述文本（含本细则）被扫出关键词字面＝自指命中，判级时区分「违规行为」与「规则描述」。
- **pre-commit 样例**（存 `<项目根>/.git/hooks/pre-commit`，Git Bash/Linux 加执行权限；无 git 的项目跳过此层并在安检报告写明）：

```sh
#!/bin/sh
# 交付流水线安检常驻化·提交时层（调随库 security_scan.py；六项规则面命中即拦）
py "<skill根>/scripts/security_scan.py" scan --root .
code=$?
if [ "$code" -ne 0 ]; then
  echo "[安检拦截] 六项规则面有阻断命中；确要绕过：git commit --no-verify 并在本卡回执写明理由"
  exit 1
fi
```

## 九、漏洞响应与修复 SLA（🔴 本库约定，非合规依据）

> 业界**没有**统一漏洞修复时限表：CISA BOD 22-01（KEV 默认 2 周）已于 2026-06-10 被 BOD 26-04
> 废止，改按风险四要素（暴露面/是否 KEV/可自动化利用/技术影响）定时限、未给统一天数；
> NIST SP 800-40r4 无固定天数；FIRST PSIRT Services Framework 建议组织自定义。
> **下表的合法性来自「自定」本身**——单人项目把它当自己的修复承诺执行，禁对外引用为合规依据；
> 推翻条件=CISA 后续发布可执行时限表（届时以新表为准）。

| 级 | 判级 | 修复时限（本库约定） |
|---|---|---|
| P0 | CISA KEV 在列，或 critical 且有在野利用证据 | **7 天** |
| P1 | high（或 critical 无在野利用证据） | **30 天** |
| P2 | 其余（medium/low） | **90 天**或随下次大版本 |

- **判级活读 KEV feed**（官方 JSON，零依赖比对，装了 python 即可；实测留证见本库 evidence）：

```bash
py -c "import json,urllib.request;d=json.load(urllib.request.urlopen('https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json'));print({v['cveID'] for v in d['vulnerabilities']} & {'CVE-XXXX-XXXX'} or '不在 KEV')"
```

- **响应四步**（对齐 ISO/IEC 29147 披露／30111 处理的分工，条款号为通行映射）：发现（#16 扫描＋KEV feed）→
  定级（上表）→ 修复卡（走 ⑥ 常规派遣，不另立流程）→ 复跑证据（§五 证据纪律③「修复前＋复跑后」）。
- 超期未修=进安检报告 §5 遗留风险（豁免理由＋批准人必填），禁静默拖过。
