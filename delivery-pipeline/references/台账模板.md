# 台账模板（阶段⑧ · 单一权威记录 + 派生视图）

> 一句话口径：**状态只有一份，写在 `<项目根>/docs/pipeline/state.json`；台账.md 是它打印出来的纸。**
> 以前是 md 与 json 两份手写、靠「`updated_at` 较新者为准」互相同步——那个口径已被废除（铁律 4/17）：
> 墙钟时间既排不出两个窗口的先后（同秒、改系统时钟、跨机时区），也不是字段级事实，
> 拿它当仲裁就是**后写的整份把先写的别的字段一起盖掉**（lost update）。现在时间戳只作"这条记录什么时候动的"，**不参与谁对谁错的判定**。

## 一、权威源与派生视图（谁是真的）

| 文件 | 性质 | 谁能写 | 手改了会怎样 |
|---|---|---|---|
| `docs/pipeline/state.json` | **唯一权威记录**（schema 2） | 只有 `pipeline_state.py`（tmp 写满 → fsync → `os.replace` 原子替换 → 写后读回，不符即回滚） | 手工编辑不会立刻报错，但下一次 `check` 会当场判红 |
| `docs/pipeline/台账.md` | 派生视图（给人看） | `render` 生成 | 生成区间外的手写内容会被下次 `render` 覆盖且零报警 ⇒ 人工说明只写区间外 |
| `docs/pipeline/任务板.md` | 派生视图（给 AI 认领） | `render` 生成（**标准/企业档且有卡才生成；轻量档永远不建；无卡不建空看板**） | 同上 |
| `docs/pipeline/state.lock.json` | 租约锁（不是状态） | 取锁/交锁命令 | 见 §六 |
| 项目自己的 `交付记录清单.md` | **人手维护的轨迹本**，不是派生物 | 人（AI 可代填完成行） | 工具不读它、不替它的一致性背书 |

四条硬规矩：

1. **改状态一律走命令**，命令**默认干跑**（只打印"将要写什么"），加 `--apply` 才真落盘；
2. **视图里的生成区间禁手改**——`<!-- AUTO-BEGIN … -->` 与 `AUTO-END -->` 之间由脚本重写；
   同名文件若是**人手写的**（没有 AUTO 标记），`render` **拒绝覆盖并退 8**，让人先确认改名或走并账；
3. **旧项目已有一份手写台账.md 的，不要手抄进 json**，走 `sync --from-md` 逐字段并账（见 §七）；
4. **同一信息禁两处手写**（铁律 17）：视图是打出来的，不是抄出来的；要改视图里的内容 = 改权威记录再 `render`。

## 二、命令表（更新纪律的落地形态）

解释器按本机口径（Windows 用 `py`）。所有写类命令共用：`--root <项目根>`、`--apply`、
`--holder <窗口名>`（给则取租约锁）、`--expect-rev <读到的 rev>`（乐观版本校验）、
`--takeover`（显式接管陈旧锁）、`--keep-lock`（写完不释放）。

| 要做的事 | 命令 |
|---|---|
| 自证脚本没坏（不碰真实项目） | `py scripts/pipeline_state.py selftest` |
| 新项目建账 | `… init --root <项目根> --project <名> --mode <档> --mode-source user\|auto --apply` |
| 定档／改档／按信号自动定档 | `… mode --decide --signal 键=值 …` ／ `… mode --set 企业 --apply` |
| 看这档要建哪些文件、跑哪些步 | `… plan --tier 轻量` |
| 阶段四字段与状态 | `… stage --id ③ --state done --input-version … --artifact … --criteria … --recovery … --apply` |
| 卡状态 | `… card --id 4 --state doing --executor 子代理 --acceptance "来源数≥1" --metric "…" --module retrieval --apply` |
| 门禁 | `… gate --name security_L1 --value passed --evidence docs/pipeline/安检报告.md --apply` |
| 登记已答事项／问前先查 | `… answer --id 落盘目录 --answer "docs/pipeline/" --source 用户已说明 --apply` ／ `… answer --id 落盘目录 --check` |
| 外部动作账 | `… action --id push-1 --kind git-push --idem-key <键> --done --evidence <路径> --apply` ／ `--check` |
| 依赖快照（哈希/映射/链接） | `… deps --record 路径|来源|版本 --map 上游=本地 --check-links a.md,b.md --apply` |
| 重新打印视图 | `… render --apply`（或 `--view ledger\|board`） |
| **对账**（派生物＝权威记录？） | `… check` |
| 中断恢复：该从哪续＋不许重做的清单 | `… resume --root <项目根>` |
| 打印权威记录 | `… show`（`--json` 出机器可读） |
| 交回自己的锁 | `… unlock --holder <本人>` |

**顺序纪律（原三条仍守）**：① AI 删任务板条目之前必须先写回权威记录——顺序反了会出现"任务没了、台账没记"的丢失窗口（现在更简单：认领状态改 `card --state`，任务板自己会重画）；② 卡编号在台账可追溯；③ 记录清单只记事实（日期+关键数字+证据路径），不写判断。

## 三、state.json 结构

```json
{
  "schema": 2,
  "project": "项目名",
  "mode": "轻量|标准|企业",
  "mode_source": "user|auto|default",
  "rev": 7,
  "updated_at": "2026-10-14T09:12:03",
  "status": "进行中|已完成|已归档",
  "stages": { "①": { "name": "磨设计", "state": "done",
                       "input_version": "", "artifacts": [], "done_criteria": "",
                       "recovery_point": "", "evidence": [] } },
  "cards": { "3": { "state": "doing", "title": "", "executor": "", "started": "",
                    "acceptance": "", "metric": "", "date": "", "note": "",
                    "depends": [], "modules": [], "parallel_ok": 0 } },
  "answers": { "落盘目录": { "answer": "docs/pipeline/", "source": "用户已说明", "at": "" } },
  "external_actions": [ { "id": "push-1", "kind": "git-push", "idem_key": "",
                          "done": true, "at": "", "evidence": "" } ],
  "gates": { "security_L1": "pending", "outward_claims": "na",
             "model_eval": "na", "multi_agent": "na" },
  "deps": { "snapshot_at": "", "files": [], "path_map": {},
            "link_check": "unchecked", "broken_links": [] },
  "sync_conflicts": [],
  "history": [ { "rev": 1, "at": "", "event": "init mode=标准" } ]
}
```

**rev 与 updated_at 分工不同**（这是新口径的核心，别再混用）：
`rev` 每次成功写入 +1，是**并发校验用的整数**——写的时候带上你读到的 `--expect-rev`，不符就退 6 让你重读；
`updated_at` 只是"这条记录什么时候动的"的**说明性时间戳**，永远不参与"谁覆盖谁"的判定。

## 四、阶段四字段与外部动作幂等账（断点续传的硬闸）

一个阶段标 `done` 之前必须写满四字段，**缺任一项或产物不在盘上，脚本拒写（退 4）**：

| 字段 | 写什么 | 为什么硬要 |
|---|---|---|
| `input_version` | 这步吃的是哪版输入（commit / PRD 版本 / 快照时间） | 否则"重跑"无从判断是不是同一件事 |
| `artifacts` | 产物相对路径（可多条） | **标 done 时逐条查盘**；说做了但东西不在＝续传最坏的坑 |
| `done_criteria` | 完成条件（可判定的那句话） | 防止把"差不多"当成"完成" |
| `recovery_point` | 中断后下一步从哪续 | 要写到"下一个窗拿着就能接"，如"从第 4 节续写，1-3 节勿改"，不是"继续" |

卡级另有一条：`card --state done` 而 `metric` 为空 ⇒ 拒写（退 4）——台账约束 1「状态只有实测值」现在是代码而不是规矩。

**外部动作单独记账**：push / 发信 / 建 PR / 上传这类**不在本项目盘上、重放有副作用**的动作，
用 `action --idem-key` 登记；`resume` 会把已生效的列成「不许重做」清单。判据：
**中断重启后，已完成的外部动作必须零重放**（重放＝重复 push／重复发信，这是事故不是麻烦）。

## 五、已问过／已授权（不重复确认清单）

- 要向用户确认的每一件事，**先 `answer --id <项> --check`**（已答过退 0）；
- 拿到答复立刻落账：`answer --id <项> --answer <结论> --source 用户已说明|用户授权|沿用上次|推导 --apply`；
- `--source 推导` 表示是 AI 替用户拍的（要能在台账里看出是谁定的），别把它写成"用户已说明"；
- 台账第七节自动生成这张表，`resume` 也会打印它 ⇒ 新窗口不会把问过的再问一遍。
  依据：**重复确认已说明/已授权的事项是缺陷**（外部审查 2026-10-11 复核；「先查账再开口」与 §一 启动路由同口径）。

## 六、并发与锁（多窗／多分身同写一棵树）

- **单写者**：§一 的原子替换就够了，不用取锁；
- **多写者**：加两件事——
  1. **租约锁**：`--holder <窗口名>` 取锁（`O_CREAT|O_EXCL` 原子建锁）＋ 心跳；
     崩窗留下的**陈旧锁绝不自动接管**，必须本人显式 `--takeover`（代次 generation +1，只增不减）；
     `unlock` 只准登记的持锁窗本人交锁，替别人交一律拒。
  2. **rev 乐观校验**：`--expect-rev` 读到哪版就按哪版改；版本不符退 6，重读再改，**永不整份覆盖**。
     语义与 HTTP `If-Match`/ETag 同款（RFC 9110 §4.12 precondition 失败，检索 2026-10-14）。
- 退出码与「多 Agent 团队协作文档治理」的 `edit_lock.py` 保持同一套（同一体系里两套码＝换工具就要重背一遍表）。

| 码 | 含义 | 该做什么 |
|---|---|---|
| 0 | 通过／无事 | — |
| 1 | 对账不通过（派生物≠权威记录、依赖链接断、写后读回不符已回滚）<br>另注：`mode --decide` 平档时也返回 1——那是"**该问用户**"，不是错误 | 看打印的具体条目，改权威记录后重跑 `render` |
| 2 | 参数错（未知档位/阶段/信号写法/门禁值） | 按打印的可用值改命令 |
| 3 | 缺权威记录（还没 `init`） | 新项目 `init`；旧台账先 `sync --from-md` |
| 4 | **硬闸拒写**：四字段缺／产物不在盘／卡无实测 metric／依赖件不存在／**权威记录或锁记录本身非法** | 补内容再标 done；记录非法时**别手改**，先确认谁写坏了 |
| 5 | 锁被他人持有 | 等它 `unlock`，或协调后由本人 `--takeover`；不许绕锁直接写文件 |
| 6 | rev 版本冲突 | `show --json` 重读，按新版重做这次改动 |
| 7 | 租约过期（陈旧锁） | 现场确认无人正在写，再 `--takeover` |
| 8 | 拒写人手写的同名视图 | 人工确认并改名，或把内容并账进权威记录 |

## 七、旧台账怎么并进来（`sync --from-md`）

老项目往往已有一份手写 `台账.md`（三区制格式，来自多 Agent 文档治理 v1.3）。**不手抄、不重打一遍**：

```
py scripts/pipeline_state.py sync --root <项目根> --from-md docs/pipeline/台账.md --apply
```

- 逐字段比对并写入，两侧值不同时**脚本一律不自动取舍**：冲突记进 `sync_conflicts`，
  台账自动多出**第十节「待人工裁决」**，把两侧原值都列出来等人拍板；
- 判据：**并账不能变成"挑一份覆盖另一份"**——那正是被废除的旧毛病换了个入口；
- 并完再 `check`，红点必须清零才能继续用 `render` 重画视图。

## 八、生成的台账.md 长什么样（十节，不用手写）

```
# {项目名} · 交付流水线台账（生成视图＝派生物，真源是 state.json）
## 一、阶段进度（四字段齐才允许标 done）   ← 步/阶段/状态/输入版本/产物位置/完成条件/恢复点
## 二、在做（最多一张）
## 三、待执行（按依赖顺序）
## 四、做完                                ← 卡行尾带「模块：」字段，对齐模块地图（铁律 16）
## 五、阻塞区
## 六、门禁（未 passed 不许收尾／投递）
## 七、已问过／已授权（不重复确认清单）
## 八、外部动作账（已生效的不许重做）
## 九、依赖快照（版本＋哈希＋路径映射）与链接检查
## 十、待人工裁决                          ← 只有并账冲突时才出现
```

一~五节即原「在做/待执行/做完/阻塞」三区制（格式沿用治理 v1.3，只是改为生成）；
六节是第⑬/⑭步门禁的机器可读版；九节里若某条路径映射写成**本机绝对路径**，
生成视图会当场标「🔴 本机绝对路径（发布前必须改成相对形态或删掉）」——发布前的泄漏扫描靠这一眼。

## 九、中断恢复的读法

```
py scripts/pipeline_state.py resume --root <项目根>
```
打印三样：**该从哪一阶段续**（已 done/skipped 的步不许重跑）、**不许重做的外部动作**、**已问过／已授权别再问的事项**。
主 skill 启动路由第 0 步就是它（§一 权威记录优先，不靠记忆、不靠"上次我们聊到"）。

## 十、收尾归档

项目完成（阶段⑫）时：先 `check` 退 0，再把 `台账.md` 改名 `台账_归档_YYYYMMDD.md` 并在 AUTO 区间**之外**的顶部加一行"本项目已交付，台账仅供追溯"；
`state.json` 留在原地别删（它是这份归档的机器可读真源，删了归档就成孤本）。

## 十一、个人适配层（不在本细则里）

本机专属的东西（本机技能库路径、现役项目的既有台账/卡/evidence 惯例、个人习惯口径）一律放
本机那份 `personal.local.md`（放在本细则同目录，照 `references/personal.example.md` 样板复制，
别直接改样板），发布时被 `*.local.md` 排除，不跟本 skill 出仓。
判据：**删掉那个文件，本 skill 在别人机器上照样能跑**；本细则里出现的每个路径都必须是相对形态。
