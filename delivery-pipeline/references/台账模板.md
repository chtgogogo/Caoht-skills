# 台账模板（阶段⑧ · 单一权威记录 + 派生视图）

> 一句话口径：**状态只有一份，写在 `<项目根>/docs/pipeline/state.json`；台账.md 是它打印出来的纸。**
> 旧口径（md 与 json 两份手写、按 `updated_at` 较新者同步）已废除（铁律 4/17；墙钟排不出窗口先后，拿它仲裁＝后写整份盖掉先写，lost update；沿革 → 修订记录·台账模板移出节）。现在时间戳只作"这条记录什么时候动的"，**不参与谁对谁错的判定**。

## 一、权威源与派生视图（谁是真的）

| 文件 | 性质 | 谁能写 | 手改了会怎样 |
|---|---|---|---|
| `docs/pipeline/state.json` | **唯一权威记录**（schema 2） | 只有 `pipeline_state.py`（tmp 写满 → fsync → `os.replace` 原子替换 → 写后读回，不符即回滚） | 手工编辑不会立刻报错，但下一次 `check` 会当场判红；编辑坏了（schema 比脚本新／rev 非整数／段类型不对）下一次任何命令拒读（退 4） |
| `docs/pipeline/台账.md` | 派生视图（给人看） | `render` 生成 | `render` **重写整份文件**——AUTO 标记是给人看的地界，不是保全区；人工说明别写进派生视图，要留话进权威记录（`answer`）或另立文件 |
| `docs/pipeline/任务板.md` | 派生视图（给 AI 认领） | `render` 生成（**标准/企业档且有卡才生成；轻量档永远不建；无卡不建空看板**） | 同上 |
| `docs/pipeline/.locks/state.lock.json` | 租约锁（不是状态，`check` 不对它对账） | 取锁/交锁命令 | 见 §六；锁记录损坏（非法 JSON）退 4——互斥已失效，人工确认无人正在写后删掉它 |
| `AGENTS.md` 等 L0 文档六件与三份大计划产物骨架 | init 搭的骨架（首行带 `<!-- pipeline-scaffold -->` 标记，人填实），**不是派生物** | 人（AI 代填） | ①②③ 标 done 时缺件或仍带骨架标记被硬闸拒（退 4）；① done 之后缺件 `check` 判红；显式退出唯一通道＝`docs --opt-out <路径> --why <用户原话>`（§二） |
| 项目自己的 `交付记录清单.md` | **人手维护的轨迹本**，不是派生物 | 人（AI 可代填完成行） | 工具不读它、不替它的一致性背书 |

四条硬规矩：

1. **改状态一律走命令**，命令**默认干跑**（只打印"将要写什么"），加 `--apply` 才真落盘；
2. **视图整份都是生成物**——从 AUTO-BEGIN 标记开头到 AUTO-END 结尾；`render` 对**文件头 800 字符内没有 AUTO-BEGIN** 的同名文件判为人手写件，**拒绝覆盖并退 8**，让人先确认改名或走并账；
3. **旧项目已有一份手写台账.md 的，不要手抄进 json**，走 `sync --from-md` 逐字段并账（见 §七）；
4. **同一信息禁两处手写**（铁律 17）：视图是打出来的，不是抄出来的；要改视图里的内容 = 改权威记录再 `render`。

## 二、命令表（更新纪律的落地形态）

解释器按本机口径（Windows 用 `py`），所有命令形如 `py scripts/pipeline_state.py <子命令> …`。公共参数：

- 所有子命令都有 `--root <项目根>`（默认当前目录）与 `--subdir`（覆盖状态子目录，默认 `docs/pipeline`）；
- **写类命令**（mode/render/sync/stage/card/gate/docs/answer/action/deps）另有：`--apply`（真落盘，默认干跑）、
  `--holder <窗口名>`（给则取租约锁）、`--expect-rev <读到的 rev>`（乐观版本校验）、
  `--takeover`（显式接管**陈旧**锁）、`--lease <秒>`（租约长度，默认 3600）、`--keep-lock`（写完不释放）；
- `init` 有 `--apply` 但没有锁参（建账前无状态可锁）；`plan/check/resume/show` 只读不取锁；
  `unlock` 只带 `--root/--subdir/--holder`。

| 要做的事 | 命令 |
|---|---|
| 自证脚本没坏（不碰真实项目；有 FAIL 退 2） | `py scripts/pipeline_state.py selftest` |
| 新项目建账（默认搭 L0 文档骨架六件，标准/企业档再搭三份大计划产物骨架；棕地已有件不覆盖） | `… init --root <项目根> --project <名> --mode <轻量\|标准\|企业> --mode-source user\|auto\|default --docs-tier L0\|none --apply`（重来加 `--force`） |
| 定档／改档／按信号自动定档 | `… mode --decide --signal 键=值 … [--ask]` ／ `… mode --set 企业 --apply` |
| 看这档要建哪些文件、跑哪些步 | `… plan --tier 轻量` |
| 阶段四字段与状态（跳步授权走 `--skip-auth`，v1.18） | `… stage --id ③ --state done --input-version … --artifact … --criteria … --recovery … [--evidence …] [--skip-auth "授权说明"] --apply` |
| 文档层逐件状态／显式退出某件（v1.14） | `… docs --show` ／ `… docs --opt-out <路径> --why <用户原话> --apply`（`--why` 必带，缺了退 2） |
| 卡状态 | `… card --id 4 --state doing --title "…" --executor 子代理 --acceptance "来源数≥1" --metric "…" --module retrieval --depends 3 --parallel-ok 1 --apply`（`--state done` 时 `--metric` 必填） |
| 门禁 | `… gate --name security_L1 --value passed --evidence docs/pipeline/安检报告.md --apply` |
| 登记已答事项／问前先查 | `… answer --id 落盘目录 --answer "docs/pipeline/" --source 用户已说明\|用户授权\|沿用上次\|推导 --apply` ／ `… answer --id 落盘目录 --check`（已答退 0／未答退 1＝可以问） |
| 外部动作账 | `… action --id push-1 --kind git-push --idem-key <键> --done --evidence <路径> --apply` ／ `… action --id push-1 --check`（已做过退 0＝续传跳过／未做退 1＝可以执行） |
| 依赖快照（哈希/映射/链接） | `… deps --record 路径\|来源\|版本 --map 上游=本地 --check-links a.md,b.md --apply`（登记不存在的件退 4；断链退 1 且不落盘） |
| 重新打印视图 | `… render --apply`（`--view ledger\|board\|all`，默认 all） |
| **对账**（派生物＝权威记录？） | `… check` |
| 中断恢复：该从哪续＋不许重做的清单 | `… resume --root <项目根>` |
| 打印权威记录 | `… show`（`--json` 出机器可读） |
| 项目状态（v1.25.0 唯一写入通道） | `… status --set 已完成`（反查 security_L1/outward_claims 两道门禁，未过退 4）／`… status --set 已归档`（要求已完成）／`… status`（只读打印） |
| 台账归档（v1.25.0 机器通道） | `… archive`（要求 status=已完成；改名 台账_归档_YYYYMMDD.md＋置已归档；归档态 render 不再生成活台账、check 反向要求活台账不存在） |
| 交回自己的锁 | `… unlock --holder <本人>` |

**顺序纪律（原三条仍守）**：① AI 删任务板条目之前必须先写回权威记录——顺序反了会出现"任务没了、台账没记"的丢失窗口（现在更简单：认领状态改 `card --state`，任务板自己会重画）；② 卡编号在台账可追溯；③ 记录清单只记事实（日期+关键数字+证据路径），不写判断。

## 三、state.json 结构

```json
{
  "schema": 2,
  "project": "项目名",
  "mode": "轻量|标准|企业",
  "mode_source": "user|auto|default",
  "rev": 7,
  "updated_at": "2026-10-14 09:12:03",
  "status": "进行中|已完成|已归档",
  "stages": { "①": { "name": "磨设计", "state": "todo|doing|done|skipped|na",
                     "input_version": "", "artifacts": [], "done_criteria": "",
                     "recovery_point": "", "evidence": [] } },
  "cards": { "c3": { "state": "todo|doing|done|blocked", "title": "", "executor": "", "started": "",
                     "acceptance": "", "metric": "", "date": "", "note": "", "who": "",
                     "depends": [], "modules": [], "parallel_ok": 0 } },
  "answers": { "落盘目录": { "answer": "docs/pipeline/",
                             "source": "用户已说明|用户授权|沿用上次|推导", "at": "" } },
  "external_actions": [ { "id": "push-1", "kind": "git-push", "idem_key": "",
                          "effect_applied": true, "at": "", "evidence": "" } ],
  "gates": { "security_L1": "pending", "outward_claims": "na",
             "model_eval": "na", "multi_agent": "na" },
  "gate_evidence": { "security_L1": "docs/pipeline/安检报告.md" },
  "deps": { "snapshot_at": "",
            "files": [ { "path": "", "source": "", "version": "", "sha256": "" } ],
            "path_map": {}, "link_check": "unchecked|passed|failed", "broken_links": [] },
  "docs": { "tier": "L0|L1|L2|none",
            "opt_out": [ { "path": "", "why": "", "at": "" } ], "decided_at": "" },
  "skip_auths": [ { "stage": "②", "auth": "用户点名的授权说明", "at": "" } ],
  "notes": [ "sync --from-md 从旧台账吸收的手写注记" ],
  "sync_conflicts": [],
  "history": [ { "rev": 1, "at": "", "event": "init mode=标准" } ]
}
```

**字段口径（与脚本的 blank_state/load_state 逐字对应，别凭印象写）**：

- `rev` 初值 1（init），此后每次成功写入 +1；`history` 只留最近 60 条；`updated_at` 格式 `YYYY-MM-DD HH:MM:SS`（空格分隔，不是 ISO 的 T）；
- 卡号权威形态是 `c<数字>`（命令里写裸数字自动补 c 前缀）；卡上的 `who` 只给阻塞卡用，`source` 是 sync 并账留的来源标；
- **外部动作的"已生效"标记是 `effect_applied`**——旧文档写过的 `done` 字段在权威记录里不存在（`--done` 是命令旗标，落账时改名）；
- `gate_evidence`／`skip_auths`／`notes` 是按需出现的键：`gate --evidence`、`stage --skip-auth`（v1.18 单步直调留痕）、`sync --from-md` 各自写入，没触发过就没有这个键；
- 老的 schema-2 文件缺 `docs` 段不报错——读入时按 L0 默认补齐（平滑升级，`check` 照旧要求 ① done 后文档层在盘）；
- 读入即拒（退 4）的非法形态：schema 比脚本新（提示更新脚本，别猜格式）、rev 非整数、`stages/cards/answers/gates/deps` 段类型不对。

**rev 与 updated_at 分工不同**（这是新口径的核心，别再混用）：
`rev` 每次成功写入 +1，是**并发校验用的整数**——写的时候带上你读到的 `--expect-rev`，不符就退 6 让你重读；
`updated_at` 只是"这条记录什么时候动的"的**说明性时间戳**，永远不参与"谁覆盖谁"的判定。

## 四、阶段四字段与三道硬闸（断点续传的硬闸）

一个阶段标 `done` 之前必须写满四字段，**缺任一项或产物不在盘上，脚本拒写（退 4）**：

| 字段 | 写什么 | 为什么硬要 |
|---|---|---|
| `input_version` | 这步吃的是哪版输入（commit / PRD 版本 / 快照时间） | 否则"重跑"无从判断是不是同一件事 |
| `artifacts` | 产物相对路径（可多条） | **标 done 时逐条查盘**；说做了但东西不在＝续传最坏的坑 |
| `done_criteria` | 完成条件（可判定的那句话） | 防止把"差不多"当成"完成" |
| `recovery_point` | 中断后下一步从哪续 | 要写到"下一个窗拿着就能接"，如"从第 4 节续写，1-3 节勿改"，不是"继续" |

卡级另有一条：`card --state done` 而 `metric` 为空 ⇒ 拒写（退 4）——台账约束 1「状态只有实测值」现在是代码而不是规矩。

**开工也过闸（v1.18 起全 DAG，不是全线性链）**：`stage --state doing` 时前置阶段未 done/na/skipped 拒开工（退 4）。
依赖表：②←①、③←②、④←③、⑤←④、⑦←③、⑥←⑦④⑤、⑩←⑥、⑪←⑥、⑬←⑥、⑫←⑬（⑧ 台账是持续动作不锁，⑨ 默认 na；
每步只挡真依赖它的，被挡时脚本当场打印缺哪些前置）。na/skipped＝显式豁免——跳步必须先
`stage --id X --state skipped` 留痕，不静默。

**单步直调的合法通道（v1.18）**：用户点名只跑某一步（如"只跑安检"）时，加
`--skip-auth "授权说明"`——前置闸放行，但**账上留痕**：进权威记录 `skip_auths`（哪步、凭什么、何时），台账可查。
口头跳步不算数，账上要有这一笔。

**产物清单硬闸（v1.14）**：①②③ 标 done 除四字段外还查"该有的有没有"——清单内产物缺一件、或文件仍在盘上
带着 `<!-- pipeline-scaffold -->` 骨架标记（搭了骨架没填实），都退 4；⑤ 另查卡头标了模块而 `<模块>/MODULE.md`
不在盘。清单内容以 `… docs --show` 活读，此处不手抄（防漂移）。唯一合法退出：
`docs --opt-out <路径> --why <用户原话> --apply`，理由进权威记录，不静默跳过。

**外部动作单独记账**：push / 发信 / 建 PR / 上传这类**不在本项目盘上、重放有副作用**的动作，
用 `action --idem-key` 登记；`resume` 会把已生效的列成「不许重做」清单。判据：
**中断重启后，已完成的外部动作必须零重放**（重放＝重复 push／重复发信，这是事故不是麻烦）。
依据（Stripe idempotency-key B 类／Argo·Durable memoization C 类）→ 修订记录·台账模板移出节。

## 五、已问过／已授权（不重复确认清单）

- 要向用户确认的每一件事，**先 `answer --id <项> --check`**（已答过退 0；未答退 1＝可以问）；
- 拿到答复立刻落账：`answer --id <项> --answer <结论> --source 用户已说明|用户授权|沿用上次|推导 --apply`；
- `--source 推导` 表示是 AI 替用户拍的（要能在台账里看出是谁定的），别把它写成"用户已说明"；
- 台账第七节自动生成这张表，`resume` 也会打印它 ⇒ 新窗口不会把问过的再问一遍。
  依据：**重复确认已说明/已授权的事项是缺陷**（外部审查 2026-10-11 复核；「先查账再开口」与 §一 启动路由同口径）。## 六、并发与锁（多窗／多分身同写一棵树）

- **单写者**：§一 的原子替换就够了，不用取锁；
- **多写者**：加两件事——
  1. **租约锁**：`--holder <窗口名>` 取锁（`O_CREAT|O_EXCL` 原子建锁）＋ 心跳，租约默认 3600 秒（`--lease` 可调）；
     判陈旧按**锁记录里登记的租约**算（来者自带的租约不算数，另设 5 秒下限）；
     同窗再取＝续心跳不重取（代次不变）——缺这条，用 `--keep-lock` 的窗口会把自己锁死；
     崩窗留下的**陈旧锁绝不自动接管**，必须本人显式 `--takeover`（代次 generation +1，只增不减）；
     **接管只对陈旧锁生效**——租约内的活锁谁加 `--takeover` 都照样退 5；
     `unlock` 只准登记的持锁窗本人交锁，替别人交一律拒（无锁时幂等退 0）。
  2. **rev 乐观校验**：`--expect-rev` 读到哪版就按哪版改；版本不符退 6，重读再改，**永不整份覆盖**。
     语义与 HTTP `If-Match`/ETag 同款（A 类依据：RFC 9110 §13，检索 2026-10-15；原稿误引 §4.12 已改）。
- 退出码与「多 Agent 团队协作文档治理」的 `edit_lock.py` 保持同一套（同一体系里两套码＝换工具就要重背一遍表）。

| 码 | 含义 | 该做什么 |
|---|---|---|
| 0 | 通过／无事（含 `unlock` 时本无锁＝幂等成功） | — |
| 1 | **检查不通过／查询为否**：`check` 对账漂移·缺派生物·① done 后缺件·骨架未填实；`deps --check-links` 断链；`answer --check` 未答过；`action --check` 未做过；写后读回不符已回滚。<br>另注：`mode --decide` 平档时也返回 1——那是"**该问用户**"，不是错误 | 查询类退 1 不是故障（未答就去问、未做就去执行）；对账类看打印的具体条目，改权威记录后重跑 `render` |
| 2 | **参数或路径错误**：未知档位/阶段/卡状态/门禁值、`--signal` 缺 `=`、`--map` 缺 `=`、`--opt-out` 缺 `--why`、`sync --from-md` 文件不在、未带子命令；**`selftest` 有 FAIL 也退 2** | 按打印的可用值改命令；selftest 红＝先停下修环境，别带病往下跑 |
| 3 | 缺权威记录（还没 `init`） | 新项目 `init`；旧台账先 `sync --from-md` |
| 4 | **硬闸拒写**：阶段四字段缺／登记产物不在盘／卡无实测 metric／**顺序闸**（前置未 done/na/skipped）／**清单闸**（清单件缺失或仍是骨架、⑤卡头标了模块而 `<模块>/MODULE.md` 不在盘）／deps 登记不存在的件／**权威记录或锁记录本身非法** | 补内容或先补前置再标；清单缺件的唯一退出＝`docs --opt-out --why`；记录非法时**别手改**，先确认谁写坏了 |
| 5 | 锁被他人**有效**持有（租约内）；活锁加 `--takeover` 也拒；接管被别的窗抢先也退 5 | 等它 `unlock`，或等租约过期（退 7）再接管；不许绕锁直接写文件 |
| 6 | rev 版本冲突 | `show --json` 重读，按新版重做这次改动 |
| 7 | 租约过期（陈旧锁）：取锁与 `unlock` 撞上陈旧锁都退 7 | 现场确认无人正在写，再 `--takeover` |
| 8 | 拒写人手写的同名视图（文件头无 AUTO-BEGIN） | 人工确认并改名，或把内容并账进权威记录 |

## 七、旧台账怎么并进来（`sync --from-md`）

老项目往往已有一份手写 `台账.md`（三区制格式，来自多 Agent 文档治理 v1.3）。**不手抄、不重打一遍**：

```
py scripts/pipeline_state.py sync --root <项目根> --from-md docs/pipeline/台账.md --apply
```

- **只吸收权威记录里没有的**：state 里没有的卡、空着的标题、done 卡空着的实测数字、
  `>` 引用的手写注记（进权威记录的 `notes` 键）；
- **state 已有值的字段冲突＝保留 state、把 md 侧原值登记进 `sync_conflicts`**（mode/status 不同同样登记）——
  脚本永不拿 md 覆盖 state、也永不自动判胜负；冲突会在台账**第十一节「待人工裁决」**把两侧值都列出来等人拍板；
- 判据：**并账不能变成"挑一份覆盖另一份"**——那正是被废除的旧毛病换了个入口；
- 并账只在 `--apply` 且确有吸收或冲突时写盘，写完顺手重画视图；之后跑 `check` 必须**退 0** 才算并干净。

## 八、生成的台账.md 长什么样（十一节，不用手写）

```
# {项目名} · 交付流水线台账（生成视图＝派生物，真源是 state.json）
## 一、阶段进度（四字段齐才允许标 done）   ← 步/阶段/状态/输入版本/产物位置/完成条件/恢复点
## 二、在做（最多一张）
## 三、待执行（按依赖顺序）
## 四、做完                                ← 卡行尾带「模块：」字段，对齐模块地图（铁律 16）
## 五、阻塞区
## 六、门禁（未 passed 不许收尾／投递）
## 七、已问过／已授权（不重复确认清单）
## 八、外部动作账（已生效的不许重做）
## 九、依赖快照（版本＋哈希＋路径映射）与链接检查
## 十、文档层（L0 默认落地；显式退出必须带理由）   ← v1.14 起：逐件列 ○ 在盘／⊘ 已退出（带理由与时间）
## 十一、待人工裁决                        ← 只有并账冲突时才出现
```

一~五节即原「在做/待执行/做完/阻塞」三区制（格式沿用治理 v1.3，只是改为生成）；
六节是第⑬/⑭步门禁的机器可读版；九节里若某条路径映射写成**本机绝对路径**，
生成视图会当场标「🔴 本机绝对路径（发布前必须改成相对形态或删掉）」，断链同理标「🔴 断链」——发布前的泄漏扫描靠这一眼。
（十节/十一节的编号沿革 → 修订记录·台账模板移出节。）

## 九、中断恢复的读法

```
py scripts/pipeline_state.py resume --root <项目根>
```
打印：**该从哪一阶段续**（已 done/skipped 的步不许重跑；附该阶段的恢复点／完成条件／输入版本／产物已在与尚缺清单）、
**卡状态汇总**（在办/待办/阻塞/已完成）、**不许重做的外部动作**、**已问过／已授权别再问的事项**（有并账冲突时另报条数）。
主 skill 启动路由第 0 步就是它（§一 权威记录优先，不靠记忆、不靠"上次我们聊到"）。

## 十、收尾归档

项目完成（阶段⑫）时：⑫ 开工本身有前置（⑬ 必须 done ⇒ 先 `gate --name security_L1 --value passed --apply` 落账）；
随后 `check` 退 0，归档收口跑 `… archive`（v1.25.0：自动改名 台账_归档_YYYYMMDD.md＋置已归档；
改名后可在归档件顶部 AUTO 标记之外补一行"本项目已交付，台账仅供追溯"）；
`state.json` 留在原地别删（它是这份归档的机器可读真源，删了归档就成孤本）。归档后的目录不再跑 check/render
（活台账已不存在；归档态下 check 反向要求活台账不存在——再冒出来＝C19 的「复活」警）。

`check` 另有一条收尾闸：项目状态写着「已完成」时，`security_L1` 必须 passed、`outward_claims` 只认 passed/na。
项目状态的合法写入通道（v1.25.0 补齐旧缺口）：`… status --set 已完成`（自带两道门禁反查）／`… status --set 已归档`；
仍禁手写 state.json。

## 十一、个人适配层（不在本细则里）

本机专属的东西（本机技能库路径、现役项目的既有台账/卡/evidence 惯例、个人习惯口径）一律放
本机那份 `personal.local.md`（放在本细则同目录，照 `references/personal.example.md` 样板复制，
别直接改样板），发布时被 `*.local.md` 排除，不跟本 skill 出仓。
判据：**删掉那个文件，本 skill 在别人机器上照样能跑**；本细则里出现的每个路径都必须是相对形态。
