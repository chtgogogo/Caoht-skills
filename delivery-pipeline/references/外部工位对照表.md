# 外部工位对照表（市场插件可选外挂 · 接线不改骨）

> **两条硬规则，凌驾本表一切内容**：
> ① **产物一律落 `<项目根>/docs/pipeline/`**——外部插件默认往自己的目录写（见 §三第 2 条），派遣时必须显式改道，并把它实际写到哪记进台账与 `state.json`。
> ② **判定权与结论永远在本地**——外部 skill 可以产出内容（设计物、字段、清单、模板），**不得**替本流水线做"通过/不通过"结论，也不得改写本库的红线与五态判定。
>   不可让渡的具体面（无论启用哪个工位都一样）：**各步门禁与五态的判定结论、用户拍板权、本库红线与宪章**。
>   逐工位借什么/管什么见 §一 两列的分界；遇到表外新工位怎么判，走 §六 三问。
>
> 定位：本表只登记"哪些工位可以让市场插件顶、借它什么、本地仍管什么"。启用是**按需**的，不启用不阻塞流水线（与 §〇 依赖自检同一降级思路：缺就当没有）。

## 一、工位对照

## 二、不并入清单（重叠且本地纪律更强 → 只借字段，主干留本地）

> 表外新工位（新装了插件、或插件升版冒出新 skill）先过 §六 三问再决定进不进本表；判完"只借字段"的，照本表格式追加一行，不重排已有行。

| 外部 skill | 本地对应 | 为什么不并 |
|---|---|---|
| `check` / `qa` / `audit` | `Cao-项目验收官`、`代码审查-双轴PR改动审查` | 三者 findings **无证据槽**（字段仅 category/severity/description/suggestion/location），"待确认/N/A"有但无"原始输出落盘"；本库是五态 + 命令与退出码 + `文件:行号` + 三禁反作弊 |
| `retro` | `证据复盘-AI编程对话转九段可核验证据链` | 它只要求"对照实际度量（如有）"，无数据即靠口述；本库要求证据链可核验 |
| `prd` / `需求文档撰写` | 流水线 ③ | 双 PRD 生成器 = 双入口必打架；且 `需求文档撰写` 只要求"有数据支撑"，**无引证与禁编造条款**，弱于 ③+⑭ 的组合 |
| `stories` | 流水线 ⑤ / `需求转Issue` | 借写法不借流程：它不产出可执行卡，也不带"验收先于实现" |
| `frame` | `头脑风暴-先想清再写码` | 本库更严（批准后为实现前置门），借它的三入口分流即可 |

## 三、启用姿势（三条＋第 4 条检查清单，缺一即视为未启用）

1. **调用**：Qoder 宿主用限定名（`product-design:prd`、`pm-output-engine:需求文档撰写`）经 skill 调度入口调用；未装该插件的机器整段忽略。**插件本体只读**——它装在 `plugins\cache\qoder-marketplace\<插件>\<版本号>\skills\`，**带版本号目录，升级即另开新目录**，任何写进插件的改动当场作废。**版本漂移两条应对**：① 引用插件一律写**限定名**，禁写带版本号的绝对路径（升级换目录，路径即断链；指向名字，不指向版本快照）；② 启用时把「限定名＋版本号」记进该步 `input_version`（台账四字段之一），它是 §五 复扫的对照锚。
2. **落盘改道**：外部插件写自己的 `spark-output/…`（它的协议文档另有 `.spark/…` 写法，两份不一致，实测 28 份 SKILL.md 全用 `spark-output/`）。派遣提示词里必须显式写"产物写到 `<项目根>/docs/pipeline/外部/<skill>/`"，并把实际产物路径记进该步的 `artifacts` 字段（相对路径，**done 硬闸逐条查盘**——外挂产物并入正常产物清单受同一硬闸管，不另立门）。🔴 本库 `state.json` **没有** `artifacts.external` 这个字段（脚本实查），旧版本表这么写过，以本条为准；插件名与版本记 `input_version`，字段语义见 `台账模板.md` §四。
3. **token 闸门**：外部 skill 单个正文 500–1350 行（另需读它的协议文档约 34KB）。一次只启用**一个**工位，只在"确需它的产物形态"时启用；本地细则能解决的不启用。
4. **启用检查清单（逐项可勾，按序执行；任一项不过即不启用或中止）**：
   - [ ] 本地先答：本库细则/模板能否产出同等形态？能 ⇒ 不启用（与铁律 9 按需加载同款判据）；
   - [ ] 已读该工位行「本地仍管什么」，逐条转写成派遣提示词里的**禁令句**（子代理任务不写明输出格式与任务边界 ⇒ 越界、重复或留缺口，Anthropic 多代理实证，见 §六 依据）；
   - [ ] 派遣提示词含第 2 条落盘改道句（原句照抄，别现场改写路径）；
   - [ ] 产物回来核三件：实际落盘路径＝台账登记路径；产物里无「通过/不通过」类越权结论（有 ⇒ 判定作废、只取内容，判定由本地按本库口径重下）；借来的字段已并入本地产物，不是散在外部目录等下次现找；
   - [ ] 该步 `input_version`＝插件限定名＋版本号，`artifacts`＝产物相对路径（标 done 时硬闸自动查盘）；
   - [ ] 此后插件若升级：未按 §五 复扫前，不据它新产物下判定（已落本地的旧产物不受升级影响——这正是产物改道落本地的意义）。

## 五、维护

- 外部插件升级或换版后**先复扫再采信**：它的 skill 数、路径、字段可能变；本表按 `路径:行号` 记的判断过期就改本表（本表是指针型文本，只写现状，不记"上一版曾如何"）。复扫的对照锚＝各步 `input_version` 里记的旧版本号（§三第 1 条）；复扫完把新版本号写回去。凡发现哪里写死了旧版本绝对路径，一律改回限定名（指针原则：指向名字，不指向版本快照）。
- 新增外挂工位 → 同步 `__SKILL详细名映射表.md` 与本库 CHANGELOG；改完跑本机的 skill 包体检脚本
  （路径与命令见本机专属件 `personal.local.md`——就是 `references/personal.example.md` 那份样板
  复制出来后填真值的副本，随 `*.local.md` 规则不随本 skill 出仓；
  没有该脚本时改跑 `py scripts/depends_snapshot.py check` + 发布仓 `library_check.py`，同样能抓到断链与绝对路径泄漏）。

## 六、取舍判据：「借覆盖面不借判定纪律」的可操作三问（2026-10-15 追加）

> v1.4.0 定的口径落到**遇到新工位时**怎么判——按序三问，不听插件的自我介绍，只看实证；任何一问答出"判定类"即按「只借字段」处理。

| 问 | 分界线 | 怎么判（实证动作） | 答案落点 |
|---|---|---|---|
| ① 它的产物是**内容**还是**结论**？ | 素材/字段/清单/模板/话术/调研条目＝内容，可借；「通过/不通过/合格/放行」类判定句＝结论，不借 | 翻它实际产出的样例找判定句；有 ⇒ 判定作废、只取内容，判定由本地按本库口径重下 | 顶部硬规则② |
| ② 它的**证据形态**达标吗？ | 三处查它的 SKILL.md：有无「原始输出落盘」要求／有无命令＋退出码／有无 `文件:行号` 定位 | 三处全无（如 §二 `check`/`qa`/`audit` 的 findings 只剩 category/severity/description/suggestion/location）⇒ 它的审查/验收产物只能当清单素材，不当判定依据 | §二 不并入清单 |
| ③ 本库对应环节**纪律更强吗**？ | 本库该步有证据链/五态判定/门禁/验收先于实现 ⇒ 主干留本地，只借它多出的覆盖面 | 对照 §一「本地仍管什么」列＋该步本库细则逐条比 | §二＋本表该行 |

- 两个词的分界：**覆盖面**＝它管而本库不管的主题、段落、清单条目；**判定纪律**＝证据形态＋通过标准＋反作弊。借前者，后者永远本地。
- 依据（强度如实标，2026-10-15 原文抓取）：Anthropic 工程博客（**B 级**）——子代理任务必须带显式输出格式与清晰任务边界，综合与"是否继续"的判断留在 lead（＝"判定权在本地"同构）；渐进披露、按需加载（＝一次只启用一个工位的省 token 依据；**"一次只一个"是本库约定**，不冒充外部依据）。三问本身是本库约定，有效性由 §二 实测证据支撑。原文明细 → 修订记录·外部工位移出节。
