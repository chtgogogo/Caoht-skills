## §1 磨设计（阶段①）

骨架源＝头脑风暴九步（冻结副本 `references/depends/头脑风暴_v1.1.md`），提问技巧源＝grill-me（`references/depends/grill-me_v1.0.md`）；下面 8 条规则是两者的本地化收口——**照 1~8 条执行即可，不必回读原文副本**。规则：

1. **每问必带推荐答案与分析，且一次只问一个问题**：先给推荐选项+理由（适用/优缺点/成本），用户拿现成选项决策；选了非推荐项先确认理解取舍。**一问一答**——每条消息只抛一个问题，不倾倒方案（连珠炮盘问会淹没零基础用户）。
2. **盘问分工红线——用户拍「要什么」，AI 包办「怎么做」**：用户能答需求/价值/成功标准，答不了技术方案（用户计算机基础≈0 是常态而非例外）。所有技术决策必须包成**带推荐的大白话选择题**（选项+取舍+理由），用户拍选择不拍设计；禁止把方案设计推给用户（"你想用什么框架？"=失职），也禁止替用户拍需求（"你肯定就是想要 X"=越权）。依据：Anthropic Claude Code best practices（"describe what you want and Claude figures out how"，检索 2026-10-11）。
3. **决策树盘问**：先判该不该拆——需求含多个相互独立的子系统时先分解成子项目、各走规格→计划→实现循环，别在一张决策树上白烧盘问轮次；然后列出 3~6 个顶层决策分支 → 从最基础的问起（其他分支常依赖它）→ 逐支问到没有"看情况"残留，**支内子决策同样按依赖序解决**（乱序问会答完 A 又被 B 推翻、来回翻烧饼）。
4. **轮数弹性**：问到无死角为止（两轮或四轮都有可能）；**每轮结束出书面小结**让用户确认，防跑偏。
5. **HARD-GATE**：设计未获批准前，禁止写任何代码/搭任何骨架。
6. **无情 YAGNI**：每个方案砍掉不必要功能；每个方案必须如实列出已知缺陷与翻车场景。
7. 能靠读项目文件回答的问题，自己查，不问用户。
8. **盘问决策检查单 12 维逐项过（v1.15.0）**：磨设计必须对照 `references/大计划产物模板.md` §1 的 12 维清单**逐项**给结论（决策或「经确认：不适用」），禁跳项——死角清单预设进文件，不靠执行者现场发挥（实测触发：三平行窗同一需求，一窗漏掉「过去时刻」这条两窗都抓到的高频坑）。产物结构照同文件 §2/§3 骨架填实并带 §5 新鲜度头；用户不在场走 §4 自主降级协议（逐项自答+标【推定】+停点请用户复核）。本步的活是**填实后删首行 `<!-- pipeline-scaffold -->` 标记**；填实后的结构由 `check` 验结构锚（缺锚记「警」不记红——刻意自定义不炸闸，但当场点名）。填实前对产物做**规格自审两查**：一致性（章节之间有没有互相矛盾的说法）与歧义（有没有能读出两种解读的句子）——查到先改再交。

产出 `docs/pipeline/设计纪要.md`：七节结构照 `references/大计划产物模板.md` §2 骨架（init 已生成），其中 **§1 交付物定义**（铁律 12）与 **§3 盘问决策留痕**（12 维）是磨设计独有的两节，别处不重抄；叙述部分讲道理可以像文章，需求条目必须像条款（见 §3.2）。

### §1.8 文档层落地（建账动作：定文档档＋建文档层文件）

**两条轴别混**（细则 §8.0）：流程档（轻量/标准/企业，`mode --decide` 按信号定）管跑几步、审几层；**文档档（L0/L1/L2）管写几份文档、用不用自动化工具**——本步由 AI 带推荐、用户拍板，选定结果写进设计纪要。

- **默认推荐 L0**：demo／个人项目／时间紧——八件文件、零写盘工具；
- **L1 信号**：模块超过 5–8 个，或维护开始吃力（补齐模块四件套＋模块索引＋链接检查）；

1. **建账即搭骨架**：`init` 已默认搭好 L0 六件骨架（`AGENTS.md`／`CONTEXT.md`／`docs/权威源表.md`／`docs/human/小白手册.md`／`docs/human/故障对照表.md`／`<落盘目录>/上下文体检.md`），**标准/企业档另搭三份大计划产物骨架**（设计纪要／技术选型记录／PRD；轻量档不搭——索引原文"①一句话版/③规格层可省"）。本步的活是**填实**（磨设计的答案直接写进骨架），不是从零建；填实后删掉首行的 `<!-- pipeline-scaffold -->` 标记。棕地项目 init 时不覆盖已有件。整项目不要文档层＝`init --docs-tier none`（从建账留痕）；单件不要＝用户明说后走 `docs --opt-out`（见下）。
2. **① done 硬闸**：`stage ① --state done` 时脚本逐件验盘——缺一件、或仍是骨架 ⇒ **退 4 拒写**；轻量档豁免设计纪要（索引"一句话版"），文档层六件照样要。标 done 还须**写满阶段四字段**（输入版本／产物位置／完成条件／恢复点，铁律 19——恢复点写到"下一个窗拿着就能接"）。**顺序闸**：② 标 `doing` 前本步必须 done（na/skipped 算显式豁免；单步直调走 `--skip-auth "授权说明"` 留痕放行）。退出唯一通道：`docs --opt-out <路径> --why <用户原话>`（不带理由退 2；退出记录进权威记录与台账第十节）。
3. **持续在盘**：① done 之后删掉任何一件，`check` 照样判红——落地是持续状态，不是一次性动作。`check` 同时逐件验**结构锚**（缺锚记「警」不记红；锚表＝脚本 `STRUCTURE_ANCHORS`，只管"结构块在不在"、不管内容对错——语义面归出题验收与人）。
   命令形态：`py scripts/pipeline_state.py docs --root <项目根> --show`（逐件状态：✓已落地／◐骨架／✗缺失／⊘已退出+理由）。

## §2 技术选型分层深选（阶段②·选型树＝层 0~15）

**总规则**：
- 展开成表格的层（层 1/3/5/6 及实际展开的层）给 **5~9 个候选**；行文简列的层（层 4/7~15）至少给**默认项＋2 个替代**；每个候选/选项必须**如实告知缺陷与翻车场景**（只说优点 = 卖文创收智商税）；
- 一层选完才进下一层（下层候选受上层约束）；
- **全部选完后做冲突调和**：单独最优 ≠ 组合最优（如 Rust+K8s+微服务 对个人项目 = 过重三连），AI 给出调和方案（降级/替换/补位）并说明理由；
- **按模式裁剪（钉死口径）**：★层＝树中标 ★ 的五层（0/1/3/5/6）。轻量只走 ★层；标准＝★层＋层 9（测试）＋**被已选项直接牵出的层**（例：选 Next.js ⇒ 层 7 渲染、层 8 前端深选；树里自带的展开条件如层 2"中大型才展开"照树执行）；企业全走。裁剪时告知"跳过了什么、什么时候会需要它"，写进产出骨架第 4 节。

### 层 0 · 项目目标与约束（★必问，决定后面所有层）
| 维度 | 选项示例 |
|---|---|
| 项目类型 | 官网 / 中后台 / 电商 / IM / 小程序 / AI 应用 / IoT / 游戏 |
| 规模 | 个人 / 团队 / 企业级 |
| 约束 | 时间 / 预算 / 团队技能 / 招聘成本 / 合规 |
| 非功能 | 并发 / 延迟 / 可用性 / SEO / 跨端 / 可维护性 |

### 层 1 · 语言与运行时（★）
| 候选 | 适用 | 缺陷/坑 |
|---|---|---|
| Python | AI/数据/快速后端，生态最全 | 性能弱、GIL 限制并发、部署依赖管理烦 |
| JavaScript/TypeScript | 前端唯一原生语言，全栈通吃 | JS 动态类型坑多（务必上 TS）；npm 生态质量参差 |
| Java | 企业级后端、大厂标配 | 样板代码多、启动慢、个人项目过重 |
| Go | 高并发服务、云原生基建 | 泛型与生态较年轻、Web 框架不如 Python 顺手 |
| Rust | 极致性能/安全关键/基础设施 | 学习曲线陡峭，开发速度慢数倍，个人项目慎选 |
| C++ | 游戏 engine/高频交易/嵌入式 | 内存安全坑、开发成本最高，Web 后端不推荐 |

### 层 2 · 架构模式（中大型才展开）
单体（默认起步）/ 模块化单体 / 微服务（运维成本×N，个人项目毒药）/ Serverless（冷启动+供应商锁定）/ 事件驱动 / BFF。

### 层 3 · 后端框架（★）
| 候选 | 适用 | 缺陷/坑 |
|---|---|---|
| FastAPI(Python) | API 快速开发、AI 应用、自动文档 | 异步生态半成熟，ORM 需自选 |
| Django(Python) | 全功能后台（自带 admin/ORM/认证） | 全家桶重、异步支持弱 |
| Spring Boot(Java) | 企业标准、招聘面最广 | 重、内存占用大、个人项目学习曲线陡 |
| Express/NestJS(Node) | 全栈同语言、实时应用 | 回调/异步陷阱、CPU 密集弱 |
| Gin/Go 标准库 | 高并发轻量服务 | 生态要自己拼装 |
| Axum/Rust | 性能极致 | 学习+开发双慢 |

### 层 4 · API 与通信
REST（默认，生态最广）/ GraphQL（灵活但缓存与复杂度坑）/ gRPC（内部高性能，浏览器需网关）/ tRPC（TS 全栈类型安全）/ WebSocket（实时双向）/ SSE（服务器推送，RAG 流式标配）。契约：OpenAPI / Protobuf。网关：Nginx / Kong / 云网关。

### 层 5 · 数据与存储（★）
| 候选 | 适用 | 缺陷/坑 |
|---|---|---|
| SQLite | 个人项目/原型，零运维 | 并发写弱，不适合多实例 |
| PostgreSQL | 关系型默认最优解 | 运维需学习 |
| MySQL | 国内生态最广 | 功能较 PG 少 |
| MongoDB | 文档型/ Schema 不定 | 事务弱，别当关系库用 |
| Redis | 缓存/会话/队列 | 内存贵，持久化要配 |
| Milvus/pgvector/Chroma | 向量检索（AI 应用） | 运维成本递增 |
| Elasticsearch/Meilisearch | 全文搜索 | ES 重且吃内存 |
| Kafka/RabbitMQ | 消息队列 | 中大型才需要 |

### 层 6 · 前端框架与元框架（★）
| 候选 | 适用 | 缺陷/坑 |
|---|---|---|
| Vue3 + Element/Naive | 中文生态最好、上手最快 | 大型复杂状态管理要纪律 |
| React + Next.js | 生态最大、招聘最多、AI 生成质量最高 | 概念多（hooks/SSR/RSC），学习曲线最陡 |
| Svelte/SvelteKit | 代码量最少、性能好 | 生态与招聘面小 |
| 原生 HTML/JS | 单页小工具零依赖 | 复杂度上来后不可维护 |
| Angular | 大型企业规范统一 | 学习曲线最陡、个人项目过重 |

### 层 7 · 渲染模式
SPA（默认）/ SSR（SEO+首屏）/ SSG（静态内容）/ ISR / 边缘渲染 / CSR+API。SEO 有要求就别纯 SPA。

### 层 8 · 前端深选
模板（原生HTML / JSX/TSX / Vue SFC / Svelte 模板）· 样式（Tailwind / CSS Modules / 组件库自带）· 状态（Pinia / Redux / Zustand）· 路由（Vue Router / React Router / TanStack）· UI 组件库（Element Plus / Ant Design / shadcn/ui / MUI）· 请求（axios / TanStack Query）· 表单（VeeValidate / React Hook Form）。

### 层 9 · 测试与质量
pytest / Vitest-Jest / JUnit；Playwright / Cypress（E2E）；ESLint / Prettier / Biome；契约测试 / 性能测试。**评测集驱动也属此类**（AI 应用首选）。

### 层 10 · 认证授权与安全
JWT（简单无状态）/ Session（传统稳妥）/ OAuth2-OIDC（第三方登录）/ Keycloak-Auth0-Clerk（全家桶）；RBAC / ABAC。**安全底线**：参数化 SQL、XSS/CSRF 防护、限流、密钥只放环境变量。

### 层 11 · 部署与基础设施
直接部署（个人最简）/ Docker（默认推荐）/ Kubernetes（企业，个人毒药）；云（阿里云/腾讯云/AWS/Cloudflare）；CDN；CI/CD（GitHub Actions 默认）；IaC（Terraform，企业级）。

### 层 12 · 可观测性
日志（Loki/ELK）· 指标（Prometheus+Grafana）· 链路追踪（OpenTelemetry/Jaeger）· 错误监控（Sentry）。个人项目：结构化日志 + Sentry 免费档就够。

### 层 13 · 工程化与构建
包管理（pip-uv / npm-pnpm / Maven-Gradle / Cargo）· 构建（Vite 默认 / Webpack 旧项目）· Monorepo（pnpm workspace / Turborepo，多包才用）· 分支策略与文档。

### 层 14 · 集成与第三方
支付（支付宝/微信/Stripe）、短信/邮件、对象存储（S3/OSS/MinIO）、第三方登录、地图/AI 服务。按需引入，每个都加一层故障面。

### 层 15 · 成本、合规与团队
云成本估算 / 供应商锁定风险 / GDPR-等保 / 招聘与学习成本 / 长期维护承诺。**个人项目也要问自己一句：这个项目三个月后我还维护得动吗。**

### 冲突调和示例
用户全选"最强"：Rust + 微服务 + K8s + GraphQL + Next.js —— 对个人项目输出调和案：**Python/FastAPI + SQLite/PostgreSQL + Vue3 + Docker 单体**，说明"每项降级省下的时间够你把产品做完上线三次"。

### 产出与闸门（阶段② 收口，脚本口径）

产出 `docs/pipeline/技术选型记录.md`——**落点固定**：`stage ② --state done` 硬闸认这个位置，只有 `docs/adr/` 之类的"换家"版本＝退 4。轻量档 ② 无此硬闸（索引产物列为"—"，可不产；要产仍落这里）。标准/企业档 init 已按骨架生成，填实后删首行 `<!-- pipeline-scaffold -->` 标记。骨架五节（与脚本 `PLAN_STUBS` 一致，改结构两处同步）：


## §3 PRD（阶段③）

> **交付物定义锁定（铁律 12 前置，先于一切功能讨论）**：磨设计的第一个产出不是功能清单，是一句可验证的交付物定义——谁用（具体到角色）/怎么用（一次真实操作）/第一次交付长什么样（30 分钟内能发生的场景）。例：会计朋友拿到包，30 分钟内启动、浏览器登录、导入 3 张 PO、2 张 GRN、5 张发票、看到差异并导出，全程除启动外零命令行。锁定后写进**设计纪要 §1**（PRD 按骨架留指针指设计纪要 §1，不重抄），后续所有验收以此为准（教训锚点：45 轮没人问过给谁用、725 测试全绿但目标用户不能用——同 SKILL.md 铁律 12）。

### §3.1 项目宪章（PRD 头部一节，**不新建文件**）

**是什么**：本项目**不可违背**的约束，5–8 条，每条都可判定（带数字、单位或"不得／禁止／只允许"这类硬词）。切卡、验收、收尾都对照它——它回答"哪怕功能全绿，犯了这几条也算失败"。

**为什么不另立一份 `constitution.md`**：`AGENTS.md` 已有一格红线摘要（`项目文档与上下文规范.md` §2），再起一份文件＝同一信息两处手写（铁律 17）。所以宪章进 **PRD 头部一节**，`AGENTS.md` 那一格改成一指针：`本项目宪章见 docs/pipeline/PRD.md §项目宪章`。

```markdown
### 项目宪章
1. 现场演示必须零外网依赖：断网时启动命令数量不得变化。
2. 运行时依赖的许可证只允许 MIT 或 BSD 系，禁止引入 GPL 依赖。
3. 错误反馈必须是中文人话，且不得出现堆栈信息。
4. 页面刷新与服务重启后，数据必须仍可从 SQLite 读到。
5. 启动命令必须只有 1 条，端口固定 8000。
6. 列表接口 p95 延迟 <500ms（测量命令：`k6 run perf/smoke.js`；环境没装 k6 则收尾降级为
   基线对比脚本或人工压测记录，写明降级路径——阈值三件套：指标名＋数值＋测量命令）。
```

🔴 **反例**（这类条目一律退回重写）："性能要好"／"界面要友好"／"代码尽量复用"——不可判定，等于没约束。判据就一句话：**这条能不能不加解释地判出"违反／没违反"**。
🔴 **阈值三件套（v1.28.0）**：宪章里的性能/资源阈值（响应时间/并发/内存/启动时长…）必须写成**指标名＋数值＋测量命令**三件齐——缺测量命令的阈值记**警**（机械断言=规格侧，EverSpec spec_check 管；管线侧硬要求在 ⑫ 收尾第 1 步：逐条跑测量命令留证据，装了 k6/Lighthouse 就用、没装降级写明）。只写数字不给测法的阈值在收尾那天必然变成"感觉达标了"。

**条数为什么是 5–8**：少于 5 条盖不住常见决策（技术选型/依赖许可证/数据持久/对外反馈/启动方式各占一条就没了），多于 8 条没人会回看——本库约定，不是标准（同构对标 spec-kit constitution，B 级，明细 → 修订记录·阶段①移出）。机械判据在 `spec_check.py` 的 C11（整节缺失、含模糊词、不含阈值、条数越界都翻红；PRD 整件不在盘时 C11 记「警」不记红——"没燃料"，红由 ③ 的阶段硬闸管）。**派工时这 ≤8 行随卡带上**（`阶段⑥执行与派遣.md` §2 装配上下文·子代理模式第 1 条；§3 提示词卡模板同要求"逐条贴"），它是每张卡的隐式禁改清单。

### §3.2 功能需求条目用 EARS 句式（五种，句式表只在一处）

五种合法句式与例句见 `规格层-主规格变更与归档.md` §3（**同一张表不两处抄**）。本节的三条边界：

1. **只约束功能需求条目**，不约束设计纪要的叙述部分——设计纪要讲道理可以写得像文章，需求条目必须像条款；
2. **EARS 是需求层，Given/When/Then 是卡验收层，两层不重抄**：EARS 一句说"系统承诺什么"（`当…时，系统应…`），GWT 展开"怎么验这条承诺"（`Given 已有 09:00–10:00 的预约 / When 提交 09:30–10:30 / Then 拒绝并给出人话理由`）。卡的第 8 节继续用 GWT（`阶段⑤切任务卡.md` §5.1），别在 PRD 里再写一遍用例。需求层另有一个**可选的场景块**（`#### 场景：`＋粗体 WHEN/THEN，多分支行为逐条拆）＝契约枚举，格式与判据（C15）见 `规格层-主规格变更与归档.md` §3——它与卡例表的分工同此条：场景块答"承诺拆开哪几种触发→结果"，例表答"怎么验这一卡"，两层两用，不互抄；
3. **句式里的主语（用户／系统／会议室…）用项目术语表的口径**——术语表由 `domain-modeling` 维护在 `CONTEXT.md`，本支只引用不自建（`项目文档与上下文规范.md` §0）。

PRD 定稿之后，**行为条款搬进 `specs/`**（③立约）：PRD 留"要做什么、什么优先级"，规格层留"系统当前承诺什么行为"。谁抄谁一遍，两处就开始分叉。
