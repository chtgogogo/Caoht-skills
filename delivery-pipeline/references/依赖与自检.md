# 依赖与自检（阶段〇启动自检的依据）

> 设计原则：本 skill **自包含**——凡引用了外部 skill 的精华内容，原文副本已落档在
> `references/depends/`，外部 skill 消失也不会让本 skill 报废。
> 自检**不靠人肉数文件**：两个自带脚本（零第三方依赖）跑一遍约 5 秒，结果分三级处理。

## 一、两个自检脚本（口径：能跑的读数 > 抄下来的数字）

| 脚本 | 命令 | 管什么 |
|---|---|---|
| `scripts/pipeline_state.py` | `py scripts/pipeline_state.py selftest` | 状态机自证（合成夹具，不碰任何真实项目）：断点续传四字段硬闸、租约锁、rev 版本冲突、门禁、派生视图对账 |
| `scripts/depends_snapshot.py` | `py scripts/depends_snapshot.py check` | 依赖对账一条龙：副本哈希 + 路径映射 + 全库相对链接/库内路径检查 |

```
py scripts/pipeline_state.py selftest      # 全绿才继续
py scripts/depends_snapshot.py check       # 全绿才继续
```

`depends_snapshot.py` 的全部子命令（与脚本 argparse 逐字对照；通用参数 `--root <目录>` 换库根，默认 skill 根）：

| 子命令 | 作用 |
|---|---|
| `make [--apply]` | 生成/刷新 `references/depends/快照清单.md`。**默认干跑**（只报"将生成 N 件"，不写盘），加 `--apply` 才真写；**整份文件都是输出**——含 AUTO 块外的标题/引用块/继承声明，不是只有 AUTO 区间重写 |
| `verify` | 盘上 `depends/` 子树 ↔ 清单逐件对账：sha256（清单存前 16 位十六进制、前缀比对）＋路径映射＋成员集——副本被删、新副本漏登都报，判"副本还是不是抓取那天那份" |
| `links [--path a.md,b.md]` | 全库 `.md` 扫相对链接与库内路径提及（`--path` 可只检指定文件）；报断链、报**本机绝对路径泄漏**、报外指声明命中条数 |
| `check [--apply]` | make + verify + links 一条龙。**启动自检用不带 `--apply` 的形态**：它最严，清单没跟上副本也照样红；带了 `--apply` 会先重生成清单，把哈希/清单漂移静默治愈，只剩链接检查还有牙齿 |
| `selftest` | 合成夹具自证（临时目录造最小 skill 树，不碰真实库）：D 系列具名断言验证脚本自身行为（判据能红、继承声明生效、围栏跳过、退出码传导），退 0 全过 / 退 2 有断言挂 |

退出码（与脚本 docstring 逐字对照；`selftest` 例外：0 全过 / 2 有断言挂）：

| 退出码 | 含义 |
|---|---|
| 0 | 通过 |
| 1 | 检出问题（断链/绝对路径泄漏/哈希不符/清单漏登多登） |
| 2 | 用法或参数错（找不到 `depends/` 目录、`--root` 不存在、`--path` 文件不存在） |
| 3 | 清单缺失（verify：先 `make --apply`） |
| 4 | 清单非法（无 AUTO 标记，拒据此对账）或写后读回不符 |
| 8 | make 拒覆盖：同名清单在盘但无 AUTO 标记＝人手写的，一个字节不动退回（selftest D19 证明） |

> 🔴 **副本件数、映射条数一律不在本文抄**（抄了就过期，而且过期得静默无声）。
> 要读数就跑 `check` 或读 `references/depends/快照清单.md` 的生成头一行。
> 本文件的表格只讲**用途与缺失影响**，它不是清单的真源，清单真源是盘上文件 + `make`。

## 四、自检三级处理

| 级别 | 条件 | 动作 |
|---|---|---|
| 🟢 正常 | 两条自检命令都退 0 | 直接开工 |
| 🟡 降级 | `depends/` 副本缺失，但**细则文件齐全** | 提示用户：「依赖副本缺失，将按自包含细则继续（功能不受影响）。可按清单里标注的来源重新补齐」——补齐后：**原样放回（字节一致）则 verify 直接复绿、不用 make**；换了新版本才需要 `make --apply` 重登记 |
| 🔴 报错 | **细则文件本身缺失**（阶段①/⑤/⑥/台账模板/模式判定任一），或两条 `selftest`（`pipeline_state.py` / `depends_snapshot.py`）任一判红，或权威记录/清单本身非法 | 停止流水线，提示用户：「缺少关键细则文件 {文件名}。请从安装源重新获取本 skill，或把该文件手动放回 `references/`」；`selftest` 判红说明脚本本体被改坏，别拿它当"环境问题"绕过去 |

细则文件是否齐全，`depends_snapshot.py check` 的链接检查会覆盖（细则之间互相引用，缺一个就报断链）；
不必再手抄一份文件清单来数——**以前那份 30 行的手工清单正是最容易过期的东西**。

## 五、外指声明与"清单继承声明"的口径

副本头部若写了 `> 【外指声明】某上游件的路径 —— …`，指的是**上游 skill 里的件、本库刻意未收**。
六条规则：

1. **只认人工声明**：解析器只读文件**前 15 行**里的 `【外指声明】` 行，按分隔符切出路径 token。
   🔴 **声明行只列"上游的件"**，别把命令、脚本名混在同一句里——
   工具会把同一行切出来的每个路径样 token 都当成一条声明，`py scripts/depends_snapshot.py links` 混进去
   就成了"工具自己豁免自己"（声明集虚胖）。要写命令就另起一行、换个标记（如 `【外指对账】`）。
2. **没声明一律算真断链**：工具**绝不**按"盘上找不到就自动放行"——那样豁免变成万能钥匙，真断链一起被放掉。
   豁免是换来的，不是白给的。
3. **命中条数可见**：`links` 报告明写"外指声明命中 N 条"，不做静默豁免（静默＝没人知道放过了多少）。
4. **清单继承副本的声明**：`快照清单.md` 的"来源"列会摘录各副本头部原文，于是把摘录来的上游路径带了进来；
   生成器因此**继承**（union）各副本自己的声明写进清单头部，否则"摘录来的引用"会被当成清单新造的断链报错。
   反向验证同样有：抹掉副本声明 ⇒ 清单不再豁免 ⇒ 同一处必须翻红（红点落在清单自己那一行）。
5. **声明 token 的认定标准**（与脚本 `declared_externals()` 逐字对照）：`【外指声明】` 出现在行内任意位置都认（限前 15 行）；
   后面按**顿号/逗号/分号/空白**切开，每个 token 要**含 `/` 或以 `.md`/`.py`/`.sh`/`.json` 结尾**才被认——
   裸名字（如「上游模板」四个字，无斜杠无后缀）不认；首尾的反引号/括号/句读、开头的 `./` 会被剥掉。
6. **生效范围**：链接检查对库内**每个 `.md` 的前 15 行**都认声明（不只 `depends/` 副本，普通细则文件也能声明）；
   但**清单继承**（第 4 条）只 union `depends/` 子树里副本的声明——清单本来就只登记 depends（收录范围见 §九）。

## 六、链接检查的覆盖面与已知盲区（别把绿当万能）

- 检查对象：本 skill 目录下**全部 `.md`**（排除 `*.local.md` 个人适配层，见下 §八）里的
  Markdown 链接目标 + `references/…`、`scripts/…` 这类库内路径提及；
- **围栏代码块内部不检**（示例代码里的假路径不该算断链）——代价：真写进代码块的错路径抓不到，
  代码块内引用要靠两条脚本各自的 `selftest` 具名断言和人工读；
- 本机绝对路径（`X:\…` 或 `/…` 开头）不算断链，**单独报"绝对路径泄漏"**——发布前必须清零；
- 上游件走 §五 的声明口子，未声明的一律红。

## 七、版本同步纪律

`depends/` 里的副本是**快照**，不自动跟随源更新。若源 skill 升级了（如头脑风暴出 v1.2），由维护者决定：
重新拷贝覆盖副本 + 更新副本头部来源标注 → `py scripts/depends_snapshot.py make --apply` 重生成清单 →
`check` 必须退 0。本 skill 的细则若吸收了新版改动，记得同步改细则。
动手前想先看清漂移：先跑**不带 `--apply`** 的 `check`——verify 会把哈希不符的副本逐件点名，确认无误再 `make --apply` 落账。

## 八、个人适配层（出仓时不带）

本机专属内容（本机技能库路径、现役项目的既有惯例等）写在本机那份 `personal.local.md` 里
（照 `references/personal.example.md` 样板复制到本文件同目录，别直接改样板）：
发布映射按 `*.local.md` 全局排除，链接检查也跳过它。
判据：**删掉这个文件，本 skill 在别人机器上照样能跑**；`check` 里"绝对路径泄漏"必须 0 命中。

## 九、清单收录范围与"生成件"边界（附依赖锁定惯例对标）

> 证据标注：【A】＝脚本源码/盘上实测（最高效力，与本文任何冲突处以脚本为准）；【B】＝业界惯例联网对标；【C】＝推断待核实（本文未使用）。

**什么进清单**（判据＝脚本 `list_depends()`：只走 `references/depends/` 一棵子树【A】）：

- **进**：`depends/` 下全部快照件，递归含 `superpowers_assets/` 附属件；排除点开头文件、`.git`、`__pycache__`，以及清单自身（清单是派生物，不给自己登记）。【A】
- **不进**：普通细则（阶段①…、大计划产物模板.md、台账模板…）、`SKILL.md`、`scripts/`、`personal.*`。
  它们是本库自写件，不是上游快照，不存在"还是不是抓取那天那份"的问题；登记进清单只会制造一张永远要人肉同步的对账面。【A】
- 推论：**新增一份普通细则文件 ⇒ 不需要、也不应该进快照清单**。它的齐全性由链接检查兜底——
  别的文件引用它，它丢了就是断链，`check` 当场红（§四）；对它跑 `make --apply` 也**无效果**（脚本根本不走那条子树）。【A】

**"清单是生成件、禁手改"的精确边界**（AUTO 块内、外不是一个待遇）：

- 整份文件——含 AUTO 块**外**的标题、引用块、继承声明——都是 `make` 的输出。手改块外内容**不报错**，
  但下次 `make --apply` 会被整份静默覆盖（不红不叫，比打红更阴）；
- 机器校验只认两样：①文件里含 `AUTO-BEGIN` 标记（`verify` 无标记退 4 拒对账；`make` 对无标记同名件退 8 拒覆盖、一字节不动）；
  ②AUTO 块**内**的表格行——解析器只吃块内行，块外塞同样式的表格行**不生效**（selftest D35 夹具证明）；
- 块内手改会被 `verify` 当场打红（哈希/路径映射/成员集对不上盘上实况）。所以改清单的正道只有两条：
  改副本本身，或改生成逻辑（脚本），然后 `make --apply`。【A】

**对标惯例**（只作理解辅助，判据仍以脚本为准；package-lock/Cargo.lock 锁文件哲学、go.sum 哈希对账、锁外部不锁自家源码——三条明细 → 修订记录·依赖与自检移出节）。
