# 依赖与自检（阶段〇启动自检的依据）

> 设计原则：本 skill **自包含**——凡引用了外部 skill 的精华内容，原文副本已落档在
> `references/depends/`，外部 skill 消失也不会让本 skill 报废。
> 自检**不靠人肉数文件**：两个自带脚本（零第三方依赖）跑一遍约 5 秒，结果分三级处理。

## 一、两个自检脚本（口径：能跑的读数 > 抄下来的数字）

| 脚本 | 命令 | 管什么 |
|---|---|---|
| `scripts/pipeline_state.py` | `py scripts/pipeline_state.py selftest` | 状态机自证（合成夹具，不碰任何真实项目）：断点续传四字段硬闸、租约锁、rev 版本冲突、门禁、派生视图对账 |
| `scripts/depends_snapshot.py` | `py scripts/depends_snapshot.py check` | 依赖对账一条龙：副本哈希 + 路径映射 + 全库相对链接/库内路径检查 |

```
py scripts/pipeline_state.py selftest      # 全绿才继续
py scripts/depends_snapshot.py check       # 全绿才继续
```

`depends_snapshot.py` 的其他子命令：

| 子命令 | 作用 |
|---|---|
| `make --apply` | 生成/刷新 `references/depends/快照清单.md`（**生成件**，AUTO 区间整段重写） |
| `verify` | 盘上副本 ↔ 清单逐件对 sha256，判"副本还是不是抓取那天那份" |
| `links` | 全库 `.md` 扫相对链接与库内路径；报断链、报**本机绝对路径泄漏**、报外指声明命中条数 |
| `check` | 上面三件一起跑（启动自检用的就是它） |

> 🔴 **副本件数、映射条数一律不在本文抄**（抄了就过期，而且过期得静默无声）。
> 要读数就跑 `check` 或读 `references/depends/快照清单.md` 的生成头一行。
> 本文件的表格只讲**用途与缺失影响**，它不是清单的真源，清单真源是盘上文件 + `make`。

## 四、自检三级处理

| 级别 | 条件 | 动作 |
|---|---|---|
| 🟢 正常 | 两条自检命令都退 0 | 直接开工 |
| 🟡 降级 | `depends/` 副本缺失，但**细则文件齐全** | 提示用户：「依赖副本缺失，将按自包含细则继续（功能不受影响）。可按清单里标注的来源重新补齐」——补齐后跑 `make --apply` 刷新清单 |
| 🔴 报错 | **细则文件本身缺失**（阶段①/⑤/⑥/台账模板/模式判定任一），或 `selftest` 判红，或权威记录/清单本身非法 | 停止流水线，提示用户：「缺少关键细则文件 {文件名}。请从安装源重新获取本 skill，或把该文件手动放回 `references/`」；`selftest` 判红说明脚本本体被改坏，别拿它当"环境问题"绕过去 |

细则文件是否齐全，`depends_snapshot.py check` 的链接检查会覆盖（细则之间互相引用，缺一个就报断链）；
不必再手抄一份文件清单来数——**以前那份 30 行的手工清单正是最容易过期的东西**。

## 五、外指声明与"清单继承声明"的口径

副本头部若写了 `> 【外指声明】某上游件的路径 —— …`，指的是**上游 skill 里的件、本库刻意未收**。
四条规则：

1. **只认人工声明**：解析器只读文件**前 15 行**里的 `【外指声明】` 行，按分隔符切出路径 token。
   🔴 **声明行只列"上游的件"**，别把命令、脚本名混在同一句里——
   工具会把同一行切出来的每个路径样 token 都当成一条声明，`py scripts/depends_snapshot.py links` 混进去
   就成了"工具自己豁免自己"（声明集虚胖）。要写命令就另起一行、换个标记（如 `【外指对账】`）。
2. **没声明一律算真断链**：工具**绝不**按"盘上找不到就自动放行"——那样豁免变成万能钥匙，真断链一起被放掉。
   豁免是换来的，不是白给的。
3. **命中条数可见**：`links` 报告明写"外指声明命中 N 条"，不做静默豁免（静默＝没人知道放过了多少）。
4. **清单继承副本的声明**：`快照清单.md` 的"来源"列会摘录各副本头部原文，于是把摘录来的上游路径带了进来；
   生成器因此**继承**（union）各副本自己的声明写进清单头部，否则"摘录来的引用"会被当成清单新造的断链报错。
   反向验证同样有：抹掉副本声明 ⇒ 清单不再豁免 ⇒ 同一处必须翻红（红点落在清单自己那一行）。

## 六、链接检查的覆盖面与已知盲区（别把绿当万能）

- 检查对象：本 skill 目录下**全部 `.md`**（排除 `*.local.md` 个人适配层，见下 §八）里的
  Markdown 链接目标 + `references/…`、`scripts/…` 这类库内路径提及；
- **围栏代码块内部不检**（示例代码里的假路径不该算断链）——代价：真写进代码块的错路径抓不到，
  代码块内引用要靠 `selftest` 的具名断言和人工读；
- 本机绝对路径（`X:\…` 或 `/…` 开头）不算断链，**单独报"绝对路径泄漏"**——发布前必须清零；
- 上游件走 §五 的声明口子，未声明的一律红。

## 七、版本同步纪律

`depends/` 里的副本是**快照**，不自动跟随源更新。若源 skill 升级了（如头脑风暴出 v1.2），由维护者决定：
重新拷贝覆盖副本 + 更新副本头部来源标注 → `py scripts/depends_snapshot.py make --apply` 重生成清单 →
`check` 必须退 0。本 skill 的细则若吸收了新版改动，记得同步改细则。

## 八、个人适配层（出仓时不带）

本机专属内容（本机技能库路径、现役项目的既有惯例等）写在本机那份 `personal.local.md` 里
（照 `references/personal.example.md` 样板复制到本文件同目录，别直接改样板）：
发布映射按 `*.local.md` 全局排除，链接检查也跳过它。
判据：**删掉这个文件，本 skill 在别人机器上照样能跑**；`check` 里"绝对路径泄漏"必须 0 命中。
