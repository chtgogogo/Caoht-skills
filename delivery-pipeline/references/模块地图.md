# 模块地图（Module Map）——项目级框架表，挂在⑤立骨 / ⑥回写 / ⑫定稿

> **是什么**：一张项目级表格，回答"这个项目有哪几个模块、每个模块管什么、谁依赖谁、改 X 该去哪"。
> 它补的是卡级施工图盖不住的全局视野：每张卡知道自己动哪几个文件，但没人知道项目整体长什么样。
> **给谁用**：新接手的 AI 窗口读它定向（不必浏览全部代码）；主会话派遣时按图喂上下文；人改功能时按图找模块。
> 产出物：`<项目根>/docs/pipeline/模块地图.md`——**落点定死**（`spec_check.py` C13 按此路径扫描，挪窝＝脚本与本行同改）。与台账/state.json 同级，是项目导航资产。

## §1 三个维护时点（缺一就是断档）

| 时点 | 动作 | 产出 |
|---|---|---|
| **⑤切卡：首卡波次立骨架** | 从 PRD 功能列表 + 设计纪要推导模块划分意图（AI 起草→用户确认模块边界），每个卡头标【动到的模块】 | 骨架图（职责/依赖按意图填，定位可留空） |
| **⑥执行：每卡完成回写** | 卡的 DoD 链加一步：用真代码校准本卡动到的模块行（补定位/改依赖），随台账更新一起做 | 逐卡校准的活地图 |
| **⑫收尾：定稿校准** | 对照最终代码全表过一遍：定位逐条抽查、依赖重新核对、状态列定稿；记录校准 commit | 定稿地图（新窗口的第一读物） |

**三时点各自的勾单**（照勾执行，缺项＝该时点没做完）：

- **⑤ 勾单**：
  - [ ] 从 PRD 功能列表＋设计纪要起草模块划分（"什么算一个模块"的粒度判据用现成的：`项目文档与上下文规范.md` §3.1，不重抄）；
  - [ ] 用户拍板模块边界（铁律 15：AI 出带推荐的选项，人拍板）；
  - [ ] 落骨架表（§2 模板；定位没查到的先留空，不许瞎编占位）；
  - [ ] 每个模块建 `<模块>/MODULE.md`（模块卡写法＝`项目文档与上下文规范.md` §3——🔴 ⑤ done 硬闸逐个验，见 §1.1）；
  - [ ] 自此每张卡头标【动到的模块】（阶段⑤ §3 第 7 条）。
- **⑥ 勾单**（并入过卡链第 5 步，操作序＝`阶段⑥执行与派遣.md` §流程 5）：
  - [ ] 用真代码校准本卡【动到的模块】行：补定位（文件＋标识符）／改依赖／更新状态；
  - [ ] 卡头标了**新**模块 ⇒ 本表加行＋建对应 `<模块>/MODULE.md`——模块名三处字面一致（§1.1）；
  - [ ] 只动本卡行，不重构全表；
  - [ ] 台账「做完」区该卡「模块：」字段与本表对得上（台账模板 §四）。
- **⑫ 勾单**（SKILL.md §收尾第 3 项）：
  - [ ] 定位列逐条抽查（每条 grep 标识符，操作法见 §4 第 2 步）；
  - [ ] 依赖列两向复核（我调谁／谁调我，与代码 import 对表）；
  - [ ] 状态列定稿：❓🔧 清零，清不掉的行注记原因；
  - [ ] 头部「最后校准」记 commit；全程小卡未建图的项目此处补最小版，写明"未建图"也算交代。

### §1.1 与机械闸的咬合（这些不是自觉约定，是能红的检查）

1. **⑤ done 硬闸**（`pipeline_state.py`，铁律 22 落点）：`stage ⑤ --state done` 时对卡头【动到的模块】逐个验 `<模块>/MODULE.md` 在盘，缺 ⇒ 退 4 拒写。⇒ 推论：**本表"模块"列的名字＝模块目录名＝卡头标记名，三处字面一致**；改名必须三处同改，地图单方改名＝硬闸按字面找不到目录。
2. **C13 禁行号扫描**（`spec_check.py`）：`docs/pipeline/模块地图.md` 在扫描范围内（规格层＋PRD＋地图；卡片豁免）——§3 规则 1 是被机器扫的红线，不是风格建议。
3. **台账挂钩**：台账「做完」区卡行尾「模块：」字段与地图模块列用同一套名字（台账模板 §四，指针不重抄）。

## §2 表模板（列结构定死，字段从使用场景反推：定向/派活/改功能各取所需）

**列结构约定**（列形状是出口：aoci 互导、C13 扫描、新窗 AI 解析都按它读）：

- **八列的列名与顺序固定，不删列、不改名、不换序**；小项目/轻量档最小填五列（模块／职责／关键定位／依赖／状态），其余三列填"—"，**列保留**；
- 要加列/改列名 ⇒ 先改本细则再改图（列语义全局唯一，禁项目自造同义列）；
- 各列口径：**模块**＝目录名字面（§1.1 硬闸）；**关键定位**＝文件路径＋标识符，禁行号（§3 规则 1）；**实现的功能**＝PRD 功能编号——需求号归规格层，两套号不混用（分工见 `规格层-主规格变更与归档.md` §分工表）；**联动**＝谁调我↔我调谁，一句话带对象；**依赖**＝本模块 import/调用谁：表内写模块名，表外（DB/外部服务）写技术栈名；**状态**＝✅/🔧/❓三态（§3 规则 5）。

```markdown
# 模块地图 · {项目名}
> 最后校准：{commit 或日期} · 校准人：{卡号/收尾} · 接手者先跑 §4 三步

| 模块 | 职责（一句话） | 关键定位（文件+标识符） | 实现的功能（PRD 编号） | 联动（调用↔被调） | 依赖（前置） | 设计要点 | 状态 |
|---|---|---|---|---|---|---|---|
| auth | 登录/会话/权限 | api/auth.py: login(); stores/auth.ts | F-3 | approval 读它鉴权 | — | HttpOnly cookie+内存会话 | ✅ |
| approval | 审批决议 | api/approvals.py: decide(); views/ApprovalDetailView.vue | F-5 | 调 rag 取制度依据 | auth, rag | 台账 append-only | 🔧 |

## 模块划分决策记录（为什么这么分——记决策，不记快照；只收跨模块的划分理由）
- 2026-10-11：rag 独立成模块而不塞进 approval——制度问答与审批归因共用语料（来源：设计纪要 §X；被否备选：并入 approval）
```

**横向公用件默认不立行**（utils/types/配置这类碎件写进表只刷行数）；被 ≥3 个模块引用时才升格成行，升格理由进决策记录。

**决策记录字段（每条四件，顺序固定）**：`- YYYY-MM-DD：{决策一句话}——为什么 A 不为什么 B（来源：卡号/设计纪要 §X/用户原话；被否备选：{B}）`。它是 ADR 五字段（Status/Context/Decision/Consequences，见 §6）的最小映射：日期＋来源≈Status，理由≈Context，决策≈Decision，被否备选≈Consequences 的可读替身。**append-only**：推翻旧决策＝追加新条并写明"第 X 条作废、以本条为准"，不删不改旧条（ADR 的 Superseded 同款，只追加不回改）。

字段取舍：**"设计要点"只写一句话 + 指向决策记录**；实现细节不进地图（代码自己会说话，地图只负责给"针"——指针而非细节复制品，依据见 §6 matklad 条）。

🔴 **地图与模块卡是两层，不是同一份**（撞词消歧）：地图＝**项目级一张表**（哪几个模块、各管什么、谁依赖谁、改 X 去哪）；模块卡＝**每模块一份**，摆在该模块目录里（职责／不负责／文件路径／依赖谁与被谁依赖／影响面三问／怎么验证）。分工与落点见 `项目文档与上下文规范.md` §1／§3。**§2 决策记录节只收"跨模块的划分理由"**；单个模块内部的设计理由进该模块的 ADR，不两处写（同一条规矩只在一处维护）。

## §3 防漂移五规则（违反任何一条 = 地图开始骗人，比没有更毒）

1. **禁行号**：定位一律写「文件路径 + 标识符」（函数/类/路由/表名）。行号是时点快照必漂——ADR 哲学同样适用于地图：**记决策与锚点，不记快照**。机械执行：`spec_check.py` C13 把本图纳入扫描（§1.1 第 2 条）。
2. **每卡完成必回写**（绑定铁律 16）：执行窗口的 DoD 链 = 回执 + 权威记录（`state.json` 写回，台账/任务板由它生成）+ 记录清单 + **地图回写**，缺地图回写不算过卡。回写只动本卡模块行，不重构全表。（脚本侧另一道闸管"模块卡在不在盘上"＝⑤ 硬闸，见 §1.1 第 1 条——那道管卡，本条管图，互补。）
3. **信任前先抽查**：新窗口接手时先抽 ≥2 条定位验证（操作法＝§4 第 2 步）——失效即触发重建，不许拿未校准的地图直接开工。地图头部"最后校准"就是为此存在的。
4. **小改顺手改，大改立专项**：卡内改动回写由执行卡顺手做；跨模块重构先在地图加"🔧 更改中+日期"标记，收口再摘。
5. **单字段语义**：状态列只用 ✅（与代码一致）/ 🔧（更改中+日期）/ ❓（未校准）三态——出现第五种解释就是该重建了。

## §4 新窗口接手三步（写进派遣提示词的标准动作，三步照做不跳）

1. **读图定向**：先看头部「最后校准」（离最近一次结构改动太远 ⇒ 按未校准对待，抽查加倍），再读全表（30 秒知道全局）；
2. **抽查定位**：对本卡【动到的模块】各抽 1 条定位（合计 ≥2 条），逐条验证＝文件存在＋`grep -rn "<标识符>" <仓库根>`（或 IDE 全局搜）命中；
3. **分支执行**：全过 ⇒ 按图施工；任一失效 ⇒ 先修图再干活（修图 diff 进卡回执，算交付物）。抽查结论随"拉上下文"一句话交代即可，不新增落盘仪式。

## §5 与 aoci 的关系（有现成体系就挂，不重造）

项目已建 **aoci 代码认知索引**（扫描生成、带指纹、能自动检测过期）时：模块地图**指向 aoci 作为活读数**，本文件只保留"模块级导航 + 决策记录"两层 aoci 覆盖不了的内容——避免同一信息两处手写（快照禁令：会自变的信息禁手写副本）。aoci 条目格式即「功能 / 相关代码 / 接口 / 备注」，与本表 §2 字段同构，可互相导出（列形状定死就是为这个，见 §2 列结构约定）。无 aoci 的项目按 §2 模板手写最小版（先有骨架，收尾校准补齐）。
