# Cao 交付流水线：需求到交付分身编排

> 总装调度器：把「想法 → 设计 → 选型 → PRD → 任务卡 → 分身执行 → 验收 → 收尾」串成自动流水线。
> 设计原则：**每步绑产出物**（这步的产出 = 下步的原料）；**卡文件制**（一卡一文件，拒绝单文件巨石）；
> **三层任务文档**（L1 双清单：任务板给 AI 认领+记录清单给人看轨迹 → L2 纲要卡 → L3 施工图卡，颗粒度递增）；
> **单一权威状态源**（`docs/pipeline/state.json` 是唯一的账，台账/看板都是它生成的视图，见 §三 铁律 4/17）；
> **台账即断点存档**（随时中断，随时续传，续传只读文件不靠记忆）；**验收先于实现**（每卡开工前基线就绪）。

## 〇、依赖自检（每次启动先跑，约 5 秒）

自带脚本都是零依赖纯标准库，解释器按本机口径（Windows 用 `py`，其他环境用等价入口）：

```
py scripts/pipeline_state.py selftest      # 状态机自证：断点续传/锁/版本冲突/门禁，全绿才继续
py scripts/depends_snapshot.py check       # 依赖对账一条龙：副本哈希 + 路径映射 + 全库链接
```

- 两条都退 0 → 继续；
- `check` 报「哈希不符」→ 副本被抓改过，按 `references/depends/快照清单.md` 里的来源锚回上游重取，别手改清单；
- `check` 报「断链/缺失」→ 本库该有却没有的件，先看清单头部的**外指声明**（声明过的＝上游件、本库刻意未收，报告里会明写命中条数），没声明的一律算真断链要补；
- 细则缺失需顶替时读 `references/depends/` 的**自包含副本**（本 skill 的细则均为自包含，不硬依赖外部 skill）；
  连副本也缺 → 按该文件头部标注的来源提示用户重新获取（如「从 github.com/obra/superpowers 重新下载」）。

> 副本件数与路径映射**不在本文抄数**（抄了就过期）：现读 `references/depends/快照清单.md`，
> 它是 `depends_snapshot.py make` 的生成件，`verify` 会把「清单 ≠ 盘上实际」当场打红。
> 口径与外指声明规则见 `references/依赖与自检.md`。

## 一、启动路由（每次触发必走 · 只读文件不读记忆）

```
0. 点火先读账：py scripts/pipeline_state.py resume --root <项目根>
   ├── 有 docs/pipeline/state.json → 照它给的续传结论走：
   │     · 「从 ③ 继续」＝① ② 已 done/skipped，**不许重跑**
   │     · 「不许重做的外部动作」里的（已 push / 已发信 / 已建 PR）一律不重放
   │     · 「已问过／已授权，别再问」里的一律不再向用户重复确认
   └── 没有 → 新项目，走 1
1. 定档：py scripts/pipeline_state.py mode --decide --signal 键=值 …（信号表见 references/模式判定.md）
   ├── 判得出 → 自动定档，**告知即可不追问**，直接进 2
   └── 平档同分（判据明写「置信度不足」）→ 才把 A/B/C/D 四选项摆给用户拍板（先给推荐+理由）
   用户显式点了档（"就要企业档"/"随便快点"）→ 用 --mode 覆盖并记 --mode-source user，自动结果让位
2. 建账：py scripts/pipeline_state.py init --root <项目根> --project <名> --mode <档> --apply
   · 轻量档只产 state.json + 台账.md，**不建任务板/卡库/选型等空文件**（跑 `plan --tier 轻量` 可先看清单）
3. 落盘目录：先 `answer --id 落盘目录 --check`——**答过就别再问**（默认 <项目根>/docs/pipeline/，用户可改）
4. 跳步优化（D 档）：已有项目先扫十二步找短板 → 列缺口清单 → 用户勾选 → 只把选中的阶段建账执行

单步直调：用户点名某一步（"帮我切卡""就跑个评审"）时跳过 1-2，直接读该步细则执行；
仅两件事不可省——落盘目录确认（答过即视为已确认）+ 台账登记（保持断点可续）。
单步直调撞上顺序闸时凭 `--skip-auth "授权说明"` 放行并留痕（v1.18 单步直调 A 方案：
用户点名＝显式授权，账上必须有这一笔；口头跳步不算数）。
```

> 🔴 **固定提问是缺陷不是纪律**：要向用户确认的每一件事，先查权威记录的 `answers`；
> 拿到答复后立刻 `answer --id <项> --answer <结论> --source 用户已说明 --apply` 落账。
> 「已授权做过 X」和「已答过 Y」进同一张不重复确认清单（台账第七节自动生成）。

## 三、执行铁律

1. **每步绑产出物**：产出物文件不落盘 = 这步没做完（⑧的硬闸按铁律 19 逐条验产物在不在盘上，不在就不许标 done）。
2. **验收先于实现**：卡开工前验收动作必须就绪（评测基线分/测试脚本/肉眼清单，形式不限但必须写进卡）。
3. **一卡一文件**：任务卡禁止塞进单个巨型计划文件（token 黑洞）。
4. **台账即时更新，且只有一本账**：每张卡完成立即经 `scripts/pipeline_state.py` 写 `docs/pipeline/state.json`
   （断点存档，不是事后补记）。台账.md／任务板.md 是它生成的**视图**，禁手改（含 AUTO 标记，手改会被下次生成覆盖）；
   🔴 项目里若另有一件手写的 `STATE.md`，它**不是脚本生成的视图**（脚本只认这两个视图名），它的身份是**待并入的旧外部 md**：
   读数一律以 `state.json` 为准，内容要么走 `sync --from-md` 逐字段并账后废弃，要么明确留着当人读的工作稿——**不许两边各写各的**；
   两侧值不一致时**不做任何自动取舍**——`sync --from-md` 只逐字段吸收「权威记录里没有」的，
   同名不同值的一律写进「待人工裁决」由人拍板。**旧版「以 `updated_at` 较新者为准整份互相覆盖」已废除**
   （那等于把另一侧改过的字段静默抹掉＝lost update；墙钟时间既不能排序两个窗口的写，也不是字段级事实）。格式与命令见台账模板.md。
5. **派遣上下文最小化**：子代理只喂「该卡 + PRD 相关段 + 精确文件路径」，绝不喂全项目历史。
6. **默认接力**：有依赖的卡依次执行；无依赖的卡先问用户要不要并行。
7. **双评审**（企业/子代理模式）：每卡完成后先审「是否符合设计」再审「代码质量」，严重问题阻断下一卡。

   问之前先 `answer --id 落盘目录 --check`，**答过就别再问**（拿到答复立刻 `answer --apply` 落账 ⇒ 进台账第七节「已问过／已授权」清单）。
9. **按需加载（省 token 铁律）**：启动只读本 SKILL.md（索引+路由），禁止预读/通读 references/ 目录；
   进入某一步才读该步细则，一次只读一个；depends/ 副本只在两种情况读——对应细则缺失需顶替、或执行中需要外部 skill 原文细节；
   superpowers_assets/ 只在派遣/评审需要整篇模板时读对应那一个文件。
10. **安全基线不可跳过**：收尾（⑫）前必须先过第⑬步 L1 档；L1 有阻断项（可被直接利用的漏洞）不许收尾。教训锚点→修订记录·铁律区（安全维度曾整体漏网于卡内验收）。
11. **对外口径不可带病投递**：凡有对外输出（简历/README/汇报/作品集）的项目，收尾（⑫）前必须过第⑭步；出现"数字缺四件套 / 数字早于最后一次评测 / 引用不存在的 commit / AI Agent 冒充真人署名"任一 → 阻断收尾与投递。教训锚点→修订记录·铁律区（根因：没人管"说出去的话站不站得住"）。

13. **测试证据形态遵循 A-Cao-测试纪律**：每卡的"测试全绿/评测达标"必须按其标准交付证据——原始输出落盘（acceptance/evidence 或卡内路径）、改前改后各跑一遍、口径标注、**禁止只在对话里说"绿了"不留输出文件**；收尾⑫全量评测与⑭口径检查同此标准。
14. **三层任务文档不可跳层（v1.5）**：中/大卡必须有三层——L1 任务板条目（AI 认领+波次顺序+【依赖】/【P】并行标记）→ L2 纲要卡 → L3 施工图卡（全量 18 节/轻量 9 节，见 阶段⑤切任务卡.md §5，深写者必须现查代码、过 §5.3 自检清单）。**禁止拿三行摘要直接施工**——"拿着就能施工"的施工图缺位=质量全凭执行者发挥；小卡（子代理 2~5 分钟、≤3 文件）可只用 L2 §4.1 实习生模板。教训锚点→修订记录·铁律区（3 行摘要派活 vs G 系深写卡实证）。
15. **盘问分工——用户拍「要什么」，AI 包办「怎么做」（v1.6）**：磨设计与规格设计环节，所有技术决策必须包成带推荐的大白话选择题（选项+取舍+理由）让用户拍选择；禁止把方案设计推给用户（"你想用什么框架？"=失职），也禁止替用户拍需求（"你肯定想要 X"=越权）。细则=阶段①磨设计与选型.md §1 规则 2（依据→修订记录·铁律区）。
16. **模块地图三时点维护（v1.6）**：⑤首卡波次立骨架图（卡头必标【动到的模块】）→ ⑥每卡过卡回写本卡模块行（DoD 链第五件，缺回写不算过卡）→ ⑫收尾对照真代码定稿校准。防漂移三禁（**定位禁行号／记决策不记快照／信任前先抽查**）与"地图≠模块卡、两层不两写"的分工细则=`references/模块地图.md`；已有 aoci 认知索引的项目挂 aoci 作活读数，禁两处手写同一信息。
17. **单一权威状态源，Markdown 只是视图（v1.7）**：所有状态字段（阶段、卡、门禁、恢复点、已答事项、外部动作账、依赖快照）只认 `docs/pipeline/state.json`；台账.md／任务板.md 由 `render` 生成、带 AUTO 标记、**禁手改**，人手改视图不算数（外部既有 md 要并进来走 `sync --from-md`，逐字段并账、冲突不自动取舍）。🔴 项目里若另有一件手写的 `STATE.md`：**它不在脚本生成的视图范围内**（`VIEW_FILE` 只有 ledger／board），所以**没有"下次生成会覆盖它"这层兜底**，只能二选一——走 `sync --from-md` 并进权威后废弃它，或就地改成一行指针指向 `state.json`；留着它继续手写＝两份手写状态互相矛盾且无人报警。同一信息禁两处手写。**反过来，`state.json` 也装不下"读数与缺口清单"**（四个有效性指标／下次开窗口该贴哪几份模块卡／出题答错的那些）——它们不是状态字段，落 `<落盘目录>/上下文体检.md`，人读人写（判据与落点见 `references/项目文档与上下文规范.md` §4）。细则=台账模板.md §一（依据→修订记录·铁律区）。
18. **原子替换 + 多写者要锁与版本校验（v1.7）**：写权威记录一律走脚本（tmp 写满 + fsync + `os.replace` 原子替换 + 写后读回不符即回滚），禁手工编辑 `state.json`。单写者场景这样就够了；多窗口／多分身同写一棵树时加两件事——① **租约锁**（`--holder` 取锁、心跳、崩窗留下的陈旧锁**必须显式 `--takeover` 才接管**，绝不自动接手；代次 generation 只增不减）② **rev 乐观校验**（`--expect-rev` 读到的是哪版就按哪版改，版本不符退 6 让人重读，绝不整份覆盖）。退出码口径与卡05 协作治理的 `edit_lock.py` 一致（5 他人持有／7 陈旧锁／4 锁损坏／8 拒写手写件／6 版本冲突）。依据（RFC 9110 `If-Match`/ETag 同款、POSIX `rename` 原子性）→修订记录·铁律区。
19. **阶段四字段齐了才算做完，外部动作记幂等账（v1.7）**：每个阶段标 `done` 前必须写满四字段——**输入版本／产物位置／完成条件／恢复点**；产物路径不在盘上就标 done ⇒ 脚本硬拒（退 4），因为「说做了但东西不在」正是断点续传最坏的坑。恢复点要写到"下一个窗拿着就能接"的程度（"从第 4 节续写，1-3 节勿改"，不是"继续"）。push／发信／建 PR 这类**外部动作**单独记幂等账（`action --idem-key`），已生效的列入「不许重做」清单，续传时零重放。依据（Stripe/AWS idempotency key 惯例）→修订记录·铁律区。
20. **文档层四条硬规（v1.10 立①②③，v1.11 补④）**：① **必填项禁写「无」／「暂无」占位**——分不清"查过了确实没有"和"没查"，查过没有就写**「经确认：无（日期，依据）」**（例：`经确认：无对外接口（2026-10-14，grep 全部路由文件未命中本模块标识符）`）；② **叙事层与模块卡的对账只许逐条出四列表、禁通读重写，第④列判定权归人，AI 不许在自己的产出上盖章**（自增强偏差依据 NeurIPS 2024 arXiv:2404.13076 →修订记录·铁律区；确需 AI 辅助对账时裁判必须换一个不同模型家族，且它只出前三列事实与锚点）；③ **锚点写成 Markdown 链接、禁行号**——链接能被 `markdown-link-check`／`lychee`／现成 CI Action 查到，纯文本注记（`← 锚点：config.py`）文件改名后照样"看起来是对的"、零报错；行号是快照必漂，只写文件名＋标识符。细则=`references/项目文档与上下文规范.md` §3.2／§3.3／§6；④ **小白版不许用「让 AI 现讲」顶替（v1.11 补）**——能从代码现生成的只是**事实**，小白版的产品是**事实的固定说法**（比喻一换，零基础读者等于重学一遍），而其中三栏（它怎么做的／怎么算它做对了／它防的是什么坏事）**代码里根本没有**，现讲讲不出来。它必须落盘、说法固定，维护只盯「小白版作废登记」那一格。细则=§5.0／§5.4／§5.5。

4. 台账归档（`docs/pipeline/台账_归档_YYYYMMDD.md`）；

## 五、通用化说明（本 skill 可跨机器/上传 GitHub 复用）

- 正文不含任何本机绝对路径（形如 `X:\...` 或 `/home/...`）；落盘位置一律以 `<项目根>`、`docs/pipeline/` 相对形态表达；
- 跨会话记忆库、知识库等外部设施以「若有则用」方式引用，缺失不阻塞；
- 依赖的外部 skill 精华已自包含进 `references/`（原文副本见 `references/depends/`，含来源与版本标注）；
- **自带脚本零第三方依赖**：`scripts/pipeline_state.py`（权威状态读写）、`scripts/depends_snapshot.py`（依赖快照与链接检查）、`scripts/spec_check.py`（规格层机械校验）、`scripts/trace_matrix.py`（追踪矩阵生成与活性校验，v1.20.0）、`scripts/render_agents.py`（AGENTS.md 生成区渲染，v1.20.0）、`scripts/security_scan.py`（安检常驻化扫描器：L1 六项规则面＋签核机检＋报告追加区，v1.28.0）都只用 Python 3 标准库，换机器不需要 `pip install`，只要该机能跑 `python3`；规格层校验器**刻意不依赖任何第三方 SDD CLI**（装了 OpenSpec 之类也只换布局前缀，判据不变）；
- **抄来的数字会过期**：正文与细则一律不写"副本 N 件 / 映射 M 条 / 共 K 个 md"这类计数，需要读数时跑 `py scripts/depends_snapshot.py check` 现采；
- **快照清单是生成件**：`references/depends/快照清单.md` 由 `depends_snapshot.py make` 生成，`<!-- AUTO-BEGIN -->` 与 `AUTO-END -->` 之间的内容**禁手改**（改了下次生成即被覆盖，且不会报错）；要人工说明写在 AUTO 块之外；
- **外指声明口径**（副本引用了本库刻意未收的上游件时）：只认副本头部那一行**人工**写的 `> 【外指声明】...`，工具**绝不**按"盘上找不到就自动放行"来豁免——那样豁免会变成万能钥匙，真正的断链也跟着一起被放掉。豁免是换来的，不是白给的；命中条数在 `links` 报告里明写，可见不作静默。生成的清单会**继承**各副本自己的声明（否则清单"来源"列摘录副本原文时，会把摘录来的引用当成清单新造的断链）；
- **个人适配层不入仓**：本机路径、本机项目名、只对自己有意义的习惯一律写进本机专属件
  （文件名 `personal.local.md`，放在 `references/` 里那份样板的同目录；样板见
  `references/personal.example.md`，**照它复制、别直接改样板**）。发布映射按 `*.local.md` 全局排除，
  所以样板出仓、填了真值的那份不出仓。判据：删掉那份本地件后，本 skill 在别人机器上必须照样能跑。
