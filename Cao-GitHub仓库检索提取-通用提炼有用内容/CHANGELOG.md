## v1.2.0 · 2026-10-12

- **怎么验证的**：每处红→绿都留了读数（任务包 `evidence/卡09/`）。git 导出的旧原文在两把尺子（PyYAML 真解析／体检内置严格子集）下都报 `重复键 metadata`，五处硬伤旧原文 5/5 命中、修后形状逐条落地（`_frontmatter-old-vs-new.txt`，退出码 0）；`gh repo view … --json stars` 当场报 `Unknown JSON field: "stars"`，同日改 `stargazerCount` 正常返回 9,633（`_gh-stars-RED.txt`／`_gh-stargazerCount-GREEN.txt`）；新旧编码判据在 9 条合成样例上对账——旧尺既放过真损坏又冤枉正常文件，新尺 9/9 判对（第一版读数 `_ab-encoding-old-vs-new.txt` 18 条；补上豁免通道与「检自己不判红」两条断言后复跑 19/19＝`_ab-encoding-old-vs-new-run3.txt`，退出码 0，前两份读数按「红样本留原件」的原则不覆盖）；脚本自检 13/13（`_encoding-selftest-default.txt`，`py -3.12` 同绿＝`_encoding-selftest-3.12.txt`；S1 正例哨兵＋六类判据各能红＋S11/S12 是豁免通道的红绿一对：同一份乱码，行尾带标记则降级为豁免、去标记必须照旧判红＋S13 是「同名乱码出现两处、只有第一处带标记」必须仍判红）；变异探针两组：判据表 8 组逐条点名要翻红的断言全部被抓（`_mutation-probe.txt`），豁免与重复命中另打 3 组（标记匹配改恒假 ⇒ S11 翻红；改恒真 ⇒ S12 翻红；特征扫描退回「只报第一处」 ⇒ S13 翻红；`_encoding-mutation.txt`，跑后源文件 md5 反查未变）；名称解析断言实测 4/4（`_dns-claim-probe.txt`）；注入回放在合成仓库 `orbis` 里埋 5 个「给 AI 的指令」向量＋四个金丝雀落点，两个互不知情的执行窗跑完后机械对账 15/15 绿、报告判卷 40/40 绿，两把尺子各自都先证明过能红（说明与局限见 `_replay-notes.md`）；发布仓体检 `library_check.py` 退出码 0。

## v1.1.1 · 2026-10-11

**只修 frontmatter：重复的 `metadata` 键合并成一块，正文与描述文字一字未动**。

- **解决了什么**：frontmatter 里连着出现**两个 `metadata:` 块**（第一块只有 `agent_created: true`，第二块才有 `version: 1.1.0`）。YAML 标准解析器对重复键直接报 `duplicate key: metadata`；宽松解析器按"后者覆盖前者"静默放过——两种结果都可能让宿主读不到版本，而这类形状错误靠"字段齐不齐"的粗检查永远发现不了（旧体检脚本对本支报绿）。
- **怎么解决的**：两块合并为一块，内容取并集（`agent_created: true` + `version: 1.1.1`），删除重复的第二块首行。`description`（294 字符）与其他字段文本保持原样。
- **怎么验证的**：PyYAML 与内置严格子集解析器两种模式都能解析，且读到的 `description` 逐字一致；重写后的 `library_check.py` 对本支不再有红项。命令输出落盘：`<你的任务包>\evidence\卡01\_fix-frontmatter-output.txt`。
- **版本号**：1.1.0 → 1.1.1（补丁级：只动元数据结构，SOP 步骤与 License 红线矩阵无变化）。
