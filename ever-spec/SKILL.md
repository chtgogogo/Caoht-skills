# EverSpec：常新规格 · 规格驱动开发（独立件）

> 「常新」= 主规格永远说「系统**当前**承诺什么」：改动走增量、做完必归档并回，规格不烂尾、不退化为第二份 PRD。
> 本件是 Cao-交付流水线规格层的**活正本**（2026-10-27 天令「额外提取不是拆解」抽出）；管线内嵌版冻结为适配快照，判据升级只改本件，随维护窗回同步管线（细则 §7）。
> 三件套：**一层契约**（`specs/`＋`changes/`）＋**一把能红的尺**（spec_check）＋**一条机读追踪链**（trace_matrix＋render_agents）。

## 〇、依赖自检（每次启动先跑；零第三方依赖，Python 3 标准库）

```
py scripts/spec_check.py selftest      # 尺子自证：合法树全绿＋逐条做坏必红＋反恒真哨兵＋变异探针臂＋分母闸
py scripts/trace_matrix.py selftest    # 矩阵自证（spec_check 的 selftest 也会顺带加载它验 C17 联动）
py scripts/evidence_chain.py selftest  # 证据链自证（细则 §6.6）
py scripts/catalog.py selftest         # 活目录自证（细则 §6.5；gen 幂等＋手改派生物必红）
py scripts/reanchor.py selftest        # 开窗重锚自证（细则 §6.5；读取集过滤＋断点摘要＋链尾锚）
py scripts/doc_lint.py selftest        # 文档体系尺自证（细则 §6.8；断链/孤儿/supersede 双向/术语双定义/waiver 审计）
```

- 六条都退 0 → 继续；render_agents 无 selftest，行为由「写后读回自证」兜底（不符退 1）。
- selftest 只写临时树，不碰真实项目；本件 scripts/ 若被人改动，selftest 的 mtime 哨兵（S26）会抓。

## 一、启动路由（每次触发必走）

```

1. 项目里已有 specs/ 或 changes/ → 先跑 py scripts/spec_check.py check --root <项目根> 看红绿，按输出修；
   退出码 0=全绿（可含警）｜1=有红｜2=根目录不对（退 2 不是"没问题"，是"没查"）
2. 新能力要立约 → 读 references/规格层规范.md §3（需求块/EARS 五型/场景块/锚点分级），落 specs/<能力>/spec.md；
3. 要改行为 → 读 §4 开变更包（三动词增量），做完走 §5 归档五步（顺序即载荷，不许换序）；
4. 想让"条款↔代码↔测试"可机读 → 读 §6.5，gen 矩阵＋render AGENTS.md 生成区；
5. 团队/管线要自动化咬合 → 读 §7 管线适配（交付流水线四挂点；无管线时进度权威降级见 §三 纪律 5）；
6. 存量项目没有 specs/（棕地）→ 读 §3.5 反提三步（依赖图打底→AI 起草现状行为清单→现有测试跑通＋人审签收才转正）；反提件没签收就进 specs/ 会吃 C21 红；转正链路与 reverse/ 扫描面（缺证据坐标／行号锚／未签收转正三面吃 C21 红）见 §3.5 逆向升格四步。
```

## 三、执行纪律（硬规，违反＝这层白做）

1. **判据真源是脚本**：细则抄录的口径（五型正则、12 个元信息前缀、两把词表、扫描面、增量标头形状）与脚本不一致时，**改脚本方为正着，然后回改细则**——只改细则＝尺子没变、说明书变了，更危险。
2. **证据落盘**：check/selftest/gen 的原始输出存 `evidence/`（文件名带日期戳）；只说"绿了"不留输出文件＝没测。多批证据要防事后翻改 → `evidence_chain.py append/check` 链式登记（细则 §6.6）。
3. **编号冻结**：断言编号 C01–C31 只追加不顺延（文档面自称与 CHECKS 不一致＝C22 红）；需求号发出去就不回收（删了 R-2 也不许把 R-2 发给新需求）。
4. **证词不改史**：归档包、旧输出、历史记录是证词，发现错误新节勘误，不涂改原文。
5. **无管线模式口径**：项目里没有 `docs/pipeline/`（无 PRD/卡片/state.json）照样能用——C06/C07/C11/C17/C18 **自动降警不拦人**（selftest 哨兵 S-NP 钉死这个行为）；此时"走到哪了"的进度权威＝变更包 `tasks.md` 勾选或项目自带的任务清单/issue，**在 PRD 或 README 写一句降级声明**（"进度权威=X，非 state.json"，样例＝`examples/最小项目/README.md`），禁两处各写各的。
6. **别对外吹**：这把尺只查机械面（句式/编号/文件在不在盘上），**语义漂移查不到**——条款说"拒绝"、代码改成"警告"，尺子不响，那层靠测试与人工验收。四条完整边界见细则 §6。

## 四、元方法论六件套（本件 selftest 内嵌的范式，可复用）

给任何"流程规矩"配机械尺时，照这六件做（全部已在 spec_check.py selftest 内实现，抄结构即可）：

| 件 | 判据 |
|---|---|
| 地基绿 | 合法树必须零红零警（S00）——否则后面全是假绿 |
| 点名必红 | 每条断言都要有"做坏必翻红"的用例（S01–S22），且只准点名的那根红（涟漪红不算败） |
| 反恒真 | 哨兵反查判据本身（S25b：畸形行必须被判否）——防"永远红/永远绿"的坏尺子蒙对 |
| 分母闸 | 断言条数有下限（ASSERT_FLOOR），删用例自爆（S29） |
| 变异探针 | 每臂打坏一个判据实现，点名用例必须翻 FAIL；原样对照臂全绿 |
| 自错登记 | 每版自己引入的错写进修订记录当防重犯教材 |

**复用指南（给其他 skill 抄这套结构的最低清单）**：

1. 判据进 `CHECKS` 注册表（编号＋标题），编号只追加不顺延；输出行固定形状「[红] C号 标题｜位置｜人话」；
2. selftest 五件：地基绿（合法树零红零警）→ 点名必红（每条断言一个做坏用例，涟漪红不算败）→ 真出口（退出码 0/1/2 实测，不只看函数返回值）→ 反恒真（哨兵＋畸形输入判否）→ 分母闸（ASSERT_FLOOR，删用例自爆）；
3. 每个行为改动带一条 selftest 用例（先红后绿两份输出都落盘）＋一根变异探针臂（源码打补丁在独立命名空间重载，实现打坏→点名现象翻面）；
4. selftest 只写临时树、收尾清理、scripts/ 零写入（mtime 哨兵钉住）；
5. 证据落盘带日期戳，多批证据上哈希链。

抄结构不抄判据：判据是你自己领域的，这六件是让判据「能被证明会响」的骨架。

## 五、管线适配（宿主＝Cao-交付流水线；别的宿主照此模式接入）

- 四挂点：③ 立约后立规格、⑤ 切卡咬合需求号（C05/C06＝**适配开关**：有卡则咬合校验、无卡自动降警）、⑥ 过卡后归档触发、⑫ 收尾跑尺落证据。
- 适配模式下进度权威回归管线 `state.json`（细则 §2 表）；归档记账步用管线 `pipeline_state.py action` 幂等账（细则 §5 第 3 步）。
- ⑫ 收尾落盘的原始输出可用 `evidence_chain.py` 链式登记防翻改（细则 §6.6）；管线侧调用面由管线维护窗跟随本件演进。
