# 漏捕对账（换窗交接 · MUST-12 · P0-7）

> **何时读**：换窗/交接时，把交接块里的需求性陈述对账清零再关窗。
> **不读会怎样**：口头答应的需求在换窗中蒸发，规格与交付脱节，验收时才发现少了整块行为。
> **上一层指针**：流程与机检边界 → `references/规格层规范.md` §4「漏捕对账」；本模板是人工兜底，机械尺不查这件事。

## 换窗前先过一问（压缩 vs 交接分水岭，K22 · v1.21.0）

> **这段对话里，还有没有"只在这里存在、还没进任何文件"的东西？**
> 有 → 先写盘（变更包/草案/教训），写完再压或再换窗；没有 → 直接换窗，比压缩干净。拿不准按"有"处理。

## 大项目对账派子代理（防主会话塞满，参考① §10.1.2）

```
用只读子代理对账 <交接块/纪要> 与 changes/（含 archive）＋specs/：
只回对账四列中的前三列（陈述/出处/承接去向），裁决列一律留空给我；
承接核验必须给出 grep 关键词与命中位置；不要改任何文件。
```

## 走查/对账证据五项格式（R3 同源，K22）

争议或承接主张必须给全五项：①文件路径 ②函数名/类名/标识符 ③一个能搜到的关键词
④原样复制的 ≤15 行原文片段（工具截取优先，AI 手打只算转述）⑤**人的复核动作**
（大白话写清：打开哪、搜什么、该看到什么）——五项缺一，该主张按「待核」处理。

## 用法（三步）

1. **捞陈述**：从交接块/聊天记录/会议纪要里把**需求性陈述**逐条抄进下表（"应该要支持…"、"客户要…"、"下次记得…"——判据：这句话如果没人接，交付就会少一块行为）。
2. **对承接**：每条去 `changes/`（含 archive）与 `specs/` 里 grep 关键词——有承接写明落在哪个变更包/条款号；没有的列**漏捕候选**。
3. **交拍板**：漏捕候选逐条裁决（收编成变更包／丢弃／挂起），**签收人＋日期落表**——没人签收的条目不算对完账。
