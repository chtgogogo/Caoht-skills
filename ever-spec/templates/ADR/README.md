# templates/ADR/：架构决策记录（ADR）模板与用法

> 一句话：决策要留痕的留一份短文档，状态字段让机器认得出哪份是现行版；**何时立的准入门槛三条与 supersede 纪律，细则 §2.1 是口径真源**，本页只讲用法不另立判据。

## 里面有什么

| 件 | 用途 |
|---|---|
| `ADR-模板.md` | MADR-lite 形状模板：状态／背景（Context）／决策（Decision）／取代双向字段在场——四组字段在场即可机检（对标 MADR，供应链登记 #6）。复制到项目 `docs/adr/ADR-NNN-<slug>.md` 使用，NNN 三位递增、号发出去不回收 |

## 使用纪律（四条）

1. **先过门槛再立**：翻盘付代价／不可逆／曾有分歧，满足任一才立（细则 §2.1）；一条不沾就写进普通 design/笔记，别灌水。
2. **状态用四态**：草案→生效→已取代／废弃，与规格层状态机同口径（细则 §3；写了就查，同 C23）。
3. **推翻必双向**：新 ADR 写 `- 取代：<旧 ADR 路径>`，旧件改「状态：已取代」＋`- 被取代：<新 ADR 路径>`——单向残缺由 doc_lint D02/D03 红（细则 §6.8）。
4. **两套指针不混用**：文档级决策推翻用路径指针（doc_lint 管）；决策落到具体需求条款用 `取代：R-x` 需求号指针（spec_check C30 管，细则 §3）。

## 机检挂点

- `py <EverSpec根>/scripts/doc_lint.py check --root <项目根>`：ADR 间取代对、断链、状态值合法性。
- `py <EverSpec根>/scripts/spec_check.py check --root <项目根>`：ADR 之外，需求块级取代对（C30）与整套规格咬合。
