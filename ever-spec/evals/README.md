# 效果评测基线（evals）· ever-spec

回答一个问题：**装上这支 skill，比不装好在哪？**
本支评的是 **skill 级行为**（该触发时触发没有／路由走没走对／降级明不明显／越界改没改），
不是脚本判据（那层由六支 selftest 覆盖）——两层分开，别拿 selftest 绿冒充 skill 有用。

## 三态取样

| 态 | 是什么 | 怎么取 |
|---|---|---|
| A 无技能基线 | 只给任务本身，不给 SKILL.md | 朴素执行器按常识做（典型病：规格写成第二份 PRD、改完代码条款烂尾、证据只在对话里说） |
| B 升级前 | git 历史版本的 SKILL.md＋细则 | 在本 skill 的 git 仓根跑 `git log -- skill/Cao-EverSpec-常新规格规格驱动开发` 取对应版本单独放一处（仓根位置因机而异，用占位符思维自行代入） |
| C 当前版本 | 手上这份（v1.18.0 起含 evals） | 直接用 |

## 🔴 回放信道的已知坑（必须先读）

**对照污染（pit-073 实录）**：宿主每轮注入技能清单，「无技能臂」在宿主会话里**不干净**——被测窗看得见别的 skill。
处置：A 态回放必须用**无宿主注入的最小执行器**（干净 CLI 会话只贴任务文本），或如实标注「A 态带注入污染，差分下界」。
每格 n=1 必须如实标注；回放窗互不知情，判定只读报告正文与盘上真值。

## 两条信道

- **脚本信道（本包已跑）**：场景↔触发面覆盖自检（`trial-覆盖自检-20261029.txt`）——每个场景的预期行为所依赖的 SKILL.md 路由行/触发词/降级句，机械核验在场。这证明**靶子在**，不证明**行为对**。
- **回放信道（待独立窗）**：同一句任务分别交给 A/B/C 三态执行器，按 evals.json 每格 judge 判定。首轮全量回放的开工协议：一次一窗、每格落原始输出＋七字段记录、判定列留人。

## 场景集（八轴，细定义见 evals.json）

正常任务（E1）／相似不适用（E2 误触发）／缺工具降级（E3）／已授权不盘问（E4）／只分析不改（E5 越界修改）／中断续作（E6）／证据不足保留未知（E7）／多技能共存（E8 冲突）。

## 成本口径

token 与耗时**依宿主而定**（不同模型/上下文注入差异大），记录模板照实填，不预填数字、不跨宿主比大小。
