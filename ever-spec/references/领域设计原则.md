# 领域设计原则：四理念与不变量块（v1.17.0 · K15）

> **何时读**：定架构、做技术选型、立设计约定、新项目冷启动定基调时。
> **不读会怎样**：原则散在人心（换人就丢）、翻盘无记录（同一个坑重踩）。
> **上一层指针**：细则 §2.1（ADR 何时立·准入三条）＋`templates/ADR/`。

## 一、四理念（B 级实践共识，来源 obra/superpowers 社区，供应链登记在案）

| 理念 | 本体系落点 |
|---|---|
| **TDD** | 判据先行：尺子 selftest 先红后绿＝对流程本身的 TDD；项目侧测试在验收环（C14/C20） |
| **系统优于临时** | 一次性口诀进尺子、进模板、进断言——第二个月还成立的规矩才配写进长期层 |
| **复杂度优先降低** | 新能力动工前先问"能不能删"：砍掉没信息量的行（R7 判据：删了它 AI 会不会犯原本不会犯的错） |
| **证据优于声明** | 落盘纪律：没落盘的输出不算实测；runs.log 机读读数替代手抄汇报 |

## 二、存量工程三件套优先序（B 级，superpowers 同源）

治理老项目按这个顺序取用：**systematic-debugging**（排老 Bug：复现→定位→假设→验证，禁散弹枪试错）→ **verification-before-completion**（改完必跑验证贴真实输出，证据优先于断言）→ **writing-plans**（改造先出计划，每步带路径与验证——见[变更影响链](变更影响链.md)第三节）。本件与之咬合的面：规格层管"契约与现状对不对"，调试与测试流程归项目自己的纪律件。

## 三、全局不变量块模板（项目自愿采用；v1.17.0 自 K20 降级而来）

> 出处与教训：GitHub spec-kit 的 constitution（/speckit.constitution）允许项目写"宪法"，但社区实证其**执行弱**——「代码产出大、宪法约束弱」（官方讨论 #1619）。**说得到查不到的原则块是装饰**，这是 K20 断言卡被砍的原因。本模板的价值不在"自动执行"，在两件小事：把散落各处的项目级约束**收成一张可归属清单**，并随读取集常驻（reanchor 会带出来）。

`specs/_invariants.md`（位置可自定，写进 PRD 指针）：每条不变量**必须二选一**，禁止裸奔——

```
- 不变量：密码不许明文落库
  核验：人工（评审时逐 diff 看写入点）
- 不变量：对外接口失败必须可幂等重试
  测量命令：py -m pytest tests/test_idempotent.py -q
```

边界照实说：带「测量命令」的条目进了跑尺生态能红能绿；标「人工」的只是**归属清晰**，不是被机器强制——别在对外介绍里把后者说成前者（细则 §6「别对外吹」同源）。

## 四、复杂度优先降低的操作化

1. 写新条款前先问：这条删掉，AI 会不会犯一个原本不会犯的错？不会就删（R7）；
2. 新断言前先问：现有断言能否扩容覆盖？（K11 先例：C21 扩容非新增，省一个编号的维护面）；
3. 新文件前先问：载体判定表判它该不该独立（渐进式披露军规①）。
