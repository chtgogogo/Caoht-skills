# 文档类型学：这段内容该建成什么型（v1.17.0 · K15）

> **何时读**：新文档不知道该建成什么型、判断一段内容该进哪个文件、怀疑文档型错位时。
> **不读会怎样**：把事实写成叙事、把叙事当规则、把"为什么"抄进三处（MUST-01 单一事实源破产）。
> **上一层指针**：`references/载体判定表.md`（K03：一段内容进哪个**载体**按 token 实测阈值判）；细则 §2（权威分工）。

## 一、权威矩阵（MUST-01 验收锚）

🔴 **唯一真相源列以细则 §2 六问表为准，本表不重复抄**——本表只补 §2 没有的两个维度（寿命、核对节奏），事实类型与 §2 七行一一对应：

| 事实类型（§2 行） | 寿命 | 核对节奏 | 过期了怎么办 |
|---|---|---|---|
| 系统现在承诺什么行为（specs/） | 长期 | 每次跑尺即核（C 系断言） | 走变更包改，禁手抄新状态 |
| 这次改动打算改成什么（changes/） | 短期（归档即止） | 归档五步第④步跑尺 | 按五步并回，不烂尾 |
| 什么算做完（PRD） | 长期 | C11/C12 宪章与占位检查 | 开变更包改范围 |
| 不可违背约束（宪章节） | 长期 | C11 每次跑尺 | 立变更包＋必要时装 ADR |
| 进度（state.json 或降级权威） | 实时 | C07 对账 | 改权威源，视图让它重生成 |
| 为什么这么设计（ADR 类） | **决策长期有效**（不记时点快照） | C30/doc_lint 双向咬合 | 标「被取代」链新条，不删 |
| 资产自身质量（资产卡） | 长期 | 管线阶段⑤卡头 | 改资产卡本体 |

## 二、Diátaxis 四型映射（词汇参考，diataxis.fr）

| Diátaxis 型 | 本体系落点 |
|---|---|
| 教程 learning | `examples/最小项目`（30 秒上手） |
| 操作 how-to | SKILL.md 启动路由（第 0-5 步，按场景跳） |
| 参考 reference | `specs/`＋scripts＋细则 §3-§5（判据即参考） |
| 解释 explanation | 本 references 组＋细则 §6-§7（为什么这样设计） |

判据：一段话若同时像两种型，拆开——操作里夹解释是文档臃肿的第一成因。

## 三、两条明确不采纳（防过度设计）

- **U 型排版**（重要放两头）：适用于长文档；本件 render_agents 生成区仅数十行、SKILL.md 有行数预算，收益不成立。
- **L0/L1/L2 文档分档**：本件已有双轴（管线/无管线 × 载体判定表实测阈值），再加一轴纯增心智负担。

## 四、「为什么」的归属（与 K12 §2.1 咬合）

AI 写得出"是什么"，写不出"为什么"——理由在代码外（业务约束、踩过的坑、否掉的方案）。规矩：模块内部的理由=模块 ADR；跨模块划分=ADR 或架构文档；**AI 不许自己编"为什么"**，人没说就写「待你确认」。
