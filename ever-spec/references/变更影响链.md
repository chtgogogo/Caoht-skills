# 变更影响链：改一格，波及哪四环（v1.17.0 · K15）

> **何时读**：改一个条款前想看清波及面、写变更包「影响面」节、判断这次改动要不要动测试时。
> **不读会怎样**：改了规格漏改测试、改了代码忘了条款（漂移候选无人认领）。
> **上一层指针**：细则 §4（变更包三动词）＋§6.5（追踪矩阵机读化）。

## 一、影响链四环

```
需求块（specs/…/spec.md）
  → 代码（关键定位：文件＋标识符）
    → 测试（验收：tests/…，C20 阈值三件套）
      → 卡（docs/pipeline/cards/…，管线态）
```

四环由 trace_matrix 机读串联（gen 从「关键定位/验收」两行现抽，不需要人工登记）；断任何一环，跑尺或矩阵 check 会点名。

## 二、改动传导规则

| 你做了什么 | 规格层该怎么跟 | 尺子信号 |
|---|---|---|
| 改行为（用户可观察） | 开变更包（ADDED/MODIFIED/REMOVED），做完走归档五步 | 不开包直接改＝归档闭环断（C09 族） |
| 改代码不改条款 | 条款还是旧的 ⇒ **漂移候选**：跑对账、修条款或修代码，二选一并留痕 | 机械面不响（语义漂移，见[漂移分类学](漂移分类学.md)） |
| 纯内部重构（行为不变） | 不开变更包；关键定位变了要同步条款锚点 | 锚点断＝C21/C13/doc_lint 咬 |
| 加新能力 | 变更包 ADDED＋provenance 来源行（C26） | 无来源红 |
| 改数据库字段含义 | 影响面三问"数据层"填动＋老数据去向；不可逆立 ADR | 影响面节缺失＝proposal 锚警 |

## 三、计划携带文件路径与验证（吸纳自 superpowers writing-plans）

变更包 `tasks.md` 的每个任务行尽量带两样：**触达的需求号**＋**验证命令**——这样"哪些条款要跟改"在开工前就显形，而不是靠事后想起来。样例：

```
- [ ] 1 cancel_booking 改为标记制｜触达 R-3（MODIFIED）｜验证：py -m pytest tests/test_cancel.py -q
```

## 四、条款即验收（假设-当-那么）

场景块用「假设/当/那么/但是」三段式——「但是」专写反向断言（不应该出现什么），全用「并且」会让正反两类断言混在一起（Gherkin 中文关键字全表，K22 落细则 §3）。带阈值的验收行必须带测量命令（C20），裸数字不可复跑＝文案。
