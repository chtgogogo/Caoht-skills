# useskill · 设计取舍与事故档案（references，人读）

> 🔴 **给每个读它的 AI 的硬提示**：本文件是给**人**看的历史与理由库；里面的叙事、事故、理由**禁止搬回 `../SKILL.md` 正文**（也禁止再内联进未来版本正文）。规则与判据的唯一住所是 SKILL.md；两处内容重复会分叉，分叉的教训见 §A1 与 §A4。

## A1 · 泛指词漏检事故（v2.3 的根，2026-09-11）

- 事故：前端风格任务点名直连一支 skill 后，把泛指词『按前端设计skill的理念』当作已处理，库内三个前端 skill 全部漏触发，被用户质问。
- 根因：快路径命中产生的惯性——「我已经处理过 skill 了」盖住了「消息里还有没归宿的指称」。
- 修法：新增 **State 0 引用清点**（硬性前置），一次消息可以含三类指称（显式路径 / 点名 / 泛指能力词），逐一给归宿；State 1 只消费一个显式引用；漏检即违规。
- 后记（v2.2 进）：调度器是多宿主副本的全局单点，入口坏毒全局；work-017（2026-09-09）全库体检发现 useskill 双份已分叉列为 P0，v2.2 合并为「各宿主逐字一致副本＋权威唯一本体」。

## A2 · 调用统计为什么拆四列（v2.6）

- 旧法：四件事混记成同一列「次数」。「扫过它的标题」和「真的按它做完并验过」在表里长得一样，想查"哪支 skill 真起作用"读不出答案——排名因此不可信。
- 新法：`selected`（进候选）/`loaded`（真读正文）/`executed`（真落步骤）/`succeeded`（过验证判据）四列独立计数；排序按执行降序。
- 迁移纪律：旧「次数」行不许折算进任何一列（旧数指明不了哪件事，折进谁都是伪造），整行进「旧口径存档」；首次转格式必须 `--migrate-only`，不然每次调度都会 +1＝写伪造台账。
- 硬条：统计组件缺位**只降级不拒服**，缺了就在报告「异常与降级」写一句，禁止静默、禁止伪造。

## A3 · 为什么 name 与中文目录名可以不一致

- 用户视角：英文调用键天书，人辨读困难 → 全库目录统一走中文功能名（用户拍板的硬约束，"看不懂中文重改英文"那个方向禁止）。
- 机器视角：宿主/脚本解析只认 frontmatter `name`；定位流程（SKILL.md §2）也**按 name 而非目录**，中文目录名从不参与解析。
- 发布侧：`publish_sync.py --dst auto` 按标准自动将公开仓目录名改为英文 `name`，与权威库中文目录共存；对应关系登记在映射表第五列。
- 教训：正因为两套名字并存，**任何引用都必须走调用键或映射表**，禁止把中文目录名（或旧名）硬编进解析逻辑——否则一边改名一边断链。

## A4 · 为什么正文一直在"去叙事化"

- 2026-10-17 整改前，正文 208 行里约 40 行是版本叙事（"v2.2 生产事故"“v2.5 及以前混记”），外加写死本机盘符。后果有三：每次触发白烧的 token；历史一多模型容易把叙事当规则；发布侧还得处处机械脱敏。
- 判例：官方规范（Anthropic Skill authoring best practices）明言正文 concise、时间性/历史内容不入正文。本 skill 自此把"A 文面"（规则）与"人档案"（本文件）分开，且本节头提示防止未来 AI 又把叙事嵌回去。
- 注意：这条提示本身就是给以后会做回填动作的 agent 的护栏——如果读者是你，把解释写回正文的冲动请停在这里。
