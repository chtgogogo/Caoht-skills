# useskill — Skill 统一调度规则

> **词汇表（全文每词一义，不再换叫法）**
> - **调用键**：frontmatter 的 `name` 字段，英文 kebab-case，机器唯一解析键
> - **文件夹名**：中文目录名，给人一眼辨读（本库约定，与调用键无需一致）；定位按调用键，不按文件夹名
> - **指称**：用户消息里对任何 skill 的一切提及（显式路径 / 点名 / 泛指能力词都算）
> - **库根**：唯一技能库根目录（解析序见第三节）；**清单**：`<库根>/__技能清单.md`（脚本生成，禁手抄）；**映射表**：`<库根>/__SKILL详细名映射表.md`（权威源；同名 `.csv` 是冻结存档，不跟随更新）
> - 历史复盘、事故档案、设计理由 → `references/design-decisions.md`（人读档案）。🔴 禁止把叙事内容搬回本正文。

## 〇、定位：先确认自己在哪种口径下运行

| 你在哪 | 本 skill 的身份 | 硬规则 |
|---|---|---|
| 本机权威库（宿主 AGENTS.md 已把本 skill 设为常驻入口） | **强制前置调度器** | 库内技能的调用一律先过本规则；禁止绕过本规则直接读别的 skill 执行体 |
| 陌生宿主 / 只把本目录拷进技能库单独安装 | **可选导航器** | 宿主原生技能发现机制优先，本 skill 不抢入口；只在「宿主找不到」或「用户点名」时补位导航 |

- **本机口径以 `personal.local.md` 为准**：存在 → 先读它，它覆盖上表默认口径；不存在 → 走右上列的通用口径。**读不到这个文件不是错误**，照常服务，不许报断链。
- **与宿主原生技能发现的分工**（两口径共用）：宿主自挂载或插件市场提供的内置 skill 由宿主自己发现直连，本调度器不拦截、不代读、不重复登记；本调度器管**库根内**那批技能目录的清点、检索、路由与报告。内置件名单以宿主面板当版为准，正文不写死。
- **配套件缺位只降级、不停服**：按第八节右列兜底手工走完，用户的任务照常交付。

## 一、触发与短路

**触发（满足任一）**：

1. 用户显式说「调用 / 使用 / 找 skill / useskill」
2. **穷举授权**：说「全面调用 / 全面使用 / 尽可能用 useskill / 把相关的 skill 都挑出来」→ 直接进**穷举模式**（无需其他引用）
3. 任务超出自身基础能力（生成特定格式文件、外部检索、图像处理…）
4. 兜底：连续 2 次工具调用失败，或某子任务 3 轮无实质进展

**短路（直接正常对话）**：纯打招呼、闲聊、单行知识问答、简单总结等不涉及外部工具的任务。

## 二、调度状态机（核心流程）

### State 0 · 引用清点（每次调度第一步，硬性前置）

调度开始时（无论后续走哪个 State），先把用户本条消息中的**全部 skill 指称**列为清单，逐一标注归宿。指称分三类：

1. **显式路径**：给出了 skill 所在目录/文件路径 → 直接定位；
2. **点名 name**：给出了调用键或中文文件夹名 → 按第三节解析；
3. **泛指能力词**：「XX skill」「用/按/参考 XX 的理念/规范/方法」「XX 指南」及任何"某领域 + skill"合成词（例：『按前端设计skill的理念』『用数据分析的skill』『Frontendskill』）。

**快路径惯性防御**：State 1 命中只消费**一个**显式引用，禁止因已命中而跳过对剩余泛指引用的解析（事故档案见 `references/design-decisions.md` §A1）。

### State 1 · DIRECT_MATCH（已知名字快路径）

- 条件：引用清点中存在显式路径或点名引用。
- 动作：按第三节解析路径读目标 `SKILL.md` 执行；本机缺失 → 跳 State 3。

### State 2 · LOCAL_SEARCH（本地语义检索）

- 条件：引用清点中的**泛指能力词**（State 0 第 3 类），或任务类型明确但不知具体名字。
- 动作：
  1. **索引优先**：先查库根 `__技能清单.md`（`scripts/gen_skill_manifest.py` 从实际目录生成，含 name／展示名／入口／版本／依赖／适用场景六列，**只能生成不能手抄**；是否过期用 `--check` 现判，命令形状见 `references/maintenance.md` §1），再查映射表。**泛指词先按"中文文件夹名前缀"匹配**——库内文件夹名即中文功能名，泛指词往往就是前缀（例：『前端开发』→「前端开发-写页面组件实现」），一查即中，成本极低，禁止跳过；
  2. **目录兜底**：两表都缺或未命中 → 扫库根下各 `SKILL.md` 的 `name` + `description` 做语义匹配；
  3. 选中读 `SKILL.md` 执行；无匹配 → 跳 State 3。

### 穷举模式（用户明示「全面 / 尽可能」时才启用）

1. **全库浏览的正确姿势**：读库根 `__技能清单.md` 全表——它就是全库目录的索引视图，一次 IO 等于浏览整个目录，且自带版本与依赖列；缺失或 `--check` 报不一致时退读映射表；两者都不在场才实际扫库根下各 `SKILL.md` 的 `name` + `description`。
2. **相关性筛选**：按当前任务关键词逐行比对，把**所有相关候选全部列出**——宁多勿少（用户说"全面"即授权宽口径，拿不准的倾向纳入），但禁止把明显无关的 skill 塞进上下文。
3. **分阶段使用**：多 skill 命中时按任务阶段排序执行（规范/设计 → 实现 → 审查/打磨），每个命中 skill 都要实际读取其 `SKILL.md` 后才允许声称"用了"。
4. **透明可见**：候选清单、纳入/排除理由，全部写进调度报告的「引用清点」行，用户可逐条复核。

### 反例 · 容易混淆但**不应**触发（拿不准时就往「不加载」判）

| 用户在做的事 | 容易被误当成 | 正确动作 |
|---|---|---|
| 「解释一下这段代码／这一行什么意思」 | 交付流水线、五模板之「构建生产就绪应用」 | 就地解释；顶多读被点名的那一支，**不加载整套流水线** |
| 「审判这份东西差在哪／给个评分」 | 项目验收、上线放行 | 按审判类 skill 出差距清单；**审判结论 ≠ 验收通过**，报告里不许写「已验收」 |
| 「按 XX skill 的理念稍微美化下」 | 只消费已点名的那一支 | State 0 仍须把这条泛指词单独清点，命中几条读几条 |
| 「问一个技术概念／贴一段报错求解释」 | 「任务超出基础能力」→ 开穷举 | 直接回答；穷举只在用户明示「全面／尽可能」时启用，其余一律窄口径 |

判据一句话：**流程规模由用户要求的那件事决定，不由「库里恰好有一支重型 skill」决定**。

### State 3 · MARKET_FETCH（GitHub 检索兜底，唯一口径）

- 条件：State 1/2 均无匹配（本地缺、库里也没有）。
- 动作：
  1. **以 GitHub 检索为准**：关键词＝任务类型 + skill；优先高星、近期维护、License 明确、SKILL.md 形态齐全的仓库或技能库；
  2. 命中：列出候选与来源链接 → 询问用户是否下载及落点（下载/克隆一律落非系统盘，库根优先）；
  3. **入库安检门（强制，永不静默跳过）**：过**安检件 `skill-inspector`**（库内「SkillSpector安检-装skill前官方安全审查」；上游＝NVIDIA/SkillSpector 官方审查件，来源 blob sha 与装前安检读数见该支自身 CHANGELOG.md）——APPROVE 才入库；CAUTION 须用户明确点头；REJECT 拒装并出示证据。其 CLI 缺位时它会自动转 Manual Fallback 手动审；
  4. 入库 → 登记：映射表加行＋清单重生成（见第七节与 `references/maintenance.md` §1）→ 回 State 1。
- 未命中：如实告知「暂无可用 skill」→ 建议自建：调用 `skill-creator`（本库「技能创建器-创建更新skill规范」；宿主也内置同名件时宿主直连优先），并向用户提问协助搭建。

## 三、路径解析（库根 + 按调用键定位）

1. **库根解析序**：环境变量 `WORKBUDDY_SKILLS_PATH` → **本 skill 目录的父目录**（本机＝权威库；单装＝技能装到的那个目录）→ 标准兜底路径 `~/.某宿主/skills/`、`./skills/`、`~/.codex/skills/`（仅用于找本调度器自身，不用于找 skill 本体）。本机现值记在 `personal.local.md` §2，正文不写死。
2. **定位 skill 本体按 `name`（调用键），不按文件夹名**：
   - 清单/映射表解析调用键 → 得中文文件夹名 → 读 `<库根>/<中文文件夹名>/SKILL.md`；
   - 两表都缺席时兜底＝扫 `<库根>/*/SKILL.md` 的 frontmatter 找 `^name: <调用键>` 行，三组 shell 等价写法任选（`py` 启动器 Windows 用 `py`，类 Unix 用 `python3`）：

```text
# 任意 shell，跨平台首选（一行式）
py -c "import re,sys;from pathlib import Path;[print(p.parent) for p in Path(sys.argv[2]).glob('*/SKILL.md') if re.search(r'(?m)^name: ' + re.escape(sys.argv[1]) + r'\s*$', p.read_text(encoding='utf-8', errors='ignore'))]" <调用键> <库根>
# PowerShell 5.1+
Select-String -Path "<库根>\*\SKILL.md" -Pattern "^name: <调用键>\s*$" | Select-Object -ExpandProperty Path
# Git Bash / GNU grep
grep -rl "^name: <调用键>" <库根>
```

## 四、异常处理与降级

被调 skill 出错（超时 / API 异常 / 死循环）：

1. **参数修正重试**：同 skill 换保守参数重试 1 次
2. **同级降级**：换功能相近备选 skill 重试 1 次
3. **硬终止上报**：仍失败立即停止，不静默掩盖，回复末尾输出错误与已尝试路径

## 五、透明性报告（强制）

每次经本 skill 触发调度后，回复末尾追加标准块：

```
---
### 🛠️ Skill 调度报告
- **已调用**: `[skill_name]`（无则 `无`）
- **引用清点**: 消息内全部 skill 指称 → 各自归宿（已调用 / 不适用+原因；**一条指称都没有时填 `无指称`**）；出现「漏检」即为违规
- **触发原因**: [显式指令 / 任务匹配 / 穷举授权 / 兜底激活]
- **检索路径**: [引用清点→… / DIRECT_MATCH / LOCAL_SEARCH / MARKET_FETCH]
- **异常与降级**: [正常 / 简述降级动作]
---
```

## 六、调用统计（四事件分计 · 每次调度后更新）

| 事件 | 记的是哪件事 | 什么时候 +1 | 什么时候**不**记 |
|---|---|---|---|
| `selected` 选中 | 进了候选清单 | 含穷举模式的宽口径候选，被列进候选就记 | —— |
| `loaded` 读取 | 真读了它的 `SKILL.md` 正文 | 打开正文并据其执行 | 只列进候选、没读正文 |
| `executed` 执行 | 按它的流程实际走了步骤 | 流程步骤落地（跑了它的命令／交了它该产的物） | 读完没动手 |
| `succeeded` 成功 | 产出通过了本次任务的成功判据 | **验证过了**才记 | 「看起来行」、验证没过、压根没验 |

为什么拆四列、旧「次数」怎么迁移：`references/design-decisions.md` §A2（混记四件事＝排名不可用）。表在 `<库根>/__usage_stats.md`，列序固定 `| skill (name) | 选中 | 读取 | 执行 | 成功 | 最近调用 |`，按「执行」降序，同值依次看成功、读取、选中。

**首选跑脚本**（缺表缺行自动建、只加被点到的列、改日期、重排、表下方别人手写的注解行原样保留、落盘后读回对账）：

```text
py <库根>/__tools/usage_update.py <name>                          # 记一次 executed（旧命令形状不变）
py <库根>/__tools/usage_update.py <name> --event loaded executed succeeded
py <库根>/__tools/usage_update.py <name> --root <库根>             # 库不在脚本上一层时显式指，不默认赌盘符
py <库根>/__tools/usage_update.py --migrate-only --root <库根>     # 只把旧口径行搬进存档，一个计数都不加
```

- 🔴 **第一次转格式必须用 `--migrate-only`**：正常调用每次都会 +1，在没有「真发生了那次事件」的时候调用它＝往台账写伪造的数。`--migrate-only` 与 `--event` 同给会被拒绝（退出码 2）。
- 🔴 **统计不是服务的前提**（硬性）：脚本不在、库根不对、文件不可写、退出码非 0——一律**照常把用户的任务做完**，只在报告「异常与降级」行写一句「统计未记（原因）」。禁止因统计挂掉拒绝调度，也禁止伪造计数。

> 兜底（脚本不可用时手工改）：找到该 `name` 那一行 → 对应事件列 +1、`最近调用` 改为今天；没有该行就新建一行（其余列填 0）；保持「执行」降序。旧口径「次数」行**不要折算进任何一列**——旧数字指明不了是哪件事，折进哪一列都是伪造；整行原样搬进文件末尾「旧口径存档」。
> 用户问「哪些 skill 最常用」时直接读这个表回答，但要说清是**哪一列**的排名（选中 ≠ 执行 ≠ 成功）；表很小，多读一次不费 token。

## 七、维护（完整操作手册见 `references/maintenance.md`）

- 新增 / 删除 / 改名 skill → 同步更新映射表 ＋ 重生成清单并自证：

```text
py <本skill目录>/scripts/gen_skill_manifest.py --root <库根>          # 生成（幂等：内容没变不重写文件）
py <本skill目录>/scripts/gen_skill_manifest.py --root <库根> --check  # 纯读核对：不一致＝过期，退出码 1
```

- **创建 / 修改 skill 后必跑体检器（PASS 才算完工）**：`py <库根>/__tools/lint_skill.py <skill目录>`；全库加 `--all`；连宿主挂载副本逐字对账再加 `--host <宿主技能目录>`（本机目录在 `personal.local.md` §3；没有副本层就不加，单目录与全库体检照样能判 PASS）。
- **多宿主副本逐字一致**：先改权威本体；junction 类副本自动同字节；拷贝类副本用体检器 `--host` 对账（流程见 `references/maintenance.md` §4）。
- 分类索引（本机位置记在 `personal.local.md`）过时 → 去那个位置改；没有该文件就跳过这条，不算失败。
- 调度逻辑升级 → 只改本 SKILL.md；史话 / 复盘写 CHANGELOG 与 `references/design-decisions.md`，**不回填正文**。
- **收口四检**：凡动了库结构（装／删／改／挂载／改名），完工判据＝映射表登记 → 清单 `--check` 退 0 → 体检器 PASS → 宿主注入卡/副本/发布仓同步，四件全绿才许宣称完成；当场缺哪件就在报告「异常与降级」写明（细则与为什么见 `references/maintenance.md` §6）。

## 八、依赖件清单与缺件降级（单装也要能跑通）

正文会引用几张**不一定在场**的件。引用之前先确认它在场（列一次目录即可），不在就走右列兜底——**不静默跳过，也不谎称跑过**。

| 依赖件 | 在哪 | 随本 skill 发布？ | 缺了怎么办（任务照常交付） |
|---|---|---|---|
| `scripts/gen_skill_manifest.py` | 本 skill 目录内 | ✅ 随包发布 | 不需要兜底；库根没有清单就现跑一次生成 |
| `__技能清单.md` | 库根（派生物） | ❌ 各库自己生成 | 跳过清单，按 State 2 扫库根各 `SKILL.md` 的 name+description |
| `__SKILL详细名映射表.md` | 库根 | ❌ 库级件 | 同上；「中文文件夹名前缀」匹配照样能用，不必非读表 |
| `__usage_stats.md` ＋ `__tools/usage_update.py` | 库根 / 库级 tools | ❌ 不随包发布 | 手工改表，或整条跳过统计——第六节硬条：统计挂掉不影响服务 |
| `__tools/lint_skill.py` | 库级 tools | ❌ 不随包发布 | 改用发布仓仓根自带的 `library_check.py`；都没有就手工核对 frontmatter 三件（name／description／version 在场且是字符串）＋正文相对链接目标确实存在 |
| **安检件 `skill-inspector`** | 库内「SkillSpector安检-装skill前官方安全审查」 | ❌ 库级件（2026-10-17 新装） | 装前审计退回 `skillhub-install-audit`（SkillHub安装审计）§二的手动清单一套；都没有就口头三查（外联／执行／凭据）并在报告写明查法 |
| GitHub 检索（网络行为，非文件件） | 运行时网络 | —— | 环境禁网时如实告知「无法检索市场」，不做假搜；给库内替代选择或建议自建 |

> 判「在不在场」用**现扫**，不用记忆：本节任何一行的路径都可能随搬家／改名失效，`ls` 一次只要几毫秒，比按旧印象引用一支不存在的脚本便宜得多。
