# useskill — Skill 统一调度规则

## 〇、定位：先确认自己在哪种口径下运行

| 你在哪 | 本 skill 的身份 | 硬规则 |
|---|---|---|
| 本机权威库（宿主 AGENTS.md 已把本 skill 设为常驻入口） | **强制前置调度器** | 库内技能的调用一律先过本规则；禁止绕过本规则直接读别的 skill 执行体 |
| 陌生宿主 / 只把本目录拷进技能库单独安装 | **可选导航器** | 宿主原生的技能发现机制优先，本 skill 不抢入口；只在「宿主找不到」或「用户点名」时补位导航 |

- **本机口径以 `personal.local.md` 为准**：本目录若存在 `personal.local.md`（个人适配层，不随公开包发布）→ 先读它，它覆盖上表的默认口径；不存在 → 走上表右列的通用口径。**读不到这个文件不是错误**，照常服务，不许报断链。
- **与宿主原生技能发现的分工**（两种口径共用）：宿主自己挂载或由插件市场提供的内置 skill（如 `security-scan`、`skill-creator`、`mcp-config`）由宿主自己发现并直连，本调度器**不拦截、不代读、不重复登记**；本调度器管的是**技能库根**（见第三节）内那批技能目录的清点、检索、路由与报告。
- **配套件挂了只降级、不停服**：清单／统计／体检脚本或映射表缺位时，按第八节的兜底流程手工走完，用户的任务照常交付。

## 一、触发与短路

**触发（满足任一）**：

- 用户显式说「调用 / 使用 / 找 skill / useskill」
- **穷举授权**：用户说「全面调用 useskill / 全面使用 useskill / 尽可能用 useskill / 把相关的 skill 都挑出来」等 → 直接进入 **State 2-EX 全库扫描模式**（无需其他引用）
- 任务超出自身基础能力（生成特定格式文件、外部检索、图像处理…）
- 兜底：连续 2 次工具调用失败，或某子任务 3 轮无实质进展

**短路（直接正常对话）**：纯打招呼、闲聊、单行知识问答、简单总结等不涉及外部工具的任务。

## 二、调度状态机（核心流程）

### State 0 · 引用清点（每次调度第一步，硬性前置）

调度开始时（无论后续走哪个 State），先把用户本条消息中的**全部 skill 指称**列成清单，逐一标注归宿。指称分三类：

1. **显式路径**：给出了 skill 所在目录/文件路径 → 直接定位；
2. **点名 name**：给出了 skill 名字（英文调用键或中文文件夹名）→ 按第三节解析；
3. **泛指能力词**：「XX skill」「用/按/参考 XX 的理念/规范/方法」「XX 指南」及任何"某领域 + skill"合成词（例：『按前端设计skill的理念』『用数据分析的skill』『Frontendskill』）。

**快路径惯性防御**：State 1 命中只消费**一个**显式引用，禁止因已命中而跳过对剩余泛指引用的解析——v2.2 生产事故（2026-09-11，前端风格任务）：点名直连后把泛指词『按前端设计skill的理念』等同于已点名 skill，导致库内三个前端 skill 漏触发，被用户质问。

### State 1 · DIRECT_MATCH（已知名字快路径）

- 条件：引用清点中存在显式路径或点名 name 的引用。
- 动作：按第三节解析路径读目标 `SKILL.md` 执行；本机缺失 → 跳 State 3。

### State 2 · LOCAL_SEARCH（本地语义检索）

- 条件：引用清点中的**泛指能力词**（State 0 第 3 类），或未知具体名字但任务类型明确。
- 动作：
  1. 索引优先：先查库根 `__技能清单.md`（由 `scripts/gen_skill_manifest.py` 从实际目录生成，含 name／展示名／入口／版本／依赖／适用场景，**只能生成不能手抄**，生成与过期核对见第七节），再查映射表 `__SKILL详细名映射表.md`（中文文件夹名 ↔ name 字段 ↔ 功能）。**泛指词先按"中文文件夹名前缀"匹配**——库内文件夹名即中文功能名，泛指词往往就是前缀（例：『前端设计』→「前端设计指南-美观现代UI规范」），一查即中，成本极低，禁止跳过；
  2. 目录兜底：无索引/未命中，扫唯一库下各 `SKILL.md` 的 `name` + `description` 做语义匹配；
  3. 选中读 `SKILL.md` 执行；无匹配 → 跳 State 3。

**穷举模式（State 2-EX，用户明示「全面 / 尽可能」时启用）**：

1. **全库浏览的正确姿势**：读库根 `__技能清单.md` 全表——它就是全库目录的索引视图，一次 IO 等于浏览整个目录，且自带版本与依赖列；清单缺失或已过期（第七节 `--check` 报不一致）时退化为读映射表 `__SKILL详细名映射表.md`，两者都不在场才实际扫描唯一库下各 `SKILL.md` 的 `name` + `description`。
2. **相关性筛选**：按当前任务关键词逐行比对，把**所有相关候选全部列出**——宁多勿少（用户说"全面"即授权宽口径，拿不准的倾向纳入），但禁止把明显无关的 skill 塞进上下文。
3. **分阶段使用**：多 skill 命中时按任务阶段排序执行（规范/设计 → 实现 → 审查/打磨），每个命中 skill 都要实际读取其 `SKILL.md` 后才允许声称"用了"。
4. **透明可见**：候选清单、纳入/排除理由，全部写进调度报告的「引用清点」行，用户可逐条复核。

### 反例 · 容易混淆但**不应**触发（拿不准时就往「不加载」判）

| 用户在做的事 | 容易被误当成 | 正确动作 |
|---|---|---|
| 「解释一下这段代码／这一行什么意思」 | 交付流水线、五模板之「构建生产就绪应用」 | 就地解释；顶多读被点名的那一条 skill，**不加载整套流水线** |
| 「审判这份东西差在哪／给个评分」 | 项目验收、上线放行 | 按审判类 skill 出差距清单；**审判结论 ≠ 验收通过**，报告里不许写「已验收」 |
| 「按 XX skill 的理念稍微美化下」 | 只消费已点名的那一个 skill | State 0 仍须把这条泛指词单独清点一遍（v2.3 修的正是这个），命中几条读几条 |
| 「问一个技术概念／贴一段报错求解释」 | 「任务超出基础能力」→ 开穷举 | 直接回答；穷举只在用户明示「全面／尽可能」时启用，其余一律窄口径 |

判据一句话：**流程规模由用户要求的那件事决定，不由「库里恰好有一支重型 skill」决定**。误加载的代价是上下文被无关流程挤爆，并且调度报告里出现「用了但其实没读」。

### State 3 · MARKET_FETCH（市场兜底）

- GitHub 检索相关 skill，询问用户是否下载以及下载位置（下载/克隆一律落非系统盘）。
- 命中：提示用户 → 经 `skills-security-check` 审计 → 标准安装 → 回 State 1。
- 未命中：如实告知「暂无可用 skill」，建议可用 `skill-creator` 自建，并向用户提问，协助用户搭建所需skill。

## 三、路径解析（唯一库 + 自动发现）

按优先级确定 skill 库根目录：

1. 环境变量 `WORKBUDDY_SKILLS_PATH`（非标目录时用它覆盖）
2. **唯一权威库：`<你的技能库>\`**（默认，全部 skill 本体在此）
3. 兜底标准路径：`~/.某宿主/skills/`、`./skills/`、`~/.codex/skills/`（仅用于找本调度器自身，不用于找 skill 本体）

**定位 skill 本体按 `name` 字段（调用键），不是文件夹名**（文件夹是详细中文说明书名）：

- 先查映射表拿中文文件夹名 → 读 `<你的技能库>\<中文文件夹名>\SKILL.md`
- 兜底：`grep -rl "^name: <调用键>" <你的技能库>`

## 四、异常处理与降级

被调 skill 出错（超时 / API 异常 / 死循环）：

1. **参数修正重试**：同 skill 换保守参数重试 1 次
2. **同级降级**：换功能相近备选 skill 重试 1 次
3. **硬终止上报**：仍失败立即停止，不静默掩盖，回复末尾输出错误与已尝试路径

## 五、透明性报告（强制）

每次经本 skill 触发调度后，回复末尾追加标准块：

```
---
### 🛠️ Skill 调度报告
- **已调用**: `[skill_name]`（无则 `无`）
- **引用清点**: 消息内全部 skill 指称 → 各自归宿（已调用 / 不适用+原因）；出现「漏检」即为违规
- **触发原因**: [显式指令 / 任务匹配 / 兜底激活]
- **检索路径**: [引用清点→… / DIRECT_MATCH / LOCAL_SEARCH / MARKET_FETCH]
- **异常与降级**: [正常 / 简述降级动作]
---
```

## 六、调用统计（四事件分计 · 每次调度后更新）

一次调度其实是**四件不同的事**。v2.5 及以前把它们混记成同一个「次数」，于是「扫过它的标题」和「真的按它做完并验过」在表里长得一样，想查「哪支 skill 真起作用」读不出答案。v2.6 拆成四列独立计数：

| 事件 | 记的是哪件事 | 什么时候 +1 | 什么时候**不**记 |
|---|---|---|---|
| `selected` 选中 | 进了候选清单 | 含穷举模式的宽口径候选，被列进候选就记 | —— |
| `loaded` 读取 | 真读了它的 `SKILL.md` 正文 | 打开正文并据其执行 | 只列进候选、没读正文 |
| `executed` 执行 | 按它的流程实际走了步骤 | 流程步骤落地（跑了它的命令／交了它该产的物） | 读完没动手 |
| `succeeded` 成功 | 产出通过了本次任务的成功判据 | **验证过了**才记 | 「看起来行」、验证没过、压根没验 |

表在库根（第三节；本机＝`<你的技能库>\`）的 `__usage_stats.md`，列序固定 `| skill (name) | 选中 | 读取 | 执行 | 成功 | 最近调用 |`，按「执行」降序，同值依次看成功、读取、选中。

**首选跑脚本**（缺表缺行自动建、只加被点到的列、改日期、重排、表下方别人手写的注解行原样保留、落盘后读回对账）：

```text
py <库根>/__tools/usage_update.py <name>                          # 记一次 executed（旧命令形状不变）
py <库根>/__tools/usage_update.py <name> --event loaded executed succeeded
py <库根>/__tools/usage_update.py <name> --root <库根>             # 库不在脚本上一层时显式指，不默认赌盘符
py <库根>/__tools/usage_update.py --migrate-only --root <库根>     # 只把旧口径行搬进存档，一个计数都不加
```

🔴 **第一次转格式必须用 `--migrate-only`**：正常调用每次都会 +1，在没有「真发生了那次事件」的时候调用它，就是往台账里写伪造的数。`--migrate-only` 与 `--event` 同时给会被拒绝（退出码 2）。

🔴 **统计不是服务的前提**（硬性）：脚本不在、库根不对、文件不可写、退出码非 0——一律**照常把用户的任务做完**，只在调度报告的「异常与降级」行写一句「统计未记（原因）」。禁止因为统计挂掉而拒绝调度，也禁止因此往上伪造一个数。

> 兜底（脚本不可用时手工改）：找到该 `name` 那一行 → 对应事件列 +1、`最近调用` 改为今天；没有该行就新建一行（其余列填 0）；保持按「执行」**降序**排列。旧口径「次数」列的整行**不要折算进任何一列**——旧数字本来就不指明是哪一件事，折进哪一列都是伪造；整行原样搬进文件末尾「旧口径存档」一节。

> 这是「宁多勿少」的统计，做对即可；统计文件很小，多读一次不费 token。用户问「哪些 skill 最常用」时直接读这个文件回答，但要把话说清是**哪一列**的排名（选中 ≠ 执行 ≠ 成功）。

## 七、维护

- 新增 / 删除 / 改名 skill → 同步更新 `<你的技能库>\__SKILL详细名映射表.md`（调用键 `name` 字段保持稳定）
- **技能清单只能由脚本生成，禁止手抄**（快照禁令：手抄件没有再生成机制，一定会变成假数据）：

```text
py <你的技能库>\useskill\scripts\gen_skill_manifest.py --root <你的技能库>
py <你的技能库>\useskill\scripts\gen_skill_manifest.py --root <你的技能库> --check
```

  第一条（重）生成库根 `__技能清单.md`；内容没变它不重写文件（幂等，看 mtime 就知道）。第二条只读核对：现扫与在场清单正文不一致就退 1，用来回答「这份清单还作不作数」——比对时忽略 `> 生成日期：` 那一行。新增／删除／改名／改 version 之后重跑第一条。
- **创建 / 修改 skill 后必跑体检器**：`py <你的技能库>\__tools\lint_skill.py <skill目录>`；全库体检加 `--all`，要连宿主挂载的副本一起对账时再加 `--host <宿主技能目录>`（本机这个目录写在 `personal.local.md` §3；没有副本层就不加 `--host`，单目录与全库体检照样能判 PASS）；PASS 才算完工（规范=detail-003 五步法）
- 分类索引（本机位置记在 `personal.local.md`）过时 → 去那个位置改；没有该文件就跳过这条，不算失败
- 调度逻辑升级 → 只改本 SKILL.md

> **版本与副本同步（v2.2）**：本调度器 SKILL.md 在各宿主各放一份逐字一致副本（`useskill` 文件夹）；真正的 skill 本体只在 `<你的技能库>\`，不要在 `<某宿主的配置目录>\skills` 或 `<你的数据目录>\skills` 里再维护第二套。

## 八、依赖件清单与缺件降级（单装也要能跑通）

正文会引用几张**不一定在场**的件。引用之前先确认它在场（`ls`／`test -f`），不在就走右列兜底——**不静默跳过，也不谎称跑过**。

| 依赖件 | 在哪 | 随本 skill 发布？ | 缺了怎么办（任务照常交付） |
|---|---|---|---|
| `scripts/gen_skill_manifest.py` | 本 skill 目录内 | ✅ 随包发布 | 不需要兜底；库根没有清单就现跑一次生成 |
| `__技能清单.md` | 库根（派生物） | ❌ 各库自己生成 | 跳过清单，按第三节扫库内各 `SKILL.md` 的 `name` + `description` |
| `__SKILL详细名映射表.md` | 库根 | ❌ 库级件 | 同上；「中文文件夹名前缀」匹配照样能用，不必非读表 |
| `__usage_stats.md` ＋ `__tools/usage_update.py` | 库根／库级 tools | ❌ 不随包发布 | 手工改表，或整条跳过统计——第六节硬条：统计挂掉不影响服务 |
| `__tools/lint_skill.py` | 库级 tools | ❌ 不随包发布 | 改用发布仓仓根自带的 `library_check.py`；都没有就手工核对 frontmatter（`name`／`description`／`version` 三件在场且是字符串）＋正文相对链接的目标确实存在 |

> 判「在不在场」用**现扫**，不用记忆：本节任何一行的路径都可能随搬家／改名失效，`ls` 一次只要几毫秒，比按旧印象引用一支不存在的脚本便宜得多。
