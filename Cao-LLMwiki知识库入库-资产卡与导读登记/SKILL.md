# LLMwiki 知识库入库流水线

## Overview

把「用户指着一个软件/仓库/资料说『这个也得记进 obs』」变成一条七步可复现管线：认库 → 读规矩 → 分流 → 写卡 → 登记 → 追加版本节 → 收尾三连。

库的规矩分散在 `AGENTS.md`、`0-入口\AI导读.md`、`0-入口\模板\资产卡模板.md` 三处。**这三份文件是唯一真源**；本 skill 只是流程骨架，与库内文件冲突时以库内为准，并当场报告差异（库在被五个 AI 持续改动，写死快照必然过时）。

## 0. 先认库（写错库＝白干）

| 路径 | 状态 | 可写性 |
|---|---|---|
| `<你的知识库>` | 活跃库，有 git 与月度体检 | 唯一入库目标 |
| `<你的记录根目录>\知识库` | 2026-09 封存冷备 | 只读；要内容捞出来按本库规范重录，绝不回旧库写 |

判活跃/封存别只信本文：现查 `git -C <你的知识库> log --oneline -3` 与 `ls -l <你的知识库>\CHANGELOG.md`，看是否仍有活动。行为记忆（怎么干活／踩坑／会话记忆）**不进本库**，进各家记忆 store——分工红线写在 `AGENTS.md` §1。

## 1. 进库必读三份（≤2000 token 预算）

1. `AGENTS.md` — 三步调度法、分工红线、五不收、格式约定、留痕规范、数据安全
2. `0-入口\AI导读.md` — 触发词组路由表（「触发词组」＝按“干什么活”给卡片分组的组）＋底部「触发词组清单」节
3. `0-入口\模板\资产卡模板.md` — 卡片形状

**三步调度法（库定的硬规则）**：查表找组 → 命中组内**至少读 2 张卡**再动手（同型去偏）→ 没命中才按五不收补卡。单次检索超 2000 token 就强制停，并向用户说明「可能有遗漏」。

组清单会增会变，一律现查，别抄快照。

## 2. 分流：五不收 ＋ 三分法

**五不收门槛**（逐条对上才收）：与 AI 协作无关不收 ／ 来源核实不了不收 ／ NC 协议不商用（NC＝非商业许可：个人学习可下载收藏，卡片如实标注并写明「仅个人学习，禁商用禁入对外交付工程」）／ 只存长文不配卡不收 ／ 重复不收。

**三分法**决定内容落哪个文件：

| 回答的问题 | 落点 | 例子 |
|---|---|---|
| 这东西装在哪、能干嘛 | `3-本机资产\AI工具地图.md`（只加行，不配卡） | Godot、Krita、ffmpeg、yt-dlp、cpolar、npm-cache／gocache／pip-cache 等缓存重定向目录 |
| AI 干活时该想起哪个仓库／资料 | `1-资产卡\<组名>-<对象名>.md` | aoci-code、blender-mcp、anything-llm |
| 这是用户自己的工程还是工具 | `3-本机资产\项目档案.md` | 判据：`git log` 零提交或无上游＝用户自有工程，不当工具登记 |

新卡命名照既成惯例：`组名-对象名.md`（例 `Agent生产-aoci-code.md`、`LLM教程-happy-llm.md`）。

## 3. 写卡：硬格式（缺一项就吃体检红项）

**frontmatter 六字段行必须在场**（这是 `tools\kb_check.py` 的实际校验口径，不是「五必填」）：

```yaml
---
type: asset-card
group: <触发词组名>
source: <上游仓库／官方地址>
local: <本地路径；纯在线卡写"仅在线"或留空值>
license: <许可证>
status: active
superseded_by:
last_checked: <YYYY-MM-DD>
tags: [资产卡, <触发词组名>]
---
```

- 🔴 `local` **允许留空值，但字段行不能少**：体检查六行齐全（group／source／local／license／last_checked／status），除 local 外五项还必须有值。少写一行直接红。
- `tags` 第一个＝类型，第二个＝触发词组名。
- `last_checked` 必须是 `YYYY-MM-DD`，否则体检报「无法解析」红项；超 90 天未核对报过期。

**正文首行面包屑**（页面顶部的返回导航行，体检逐页扫）：

`> 🏠 [[首页]] ｜ 📖 [[AI导读]] ｜ 📁 1-资产卡`

**双链** `[[文件名]]` 只能指向真实存在的文件（体检按全库 md 判死链）。拿不准就用只读方式核对目标文件存在，别靠反复跑体检来试错（副作用见 §6）。

**事实必须实测，禁止按常识填**：上游地址取 `git remote -v`，许可证取 `LICENSE` 原文首行；查不到就写「未核实」。曾有两次按常识推断差点写错（Godot 目录内无 LICENSE 文件、yt-dlp 打包版只附第三方依赖的许可证），ffmpeg 由「GPL」实测纠正为 GPL-3.0。许可证的商用边界要引条款原文写清（例 FSL-1.1-MIT 的红线是「做成竞争性商业产品或服务」，自用／教学／科研／服务均可）。

**用法段要能照做**：命令、安装方式、产物、参数默认值取自 README 实测行，并单列「静默失败坑」——那种不报错却不生效的边界最值钱。

## 4. 登记：AI 导读两处同步（最容易漏的一步）

新卡必须在 `0-入口\AI导读.md` 落地，否则体检报「孤儿卡」黄项：

1. **总索引表**：找到目标组那一行，把新卡并列进「目标」列（用 ＋ 连接），并在「说明」列写清各张卡的口径差异（例：网上选中的／本机已有的／某张专卡）。同组并列展示，不覆盖旧条目。
2. **触发词列**：按新卡内容补触发词（例：新增「代码认知／仓库索引／AI记忆层」）。
3. **建了新组才动这条**：新组名必须同时进总索引表和底部「触发词组清单」节——只写一处体检报「导读组清单不同步」黄项。

用卡时发现内容过期 → **当场修** ＋ 刷 `last_checked` ＋ 提交，不许「知道错了先记着」。

## 5. CHANGELOG：顶部倒序纯插入

`CHANGELOG.md` 版本节按**时间倒序**排：新节插在标题与格式说明行之后、**当前最上方那个 `## v` 节之前**；文件末尾的 `<!-- 后续版本按时间倒序追加在上方 -->` 注释不动。

写法 `## v<X.Y.Z>（YYYY-MM-DD）<一句话主题>`，正文三小节：**优化了什么／新增了什么／解决了什么问题**（库的铁律 6 格式）。

🔴 **号位先现查再定**（五个 AI 同时在写这一个文件）：HEAD 与工作树都要查，只查已提交的会漏掉别人尚未 commit 的同号节。

```bash
git -C <你的知识库> show HEAD:CHANGELOG.md | head -6
grep -n "^## v" <你的知识库>/CHANGELOG.md | head -6
```

用 Edit 把新节整块插到旧首节之前，**绝不把邻居版本节圈进替换范围**（要逐字重抄就必漏抄＝吞掉他人历史证据，且零报错）。

## 6. 收尾三连（顺序不能换）

1. **留痕**：`py <你的知识库>\tools\kb_track.py --cards "卡A,卡B" --scene "任务场景" --host <宿主名>`
   - 🔴 `--host` **必须显式给**：脚本默认值是 `某宿主`，漏传就把别家 AI 的功劳记到 某宿主 名下，体检「覆盖宿主」榜永远不出现你家（覆盖宿主是从 `6-outputs\usage.log` 实际解析的，禁止手写报告）。
   - `--scene` 里必须写「同组只用其一」的选择理由（月度体检抽查）；浏览未用不计，只记实质引用／查证／参照。
2. **体检**：`py <你的知识库>\tools\kb_check.py`（不带参数＝无条件出报告；`--schedule` 是计划任务门闸，手工别加）。它会重写 `6-outputs\体检报告_YYYY-MM.md`——这文件是被 git 跟踪的，跑完连着一起提交，否则下一轮又报「git 有未提交内容」黄项。**一轮跑一次就够，别反复跑脏它。**
3. **提交**：先 `git -C <你的知识库> status --short` 看清在途，再**只按路径** `git add`（禁 `git add -A`／`.`，别人的在途改动不代提交），commit 信息照既有风格写版本号＋改动面。
4. **push 先问用户**：远端 `https://github.com/chtgogogo/LLMwiki`，五个 AI 共用的门面，没明确指令不推。

体检项含义：断链／垃圾文件／面包屑／孤儿卡／frontmatter 六字段／导读组清单同步／过期卡／热度榜与日志健康／注入点存活／宿主地图时效／同组冲突自洽／冷卡候选（只列不删）／超大文件（>500KB）／git 未提交。

## 7. 多人共写防线（本库最高频的毁数据方式）

- 开工第一件事：`git -C <你的知识库> status --short`，把别人在途的文件记下来，收尾时**不碰它们的行**。
- 改完对账分两类判据，别一刀切要求「删除行为 0」：
  - **纯追加类**（CHANGELOG 新节、地图新行、清单节）：`git -C <你的知识库> diff --numstat` 删除列必须为 0。
  - **就地改行类**（导读表某组行扩写）：删除列＝预期改行数（改 1 行就是 1/1），并逐条确认邻居组行原样还在。
- 🔴 **Git Bash 里中文关键词传给 grep 会静默零命中**（实测：六个中文词全报「没有」、退出码 0 无报错，同一棵树 Python 全库扫却数出了命中）。核对中文行是否存在，要么用 Read 直接读回，要么 Write 成 `.py` 再跑；非用 shell 不可时先塞一个**已知存在**的中文词做正例校验，正例没中就判这把尺子作废。
- 🔴 **本机跑 Python 只用 `py`**，禁用 `python`／`python3`——两者指向商店占位 stub，零输出＋退出码 49，接上管道后退出码被吃掉＝静默假成功。
- 🔴 **别把 Windows 反斜杠路径写进内联脚本**（`py -c`／heredoc 里 `\t` 会吞字符、`\202` 被当八进制）。路径落成 `.py` 文件再跑，或用正斜杠／`chr(92)`。
- 🔴 **原地改写文件与丢弃报错绝不同条**：禁裸 `sed -i` 叠 `2>/dev/null`；对不可再生的原始输出（命令回显、真调记录）二次写入前先复制，改完数行数对账。
- 🔴 **改完本体只算改了一半**：新卡建完后派生物四类逐类核对——导读总索引行、组清单行、CHANGELOG 节、自己那页宿主地图状态，缺一类就漏一类。
- `4-AI宿主地图\<你的宿主>.md`：**谁的地盘谁更新自己那页**（含 `last_self_check` 与收尾链真实状态）。进库发现自己页缺失或未登记→当场补。

## 8. 另一类入库：8-检索智慧（联网检索到的精华）

沉淀「AI 联网检索到的优秀设计／权威资料／行业数字」走这个组，**不收进 1-资产卡、字段口径也不同**：建卡四件套＝① frontmatter `title／来源URL／检索日期／last_check／复核条件／deps` ② 正文大白话一句话＋要点＋适用场景＋**反例边界**（何时不适用，防误用）③ AI导读加行 ④ 来源核实且 NC 如实标注；并按快／中／慢三档 decay 定复核节奏。细则现查 `8-检索智慧\README.md`。

权威原文进 `7-工具书\` 另加三验：来源验（只收官方域名，记确切 URL）、完整验（大小与官方发布一致）、许可验（NC 不收），三验记录写进该子目录 README。

## 9. 硬红线（任何时候）

- 密钥／密码／token 绝不写入本库任何文件。
- `9-归档\` 永不删；冷卡（90 天零命中＋未核对，双条件）只能列候选，**降权归档必须用户确认**，热度数据绝不自动删东西。
- `_Repos\` 不进 git（外部仓库克隆区）。
- 与记忆库分工：本库只存资料与资产；行为经验／踩坑／偏好进各 agent 的记忆 store，别混。

## 快速自检清单（收尾前逐条打勾）

1. 写的是 `<你的知识库>` 而不是封存旧库？
2. 过了五不收，且落点对（地图／资产卡／项目档案）？
3. 六字段行齐、`last_checked` 是 `YYYY-MM-DD`、面包屑首行在、双链目标实存？
4. 许可证与上游是实测值，查不到的写了「未核实」？
5. AI导读 组行已并列、触发词已扩；（若新建组）组清单节也同步了？
6. CHANGELOG 新节插在最上方版本节之前，邻居节未动？
7. `kb_track` 带上了 `--host <宿主名>`，scene 写了同组取舍理由？
8. `kb_check` 结论绿（红 0 黄 0），或黄项已如实说明？
9. 只 `git add` 自有路径、未提交他人改动、未擅自 push？
