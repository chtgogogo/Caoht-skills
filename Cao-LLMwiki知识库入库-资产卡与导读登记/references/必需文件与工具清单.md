# 必需文件与工具清单（缺哪个会怎样、缺了怎么手工顶）

> 本页是「公开包能不能跑」的账。`scripts/kb_intake.py` 只依赖 Python 标准库＋一份配置；
> 别的库自带工具（留痕器、体检器）**一律是可选外挂**，缺了不许把流程判死。

## 一、脚本运行必需（缺 ⇒ 退 2，不开工）

| 文件 | 作用 | 缺了会怎样 |
|---|---|---|
| `intake_config.json`（库根） | 唯一配置：各路径、必填字段名、版本分配口径、项目类型规则、落点表 | 直接拒绝开工，不猜默认库根 |
| `paths.guide` 指向的导读 | 总索引表＋组清单，卡片的登记位 | 成组写盘无处可写 ⇒ 该步失败并停住 |
| `paths.card_dir` 目录 | 卡片存放处 | 新建卡片无处可落 |
| `paths.changelog` 指向的版本史 | 每组的版本节落点 | 插入锚点找不到 ⇒ 该步失败 |
| `paths.version_ledger` 指向的版本台账 | 版本号唯一写入点 | `apply` 拒绝入库；先 `seed-ledger` 播种 |

## 二、库该有但脚本能容忍（diagnose 报黄不报红）

| 文件 | 作用 | 缺了会怎样 |
|---|---|---|
| `0-入口/模板/资产卡模板.md` | 写卡的形状参照 | 报黄：新卡形状只能靠正文 §3 的记忆 |
| `AGENTS.md`（库规矩） | 分流红线、格式约定的权威源 | 报黄：规矩只在本 skill 里，库内无据可查 |
| `3-本机资产/AI工具地图.md` | 「装在哪、能干嘛」的行表 | 报黄：地图类条目没地方落 |
| `3-本机资产/项目档案.md` | 自有工程的行表 | 缺文件本身＝**报黄**（自有工程无处登记）；🔴 **报红**是另一件事：`landing_by_type` 声明了 `user_project` 的落点键、而 `paths` 里那个键没给路径 ⇒ 退 1 并点名类型 |
| `6-outputs/usage.log` | 用卡留痕流水 | 报黄并点名文件；`diagnose --fix` 可建骨架（建完复跑即转绿，不是把黄项静音） |
| 首页（面包屑指向的页） | 卡片顶部的返回导航目标 | 卡片双链成死链 ⇒ **判红**退 1；诊断报告照常打印并点名「哪张卡 → 哪个目标」 |

## 三、可选外挂：留痕器与体检器

| 外部工具 | 职责 | 在场时 | 缺失时的纯手工降级 |
|---|---|---|---|
| 留痕器（本机叫 `kb_track.py`） | 往 `usage.log` 追加一行「日期｜用到的卡｜宿主｜场景」 | `apply` 成功后调它；**宿主名必须显式给**，否则默认值会把功劳记到别人名下 | 手工按表头格式追加一行；同组只用其一时要写清取舍理由 |
| 体检器（本机叫 `kb_check.py`） | 全库扫断链／孤儿卡／字段行／组清单同步／热度榜，并**重写**报告文件 | 收尾跑一次（一轮一次，它改文件） | 跑 `kb_intake.py diagnose`（默认只读，判据见下表）＋按正文末尾「快速自检清单」逐条打勾；报告文件不重写，就别把它写进提交 |

配置位：`tool_paths.track` / `tool_paths.check` 写绝对路径；留空 ⇒ 脚本自动走降级分支并打印说明。
**别把这两个路径写进公开正文**：它们是本机坐标，属于 `personal.local.md`。

## 四、`kb_intake.py` 的判据口径（和库体检器保持一致）

| 检查 | 口径 | 红/黄 |
|---|---|---|
| 卡片字段行 | `card_required_lines` 六行必须在场（`local` 可空值，**行不能少**） | 缺行＝红 |
| 卡片字段值 | `card_required_values` 必须有值（`local` 除外） | 空值＝红 |
| 核对日期 | `date_field` 必须 `YYYY-MM-DD` | 解析不了＝红 |
| 面包屑 | 正文开头 400 字内出现 `breadcrumb_token` | 缺＝红 |
| 双链 | `[[目标]]` 必须能对上全库 `.md` 文件名（`模板`／`.git`／`_Repos` 等目录不参与） | 死链＝红 |
| 孤儿卡 | 卡片名必须出现在导读里 | 缺＝黄 |
| 组清单同步 | 总索引表里的组 ⇄ 组清单节反引号里的组，双向对齐 | 不齐＝黄 |
| 版本台账 | 同号被认领两次＝并发撞号 | 红 |
| 台账 ⇄ 版本史 | 版本史最大号高于台账 ⇒ 台账漏记 | 黄（跑 `seed-ledger` 补认领） |
| 分母闸 | 必需路径一个都没找到 ⇒ 判据作废并明说 | 红（拒绝打「全绿」） |

## 五、退出码

`0` 成功 ｜ `1` 某一步未过或诊断有红 ｜ `2` 用法与配置错（含库根缺失、无配置、判不出类型）｜
`3` 成组不一致（先 `resume` 补，或 `rollback` 还原，**别提交**）｜ `4` 锁被活写者占用／号位撞车 ｜
`70` 测试钩子模拟的中断（`--crash-after`）

## 六、随包资产

- `templates/最小可运行库/` ＝ 完整可跑的空白示例库（不是填空骨架）：配置、导读、模板、示例卡、版本史、台账、流水全在场；
  `selftest` 就是拿它复制出多份合成夹具来跑断言，示例库自身一个字节不改。
- `scripts/kb_intake.py` ＝ 上面这套机制的实现；`selftest` 断言条数**现查**（跑一次看最后一行），别抄文档里的数字。
