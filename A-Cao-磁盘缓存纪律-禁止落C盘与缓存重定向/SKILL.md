# 磁盘与缓存纪律（禁止落 C 盘 · 缓存重定向）

> **定位**：这是**环境层**的纪律，管"东西写哪个盘"。
> 与它并列的三件：`编码行为准则`、`测试纪律`、`抗幻觉纪律`。**四件互不重叠。**

## 0. 核心（每轮必守）

1. 所有**下载 / 克隆 / 虚拟环境 / 模型权重 / 日志 / 解压产物**，默认写**非系统盘**（D 盘、E 盘），**严禁** `C:\Users\<user>\Downloads`、`C:\Users\<user>\.cache` 等默认路径。
2. 在非系统盘建统一目录（本机约定）：
   - 工程：`<非系统盘>\AI_Projects`
   - 缓存：`<非系统盘>\AI_Cache`

---

## 一、缓存与环境重定向

| 工具 | 环境变量 | 说明 |
|---|---|---|
| pip | `PIP_CACHE_DIR` | 或 `pip install --cache-dir <非系统盘>` |
| npm / pnpm | `npm_config_cache` / `PNPM_HOME` | |
| HuggingFace | `HF_HOME` | **下载模型前**先设，否则权重落 C 盘 |
| 其它 | — | 任何"默认往用户目录 `.cache` 写"的工具，**先查它的缓存环境变量**，指到非系统盘 |

**原则**：动手前先问"这个工具默认写哪"，而不是装完了才发现 C 盘少了 20G。

---

## 二、目录联接（Junction / Symlink 转移术）

遇到**强制写 C 盘固定路径**的老旧程序：

1. 停掉占用进程；
2. 把已生成数据移到非系统盘；
3. **删除 C 盘原目录（必须已空）**；
4. 管理员执行：
   ```cmd
   mklink /J "C:\原路径" "<非系统盘>\实际路径"
   ```
   `mklink /D` = 符号链接；`mklink /J` = 联接（兼容性更好，**优先用 /J**）。

**效果**：程序以为还在读写 C 盘，实际数据已落非系统盘。

---

## 三、幂等检测（防重复挪动）⚠️ 最容易出错的一步

迁移 / 建链接**之前**，先检测当前状态：

```powershell
dir <目标路径>                          # 看是否有 <JUNCTION> / <SYMLINK> 标记
fsutil reparsepoint query <路径>        # 精确查询是否为重解析点
```

判定与动作：

| 当前状态 | 动作 |
|---|---|
| 已是链接且指向正确的非系统盘 | **立即停止，绝不重复移动 / 建链接** |
| 是实体目录且占空间 | 才执行「移动 + 建链」 |
| 是链接但指向错误位置 | 先删链接（`rmdir`，**不是 `rmdir /s`**），再重建 |

## 四、临时文件即时清理

- 任务产生的临时解压、中间产物，**完成后主动清理**。
- 解压安装包后无需保留立即删；不在桌面遗留大文件。

## 五、空间预警

- 大规模写入（几十 GB 模型 / 数据集）**前**，先查剩余空间：
  ```powershell
  Get-PSDrive -PSProvider FileSystem | Select-Object Name,@{n='FreeGB';e={[math]::Round($_.Free/1GB,1)}},@{n='UsedGB';e={[math]::Round($_.Used/1GB,1)}}
  ```
- 目标盘不足 → **立即停、报告用户**，禁止未确认的跨盘写入。
