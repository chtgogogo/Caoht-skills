# 磁盘与缓存纪律（禁止落 C 盘 · 缓存重定向）

> **定位**：这是**环境层**的纪律，管"东西写哪个盘"。
> 与它并列的三件：`编码行为准则`、`测试纪律`、`抗幻觉纪律`。**四件互不重叠。**

## 0. 核心（每轮必守）

1. 所有**下载 / 克隆 / 虚拟环境 / 模型权重 / 日志 / 解压产物**，默认写**非系统盘**（D 盘、E 盘），**严禁** `C:\Users\<user>\Downloads`、`C:\Users\<user>\.cache` 等默认路径。
2. 在非系统盘建统一目录（本机约定）：
   - 工程：`<非系统盘>\AI_Projects`
   - 缓存：`<非系统盘>\AI_Cache`

---

## 一、缓存与环境重定向

| 工具 | 环境变量 | 说明 |
|---|---|---|
| pip | `PIP_CACHE_DIR` | 或 `pip install --cache-dir <非系统盘>` |
| npm / pnpm | `npm_config_cache` / `PNPM_HOME` | |
| HuggingFace | `HF_HOME` | **下载模型前**先设，否则权重落 C 盘 |
| 其它 | — | 任何"默认往用户目录 `.cache` 写"的工具，**先查它的缓存环境变量**，指到非系统盘 |

**原则**：动手前先问"这个工具默认写哪"，而不是装完了才发现 C 盘少了 20G。

---

## 二、目录联接（Junction / Symlink 转移术）

遇到**强制写 C 盘固定路径**的老旧程序：

1. 停掉占用进程；
2. 把已生成数据移到非系统盘；
3. **删除 C 盘原目录（必须已空）**；
4. 管理员执行：
   ```cmd
   mklink /J "C:\原路径" "<非系统盘>\实际路径"
   ```
   `mklink /D` = 符号链接；`mklink /J` = 联接（兼容性更好，**优先用 /J**）。

**效果**：程序以为还在读写 C 盘，实际数据已落非系统盘。

---

## 三、幂等检测（防重复挪动）⚠️ 最容易出错的一步

迁移 / 建链接**之前**，先检测当前状态：

```powershell
dir <目标路径>                          # 看是否有 <JUNCTION> / <SYMLINK> 标记
fsutil reparsepoint query <路径>        # 精确查询是否为重解析点
```

判定与动作：

| 当前状态 | 动作 |
|---|---|
| 已是链接且指向正确的非系统盘 | **立即停止，绝不重复移动 / 建链接** |
| 是实体目录且占空间 | 才执行「移动 + 建链」 |
| 是链接但指向错误位置 | 先删链接（`rmdir`，**不是 `rmdir /s`**），再重建 |

---

## 四、临时文件即时清理

- 任务产生的临时解压、中间产物，**完成后主动清理**。
- 解压安装包后无需保留立即删；不在桌面遗留大文件。

## 五、空间预警

- 大规模写入（几十 GB 模型 / 数据集）**前**，先查剩余空间：
  ```powershell
  Get-PSDrive -PSProvider FileSystem | Select-Object Name,@{n='FreeGB';e={[math]::Round($_.Free/1GB,1)}},@{n='UsedGB';e={[math]::Round($_.Used/1GB,1)}}
  ```
- 目标盘不足 → **立即停、报告用户**，禁止未确认的跨盘写入。

## 六、体检脚本

```powershell
# 只体检（不动作）
python "<你的技能库>\A-Cao-磁盘缓存纪律-禁止落C盘与缓存重定向\scripts\disk_check.py"

# 附带列出 C 盘可疑大目录（只报告，不删）
python "...\disk_check.py" --scan-user
```

**脚本查四件事**：① 关键环境变量是否已重定向到非系统盘 ② C 盘常见缓存/下载路径是否异常膨胀 ③ 已知路径是否为 junction 且指向非系统盘 ④ 各盘剩余空间是否低于阈值。

## 八、C盘体检瘦身标准流程（2026-10-06 实战沉淀）

> 触发：用户说「C盘满了 / 瘦身 / 体检 / 清理」。心法八字：**先量后删、钻层定性**。落点会随软件更新漂移，判据不变——吸纳思路，不背路径。

**1. 体检漏斗（三层钻取，禁止只扫一层就下结论）**
- L1 广度：四大主战场各扫一轮 `du -sh <根>/* | sort -rh | head -20`（用户根、AppData/Local、AppData/Roaming、ProgramData）
- L2 定位：对可疑大目录钻一层
- L3 定性：钻到「能判断是缓存还是数据」那层为止（实例：飞书 1.5G → aha/users → profile_explorer → Service Worker 1.1G 才实锤是缓存）

**2. 定性判据（看构成，不看名字）**

| 构成特征 | 定性 | 处置 |
|---|---|---|
| Cache / Code Cache / GPUCache / Service Worker / Dawn* / GrShaderCache | 再生缓存 | 删 |
| installer.exe / patch / pending（更新器目录**内**） | 旧更新包 | 删，留目录 |
| Temp / CrashDumps / node-gyp / 陈旧 MessageBus 日志 | 垃圾 | 删 |
| logs/ | 流水账 | 删或建道 |
| IndexedDB / Local Storage / Screenshot / *.sqlite 聊天库 / 下载历史 / AI 索引(projects) / tools/ / NGX 模型 / Package Cache | 用户数据或本体 | **禁删** |

⚠️ 反例实录（2026-10-06）：`Roaming/uv` 名字像 uv 缓存，钻层实为**已装工具本体**——名字像≠是，先定性再动手。

**3. 占用核查前置**：清理前 tasklist 确认程序已关；浏览器分清 `msedge.exe`（本体，可清缓存）与 `msedgewebview2.exe`（被其他软件复用的内核，不代表 Edge 在跑）。

**4. 处置三分类**：A=直接清（上表可删类）；B=建道（持续再生的大缓存/日志→junction 搬非系统盘：幂等检测→关进程→删→mklink /J→跨盘写测试）；C=拍板（用户数据/系统件/拿不准的→列清单+建议交用户，禁擅自删）。

**5. 验证收尾**：df 前后对比；联接写测试；报告落盘**必含勿动清单**（防下次误伤）；记忆/账本留痕。

**6. 常见落点族（举一反三）**：Electron 系=Roaming/<app-id>（logs/Cache）+ Local/<app>-updater（installer.exe 堆积）；Chromium 内核应用=User Data/Default/{Cache 族}；国内聊天/办公软件 patch 目录=补丁包堆积；国内版软件路径常不等于国际版（目录名带 CN 等后缀，用 `find -iname` 实测定位）。
