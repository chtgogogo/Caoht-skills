## v2.5（2026-09-17）
- **做了什么**：第六节调用统计脚本化（`__tools/usage_update.py` 一条命令完成 +1、改日期、降序重排、缺行自动建，手动改降级为兜底）；第七节维护新增「创建/修改 skill 后必跑 `__tools/lint_skill.py` 体检器」（detail-003 五步法第五步）。
- **解决了什么**：调用统计靠手动改表、易漏易错；新建/修改 skill 后没有强制的质量体检门。
- **怎么解决的**：脚本一条龙 + 体检器挂进维护流程。work-79（2026-09-18）记录：usage_update → 第六节、lint_skill → 第七节 v2.5 两钩子已挂进正文，「useskill v2.5 已双份同步」。

## v2.4（2026-09-11）
- **做了什么**：新增 **State 2-EX 穷举模式**——用户说「全面调用 / 全面使用 / 尽可能用 useskill」等穷举授权语时，读映射表全表做全库相关性筛选（映射表失效才真扫目录），相关的全挑出来、宁多勿少、分阶段使用、候选清单进调度报告；触发清单同步增加穷举授权语。
- **解决了什么**：普通检索只挑少数命中，用户明确要求「全面」时覆盖不足。
- **怎么解决的**：把映射表当全库目录的索引视图（一次 IO 等于浏览整个目录），穷举授权即启用宽口径筛选并全程透明可见。

## v2.3（2026-09-11）
- **做了什么**：新增 **State 0 引用清点**——一条消息可含多个 skill 指称（显式路径 / 点名 name / 泛指能力词），逐一清点归宿；State 1 命中只消费一个显式引用（快路径惯性防御）；State 2 明确泛指词按映射表**中文文件夹名前缀**优先匹配；调度报告新增「引用清点」行。
- **解决了什么**：v2.2 生产事故（2026-09-11，前端风格任务）：点名直连后把泛指词『按前端设计skill的理念』等同于已点名 skill，导致库内三个前端 skill 漏触发，被用户质问。
- **怎么解决的**：强制每次调度先做引用清点、逐一标注归宿，禁止因快路径命中而跳过剩余泛指引用的解析；出现「漏检」即违规。
