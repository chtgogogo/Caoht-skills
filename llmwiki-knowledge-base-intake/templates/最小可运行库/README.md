# 最小可运行库（空白示例知识库）

这是一个**完整能跑**的示例知识库，不是要你填空的骨架：里面的卡片、导读、版本台账、CHANGELOG
都是真形状，配套的 `scripts/kb_intake.py` 直接就能在它上面跑通「诊断 → 判类型 → 成组入库 → 中断恢复 → 回滚」。

## 为什么要有它

公开包的读者没有本机的知识库，也没有本机那两个外部工具。没有可跑的例子，「入库流程」就只能靠读文字想象，
第一次上手必然写坏字段行或漏登记。有了它：**先在这儿练，跑绿了再往自己的库上搬。**

## 目录形状（每一项都被 `intake_config.json` 指着，改名要同步改配置）

| 路径 | 作用 | 少了会怎样 |
|---|---|---|
| `intake_config.json` | 唯一配置：路径、必填字段、版本分配、项目类型规则 | 脚本退 2 拒绝开工（不猜） |
| `0-入口/AI导读.md` | 总索引表 ＋ 组清单节 | 新卡无处登记 ⇒ 复核判孤儿卡 |
| `0-入口/首页.md` | 面包屑指向的首页 | 卡片双链成死链 ⇒ 判红退 1（诊断报告照常打印并点名哪张卡） |
| `0-入口/模板/资产卡模板.md` | 写卡的形状参照 | 只报黄（缺形状参照，不拦施工） |
| `1-资产卡/` | 卡片存放目录 | 必需路径缺失 ⇒ 判红 |
| `3-本机资产/AI工具地图.md` | 「装在哪、能干嘛」的行表 | 只报黄 |
| `3-本机资产/项目档案.md` | 自有工程的行表 | 缺文件只报黄；配置 `landing_by_type` 声明了 `user_project` 的落点键却没给路径 ⇒ 判红 |
| `CHANGELOG.md` | 时间倒序版本史 | 必需路径缺失 ⇒ 判红 |
| `6-outputs/version_ledger.md` | 版本号唯一写入点 | apply 拒绝入库 ⇒ 先跑 seed-ledger |
| `6-outputs/usage.log` | 用卡留痕流水 | 只报黄（手工补一行即可） |
| `AGENTS.md` | 库自己的规矩 | 只报黄 |

## 上手三条命令

```
py <技能目录>/scripts/kb_intake.py diagnose --vault <本目录>
py <技能目录>/scripts/kb_intake.py apply --vault <本目录> --plan <你的plan.json> --dry-run
py <技能目录>/scripts/kb_intake.py selftest
```

`selftest` 会把本目录复制成若干份合成夹具，在上面跑完全部断言——**本目录自己一个字节都不会变**，
你可以边读边跑。想留着夹具看现场：`selftest --tmp <空目录> --keep`。

## 搬去自己的库要改什么

1. 改 `intake_config.json` 的 `paths`（目录名不一样就指过来）。
2. 往 `project_type_rules` 里逐条写清「什么算工具、什么算自有工程」——脚本不跑 git，判不了就由你定。
3. 删掉 `1-资产卡/示例组-示例资产.md` 时，同步删导读总索引那一行与组清单里的 `` `示例组` ``，否则报孤儿卡／幽灵组。
