# 知识库入库流水线

## Overview

把「用户指着一个软件/仓库/资料说『这个也得记进 obs』」变成一条可复现管线：认库 → 读规矩 → 判类型 → 写卡 → 登记 → 追加版本节 → 收尾三连。

三个层次分清楚，别混：

| 层 | 在哪 | 谁改 |
|---|---|---|
| 通用流程（本文） | `SKILL.md` ＋ `scripts/kb_intake.py` ＋ `templates/最小可运行库/` ＋ `references/必需文件与工具清单.md` | 随技能包发布，不含任何本机路径 |
| 个人库适配 | `personal.local.md`（若存在） | 各家自己写：库根、封存库、外部工具参数、成组日志位置、自己的类型规则 |
| 库内规矩 | `<库根>/AGENTS.md`、`0-入口/AI导读.md`、`0-入口/模板/资产卡模板.md` | **唯一真源**；与本文冲突以库内为准，并当场报告差异 |

引用适配层的固定句式：**若技能目录存在 `personal.local.md` 则读取它并按其中的路径与参数执行；不存在则按本文的通用流程走**（通用流程不依赖任何特定目录，见 §8）。

## 0. 先认库（写错库＝白干）

- 活跃库＝唯一入库目标；同名旧副本一律视为只读冷备，要内容就捞出来按现库规范重录，绝不回冷备写。
- 哪个是活跃库、哪个已封存：**现查**（看是否仍有提交与版本节活动），别只信本文或适配层里写着的日期。
- 库根必须显式给（`--vault <库根>`）。脚本不拿当前目录当库根——在错目录里量到空集照样打「全绿」，是最坏的一种假通过。
- 行为记忆（怎么干活／踩坑／偏好）**不进本库**，进各 agent 的记忆 store；分工红线现查库内 `AGENTS.md`。

## 1. 进库必读三份（≤2000 token 预算）

1. `AGENTS.md` — 调度法、分工红线、五不收、格式约定、留痕规范、数据安全
2. `0-入口/AI导读.md` — 触发词组路由表（「触发词组」＝按“干什么活”给卡片分组的组）＋底部「触发词组清单」节
3. `0-入口/模板/资产卡模板.md` — 卡片形状

**三步调度法（库定的硬规则）**：查表找组 → 命中组内**至少读 2 张卡**再动手（同型去偏）→ 没命中才按五不收补卡。单次检索超 2000 token 就强制停，并向用户说明「可能有遗漏」。

组清单会增会变，一律现查，别抄快照。**要改哪一行，就先读那一行的当前原文**——锚点凭记忆抄是本流程最高频的失效模式（§5、§6 全部建立在「先读现状」上）。

## 2. 分流：五不收 ＋ 类型由配置判

**五不收门槛**（逐条对上才收）：与 AI 协作无关不收 ／ 来源核实不了不收 ／ NC 协议不商用（NC＝非商业许可：个人学习可下载收藏，卡片如实标注并写明「仅个人学习，禁商用禁入对外交付工程」）／ 只存长文不配卡不收 ／ 重复不收。

**落点由「项目类型」决定，类型由明确配置决定，不靠猜**：

```
<库根>/intake_config.json → project_type_rules: [{name|prefix|url_prefix, type}, ...] 按顺序匹配
```

| 类型 | 落点 | 例子 |
|---|---|---|
| `tool`（工具／软件／外部仓库） | 地图行 或 `1-资产卡/<组名>-<对象名>.md` | Godot、Krita、ffmpeg、blender-mcp |
| `user_project`（用户自有工程） | `3-本机资产/项目档案.md`（库里配置的落点键） | 用户自己写的工程 |
| `unknown` | **拒绝并停手**（退出码 2）⇒ 问用户，再往配置补一条规则 | 新遇到的东西 |

🔴 **禁止用「有没有 upstream / 有没有提交」判类型**：有 origin 的自有工程会被判成工具，无 git 的纯在线资料会被判成自有工程——形状对、语义错。判据只从配置读，脚本一个 git 都不跑（`selftest` 里有一条断言逐字盯着「源码里不许出现调外部命令的三种形状」）。

缓存重定向目录一类（npm-cache／gocache／pip-cache）只加地图行，不配卡。新卡命名照既成惯例：`组名-对象名.md`。

## 3. 写卡：硬格式（缺一项就吃体检红项）

**frontmatter 六字段行必须在场**（这是体检的实际口径，不是「五必填」）：

```yaml
---
type: asset-card
group: <触发词组名>
source: <上游仓库／官方地址>
local: <本地路径；纯在线卡写"仅在线"或留空值>
license: <许可证>
status: active
superseded_by:
last_checked: <YYYY-MM-DD>
tags: [资产卡, <触发词组名>]
---
```

- 🔴 `local` **允许留空值，但字段行不能少**：体检查六行齐全（group／source／local／license／last_checked／status），除 local 外五项还必须有值——**「有字段行但值是空的」同样判红**，只查行在不在等于没查。少写一行直接红。
- `tags` 第一个＝类型，第二个＝触发词组名。
- `last_checked` 必须是 `YYYY-MM-DD`，否则报「无法解析」红项；超 90 天未核对报过期。

**正文首行面包屑**（页面顶部的返回导航行，体检逐页扫）：

`> 🏠 [[首页]] ｜ 📖 [[AI导读]] ｜ 📁 1-资产卡`

**双链** `[[文件名]]` 只能指向真实存在的文件（体检按全库 md 判死链）。拿不准就用只读方式核对目标文件存在，别靠反复跑体检来试错（副作用见 §9 第 2 步：报告会重写，那文件被 git 跟踪）。

**事实必须实测，禁止按常识填**：上游地址取 `git remote -v`，许可证取 `LICENSE` 原文首行；查不到就写「未核实」。曾有两次按常识推断差点写错（Godot 目录内无 LICENSE 文件、yt-dlp 打包版只附第三方依赖的许可证），ffmpeg 由「GPL」实测纠正为 GPL-3.0。许可证的商用边界要引条款原文写清（例 FSL-1.1-MIT 的红线是「做成竞争性商业产品或服务」，自用／教学／科研／服务均可）。

**用法段要能照做**：命令、安装方式、产物、参数默认值取自 README 实测行，并单列「静默失败坑」——那种不报错却不生效的边界最值钱。

## 4. 登记：AI 导读两处同步（最容易漏的一步）

新卡必须在 `0-入口/AI导读.md` 落地，否则体检报「孤儿卡」：

1. **总索引表**：找到目标组那一行，把新卡并列进「目标」列（用 ＋ 连接），并在「说明」列写清各张卡的口径差异。同组并列展示，不覆盖旧条目。
2. **触发词列**：按新卡内容补触发词（例：新增「代码认知／仓库索引／AI记忆层」）。
3. **建了新组才动这条**：新组名必须同时进总索引表和底部「触发词组清单」节——只写一处报「导读组清单不同步」。

用卡时发现内容过期 → **当场修** ＋ 刷 `last_checked` ＋ 提交，不许「知道错了先记着」。

## 5. 版本号：单一写入点认领（不读 git、不扫工作区）

版本史 `CHANGELOG.md` 按**时间倒序**排：新节插在**当前最上方那个 `## v` 节之前**（锚点取自现状；写死某一行会让第二次入库插到第一次下面，倒序当场被打乱）。写法 `## v<X.Y.Z>（YYYY-MM-DD）<一句话主题>`，正文三小节：**优化了什么／新增了什么／解决了什么问题**。

🔴 **号位只从版本台账 `6-outputs/version_ledger.md` 认领**，一条追加式（append-only＝只往后加行、不改写历史）表格：

```
| 版本 | 时间 | 宿主 | 主题 | 状态 |     状态 ∈ claimed（已占号）/ released（已发布）/ seeded（老库迁移播种）
```

认领过程＝**锁内**（`O_CREAT|O_EXCL` 独占建锁文件）重算最大号 → 进位 → 追加一行 `claimed` → 读回确认。于是：

- 别人的节改在文件里还没提交 ⇒ 劫持不了号位（旧口径「HEAD ＋工作树都扫一遍」会当场跳几十个大版本）。
- 两个窗口同时入库 ⇒ 第二家拿不到同一个号（撞号退 4，一个字节都不写）。
- 老库首次接入先 `seed-ledger` 从现有最大号播种一行，之后只往上进位。

体检会黄报「版本史最大号高于台账」⇒ 台账漏记，补跑 `seed-ledger`，别手改号位。

## 6. 成组更新与中断恢复（一次入库＝一处都不能少）

卡片、导读行、版本节、台账行是**一组**：任一步失败留下半成品，下一任 agent 读到的是互相矛盾的现状。所以走「写前日志（journal＝先把要做的每一步记在磁盘上，再动真文件）→ 逐步原子替换（tmp 写完再整文件改名，不给半截内容）→ 每步写后读回 → 成组一致性复核」，而不是手工连改三处。

```
py scripts/kb_intake.py apply     --vault <库根> --plan <plan.json> --host <宿主名>
py scripts/kb_intake.py status    --vault <库根>            # 谁停在第几步
py scripts/kb_intake.py resume    --vault <库根>            # 幂等续跑（已做的步不重做）
py scripts/kb_intake.py rollback  --vault <库根> --journal <版本号>   # 只认日志登记的备份，按原字节还原
```

要点：

- plan 里的锚点必须**现读**（`--plan` 指向的 JSON 由你根据当前文件内容生成，不是模板照抄）。
- **幂等**（同一件事跑两遍结果不翻倍）靠整行标记识别：目标行已在就跳过并如实报 `skipped_exists`，重跑不许多插一行。
- 不一致时**不回滚**：文件留着，日志状态记 `inconsistent`，退出码 3 ⇒ 先 `resume` 补齐或 `rollback` 还原，**期间禁止提交**。
- 中断（进程被砍、断电）留下的残留锁：超过陈旧线（默认 120 秒）判定写者已死，接管继续；没超线退 4 等它。
- 换行形状保护：全程二进制读、按原文件行尾写回；混进 `\r\r\n` 直接拒写。
- 成组日志目录可以指到库外（`--journal-dir`）；指在库内时确认它被 `.gitignore` 盖住，否则库体检会报「git 有未提交内容」。

退出码：0 成功／1 某步未过或有红项／2 用法与配置错／3 成组不一致（要 resume 或 rollback）／4 锁被活的写者占用或号位撞车。

## 7. 检查流程：三种模式，读写边界写明

```
diagnose                默认＝只读环境诊断，一个字节都不写（跑完逐文件对账必须一字不差）
diagnose --report P     显式出报告＝只写 P 这一个文件
diagnose --fix          显式修复＝只建「声明可建」的骨架文件（版本台账＋留痕流水），
                        绝不改卡片／导读／版本史正文——改正文＝替人做内容决定
apply / resume / rollback   唯一写库内正文的入口，全部走 §6 的成组机制
```

🔴 「读的时候顺手改」是旧版最危险的习惯：查一下现状就把报告重写一遍、把卡片顺手修一下，还会把别人的在途改动一起提交。**默认模式必须零写入**；要写就显式点名哪一个文件。有红项时 `--fix` 照样退 1，不把红盖成绿。

## 8. 缺外部工具时的纯手工降级

留痕器（记「这次用了哪几张卡、什么场景」）与体检器（查断链／孤儿卡／格式）属于**可选外挂**：没有它们本流程照样跑。配置里 `tool_paths` 留空即走降级：

- 留痕＝人工在 `6-outputs/usage.log` 追加一行（宿主名自己写清，别家的功劳别记到自己名下）；
- 体检＝按 `references/必需文件与工具清单.md` 的判据口径逐条手工核对（行在／值在／日期／面包屑／双链／孤儿卡／组清单双向／同号两次／台账⇄版本史漂移／分母闸／留痕流水与落点档位＝缺流水报黄、声明了落点键没给路径报红）；
- 脚本对「必需文件缺失」退 2 并点名缺哪一个，**不自己造文件凑数**。

要接现成工具就把命令与参数写进 `personal.local.md`（含「哪个参数有默认值、漏传会静默记到别人名下」这类坑）。

## 9. 收尾三连（顺序不能换）

1. **留痕**：工具或纯手工都行，但宿主名必须显式、`--scene` 里必须写「同组只用其一」的选择理由（月度体检抽查）。浏览未用不计，只记实质引用／查证／参照。
2. **体检**：一轮跑一次就够。报告文件是被 git 跟踪的机器产物 ⇒ 跑完连着一起提交，否则下一轮又报「git 有未提交内容」。
3. **提交**：先 `git status --short` 看清在途，再**只按路径** `git add`（禁 `git add -A`／`.`，别人的在途改动不代提交），commit 信息照既有风格写版本号＋改动面。
4. **push 先问用户**：共用门面仓库，没明确指令不推。

## 10. 多人共写防线（本库最高频的毁数据方式）

- 开工第一件事：`git status --short`，把别人在途的文件记下来，收尾时**不碰它们的行**。
- 改完对账分两类判据，别一刀切要求「删除行为 0」：
  - **纯追加类**（版本节、地图行、清单节）：`git diff --numstat` 删除列必须为 0。
  - **就地改行类**（导读表某组行扩写）：删除列＝预期改行数（改 1 行就是 1/1），并逐条确认邻居组行原样还在。
- 🔴 **Git Bash 里中文关键词传给 grep 会静默零命中**（实测：六个中文词全报「没有」、退出码 0 无报错，同一棵树 Python 全库扫却数出了命中）。核对中文行是否存在，要么用 Read 直接读回，要么 Write 成 `.py` 再跑；非用 shell 不可时先塞一个**已知存在**的中文词做正例校验，正例没中就判这把尺子作废。
- 🔴 **本机跑 Python 只用 `py`**，禁用 `python`／`python3`——两者可能是商店占位 stub，零输出＋退出码 49，接上管道后退出码被吃掉＝静默假成功。
- 🔴 **别把 Windows 反斜杠路径写进内联脚本**（`py -c`／heredoc 里 `\t` 会吞字符、`\202` 被当八进制）。路径落成 `.py` 文件再跑，或用正斜杠／`chr(92)`。
- 🔴 **原地改写文件与丢弃报错绝不同条**：禁裸 `sed -i` 叠 `2>/dev/null`；对不可再生的原始输出（命令回显、真调记录）二次写入前先复制，改完数行数对账。
- 🔴 **改完本体只算改了一半**：新卡建完后派生物四类逐类核对——导读总索引行、组清单行、版本史节、自己那页宿主地图状态，缺一类就漏一类。
- `4-AI宿主地图/<你的宿主>.md`：**谁的地盘谁更新自己那页**（含自查日期与收尾链真实状态）。进库发现自己页缺失或未登记→当场补。

## 11. 与上层体系规矩的接缝（避免三条规则各跑一套）

若你所在体系另有「资产登记回写」「外部智慧入库」类铁律（个人版的具体条款坐标见 `personal.local.md`）：

- **写盘入口只有一个**：本 skill 的成组更新（§6）。上层铁律要登记，就挂在收尾步里一次，不另开一条写库通道。
- **入库分流先判类型**（§2）：资料型进资产卡；检索到的经验／精华走 §12 那个独立组，字段口径不同，别混进 1-资产卡；行为经验／踩坑进记忆 store，不进本库。
- 两边冲突时以库内 `AGENTS.md` 为准并报告差异。

## 12. 另一类入库：外部智慧组（联网检索到的精华）

沉淀「AI 联网检索到的优秀设计／权威资料／行业数字」走这个组，**不收进 1-资产卡、字段口径也不同**：建卡四件套＝① frontmatter `title／来源URL／检索日期／last_check／复核条件／deps` ② 正文大白话一句话＋要点＋适用场景＋**反例边界**（何时不适用，防误用）③ AI导读加行 ④ 来源核实且 NC 如实标注；并按快／中／慢三档复核节奏定档。细则现查该组目录的 `README.md`。

权威原文进「工具书」目录另加三验：来源验（只收官方域名，记确切 URL）、完整验（大小与官方发布一致）、许可验（NC 不收），三验记录写进该子目录 README。

## 13. 硬红线（任何时候）

- 密钥／密码／token 绝不写入本库任何文件。
- 归档目录永不删；冷卡（90 天零命中＋未核对，双条件）只能列候选，**降权归档必须用户确认**，热度数据绝不自动删东西。
- 外部仓库克隆区不进 git。
- 与记忆库分工：本库只存资料与资产；行为经验／踩坑／偏好进各 agent 的记忆 store，别混。

## 快速自检清单（收尾前逐条打勾）

1. 写的是活跃库而不是封存冷备？库根显式给了？
2. 过了五不收，类型由配置判出（判不出就停手问用户），落点对？
3. 六字段行齐**且值也非空**（local 除外）、`last_checked` 是 `YYYY-MM-DD`、面包屑首行在、双链目标实存？
4. 许可证与上游是实测值，查不到的写了「未核实」？
5. 号位是从版本台账认领的（不是读 HEAD／扫工作区算的）？台账没被同号占两次？
6. 版本史新节插在**当前最上方**版本节之前，邻居节未动，插完仍是顶部倒序？
7. 卡片／导读／版本史／台账四者一致？中断过就跑过 `status`＋`resume`（或 `rollback`），没有留半成品就提交？
8. 检查用默认只读模式，没在读取时顺手改文件？
9. 缺外部工具时按 §8 降级补齐了，没有拿「工具不在」当没做的借口？
10. 留痕带上宿主名与同组取舍理由；体检结论绿，或黄项已如实说明？
11. 只 `git add` 自有路径、未提交他人改动、未擅自 push？

## 随包资产（计数一律现查，别抄本文）

- `scripts/kb_intake.py`——本流程的执行器：`diagnose / classify / seed-ledger / apply / resume / status / rollback / selftest`。只用标准库，一个外部命令都不调。
- `selftest`——全是合成夹具（造一个空白库的副本，在里面试图入库、故意中断、再恢复），**不碰任何真库**。条数现跑现看：`py scripts/kb_intake.py selftest --keep`。
- `templates/最小可运行库/`——空白示例知识库：配置＋导读＋首页＋卡片模板＋一张示例卡＋版本史＋规矩文件＋地图＋项目档案＋版本台账＋留痕流水＋README（件数现查 `ls`，别抄本文）。别人照它跑通首次入库，再按自己情况改。
- `references/必需文件与工具清单.md`——必需／可容忍缺失／可选外挂三档，加判据口径表与退出码表。
- `personal.local.md`——个人库适配层（**发布同步会排除 `*.local.md`，本机路径只活在这一份里**）。
