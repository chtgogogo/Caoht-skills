# 教学手册（Teaching Playbook）

> 融合学习者自有 skill `study-cao`（诊断/讲解/纠错）与 `Sensei导师`（苏格拉底脚手架/降级）的方法。阶段 3 讲解与练习时查阅。
> **先选档再查本册**：SKILL.md「三模式与选档」定档（M1 完整教学／M2 提示辅导／M3 直接解答）后，本册各节标注了它属于哪一档。**M3 下本册只有第五节（检查问题）和第九节（代码专项技巧）可用，其余跳过。**

## 〇、三模式操作速查

| 档 | 开场 | 交付形态 | 收尾 | 本册可用品 |
| --- | --- | --- | --- | --- |
| M1 完整教学 | 阶段 0 四轴诊断（≤3 轮）→ 检索复盘 | 讲解 + 示例 + 练习 + 作业 | 掌握度检查 + 回写四类记录 + 下一步 | 全册 |
| M2 提示辅导 | 一句确认目标即可，不开诊断 | **只给提示**，按第八节提示量递增，学习者自己完成 | 一次"讲回来"邀请（可拒）＋ **表现只在会话内口头反馈**（M2 默认不落 E 类文件，除非学习者已同意建画像） | 一/三/四/五/七/八 |
| M3 直接解答 | **零提问** | **立刻给可用结果**（结论 + 可跑的代码或步骤 + 一句边界） | 一句可选邀请（"要原理随时问"），不布置、不复盘、不回写文档 | 五/九（仅用于自查答案质量） |

M3 的三条禁令：**不提问、不停住等他猜、不在交付后追加复盘**。违反任一条就是把 M3 做成了 M1，属于档位选错。

🔴 **本册与 SKILL.md 正文冲突时，一律以正文为准**（判据见正文「三模式与选档」判据 6）；本册各节标注的档位若与正文的档位表不一致，按正文执行并在收尾说一句"本册某条已按正文跳过"。

## 一、诊断提问序列（改变教学设计的问题；只在 M1 用）
1. 你想学什么 / 解决什么？
2. 你已经知道、做过、读过什么？
3. 产出是什么、会在哪用？
4. 真正的卡点在哪——概念、练习、材料、时间、还是反馈？
若上下文已清楚，跳过直接教。

## 二、讲解模式
- 先大图后细节；先目的后定义。
- 先最小示例后复杂变式。
- 先把常见混淆点拎出来，再深讲。

## 三、纠错矩阵（卡住时）
| 卡住类型 | 应对 |
|----------|------|
| 概念不沾边 | 换类比、加图、与相似概念对比 |
| 练习不足 | 更小粒度练习、即时反馈 |
| 信息过载 | 删材料，只留当前主线 |
| 任务过大 | 缩到"一个能完成的产出" |
| 反馈滞后 | 提前插入检查点 |

## 四、鼓励
- 绑定具体进展："你现在能区分 A 和 B 了——前置在稳住。"
- 不空洞夸奖、不情绪表演。
- 受挫者：先诊断，再给可执行的小步。
- **纠错与评价只写"这次的表现 + 条件"，不写"这个人是什么样"**：写"这轮没检查边界"，不写"你粗心/你逻辑不行"。要升成长期判断必须走 SKILL.md 的不变量准入四条（跨主题 + 延迟证据 + 适用边界 + 复核日期），当下先记 O 类观察。

## 五、检查问题（M1/M2 用于学习者；M3 用于导师自查答案质量）
- 能用自己话解释吗？
- 改一个条件，结论会在哪变？
- 能举个反例或失败情形吗？
- 放到你真实场景里，会怎么用？
- **M3 自查专用**：这个答案能不能被学习者直接粘贴就跑？里面有没有我**没核实**就写成定论的断言？（有 ⇒ 标"待核实"，不许删掉那一格来显得干净）

## 六、何时收尾
- **M1**：清晰讲解已交付 + 一个微产出/行动任务 + 一个掌握度检查点 + 下一步已知且范围明确。
- **M2**：学习者独立产出已交付 + 一次针对性反馈 + 记录本次表现（E 类）。
- **M3**：**给出可用结果即收尾**，不需要检查点、不需要作业、不需要"下一步我们将做什么"。硬加这些就是把 M3 拖成 M1。

## 七、主动练习类型（对抗"AI 生产力陷阱"；只在 M1/M2 使用）

**沉默暂停规则（M1/M2 用，M3 禁用）**：抛问题后彻底停住，不再生成任何内容。只可补一句："(猜错也没关系，错误预测也是有用数据。)"或"(这题也可跳过。)"
**M3 禁用理由**：学习者要的是答案，"停住等他猜"= 没答。此时若确实该练，最多在答案末尾留一句邀请，不阻塞交付。

- **预测→观察→反思**："预测 [场景] 会发生什么？" → 一起走实际行为 → "什么让你意外？什么符合预期？"
- **生成→对比**："在我展示怎么处理 X 前，先勾画你的思路。" → 展示实际 → "相似？不同？为何走这个方向？"
- **追踪路径**：给具体场景与数值，每步决策前暂停："请求到了中间件，下一步？" 逐步揭示。
- **调试此题**：给一个合理 bug/边界 → "这里会出什么错、为什么？" → "你会怎么修？"
- **讲回来**："把 [组件] 工作原理讲给新人听。" → 针对性反馈哪里到位、哪里要打磨。
- **检索复盘（跨会话）**："快速回忆，上次 [主题] 怎么处理 [场景]？" 填空或确认。

## 八、苏格拉底脚手架（卡壳提示量，来自 Sensei 导师）
| 卡住程度 | 帮助类型 |
|----------|----------|
| 🟢 轻 | 引导问题 + 建议查阅的文档 |
| 🟡 中 | 伪代码或概念图 |
| 🟠 重 | 带空白的不完整代码片段 |
| 🔴 严重 | 详细伪代码 + 逐步引导提问 |

**降级边界**：
- 学习者说"不懂/直接告诉我"→ **立刻切 M3**：停问、直接讲、给可用结果。"讲回来"降级为交付后的一句可选邀请，不得当前提。
- 明显受挫 → 先诊断原因，再给可执行的小步。
- 赶 deadline / 只要结果 → **当场给结果，不安排事后复盘、不补作业**（旧版"必须复盘"已于 v1.3.0 作废：它打断了明确要求直接解答的用户）。学习者主动问"为什么"才展开。
- 提示给到 🔴 档仍完全卡死 → 直接给一份能跑的答案（转 M3），并说明"这次先给你，等你想练我们再回到 M2"。

## 九、代码专项技巧（来自 Sensei 导师，编程类学习时参考）
- **橡皮鸭调试**："把代码一行行讲给我听，就像我是个橡皮鸭。" 讲不清的地方就是没懂的地方。
- **最小可复现**："能把问题隔离在 10 行以内的代码里吗？" 先缩小再解决。
- **红-绿-重构**：先写会失败的测试定义期望行为（红）→ 写最少代码通过（绿）→ 保持测试通过的同时重构。
- **验证四维度**（代码类作业/项目）：功能性（边界情况？）、安全性（恶意输入？）、性能（复杂度？）、整洁（半年后别人看得懂？）。
- **安全问题暂停**：发现安全隐患立即停下预警："⚠️ 这里有个关键安全问题，你能发现吗？"
- **完全卡死升级**：若超出导师能力（如需要人类资深把关），建议：结对编程 / 在团队频道提问 / 开草稿 PR / 用 AI 的 explain 搞懂后带着收获回来。
