# Engramory 记忆分层架构

记忆分三层，职责严格分离。

## 0. 目录结构与指针模型（设计好的布局）

```
<root>/                         # ENGRAMORY_ROOT（默认 ~/.engramory/）
  MEMORY.md                     # 索引：只存指针，绝不存正文；每轮唯一必读文件
  memory/                       # 详情文件，按类型分目录
    feedback/                   #   - 反馈类（含 Why / How to apply）
    project/                    #   - 项目类
    user/                       #   - 用户画像 / 偏好
    reference/                  #   - 参考资料索引
  archive/                      # 已 Consolidated / 冷记忆（移出热路径，仍可被检索）
  ledger.md                     # 多 agent 同步账本（可选）
```

**指针模型（省 token 的根本）**：
- `MEMORY.md` 是**纯索引**，每行只是指向详情文件的指针，绝不内联正文。它每轮必读，成本恒定（≤200 行 / 25KB）。
- `memory/<type>/<slug>.md` 是**详情**，懒加载——只有被当前任务命中时才 `Read`。
- 因此每轮上下文开销 ≈ "1 次小索引读 + 少数命中详情读"，而不是"N 个详情全读"。
- `archive/` 承接被整理出去的冷记忆，仍在磁盘上可被 `engramory_recall.py` 检索，只是不再占用热索引行数。

**索引行格式（单一真相源）**：
```
- [中文标题](memory/feedback/slug.md) · feedback · 2026-07-30 — 一句话 hook
```
脚本（`engramory_recall.py` / `engramory_organize.py` / `engramory_doctor.py`）与 AI 都解析这行、按相对路径定位详情文件；目录如何再组织都不影响定位。

## 1. 全局记忆 store（跨一切）
- 路径：见 discipline.md 的 `ENGRAMORY_ROOT`（默认 `~/.engramory/`）。
- 范围：跨越所有对话、会话、项目都可读写。
- 内容：统一规范、全局性的坑与教训、跨项目通用工作纪律。
- 生命周期：长期存活，不随某个项目结束而废弃。

## 2. 项目记忆 store（单项目）
- 路径：各工程根目录下的 `.engramory-<项目名>/`。
- 范围：仅记录只适用于该项目的东西。
- 生命周期：
  - 项目进行中正常使用；
  - 项目结束前做"提炼→全局、其余丢弃"收尾，避免项目专属内容泄漏到无关项目、保持项目 store 不腌臜。
- 新工程：每开新工程新建一个 `.engramory-<新工程名>/`；写 `.gitignore` 排除，避免本机细节入库。

## 3. 多 Agent 共享记忆（可选，进阶）
本 skill 的核心价值之一：让**多个 AI agent（读了本 skill 后）检索到并共同读写同一份记忆**，而不只是单个助手自用。

### 协议（通用，不绑定特定产品）
- **共享 store**：用一个所有参与 agent 都能访问的路径作共享记忆根（环境变量 `ENGRAMORY_SHARED_ROOT`；未设则复用 `ENGRAMORY_ROOT`）。各 agent 把"要共享的记忆"放这里。
- **单一事实源**：共享 store 内的 `MEMORY.md` 是索引唯一真相源；所有 agent 每轮任务开始都读它 → 检索天然跨 agent 生效。
- **写入不冲突**：各 agent 按 §3 的"一条记忆一个文件 + 加索引指针"规则追加/更新；为审计与回退，维护一个 `ledger.md`，每次变更追加一行（时间 / 修改方 / 改了什么）。
- **推荐默认范围：仅共享全局 store**。项目记忆除非用户明确指定，否则不跨 agent 共享（保持各自独立）。范围可按用户需求放宽到"全局+某项目"或"全部"。
- **冲突处理（必须遵循）**：
  - 重叠（同一 slug / 同主题笔记）：合并为一份，去除重复。
  - 矛盾（内容相互冲突）：**必须询问用户**如何处置（融合 / 删除 / 修正 / 其他），绝不可自行决定、静默覆盖或静默删除。
  - 非共享范围：各自独立 store，不互通、不合并。
- **项目记忆默认不跨 agent 共享**，除非用户明确指定；共享项目记忆时同样走 ledger 审计。

### 实现提示
- 原始作者用 `D:\_ai_memory_sync\global-behavior-rules.md` 作全局行为准则单一事实源、`ledger.md` 作同步账本（仅参考，不要硬编码路径进通用 skill）。
- 共享 store 应放在不会被某 agent 的 `.gitignore` 误删、也不进云同步的位置。

## How to apply
- 写记忆前先判层级：跨项目通用 → 全局 store；仅本项目 → 项目 store；跨 Agent 共享准则 → 走第 3 层同步协议。
- 绝不把项目专属内容写进全局 store（会泄漏到无关项目）；也别把跨项目铁律只锁在某个项目 store。
- 发现项目 store 内容可泛化时，主动提炼到全局，但避免在项目已有文档（如 AGENTS.md）中重复抄写。
