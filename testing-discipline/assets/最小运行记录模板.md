# 最小运行记录模板（七字段，一次执行一份）

> **用法**：复制本文件 → 改名 `run_<YYYYMMDD>_<任务短名>_<before|after>.md` → 逐格填写 → 与原始输出放同一目录。
> **填不满的格写「未记录＋为什么」**，不许留空，也不许估一个数填进去（留空分不清"没测"和"忘了写"）。
> **改前、改后各一份**，不要合并成"一份记录两次数"。
> 判据来源：`SKILL.md` 第一节铁律 6；合格标准见第十一、十二节。

## 1. 代码版本

```
提交号（40 位）：
工作区状态：  ☐ clean ☐ dirty（dirty 时列出未提交文件）
无版本库时的替代：被测文件 sha256 前 12 位 =
```

- 取法：`git rev-parse HEAD`、`git status --porcelain`（有输出＝dirty）。
- 为什么：只说"改后"不说"哪个改后"，别人回不到同一状态。

## 2. 命令

```bash
# 逐字粘贴你真正跑通的那一条，含解释器、参数、被跑对象、重定向目标

```

- 🔴 写**实际跑的**那条，不写"理想中的"那条：`python`／`py`／`python3` 在同一台机器上可能是不同版本、装不同依赖集。
- 为什么：换参数＝换测试。"我跑了 pytest"不等于跑的是同一批用例。

## 4. 退出码

```

```

- 🔴 接了管道（`| head`、`| tee`）时要在管道之外另取一次（例：`cmd > out.txt 2>&1; echo EXIT=$?`），否则报出来的 0 可能不是被测命令的 0＝静默假成功。

- 随机性明显的指标（LLM 输出／并发计时／抽样评测／掷骰生成）另填：`n=___，r=___，波动范围=___`；**两次数字之差落在波动范围内 ⇒ 只能写「未见稳定差异」**。

## 9. 基线不可用（仅在取不到改前那一份时填）

```
原因（缺什么、为什么补不回来）：
结论因此降级为：  ☐ 现状快照  ☐ 方向性观察  ☐ 未测
什么条件下能补上对照：
```

- 🔴 这一节空着不代表"没问题"，代表"没遇到"；真取不到就必须写，**绝不允许补写一份没跑过的改前输出**。
