# 验收模板 · 测试证据完整性

> **本文件是验收模板**：新项目把它复制到 `<项目根>/ACCEPTANCE.md`（整份或只取本节）后逐项填写。适合在项目收尾、或任何要对外声称「修好了 / 更快了 / 更准了 / 跑过了」的时刻运行。
> **版本锚定**：派生自 A-Cao-测试纪律-测试证据形态规范 v1.2（2026-10-18）。复制到项目后**锁定当前版本**——skill 后续升级不追溯已归档项目。验收标准是交付时的契约，中途换标准等于移动球门。**已按 v1.0／v1.1 归档的项目不必回改**：六条铁律在两版之间一条没动，v1.1 加的是铁律 6 与四项新规矩，v1.2 加的是第〇节四道闸门与随包判据脚本（属于"怎么机械执行"，不是"改了判据"）。
> **执行方式**：把本文件喂给 AI Agent，让它逐节执行，每项给出「通过 / 阻断 / 不适用 + 证据（文件路径:行号 或 命令输出原文）」，验收报告落盘 `<项目根>/docs/acceptance/证据完整性验收_YYYYMMDD.md`。Agent 自己报的数字同样必须在落盘文件里看得到对应行，看不到按未通过处理。🔴 **勾法见文末"验收结论"第一条：空格＝未验收＝不通过**，全勾满不等于全过。
>
> **配载标记**：【必选】凡对外声称过测试结果的项目。【不适用】可整节标注跳过，但必须写明为什么（例：纯文档项目无测试）。

## 第 0 节 · 验收前置（环境三查，防假失败污染结论）

| # | 检查项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|---|
| 0.1 | 外部依赖就位（模型权重/固定测试图/数据库/外部服务） | 对照测试代码里的依赖清单逐一确认存在 | 全部就位；确实缺失的，跳过条数已写进报告 | ☐ |
| 0.2 | 套件可独立运行 | `python -m pytest --collect-only -q` 确认收集数；共享测试库的套件禁止多进程并行 | 收集数与报告一致；无并行互删风险 | ☐ |
| 0.3 | 路径隔离 | 确认被测代码引用的是本仓库这份（副本缺目录会导致「读源码」类测试假失败） | 断言引用的路径在本项目内真实存在 | ☐ |

## 第 1 节 · 六条铁律＋四道闸门逐项验收（T1–T7）

### T1 · 输出必须落盘

| 验收项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|
| 报告里的测试结果给了落盘文件路径 | 找报告中的结果引用，确认指向真实文件 | 路径存在，非转述 | ☐ |
| 文件内容包含报告所引数字 | 对报告中每个数字在落盘文件里 grep | 每个数字都有对应原始行 | ☐ |
| 本次文件不是上一次的复制改数 | `diff` 本次与上次归档；重点看文件尾部是否残留旧文件名、两版是否仅个别数字不同 | 两版结构独立，或报告已声明「沿用 X 月 X 日结果，本次未重跑」 | ☐ |

### T2 · 改前改后各一次（红-绿对照）

| 验收项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|
| 修复/优化类改动有 before 与 after 两份输出 | `ls evidence/`（或约定目录），应见 `*_before_*` 与 `*_after_*` | 两份都在，且时间戳合理 | ☐ |
| **before 的取法已声明** | 读记录里的「before 取法＝当场／事后副本检出」（铁律 2） | 两者之一都合法，但必须写明；没写＝按未通过 | ☐ |
| before 不是凭空补写 | 当场取的：比对 before 文件时间戳与 `git log -1 --format=%ci <修复提交>`；事后副本检出的：比对产物落盘时间与该记录 F5 起始时间 | 当场取⇒早于修复提交；事后取⇒与 F5 相差 ≤6 小时且报告注明了取法 | ☐ |
| 两份数字相同时的处理 | 相同也算通过，但确认两份都是真跑（时间戳不同） | 未用同一份文件冒充两次运行 | ☐ |

> 🔴 **原写法「before 时间早于修复提交」是一条会把合法动作判成造假的坏判据**：铁律 2 允许"把代码退回改动前、检出到副本目录再跑"，那份 before 的文件时间**必然**晚于修复提交。旧写法还会诱导造假——`touch` 一下 mtime 就"通过"了。所以时间对账只用来**筛出可疑**，定案靠两件事：这份输出能否用记录里的同一条命令重跑出来，以及内容形状是否合理（失败块、汇总行、退出码齐不齐）。`td_evidence.py` 的 C7 判的就是"落盘时间与记录起始差 >6 小时"这种**可疑信号**，红了要人解释，不是自动判伪造。

### T3 · 报指标必须给总体输出行

| 验收项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|
| 每个百分比/汇总数字可溯源 | 逐个数字反查产生它的原始汇总行（如 `396 passed, 2 skipped in 167.44s`） | 全部可溯源 | ☐ |
| 无「手抄进表格却无出处」的数字 | 表格数字逐一在落盘文件中定位 | 零孤儿数字 | ☐ |

### T4 · 改断言必须分类声明

| 验收项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|
| 断言改动有 diff 依据 | `git diff <修复前> <修复后> -- '**/test*'` 逐个看 | 报告所列与实际 diff 一致 | ☐ |
| A 类（口径重算）逐条说明语义变化 | 报告应写「哪条语义变了 → 期望值从多少改到多少」 | 无遗漏 | ☐ |
| B 类（断言弱化，如 `==` 改 `<=`）单独列出并给理由 | 重点盯比较符变松的改动 | 弱化无隐藏；「弱化不是错，藏起来才是」 | ☐ |

### T5 · 回归测试要能失败

| 验收项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|
| 证明「bug 已修复」的新测试，在 before 输出里红过 | 在 before 文件中找该测试的失败记录 | 有红记录 = 回归证据 | ☐ |
| 无红记录时的标注 | 报告应标「本次测试是现状快照，非回归证据」 | 已标注，未冒充回归证据 | ☐ |
| 反向工程嫌疑 | 新断言的期望值与跑出的结果完全一致、且无独立来源说明（如手算/规格推导） | 断言值来源可说明，非「跑完抄进去」 | ☐ |

### T6 · 每次执行留一份最小运行记录（七字段）

| 验收项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|
| 每次执行都有对应记录文件（改前／改后各一份） | `ls` 证据目录，按 `run_*_before/after*` 对账 | 一份执行对一份记录，没有"一次记录冒充两次" | ☐ |
| 七字段齐：代码版本／命令／环境／退出码／时间／数据集版本／产物位置 | 逐格读记录文件 | 无空格；缺项写成「未记录＋原因」 | ☐ |
| 命令一栏是**真正跑通**的那条 | 把记录里的命令原样重跑一次 | 能重跑且退出码与记录一致 | ☐ |
| 代码版本可对账 | `git rev-parse HEAD` 与记录比对；无版本库时比被测文件哈希 | 一致，且 dirty/clean 状态已标注 | ☐ |
| 退出码取自管道之外 | 看命令有没有接 `| head`、`| tee`；有则要求另有一次独立取码 | 记录的码是被测命令本身的 | ☐ |
| 产物位置可打开 | 逐个路径 `ls` | 文件在场、非空、非上一次复制改数（与 T1 第三条合验） | ☐ |

### T7 · 四道闸门有没有真过【必选：用了随包脚本的项目】

| 验收项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|
| 机器字段不是手抄的 | 把记录里的 F1/F2/F4/F5/F7 与 `git rev-parse HEAD`、`py -V`、`ls` 实测对账；手抄的记录在 capture 之外没有生成痕迹 | 逐项对得上；对不上按伪造嫌疑处理 | ☐ |
| 每份交出去的记录都过了 check | 逐份重跑 `py scripts/td_evidence.py check <记录.md>`（手写形状用 `--format freeform`），记下退出码 | 退出码全为 0，且验收报告里**逐份列出命令与退出码**（只写"都过了"＝本次验收自身违反铁律 1） | ☐ |
| 判据能红（防恒真） | 跑 `py scripts/td_selftest.py --out <非系统盘目录>` | 退出码 0，且原始逐条回显文件在场（`selftest_raw.txt`）；🔴 这条不跑，上面两行的"全绿"没有任何意义 | ☐ |
| 逃生舱没超载 | 数记录里「未记录」的项数 | ≥3 项 ⇒ 整份按未测处理，不许出现在"已证明"栏 | ☐ |
| 密钥检查没被延迟 | 看验收报告里有没有逐份的扫描命令与退出码 | 每份都有；🔴 注意 grep 反语义：**退码 0＝命中＝脏，退码 1＝没命中＝干净** | ☐ |

## 第 2 节 · 分类证据、随机性、脱敏的验收【必选：涉及性能或模型效果指标的项目】

### 2A · 三类检查分开定证据

| 验收项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|
| 每处结论都归了类（正确性／性能／模型效果） | 读报告，看每个数字标没标类别 | 无未归类的结论 | ☐ |
| 没有拿正确性证据替性能或效果说话 | 盯"提升了 x%／快了 x%"这类句子引用的证据 | 引用的是同类别证据，不是 `全过了` | ☐ |
| 对应类别的必备证据齐 | 对照 `assets/三类检查证据清单模板.md` 逐格勾 | 该类别格子全过或写明未记录＋原因 | ☐ |

### 2B · 随机性指标（LLM 输出／并发计时／抽样评测／掷骰生成）

| 验收项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|
| 样本量 n、重复次数 r、波动范围三件齐 | 读每个随机指标 | 三件都在，缺件写「未测波动」 | ☐ |
| 提升幅度与波动范围比过 | 比较两次之差与各自范围 | 差落在范围内 ⇒ 结论是「未见稳定差异」，不是「提升了 x%」 | ☐ |
| 单次运行的标注 | 查是否只跑一次却报成稳定值 | 标了「单次，未重复」或补了重复次数 | ☐ |
| 波动范围有来源 | 反查范围是不是由那几次真实运行算出来的 | 没有来路不明的「±2%」 | ☐ |

### 2C · 基线不可用与检查广度

| 验收项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|
| 取不到改前的场景按四类走对（新项目／旧版跑不起来／文档改动／紧急修复） | 读记录的"基线不可用"段 | 给了原因＋降级档＋补齐条件三件 | ☐ |
| 没有补写不存在的前测结果 | 比对 before 文件与其时间戳、T2 第二条 | 零伪造；缺就是缺 | ☐ |
| 检查广度与修改范围相称 | 对照 SKILL.md 第九节表 | 广度过窄要写为什么，不许默认"改一行不跑" | ☐ |
| 授权边界被遵守 | 查有没有未经授权的花钱／长时间／联网运行 | 未跑的都标「因授权未执行，指标未测」 | ☐ |

### 2D · 日志的脱敏、体积与保留

| 验收项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|
| 落盘日志无凭据 | `grep -Ein "api[_-]?key|token|secret|password|private key" <日志>`；🔴 **反语义**：退码 0＝命中＝脏，退码 1＝没命中＝干净（把它当"跑成功＝通过"就把泄露判成合格）；脚本通道用 `td_evidence.py check` 的 C8，两种格式都扫 | 零明文密钥，且命令与退出码一起写进报告 | ☐ |
| 截断没截掉关键三样 | 读截断后的原始输出 | 汇总行、失败段、退出码在场 | ☐ |
| 保留与归档策略写明 | 看记录第 7 字段 | 截断规则、完整件位置、保留期三件齐；不可再生件标了永久保留 | ☐ |

## 第 3 节 · 反例自测（先证明这把尺子能红，再用它判项目）【必选：任何用了判据的项目】

一份"全绿"的验收报告，如果它的判据从来不会红，那么这份绿是**量出来的**还是**尺子坏了**，没人分得清。所以本节放在结论之前：

| # | 自测动作 | 期望结果 | 不做会怎样 | 结果 |
|---|---|---|---|---|
| 3.1 | 随包脚本：`py scripts/td_selftest.py --out <非系统盘目录>` | 退出码 0；汇总行显示"strict 与 freeform 两组变异全部抓到、正向对照不假红、回滚可逆" | 判据里有一条恒真，后面所有闸门静默放行 | ☐ |
| 3.2 | 挑一份真记录，**故意把一格删空**（例：F6 值删掉）再跑 check | **必须翻红**（C2 空值） | 没翻红＝这条判据是摆设 | ☐ |
| 3.3 | 把被引用的原始输出文件名改一个字母 | 必须翻红（C1 路径不在场） | 说明"产物在不在场"没人真看过 | ☐ |
| 3.4 | 在报告里加一句"准确率提升到 95%"（不带口径） | 必须翻红（C9 提升无口径） | 说明"数字要带口径"只是写着好看 | ☐ |
| 3.5 | 全部还原，重跑一次 | 回到绿 | 还原不回去＝刚才的红不是由改动引起，尺子另有问题 | ☐ |

> 没装随包脚本的项目：用手写版等价动作——把本模板的每一节各挑一条判据**故意做成不合格**，看验收 Agent 是否报"阻断"。它报"通过"就说明这份验收在自证清白，不能采信。

## 验收结论

- 🔴 **通过 = 每一格都填了「通过／阻断／不适用＋证据」；空格＝未验收＝不通过。** 原写法"各节全部 ☐"是恒真判据（☐ 是空框，谁交上来都是全 ☐，等于谁都通过），已于 v1.2 废弃——**照旧写法执行的验收报告一律视为未做**。
- 任一项「阻断」→ 修复后**复跑本模板**（含第 3 节反例自测），全绿才算数。
- 阻断项处理四选一：重跑 / 补证据 / 删数字 / 降级表述（如改标「现状快照」）。不许「先记着」。
- 报告落盘路径：`<项目根>/docs/acceptance/证据完整性验收_YYYYMMDD.md`
- 项目归档时本文件随版本锁定：模板源头若有升级（v1.0 → v1.x），**不追溯**本项目的已填版本。
