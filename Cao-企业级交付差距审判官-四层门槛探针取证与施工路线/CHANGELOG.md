# CHANGELOG · 企业级交付差距审判官

## v1.1.0 · 2026-10-08

**新增「联网取证」与「业务场景差距判别法」两大能力**。

### 缘起
CaoHT 于 2026-10-08 追加要求：「你再联网检索相关资料，看看还能从哪些方面找企业级差距，和实际业务场景的差距怎么判别，让这个 skill 能一次性找清楚，**给 skill 加一个联网命令**，让它使用时，会联网自动检索**当前最新需求**，和**同类型竞品的业务功能差距**」。

### 本次新增

1. **§1.5 外部判据锚（"横向"判据）**
   - 生产安全八域 PSF（输入治理/输出验证/数据保护/可观测/部署安全/人工监督/安全/供应商韧性）
   - 七个生产就绪门（业务所有权/权限边界/集成就绪/服务可靠性/保证证据/运营模型/受控变更）
   - 五域就绪评估（集成/评估/监控/组织所有权/范围数据）
   - 法规时间线（EU AI Act 2026-08-02 执法等）
   - 行业命中率基线（14% 完整审批上线 / 82% vs 21% 可见性 / 46% 集成障碍 / 60% 缺 AI-ready 数据项目被弃 / AP 单票成本 $9.84 vs $2.65 等）
   - **定位**：四层门槛是"纵向"（本项目能走到哪层），外部锚是"横向"（同行做到哪）——交叉才能回答"我放到市场上算能交付吗"

2. **§1.6 业务场景差距判别法（七条）**
   - 主数据可对齐 / 异常有归属 / 阈值分档 / 写回验证 / 基线先立 / 失败可逆性 / 指标口径
   - **回答用户核心问题**："和实际业务场景的差距怎么判别"
   - 核心命题：**"跑得通" ≠ "用得上"**

3. **§2.5 联网取证（三条固定检索线）**
   - ① 法规/标准线 ② 竞品功能线 ③ 失败案例线
   - 含关键词模板、竞品对照表格式、四条判读铁律
   - **竞品对照纪律**：取功能不取吹嘘；不拿竞品宣传的直通率当目标（高直通率常是窄分母）

4. **流程从六步升为八步**
   - 新增 Step 3「联网取尺子」（**在探针之前**——先知道外面要求什么，探针才知道重点查什么）
   - 新增 Step 5「业务场景贴合度判别」
   - Step 4 探针维度补：基线（行业最常跳过）、韧性（PSF-8）
   - Step 7 坑栏要求结合 Step 3 失败案例线

5. **军规从四条增为六条**
   - 新增军规 5：**外部判据必须联网取，且标明出处与日期**（禁用训练记忆里的"我印象中是"）
   - 新增军规 6：**区分"行业普遍状况"与"本项目的差距"**（行业数据定严重度，代码探针定有无）

6. **新增 §6.5 联网取证速用**：一句话触发词（"联网看看我们和竞品差什么"等）

7. **报告结构扩为十一节**：新增 §五 外部判据对照、§六 业务场景贴合度判别

8. **模板同步升级**：`report-template.md` 加竞品对照表、场景七条判别表、联网检索清单；检查清单从 14 项增至 19 项
   `probe-library.md` 加 §五 场景贴合探针（7 组）、§六 联网取证探针、反面案例从 5 条增至 8 条

### 诚实声明（v1.1.0）
- §1.5 的框架（PSF/七门/五域）与 §1.6 的失败模式，均来自 2026-10-08 的联网检索（搜索所得），**已标注为外部判据**；
- 行业数字**会随时间变化**，使用时须按军规 5 重新联网复核；
- 竞品数据为 2026 年公开信息，**引用前须复核**。

## v1.0.0 · 2026-10-08

**首次创建**。

### 缘起
CaoHT 于 2026-10-08 提出：「检查企业级交付那个东西做成 skill，让使用这个 skill 就会对项目审判，将其和真正企业级交付的差距全部都找出来，并给予执行建议，类似现在的 P9 卡」。

### 素材来源
- **P9 卡**（`<你的项目工作台>/content/P-项目内功/P9-企业级交付差距与升级路线.md`）：四层交付门槛模型的原始提出
- **业财单据中枢项目**：探针取证法的实战来源
- **关键复盘事件**：P9 卡初版照抄旧文档待办清单，回代码 grep 核实后发现「8 项里 5 项早已完成」——**这个误判直接催生了本 skill 的第一条军规**

### 核心设计决策

1. **为什么不做成"固定清单"**
   - 固定清单必然过时（P9 卡初版翻车就是这个原因）
   - 故本 skill 的灵魂是**探针取证法**（§2）：教"怎么取真相"，而非"背答案"
   - 清单只用作**生成假设**，代码用来**验证假设**

2. **为什么"区分做不到与不需要"是灵魂**
   - 四层门槛里，第二层多数靠客户给料、第三层一半是资质与运维组织
   - 笼统列成"待办"会让人误以为"能力不足"
   - 故每项差距强制打标签：🧩能力 / 🤝资源 / 🏛️资质 / ⬜目标不匹配

3. **为什么设"只审判不施工"军规**
   - 继承 `Cao-项目验收官` 的同款纪律
   - 防止"顺手改代码让报告好看"——那会让报告失真

### 与既有 skill 的分工
- **Cao-项目验收官-四层漏斗固定清单加动态启发**：判「现在质量合不合格」（体检）
- **本 skill**：判「离企业级还差哪些路」（差距地图 + 施工路线）
- 建议协同：先验收官（确认现状），再本 skill（判差距）

### 文件构成
```

references/report-template.md         报告总装模板 + 落盘前检查清单
references/probe-library.md           探针库（含判读铁律 + 反面案例集）

```

### 诚实声明
- 四层门槛模型的**分层判据**是 CaoHT 在 P9 卡中提出的原创框架；
- **探针形态**借鉴了通用工程审计实践（grep/配置读原文/调用链确认），非独创；
- 本 skill **未包含任何特定项目的专有数字**——它是方法论，不是某个项目的报告。
