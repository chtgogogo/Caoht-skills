# CHANGELOG · 项目验收官（project-acceptance）

> 迭代留痕（用户铁律 6）：每版记录三件事——优化了哪些地方、增加了什么功能、解决了什么问题。

## v1.1.0（2026-09-25）· 动态层反幻觉 + 新死法回流闭环

**来源**：外部建议（用户转达）——"动态发现也必须走证据落盘+是否判定，不能变成新幻觉源；库外新死法按失败模式库七字段回流 01"。采纳并做两点加强（假设/实证二轨分流；回流加质量门与路由分家）。

### 优化了哪些地方
- **动态层从"记录格式"升级为"实证门槛铁律"**（heuristics-playbook.md）：原 v1.0.0 只要求动态发现附证据与复现方法，未堵死"没跑验证就把猜测写成分级发现"的通道。现在假设（H-n）必须当场转化为最小探针跑出证实/证伪，才可升级为实证发现（D-n）。
- **报告第 4 节改为二轨三区**（report-template.md）：实证发现区（参与结论）/ 假设区（不参与结论、禁止 P 级）/ 排除区（证伪留痕防重猜）。
- **结论映射补一条二轨规则**（scoring-and-verdicts.md）：只有 D-n 参与结论映射与 P 分级；验收官自查清单新增 2 项（二轨分离检查、回流质量门检查）。

### 增加了什么功能
- **S7 知识回流闭环**（新增章节）：验收 → 库 → 下次验收的双向循环。回流三道质量门（已实证/通用型/库内查重非重复）；回流路由按知识归属分家——Agent/LLM 新死法按**七字段格式**（现象/术语/根因/对策/最坏后果/检查问题/相关）写进失败模式库 `01-failure-modes` 对应类别（编号接续 LOOP/ERR/COST/SEC/CTX/CONC/GOV-、先查 03 术语表、同步 C 盘注册副本、库 CHANGELOG 留痕、02/05 视图同步列待办）；通用工程坑回踩坑日志；本机私有进 store PITFALL。
- **库→验收方向补全**：S2 的 Agent/LLM 行改为"先读失败模式库七类死法逐条对号入座，对不上号的即回流候选"，形成双向闭环。

### 解决了什么问题
- **动态层幻觉通道**：v1.0.0 的动态启发若 AI 只"感觉有风险"就写进报告，会绕过固定清单的证据纪律。现在假设与实证强制分流，结论只认探针证据。
- **知识不回流、踩坑重复踩**：验收发现的新死法此前只留在当次报告里；现在回流进失败模式库/踩坑日志，下次验收从"现场排查"变"对号入座"。
- **回流污染风险**：直接照建议"无条件回流 01"会让库被猜测和项目特例污染——三道质量门 + 路由分家 + 查重先行解决了这个隐患。

## v1.0.0（2026-09-25）· 首发版

**从零建成**，基于用户 CaoHT 提出的"四层漏斗 + 固定清单 + 动态启发"验收框架，经权威实践扩充后产品化。

### 增加了什么功能
- **四层漏斗验收流程**：第一层基础工程（拦截级，任何 ❌ 直接打回）→ 第二层指标性能（硬指标红线）→ 第三层 AI 特有质量（定量分数，评测体系健全性先行）→ 第四层业务兜底（闭环级，兜底链路必须真实触发一次验证）。每层独立清单文件，每项带"查什么/怎么查/通过标准/证据要求"，共 40+ 固定检查项。
- **动态启发六步法**（references/heuristics-playbook.md）：画像打底 → 项目类型 playbook（7 类项目已知坑清单）→ 风险维度扫描（9 维提问表）→ 攻击者视角刁钻用例（弄崩/骗过/诱导做坏事）→ 上线前夜 pre-mortem → diff 驱动增量验收。
- **五态判定 + P0/P1/P2 分级 + 结论映射表**：通过/有条件通过/不通过的判定完全规则化，含"数据不足封顶"规则（关键项未测时禁止给"通过"），杜绝和稀泥结论。
- **九节报告模板**（references/report-template.md）：含诚实暴露弱点、能力缺口与未测项、历史对比三节，报告落盘 `acceptance/` 目录并支持跨轮趋势对比。
- **项目画像脚本**（scripts/profile_project.py，纯标准库）：一键产出语言/框架/项目类型猜测/工具链/红旗（.env 被 git 跟踪、无锁文件、疑似硬编码密钥等 8 类）JSON 画像，降低 Phase 0 的探索 token 成本。
- **验收级别分级**：快检（15-40 分钟）/ 标准（默认）/ 全量，对应不同深度与 API 花费；付费评测先报预算。
- **项目级定制接口**：支持项目根 `ACCEPTANCE.md` 覆盖默认红线；首轮验收自动生成草稿，红线固化后改动须留痕（防"改红线凑通过"）。
- **生态互认**：证据形态对接 `A-Cao-测试纪律`、结论可证伪对接 `A-Cao-抗幻觉纪律`、新坑沉淀对接 `A-Cao-踩坑日志`、Agent 失败模式参考 `Cao-失败模式与对策库`、增量审查参考 `代码审查-双轴PR改动审查`。

### 解决了什么问题
- **AI 编数字填表问题**：原构想是纯 Prompt，AI 可能在无法实测时编造 P95/准确率。本版以"四条军规 + 三禁（禁改测试凑通过/禁编数字/禁硬测不适用项）+ 五态判定 + 数据不足封顶"硬性约束，编造无门。
- **"不适用项被迫硬测"问题**：原清单对非 AI 项目、无用户体系项目没有豁免机制。本版引入 ➖不适用态 + Phase 0 画像驱动的适用性判定。
- **动态启发无方法论问题**：原构想只有"针对本项目特征排查"一句口号。本版给 AI 六步可执行流程 + 7 类项目 playbook + 9 维提问表，启发项强制带 P 级、证据、复现方法。
- **验收结论口径不一问题**：原构想四层判定原则各说各话（打回/高危/定量/闭环）。本版统一为 P0/P1/P2 + 规则化结论映射。
