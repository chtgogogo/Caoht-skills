# 第二层 · 指标与性能验收（硬指标）

> 判定原则：触达红线记为 P0/P1 高危风险，必须附优化方案。
> 前提：项目本地可运行。不可运行 → 本层实测项整体 ⬜ 未测 + 原因，静态可查项照查。
> **铁的口径纪律**：所有数字必须标注（环境配置 / 预热方式 / 轮数 / 时间窗），无口径的数字无效；禁止只报平均值不报尾部。

## A. 延迟与吞吐

**1. 冷启动剔除**
- 怎么查：先预热（空跑 N≥3 次）再正式测量；冷启动数据单独记录（启动耗时本身也是指标）。
- 通过标准：报告中"热态"与"冷态"数字分列，不混报。

**2. 延迟 P50/P95/P99**
- 怎么查：对核心链路压 ≥100 次请求（脚本计时即可，`time.perf_counter` / httpx 并发）；或用项目自带 benchmark。
- 默认红线（ACCEPTANCE.md 可覆盖）：本地对话/检索类 P95 ≤ 3s；纯接口类 P95 ≤ 1s；无既有基线时，首次测得值记为基线，红线待用户确认。
- 证据：原始计时输出落盘 + 分位数表。

**3. 吞吐量**
- 怎么查：固定时间窗（30s）内成功完成的任务数（QPS/RPS 或 任务/分钟）。
- 通过标准：给出实测值；与需求对不上才是问题（无明确需求时记基线）。

**4. 错误率（SRE 黄金信号之一）**
- 怎么查：压测期间统计失败响应 / 总请求；收集 5xx 与异常日志。
- 默认红线：< 1%（本地单机）。

## B. 并发与资源

**5. 并发能力**
- 怎么查：阶梯加压（1 → 5 → 10 → 20 并发，每档 30s），观察错误率拐点与延迟劣化曲线；确认是否有限流/排队机制。
- 通过标准：目标并发下错误率达标、延迟可控；找到"崩塌点"并记录。
- 红线：并发翻倍导致错误率 >10% 或进程崩溃 = P1；有用户量预期却完全无限流 = ⚠️。

**6. 资源占用与泄漏**
- 怎么查：持续运行 15–30 分钟（快检可 5 分钟），记录内存曲线（taskmgr / psutil / `docker stats`）；观察是否单调爬升不回落；连接/句柄数是否持续增长。
- 通过标准：内存有涨有落（GC 正常）；持续爬升 = ⚠️（疑似泄漏，给出复现步骤）。

**7. 启动时间**
- 怎么查：从启动命令到"可响应第一请求"的耗时，冷态测 3 次取中位。
- 通过标准：记录数值；> 60s 的服务记 ⚠️（影响部署与自愈）。

## C. 数据与外部依赖

**8. 数据库体检（有 DB 时）**
- 怎么查：慢查询日志/EXPLAIN 抽 3 条核心查询；查 N+1（循环内查库的代码模式，全局搜循环体里的 query/find）；连接池大小配置。
- 通过标准：核心查询无全表扫；N+1 = 0 处（发现即 P1）。

**9. 外部调用韧性**
- 怎么查：逐个外部依赖（LLM API/第三方 HTTP/DB）确认：①设超时了吗 ②失败重试有退避吗（指数退避+抖动，防重试风暴）③有熔断/降级吗 ④有兜底假数据或友好报错吗。
- 通过标准：①②必须有（缺 = P1）；③④建议有（缺 = ⚠️）。

**10. 幂等性（有写操作/消息/重试机制时）**
- 怎么查：同一写操作重放两次，会否产生重复副作用（重复下单/重复入库/重复发消息）。
- 通过标准：重试安全（幂等键/去重）；不安全且涉及资金或不可逆操作 = P0。

## D. 缓存与成本

**11. 缓存命中**
- 怎么查：有缓存（语义/精确）则统计命中率与命中/未命中延迟对比（同问题问两遍）。
- 通过标准：给出命中率；命中有显著收益（如 70s → 6s 这类）才算缓存生效，只缓存不命中 = ⚠️。

**12. 成本核算（AI 项目）**
- 怎么查：单次典型任务 token 消耗（prompt + completion 分列）× 单价 = 单次成本；× 预估日活 = 月度成本估算。
- 通过标准：给出数字；对照 ACCEPTANCE.md 预算线；**成本随上下文长度非线性膨胀的场景要单独测长对话成本**（暗坑高发区）。

## E. 性能回归与暗坑

**13. 性能回归基线**
- 怎么查：读上次验收报告/benchmark 文件对比；无基线则本次建立（写入 acceptance/ 供下轮对比）。
- 通过标准：相比基线劣化 >30% 的指标 = P1（哪怕绝对值达标——说明有退化）。

**14. 暗坑扫描（静态排查，快检也要做）**
- 逐条核对：①异步链路里的同步阻塞调用（如 async 函数里裸 requests/cursor）②大对象深拷贝/整表读入内存 ③循环里重复编译正则/重复建连接 ④未分页的大列表接口 ⑤日志无上限增长。
- 通过标准：逐条给 ✅/⚠️；发现真实隐患升 P1。
