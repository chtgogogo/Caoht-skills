# 第一层 · 基础工程验收（拦截级）

> 判定原则：本层出现任何 ❌ → 报告结论锁定「不通过」。
> 每项必给五态判定之一（✅❌⚠️⬜➖）+ 证据。证据文件统一存 `acceptance/evidence/`。
> 标注【增量必查】的项目即使增量验收也不许跳过。

## A. 构建与复现（最强的一组检查：从零到绿）

**1. 全新环境复现**【增量必查】
- 怎么查：干净目录克隆/复制源码 → 按 README 装依赖 → 构建 → 跑测试，全程照文档命令，文档缺哪步记哪步。
- 通过标准：一次成功；README 的命令照抄就能跑。
- 证据：`evidence/fresh_install_<date>.txt`。

**2. 单元测试全过 + 无静默跳过**【增量必查】
- 怎么查：跑全部测试（pytest/jest/go test…），统计 passed/failed/skipped。
- 通过标准：failed=0；skipped/xfail 逐个列出并给理由（说不清理由的跳过测试按 ❌ 记）。
- 证据：测试完整输出落盘（按 `A-Cao-测试纪律`，禁止只报总结数字）。

**3. 测试有效性抽检**
- 怎么查：随机抽 3 个测试文件读断言——断言是真实校验输出，还是 `assert result` 空转 / 只跑不判。
- 通过标准：抽到的测试都有实质断言；发现"跑过但没断言"的测试按 ⚠️，成片出现按 ❌。
- 说明：测试通过率 100% 但断言空心 = 测试是装饰品。

**4. 类型检查（有类型注解的项目）**
- 怎么查：mypy/pyright/tsc（按栈选），无配置则 ⬜并给补齐建议。
- 通过标准：0 error（warning 列出）。

**5. 构建产物卫生**
- 怎么查：`git status` + 抽查仓库里有没有误提交的临时物/大文件/构建产物/虚拟环境目录。
- 通过标准：无；`git ls-files` 无 >5MB 的非资源文件（模型权重、数据集不该进 git）。

## B. 代码质量

**6. Lint 静态检查**
- 怎么查：ruff/eslint/flake8/prettier（按栈选）；连 lint 配置都没有记 ⚠️。
- 通过标准：0 error；warning 列出前 10 条。

**7. 调试残留**
- 怎么查：全局搜 `print(`（Python 生产代码，排除 tests/scripts）、`console.log`、`debugger`、`pdb.set_trace`、被注释掉的大段代码。
- 通过标准：生产代码零调试残留；TODO/FIXME 计数并点名超过 20 个的文件。

**8. 裸异常与吞异常**
- 怎么查：搜 `except:` / `except Exception` 后无处理直接 pass 的位置（Python）、空 catch（JS/Go）。
- 通过标准：无裸 except；捕获后必须有日志或明确处理，吞掉异常的位置逐个列出。

## C. 依赖管理

**9. 锁文件存在且入库**
- 怎么查：requirements.txt 带 `==` 锁定 / poetry.lock / uv.lock / package-lock.json / pnpm-lock.yaml / go.sum。
- 通过标准：存在且被 git 跟踪。缺锁文件 = ❌（不可复现构建）。

**10. 冗余依赖**
- 怎么查：pip 系用 `pipreqs` 对比或人工抽查 import；npm 用 `depcheck`；粗查：声明了的依赖在代码里 import 不到的列出。
- 通过标准：无引用死依赖；发现即列清单（P2）。

**11. 已知漏洞扫描**
- 怎么查：`pip-audit` / `npm audit` / `osv-scanner`；工具不在环境里 → ⬜ 并附安装命令，禁止跳过不提。
- 通过标准：无高危 CVE；中低危列出。

**12. 许可证合规**
- 怎么查：依赖许可证里排查 **NC（非商用）类协议**——用户资源红线：CC-BY-NC 等商用素材绝不纳入工程；无许可证代码默认只读参考。
- 通过标准：无 NC/未明许可证被当作工程依赖使用；发现即 P0。

## D. 安全（每一条都要"查过"，不是"觉得没有"）

**13. 密钥硬编码扫描**【增量必查】
- 怎么查：gitleaks（有则用）；无工具则正则抽扫：`sk-[A-Za-z0-9]{20,}`、`AKIA[0-9A-Z]{16}`、`ghp_[A-Za-z0-9]{20,}`、`AIza[A-Za-z0-9_-]{30,}`、`(api_key|secret|token|password)\s*=\s*["'][^"']{8,}["']`。
- 通过标准：0 命中（样例/占位符除外，需逐个人工确认是假值）。
- ⚠️ 特别核对：`.env` 是否被 git 跟踪（`git ls-files | grep .env`）——被跟踪 = ❌ P0。

**14. .gitignore 正确性**
- 怎么查：确认 .env、密钥文件、数据目录、缓存目录在 ignore 列表；提供 `.env.example` 模板（不含真值）。
- 通过标准：敏感与生成物全覆盖 + 有 example 模板。

**15. 注入类抽检**
- 怎么查：抽查 SQL 是否全部参数绑定（禁拼接/format/f-string 组装 SQL）；命令拼接（os.system/subprocess shell=True）；路径拼接是否用到了用户输入（路径穿越）。
- 通过标准：抽查面内 0 风险；发现 1 处即 ❌ P0。

**16. 越权与鉴权（有用户体系时）**
- 怎么查：横向越权（A 用户能否读 B 的资源：抽 1-2 个带 ID 的接口用别人的 ID 试）、未鉴权路由清单。
- 通过标准：受保护接口全部要求身份；无水平越权。
- 无用户体系 → ➖。

**17. 日志泄漏**
- 怎么查：搜日志语句里是否打了密钥、token、用户密码、手机号/身份证等 PII。
- 通过标准：无。

## E. 日志与可观测基础

**18. 日志规范**
- 怎么查：是否用统一日志方案（logging/结构化日志）而非散装 print；有无分级（INFO/WARN/ERROR）；关键链路有无日志。
- 通过标准：生产代码不裸 print；异常处有带上下文的日志。

**19. 全局兜底**
- 怎么查：服务型项目有无全局异常处理器（未捕获异常返回 500 而非进程崩）；CLI 有无顶层 try。
- 通过标准：未捕获异常有去处且被记录。

## F. 版本控制与 CI

**20. git 工作区状态**【增量必查】
- 怎么查：`git status --porcelain`、`git log -1`（记录 HEAD）。
- 通过标准：验收时工作区干净（脏区列出未提交内容，提醒用户）。

**21. CI 状态**【增量必查】
- 怎么查：`.github/workflows` 等配置存在？最近一次运行状态（`gh run list --limit 5`）？
- 通过标准：配置存在 + 最近一次绿。**红叉 CI 而文档宣称质量达标 = ❌ P0（宣称与事实打架，比没 CI 更糟）**。无 CI = ⚠️（个人小项目）或 ❌（多人/公开仓库）。

**22. 迭代留痕（用户铁律 6）**
- 怎么查：资产型产出必须有 CHANGELOG.md（或等价）且跟随最近变更更新。
- 通过标准：存在且最新条目对应近期变更；缺失按 ⚠️（提醒补建）。

## G. 文档

**23. README 与实际一致**
- 怎么查：照 README 的安装/运行/测试命令逐条执行（与第 1 项合并做）；截图/架构图与当前版本相符。
- 通过标准：命令全部可执行；宣称的功能真实存在。

**24. 接口与部署文档（按项目类型）**
- 怎么查：Web 服务有 API 文档（自动生成也算）；有部署说明（环境变量清单、启动命令、依赖服务）。
- 通过标准：一个新人照文档能跑起来；缺部署文档按 ⚠️。

**25. 配置样例**
- 怎么查：`.env.example` 或配置文档，列出全部必需配置项。
- 通过标准：新环境照 example 配置即可运行。

## H. 平台与类型基础项（结合 Phase 0 画像取舍）

**26. Windows 兼容**（用户主力环境是 Windows，重点查）
- 怎么查：路径是否硬编码 `/` 或反斜杠拼接（应用 os.path/pathlib）；有无 UTF-8/GBK 编码坑；shell 脚本在 Windows 能否跑；换行符。
- 通过标准：核心链路在 Windows 下可跑；发现平台专属坑列 ⚠️。

**27. 类型特有基础缺陷**（动态启发交叉项，逐条过）
- Web 服务：CORS 配置、健康检查端点、优雅停机、静态资源、请求体大小限制。
- CLI：无参数时 --help 友好、参数校验、Ctrl+C 信号处理、退出码语义（0 成功非 0 失败）。
- 库/SDK：公共 API 面清晰（`__all__`）、无意外副作用（import 即执行重活）、版本语义化。
- 前端：错误边界、空态/加载态/错误态三态、控制台无报错。
