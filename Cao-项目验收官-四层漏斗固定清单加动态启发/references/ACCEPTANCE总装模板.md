# ACCEPTANCE.md · 项目验收总装模板

> **用途**：新项目把本文件复制到 `<项目根>/ACCEPTANCE.md`，填好「D · 项目专属红线区」后生效。生效后：项目验收官 Phase 0 **优先读本文件**（红线值/评测集路径/豁免项优先于 skill 默认值）；交付流水线第⑬⑭步按它执行；平时它就是项目自己的质量契约。
> **版本锚定**：本文件是三个源模板的**总装视图**——测试纪律 v1.0 / 交付流水线 v1.3.0 / 失败模式与对策库 v1.1.1（均为 2026-09 定稿）。复制到项目后锁定当前版本，源模板升级不追溯已归档项目。
> **配载规则**：A 节【必选】；B 节【有对外输出必选】；C 节【Agent 项目必选，否则删】；D 节【必填，哪怕一行】。每节末尾的指针指向完整判定条款——本文件只内联最小核心，够 90% 场景；要跑全套就沿指针取。
> **执行方式**：项目收尾/交付前，把本文件喂给 AI Agent（或直接触发项目验收官 skill），逐节给「通过 / 阻断 / 不适用 + 证据（文件:行号 或 命令输出）」。阻断项修复后复跑该节，全绿放行。

## A · 测试证据完整性【必选】

- ☐ **A1 结果落盘**：报告里每个测试数字，都能在落盘文件里 grep 到对应原始行（`evidence/` 目录；只报「396 passed」而无文件 = 未通过）
- ☐ **A2 红绿对照**：修复/优化类改动有 before/after 两份真实输出；before 文件时间戳早于修复提交（防事后补造）
- ☐ **A3 断言弱化单独声明**：`==` 改 `<=` 之类的放松必须单独列出并给理由，不许混在口径重算里
- ☐ **A4 回归证据**：证明「修好了」的新测试在改前输出里红过；没有就标「现状快照，非回归证据」，不许冒充

> 完整版（含 diff 防伪、环境三查、反向工程嫌疑检测）→ `A-Cao-测试纪律-测试证据形态规范/references/验收模板-证据完整性.md`

## B · 上线门禁与对外口径【有对外输出（README/简历/汇报/作品集）必选】

- ☐ **B1 密钥零硬编码**：`grep -r "sk-\|secret\|password\|api_key"` 零可用凭据命中；历史残留须确认已在服务商处作废
- ☐ **B2 无弱默认值上生产**：密钥/管理员码/库密码等安全配置，部署文件已覆盖默认值
- ☐ **B3 鉴权覆盖**：存敏感数据的接口无「全挂了唯独它没挂」
- ☐ **B4 数字四件套**：对外数字齐「来源命令 / 样本量分母 / 统计口径含置信区间 / 生成日期」
- ☐ **B5 数字不过期**：任何数字的生成日期 ≥ 最后一次评测日期，早于 = 重跑或删除
- ☐ **B6 引用可验证**：`git cat-file -t <commit>`、`Test-Path <file>` 逐个通过（引用不存在的对象 = 阻断）
- ☐ **B7 AI 署名带标识**：`git log --format='%an <%ae>'` 无真人化假名/假企业域名；README 声明 AI 参与范围

> 完整版（安全 L1 十二项 + 口径十二项 + 收尾推送六项）→ `Cao-交付流水线-需求到交付分身编排/references/验收模板-上线门禁与口径.md`

## 验收结论

- 放行 = 所载各节零阻断。阻断项修复后复跑该节；改口径四选一（改简历 / 重跑评测 / 补证据 / 删数字），不许「先记着」。
- 本文件随项目归档锁定复制时的源模板版本；验收中发现的模板外新死法，按失败模式库七字段格式回流。
