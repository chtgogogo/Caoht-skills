# 上线前检查清单（05-checklists）

> **派生声明**：本文件是 01-failure-modes（唯一事实源）的"门禁"视图——十问与门禁的依据在 01 对应条目的"检查问题/对策"字段。修改顺序：先改 01，再同步本文件。
>
> 用法：Agent 写完、准备真跑之前，过两部分：**凌晨三点十问**（想清楚出事场景）+ **八项硬门禁**（缺一项不上线）+ 企业级附加门禁（有合规/多租户义务时必过）。产出物是《风险清单表》（模板在最后）。

## 凌晨三点十问

问自己：**它上线后，凌晨三点我被叫醒，最可能是因为什么？** 每问必须答出"靠什么护栏让这一问不成立"。

1. 它卡住了吗？我 5 分钟内怎么发现？→（心跳/进度日志，LOOP-2）
2. 它花钱超预算了吗？→（预算硬上限+告警，COST-1）
3. 它做了不可逆的事吗？→（权限门+确认，SEC-4）
4. 它在反复失败刷屏吗？→（熔断器+告警聚合，ERR-1/2）
5. 它还记得自己要干什么吗？→（上下文水位监控+压缩，CTX-1）
6. 有用户在等它吗？等待有反馈吗？→（超时告知，LOOP-4/COST-2）
7. 它留下的中间产物能清理或复用吗？→（幂等+清理钩子，ERR-4/COST-3）
8. 我能从日志一句话还原它干了什么吗？→（结构化日志，CTX-5）
9. 最坏情况是什么？概率多大？兜底是什么？→（写进下面的风险清单表）
10. 明早怎么一句话向上级解释发生了什么？→（审计留痕，CTX-5）

## 八项硬门禁（缺一不上线）

- [ ] 1. 迭代上限已设，数值是 ____，超限行为是"停止并报告"
- [ ] 2. 预算上限已设（token ____ / 金额 ____ / 时间 ____），超限立即收尾
- [ ] 3. 每次工具调用都有超时，整体任务有截止时间
- [ ] 4. 连续失败会熔断，熔断时**人能收到通知**（不是静默停）
- [ ] 5. 全部不可逆操作都有人工确认门，默认无自动同意
- [ ] 6. 中断重启能从检查点继续，不会重做已付费的步骤
- [ ] 7. 日志能还原全流程，且出口已脱敏（拿一个真实日志 grep 密钥/手机号验证）
- [ ] 8. 有总开关（kill switch）能随时停，停了之后现场是干净的或可恢复的

## 企业级附加门禁（涉及真实用户/多租户/合规义务时必过）

- [ ] 9. 有评估回归基线：固定考卷（golden dataset）≥30 条，本次改动跑过且成功率不低于上一版（GOV-6 / P-21）
- [ ] 10. 审计留痕能回答"谁、何时、依据哪版指令、让 Agent 做了什么"（GOV-2 / P-23）
- [ ] 11. 有灰度/影子计划：新版先影子观察或小流量，定义了"差异多大算异常"的量化回退阈值（GOV-7 / P-20）
- [ ] 12. 供应商与模型版本已锁定，退役公告有人盯，切换退路演练过一次（GOV-5）

## 风险清单表（本清单的交付物，也是设计时/查漏环节的汇总出口）

| 编号 | 现象 | 严重度 | 术语 | 解法 | 修复成本 | 本轮是否处理 |
|---|---|---|---|---|---|---|
| 例 | 反复调同一工具无进展 | 高 | Livelock | 迭代上限+状态指纹+熔断 | 计数器级（10 行） | 是 |
|  |  |  |  |  | （计数器级/中等/架构级） |  |

- 排序规则：严重度 × 修复成本，**先做"高严重度+计数器级"的**，这是性价比最高的三两件事。
- "本轮不处理"的行不许删，留着当已知风险台账。
