# 失败模式：上下文与状态（CTX）

> 这一类死法的共同点：**Agent 的"脑子"（上下文）和"记性"（状态）出了问题**——要么撑爆、要么中毒、要么失忆。

### CTX-1 上下文爆窗
- 现象：长任务跑到几十轮，历史塞满窗口，要么直接报错截断，要么最早的任务目标被挤出去，Agent 开始"忘了自己要干嘛"
- 术语：Context window overflow / Context compaction（上下文窗口溢出 / 上下文压缩）
- 根因：工具返回全量塞入；历史只增不减；大文件反复进出
- 对策：上下文压缩（老历史摘要化）+ 输出截断与告知 + 大资源取摘要按需回读
- 最坏后果：任务目标丢失，Agent 开始自信地做完全偏离的事，产出物表面完整实则答非所问
- 检查问题：第 50 轮时，Agent 还记得第 1 轮的目标吗？靠什么记得？
- 相关：Context compaction, Output truncation

### CTX-2 上下文中毒（错误结论带全程）
- 现象：第 2 轮模型得出了错误结论（或工具返回了错误数据），之后所有轮次都把这个错误当公理引用，自我强化到收尾
- 术语：Context poisoning / Belief perseverance（上下文中毒 / 信念固着）
- 根因：早期结论没有复核机制；错误信息留在上下文里持续被引用
- 对策：阶段性复核（关键结论二次验证后再当依据）+ 压缩时对未验证结论降级标注（"待验证"）+ 允许显式撤销早前结论
- 最坏后果：一个早期小错误污染全部下游工作，且因为"上下文里一致"显得格外可信
- 检查问题：进入上下文的结论，哪些验证过、哪些只是模型自己说的？
- 相关：Context compaction, Golden dataset

### CTX-3 状态丢失（重启断档）
- 现象：会话重启、进程崩溃、换了个窗口——Agent 完全失忆，要么从头重做（重复花钱），要么在错误的基础上继续
- 术语：State persistence / Checkpoint / Resume（状态持久化 / 检查点 / 断点续跑）
- 根因：任务状态只在对话上下文里，没落盘；没有"已完成步骤"的外部记录
- 对策：检查点落盘（每完成一步写结构化进度文件）+ 启动时先读检查点决定从哪继续 + 已完成步骤的产物可复用
- 最坏后果：长任务永远跑不完（每次都在 80% 处崩溃重来）；重复执行已产生的副作用
- 检查问题：现在杀掉进程再重启，它能从哪一步继续？怎么知道前几步的产物在哪？
- 相关：Checkpoint, Idempotency key

### CTX-4 输出格式漂移
- 现象：前几轮模型老老实实输出 JSON，第 10 轮开始加解释文字、换字段名、数组变对象——下游解析全线崩
- 术语：Structured output / Schema constraint / Format drift（结构化输出 / schema 约束 / 格式漂移）
- 根因：靠"求模型输出 JSON"而不是"强制 schema"；解析失败后没有标准处理路径
- 对策：结构化输出（schema 硬约束）+ 解析失败带具体错误重试一次 + 再失败走升级而不是硬抠正则
- 最坏后果：下游拿残缺数据照跑，产出静默错乱
- 检查问题：格式解析失败时，谁发现？发现后走哪条路？
- 相关：Structured output

### CTX-5 不可观测（出事查不了案）
- 现象：Agent 行为诡异，想排查——发现没有日志、没有步骤记录、没有耗时和 token 统计，只能靠猜
- 术语：Observability / Tracing / Structured logging（可观测性 / 链路追踪 / 结构化日志）
- 根因：开发时靠"看屏幕输出"当日志；没有按任务串起全链路的 id
- 对策：结构化日志（每步一行：步骤/工具/状态/耗时/token）+ 任务 id 串联 + 关键决策点记录"为什么选这条路"
- 最坏后果：线上问题完全黑箱，复现和归因全靠玄学；同样的事故反复发生学不到教训
- 检查问题：任务跑完后，我能只靠日志还原"它每一步做了什么、为什么"吗？
- 相关：Structured logging, Tracing

### CTX-6 知识过期与检索错配（RAG 场景）
- 现象：Agent 引用过期政策（去年的价格表）、检索回来的文档文不对题、知识库更新了但 Agent 还在用旧快照
- 术语：Knowledge staleness / Retrieval failure / Grounding / RAG（知识过期 / 检索失败 / 接地依据 / 检索增强生成）
- 根因：知识源没有版本和新鲜度管理；检索质量没人评估；模型把"检索到的"直接当"正确的"
- 对策：知识源版本化+新鲜度标记（文档带生效日期，过期不检索）+ 检索质量评估（固定问题集测命中率）+ 要求回答附引用出处
- 最坏后果：基于过期知识批量产出错误决策（报价、合规口径），且输出自信满满
- 检查问题：知识库上次更新是什么时候？Agent 知道每条知识的生效日期吗？
- 相关：Golden dataset, CTX-2 上下文中毒, Grounding
