# 失败模式：循环与终止（LOOP）

> 这一类死法的共同点：**Agent 停不下来，或停下来的方式不对**。设计任何带主循环的 Agent，先过这 5 条。

### LOOP-1 无限循环（同一错误反复试）
- 现象：任务失败后 Agent 原样重试，第 10 次和第 1 次的做法一模一样
- 术语：Infinite loop / Termination analysis（无限循环 / 终止性分析）
- 根因：没有迭代上限；模型相信"再试一次就成了"，但没有任何东西发生变化
- 对策：迭代上限 + 策略升级（同法失败 3 次强制换路）
- 最坏后果：无限烧 token 直到人为发现；任务永远不结束
- 检查问题：主循环有总步数上限吗？同一方法连续失败几次会强制换策略？
- 相关：Iteration limit, Escalation, Exponential backoff

### LOOP-2 活锁（有活动无进展）
- 现象：Agent 反复调同一个工具，没有进展；看着很忙，实际在原地打转
- 术语：Livelock / Non-progress detection（活锁 / 无进展检测）
- 根因：模型陷入局部循环，或工具持续失败但未上报；每轮输出略有不同，骗过了"完全相同"检测
- 对策：迭代上限 + 状态指纹做进展判据 + 熔断器
- 最坏后果：烧 token、卡死任务、上下文被垃圾填充污染后续判断
- 检查问题：最近 N 轮状态有没有变化？同一工具同参数调了几次？
- 相关：Circuit breaker, State fingerprint, Progress metric

### LOOP-3 假进展（微变绕过检测）
- 现象：每轮状态都"变了一点"（换个措辞、挪个顺序），但离目标没近一步，指纹检测全放行
- 术语：Progress metric / Pseudo-progress（进展度量 / 假进展）
- 根因：用"状态是否相等"判循环，而循环的证明应该是"指标是否不动"
- 对策：改用进展度量（剩余待办数、完成比例），连续 3 轮指标不降判无进展
- 最坏后果：绕过所有基于"完全相同"的防护，活锁带防护跑到底
- 检查问题：我拿什么当"进展"的判据？是活动量（调了工具）还是完成量（目标逼近）？
- 相关：State fingerprint, Progress metric

### LOOP-4 死等（等一个不会来的事件）
- 现象：Agent 在轮询等待外部事件（文件出现、审批通过、任务回调），该事件永远不会发生，Agent 永远等下去
- 术语：Deadlock / Deadline miss（死锁 / 错过截止期）
- 根因：等待没有截止时间；上游已失败但没通知下游
- 对策：所有等待带 deadline，到期走降级路径（上报/放弃/换路）
- 最坏后果：Agent 永久挂起，占着资源和会话，用户以为在跑实际早死了
- 检查问题：每一处"等待"有到期时间吗？到期后走哪条路？
- 相关：Timeout, Deadline, Escalation

### LOOP-5 任务膨胀（子任务无限派生）
- 现象：Agent 为完成 A 派生子任务 B，为 B 派生 C……任务树越生越大，永远到不了叶子
- 术语：Runaway recursion / Task explosion（失控递归 / 任务爆炸）
- 根因：派生没有深度限制；"完成父任务"被定义成了"完成所有子任务"，而子任务可以无限细分
- 对策：任务派生深度上限（如 3 层）+ 单任务子任务数上限 + 叶子必须是"直接可执行"的原语操作
- 最坏后果：任务树指数爆炸，token 消耗随之爆炸
- 检查问题：允许最多几层嵌套派生？叶子节点必须是什么形态才算数？
- 相关：Iteration limit, Budget governor

### LOOP-6 提前收工（谎报完成）
- 现象：任务没做完，Agent 宣布"已完成"；或遇到困难就草草交付一个空壳产物
- 术语：Premature termination / Weak verification / Task verification（提前终止 / 验证薄弱，MAST 第三大类"任务验证"）
- 根因：完成判定靠模型自述而不是产物校验；没有"宣布完成必须拿出证据"的要求
- 对策：完成门（声明完成时必须附产物证据：文件路径、查询结果、测试输出）+ 独立验证步骤（另一个调用只管验收，不管干活）
- 最坏后果：下游拿着空壳继续盖楼，错误在"已完成"的掩护下扩散；用户以为交付了
- 检查问题："完成"是模型说的还是验证过的？完成标准能写成机器可查的断言吗？
- 相关：Task verification, ERR-3 假成功, Evaluator-optimizer
