# 失败模式：成本与预算（COST）

> 这一类死法的共同点：**任务可能最终能完成，但代价是天文数字**。成本失控最阴险——它不报错，等你收到账单才知道。

### COST-1 费用/token 失控
- 现象：一个本该 5 美元的任务跑出 500 美元；账单日才发现，中间没人知道
- 术语：Budget governor / Token budget / Cost overrun（预算控制器 / token 预算 / 成本超支）
- 根因：没有边跑边累计消耗；循环类死法（LOOP-1/2）的代价最终都体现在这里
- 对策：预算控制（token/金额硬上限，边跑边累计，超限立即收尾报告）+ 迭代上限从源头掐
- 最坏后果：真金白银的损失；失控循环一晚上烧掉一个月预算
- 检查问题：每次调用后我读 usage 了吗？上限是多少、超了之后做什么？
- 相关：Budget governor, Iteration limit

### COST-2 时间失控
- 现象：预计 10 分钟的任务跑了 6 小时还没完，用户早就走了，Agent 还在跑
- 术语：Deadline / Timeout / Wall-clock budget（截止时间 / 超时 / 墙钟预算）
- 根因：只有单次调用超时，没有整体截止时间；慢工出细活被当成了默认合理
- 对策：整体 deadline + 阶段性检查点（每 X 分钟自评"还值得继续吗"）+ 超时收尾报告已有进展
- 最坏后果：占用的会话/进程/并发额度一直不放；用户等到放弃，产物也拿不到
- 检查问题：整个任务最迟什么时候必须停？停的时候怎么把半成品交出去？
- 相关：Timeout, Deadline

### COST-3 重复调用浪费
- 现象：网络抖动重试、用户刷新重发、多 Agent 抢同一任务——同一个昂贵操作（查询、生成、支付）被执行了多遍
- 术语：Idempotency key / Deduplication / Memoization（幂等键 / 去重 / 记忆化）
- 根因：副作用调用没有幂等键；结果没有缓存，同样的输入重复计算
- 对策：幂等键（同键返回上次结果）+ 结果缓存（同参数直接命中）
- 最坏后果：重复扣款/重复发消息等真实副作用；同一大查询每次 30 秒 × 每任务 20 次
- 检查问题：这个操作执行两次会发生什么？会双倍花钱吗？
- 相关：Idempotency key

### COST-4 上下文重复传输浪费
- 现象：同一个大文件/长文档在第 3、7、12 轮对话里被完整塞进上下文，token 费用按轮数翻倍
- 术语：Context re-ingestion / Context caching（上下文重复摄取 / 上下文缓存）
- 根因：大资源没有"取一次、留摘要、按需回读"的机制；每轮都靠重新读取来"记住"
- 对策：大资源首轮取摘要+存索引，后续按需分页回读；支持 prompt caching 的服务开启缓存
- 最坏后果：成本随对话轮数线性暴涨，且每轮都挤占有效上下文窗口
- 检查问题：超过 5k 字的资源，我会读它几次？第二轮还需要全文吗？
- 相关：Context compaction, Output truncation
