# 提问模板：让 AI 生成问题清单（06-prompts）

> 用法：代码写完后，怕自己有盲区——**不要让 AI 直接给答案，让 AI 先给你问题清单**。你是需求方，它是找茬的。模板一用于找茬，模板二（角色轮换）用于换视角补漏。

## 模板一：六维度问题清单（主模板）

> **不要这样问**："帮我实现一个限制器"——你会得到一个通用实现，覆盖不了你的具体风险。
> **要这样问**：先要问题清单，再挑着解决。照抄：

```
我在设计一个 Agent，它的工具执行部分是这样的：
[贴代码]

请你扮演一个挑剔的 SRE / 运维工程师 / 安全工程师，
按以下维度列出这个 Agent 上线后可能出现的所有问题：
1. 循环与终止（无限循环、无进展、活锁、提前收工）
2. 错误与恢复（工具失败、重试、熔断）
3. 成本与预算（token、API 费用、时间）
4. 安全与权限（越权、注入、数据泄露、工具投毒）
5. 上下文与状态（上下文爆、状态丢失、重复调用）
6. 并发与顺序（写冲突、依赖顺序、并行安全）
7. 治理与合规（规格含糊、审计断层、多租户串扰、合规、供应商锁定、评估基线、灰度、配置漂移——企业级/上线场景必问）

每个问题请给出：
- 问题的具体表现
- 对应的专业术语
- 业界标准解法
- 如果我不处理，最坏后果是什么

按严重程度排序。先不要给代码，只给问题清单。
```

拿到清单后，接着问（转 06-prompts/差距分析.md）：
> "这些问题里，哪些可以用简单计数器解决？哪些需要更复杂的检测？分别对应什么术语？业界通常怎么解决？"

## 模板二：角色轮换（换视角补盲区）

同一个代码，分别用以下角色各跑一遍模板一，**不同角色挑出的问题几乎不重叠**：

| 角色 | 它最容易抓到的问题 |
|---|---|
| 挑剔的 SRE | 卡死、告警风暴、半夜重启、监控盲区 |
| 安全工程师 | 提示注入、越权、凭证泄露、注入路径 |
| 财务/采购 | 费用失控、重复付费、没有用量封顶 |
| 终端用户 | 等待无反馈、产物不可用、出错没人管 |
| 红队攻击者 | 诱导承诺、绕过确认门、污染数据源 |

收尾追问一句：
> "以上五份清单合并去重，只保留【不处理就会出真实事故】的条目，按严重度排序。"

## 本卡片的长期习惯（语料积累）

- 每次真实出事（自己或别人），搜一遍英文事故报告：`LLM agent incident report`、`LLM agent failure case study`、`AI agent postmortem`。
- 挑可迁移的案例按 04-incidents 的标注规范入库——**案例库越厚，模板一问出来的问题越准**（模型见过的死法多，联想就多）。
