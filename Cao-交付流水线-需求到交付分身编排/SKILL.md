# Cao 交付流水线：需求到交付分身编排

> 总装调度器：把「想法 → 设计 → 选型 → PRD → 任务卡 → 分身执行 → 验收 → 收尾」串成自动流水线。
> 设计原则：**每步绑产出物**（这步的产出 = 下步的原料）；**卡文件制**（一卡一文件，拒绝单文件巨石）；
> **台账即断点存档**（随时中断，随时续传）；**验收先于实现**（每卡开工前基线就绪）。

## 〇、依赖自检（每次启动先跑，约 5 秒）

检查 `references/` 细则与 `references/depends/` 自包含副本（20 份：本机 skill 原文 8 份 + superpowers 十二步对应 skill 原文 12 份）是否齐全——清单、分级处理与"刻意不收"说明见 `references/依赖与自检.md`：
- 齐全 → 继续；
- 缺失 → 用 `references/depends/` 里的**自包含副本**顶上（本 skill 的细则均为自包含，不硬依赖外部 skill）；
- 连副本也缺 → 按该文件头部标注的来源提示用户重新获取（如「从 SkillHub / github.com/obra/superpowers 重新下载」）。

## 一、启动路由（每次触发必走）

```
1. 查台账：在 <项目根>/docs/pipeline/ 找 台账.md
   ├── 找到且存在未完成卡 → 问用户：「继续上次（从第 N 张卡接着来）还是开新的？」
   └── 没有 → 问用户：项目落盘目录（默认建议 <项目根>/docs/pipeline/，用户可改）

2. 四选项提问（先给推荐+理由，用户拍板）：
   A 轻量  —— 小改动五步（磨需求一句话版→一行PRD→执行卡→台账→收尾）
   B 标准  —— 新功能九步（磨设计→PRD→切卡→派遣→台账→回看→收尾）
   C 企业  —— 全十二步（+技术选型深选+卡库+双评审+总评审+工具箱外挂）
   D 跳步优化 —— 已有项目：先扫十二步找短板 → 列缺口清单 → 用户勾选 → 直接执行对应阶段
   （判定依据见 references/模式判定.md；先给推荐再让用户选）

3. 单步直调：用户点名某一步时（如"帮我切卡""就跑个评审"）跳过路由，
   直接读该步细则执行；仅两件事不可省——落盘目录确认 + 台账登记（保持断点可续）。
```

## 三、执行铁律

1. **每步绑产出物**：产出物文件不落盘 = 这步没做完。
2. **验收先于实现**：卡开工前验收动作必须就绪（评测基线分/测试脚本/肉眼清单，形式不限但必须写进卡）。
3. **一卡一文件**：任务卡禁止塞进单个巨型计划文件（token 黑洞）。
4. **台账即时更新**：每张卡完成立即勾台账（它是断点续传存档，不是事后补记）。
5. **派遣上下文最小化**：子代理只喂「该卡 + PRD 相关段 + 精确文件路径」，绝不喂全项目历史。
6. **默认接力**：有依赖的卡依次执行；无依赖的卡先问用户要不要并行。
7. **双评审**（企业/子代理模式）：每卡完成后先审「是否符合设计」再审「代码质量」，严重问题阻断下一卡。
8. **落盘目录先问**：流水线产物的落盘目录在启动时问用户（默认建议 `<项目根>/docs/pipeline/`）。
9. **按需加载（省 token 铁律）**：启动只读本 SKILL.md（索引+路由），禁止预读/通读 references/ 目录；
   进入某一步才读该步细则，一次只读一个；depends/ 副本只在两种情况读——对应细则缺失需顶替、或执行中需要外部 skill 原文细节；
   superpowers_assets/ 只在派遣/评审需要整篇模板时读对应那一个文件。
10. **安全基线不可跳过**：收尾（⑫）前必须先过第⑬步 L1 档；L1 有阻断项（可被直接利用的漏洞）不许收尾。
   教训锚点：2026-09-23 外部安全拷问暴露 11 项实锤（JWT 默认密钥/DEBUG 连坐限流/role 自报/审计裸奔/async 同步阻塞等），
   全部漏网于"卡内验收"——根因是检查表缺安全维度，不是执行不力。
11. **对外口径不可带病投递**：凡有对外输出（简历/README/汇报/作品集）的项目，收尾（⑫）前必须过第⑭步；
    出现"数字缺四件套 / 数字早于最后一次评测 / 引用不存在的 commit / AI Agent 冒充真人署名"任一 → 阻断收尾与投递。
    教训锚点：2026-09-23 外部拷打暴露同一批项目里的对外失实（全量耗时被抄成过期快照、用例数与 README 自记矛盾、
    "49 题"与实测 52 条不符、安检报告引用不存在的提交号 `dbaf112`）——**根因不是不会做，是⑬与编码准则都只管"东西对不对"、没人管"说出去的话站不站得住"**。

## 四、收尾（⑫细则）

1. 评测/测试全量跑一遍（有评测集的项目必跑，对照开工前基线）；
2. 更新项目 CHANGELOG（本流水线做了什么/解决了什么）；
3. 台账归档（`docs/pipeline/台账_归档_YYYYMMDD.md`）；
4. 写入工作记忆（若有跨会话记忆库，按其格式记一条工作记录）；
5. **过第⑭步对外陈述口径检查**（仅当本项目有对外输出：README/简历/汇报/作品集）；有阻断项不许收尾；
6. 问用户是否推 GitHub（推前检查：无绝对本机路径、无密钥、无隐私数据、AI Agent 署名带标识）。

## 五、通用化说明（本 skill 可跨机器/上传 GitHub 复用）
