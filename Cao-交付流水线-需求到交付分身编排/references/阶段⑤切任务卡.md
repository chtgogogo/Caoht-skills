# 阶段⑤ 切任务卡 + 阶段⑦ 验收先于实现

> 产出物：`<项目根>/docs/pipeline/cards/卡N_标题.md`（一卡一文件，禁止单文件巨石计划）。
> 台账同步建好（见 台账模板.md），每张卡在台账里登记一行。

## §1 粒度判定（切卡前先定档，LLM 分析→用户拍板）

| 档 | 卡粒度 | 执行者 | 卡模板 |
|---|---|---|---|
| 小项目/标准模式 | **子代理卡**：一个子代理一次对话能完成（约 2~5 分钟人类等价工作量） | 子代理自动执行 | §2.1 实习生标准 |
| 企业模式/大改动 | **人工窗口卡**：一个新窗口半天内完成的大块 | 用户复制提示词卡到新窗口，或大子代理 | §2.2 成人标准 |

判定依据：任务涉及的文件数（≤3 个文件→子代理卡）、是否需要大量上下文、验收是否可自动判定。**拿不准就先按子代理卡切，执行时发现不够再合并。**

## §2.1 子代理卡模板（实习生标准——热情但没判断力，所以必须写到零歧义）

```markdown
# 卡 #N：{一句话标题}
- 目标：{做什么，一句话可验证}
- 涉及文件：{精确路径列表，含要新建的}
- 前置依赖：{卡#X 已完成 / 无}
- 实现要点：{函数签名 / 接口定义 / 关键逻辑说明——写到零歧义，但不代写全部代码}
- 验收（怎么算做完）：{精确命令与预期输出，如 python -m pytest tests/test_x.py 全绿；
  评测集 xx 指标不低于基线；肉眼验收清单逐项打勾}
- 禁止：{不改哪些文件 / 不加未要求的功能 / 不引入新依赖}
- 完成后动作：{跑什么命令、更新台账哪一行、返回什么摘要给主会话}
```

## §2.2 人工窗口卡模板（成人标准——写给有判断力的你）

```markdown
# 卡 #N：{标题}
- 你要做什么：{思路与目标，引用 PRD 章节}
- 材料位置：{PRD 路径 / 相关文件 / 上游卡的产出}
- 怎么算做完：{验收清单}
- 边界提醒：{不要动什么 / 容易踩的坑}
```

## §3 切卡原则

1. **垂直切片优于水平分层**：先切"能跑通一条最小流程"的卡，再切增强卡（tracer bullet）；
2. **依赖显式标注**：卡与卡的依赖写在卡上，台账里体现顺序；无依赖的卡标"可并行"；
3. **每卡必写"怎么验证"（硬性要求）**：评测集 / 测试脚本 / 肉眼验收清单，形式不限但没有就是不许开工；
4. **YAGNI**：PRD 里 P2 的功能不切卡，等 P0 全绿再说。

## §4 验收先于实现（阶段⑦）

每张卡**开工前**完成：
1. 把验收命令/评测用例准备好（有评测集的先跑一遍**记下基线分**）；
2. 确认验收是"客观可判定"的（一条命令能跑出对/错，或清单可逐项打勾）；
3. 基线记录写进卡文件——完成时对照，防"感觉做完了"。

> 灵魂来自 TDD（先看到失败再实现），但不强制测试形式：评测基线、手动清单同样是合法的"先看到失败"。
