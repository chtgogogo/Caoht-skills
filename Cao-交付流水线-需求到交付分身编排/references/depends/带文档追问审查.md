# 带文档追问审查（Grill With Docs）

锚定项目已有领域模型的「盘问式审查」，边问边把结论沉淀回文档。

## 与 grill-me 的区别

- **grill-me**：纯对话盘问，不读、不写任何文档。适合方案还停留在概念阶段、只想把它想透。
- **grill-with-docs**：锚定项目的领域模型（CONTEXT.md、术语表、ADR）盘问，术语对照术语表质疑，达成的决策**实时写回**文档。适合项目已有领域模型、新方案必须与之对齐。

## 何时用

- 项目已有 `CONTEXT.md` / 术语表（glossary）/ `ADR`（架构决策记录）
- 新方案必须与既有领域模型对齐

## 工作流

1. **先读现状**：读 `CONTEXT.md`、术语表、已有 ADR，搞清现有领域模型与术语定义。
2. **逐层盘问**：按 grill-me 的方式逐层拆解方案（先列 3–6 个顶层决策分支 → 从最基础的开始 → 逐分支问到底）。
   - 每个问题先给推荐答案再提问，等用户回答再继续。
   - 术语不一致时，对照术语表质疑：是同一个概念吗？还是该新增一个术语？
3. **实时沉淀**：每个决策尘埃落定后，立刻写回文档：
   - 新决策 → 新增 ADR；
   - 术语澄清 → 更新术语表；
   - 领域关系变化 → 更新 `CONTEXT.md`。
   - 领域建模复杂时，借助 `domain-modeling` skill。
4. **收尾**：总结本次新增 / 修改的决策与术语，列出与既有模型对齐（或冲突并已解决）的点。

## 工具

- **Read / Grep**：读现有 CONTEXT.md、ADR、术语表、代码，能自己查清楚的不要问用户。
