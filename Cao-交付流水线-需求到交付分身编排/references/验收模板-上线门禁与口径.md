# 验收模板 · 上线门禁与对外口径

> **本文件是验收模板**：新项目复制到 `<项目根>/ACCEPTANCE.md`（整份或只取本节）后逐项填写。三节配载：S 安全基线【必选：所有项目收尾前】、K 对外口径【有对外输出（README/简历/汇报/作品集）的项目】、F 收尾推送【要推 GitHub / 交付的项目】。
> **版本锚定**：派生自 Cao-交付流水线 v1.3.0（细则：references/安全基线检查.md、references/对外陈述口径检查.md，均 2026-09-23 定稿）。复制到项目后**锁定当前版本**，skill 升级不追溯已归档项目。
> **执行方式**：把本文件喂给 AI Agent，让它逐项给出「通过 / 阻断 / 不适用 + 证据（文件:行号 或 命令输出原文）」。产出双报告落盘：`docs/pipeline/安检报告.md` 与 `docs/pipeline/口径核查表.md`——没有产出物的检查 = 空转。工具优先：能用工具的不肉眼，工具只覆盖约一半，其余走查。
>
> **两节的分工**：S 节管「可被攻击的风险」（漏洞视角），K 节管「说出去的话站不站得住」（第三方核对视角）。两边的阻断项同等效力——不许带着阻断项收尾或投递。

---

## S 节 · 安全基线 L1（收尾前必检，约 30 分钟）

| # | 检查项 | 方法 | 阻断标准 | 结果 |
|---|---|---|---|---|
| S1 | 密钥/凭据硬编码 | grep `sk-`、`secret`、`password`、`api_key` 字面量；`git log --all -S <密钥名>` 查历史 | 源码/示例/测试出现可用凭据=阻断；历史残留→确认密钥已在服务商处作废 | ☐ |
| S2 | 配置默认值审计 | 逐个检查安全类配置（密钥/管理员码/库密码）有无「可上生产」的默认值 | 安全项弱默认值且部署文件未覆盖=阻断 | ☐ |
| S3 | DEBUG/开关连坐 | 找所有 `if DEBUG` 分支，确认 DEBUG 不牵动限流/验证/加密等安全行为 | 连坐=阻断，拆独立开关 | ☐ |
| S4 | 鉴权覆盖矩阵 | 列出全部路由逐一标注鉴权方式，找「全挂了唯独它没挂」的 | 存敏感数据的接口无鉴权=阻断 | ☐ |
| S5 | CORS 策略 | 查 `allow_origins` | 生产配置 `*` 与 credentials 并用=阻断 | ☐ |
| S6 | 授权字段自报 | 搜请求体 role/permission/is_admin 字段，核对服务端是否从已认证身份**派生**而非采信 | 自报可操纵状态=阻断 | ☐ |
| S7 | 注入防御抽查 | SQL 必须参数绑定（禁拼接/f-string）；用户输入进 `eval/exec/shell/反序列化` 的按敌意数据白名单校验 | 拼接 SQL 或 eval 用户输入=阻断 | ☐ |
| S8 | 输出编码 | 返回前端的动态内容按场景转义；`v-html`/`innerHTML` 标注来源 | 用户可控内容直插=阻断 | ☐ |
| S9 | 暴力破解面 | 「码/验证码/token 验证」端点有无尝试次数限制；比较是否恒时（compare_digest） | 无限次可穷举=阻断 | ☐ |
| S10 | async 阻塞扫描 | `async def` 路由里有无秒级同步调用（LLM/推理/大 IO） | 有=阻断（改 def 或 to_thread） | ☐ |
| S11 | 死代码扫描 | 未被调用的函数、一运行就崩的文件、前端接线后端不存在的按钮 | 带 AI 协作注释的死文件=阻断（删） | ☐ |
| S12 | 调试残留 | print 调试、TODO 密钥、注释里的生产地址 | 重度=阻断，轻度=建议 | ☐ |

> L2 上线前附加（真机部署时追加）：认证端点限流、请求体护栏、响应脱敏、密码 bcrypt/argon2、HTTPS、审计日志 append-only、容器固定版本非 root、`pip-audit`/`npm audit` 高危处理。L3 企业级按需（SBOM/IaC/K8s/许可证扫描），不适用注明。

## K 节 · 对外陈述口径（有对外输出必检）

**四条核心规则**：① 任何对外数字必须齐**四件套**（来源命令 / 样本量分母 / 统计口径含置信区间 / 生成日期）；② **过期即禁写**——数字日期早于最后一次评测日期就不许对外写；③ **引用必须可验证**——commit/路径/函数名要能被一条命令证实；④ **AI 协作必须披露**——署名带 AI 标识、README 声明参与范围。

| # | 检查项 | 方法 | 阻断标准 | 结果 |
|---|---|---|---|---|
| K1 | 对外数字齐四件套 | 逐个数字查来源命令/样本量/口径/日期 | 缺任一 → 删除或补齐 | ☐ |
| K2 | 数字不过期 | 比对 `@日期` 与最后一次评测日期 | 早于 → 重跑或删除 | ☐ |
| K3 | commit/路径引用有效 | `git cat-file -t <commit>` / `Test-Path <file>` | 引用不存在对象 → 阻断（幽灵引用比不写更糟） | ☐ |
| K4 | 比率分母交代 | 查每个百分比的样本量 | 分母 < 30 或未说明 → 必须写明 | ☐ |
| K5 | 小样本加不确定性说明 | 样本 < 100 的对外指标 | 无置信区间且用于结论 → 阻断 | ☐ |
| K6 | 「训练/微调」有指标落档 | 找 mAP/loss/评测报告 | 声称训练过但无指标 → 不许写「训练」 | ☐ |
| K7 | 权重/数据集可获取 | 查获取路径与许可 | 别人拿不到 → README 说明来源或标「私有」 | ☐ |
| K8 | AI 署名带标识 | `git log --format='%an <%ae>'` 逐个看 | 真人化假名/假企业域名 → 阻断 | ☐ |
| K9 | README 声明 AI 参与范围 | 读 README 声明段 | 无声明 → 补 | ☐ |
| K10 | 简历/作品集与仓库一致 | 逐条对照主张与仓库事实 | 任一主张无法在仓库验证 → 改简历或改仓库 | ☐ |
| K11 | 无「用考卷练题再考同一张卷」 | 查评测集是否同时用于调参与汇报 | 是 → 必须标注并补独立验证集 | ☐ |
| K12 | 「杜绝/100%/全部」有全量证据 | 查是否为跳过的检查 | 未全量验证 → 降级为「已验证范围：X」 | ☐ |

## F 节 · 收尾与推送检查（要交付/推 GitHub 的项目）

| # | 检查项 | 判定方法 | 通过标准 | 结果 |
|---|---|---|---|---|
| F1 | 评测/测试全量重跑过，对照开工前基线 | 检查收尾当日的全量输出（接测试纪律验收） | 有当日全量结果，无回归未说明 | ☐ |
| F2 | CHANGELOG 已更新 | 本流水线做了什么/解决了什么有记录 | 有本阶段条目且数字带日期 | ☐ |
| F3 | 台账已归档 | `docs/pipeline/台账_归档_YYYYMMDD.md` | 归档文件存在 | ☐ |
| F4 | 无绝对本机路径 | grep `D:\\`、`E:\\`、`C:\\Users` | 零命中（相对形态表达） | ☐ |
| F5 | 无密钥/隐私数据 | grep 密钥模式；检查示例数据 | 零命中 | ☐ |
| F6 | AI 署名带标识 | 提交者/角色卡署名检查 | 符合 K8 标准 | ☐ |

## 验收结论

- 放行标准：S 节零阻断 + K 节零阻断（有对外输出时）+ F 节全勾（要推送时）。L1 全绿报告是收尾（⑫）的放行凭证。
- 阻断项处理：切修复卡修复 → **复跑该节**，全绿放行。改口径四选一：改简历 / 重跑评测 / 补证据 / 删数字。
- 项目归档时本文件锁定派生版本 v1.3.0；模板源头升级不追溯本项目。
