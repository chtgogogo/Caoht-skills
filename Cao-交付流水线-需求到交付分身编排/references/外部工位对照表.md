# 外部工位对照表（市场插件可选外挂 · 接线不改骨）

> **两条硬规则，凌驾本表一切内容**：
> ① **产物一律落 `<项目根>/docs/pipeline/`**——外部插件默认往自己的目录写（见 §三第 2 条），派遣时必须显式改道，并把它实际写到哪记进台账与 `state.json`。
> ② **判定权与结论永远在本地**——外部 skill 可以产出内容（设计物、字段、清单、模板），**不得**替本流水线做"通过/不通过"结论，也不得改写本库的红线与五态判定。
>
> 定位：本表只登记"哪些工位可以让市场插件顶、借它什么、本地仍管什么"。启用是**按需**的，不启用不阻塞流水线（与 §〇 依赖自检同一降级思路：缺就当没有）。

## 一、工位对照

| 工位（流水线步） | 可外挂的外部 skill | 借它什么（本地没有的） | 本地仍管什么 |
|---|---|---|---|
| ① 磨设计 | `product-design:frame`（无 PRD 方向探索，5–10 轮强制收敛）/ `:scope`（有 PRD 拆设计字段并标 gaps） | 盘问的**分档结构**与"新产物/改版/方向"三入口分流 | `设计纪要.md` 落盘口径、②选型树、用户拍板权 |
| ③ PRD | `product-design:prd`（8 段，含 Given/When/Then 与上游设计资产引用）/ `pm-output-engine:需求文档撰写`（9 段，含策略矩阵/排期规划/协作流程/风险应对 + HTML 单文件模板） | **策略矩阵、排期、协作流程、风险应对**四段（本地 PRD 缺）；对外汇报用的 HTML 形态 | 全局验收标准、落盘 `PRD.md`、③→⑤ 的卡切分输入口径 |
| ⑤ 切任务卡 | `product-design:stories` | JTBD + 验收标准 + 设计触点的**用户故事写法** | 卡粒度判定、一卡一文件、⑦验收先于实现 |
| 设计专项（⑥ 前按需插一个工位） | `:sitemap`（IA 骨架）/ `:flow-web`、`:flow-mobile`（多屏 flow）/ `:edge`（6 类异常态穷举）/ `:chart`（图表选型与规格）/ `:board`（情绪板 → `design-tokens.json`）/ `:motion-plan`、`:motion-apply`（动效规范与实施） | 成体系的设计产物与规格表（本地只有原则型前端 skill） | 卡内验收、⑪双评审、实现由 ⑥ 派遣执行 |
| ⑬′ 无障碍 | `product-design:access` | WCAG 2.1 清单化条目与法规依据表 | **判定已收编进本库 `Cao-项目验收官` 第五层**（五态 + 四探针 + P 级映射），插件只作可选上游 |
| ⑭ 对外陈述 | `product-design:pitch`（6 段决策叙事）/ `pm-output-engine:数据汇报文案`（一句话摘要 + pp/%/稳定期三段叙事） | 汇报**骨架与话术组织** | **⑭ 的数字四件套门禁不可让渡**（来源命令/样本量/口径/生成日期，过期即禁写） |
| 调研（横切） | `pm-output-engine:竞品行业调研`（强制联网三轮检索 + 每条注 URL + 事实/推测/观点三分 + 来源可信度 P0–P4） | 市场与竞品侧的成体系调研流程与 HTML 产出 | `技术调研`（一手 API/文档事实入 repo MD）——**两者各管一侧，不互替** |
| 专利（本地无对应步） | `pm-output-engine:专利文档生成`（实用新型**交底书** 10 节，非权利要求书） | 直接可用，本地零覆盖 | 落盘目录与命名由本地定；依赖外部 docx 生成能力 |

## 二、不并入清单（重叠且本地纪律更强 → 只借字段，主干留本地）

| 外部 skill | 本地对应 | 为什么不并 |
|---|---|---|
| `check` / `qa` / `audit` | `Cao-项目验收官`、`代码审查-双轴PR改动审查` | 三者 findings **无证据槽**（字段仅 category/severity/description/suggestion/location），"待确认/N/A"有但无"原始输出落盘"；本库是五态 + 命令与退出码 + `文件:行号` + 三禁反作弊 |
| `retro` | `证据复盘-AI编程对话转九段可核验证据链` | 它只要求"对照实际度量（如有）"，无数据即靠口述；本库要求证据链可核验 |
| `prd` / `需求文档撰写` | 流水线 ③ | 双 PRD 生成器 = 双入口必打架；且 `需求文档撰写` 只要求"有数据支撑"，**无引证与禁编造条款**，弱于 ③+⑭ 的组合 |
| `stories` | 流水线 ⑤ / `需求转Issue` | 借写法不借流程：它不产出可执行卡，也不带"验收先于实现" |
| `frame` | `头脑风暴-先想清再写码` | 本库更严（批准后为实现前置门），借它的三入口分流即可 |

## 三、启用姿势（三条，缺一即视为未启用）

1. **调用**：Qoder 宿主用限定名（`product-design:prd`、`pm-output-engine:需求文档撰写`）经 skill 调度入口调用；未装该插件的机器整段忽略。**插件本体只读**——它装在 `plugins\cache\qoder-marketplace\<插件>\<版本号>\skills\`，**带版本号目录，升级即另开新目录**，任何写进插件的改动当场作废。
2. **落盘改道**：外部插件写自己的 `spark-output/…`（它的协议文档另有 `.spark/…` 写法，两份不一致，实测 28 份 SKILL.md 全用 `spark-output/`）。派遣提示词里必须显式写"产物写到 `<项目根>/docs/pipeline/外部/<skill>/`"，并把实际路径记进台账与 `state.json` 的 `artifacts.external`。
3. **token 闸门**：外部 skill 单个正文 500–1350 行（另需读它的协议文档约 34KB）。一次只启用**一个**工位，只在"确需它的产物形态"时启用；本地细则能解决的不启用。

## 四、撞词消歧（谁优先，用户不必点名）

| 用户说 | 优先 | 补充 |
|---|---|---|
| 验收 / 上线前检查 / 挑毛病 / 能不能上线 | 本地 `project-acceptance` | `check`/`qa`/`audit` 仅在"纯设计稿审查、无代码可测"语境作可选上游 |
| 写 PRD / 需求文档 | 本地流水线 ③ | 要 HTML 汇报版或九段式 → 借模板段，不借它的判定 |
| 复盘 | 本地 `证据复盘` | `retro` 仅在已跑通设计链路（读了它 19 个上游 context）时用 |
| 做页面 / UI / 好看点 | 本地 `前端设计指南`、`高品质前端设计`、`前端开发` | 要成体系的 flow / IA / 异常态 / 图表规格 / 动效 → 外挂 |
| 无障碍 / a11y / WCAG | 本地验收官**第五层**（已收编，含判定纪律） | `access` 只补清单细节 |
| 竞品 / 行业调研 | `pm-output-engine:竞品行业调研`（市场侧） | `技术调研`（技术一手源侧），按调研对象分家 |

## 五、维护

- 外部插件升级或换版后**先复扫再采信**：它的 skill 数、路径、字段可能变；本表按 `路径:行号` 记的判断过期就改本表（本表是指针型文本，只写现状，不记"上一版曾如何"）。
- 新增外挂工位 → 同步 `__SKILL详细名映射表.md` 与本库 CHANGELOG；改完跑 `py <你的技能库>\__tools\lint_skill.py <本 skill 目录>`。
