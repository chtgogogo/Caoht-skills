# 阶段⑥ 执行与派遣 + 阶段⑪ 评审

> 两种执行模式，探测环境后自动选，用户可覆盖。产出物：完成的代码 + 更新后的卡状态 + 台账行。

## §1 模式探测与选择

| 环境 | 模式 | 说明 |
|---|---|---|
| 当前工具支持派生子代理（ZCode / Claude Code 等） | **自动子代理模式** | 主会话当项目经理，逐卡派遣，可自主连跑多卡不偏航 |
| 不支持子代理，或用户想亲自控节奏 | **提示词卡模式** | 主会话为每卡生成一张"新窗口提示词卡"，用户复制粘贴到全新对话执行，完成后把结果带回 |

探测方法：尝试调用子代理能力（或查工具说明）；不支持则自动落提示词卡模式并告知用户。**用户随时可说"这张卡我自己开窗口跑"。**

## §2 自动子代理模式（superpowers: subagent-driven-development）

每张卡的派遣循环：

1. **装配上下文（最小化铁律）**：只喂给子代理——该卡全文 + PRD 相关章节 + 涉及文件的精确路径 + 全局约束（编码纪律）。**绝不喂**：其他卡的过程、对话历史、全项目文件。
2. **派遣执行**：子代理按卡实现，返回：改动文件清单 + 验收命令输出 + 一段完成摘要。
3. **双评审**（企业模式 / 重要卡）：
   - 评审 A（设计符合）：派"评审员子代理"对照 PRD 与卡验收，逐条判定；
   - 评审 B（代码质量）：派"质量评审员"按严重度报问题（阻断/建议）。
4. **阻断处理**：有阻断级问题 → 带评审意见**重派同一子代理任务**（新分身，附评审意见）→ 再评审；最多 2 轮，仍不过则升级给用户。
5. **过卡**：通过 → 更新台账（该卡移入"做完"区）→ git 提交（信息含卡号）→ 下一卡。

## §3 提示词卡模式（无子代理环境的等价物）

为每张卡生成一段可直接复制到新对话的提示词，内含：

```text
你是本次任务的执行工程师。只做下面这一张卡，做完即停：
【此处粘贴整张卡文件内容】
全局约束：{编码纪律/代码风格一句话}
完成后输出：改动文件清单 + 验收命令的完整输出 + 三句话总结。
```

用户带回结果后，主会话按 §2.3-2.5 相同标准验收、更新台账。**用户也可以选择自己亲自执行**——卡模板已按"有判断力的成人"写好。

## §4 里程碑回看联动

每完成约 1/3 卡数，暂停派遣，执行 里程碑回看.md（见该文件），再继续。

# 阶段⑪ 代码评审（两层）

## 卡级评审（每次派遣后，轻量）
- 评审 A：符合设计吗（对照卡的验收逐条）
- 评审 B：代码质量（命名/边界/重复/安全隐患）
- 输出：严重度分级意见（阻断 / 建议 / 备忘）

## 里程碑总评审（每 1/3 进度，企业模式，重量级）
- 跨卡一致性：接口风格、错误处理、命名是否统一
- 架构漂移检查：实现是否还长在设计的样子
- 性能与安全抽查
- 产出：回看报告.md 的评审章节；阻断项回炉
