# 工具箱（大型模式外挂 · 默认不进主流水线）

> 这些工具**默认不用**。满足触发条件时，主 skill 向用户提示（"检测到项目规模较大，可启用 XX，要开吗？"），
> 用户同意才启用。流程步骤越少越好——每个工具都要问"它的产出喂给后面哪一步"。

## T1 · Git Worktrees（多工作树隔离）——企业模式可选
- 干什么：为不同任务/不同分身开独立的物理工作目录，互不干扰地改代码。
- 何时值得：多个子代理**并行改同一仓库的不同卡**、或需要"一个稳定版+一个实验版"同时存在。
- 何时不值得：单线接力开发（默认状态）——增加分支管理成本，零收益。
- 启用提示语：「检测到即将并行执行 {n} 张无依赖的卡。可选：为每张卡开独立 git worktree 隔离改动（更安全，但要管理分支合并）。要用吗？」

## T2 · 知识图谱/代码索引（graphify / AOCI / codebase-memory）——大型模式可选
- 干什么：把代码库构建成可检索的知识图谱/索引，辅助 AI 理解超大项目。
- 何时值得：项目文件数达到"AI 用 Read/Grep 已经读不过来"（数千文件、多语言混合）。
- 何时不值得：中小项目用 Read/Grep 足够；构建图谱本身消耗 token 与时间。
- 启用提示语：「检测到项目文件较多（{n} 个）。可选：构建代码知识图谱加速后续检索。要开吗？」
- 注意：AOCI 属独立治理生态（MCP 服务），启用前确认其会话规则，勿与本 skill 台账体系混写。

### 外部工具安装提示（判定需要但未安装时）

| 工具 | 是什么 | 判定需要的时机 | 未装时的话术 |
|---|---|---|---|
| graphify | 代码知识图谱构建工具 | 步⑨图谱外挂被启用、且项目大到 Read/Grep 扫不动 | 「建议安装 graphify（代码知识图谱构建），装好后 AI 能秒级检索整个项目结构。你自己装，还是我帮你装？」 |
| aoci | 代码认知索引 MCP 服务（AOCI 生态） | 大型模式需要全量代码索引/治理认知 | 「建议安装 AOCI（代码认知索引 MCP 服务）。你自己装，还是我帮你装？」 |
| codebase-memory | 代码知识图谱 MCP 服务（索引/检索/架构分析） | 需要架构总览、调用链追踪、代码检索加速 | 「建议安装 codebase-memory（MCP 服务，提供架构分析与代码检索）。你自己装，还是我帮你装？」 |

**话术纪律**：先判断需要（项目规模/任务性质），再提示；让用户**二选一**（自己装 / 让 Agent 帮装），不默认代装；
用户本机若已装（检测到对应 MCP 工具可用）则直接使用，不再提示安装。

## T3 · 强 TDD（测试先行）——用户明确要求时
- 默认形态是"验收先于实现"（见 阶段⑤切任务卡.md §4）。
- 用户明确说"我要 TDD"时升级为严格形态：先写失败测试 → 看失败 → 最小实现 → 看通过，每卡如此。

## T4 · Docker/容器化交付——部署阶段可选
- 收尾时若用户要"可移植交付"，提示启用 Dockerfile / docker-compose 生成任务卡（作为一张普通卡走标准流程）。
