# 里程碑回看（阶段⑩）

> 触发：每完成约 1/3 卡数**自动插入**（主 skill 计数达到阈值即暂停派遣执行本文件）；
> 用户任何时候说"回看一下/停一下复盘"也可手动触发。
> 产出物：`<项目根>/docs/pipeline/回看报告_YYYYMMDD.md`——没有产出物的回看 = 空转。

## 回看五问（逐项作答，用实证不用感觉）

1. **验收真相**：已完成的卡，验收是"命令跑出来的"还是"口头宣称的"？有没有卡是评审放水过的？
2. **设计漂移**：现在的实现还长设计（PRD/设计纪要）的样子吗？哪些地方走样了、走样是变好还是变坏？
3. **新需求盘点**：开发过程中冒出了哪些新想法/新需求？（记进 PRD 的 P1/P2 或 backlog，不立即做）
4. **节奏与依赖**：台账里有没有卡在阻塞区超 24 小时？剩余卡的顺序要不要重排？
5. **下一步建议**：继续按序 / 调整卡 / 升降级模式（标准↔企业）/ 建议用户介入什么。

## 报告格式

```markdown
# 回看报告 {日期}（完成 {n}/{N} 卡）
## 五问结论
1. 验收真相：…
2. 设计漂移：…
3. 新需求：…
4. 节奏与依赖：…
5. 下一步建议：…
## 需要用户拍板
- {逐条列出，用户答完才继续派遣}
```

**纪律**：回看发现阻断级问题（如设计本身错了、前卡质量塌方）→ 停止派遣，先修复再继续；回看报告未获用户确认前，不开新卡。
