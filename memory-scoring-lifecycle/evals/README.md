# 效果评测基线（evals）· memory-scoring-lifecycle

回答一个问题：**装上这支技能，比不装好在哪？**
它不是单元测试——单元测试管代码跑不跑，这里管**技能有没有改变结果**。
没有基线对比，"我加了规则所以变好了"就只是一句主张。

## 三态取样（每格都要跑齐）

| 态 | 是什么 | 怎么取 |
|---|---|---|
| A 无技能基线 | 只给任务本身，不给任何规则 | 写一个「朴素代理」：只做任何人都会做的最小动作，**故意不带纪律** |
| B 升级前 | 改动之前的旧版本文件 | `git show <旧版本号>:<文件路径>` 抽出单独放一处 |
| C 当前版本 | 手上这份仓库里的文件 | 直接用 |

🔴 顺序要求：这批改动里若含仓库合并/改名，**先把合并做完再取 B 态**，
否则 B 指向的历史版本在合并后可能不再是同一批文件的形态，读数解释不了。

## 两条信道

- **脚本信道**：确定性夹具 + 判据脚本，同一份输入分别喂三态，逐格落原始输出。可复现、可机器判。
- **回放信道**：把同一句话的任务，分别交给「没有技能的执行器」和「只给它这一份 SKILL.md 的执行器」，
  比较行为差异。唯一变量是技能正文。每格 n=1，必须如实标注，不许拿单趟读数当稳定结论。

## 判据的三条硬要求（做不到就别记数字）

1. **每把尺子必须先能红**：喂一份已知坏样本，它必须报红；再喂一份好样本，必须不报红。
   恒真（永远绿）与恒假（永远红）都是假读数。一批读数全同值＝当场判尺子坏了。
2. **护栏句不许被当成主张**：本支正文写着「推不出就说推不出」，正则直接搜"没有发现"会把
   **加了护栏的那一态判红**——尺子反过来惩罚进步。否定/禁止/排除窗口必须先剔掉。
3. **缺字段报「没有这个读数」，不许猜 0**：猜 0 会把「没测到」写成「测了且为零」。
   同理，指标要分三态读：`0`（测了且为零）／`不测这一轴`（该场景没有这个面）／`非零`，混为一谈就假红。

## 判定词汇

- `PASS` / `FAIL`：按判据读到的事实。
- `N/A`：**该态压根没有这个检查面**（基线不调用取号器，就没有"重跑撞号"这一格）。
  N/A 不作差分依据，**也不记成技能增益**。
- **同值格**：三态判定一模一样 ⇒ 只能证明"两版都不出错"，不构成增益证据，要点名。

## 成本口径

`token成本` 与 `耗时` **依宿主而定**：换宿主、换模型、换注入的上下文长度，数字整体漂移。
本模板里这两列只作**同一宿主内**的相对参考，跨宿主不可比，也不进任何对外结论。
脚本信道没有模型调用 ⇒ `token成本` 记「不适用」，不记 0。

## 本支的八个轴（详见 `evals.json`）

召回准不准（M1）／无关查询会不会硬塞（M2）／工具缺件怎么降级（M3）／已授权事项重复问不问（M4）／
只要分析时有没有改库（M5）／中断重跑会不会撞号（M6）／证据不足保不保留未知（M7）／
多技能同装会不会互相污染（M8）。每格另外记七项指标：任务成功率、误触发、无依据结论、
无关写入、询问次数、耗时、token 成本（形状见 `record-template.json`）。

## 怎么自测

1. 按 `evals.json` 的 `fixture` 造夹具——**只用合成条目**，别在真实记忆库上试写入类场景（M4/M5/M6 会碰 `--apply`）。
2. 跑三态，每格落一份 `record-template.json` 形状的记录，外加原始 stdout/stderr/命令 三个文件。
3. 判据先自证（红样本+绿样本各喂一次）再打真读数；自证不过整批不落记录。
4. 汇总保留「未证明」分栏；没跑到的场景写「未跑」，不写「预计没问题」。

## 本支实测踩过的坑（重跑前先看，能省下整整一轮）

- **恒真召回**：排序前不截断，任意查询都塞满 top-K ⇒ "召回很准"永远绿。判据要按**去重后的查询片段数**设门槛。
- **失效口径当现行规则**：本支的升华阈值改过（旧"3 次自动升"已作废，现行是同一 RT 号累计达阈只报候选）。
  判"有没有把旧口径当现行推荐"必须切句＋带否定闸，整行匹配会把答对的一态判红。
- **索引断链**：索引行指向不存在的正文文件。技能侧要点名断链，评测侧要把「引用的 `.md` 路径真的存在」做成独立真值。
- **CRLF 索引**：写索引时既用 `newline="\r\n"` 打开又手工拼行尾 ⇒ 落盘 `\r\r\n` ⇒ 读回行数翻倍 ⇒ 写后验收必然回滚。
  合成夹具若是 LF 就永远看不见这条，重跑时至少补一份 CRLF 样本。
- **跨窗口串台**：会话去重状态若只有一份，A 窗口注入过的行会让 B 窗口读成"已给过"；评测里要么按会话分文件，要么显式关闭。
- **无关写入的读数**：要用目录树摘要（sha256）跑前跑后对账，不能用"我没写东西"的自我声明——
  基线那一态往往真的写了，而它不会承认。
