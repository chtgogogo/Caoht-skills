# Agent 记忆系统 · 调参与溯源手册

> **本手册是设计说明，不构成执行规则**：讲"每条规则为什么这么设计"，供调参与深读；**生效规则以 SKILL.md 为唯一版本源，任何数值/流程冲突时以 SKILL.md 为准**（sc1.3 定位声明）。
> 本手册不重复 SKILL 已有的执行内容（量表全文、模板、六道工序表、收尾清单等一律指针化）；只留三样东西：**调参推导**（为什么是这些数）、**SKILL 没有的判据**（如降格协议、注入防护、月度指标）、**设计来源索引**。
> 检索与工具口径（六道工序/三态出口/占号语义/整理器锁）一律以 SKILL.md §4.1/§4.2/§5/§9.1/§9.2 为准。
> 工具实现细节在 `tools/` 四脚本与 `references/包结构与防腐.md`。

## 1. 这套系统在解决什么问题

| 故障 | 表现 | 对应解法（SKILL 节号） |
|---|---|---|
| ① 上下文撑爆 | 记忆越攒越多，读一遍吃掉全部 token | 渐进披露+硬预算（§4） |
| ② 噪音淹没信号 | 检索 20 条，有用的在第 17 条 | 双轨评分+相关性门槛（§3/§4.1） |
| ③ 记忆自相矛盾 | 新旧结论打架，Agent 随机挑一个 | superseded 失效链（§7） |
| ④ 同一个坑反复踩 | 坑记 100 条，第 101 次照样踩 | RT 同型聚合+≥7 升华（§7） |
| ⑤ 记忆库只增不减 | 三年前的临时信息还占着检索位 | 惰性衰减+归档（§3/§1） |

**④ 最隐蔽也最致命**——它让你以为"已经记下来了"，实际上什么都没改变，所以升华是全系统最重要的一环。
设计目标一句话：**让真正有用的记忆越来越难被忘掉，让噪音尽快消失，且全程不撑爆上下文。**

## 2. 分层依据（九层各自的存在理由）

九层结构、TTL 档与索引上限见 SKILL §1；这里只留"为什么"：

| 层 | 存在理由（一句话） |
|---|---|
| CORE | Agent 每次启动都失忆；但 150 行硬上限逼它只放摘要+指针+铁律 |
| PROFILE | 画像会增长而 CORE 有上限——CORE 只留摘要+指针 |
| WORK | 价值是"接着上次的活干"，跨周即失效，留着只会干扰检索 ⇒ 衰减最快 |
| DETAIL | 事实细节随项目演进过时 ⇒ normal 档 |
| PITFALL | 坑的价值不在"最近"而在"会不会再遇到"——三个月前的坑今天照样救两小时 ⇒ 衰减最慢 |
| REJECTED | **全系统最被低估的一层**：负知识直接砍掉搜索空间，价值常高于正知识；⚠️ 必须真试过、有证据 |
| DECISION | 记**理由**不记结论——结论在代码/文档里有，"当初为什么这么定"才是三个月后找不回来的 |
| FORGOTTEN | 归档保留索引才能找回——多数开源方案只做删除，不做可召回的归档 |
| TRASH | 物理删除不可逆，留反悔窗口 |

**分类判定顺序**（依次问，第一个命中的即归宿，顺序不许跳）：理由→DECISION｜试过不行→REJECTED｜坑→PITFALL｜用户本人→PROFILE｜最近做了啥→WORK｜其他→DETAIL｜通用规律→CORE 铁律。越靠前越不可替代，归错损失越大。

## 3. 评分引擎调参（V/R/0.6-0.4 的依据）

### 3.1 先分清三种时间语义（记忆系统头号 bug 源）

| 语义 | 回答的问题 | 用途 | 落在哪 |
|---|---|---|---|
| ① 新鲜度 recency | 此刻还相关吗？ | **排序** | 情境分 R |
| ② 衰减 decay | 该不该淘汰？ | **归档** | 固有分 V |
| ③ 有效期 validity | 现在还成立吗？ | **正确性** | valid_until/superseded |

混用的三种翻车：用衰减去排序→老但关键的记忆永远沉底（**最常见**）；用新鲜度去淘汰→三个月没碰但重要的被误删；没有有效期→过期事实和新事实打架，Agent 随机挑一个。维护口诀：动分数前先问"我在处理 ①②③ 哪一种"。

### 3.2 V 量表逐项为什么

量表全文与算例见 SKILL §3。逐项依据：

| 子项 | 为什么是这个档位/分值 |
|---|---|
| 基础分 +5 | 保证任何入库记忆至少 5 个衰减周期寿命，不会刚写完就消失 |
| 跨项目通用 +20（最高单项） | 复用最多 |
| 踩坑才得到 +15 必须高 | 重新踩一遍的代价是实打实的 |
| 稀缺性二值 | 模型本来就知道的东西，记下来纯属污染 |
| 用户强调 +20 | 用户意愿权重必须高于 Agent 自评 |

量表拆子项的理由：LLM 直接打分方差极大（同一件事今天 30 明天 50），拆成客观子项才可复现。

### 3.3 为什么相关性(6) > 新鲜度(4)

一条记忆跟当前问题**对不对得上**，比它最近有没有被用过更重要。三档不用连续值：人肉维护场景下连续值既算不准也没必要。

### 3.4 排序公式为什么是 0.6 / 0.4

- **V 必须占主导（>0.5）**：V 是长期验证过的基本盘；权重太低，刚写入、恰好触发词命中的噪音会压过核心知识；
- **R 必须不低于 0.3**：否则"此刻极其相关但分值不高"的记忆永远翻不上来（"8 分的坑记录被 30 分的无关记忆压住"问题）；
- **0.4 是平衡点**：R 满分 10 带来 4 分，相当于 V+40 的效果——够让强相关冷门翻上来，不够让纯噪音（R 通常 1-3）压过高价值。

业界对照：斯坦福 Generative Agents 原始实现 relevance 3.0 > importance 2.0 > recency 0.5，同为"相关性优先"思路（注意：折算后其 importance 权重≈0.36，低于本系统 0.6——同向不同值，本系统的 0.6/0.4 是原创参数，无外部先例）。

### 3.5 加扣分的两层含义（别只做第一层）

① **提高水位**——V 变大排序靠前；② **降低漏水速度**——strength 变大衰减周期变长。只加分不减速，该归零还是归零；**既加分又减速，反复用到的东西才能真正"刻进去"**。为什么纠正最高（+8 强制改写）：被纠正过的记忆是最准确的。为什么"检索出来但没采用"不加分：那不是复习，是擦肩。

## 4. 衰减与间隔重复调参

### 4.1 为什么扣减是 (1 + ⌊V/25⌋)——三方案取舍

- 只扣固定 1：45 分要 45 个周期，slow 档=1350 天，**等于永不淘汰**（"只增不减"的根源）；
- 比例衰减（每周期 5%）：小分数 5→4.75→4.51… 永远逼近 0 到不了；
- **折中**：V<25 扣 1（快速清噪音）；V=45 扣 2、V=75 扣 4、V=100 扣 5——**分越高衰减越快，没有任何记忆能靠"曾经重要"永远霸榜**，高分必须靠持续命中维持。

演算例（V=45/slow/strength=0/last_hit=2026-01-01，今天 08-31 间隔 242 天）：周期数=⌊242/30⌋=8；应扣=8×(1+⌊45/25⌋)=16；新 V=29；新 last_hit=+240 天（余数 2 天不丢）。结算交给 `memory_maintain.py decay`，禁手算。

### 4.2 间隔重复：strength 拉长周期

理论来源 MemoryBank 艾宾浩斯 `R = e^(-t/S)`（闪卡软件同源）。实际周期 = TTL × (1+strength/10)：strength=5→×1.5，=10→×2.0（上限 10：再慢无实际意义）。效果对比：V=45/slow 从没被想起 ≈240 天归零；被想起 5 次后（V≈55、×1.5）≈**590 天**。

### 4.3 TTL 档位为什么是 30/14/7

慢档=坑/否决（价值不随时间快速流失）、normal=事实细节（随项目演进过时）、fast=工作记忆（只在"接着干"时有价值）；三个周期刻意对齐月/双周/周的自然人肉节奏，方便形成维护习惯。

## 5. 检索依据

### 5.1 为什么渐进披露

反例：500 条 × 60 行 = 30000 行一次读入——①撑爆上下文 ②读完反而抓不住重点（注意力稀释）。正解**先便宜后贵**。单库 ≥60 条插「话题段」中间层（检索空间 N→√N）：60 行目录还能一眼扫完，超过则扫目录本身的成本已不可忽略。话题段设计来自 MemoryOS 段页式。
"真到记忆 >200 条再上向量，现在这套够用"——该判断依赖 evals 离线评测轴验证（见 §10）。

### 5.2 触发词分层依据（现行口径＝SKILL §4）

现行：**现象词必填**（2-5 个，用户原话）、实体词尽量、排除词按需（误触发过才加）、本质词＝RT 号。
- 现象词的存在理由（真实教训）：曾因只写技术词，用户说"屏幕上有三个白点"时检索不到 dissolve 着色器的坑记录，白查三轮粒子系统；
- 按需分层的理由：旧制"四层缺一不可"在冷启动期逼人硬凑，"写到第 50 条开始敷衍"——宁可少填不可假填。
- 沿革：v3.2 曾设 surface/entity/essence/alias 四层映射与同义变体层；sc1.3 减负为现行口径，同义命中交给实体词与索引语料两遍扫。

### 5.3 失败响应协议（SKILL 无此表）

| 同一症状第几次 | 强制动作 |
|---|---|
| 1 | 常规修复 |
| 2 | **强制**扫 PITFALL 目录 |
| 3 | **强制**展开全文 + **强制写新坑** |
| 4 | 停下报告请求协助 |

关键在第 3 步——**这是记忆库能自动增长的唯一下水口**：没有它，系统只会消耗记忆，不会积累记忆。

## 6. 写入依据

### 6.1 两步写入法为什么禁止合并（来源 mem0 双 LLM 架构）

"抽取事实"和"决定怎么存"是两种判断；合并成一个步骤时 Agent 会一边读一边决定存不存，该存的漏掉、不该存的写进去。

### 6.2 本质优先、细节按需——判据与 rubric

两条相反直觉各管一半：能抽象成规律的先写规律（防机械记忆）；"光凭本质无法复现"的细节必须写全（防丢参数）。
判据一句话：**三个月后，光凭本质层这句话，还能把这件事重新做出来吗？**——能→不写细节；不能→必须写全。
本质层 rubric：能脱离细节层独立成立，**不含具体参数/时间/人名**（含任何具体值=写得不够抽象）。本质层就是升华的原料，写得越准升华越顺。

### 6.3 confidence 与 sensitive（SKILL 未实现，设计在案）

`confidence: low` 检索降权 30%（比正文手标 `[推测]` 结构化，脚本能识别）；`sensitive: true` 检索只回「有这条」需用户显式要求才展开。⚠️ 两者目前只在本手册层，未进 SKILL 模板与工具实现（企业评审 P0 待办）。

## 7. 冲突与升华依据（含降格协议）

### 7.1 冲突：失效而非删除

来源 Zep/Graphiti 双时间模型，原话："一个无法表示『事实何时为真』的系统，迟早会给 Agent 两个互相矛盾的事实让它挑，这是 Agent 幻觉的第一大成因。"不删的理由："当初为什么这么定"本身有价值。
双向写入来源 A-MEM"记忆演化"；常见错误：每次新信息就新建一条 ⇒ 同一件事 5 个略异版本。正确做法：**让旧记忆变得更准，而不是让记忆库变得更大。记忆网络的价值 ∝ 连接数，不是条数。**

### 7.2 升华：把高加载成本形态压成低加载成本形态

为什么必须升华：100 条记录只在"你已经想到要去查"时才有用；1 条铁律在**每次会话**都自动生效。三级形态（记录→索引行→铁律）来源 MemOS 跨类型转换；核心洞察：**用得越多的记忆，越应该变成加载成本更低的形态**。
产物为什么必写反例：正例告诉你"做什么"，反例告诉你"别做什么"——错误往往是"看起来合理的做法"，反例更能防错。
升华后原记录保留（promoted_to、降 slow）：铁律是压缩版，复杂情况还要回来翻细节。

### 7.3 同型判定的沿革与 RT 词表

沿革一句：最初"同根因≥3 条"不可执行；v3.3 改 `root_cause_signature` 字符串全等；sc1.3 起 **RT 号受控词表判同型**（`RT-xxx|短语`，判同型=RT 号相同，`|` 后仅供人读）、阈值 3→7（天 2026-10-03 拍板）。签名的意义：把本质层再抽象一层，专服务于跨案例同型判定，聚合从主观判断变成 O(N) 机械操作。

### 7.4 铁律降格协议（升华的反操作，SKILL §7 未收录的独占活规则）

CORE 是每轮全读的硬事实层，**过期铁律待在里面 = 每轮给 Agent 注入错误信息**。
```
触发：CORE 铁律被证伪 / 用户说「这条过时了」
动作：
1. 从 CORE 铁律区物理移除（不是标 superseded）
2. 原记录的 promoted_to 清空，status 回 active
3. 新证据已成熟 → 升新铁律，复用旧 R-id（保持引用稳定）
4. 新证据未成熟 → 降为 DETAIL 普通记录，V 设 60
5. CORE 留一条「R-007 已撤回 → det-xxx」指针，30 天后清除
```
铁律要有「撤回窗口」——可能有别的记忆 `links` 指向它，一删了之会断链。

### 7.5 元认知铁律

CORE 铁律区专设子段记 **Agent 自己反复犯的系统性错误**（跨项目）。普通铁律管"这类问题怎么解"；元认知铁律管"我这个 Agent 老爱怎么犯错"。触发：同类错误在不同项目 ≥2 次。

## 8. 遗忘与召回依据

- **复活给 V=8 不给 3**：用户主动找说明有明确需求，给太低会刚复活又死掉白折腾；8 分保证约 100 天正常寿命。
- **主动二次判定**：完全被动的遗忘区会形成信息黑洞——你忘了它存在，它也永远不会自己出现；月度扫 FORGOTTEN 索引与活跃主题比对，是唯一补救通道。
- **永不遗忘白名单**（PROFILE/DECISION/铁律/红线）的共性：**重建成本极高，且衰减不降低它们的重要性**。

## 9. 体检依据

### 9.1 容量红线为什么是这些数

| 对象 | 上限 | 依据 |
|---|---|---|
| CORE.md | 150 行 | Claude Code 实测 200 行/25KB 截断，取 150 留余量 |
| 单库索引 | 80 行 / 60 条 | 超过 80 行扫目录的成本不可忽略 |
| 单条记录 | 120 行 | 超过就该拆或压摘要 |

⚠️ 超限部分是**静默失效**——不报错，是根本不加载。索引膨胀是无声的失效。

### 9.2 月度 5 指标（SKILL 无此设计）

| 指标 | 含义 | 低/降信号 |
|---|---|---|
| 命中率 | 命中且采用 / 总检索次数 | 触发词设计有问题 |
| 升华产出 | 本月新增铁律数 | 同型聚合链路堵了 |
| 召回率 | 「事后发现其实有相关记忆但没检索到」次数 | 检索门槛过严 |
| draft 转正率 | draft→active 比例 | 低=写入闸门太松 |
| 平均 V 分 | 全库均值 | 持续降=写入质量下滑 |

### 9.3 检索日志（会话级，不入库）

`[14:30] query:"手肘响" → L0 路由→PITFALL → L1 pit-003(R=6) → 采用:是 → 预算 180/800, 95/1200 ✅`——价值：调试、体检抽样、发现"从不被用上的候选"（=触发词设计有问题）。

### 9.4 懒迁移

旧格式记录（无 score/ttl/triggers）不批量重写：用到时顺手补 frontmatter，check 持续报告「待迁移」直到归零。旧数据不迁 = 评分/衰减规则对它们无效（真实缺口，check 会一直提醒）。

## 10. 端到端走查（骨架版）

场景：用户说"我做俯卧撑手肘疼怎么回事"。
1. **检索**：CORE 无相关铁律 → PITFALL 索引无"手肘/俯卧撑" → PROFILE 命中"用户有健身习惯"（V=40）→ 展开头部。
2. **对话**：排除关节损伤，确定肌腱滑过骨突，无痛属生理性。
3. **段落结束写入**（两步法）：列事实①手肘弹响=肌腱滑过骨突非损伤→新建 PITFALL；②健身频率高→加固已有 PROFILE（V+5 不新建）。
4. **打分**：基础5+复发15+成本15+稀缺10=V45（量表见 SKILL §3）。
5. **建条目**：frontmatter 按 SKILL §8 模板；触发词按现行分层填现象词/实体词，RT 号填坑类。
6. **三个月后用户再提"手又响了"**：索引触发词精确命中 → R=6+0 → 排序分 5.1 → 读一句话结论即可用；结算衰减 3 周期扣 6，用户提起 +3 → V=42、strength=1（周期×1.1）、draft 命中一次。
7. 半年不再提起：V 一路衰减到 0 → FORGOTTEN 归档保索引。
8. 一年后"去遗忘区找找"：命中复活，V 重置 8。

## 11. 反模式清单（无章节承载或最易犯的八条）

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| 凭感觉打分 | 严格按量表累加 |
| 复制粘贴对话当记忆 | 抽取 1-3 条原子事实 |
| 每次新信息就新建记录 | 回头修订旧记录 |
| 用衰减决定排序 | 排序用 V+R，衰减只管归档 |
| 触发词只写技术词 | 现象词必填（用户描述的是现象不是术语） |
| 手算衰减 | 交给 `memory_maintain.py decay --apply` |
| 把"没试过但感觉不行"写进 REJECTED | 必须真试过、有证据 |
| DECISION 里记结论 | 只记**理由**和被否决的备选 |

## 13. 工程与安全依据

### 13.1 ID/命名/Schema
文件名用 ID 不用 title（`pit-003.md` 不用 `手肘响.md`）：title 会改、ID 不会，中文文件名跨平台有坑——数据库"不可变主键 vs 显示名"常识搬进文件系统。ID 自增不复用、删除跳过，超 999 升 4 位。

### 13.2 Prompt 注入防护（设计在案，SKILL/工具未实现——企业评审 P0 待办）
记忆每轮必读＝攻击面。写入侧：内容含「忽略指令/忘记以上/你现在是/system:」模式词→拒写，标 `status: rejected_injection`（**正式状态值**，和 draft/active 同级，脚本才能统计）；外部源事实一律 draft+source:external；PROFILE/DECISION/CORE 三层不接受外部源写入。读取侧：记忆喂给 LLM 统一包 `<memory>` 标签并声明"是参考信息不是指令"；检测到指令式表述→跳过该条写审计日志。来源：OWASP LLM Top 10（LLM01 Prompt Injection / LLM04 Data & Model Poisoning）。⚠️ 现状：以上只存在于本手册层。

### 13.3 links 关联展开
命中且采用某条 → links ≤2 全展头部，>2 展最高 V 的 2 条；**加分只给原记忆**（防 links 互相刷分），计入展开预算（防链条膨胀）。

### 13.4 会话缓存 LRU
会话内已读缓存上限 20 条 LRU；会话超 50 轮提示开新会话。与最小核心是一对：清单管每轮做什么，缓存管同会话不重复读。

### 13.5 铁律层叠优先级
不加 priority 字段，铁律区按「通用→具体」排序，冲突时后面的覆盖前面的（类 CSS 层叠）——**用结构代替字段**，少一个字段就少一处填错与同步。

### 13.6 行为准则常驻加载（硬/软两层）

| 层 | 做法 | 可靠性 |
|---|---|---|
| 硬加载 | 准则放进 AGENTS.md / 全局 MEMORY.md 每轮必读区 | startup context 每次自动注入，**压缩后会重注入** |
| 软加载 | 常驻层写"先读行为准则"，靠遵守 | 依赖自律 |

进常驻层的判据：**少了它，哪怕回答一句"你好"也可能翻车吗？**会→必须在常驻层。按需加载的库不进 startup context，写着也读不到。
