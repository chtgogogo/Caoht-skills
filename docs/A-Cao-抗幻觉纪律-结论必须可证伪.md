## 第 0 章 五分钟速览

1. **它管的不是"别编造"，是"话怎么下"。** 全skill只干一件事：把「结论」拆成可检查的零件——来源、时点、证据强度、置信度、推翻条件——缺零件就不许把这句话当结论说出口。[实测]（正文「〇、一句话」与「一、分类口径」）
2. **一切回答之前先做四分类**：每条信息必须归入 已验证事实 / 当前假设 / 未知 / 已证伪 之一，且在回答里**显式写出**是哪一类。证据不足就写"未知"，禁止用推测填补空白。[实测]（正文「一、分类口径」）
3. **十二条纪律，条数是锁死的。** v1.1 并入"先验尺子再信读数"这条重要纪律时，特意**塞进第 3 条而不是新开第 13 条**——因为"12 条""核心 5 条"这些计数被好几处派生文件引用，加一条就要同步一片。[实测]（正文「版本」v1.1 段自己写明了这个取舍）
4. **最硬的一条是第 3 条**：它要求验证闭环留下四要素记录（命令 / 环境 / 输入 / 输出），还要求**先证明那把尺子会红**才准相信它报的"通过"。这是十二条里唯一有"物证形状"的条款。[实测]（「二、十二条」第 3 条）
5. **五种东西不算新证据**：情绪、重复、对方身份够权威、多数人都这么说、说话人自己很自信。**只有新证据或更强的逻辑才准改口**，而且改口要留四步记录。[实测]（第 6 条）
6. **高风险判断固定四段输出**：【已验证事实】【核心假设】【潜在反例/风险】【下一步验证建议】。低置信度的内容不许用确定语气说。[实测]（第 7 条）
7. **它是"结论层"，与另三件分工**：写码归编码行为准则、测试证据长什么样归测试纪律、文件写哪个盘归磁盘缓存纪律。——注意：这句"四件互不重叠"的声明和正文第 3 条实际管的范围有冲突，见第 3 章 3.4 节。[实测]（「四、与其它三件纪律的边界」）

**一句话设计目标**：让 AI 说的每一句结论都能被追问三件事——**你从哪儿知道的、什么时候知道的、什么情况下这句话作废**；追问不出来的，就不配叫结论，只配叫观点。

## 第 1 章 这套系统在解决什么问题

先说清一个容易被误解的点：**幻觉不是"AI  random 胡说"，它高度集中在几个固定场景**。这支 skill 的全部结构就是照着这些场景堵洞的。

| # | 故障 | 日常表现（读者能感觉到的） | 本 skill 的解法 | 出处 |
|---|---|---|---|---|
| ① | **把假设当事实说** | 语气笃定，读者照做，结果前提从一开始就没验证过 | 四分类强制显式标注 + 低置信度禁用确定语气 | 「一、分类口径」、第 7 条 |
| ② | **顺着用户的前提往下推** | 用户说"因为 X 所以 Y 对吧"，AI 立刻在 X 成立的前提下算 Y；X 本身是错的，后面全白干 | 第 2 条：用户给的解释/诊断/方案**一律视为待验证假设**，前提缺依据先指出并修正，不照办 | 第 2 条、「三、高频翻车场景」表"用户给了个前提"行 |
| ③ | **宣布修好了却没跑** | "改完了，应该没问题"——一次都没执行过 | 第 3 条验证闭环 + 翻车表第一行强制"跑一次给原始输出" | 第 3 条、「三」表 |
| ④ | **凭记忆写标识符** | 版本号、提交号、API 名、路径写得很顺，但那个对象根本不存在 | 翻车表"引用版本号/提交号/API 名/路径"行：**引用不存在的对象 = 阻断** | 「三」表 |
| ⑤ | **拿"我记得"当依据** | 引用一个三年前的数字，直接当现状用 | 第 9 条证据分级把"记忆"钉在 C 级（只作线索，不作依据）；第 8 条要求旧快照结论标"可能过期" | 第 8、9 条 |
| ⑥ | **被压力推着改口** | 用户一不高兴、一重复、一搬出处分，AI 就换答案 | 第 6 条：情绪、重复、权威身份、多数意见、自信程度**都不算新证据** | 第 6 条 |
| ⑦ | **越说越邪乎** | 提出一个反常识的大胆判断，证据却和最平庸的判断一样多 | 第 12 条奥卡姆剃刀后半句：**越反常识的主张，要求越强的证据** | 第 12 条 |
| ⑧ | **判据本身是坏的** | 检查项全绿、"零命中"、"没报错"，于是宣布通过——而那把尺子从构造上就不可能报红 | 第 3 条并入段"先验尺子，再信读数"三条子机制：同源单变量不算数 / 阴性必配阳性对照 / 变异检验要点名该翻红的那一条 | 第 3 条 |
| ⑨ | **规则写了没人读** | 整套准则躺在长期规则目录里，没有任何自动入口，正文 12 条实际从未被加载 | v1.0 把它封装成带触发描述的 skill（description 里写满触发场景与危险短语），让它在相关任务里被自动选中 | 「版本」v1.0 段"起因" |

**这九条里最隐蔽的是 ⑧。** ①—⑦ 都是"AI 偷懒"，读者凭常识还能察觉不对劲；⑧ 是**AI 很勤奋地跑了一整套检查、检查全绿、结论也确实有"实测痕迹"，但那个绿是假的**——因为产生"通过"这句话的判据本身没有鉴别力。v1.1 专门为此并了一段机制进第 3 条，这也是本 skill 唯一一次在 v1.0 之后动过正文实质内容。[实测]（「版本」v1.1 段写明"此前这条纪律散在四处却不在 12 条里"）

**也最容易被人误读的是它的定位**：本 skill **不是**知识问答的准确度保证，**不是**模型层面的事实校验，它是**输出格式与决策流程的约束**。它假定"验证"这件事有成本，于是用第 4 条的风险分级把成本按影响大小分配，而不是要求每句话都跑一遍实验——这是它和第 1 章 ①—⑨ 之间真正的调和方式。[实测]（第 4 条三档分档）[推演] 若取消风险分级、要求所有陈述一律走完整闭环，具体会出问题的输入是"这个函数返回值是 int 还是 str"这种 2 秒可查的问题也要写四段模板 + 留四要素记录，读者拿到的信息量不变而成本上升十倍，最终结果一定是执行者偷偷跳过整条纪律——纪律一旦在低成本场景显得荒谬，它在高成本场景也守不住。

## 第 2 章 术语表

本 skill 的术语一半是认知科学词，一半是工程黑话。**每个词后面都跟一句大白话**（这也是本页的写法规矩）。

| 术语 | 一句大白话 | 在本 skill 里的具体含义 |
|---|---|---|
| **可证伪** | 能事先说出"什么证据会证明我说错了" | 第 8 条：重要结论必须写明推翻条件；写不出推翻条件的断言，降级成"观点"而不是结论 |
| **四分类** | 把一句话分成"确定的事实/我暂时的猜测/我不知道/已经证明不成立" | 「一、分类口径」：已验证事实、当前假设、未知、已证伪 |
| **置信度** | 你自己觉得这话有几分靠谱，用 0 到 1 表示 | 第 3 档区间表：高 0.8–0.95 / 中 0.4–0.7 / 低 0.1–0.35（数值区间含义见第 4 章） |
| **证据强度** | 支撑这句话的东西有多硬 | 第 9 条的 S/A/B/C 四级 |
| **推翻条件** | "如果看到 X，这句话就不成立了"里的 X | 第 1、8 条要求重要结论必带 |
| **贝叶斯更新** | 拿到新线索就把原来的判断按比例改一改，而不是死守或全盘推翻 | 第 6 条：只在**新证据或更强逻辑**下改口 |
| **确认偏误** | 只找支持自己结论的证据，反面证据自动看不见 | 红队三问的第 ① 问专门问这个 |
| **红队** | 自己站到对面当对手，专门找自己结论的漏洞 | 第 10 条：结论输出前自问的三句话 |
| **稻草人式反驳** | 把对方的观点替换成一个更弱的版本再去驳倒它 | 第 5 条禁止；要求反驳前先构造**最强**反方论证 |
| **最强反方论证** | 用对方最好的理由把话说一遍，再驳 | 第 5 条要求的动作 |
| **奥卡姆剃刀** | 证据差不多时选假设更少、更简单的那个 | 第 12 条前半句 |
| **验证闭环** | 假设 → 最小验证 → 记录 → 对照下结论 → 修正再验，一圈走完 | 第 3 条；记录要素是 命令 / 环境 / 输入 / 输出 |
| **判据** | 可执行的判定标准（"什么算过、什么算不过"那条线） | 第 3 条并入段的核心对象 |
| **鉴别力** | 一把尺子能不能把坏的东西量出红来 | 并入段子机制①：无鉴别力的判据几条共用同一个可疑变量，全绿不算数 |
| **恒真判据** | 构造上永远为真的检查（怎么坏都报绿） | 并入段要抓的目标之一 |
| **阳性对照** | 先拿一个"已知一定能过"的东西试一次尺子，确认尺子本身在工作 | 并入段子机制②：阴性结论必配一次；对照跑不出来记 **VOID（尺子作废）**而不是 PASS |
| **VOID（尺子作废）** | 这次检查不采信，既不算通过也不算失败，只是"未评估" | 并入段：**未评估 ≠ 通过** |
| **变异检验** | 故意把东西改坏一下，看检查会不会翻红 | 并入段子机制③：必须**点名该翻红的那一条**，只要求"整套变红"抓不出恒真判据 |
| **零命中** | 搜了一圈没找到任何匹配 | 本 skill 把它归为"阴性结论"，因而必须配阳性对照 |
| **读回 / 回读** | 写完文件后换一条路把它再从磁盘读一遍确认 | 「三、高频翻车场景」表第二行指向的四步流程 |
| **工具回执** | 工具自己说"我写成功了"的那句话 | 表第二行明确它**不算证据** |
| **常驻层** | 每次对话一开始就被塞进上下文的那几行精简规则 | 「定位」段与 v1.0 段：完整版 12 条 vs 常驻 4–5 条（清点见 15.4） |
| **触发词** | description 里写的、让系统在相关任务里自动选中本 skill 的场景关键词 | frontmatter `description`，184 字符 |
| **渐进披露三层** | 名字+描述（开局常驻）→ 正文（触发才读）→ 附属文件（按需再读） | 本 skill 只有前两层，第三层为 0 个文件（见 15.3） |
| **S/A/B/C 级证据** | 按来源硬度给引用分四档 | 第 9 条表：S 官方文档/源码/可复现结果，A 日志/测试/实测，B 权威二手，C 直觉/记忆/传闻 |
| **权威二手** | 别人转述的官方内容（比如某篇讲官方规范的技术博客） | B 级：**需交叉验证**，不可单独支撑结论；该词在本 skill 里未定义边界（问题见第 6 章 6.3） |

### 3.2 为什么是这个顺序（判定顺序，不是排版顺序）

D → E 的先后是**强制的执行顺序**，正文「一、分类口径」标题后面直接写了"先做这一步，再回答"。完整执行链是：

```
第 0 步  要不要触发本 skill（看 description 的场景，或危险短语「修好了/没问题/应该可以/我记得是/通常是」）
第 1 步  四分类：把手上每条信息落到 事实 / 假设 / 未知 / 已证伪  [「一」，明确要求"先做这一步"]
第 2 步  审查前提：用户给的前提是否成立  [第 2 条]
第 3 步  定风险档：低 / 中 / 高  [第 4 条] —— 这一步决定后面花多少成本
第 4 步  取外部证据 + 先验尺子  [第 3 条及其并入段]
第 5 步  给证据分级标注  [第 9 条]
第 6 步  主动寻反例 / 构造最强反方  [第 4 条后半、第 5 条]
第 7 步  红队三问  [第 10 条]
第 8 步  按输出形状说话（高风险走四段模板）  [第 7 条]
第 9 步  若与旧结论不同：写改口四要素记录  [第 6 条]
第 10 步 若证据不足：直接说不知道 + 给验证路径  [第 11 条]
```

[实测] 第 1、2、8、9、10 步都对应正文明确写出的动作句；第 3—7 步的顺序是从各条文的前置关系推出来的整理，正文只写死了第 1 步（"先做这一步，再回答"）和第 3 步的档位效应。[推演] 若第 3 步（定风险档）被挪到第 4 步之后，会出现的实际问题是：先跑了完整闭环才发现这是个"低影响"问题（比如"这个函数返回 int 还是 str"），白付一遍成本；反过来若第 3 步挪到最前面、压过第 2 步，则会出现"判定为高影响于是直接跑了完整闭环"，但整条闭环建立在用户那个未经审查的前提上——具体翻车输入："帮我把这个 500 人的表按用户说的'只有我用这一个筛选条件'重新导出"，前提不成立时越完整的验证越贵。

### 3.3 两层加载结构（常驻层 / 完整版）

正文「定位」段声明：常驻层已经内嵌了 4–5 条核心在另一份团队共享的常驻行为准则文件里（该文件把这一节编号为 §10），而**本文件是完整 12 条的权威版，触发即在此执行**。[实测]

这是一个**双层设计**：

- **常驻层（每次对话都在上下文里）**：只放能靠"句式检查"就守住的少数条。实测那份文件此节列了 **5 条**：分清事实/假设/未知、外部证据优先（含"先验尺子再信读数"的压缩表述）、编码前先加载编码准则、结论可证伪可追溯、测试证据必须落盘。[实测]
- **完整版（触发才加载）**：12 条全量 + 翻车表 + 边界表。

两层之间的分工逻辑很实用：**常驻层负责"不许说谎"，完整版负责"怎么说才算有据"**。这也解释了为什么常驻层把"先验尺子"也压进去了——那条是 2026-10-03 才发现的、代价最高的失效模式，等不到触发再读。[实测]（常驻层文件此节确实带着这段压缩表述，并回指"完整表述只在 skill `anti-hallucination-discipline` 第 3 条"）

⚠️ 但**两层设计的成本是必然漂移**，见第 10 章 10.3 节。

### 3.4 「互不重叠」声明与正文的自相矛盾（一处实测缺陷）

「四、与其它三件纪律的边界」表把地盘划成 4 行，并配合「定位」段的"四件互不重叠"：本 skill 管结论怎么说出口，编码行为准则管代码怎么写怎么修，测试纪律管测试/评测证据长什么样，磁盘缓存纪律管文件写哪个盘。[实测]

但**同一份正文的「三、高频翻车场景」表第二行**（v1.2 新增）规定：宣布"写完了／已落盘"时必须走 `write-readback-proof` 的四步（判据先行 → 反查工具在场 → 换独立通道读回 → 正例校验分清"没写进去"还是"尺子坏了"）。这一行既不是"测试证据形态"、也不是"文件写哪个盘"，它落在**另一支独立 skill**（落盘读回自证）的主题上；同理，第 3 条并入段的"判据鉴别力"三条子机制，其成套做法正文自己指向了两支 skill（验收判据鉴别力审查、本机服务探针防假绿骨架）。[实测]

⇒ **结论**：边界表只列了 3 件邻居，漏掉了正文实际援引的 3 支 skill 的主题域；"互不重叠"这句应读作**"与那三件的主职不重叠"**，而不是"本 skill 只管一件事"。我实地检索确认：这三被引用的名字都能按 skill 调用键解析到实际目录（不是悬空引用），只是目录名与调用键并不相同；同时确认那支落盘读回 skill 的第 1 节标题确实是"四步（按序，不可合并）"，与本 skill 表第二行的措辞逐项吻合。[实测]

### 3.5 骨架与血肉：为什么这一支"设计很硬、条款偏软"

上面 3.1—3.4 说明一件事：**这份 skill 的结构层（分区、顺序、边界、双层、条数锁死、版本史就地写）设计密度极高，几乎每处都有明确取舍理由**；但**规则层（十二条本体）大多只规定"该想什么"，没规定"做完留下什么"**。

这不是文笔问题，而是可以直接清点的事——**第 11 章用一张表逐条判定 12 条各自的"能否证明它被违反了"**。预告结论：12 条里只有 5 条能被外部检查留下可 grep 的痕迹，其余 7 条在无外部检查的前提下，无法证明它被违反了。[实测]（清点依据逐条引正文原句）

这也是本页篇幅必须远大于正文 133 行的原因：正文给了骨架，**每个数值的为什么、每个失效场景、每条能不能验**都要在这一页摊开。

## 第 4 章 四分类口径与置信度三档（「一」+ 第 1 条）

### 4.1 四类各自的强制标注

「一、分类口径」是一张 4 行 2 列表：左列类别，右列"标注要求"。逐类拆：

| 类别 | 正文要求的标注 | 缺了会怎样 | 为什么这么定 |
|---|---|---|---|
| **已验证事实** | 来源 + 时点 + 证据强度 | 读者无法判断这话现在还成不成立 | 事实会过期：代码改了、文档版本变了。"时点"是唯一能区分"当时对"和"现在对"的字段 [实测]（第 8 条另要求旧快照结论标"可能过期"，与此呼应） |
| **当前假设** | 置信度 + 推翻条件 | 假设会被读者当事实继续往下推 | 推翻条件是让读者**能在自己遇到反例时立刻停手**的接口 [实测] |
| **未知** | 直接写"未知"，**不脑补** | AI 会用貌似合理的内容填空，且语气与事实无异 | 这是全 skill 唯一一条明令"禁止产生内容"的规则，针对的是模型最本能的补全倾向 [实测] |
| **已证伪** | 记录推翻依据 | 同一个错结论过两周被重新提出 | 证伪是负知识：不知道它被证伪过的人最容易重犯 [实测] |

**为什么是四类而不是三类**：常见做法只分"事实/推测"。多出的两类各堵一个具体洞——「未知」堵"用想象填空"（三类里没有"我没依据"这个合法出口，模型就永远得给个答案）；「已证伪」堵"错结论复活"（三类里没有地方存放"这条已经排除了"）。[推演] 把「已证伪」并回「未知」会出问题的具体输入：排查一个间歇性失败，第 3 轮已经用实测排除了"网络超时"这个假设；若没有"已证伪"这一类，排除结论不进记录，第 9 轮上下文压缩后"网络超时"重新出现在候选列表里，白花一遍排查。

**为什么「未知」不是「已证伪」的子集**：未知是"没测过"，已证伪是"测过且不成立"，两者的下一步动作不同——前者给验证路径（第 11 条），后者禁止再走这条路。[实测]（第 11 条要求"超出知识边界直接说不知道，并给出验证路径或所需输入"）

### 4.2 置信度三档：0.8–0.95 / 0.4–0.7 / 0.1–0.35

正文给的是三个**开区间式的数值段**，原文一行写死：高 `0.8–0.95` / 中 `0.4–0.7` / 低 `0.1–0.35`。[实测]

这四组数字值得逐段抠，因为**缝和顶都是设计，不是随手写的**：

```
0 ────── 0.1 ╱ 低档 0.1–0.35 ╲ 缝 0.35–0.4 ── 0.4 ╱ 中档 0.4–0.7 ╲ 缝 0.7–0.8 ── 0.8 ╱ 高档 0.8–0.95 ╲ 空白 0.95–1.0 ── 1.0
```

**① 为什么高档顶到 0.95 而不是 1.0。** 1.0 意味着"不可能错"。本 skill 第 8 条要求每个重要结论写推翻条件——一个置信度 1.0 的断言在定义上写不出推翻条件（什么证据能推翻"绝对正确"？），于是它会**同时违反第 8 条**。把上限压到 0.95，是让整个体系自洽：任何数值结论都还留着"我可以被推翻"的位置。[推演] 允许写 1.0 会出问题的具体输入：用户问"这个仓库的 README 里有第 3 节吗"，你刚读到过——写"事实，置信度 1.0"；十分钟后仓库被另一个窗口改了 README，而你的"1.0"已经进了下游的决策依据，没人会去复核一个 1.0 的东西。

**② 为什么 0.95 以上整段留白而不是并入高档。** 高档区间是"当前最可信但仍未定"。这一段没有第三档，含义是**本 skill 不承认"已到达绝对可信"**。它和第 9 条的 S 级（官方文档/源码/可复现结果）并不冲突：S 级证据可以支撑一个 0.95 的结论，但"支撑力强"不等于"不可能被新证据推翻"。[实测]（第 9 条给证据分级，第 1 条给置信度，两者是两条独立标注，正文从未把它们划等号）

**③ 为什么低档下界是 0.1 而不是 0。** 置信度 0 = "断言必假"，那属于"已证伪"类目，应该走第 4 类的标注要求（记录推翻依据），不该出现在"当前假设"的置信度里。所以 0.1 是"假设"这个类目的下边缘。[推演] 有人填 0.0 时的具体故障：输出"当前假设：这个报错是并发导致的（置信度 0.0）"，下游排序脚本按置信度加权时把这条压到最底，等于从候选里悄悄删掉了——而"0.0"读起来又像"我说这话不算数"，两头都不负责。

**④ 两个缝（0.35–0.4、0.7–0.8）怎么办？正文没写。** 这是这一档设计里最实际的问题。我的读法与理由：

- 缝**不是给四舍五入用的，是给"拒绝精确化"用的**。这套区间的真实作用是把人从"我 0.73 吧"这种伪精确里拉出来。落在缝里（比如 0.75）说明你以为你能区分 0.7 和 0.8——而事实上不能，所以正确动作是**降到档位而不是插值**：往低档靠（0.75 → 记"中"，甚至记"低"）。[推演] 填缝会出问题的具体输入：一条结论你标 0.75、另一条标 0.78，下游按数值排序后两条几乎并列，读者据此认为这两条等可信；但 0.75 和 0.78 的差别是你自己造的，实际两条都只到"中"，应该同样需要一次验证——伪精确把"需要验证"这件事糊掉了。
- 反过来若强行合并成三档无缝区间（0.1–0.35 / 0.36–0.7 / 0.71–0.95），则边界值 0.36 与 0.35 的结论实质相同却必须归不同档，档位就退化成噪声。

**⑤ 为什么档位只有三档而不是五档。** 正文第 7 条紧接着要求"低置信度内容不得用确定语气"——这句话是**语言层面的动作**，需要的是"要不要改语气"这种二值判断，而三档刚好支撑："高"可用陈述句、"中"须带假设前缀、"低"必须写成"未知/未验证"。五档会要求五种语气强度词表，而中文没有稳定可辨的五级不确定词；标注者之间也无法复现（同一句话两人分别给 0.55 和 0.6），最终退化回三档。[推演] 具体会出问题的输入：让两个执行者各自给"这个方案能兼容旧数据"打五档置信度并据此选择语气，两人的措辞会不同但无法说明哪个更对，且读者看不出区别。

### 4.3 「不脑补」的具体形态（把禁令换成句子）

正文第 1 条末尾六个字："证据不足写'未知'，不脑补"。它最容易在执行时被糊过去的地方是**形式上写了"未知"、实质上仍然给了答案**。三种常见糊法与对应写法：

| ❌ 看起来合规、实则脑补 | ✅ 本 skill 要求的形状 |
|---|---|
| "应该是 v2.1 左右吧"（把猜测包装成近似值） | "版本：未知。确认方法：读该文件 frontmatter 的 `version` 字段" |
| "通常这类接口限制在 1000 字符以内"（用"通常"给记忆发通行证，撞上第 9 条 C 级） | "上限值：未知（我记忆里的数字属 C 级线索，不作依据）。需查规范原文" |
| "不确定，但大概率能修好"（先补一个免责词再把乐观结论送出去） | "能否修复：未知。最小验证步骤：<一条可执行动作>"（第 11 条要求"给出验证路径或所需输入"） |

[实测] 三行的违规形态都能对上正文的具体条款：第 9 条把"记忆/直觉"钉为 C 级"只作线索，不作依据"；第 11 条要求"不猜测填充"并给验证路径；第 7 条禁止低置信度用确定语气。

## 第 5 章 前提审查与反例搜寻（第 2 条 + 第 4 条）

### 5.1 第 2 条：为什么"用户说的"必须降级成假设

原文：用户给的解释、诊断、方案一律视为**待验证假设**；前提缺依据或含逻辑谬误，先指出并修正，不照办。[实测]

这条反直觉，因为用户通常是"提出需求的人"，把他的话降级成待验证像是在质疑他。它仍然被写进第 2 条，理由有三层：

1. **用户给的是结论而不是证据。** "因为缓存没刷新所以慢"——这是用户自己的诊断，中间过程没交给你。你若直接在它之上推理，等于用一个未验证的中间结论搭一整栋楼。
2. **顺着前提推，错误不可见。** 如果前提错而推导对，输出内部没有任何信号会亮红——读者和你自己都看不出问题，直到上线炸。
3. **修正前提比执行方案便宜。** 前提审查通常是一两次查证；照错前提做完是整段返工。

[实测] 正文「三、高频翻车场景」表专门有"用户给了个前提"一行，违规表现写"顺着前提往下推"，正确动作写"先判该前提是否成立（规则 2）"——两处互相咬合。

[推演] 一个具体会出问题的输入：用户说"这个 skill 的 name 字段和目录名不一致，肯定加载不了，帮我改一下目录名。"前提里混了两件事（name 与目录名不一致是真的；因此加载不了是假的）。若按前提直接动手，会把整库所有 skill 的目录改名——而实际机制是调用键覆盖显示名、目录名同样可以调用，什么都没坏。第 2 条要求的动作是先指出后半句前提缺依据，再谈要不要动。

**"含逻辑谬误"三个字的落点**：它给了一次性否决的许可——遇到"我朋友说/网上都说/一直是这样所以是对的"这类前提，不必逐条查证即可指出谬误形态。但注意这条**不能反过来用**："我觉得有谬误"不能替代证据（第 5 条要求反驳前先构造最强反方论证）。[实测]

### 5.2 第 4 条：三档风险与"至少 1 次验证 + 1 个反例"

原文给了三档：

| 档 | 正文要求 | 含义 |
|---|---|---|
| **低影响** | 快速判断并标"未验证" | 允许不验证，但**必须留"未验证"标记** |
| **中影响** | 至少 1 次验证 + 1 个反例 | 数值门槛：验证 ≥1，反例 ≥1 |
| **高影响（不可逆 / 安全）** | 完整闭环 + 红队 | 完整闭环＝第 3 条五步走完；红队＝第 10 条三问 |

[实测]

**为什么"低影响"仍然强制标注。** 不标"未验证"，读者就把它当成走过快检的东西；标了，读者可以决定要不要自己复算。这一处也是本 skill 里少见的"允许偷懒但不许隐瞒偷懒"的设计。

**为什么中影响要的是 1 个反例，不是"多找点证据"。** 单向加证据只会加强确认偏误（红队三问第 ① 问正是这个）。1 次验证给你正向支持，1 个反例给这把尺子一次"能红"的机会——两件事不可互相替代。这与第 3 条并入段的"阳性对照"是同一个思想的两个尺度：并入段管**判具本身能不能红**（尺子层面），第 4 条管**结论经不经得住一次反驳**（命题层面）。[实测]（两处分别在第 3 条并入段与第 4 条正文）

**"高影响 = 不可逆 / 安全"这个定义方式值得注意**：它没有用"重要的/复杂的问题"这类模糊形容词，而是抓了两个可判定特征——能不能撤回、会不会伤人。这是第 4 条里唯一具备客观判据的部分。[实测]

⚠️ **但第 4 条整体仍不可判定**："低/中/高"由谁按什么标准分档，正文一个字都没写。同一条规则里"档名可判定、归档不可判定"，导致整条的强度被最软的一环锁住——见第 11 章 11.2 的清点。[推演] 具体会出问题的输入："帮我改一下这个报错文案"——改文案本身可撤回（低），但如果它出现在一个对外承诺页面上就变成对外口径（中→高）。执行者按字面判"低影响，快速判断标未验证"，于是没人去核对文案里那个数字，而数字来自旧快照。第 4 条在这里没能救你，因为它没给"影响面沿着什么边界扩散"的判据。

### 5.3 第 4 条后半：四项主动检查

原文：重要方案前主动检查 **最强反例、失败场景、边界条件、隐藏假设**。[实测]

这四项不是并列的四件事，是**同一件事的四个入口**，各管一种失效：

- **最强反例** —— 管"证据只覆盖了顺利路径"。
- **失败场景** —— 管"最坏情况没算成本"。
- **边界条件** —— 管"空值/极大值/并发/首次运行"这类边缘输入。
- **隐藏假设** —— 管"你没写出来但方案成立依赖它"的东西，常常是环境版本、时区、编码、路径分隔符。

[推演] 四项里"隐藏假设"最容易漏且代价最大，具体会出问题的输入：一套只在 Windows 上跑过（换行是 CRLF）的写前自证脚本被搬到 Linux 上的 CI，方案本身没错，隐藏假设是"读回比对时文件字节完全一致"——CI 里被 `.gitattributes` 归成 LF，比对必然不等，报错看起来像"内容写坏了"，实际是隐藏假设失效。四项检查里若做了"边界条件/隐藏假设"这一项，这一类问题会在方案阶段就被写进前置条件。

## 第 6 章 证据分级与验证闭环（第 9 条 + 第 3 条前半）

### 6.1 四级表逐行

第 9 条是一张 4 行 3 列表（级 / 内容 / 用法）：

| 级 | 内容（正文原文） | 用法（正文原文） | 这一级的实际约束力 |
|---|---|---|---|
| **S** | 官方文档 / 源码 / 可复现结果 | 可直接支撑 | 最高。"可复现结果"与 A 级"实测"的重叠处见 6.3 |
| **A** | 日志 / 测试 / 实测 | 可直接支撑 | S 与 A 的用法完全相同——**区别只在"能不能被他人复算"** |
| **B** | 权威二手 | 需交叉验证 | 不许单独支撑结论，必须有第二个来源 |
| **C** | 直觉 / 记忆 / 传闻 | 只作线索，**不作依据** | 最锋利的一级：它明确把"我记得"逐出依据范围 |

[实测]（表格内容照正文）

**C 级为什么单独成级而不是并进 B。** "直觉、记忆、传闻"三者共同点不是"权威度低"，而是**无法向他人出示**：你没法把你的记忆导出成一个文件让别人复核。B 级（权威二手）虽然要交叉验证，但它**可指认**——有出处、有链接、有段落。这条分界线的真实标准是"可出示性"（能不能把证据本身递到对方面前），不是"可信度"。这也是第 3 条并入段强调"产出判据要能复算"的同一条思路：不可出示的证据，连"它的判据会不会红"都无从检查。[实测]（第 9 条表 + 第 3 条并入段①）

**最容易犯的错**：拿 C 级证据说 A 级话——凭记忆写出一个版本号、一个 API 名、一个规范上限，却用"日志/实测"那种确定语气。正文「三、高频翻车场景」表第三行专门堵它，并给出最硬的动作：**引用不存在的对象 = 阻断**（先 `git cat-file`、查文件、读文档，查不到就不许写出来）。[实测]

**为什么是"阻断"而不是"标注为未验证"。** 因为一个不存在的标识符**不是"尚未验证的事实"，而是"根本没有那个东西"**。它属于「已证伪」类目（查了，确认不存在），而不是"未知"。把它降级为"未知"会让下游以为补一次查证就能用；而事实上这句话在任何情况下都不会变真。所以只能阻断——不写。这一处动作差别是本 skill 分类口径严谨性的最好例证。[实测]（四分类定义见「一」；"引用不存在的对象 = 阻断"见「三」表）

### 6.2 第 3 条前半：外部证据优先 + 闭环四要素

第 3 条主干三句：优先用代码执行、测试、日志、运行结果、权威文档验证；可复现证据高于直觉。然后按"有没有执行环境"分叉：

```
有执行环境  → 直接运行验证
没有执行环境 → 给出用户可独立执行的最小验证命令，并请其反馈结果作为新证据
```

[实测]

**分叉设计的重要性**：它承认了 AI 常常不能自己跑（没有 shell、没有凭据、不能联网）。但很多纪律在这里就断了——"我没法跑所以我说'大概是'"。本条把这条退路封掉：没有环境时**责任转成"移交一把可执行的尺子"**，具体化为一个用户能照抄的命令 + 请他回传结果。这一句同时解决了两个问题：读者能自证，且回传结果作为**新证据**接入第 6 条的改口机制（只有它才准改口，情绪不算）。

**闭环五步 + 四要素记录**（正文原文形状）：

```
提出假设 → 最小验证 → 记录（命令 / 环境 / 输入 / 输出）→ 对照下结论 → 修正再验
```

四个记录要素各自缺掉时的具体失效：[实测]（四要素见正文第 3 条）

| 缺哪个 | 表面看起来 | 实际坏在哪 |
|---|---|---|
| 命令 | "我跑过了" | 你不知道跑的是哪个动作；换个人复现不出来 |
| 环境 | 命令给了 | 同一命令在别的版本/别的机器上结果不同（解释器版本、CRLF、时区） |
| 输入 | 命令 + 环境齐 | 无法判断这是"对真实数据有效"还是"对一条构造样例有效" |
| 输出 | 前三项齐，只有结论 | 只剩总结数字——测试纪律明令禁止只报总结数字；本条把"原始输出"含在闭环里 |

**"最小验证"的"最小"是这条里最实用的词**：它把验证成本降到一个可以接受的锚点（不是全套回归），使"做一次验证"在低影响档也能发生。它与第 4 条的档位形成回路：中影响要 ≥1 次"最小验证"。[实测]

⚠️ 正文第 3 条末尾用一条 ⚠️ 显式把边界交出去：测试与评测类证据的**形态要求**（必须落盘、改前改后各跑一次、禁止只报总结数字）归 `A-Cao-测试纪律-测试证据形态规范`。这一句是本 skill 唯一一处明文"让权"，也是 3.4 节那个"互不重叠"声明真正成立的地方——**让权写在正文，而不是只写在边界表里**。[实测]

### 6.3 分级表的三个洞（我的清点）

分级表很好用，但**同一份证据由两个人分级会得到不同结果**，因为它缺三条定义：

1. **S 与 A 的分界不清。** "可复现结果"（S）与"实测"（A）在字面上是同一件事。我的读法：S 的"可复现"要求**他人不需要你的环境也能复现**（官方文档、源码、公开可跑的测试），A 的"实测"是**只有你这边跑出来了**。[推演] 会出问题的具体输入：你在一台有内网凭据的机器上跑了一次官方接口，得到返回体——按 A 级可直接支撑结论，于是你写下"该接口支持批量 500 条"；换一个没有凭据的读者无法复现，而文档里并没有这个数字，此时它其实是 B（你的实测外推成通用能力）。
2. **"权威二手"没定义。** 权威指来源还是内容？某高星开源项目的 README 引用官方规范、但引用错了——它是 B 级（应交叉验证后取官方原文），实际执行中它经常被误当 S 级读。[推演] 会出问题的具体输入：照着那篇 README 里的"上限 1,000 字符"设计字段长度，而该 README 抄的是草稿版本；正确动作就是 B 级要求的那一步——回到官方规范原文交叉验证。
3. **交叉验证没定义"几个来源算交叉"。** 若两个来源同源（都抄自同一份旧草稿），三个也算一个。这恰是第 3 条并入段子机制①（多条断言共用同一个可疑变量＝同一道闸抄三遍，全绿不算数）在证据侧的对应问题，但第 9 条没有把这条借过来。[实测]（两处措辞各自引自第 3 条并入段与第 9 条表）

**可执行的补丁（本页提议，正文未采纳，见 15.7）**：B 级"需交叉验证"应读作"须与一个 S/A 级取数通道不同的来源不矛盾"——用"取数通道是否独立"判，而不是用"来源数量"判。

## 第 7 章 先验尺子，再信读数（第 3 条并入段 · 本 skill 最硬的一段）

### 7.1 这段是什么时候进来的，为什么不是第 13 条

v1.1（2026-10-03）把"先验尺子，再信读数"并进第 3 条，并在末尾注明"2026-10-03 并入本条；此前这条纪律散在四处却不在 12 条里"。「版本」区的 v1.1 段写得更直白：这条纪律此前散在两支 skill（验收判据鉴别力审查、本机服务探针防假绿骨架）、各 agent 各自记忆库的踩坑档、以及用户的反馈记忆里，"唯独全队常驻的 12 条一个字都没有"。[实测]

**并进第 3 条而不是新开一条**，是本 skill 最好的一处工程判断，理由正文自己给了三条：

1. **条数是一个被外部引用的计数键**。正文多处依赖"12 条"和"核心 5 条"这两个数字（「定位」段引常驻层的条数、v1.0 段引"12 条"、常驻层那节回指"完整 12 条 = 本 skill"）。新开第 13 条要把这些派生件全改一遍，改动面大于收益。[实测]
2. **归属天然在第 3 条**：第 3 条讲"用什么当证据"，而"判据本身是否可信"就是它的下一步——先确认读数来源可信，再谈读数。
3. **条数不变 ⇒ 各处引用零改动**，v1.1 段原话"并进已有条目后条数不变，各处计数与派生件零改动"。

[推演] 反过来（新开第 13 条）会出问题的具体输入：另一个窗口按"12 条"这个数写了派生摘要与常驻层，你这边加了第 13 条，两处计数从此不一致；后来有人按常驻摘要判断"这条纪律不在 12 条里所以不用守"，新加的纪律正好被漏掉——而它是代价最高的那条。这个场景不是假想：正文声明"两处同步"，而实测同步确实会滞后（见 10.3）。

### 7.2 三条子机制逐个拆

并入段给出三条，原文形状：

**① 每条断言各读一个独立证据源；几条共用同一个可疑变量＝同一道闸抄三遍，全绿不算数。**

- 治什么：一个检查脚本里有三条断言，三条都从同一次 stdout 里取数。那个 stdout 本身被工具的默认输出格式改写过了（比如它把制表符渲染成空格），三条断言于是**共同建立在一个未验证的假设上**。全绿。
- 为什么"独立"要看**取数通道**而不是看断言条数：三条断言读同一个通道，鉴别力等于一条。[实测]（正文用"同一道闸抄三遍"打比方）
- [推演] 具体会出问题的输入：验证"新内容已写入且旧内容已移除"，写了三条断言——`新串出现在文件里`、`旧串还出现在原位置上`、`总行数增加了 1`，三条都从同一个 `read()` 到的字符串判。若写盘动作实际把内容写到了另一个同名文件（工作副本 vs 真源），三条全绿，而这三个绿来自同一个没验过的假设："我读的就是我刚写的那个文件"。第 ① 条要求把其中一条换成独立通道（换一个进程、换一条命令去问磁盘）。

**② 阴性结论必须配一次阳性对照（先跑一次已知能过的）；对照跑不出来记「尺子作废（VOID）」而不是 PASS——未评估 ≠ 通过。**

- "阴性结论"＝"没有 / 零命中 / 没报错 / 没落盘 / 无人监听"这类**否定式**结论。它们比肯定式更危险，因为**尺子写坏时它们永远成立**：一个搜错字段名的 grep 永远返回 0 命中，于是"没有重复条目"永远为真。
- 阳性对照的动作：先拿一个你**确定在盘上/确定能过**的东西塞进同一把尺子，看它报不报"命中"。正例不中 ⇒ 尺子作废 ⇒ 本轮所有"没有/0 命中"结论一律不采信，记 **VOID**。
- 关键在 **VOID 是第三种状态**。多数检查脚本只有 PASS/FAIL 两态，于是"尺子坏了"被错记成 PASS（因为没看到红）。本条明确把"未评估"与"通过"分开。[实测]
- [推演] 具体会出问题的输入：你跑一次"按行首匹配某个键名"的检查得到 0 命中，于是宣布"这个文件没有该键"；而实际是那个键写在缩进后面、行首匹配天然找不到。这是阴性结论完全来自尺子构造。阳性对照的动作是：先拿一个你确定存在于同种位置的串喂进同一条命令，若也 0 命中，说明是尺子坏了不是文件缺东西。

**③ 变异检验要点名该翻红的那一条，只要求"整套变红"抓不出恒真判据。**

- 变异检验＝故意把被测内容改坏一点（挪一个字符、删一行、换一个值），看检查会不会翻红。
- "点名"的意思：改坏第 3 条断言管的东西，就必须看到**第 3 条**翻红；看到第 5 条翻红不算（可能第 5 条本来就管这个，第 3 条仍是恒真）。
- 为什么"整套变红"不够：一整套 6 条断言，你改坏一处、看到"这一套红了一次"，你无法知道是哪条红的负责——其中 3 条可能永远为真，从没被任何东西考验过。[实测]
- [推演] 具体会出问题的输入：一个写前自证脚本要求"旧串在插入点左侧 / 右侧 / 长度差为 1"三条同时成立，你把插入点往左挪 8 个字符做变异检验，整套报红——你以为判据有效。但报红的是"长度差为 1"那条（它对所有偏移都敏感），而"左侧/右侧"两条共用同一个可疑偏移量、对这次变异根本不敏感。这三条闸其实是一条。

### 7.3 「尺子」这个比方为什么选得好（以及它不管什么）

"先验尺子，再信读数"把抽象的"验证你的验证"变成一个动作：**用之前先试一下它能不能量出错的东西**。这一句可迁移到任何检查场景（代码测试、数据核对、口径审查）。

但要说清这段**不覆盖什么**：

- 它不管"尺子有效但读数被解释错"（那是第 9 条证据分级与第 12 条的事）。
- 它不要求每次都做变异检验——并入段只在结论形如"通过/零命中/没报错/没落盘"时才触发前置检查。这个触发条件是**句式**（可判定），不是"重要性"（不可判定），因此这段是十二条里最容易自动执行的部分。[实测]

### 7.4 与两支邻居 skill 的分工（正文写明）

并入段末尾两处指向：机制与案例 → 一条本地踩坑日志的根因条目（本 skill 正文用链接指它，链接形态的缺陷见 15.5）；成套做法 → skill `acceptance-criterion-audit`（验收判据鉴别力审查）、`live-service-probe-harness`（本机服务探针防假绿骨架）。[实测]

三者关系可以这样记：**本 skill 管"你现在这句'通过'该不该说出口"（结论层闸门）；鉴别力审查管"这套验收标准本身能不能区分对错"（判据设计层）；探针骨架管"起服务时怎么不误杀别人的端口、怎么发带请求体的检查"（执行骨架层）**。本 skill 是纪律，那两支是做法。[实测]

## 第 8 章 改口纪律与红队三问（第 6 条 + 第 10 条 + 第 5 条）

### 8.1 第 6 条：什么不算新证据，比"什么算"更好用

原文关键句：仅在新证据或更强逻辑下改口。**情绪、重复、权威身份、多数意见、自信程度都不算新证据。**[实测]

这条的设计聪明在**用排除法**：正面定义"什么算证据"是个哲学难题（第 11 章会说明它为什么无法机械判定），而"什么不算"可以列成一张短名单。五种被排除的东西，逐个看它是怎么施压的：

| 被排除项 | 它长什么样 | 为什么它不该让你改口 |
|---|---|---|
| **情绪** | "我很烦了，你就说能修好" | 情绪是对话成本，不是世界状态的变化 |
| **重复** | 同一句话问第三遍 | 重复只改变你被问的次数，不改变证据 |
| **权威身份** | "我是这个模块的负责人" | 身份不等于手头有证据（负责人也可能记错） |
| **多数意见** | "团队里其他人都觉得是这个原因" | 多数是投票，不是取证 |
| **自信程度** | 对方说得很肯定 / 你自己当时很确定 | 流利度和确定感是最容易被误当成正确性的信号 |

[实测] 表格第 1 列的五个名词照正文；第 3 列的展开是本页的解释。[推演] 最后一项最隐蔽，具体会出问题的输入：上一轮你用极肯定的语气说过"这就是缓存问题"，这一轮用户只回一句"你确定吗"（没有新信息）。按第 6 条，你不该改口，也不该加强语气重申——正确动作是回答"我确定与否不取决于你的追问；支撑它的是这条实测记录；能推翻它的是 X"。绝大多数对话里，第二次追问就足以让模型翻转结论，这就是"重复被当成新证据"的实际形态。

**改口四要素记录**（原文）：旧结论 → 新依据 → 新结论 → 置信度变化。[实测]

为什么第四项是"置信度变化"而不是"谁对谁错"：这一项把改口接回第 1 条的置信度体系，让读者看到**改动幅度**——从 0.4 到 0.85 是"补上了 S 级证据"，从 0.9 到 0.8 只是"多了一个待查的反例"。没有这一项，读者只能看到"结论换了"，无法判断新结论比旧结论稳多少。[推演] 缺置信度变化会出问题的具体输入：一条结论连着换三次（甲→乙→甲），读者看到两次翻转就不知道该信哪个；若每次带幅度（0.85→0.4→0.86），第三次的回摆就明显是"回到了原证据"，而不是"又一次动摇"。

⚠️ 但**这条整体不可判定**："是否构成新证据"无法机械检查（见 11.2）。它的可判定部分只有后半——改口时**有没有留下那四项**。所以第 6 条的正确用法是：把它当"改口必留痕"的格式要求，而不是当"我能不能识别出新证据"的能力。[实测]

### 8.2 第 10 条：红队三问，逐问拆

原文：重要结论输出前自问三句。

**① 我的结论是否因为用户的前提而产生了确认偏误？**
和第 2 条是一对：第 2 条管"接不接受前提"，这一问管"接受了之后结论有没有被带跑"。它专门针对"你已经开始在对方框架里解题"的时刻——这时最强的诱惑是继续找支持证据。动作含义：把用户前提摘掉，重答一遍，看结论是否还站得住。

**② 是否存在我没考虑到的失败边界？**
不是"还有什么没做"，而是"什么输入会让它不成立"。它和第 4 条的"边界条件"同源，但第 4 条在方案阶段用，第 ② 问在**输出前**用——因为输出时的你对边界最不敏感（你已经相信它对了）。

**③ 如果这个结论是错的，最可能的原因是什么？**
三问里最锋利的一句。它强制你把"错"当成一个**有机制的事件**来预测，而不是当成一个抽象可能。答不出这一问，说明你其实不知道这条结论建立在哪个可失效的环节上——那它就不该以结论形式输出（回「一」改标"当前假设 + 推翻条件"）。

[实测] 三问原文照正文；三问各自的动作含义是本页的解释。

**为什么是 3 问而不是 7 问**：三问分别锁定三个不同的失效方向——**来源污染**（被用户前提带）、**覆盖不足**（边界没试）、**机制不清**（不知道会怎么错）。再多就是重复这三个方向（比如"有没有反例"归 ②，"我是不是想当然"归 ③），而每多一问，实际执行时被整段跳过的概率上升。三问是"还能一次答完"的上限。[推演] 检验这个说法的具体输入：把红队扩到七问，在一批长对话里检查有多少轮真的七问都写了——多数会在第四问后开始复用前一问的答案，形式在、实质没了。

⚠️ **第 10 条是全 skill 可验证性最弱的一条**：三条"自问"不要求把答案写出来，因此在外部观察上，**做了红队和没做红队产出一模一样**。正文里唯一能间接咬住它的地方是「三、高频翻车场景」表最后一行（"自己刚写完代码 → 顺手给自己好评 → 红队三问（规则 10），并构造最强反例（规则 4）"）——它把红队绑到一个具体场景上，但仍不要求留痕。详见 11.2。[实测]

### 8.3 第 5 条：不迎合不抬杠 + 反驳前先造最强反方

原文：只依证据与逻辑表态。反驳前先构造**最强反方论证**，禁止稻草人式反驳。[实测]

这一条看着最"虚"，其实是第 6 条的执行面：**不迎合 = 抗住情绪/权威/多数（第 6 条那五项）**；**不抬杠 = 抗住"为了显得专业而反驳"的冲动**。两个失效方向刚好相反，所以必须同时写——只写"不迎合"会养出逢人便驳的风格。

"最强反方论证"（把对方最好的理由先完整说一遍再说不过）是唯一可外检的动作：它要求输出里存在一段**以对方立场写的、比对方自己说的更强**的话。稻草人（替换成弱版本再驳）在输出形态上的特征是：找不到任何一段"对方观点的加强版"。[实测]（第 4 条"最强反例"是同族概念；第 12 条"越反常识要求越强证据"是它的对称面）

## 第 9 章 输出形状：四段模板、可追溯、承认无知（第 7、8、11、12 条）

### 9.1 第 7 条：固定四段（唯一有格式判据的一条）

原文：高风险或复杂判断固定四段输出，并给出代码块形状：

```
【已验证事实】来源 + 时点
【核心假设】置信度 + 推翻条件
【潜在反例/风险】最强反方 + 边界 + 失败场景
【下一步验证建议】最小可执行验证步骤
```

[实测]（四段名与每段必带项均照正文）

**每段的功能与它逼出来的东西**：

| 段 | 必带内容 | 它逼你说出什么（否则填不满） | 若跳过 |
|---|---|---|---|
| 【已验证事实】 | 来源 + 时点 | 你必须能指到某个可出示的东西 | 你会把假设写进这一段——「一」的四分类正好用来拦 |
| 【核心假设】 | 置信度 + 推翻条件 | 你必须承认自己哪里没底 | 你得到一段全是断言的输出 |
| 【潜在反例/风险】 | 最强反方 + 边界 + 失败场景 | 你必须替对面说话（第 4、5 条在这里落地） | 第 4 条要求的"1 个反例"就没了去处——**这段是反例的强制留痕位** |
| 【下一步验证建议】 | 最小可执行验证步骤 | 你必须给读者一把能自己用的尺子 | 讨论停在"我判断是这样"，读者无法接手 |

**第三段是整套设计里最关键的一处"把纪律换成格式"**：第 4 条要求"至少 1 个反例"、第 5 条要求"最强反方"、第 10 条要求"失败边界"——这三条本身都无法验证是否做了，但它们**全部要在第三段里显影**。所以四段模板实际上是那三条不可判定条款的落盘出口。[实测]（第三段必带项逐项对应第 4、5、10 条的要求）

原文另补两句约束：**一般技术判断可精简，但必须明确区分【事实】与【假设】**；**低置信度内容不得用确定语气**。[实测]

这两句的分工值得注意：前者是"最低保留量"——允许你把四段压成两句，但不许把事实和假设混写在一句里；后者是语气规则，作用在**措辞**而不是**结构**上。两者合起来使"精简"不至于退化成"无标注的断言"。[推演] 只有前者没有后者会出问题的具体输入：输出"【假设】这个改动大概不影响别人"——格式在，但"大概"配上了没标置信度的确定句式；读者按"不影响"排期。

### 9.2 第 8 条：可证伪 + 可追溯 + 过期标注

原文四句：重要结论必须写明"什么证据会推翻它"；**不可证伪的断言降级为观点**；结论可回溯到「证据 → 推理 → 结论」；来自记忆或旧快照的结论标注"**可能过期**"。[实测]

**"不可证伪 → 降级为观点"是本 skill 的收口动作。** 前面所有标注都在给结论加要求，这一句给出"要求达不到怎么办"——不是删掉，而是改名成"观点"。这样做的价值是**保留了输出量**（想法仍然可以说出来），同时取消了它的结论资格（读者知道不该据此动手）。[推演] 若没有这一句，执行者会在两种糟糕做法里选一个：要么删掉整个想法（信息损失），要么照原样说成结论（误导）。具体输入："我觉得这个架构不优雅"——它写不出任何推翻条件（什么证据能证明优雅？），若无降级出口，它要么消失、要么与前一句技术结论并列出现在同一个"事实"位置。

**"证据 → 推理 → 结论"三段可回溯**是防"证据与结论之间跳步"的。常见失效：证据是"这个函数在测试里返回空"，结论是"整个模块设计有问题"——中间那步推理（从 1 个用例推到全模块）没写出来，读者看不出错。写推理链的代价是**跳步会自己显形**。

**"可能过期"这个标注词为什么不是"未验证"**：过期意味着"当时为真、现在未知"，它暗示读者"复算很可能便宜且结果可能变"；"未验证"意味着"从来没验过"。两者处置动作不同：前者重跑一次即可（「三」表第五行正是"数字来自旧快照 → 标'可能过期'并重跑"），后者要整条闭环。[实测]

### 9.3 第 11 条：承认无知（本 skill 里最好执行的一条）

原文：超出知识边界直接说"不知道"，并给出验证路径或所需输入，**不猜测填充**。[实测]

**"不知道 + 一把尺子"是一个完整可判定的形状**：检查输出里有没有"不知道"，再看它后面有没有跟一个可执行动作或明确的所需输入。二者缺一即违反——只有"不知道"是甩锅，只有"验证路径"却把答案猜出来了是脑补。

这条同时是「一」的"未知"类目和第 3 条"没有执行环境"分支的汇合处：本 skill 在三处不同位置要求同一件事（分类里写未知、闭环里给命令、承认无知里给路径），说明设计者知道这是模型最难的动作为此重复了三遍。[实测]

### 9.4 第 12 条：奥卡姆剃刀的后半句才是重点

原文：证据相当选最简假设；**越反常识的主张，要求越强的证据**。[实测]

前半句是老生常谈，后半句是对**输出风格的直接解药**——它针对的不是错误，而是"为了显得有价值而把话说大"。模型天然偏爱信息量高、听起来更聪明的答案；"我猜是这个组件的配置写反了"远不如"这是并发时序缺陷导致的一致性破坏"抓人，而**两者的证据要求应该按反常识程度递增**，实际却常常相等。

[实测] 与第 9 条联读可得一条实用规则："反常识主张 + 只有 C 级依据"是最高危组合——C 级不作依据（第 9 条）+ 反常识要更强证据（第 12 条）双重不满足，这句话只能以"未知/待验证"的形式出现。

[推演] 具体会出问题的输入：用户问"这个页面加载慢是什么原因"，你说"通常是缓存穿透"——这句话既反常识（一个内部页面走的是本地服务，哪来缓存层？）又只有记忆作据。按第 12 + 9 条它不该被说出来；但"通常是"三个字让它伪装成了普通常识，绕过了"反常识"这个自查触发条件。这也是 description 把「通常是」「我记得是」列进危险短语的原因（见 15.2）。

## 第 10 章 它怎么坏、怎么发现、怎么退

这一支 skill 没有"运行态"，所以它的"坏"不是崩掉，而是**形式合规、实质失效**——照格式写了，纪律一条没执行。下面六种坏法按发现难度递增。

### 10.1 失效形态一：四分类变成修辞装饰

**怎么坏**：输出里确实有【已验证事实】和【核心假设】两段，但真正的猜测被放进了"已验证事实"，假设段留着一个人畜无害的空话（"假设网络稳定"）。读者看到标签就放松了警惕，比完全没有标签更危险。

**怎么发现**：拿【已验证事实】里每一条问"你的来源和时点呢"——这一要求来自第 1 条（来源+时点+证据强度）。**凡填不出这三样的，都是被错放的假设**。这也是四段模板每段必带项的真实用途：它是给读者的追问清单，不是给写作者的格式要求。[实测]

**怎么退**：该条从"已验证事实"移到"当前假设"，置信度按 4.2 的档位重贴，并补写推翻条件（第 8 条）。

### 10.2 失效形态二：标注通货膨胀（置信度全打高）

**怎么坏**：三档区间存在一段时间后，所有结论都标"高 0.8–0.95"。因为标"高"看起来更专业，而**没人能给置信度打分做验收**——这就是 11.2 说的"无外部校验者"的必然结果。

**怎么发现**：用**事后校准**，这是唯一可行的办法——把所有标"高"的结论攒起来，事后核对实际正确率。若标"高"的一组里大量条目被推翻，档位定义已经废了（0.8–0.95 意味着大约每 10 条最多错 2 条，且第 8 条要求每条都写了推翻条件——你本来就该知道哪些被推翻了）。[推演] 具体会出问题的输入：连续 20 条"高置信度"结论里 6 条后来被实测推翻，说明"高"已经被用成语气词而不是概率；此时整套三档不再影响读者的行动，纪律退化成免责格式。

**怎么退**：把"高"的准入条件写死成"必须有 S 或 A 级证据"（第 9 条），其余封顶"中"。这是一条机械可执行的映射，本 skill 没做（见 15.7 未采纳项）。

### 10.3 失效形态三：两层设计漂移（实测已发生）

正文「定位」段与 v1.0 段声明常驻层与完整版同步、本文件为准。**实测：这套双写确实会漂**，方向常常出人意料——

- **常驻层实际是 5 条，而本 skill 正文两处给出的数不一致**：「定位」段写"4-5 条核心"（含糊），v1.0 段写"常驻层仅有 4 条精简版"（一个具体数），实测常驻层那一节列了 **5** 条编号项。三个说法并存。[实测]
- **常驻层里对同体系另一支 skill 的版本指针比库里旧一个版本**（指针写某支为 v2.1，权威库那份 frontmatter 已是 v2.2）。这说明"本文件为准 / 两处同步"这句声明**没有配套的校验动作**。[实测]

**怎么发现**：任何一次改动后，检查全部派生件里出现的"12 条""4 条""5 条"这些计数与版本指针是否仍与本体一致（步骤见 11.4）。
**怎么退**：把计数从"引用数字"改成"引用条目名"——不写"核心 5 条"，改写"核心条：分清事实/假设/未知、外部证据优先、编码前加载编码准则、结论可证伪、测试证据落盘"。名字漂移得比数字慢得多，且不一致时能被读出来。这也是本页引用纪律的同一逻辑（一律用章节名不用行号）。

### 10.4 失效形态四：尺子坏了而一切绿灯（第 3 条并入段治的正是这个）

**怎么坏**：不是偷懒，是勤奋地用了坏的检查——"三条断言全绿"或"零命中所以确认没有重复"。这种坏法最难发现，因为**输出里带着实测痕迹**。

**怎么发现**：看结论的形状是不是"通过 / 零命中 / 没报错 / 没落盘"式阴性句。是的话，问三个问题（并入段三条子机制）：几条断言是不是读同一个通道？阴性结论配过阳性对照吗？变异检验点没点名该翻红的那一条？[实测]

**怎么退**：阳性对照跑不出来 ⇒ 记 **VOID（尺子作废）**，本轮所有"没有/0 命中"结论不采信，换一条独立通道重测（并入段②的原文动作）。**绝不允许**在这个状态下报 PASS。

### 10.5 失效形态五：过度触发（该沉默时它说话了）

**怎么坏**：description 明写"宁多触发勿少触发"，代价是纯创作、闲聊、两秒可答的问题也走四段模板。表现为输出里满是"【核心假设】置信度 0.9"这种对读者毫无用处的标注。

**怎么发现**：看输出**信息量是否因标注而变化**。给"今晚吃什么"贴置信度＝噪声；给"这个接口参数类型"贴置信度＝有用（读者据此决定要不要自己再查）。
**怎么退**：正文其实已经写了降级路径——第 4 条"低影响：快速判断并标未验证"、第 7 条"一般技术判断可精简"。所以过度触发的修法不是少触发，而是**把输出压回第 4 条低影响档的形状**：一句结论 + "未验证"两字。[实测]

### 10.6 失效形态六：整份 skill 根本没被读到

v1.0 的"起因"就是这一条：准则此前只存在于长期规则目录，**AI 不会自动触发**，常驻层只有精简版，正文 12 条实际无人读。[实测]

这不是历史八卦，而是一个**至今仍然生效的失效模式**：本 skill 能否被读到，取决于 frontmatter `description` 能否在宿主清单里存活。若这台机器上装了很多 skill、清单超出预算，宿主会先砍"你最少用的那些"的描述——被砍掉描述＝触发词消失＝本 skill 事实上不再触发，而**这个失效不会有任何报错**：你会继续得到一个没被纪律约束的回答，并以为纪律在生效。

**怎么发现**：宿主自带的清单开销诊断命令或调试日志里的清单溢出警告；最直接的实测法是**问一个只该由触发词命中的问题，看它是否被加载**。[推演] 具体会出问题的输入：装了几十支 skill 之后，你反复得到"修好了"式的无验证结论，排查半天怀疑模型退化——实际是本 skill 的描述被清单预算砍掉了，从来没触发过。检查动作：直接按调用键点它；能点名成功却从不自动触发 ⇒ 触发词或清单预算问题，而不是规则本身的问题。

## 第 11 章 怎么验证它真在生效（这一支没有"体检"概念，所以写"可验证性"）

### 11.1 验证方法分三层

本 skill 没有脚本、没有附属文件，因此"体检"只能靠**静态检查 + 触发检查 + 事后抽查**：

| 层 | 检查什么 | 手段 | 什么时候查 |
|---|---|---|---|
| L1 静态：文件本身 | 版本坐标、计数一致性、被引用的名字能不能解析 | 查 frontmatter + 逐个解析被引用的 skill 名 | 每次改动后 |
| L2 触发：能不能被选中 | 危险短语是否仍在 description 里、清单是否溢出 | 按调用键点名 + 只靠场景描述能否命中 | 装了新 skill 后 |
| L3 行为：说出去的话合不合规 | 抽查输出是否带四要素 / 四段 / 未验证标记 | 人工抽查（11.3）+ 事后校准（11.5） | 每若干次高风险结论后 |

### 11.2 🔴 十二条可验证性逐条清点（本手册最重要的一张表）

判据（可执行的判定标准）问的是**同一件事**：是否存在一个可观察的输出或工件，使"这条被违反了"能被第三方指认？下表"正文要求"列逐项对应正文条号 [实测]；"可验证性"列是本页的判定，标 [推演] 处均给一个具体会出问题的输入。

| 条 | 正文要求的动作 | 有没有"能证明它被违反了"的判据 | 为什么 |
|---|---|---|---|
| **1** | 重要结论标 来源/时点/证据强度/置信度/推翻条件 | ⚠️ **部分**：五项痕迹可查，但**分母不可定** | "重要结论"没有定义 ⇒ 无法判定你**该**标的那些是否都标了。把所有句子都当"非重要"就能全绿 |
| **2** | 用户前提视为待验证假设；缺依据先指出 | ⚠️ **部分**：能查"有没有对前提做独立检验"的痕迹 | "一律视为"要求对**每一句**前提动作，而对话里的前提往往不成文、无法穷举审计。[推演] 失效输入：用户说"按昨天那个方案改一下"——"昨天的方案还存在、还对"是一个隐含前提，没有任何检查能发现你没验它 |
| **3** | 外部证据优先 + 闭环四要素记录 + 三条子机制 | ✅ **有**（全 skill 最强） | 四要素是**工件**（命令/环境/输入/输出可落盘）；子机制②有硬态（VOID ≠ PASS 可查）；子机制③有明确失败形态（没点名该翻红的那条）。触发条件是句式，句式可查 |
| **4** | 低/中/高三档 + 中档 ≥1 验证 ≥1 反例 + 四项检查 | ❌ **基本无** | 分档无判据、无客观边界；中档的"≥1"确实可数，**但你无法知道你处在哪个档**，于是无法判定"你少了 1 个反例"。[推演] 失效输入：任何一次结论都可以事后自称"这是低影响"，检查者无法反驳，因为正文没给分档依据 |
| **5** | 只依证据表态；反驳前先构造最强反方 | ⚠️ **部分**：能查"反驳段之前有没有一段加强版复述" | "最强"不可验证（无参照系）。[推演] 失效输入：对方论点有甲、乙两个理由，你复述并驳掉了较弱的乙，输出里**确实有一段"对方的说法是……"**，格式合规，最强反方从未被处理 |
| **6** | 只在新证据/更强逻辑下改口；五项不算新证据；改口记四要素 | ❌ 前半无判据 / ✅ 后半有 | "是否构成新证据"不可机械判定（这是认识论问题不是格式问题）。但**改口四要素是痕迹**：没记就是违反。[推演] 前半失效输入：用户把同一句话换三种说法、内容一字不变、语气一次比一次急——结论跟着变了也不算"新证据下改口"，而没有任何外部检查能判定这一点，只有事后比对两版输出才会发现 |
| **7** | 高风险走四段；一般判断须分事实/假设；低置信度禁确定语气 | ✅ 形式有 / ⚠️ 触发条件无 | 四段段名是最强判据（可查）；但"高风险或复杂"正是第 4 条那个没有判据的分档问题；"禁用确定语气"要人工判断措辞，正文没给危险词表（词表只出现在 description 里） |
| **8** | 写明推翻条件；不可证伪降级观点；可回溯；旧快照标"可能过期" | ✅ **有（较强）** | "有没有写推翻条件"是可判定的存在性检查（能否找到"若…则本结论不成立"形状的句子）。弱点在"不可证伪"的判定本身在自然语言里边界模糊 |
| **9** | 引用带 S/A/B/C 级标；C 只作线索 | ✅ **有** | 级标是痕迹。但**分级不可复算**（6.3 的三个洞）⇒ 你能证明"没标"，证不了"标错了" |
| **10** | 红队三问 | ❌ **无** | **自问不产工件**，做与不做在外部观察上完全同形。正文唯一的锚是「三」表最后一行把它绑到"自己刚写完代码"这个场景，但仍不要求写出三个答案。[推演] 失效输入：这恰是最常被静默跳过的一条，而它管的是"自己刚写完代码顺手给自己好评"——正是最难靠自觉抵抗的场景 |
| **11** | 说不知道 + 给验证路径或所需输入，不猜测填充 | ✅ **有** | "不知道"是显式短语，"验证路径"是可执行动作；两者缺一即可判违反。**全 skill 最可执行的一条** |
| **12** | 证据相当选最简；反常识要更强证据 | ❌ **无** | 没有"简单度"度量，也没有"反常识"的判定基准（跟谁的常识比？）。[推演] 失效输入："这个故障是竞态导致的"（复杂、听起来聪明）vs "是配置项写反了"（简单）——两条哪个"证据相当"没人能判，也就没人能说你违反了第 12 条 |
| **§一** | 每条信息四分类，回答里显式区分 | ⚠️ **部分**：标注存在性可查 | 但没有**最小组合要求**：一句结论是否也要四分类？正文没说 |
| **§三** | 七行翻车自查表 | ✅ **句式最具体**（适合当抽查靶子） | 它是提示不是判据：表本身不产生工件，但每一行都描述了一个**可观察句式**（"修好了"、"已落盘"、凭记忆写的版本号/提交号/API 名/路径） |

**清点结果**（数法：按 12 条 + 「一」+「三」共 14 行逐项判定，取每行主判）：✅ 有判据 **5 条**（3、7、8、9、11）＋「三」表 1 项；⚠️ 部分 **4 条**（1、2、5、§一）；❌ 无判据 **4 条**（4、6、10、12）。[实测]（判定依据逐条对上正文；比例是本页清点结果）

⇒ **这就是"骨架优于血肉"的定量形态**：接近一半的条款在缺少外部检查时**无法证明被违反**。但要看清一件事——**这不代表它没用**：

- 第 6、10、12 条的价值不在于"能被验收"，而在于**它们是那 5 条硬条款的语义来源**。没有第 10 条（红队），第 7 条第三段就会填成"暂无风险"；没有第 6 条（什么不算新证据），第 8 条的"推翻条件"会被一句情绪就满足。**软条款给硬条款供内容**，这是这类纪律文件的正常结构，不是缺陷。
- 真正的缺陷只有一个：**正文没有区分这两类条款的遵守方式**（硬条款靠检查、软条款必须靠强制留痕），于是执行者把它们一律当"提醒"处理。修法见 15.7。

### 11.3 五个可执行的痕迹检查（把 ✅ 那五条用起来）

| 检查 | 做法 | 判红条件 |
|---|---|---|
| T1 推翻条件存在性 | 对每条"事实/假设"句问"什么证据会推翻它"，检查回答里有没有这句话 | 找不到"若…则本结论不成立"形状的句子 |
| T2 四段完整性 | 高风险输出检查四个【】段名是否齐、每段必带项是否齐 | 缺段，或【潜在反例/风险】段为空/写成"暂无" |
| T3 闭环四要素 | 要求出示验证记录：命令 / 环境 / 输入 / 输出 | 只有结论没有原始输出，或没写环境（版本/平台） |
| T4 阴性结论配对照 | 凡结论形如"没有/零命中/没报错/没落盘"，要求出示同一把尺子的阳性对照结果 | 无对照；或对照失败仍报 PASS（应记 VOID） |
| T5 C 级不作依据 | 检查每条"事实"的来源可否出示（文件/链接/日志） | 来源是"我记得/通常是/应该是" ⇒ 同时违反第 9 条与第 12 条 |

[实测] 五项分别对应正文第 8、7、3、3（并入段②）、9 与 12 条。

### 11.4 版本一致性体检（改完就查，成本极低）

因为「定位」段声明"两处同步、本文件为准"，每次改动后至少查三件事：

1. 常驻层那一节的**条数**与本版描述是否一致（实测当前不一致：常驻层 5 条 vs 正文一处"4-5 条"、一处"4 条"——见 10.3）。
2. 正文的**计数键**是否还成立："12 条""§10 保留常驻核心并指向本文件"这两处若被改动，派生件要跟着改。
3. 正文引用的**外部名字**能不能解析：`A-Cao-测试纪律-测试证据形态规范`、`A-Cao-编码行为准则-写码改bug审查重构`、`A-Cao-磁盘缓存纪律-禁止落C盘与缓存重定向`（这三个是目录名，边界表用）；`write-readback-proof`、`acceptance-criterion-audit`、`live-service-probe-harness`（这三个是 skill 调用键，第 3 条与翻车表用）。[实测] 本页在 3.4 与第 7 章已实地检索：六个名字**全部可解析到实际存在的对象**，无悬空引用；但后三个与其各自目录名并不相同（目录是中文名），所以照名字去找文件会找不到——这一点写进 15.1。

### 11.5 事后校准（唯一能给置信度做验收的办法）

把带置信度的结论攒起来，事后核对哪些被推翻，按档位算实际错误率。这是 10.2 那类"标注通货膨胀"的唯一解药：只有对照"标高/标中/标低"各自的实际错误率，才知道三档还有没有信息量。[推演] 本 skill 目前**没有支撑这件事的留痕机制**——第 6 条要求改口时记四要素，那是唯一会留下"我错了"记录的地方；校准样本只能从改口记录里取。而改口记录散在对话里、不落盘，因此永远攒不出样本。这是它的一个结构缺口（第 3 条要求"记录"，却只对验证闭环要求，没对结论本身要求）。

## 第 12 章 端到端走查（完整示例）

用一个可照抄的真实输入走完全流程。这个例子故意选**本手册自身的话题**，这样读者能自己把每一步产出核对一遍。

### 场景：对话里用户这么说

> "我记得 skill 的 description 上限就是 200 字符，超了传不上去。我们那支 anti-hallucination-discipline 肯定超了，你把它压到 200 以内就行。改完应该就没问题了吧。"

这句话里有 **4 个待处理的东西**：一个记忆值（200）、一个关于本文件的断言（肯定超了）、一个动作指令（压到 200 以内）、一个反问式的结论索取（应该就没问题了吧）。

---

**第 1 步 — 四分类落位（「一」：先做这一步再回答）**

```
① "skill 的 description 上限就是 200 字符"   → 当前假设（来自用户记忆＝C 级线索，未检索到原文）
② "超了传不上去"                             → 当前假设（与 ① 是两件事，不可合并验）
③ "anti-hallucination-discipline 肯定超了"    → 未知（一次都没测）
④ "改完应该就没问题了"                        → 未知（无验收判据）
```

本步产出：**0 条已验证事实**。这一点必须写出来——多数对话在这一步就已经开始往下推了。

---

**第 2 步 — 前提审查（第 2 条）**

用户把三件事捆成一句：(a) 存在唯一上限 200；(b) 本文件超了；(c) 改短就能解决。指出前提问题，不照办：

- (a) 缺依据：上限有**多个并存的值**，适用面各不相同（第 6 步处理）。
- (b) 可直接实测，成本极低。
- (c) 含逻辑谬误：**把"满足某个限制"当成"唯一故障原因"**——若真有问题，它可能压根不是长度造成的。

---

**第 3 步 — 定风险档（第 4 条）**

判：这是**中影响**——改动会影响一支 skill 能不能被自动选中（触发面），但不涉及数据与安全、且改法可撤回。中影响要求 = **至少 1 次验证 + 1 个反例**。
⚠️ 这一步顺带暴露了第 4 条的弱点（11.2 表第 4 行）："中影响"是我给的判档，正文没有分档判据；另一执行者若判"低影响"，他会跳过第 4—7 步直接改文本——**这就是那条不可判定条款的具体失效输入**。

---

**第 4 步 — 取外部证据（第 3 条前半：有执行环境就真跑）**

先测用户"肯定超了"那个断言（一次最小验证）：

```
命令（只读，形状可照抄）：
  在本支 skill 目录下用一条脚本读 frontmatter 的 description 键值，
  去掉两侧引号，数它的 Unicode 码点数与 UTF-8 字节数。

环境：该支 SKILL.md，v1.2，133 行 / 8,796 字节

原始输出（逐字）：
  DESC_CHARS 184
  DESC_BYTES 487
```

**这一步把 ③ 从"未知"改成"已验证事实"**，且方向与用户预期相反：**184 < 200，没超**。

⚠️ **数法必须写出来**（第 3 条要求记录环境；第 8 条要求可回溯）：中文按**码点**数 184，按 **UTF-8 字节**数 487。两种数法下"是否 ≤200"的答案不同（487 字节超过 200 **字节**——但没有任何一套口径用字节衡量 description）。若再换"整行含键名与引号"这种更粗的数法，会得到第三个数。**数法不同 ⇒ 结论可能不同**，这就是必须写明数法的原因。

---

**第 5 步 — 先验尺子（第 3 条并入段，三条子机制逐个过）**

上面那个 184 能不能信？先证明量它的那把尺子会红：

```
① 同源检查：本次只有 1 条断言（字符数）来自 1 个通道 → 不构成"同一道闸抄三遍"。
   但相关的另两条断言（"描述里没有尖括号"、"name 键格式合规"）若都从同一次读到的
   字符串判，就按并入段①处理：把其中一条换成独立通道去问。

② 阳性对照（必做，因为本步的结论是一个阴性判断："没超过 200"）：
   先拿一个已知长度的串喂进同一把尺子 → 报出预期数 ⇒ 尺子有效。
   对照跑不出来 ⇒ 记 VOID（尺子作废），本轮"没超过"一律不采信，绝不许报 PASS。

③ 变异检验（要点名那一条）：
   故意在测试串尾部加 20 个字符 → 必须看到"字符数"这一条从 184 变 204（点名它翻红）。
   若只是"整套红了一次"而说不出是哪条红的 → 本次检验不算做过。
```

本步产出：**184 这个数可以采信**，且理由可复算。

---

**第 6 步 — 证据分级（第 9 条），三个上限各自归级**

关于"上限是多少"，检索到的三套口径**必须并列、不许合成一个数**：

| 值 | 适用面 | 级 | 依据强度说明 |
|---|---|---|---|
| **1,024 字符** | 开放标准与打包上传校验（校验器逐条检查项之一） | **S** | 有规范原文 + 校验器代码为证；可直接支撑"按 1,024 这条线本文件合规" |
| **1,536 字符** | 某宿主常驻清单的截断长度（描述 + 使用时机合并后在此截） | **S**（原文可指认） | 但它**不是上传限制**，是显示预算——只能支撑"清单里会不会被截" |
| **200 字符** | 某帮助中心文章提到的上传口径 | **B**（权威二手，单句为证） | 需交叉验证；本次**未能**在服务端校验原文上取证（该页在本环境不可达）⇒ 未检索到定论 |

结论形状由此确定：**"1,024 与 200 谁生效"这件事，诚实的标注是"未知（B 级来源、未能交叉验证）"，而不是挑一个当唯一值。** 这正是第 9 条 B 级"需交叉验证"与第 11 条"给不出结论就给验证路径"的联合应用。

---

**第 7 步 — 反例与红队（第 4 条后半 + 第 5 条 + 第 10 条三问）**

最强反方（替用户把话说强，而不是驳他的弱版本）：
> "即便 184 ≤ 200，任何为提升触发率而往 description 里加场景词的改动，都会先撞上 200 而不是 1,024——所以'按 1,024 设计字段'是个危险指导。"

这个反方**成立**，必须写进结论（不能因为"没超"就把它驳回）。

红队三问（注意：这一步要求把答案写下来——正文没这么要求，是本页在 11.2 里给第 10 条补的留痕动作）：

```
① 确认偏误？ → 有。我一开始倾向证明"用户记错了"，
              于是只测字符数、只检索对 200 不利的证据。
              纠正动作：把 200 那条来源单独列为 B 级并写明"未能定论"，而不是删掉。
② 失败边界？ → 有。中文按 UTF-8 字节计为 487（第 4 步）；
              若某套校验按字节而非字符，结论反转。这一条必须进风险段。
③ 若本次结论错，最可能原因？
              → "数法选错"（键值 vs 整行 / 码点 vs 字节），或
                "把清单截断预算（1,536）误当上传上限"。
```

第 ③ 问直接产出两条可复核的待查项——这就是"红队三问值得做"的具体证据；也解释了为什么第 10 条虽然无法被验收（11.2）仍然必须做。

---

**第 8 步 — 按四段模板输出（第 7 条），最终回答文本（形状可照抄）**

```
【已验证事实】
· 本支 skill 的 description 实测 184 字符 / 487 UTF-8 字节。
  来源：该支 SKILL.md 的 frontmatter；时点：本次会话；证据强度：A 级（可复现实测，数法已标明）。
· 开放标准与打包校验器的 description 上限为 1,024 字符。
  来源：规范原文 + 校验器检查项；时点：本次检索；证据强度：S 级。
· 某宿主常驻清单把"描述 + 使用时机"合并后截断在 1,536 字符。
  来源：该宿主文档原文；证据强度：S 级；性质：显示预算，不是上传限制。

【核心假设】
· "存在唯一的 200 字符上传上限"——置信度 0.4–0.7（中档）。
  推翻条件：取得服务端字段校验原文，且其中该字段上限 ≠ 200，或该条口径被撤销。
  （该值目前只有某帮助中心文章一句话为证＝B 级，需交叉验证；本次未检索到定论。）

【潜在反例/风险】
· 最强反方：184 虽未超 200，但任何加长描述的改动都会先撞 200 而不是 1,024，
  因此"按 1,024 设计"对未来的改动是危险指导。
· 边界：中文按 UTF-8 字节计为 487；若某套校验按字节而非字符，上述全部结论反转。
· 失败场景：真正的故障可能不是长度——本支的 name 调用键与目录名并不相同，
  按开放标准的"名字须等于父目录名"同样属不合规项；若上传被拒，更可能卡在这里。

【下一步验证建议】
· 最小一步：取到服务端字段校验的原文，或直接试传一次，确认是否存在 200 这条硬线。
· 在此之前不要改 description：改了既解决不了未知问题，又会把已验证的 184 这个基线弄丢。
```

**第 8 步里最容易被忽略的一处动作**：`失败场景`那条把话题从"长度"引到了 `name` 与目录名不一致（本支实测事实，见 15.1）——**这才是"改完应该就没问题了吧"的真实答案：不对，因为你还没确认故障是什么，而长度这一项根本没坏。**

---

**第 9 步 — 若用户回一句"你别管那么多，就按 200 改短"**

按第 6 条：**这不算新证据**（没有新事实、没有更强逻辑，只有不耐烦与命令重申）。正确动作不是照改、也不是抬杠拒绝，而是把决策交回有信息的一方，并留四要素：

```
旧结论：不改（184 未超任何已知字符上限，且上限归属未定）
新依据：无（重申指令不构成新证据）
新结论：仍不改；但给出两条可选路径让你选——
        A 压到 200 字符以内（现状本就满足，等于无需动作）
        B 先取到服务端校验原文再决定
置信度变化：不适用（未改口）
```

如果用户随后**出示了新的服务端报错**（含字段名与实际校验值）——那才是新证据，走改口四要素：把"不改"改成"按报错里的值改"，并写明置信度从 0.4 升到 0.9（新增了 S/A 级证据）。

---

**第 10 步 — 收尾留痕（「一」+ 第 8 条）**

```
已证伪：「本支 skill 的 description 超过 200 字符」
  推翻依据：实测 184 字符（A 级；数法＝Unicode 码点，不含两侧引号）。
  → 记为"已证伪"而不是"未知"，否则下一次还会被重新提出（「一」表第四类的存在理由）。
未知：「某上传路径的 description 字段校验值」
  → 保留为未知，并附验证路径；不许用"通常是 1,024"填空（第 1、11、12 条联合禁止）。
```

**整条走查用到的条款**：「一」四分类、第 1、2、3、3 并入段①②③、4、5、6、7、8、9、10、11、12 —— **十二条全部命中，四分类命中两次（开头落位、结尾留痕）**。这也是检验"这套规则是否只是十几句互不相干的提醒"最直接的办法：一条真实输入能把十二条串成一条流水线，说明它有内部顺序（顺序见 3.2）。

## 第 13 章 反模式清单：十二种把这套纪律用坏的方式

第 10 章写的是**它自己怎么坏**（无人故意时也会发生），本章写的是**人怎么把它用坏**——包括把它装进系统的人，和照着它说话的人。

判定口径（可执行的判定标准）：一条反模式必须能回答"照它做，输出上会多出或少出什么**可观察的东西**"。说不出这个的只是建议，不列进本章。每条末尾标它命中的条款，以及 11.2 对那条的判据评级：✅ 有判据 / ⚠️ 部分可验 / ❌ 无判据。

**A1 把四段模板当免责声明填**

- 症状：四个【】段名齐全，但【已验证事实】里装的是推断，【潜在反例/风险】写成"暂无"或"假设网络稳定"这类废话。
- 为什么看着像对的：格式 100% 合规，T2（四段完整性检查）这一关它能过——段名在、段落齐。
- 后果：读者按"已验证"三个字排期，成本由读者承担；更狠的是**标签信用被消耗**，第二次输出即便真的有据，读者也不再区分它——整套纪律最贵的那一处收益就此作废，比不打标签更危险（同 10.1，但那里是无意为之，这里是形式合规换来的偷懒）。
- 正解：对【已验证事实】逐条问"来源呢、时点呢"（T1），填不出的搬到【核心假设】并补推翻条件；【潜在反例/风险】为空即**判红**（让检查给出"不合格"这个结果）。→ 第 7、1 条（✅ 形式有判据 / ⚠️ 触发条件无）

**A2 让每一句陈述都走完整闭环**

- 症状："这个函数返回 int 还是 str" 也写四段模板 + 四要素记录（命令/环境/输入/输出）。
- 为什么看着像对的：看起来最守纪律，且能自证"我没有跳过任何一步"。
- 后果：成本与影响不匹配，执行者撑不过一周就开始整条偷偷跳过——纪律一旦在低成本场景显得荒谬，它在高成本场景也守不住（第 1 章末已给这条推演）。**结果是全量失效，而不是部分失效**。
- 正解：先走第 4 条分档（低/中/高三档），低影响只要求"快速判断 + 标未验证"两字。→ 第 4、7 条（❌ 分档无判据）

**A3 把"先验尺子"执行成"同一把尺子多跑几遍"**

- 症状：三条断言都从同一次读到的字符串里判，跑三遍全绿，宣布通过。
- 为什么看着像对的：重复测量是工程常识，三遍比一遍听起来严谨。
- 后果：这正是并入段①点名要抓的形状——**同一道闸抄三遍**（大白话：三处检查共用同一个可疑变量，那个变量本身错了，三条一起错，而且错得整齐划一）。全绿不算数，却会被当成物证写进结论。
- 正解：每条断言换一个**独立取数通道**（大白话：从别的地方、用别的方法再问一次）；或按并入段①做单变量检查。→ 第 3 条并入段①（✅ 有判据）

**A4 拿"没找到反例"当"结论成立"的证据**

- 症状："我搜过了，没发现反例，所以这个判断成立。"
- 为什么看着像对的：第 4 条确实要求"至少 1 个反例"，动作看起来做了。
- 后果：把**自己的搜索能力**当成**世界的性质**。这是一个阴性结论（"没有/零命中"式的话，零命中＝搜了一圈没找到任何匹配），按并入段②必须配一次阳性对照（大白话：先拿一个已知一定能过的东西试这把尺子，确认尺子在工作）。不配对照时它是**恒真判据**（怎么写都过）：无论结论对错，"我没找到"这句话都成立。
- 正解：跑对照；对照跑不出来记 **VOID（尺子作废）**——本轮所有阴性结论不采信，**未评估 ≠ 通过**，此时绝不允许报 PASS。→ 第 3 条并入段②、第 4 条（✅ / ❌）

**A5 把置信度当语气词用**

- 症状：所有结论都标"高 0.8–0.95"，因为标高档看起来更专业。
- 为什么像对的：没有任何外部检查会给打分做验收（11.2 第 1、4 行），标注不消耗任何东西。
- 后果：标注通货膨胀（同 10.2），三档失去信息量，读者的处置动作不再随档位改变；事后校准（11.5）也永远攒不出分档样本，因为连"当初为什么标高"都没有记录。
- 正解：本页提议的机械映射（正文未采纳，见 15.7）——**只有 S 或 A 级证据才准标"高"**，其余封顶"中"。→ 第 1、9 条（⚠️ / ✅）

**A6 用 S 级来源支撑一条从未复现的历史读数**

- 症状：引一份权威规范原文（S 级＝官方文档/源码/可复现结果），但被引的那个对象早就改了，而引用者没重跑。
- 为什么像对的：级别钉得完全正确，第 9 条表上就是 S。
- 后果：第 9 条只管**来源硬度**、不管**时点新鲜度**，这是两个独立的轴（6.3 列的三个洞之一）。硬证据 + 过时读数＝最难识破的错，因为它经得起"你来源是哪"的追问，却经不起"什么时候"的追问。
- 正解：第 1 条要求"时点"、第 8 条要求来自记忆或旧快照的结论标"**可能过期**"并重跑（「三」表第五行正是这一形状）。→ 第 1、8、9 条（⚠️ / ✅ / ✅）

**A7 把红队三问写成一段自夸**

- 症状：输出里加一句"已过红队自查，结论稳健，无风险"。
- 为什么像对的：第 10 条要求的是"**自问**三句"，而自问不产工件（11.2 判 ❌ 无判据的那四条之一），写不写这句话都能声称自己问过。
- 后果：第 10 条被"提及"而不被"执行"。它管的场景恰恰是最难靠自觉抵抗的那一个——自己刚写完代码顺手给自己好评（「三」表末行）。最该被拦的错一个没拦住，还额外获得了一道"已自查"的免检外观。
- 正解：三个答案**必须写下来**（这是本页在 11.3 与第 12 章第 7 步替它补的留痕动作，正文没有此要求）；第 ③ 问"若本次结论错，最可能原因"的每条答案都要变成一条可复核的待查项。→ 第 10 条（❌）

**A8 只驳对方的弱版本（稻草人式反驳）**

- 症状：对方论点有甲、乙两个理由，把较弱的乙复述一遍再驳掉，输出里确实有"对方的说法是……"这一段。
- 为什么像对的：格式合规，看起来执行了第 5 条要求的"最强反方论证"（steel-manning，大白话：用对方最好的理由把他的话说一遍，再去驳这个版本）。
- 后果：最强的那个理由从未被处理，而读者看到"已驳"字样，得到的是**错误的安全感**。这正是 11.2 第 5 行给的具体失效输入。
- 正解：照第 12 章第 7 步那个形状做——替用户把话说强；**反方成立时必须写进结论**，不能因为"我实测出 184 没超 200"就把它驳回（那条反方讲的是"未来的改动会先撞哪条线"，与本次读数无关）。→ 第 5 条（⚠️ 部分）

**A9 把"不迎合"做成"死不认错"，或把"不抬杠"做成"照办"**

- 症状：两个相反方向。方向一：用户一不耐烦就改答案。方向二：用户出示了带字段名与实际校验值的服务端报错，仍然维持原结论。
- 为什么像对的：前者像服务到位，后者像"顶住压力守纪律"（第 5、6 条读快了会读成"别被用户牵着走"）。
- 后果：第 6 条两向失效——它管的是**证据资格**，不是立场硬度。方向一让结论跟着情绪漂（且看不出是证据赢了还是脾气赢了）；方向二把该升的置信度压住，读者以为问题仍未定，于是不动手，白拿了一条已经足够硬的证据。
- 正解：五项不算新证据（情绪、重复、对方身份够权威、多数人都这么说、说话人自己很自信）；真新证据到手时必须走改口四要素（旧结论 → 新依据 → 新结论 → 置信度变化），如第 12 章第 9 步那样把置信度从 0.4 写成 0.9。→ 第 6、5 条（❌ / ⚠️）

**A10 把"未检索到"写成"通常是"**

- 症状：检索失败或是记忆值，却用常态句式填空（"通常是 1,024""一般是这样"）。
- 为什么像对的：读起来更完整，更像有把握的专业回答；而且它不显得自己在报错。
- 后果：**三重绕过**，这是本章性价比最高的一条——① 绕过「一」的"未知"类目（该类的强制标注是"直接写未知，不脑补"）；② 绕过第 12 条的"反常识"自查触发条件（9.4 那条推演说得很清楚：「通常是」三个字会把一个反常识主张伪装成普通常识）；③ 绕过 frontmatter 描述里那条危险短语触发线（见 15.2）——本该被这几个字自动拦下，改写成常态句式后连触发都不触发。
- 正解：第 11 条的形状——"不知道" + 一把读者能自己用的尺子（验证路径或所需输入）；二者缺一即违反（T5 的判红条件之一）。→ 第 11、12、9 条（✅ / ❌ / ✅）

**A11 引用一个写得很顺但根本不存在的对象**

- 症状：版本号、提交号、API 名、路径一次都没查就写下，而且拼写自然、看着完全可信。
- 为什么像对的：它和真对象长得一模一样，读者无从起疑。
- 后果：「三」表第三行给这类错误的处置是**阻断**——"引用不存在的对象 = 阻断"，也就是它**不允许**用"标个低置信度继续说"来降级过关。这是整套纪律里仅有的两处硬阻断之一（另一处是 VOID 状态下不许报 PASS）。绕过去的代价是把读者的整个排查方向带到一个不存在的对象上。
- 正解：先查再写（`git cat-file` / 查文件 / 读文档），查不到就写"未检索到"。→ 第 8、9 条与「三」表（✅）

**A12 把它当成拖延决策的工具**

- 症状：凡事先标"未知"，不给验证路径、不承诺下一步，把球干净地踢回读者。
- 为什么像对的：表面上严格遵守"不脑补"，而且永远不会被抓住说错话。
- 后果：第 11 条要求"不知道"**必须**配"验证路径或所需输入"，只有前半句是甩锅；读者拿到的信息量甚至低于一条标注得当的假设（假设至少给方向，未知什么也不给）。这类输出会让整套纪律被读者判定为"免责声明"，连带 A1 的信用损耗一起发作。
- 正解：每条"未知"后面必须跟一个可执行动作（最小一步），见第 12 章第 8 步【下一步验证建议】段那个形状。→ 第 11 条（✅，正文里最好执行的一条）

**这张清单的正确用法**（本页清点后的判断，[推演]）：A1、A5、A7、A8、A12 五条**都是"格式合规而实质失效"**，且都落在 11.2 判 ❌ 或 ⚠️ 的条款上——这不是巧合，而是同一条因果：**没有判据的条款只能用句式假装遵守**。所以外部抽查的火力应当集中在 ✅ 那五条（第 3、7、8、9、11 条，对应 T1—T5），剩下七条**只能靠 A1—A12 这类句式靶子人肉识别**，指望"跑个脚本验收"是幻想。[实测]（靶子句式取自「三、高频翻车场景」表与 description 危险短语）

### 14.2 我该走几步（分档动作卡）

### 15.1 命名规范：两套名字并行，且并不相同

| 对象 | 实际写法 | 后果 |
|---|---|---|
| 权威库目录名 | 中文长名（含连字符与"结论必须可证伪"这个后缀） | 人读友好，是文档与页内链接的**唯一合法引用形式** |
| frontmatter `name` 键 | 英文短调用键 `anti-hallucination-discipline` | 宿主按它寻址与点名加载 |
| 正文援引的其它 skill | 一律写**调用键**（`write-readback-proof`、`acceptance-criterion-audit`、`live-service-probe-harness`）或**目录名**（`A-Cao-测试纪律-测试证据形态规范` 等三支），两种混用 | 照调用键去目录树里找会找不到（那三个对象的目录名是中文），照目录名去点名加载会失败 |

[实测] 三个调用键与三支目录名**全部可解析到实际存在的对象**，正文没有悬空引用（3.4 与 11.4 已实地核对）。
⇒ **本页遵守的命名规矩**：对人讲的文档一律用目录名逐字引用；只有讲"宿主怎么加载"时才用调用键，且第一次出现就注明"这是调用键，不等于目录名"。

### 15.2 字段规范：frontmatter 只有三键，但每键都吃重

（**frontmatter**＝文件开头那段用三个短横线包起来的键值块，大白话：这份文件的"身份证页"，写名字、描述、版本。宿主要先读它，才知道该不该把正文读进上下文——"上下文"就是模型当前能看见的那段内容。）

| 键 | 值 | 为什么这么写 |
|---|---|---|
| `name` | 英文调用键 | 见 15.1，寻址用 |
| `description` | 184 个 Unicode 码点 / 487 个 UTF-8 字节（数法已在第 12 章第 4 步标明） | 它**是本 skill 真正的发动机**：v1.0 的"起因"就是"准则只在规则目录里、AI 不会自动触发"，而封装成带描述的 skill 之后才有人读 |
| `metadata` | `agent_created: true`、`version: v1.2`、`source: 一份记忆规则目录下的行为准则文件（12 条完整版，2026-09-01）` | `source` 让正文能追溯到自己前身；`version` 是本页页眉基准值的来源 |

**`description` 里的两个工程决定**，值得单独记：

1. **写明"宁多触发勿少触发"**——把召回率（该触发的都触发到）放在精确率（不该触发时别说话）前面。代价写在 10.5：过度触发，用第 4 条低影响档压回去。
2. **把危险短语本身写进描述**：「修好了 / 没问题 / 应该可以 / 我记得是 / 通常是」。这是整套纪律里唯一一处**把违规句式用作触发器**的设计——不是"教它该说什么"，而是"教它听到自己准备说什么就立刻自查"。
   ⚠️ 缺陷（[推演]）：这份词表只存在于 `description`，**正文第 7 条"低置信度不得用确定语气"没有配套词表**，于是只按正文执行、不看描述的执行者拿不到这份危险词表。本页在 14.3/14.1 里把它抄进速查表，就是给这个缺口补一个可用的出口。[实测]（词表确实只出现在 `description` 一处）

### 15.3 文件与附属件：渐进披露第三层为 0

- 实测该支附属件数＝**0**：同目录只有 SKILL.md，没有 CHANGELOG.md、references/、scripts/、assets/。[实测]（照抄主控方基准表"附属件 0"）
- 因此三层加载结构只用了两层：名字+描述（常驻）→ 正文（触发才读）→ **第三层空缺**。
- **版本史就地写在正文末节「版本」**（三段：v1.2 / v1.1 / v1.0），替代了 CHANGELOG 的功能。
- 得：单文件自包含，读它一份就够，不存在"附属文件没被加载"的失效；正文 133 行也确实在"触发即全读"的预算内。
- 失：（a）**没有可执行的体检**，第 11 章全部靠静态检查与人工抽查（这就是 11.1 那三层里最底下根本没有"脚本层"这一层的原因）；（b）版本史与规则正文共用一个文件，任何一处改动都可能碰另一处，而 15.4 那三个不一致的计数正是这种共写的产物。
- [推演] 具体会出问题的输入：正文若继续长（比如并入段再加两条子机制），最先撑不住的会是"触发即全读"这个假设——133 行时读得完，250 行时宿主或执行者会开始截断，而截断掉的恰好是**排在后面的翻车表和边界表**（第 12 章依赖它们，10.6 描述的正是这类静默失效）。

### 15.5 正文指向本机位置的两处引用：链接形态缺陷与公开化防护 🔴

正文有两处指向"本机记忆库里的东西"，形态不同、毛病相同：

| # | 正文的引用 | 形态 | 毛病 | 本页的替代写法 |

| ① | 「定位」段指向团队共享常驻行为准则文件的 §10 | 一条**指向本机磁盘某个位置的绝对路径链接** | 公开仓库里必然悬空（读者机器上没有那个位置）；同时泄漏本机目录布局 | 「团队共享的那份常驻行为准则文件的 §10 一节」 |
| ② | 第 3 条并入段指向一条踩坑记录的根因条目 | 同上，且**链接文字里带着该记忆库的条目编号** | 除上述两条外，还额外暴露记忆 store 的内部编号体系 | 「一条本地踩坑日志的根因条目」 |

🔴 **公开化防护规矩**（本页与本页之后所有 docs 页遵守；正文里那些形状**不许抄进公开页**）：

1. 零盘符绝对路径：任何"某盘符下某个目录"的形状，一律抽象成"本机记忆库""用户目录下的宿主配置"。
2. 零记忆库内部编号：条目号、层级目录名、决策号一律换成"一条踩坑记录""某次事故"。
3. 零人名代号：讲机制时只说"某个 agent""各 agent 各自的记忆库""用户"。
4. 零凭据形状：需要示例值时写"你的密钥"这种占位说法，绝不写任何看起来像真凭据的串。
5. 引用只允许"文件名 + 章节名／规则名／字段名"——第 3 条并入段那两处链接若要保留，应改成"指向同名 skill 的调用键"这种**在读者机器上也能解析**的形式。

**为什么这一节要写在"工程规范"而不是"写作注意"里**：因为它是**这条 skill 自身的分发缺陷**，不只是文档问题。同一份正文如果原样发布，两处引用对读者的可操作性是 0——第 3 条并入段的三条子机制是本页第 7 章论证过的"最硬一段"，而它给出的案例出处**对外部读者不存在**。修法（未采纳，登记进 15.7）：把案例与成套做法的指向换成"随附的公开页"或"同仓库内可解析的 skill 名"，把本机路径与条目号留在内部版。

### 15.8 冷启动：第一次装上，先做这五件事（探针式检查，只读不改）

"冷启动"指一支 skill 刚装好、还没有任何历史使用时的头一遍动作（大白话：新机器上头一回该怎么确认它真的在工作）。本支没有脚本，所以五件事全是**只读探针**（只检查、不改动任何东西的动作）：

1. **能不能被点名**：按调用键 `anti-hallucination-discipline` 直接要它——成功说明对象存在且可加载。失败先查 15.1 的两套名字混用。
2. **会不会自动触发**：不点名，只问一个该由它命中的问题（例如"帮我看看这个改动是不是有问题"）。自动触发失败＝`description` 问题，**不是规则本身的问题**，这一步要分清，否则 10.6 那种"以为在生效"会一路带着你走。
3. **清单预算还在不在**：本机装了很多支时，宿主会先砍最少用那几支的描述（描述被砍＝触发词消失）。查宿主的清单开销诊断或调试日志里的溢出警告。形状见 10.6。
4. **读的是哪一版**：确认加载的正文含"先验尺子，再信读数"这一段。不含就是 v1.0（差额见 15.6），此时你得到的是一套**没有尺子校验**的弱化版，必须知道自己在用弱化版。
