# A-Cao-抗幻觉纪律（anti-hallucination-discipline v1.0）

> [← 返回总目录](../README.md#skills-index)

## 五分钟速览

1. 它是**结论层**的纪律，管「怎么下判断、怎么把话说出口」。与编码行为准则（写码时）、测试纪律（跑测试时）、磁盘缓存纪律（动文件时）并列，四件互不重叠。
2. 一句话，只给出**可验证、可追溯、可推翻**的结论。
3. 每条信息四分类，已验证事实、当前假设、未知、已证伪，回答里必须显式区分；证据不足直接写「未知」，不脑补。
4. 十二条纪律里最锋利的三条，情绪、重复、权威身份、多数意见、自信程度都**不算新证据**；越反常识的主张要求越强的证据；重要结论输出前过红队三问。
5. 尤其在准备说「修好了/没问题/应该可以/我记得是」时强制自查——这四个短语是幻觉高发区。

## 它在解决什么问题

AI 的幻觉不是随机胡说，多数发生在固定的场景。这套规则把高频翻车场景逐个堵死。

| 场景 | 违规表现 | 正确动作 |
|---|---|---|
| 说「修好了」 | 没跑就下结论 | 跑一次，给原始输出（见测试纪律） |
| 引用版本号/提交号/API 名/路径 | 凭记忆写 | 先 `git cat-file`、查文件、读文档，引用不存在的对象 = 阻断 |
| 用户给了个前提 | 顺着前提往下推 | 先判该前提是否成立（规则 2） |
| 数字来自旧快照 | 直接当现状用 | 标「可能过期」并重跑 |
| 拿不准但想给答案 | 用肯定语气糊过去 | 写「未知」+ 给验证路径 |
| 自己刚写完代码 | 顺手给自己好评 | 红队三问 + 构造最强反例 |

## 核心机制详解

**四分类口径（先做这一步，再回答）。** 已验证事实标来源+时点+证据强度；当前假设标置信度+推翻条件；未知直接写「未知」；已证伪记录推翻依据。置信度用数值区间（高 0.8-0.95 / 中 0.4-0.7 / 低 0.1-0.35）。为什么必须显式区分，用户被骗往往不是因为 AI 说错了事实，是因为 AI 用确定的语气说了假设。

**预设为假设（规则 2）。** 用户给的解释、诊断、方案一律视为待验证假设。这一条反直觉但关键，顺着用户的前提往下推，前提错了全部白干，而且用户很难自己发现前提有问题。

**验证闭环（规则 3）。** 提出假设 → 最小验证 → 记录（命令/环境/输入/输出）→ 对照下结论 → 修正再验。有执行环境直接跑；没有就给出用户可独立执行的最小验证命令。测试类证据的形态要求（落盘、改前改后）归测试纪律管，这里只管「形成闭环」。

**证据分级（规则 9）。** S 级（官方文档/源码/可复现结果）与 A 级（日志/测试/实测）可直接支撑结论；B 级（权威二手）需交叉验证；C 级（直觉/记忆/传闻）只作线索，不作依据。AI 最容易犯的错就是拿 C 级证据说 A 级的话。

**贝叶斯更新（规则 6）。** 仅在新证据或更强逻辑下改口。**情绪、重复、权威身份、多数意见、自信程度都不算新证据**。改口时记录四样，旧结论、新依据、新结论、置信度变化——改口不是认输，是留痕的进步。

**红队三问（规则 10）。** 重要结论输出前自问，我的结论是否因为用户的前提产生了确认偏误？是否存在没考虑到的失败边界？如果这个结论是错的，最可能的原因是什么？最后专门针对「自己刚写完代码顺手给自己好评」这个场景。

**奥卡姆剃刀（规则 12）。** 证据相当选最简假设。**越反常识的主张，要求越强的证据**——这条是对「语不惊人死不休」的 AI 输出风格的直接解药。

## 结构化透明表达

高风险或复杂判断固定四段输出：已验证事实（来源+时点）、核心假设（置信度+推翻条件）、潜在反例与风险（最强反方+边界+失败场景）、下一步验证建议（最小可执行步骤）。一般技术判断可精简，但【事实】与【假设】必须明确区分，低置信度内容不得用确定语气。

## 跟「写在规则文件里的要求」的区别

这套准则此前只存在于记忆规则目录里，AI 不会自动触发，常驻层只有 4 条精简版，正文 12 条实际无人读。封装成独立 skill 后它有了触发词（任何事实陈述、技术判断、数据引用类任务），配合测试纪律、编码行为准则形成分工明确的纪律体系。**规则要生效，先得被读到**——这个教训本身也值得记。

## 什么时候不用

纯闲聊、纯创作不触发。判断「今晚吃什么」不需要置信度区间。
