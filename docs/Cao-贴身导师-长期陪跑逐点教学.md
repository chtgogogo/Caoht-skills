## 第 0 章 五分钟速览

1. **它不是"答题工具"，是一台陪学引擎**。四段流程写死在正文「工作流程」一节：阶段 0 深度摸底 → 阶段 1 目标对齐 → 阶段 2 生成框架与路线 → 阶段 3 循环教学。日常 90% 的时间只在阶段 3 里转圈。`[实测]`
2. **状态全靠 4 份 Markdown 文档承载**（`user_profile.md` 画像 / `learning_framework.md` 知识树 / `learning_roadmap.md` 路线 / `learning_journal.md` 日志），文档本身不进 AI 的"脑子"，靠每次开场重新读。`[实测]`
3. **生成任何文档之前必须先问存放位置**（规则名「存放位置 · 必问」，三选一），而且必须建一个**专用子文件夹**装这 4 份，绝不散落到父目录根。这是血的教训换来的硬规则（见第 4.5 节）。`[实测]`
4. **阶段 3 是一个 10 步死循环**：锚定 → 诊断起点 → 分解能力点（2–5 个）→ 讲解（每块 3–5 句）→ 最小示例 → 即时检验（1–2 题）→ 布置产出 → 掌握度检查 → 回写文档 → 给出下一步。一轮只推一个概念。`[实测]`
5. **"学会没学会"不靠感觉，靠 5 级量表**（Know / Use / Modify / Design / Transfer，即"知道 / 会用 / 能改 / 能设计 / 能迁移"），**L3「能改」才算掌握**，且判定必须至少 2 类证据（共 6 类证据可选）。`[实测]`
6. **两处最反直觉的硬规则**：①「沉默暂停」—— 出题后彻底停住，不许给提示、不许给斜体线索，等学习者回答；②「画像蒸馏」—— 不许写流水账，每次回写前先问"这条证据指向哪条不变式（能预测他下一步怎么错的规律）"。这两条是本页第 8、9 章的主体。`[实测]`
7. **借 AI 但不丢理解**：PEAR 四步（Plan 先写伪代码 / Explore 拿起点 / Analyze 逐行读懂 / Rewrite 自己重写）+ 阶段 2 的【了解即可】取舍（AI 已能代劳的部分只讲底层原理，不占深度练习时间）。`[实测]`

**一句话设计目标**：把一个"只会一次性给很多字的 AI"，改造成一个**记得你学到哪、按你的节奏一次喂一口、并且逼你自己开口复述**的长期陪跑教练——它衡量成功的唯一标准是"你的真实能力有没有涨"，不是"这一轮答得漂不漂亮"。

## 第 1 章 这套系统在解决什么问题

普通人用 AI 学习的真实故障，不是"AI 不会讲"，而是**讲得太会、你什么都没记住**。下表每一行都是真实会出现的现象：

| # | 故障 | 表现（你身上的感觉） | 本 skill 的解法（规则名） |
|---|---|---|---|
| ① | **一次讲太多，记不住** | AI 一口气回 800 字，看着很爽，关掉就忘光 | 「教学引擎 Layer 1 费曼表达」：每个讲解块 3–5 句；「语言与交互规则」：段落不超过 6 行、**一次一个概念，确认后再继续** `[实测]` |
| ② | **没人按我的进度教** | 每次都从零开始讲，或者突然跳到我不懂的地方 | 阶段 0 四轴摸底 → `user_profile.md` 记住水平；阶段 3 第 2 步「诊断起点」：缺前置先补前置再回主线 `[实测]` |
| ③ | **学过就忘** | 上周讲明白的，这周像没学过 | 「跨会话延续」：每次开场先做**检索复盘**（"上次那个场景你是怎么处理的？"，填空或确认），而不是重新讲一遍 `[实测]` |
| ④ | **学到哪了没人记得** | 换一次会话就得重新交代背景 | 4 份文档 + 可复制的**学习状态卡**（当前阶段 / 已掌握清单 / 待补前置 / 下次任务）`[实测]` |
| ⑤ | **AI 一给答案我就"觉得懂了"** | 代码跑通了，但说不清为什么这么写 | 「主动练习系统」的**沉默暂停** + PEAR 循环 + 「流畅性错觉」对策（见第 8.5 节）`[实测]` |
| ⑥ | **学习计划是通用模板，跟我不搭** | 网上一页页"21 天从零到精通"，对我没用 | 阶段 2 产出**专属** `learning_framework.md` + `learning_roadmap.md`，每阶段标"为什么先学这个"，按掌握度动态增删跳过 `[实测]` |
| ⑦ | **评价全是客套话** | "很棒！进步很大！"——到底哪不行没说 | 「角色与使命」：所有评价**基于证据**（你的作答、表述、作业），并在画像文档里标注依据；「语言与交互规则」：鼓励要绑定具体进展，不空洞夸奖 `[实测]` |
| ⑧ | **记录是流水账，看不出规律** | 记了 20 条"这里错了"，但不知道我到底哪类问题 | 「画像蒸馏原则」：先归因再记录，画像只留 1–2 条**能预测**你下一步怎么错的不变式 `[实测]` |
| ⑨ | **老师一直问不给我答案** | 我都说"直接告诉我"了，还在苏格拉底式反问，越问越气 | 「Layer 6 降级与边界」：学习者说"不懂／直接告诉我"→ **停止提问、直接讲解**，之后再温和给一次"讲回来"机会 `[实测]` |
| ⑩ | **它把我已有的文件覆盖了** | 打开目录，自己写的东西没了 | 「文档存储」的【存放位置 · 必问】+ 专用子文件夹 + 跨学科重新询问（这条源自真实事故，见第 4.5 节）`[实测]` |
| ⑪ | **换了个 AI 老师又从零开始** | 模型一换，之前教的都不算数 | 「跨 AI 老师延续」：每次开场先读画像与日志，**用同一套不变式继续教** `[实测]` |
| ⑫ | **它自己去调别的工具，我不知情** | 突然冒出我没要求的产出，或悄悄写了文件、烧了额度 | 「申请调用其他 skill 的协议」五步：**调用前必须以提问形式向用户申请**，等待确认，拒绝就改用自己的方法不纠缠 `[实测]` |

**其中 ⑤ 是最致命的**，因为它伪装成"效率"：AI 生成一段干净的代码，你复制粘贴跑通了，主观上"懂了"，实际上一次主动提取记忆的动作都没做。正文把这件事命名为「AI 生产力陷阱」，并在 `references/learning-principles.md` 里列出 5 条「AI 辅助风险画像」逐条拆它（见第 8.5 节）。所以**沉默暂停**和**讲回来**是这一支 skill 最不像"AI 该有的样子"、也最值钱的两条规则。

## 第 2 章 术语表

### 2.1 本 skill 自己的机制词

| 术语 | 一句大白话 |
|---|---|
| **贴身导师 / 陪学** | 不是"一问一答的工具"，是长期跟着你、知道你进度、按你节奏教的教练角色 |
| **摸底 / 深度诊断（阶段 0）** | 教之前先问清楚：你现在的水平、你的性格、你怎么学最快、你到底要什么 |
| **四轴** | 摸底问的四条线：实际水平 / 性格 / 学习偏好 / 目标与动机 |
| **框架总目录（`learning_framework.md`）** | 这门学科的"地图"：领域 → 子模块 → 知识点，像书的目录 |
| **路线（`learning_roadmap.md`）** | 把地图变成有序的第一站第二站，并写明"为什么先学这站" |
| **逐点教学 / 极细极碎** | 一次只教一个能验证的小点，教完马上确认，不贪多 |
| **能力点 / 可验证点** | 拆完之后每一小块都能出一道题来验，不能出题的块说明拆得不够细 |
| **微产出** | 5–20 分钟就能做完的小任务（写个 10 行脚本、写一段 200 字口播稿） |
| **掌握度量表（L1–L5）** | 知道 / 会用 / 能改 / 能设计 / 能迁移 五级，用行为描述而不是"感觉" |
| **讲回来（Retelling）** | 让学习者用自己的话把原理讲一遍，讲不顺＝没懂 |
| **检索复盘** | 开场先让你回忆上次的内容（而不是他重讲一遍），回忆这个动作本身就是在巩固 |
| **变式题（Variant）** | 同一个概念换个场景再问一次，防"只会那道题" |
| **前置缺口** | 你现在卡住，是因为再上一层的某块基础没有；先补它再回主线 |
| **不变式 / 不变量** | 从好几件具体小事里抽出来的一条稳定规律，强到能**预测**你下一步会怎么错 |
| **本质一句话** | 把整份画像压缩成一句能挂住所有证据的判断，如"前向链路强、校验回路待接通" |
| **待二次确认** | 只出现过一次的证据不许直接当特征，先挂标签等第二次 |
| **画像蒸馏** | 每 2–3 次学习把零散证据重新归并、修正或确认不变式（"蒸馏"＝多条浓缩成一条） |
| **学习状态卡** | 一小段可复制粘贴的文字：当前阶段 / 已掌握 / 待补前置 / 下次任务，方便你随时看、随时带去别的工具 |
| **费曼表达（Layer 1）** | 讲得让 12 岁孩子能听懂：先类比后术语、先大图后细节、先目的后定义 |
| **诊断式靶向（Layer 2）** | 先找到你真正的缺口，只从缺口处教，不从头铺 |
| **第一性原理追问（Layer 3）** | 追问"它为什么存在、解决什么问题、为什么不那样设计"，把死记变理解 |
| **未知分级 P0/P1/P2** | P0＝不知道它全盘卡住；P1＝不知道它理解会歪；P2＝可以先假设以后再补 |
| **协作式发散（Layer 4）** | 题目模糊或偏创意时先一起探问题，不急着给方案 |
| **自适应偏好（Layer 5）** | 你哪种讲法吸收得好，就多用那种；但要连续 2 次确认才敢写进画像 |
| **Never 项** | 画像里"绝对不要这样对我"那一栏，严格遵循，绝不违反 |
| **苏格拉底脚手架（Layer 6）** | 不直接给答案，用问题把你托上去；按卡壳程度分 4 档给不同多的帮助 |
| **降级** | 该给答案时就给答案，不再反问——防止"引导"变成折磨 |
| **PEAR 循环** | 用 AI 帮忙的四个动作：先计划、再探索、逐行分析、自己重写 |
| **沉默暂停** | 抛出问题后彻底停住，一个字都不再往下生成，等回答 |
| **信源分级** | 你没给材料时，AI 补讲依据的优先级：一手（官方文档/规范/论文）→ 经典教材与权威课程 → 高质量教程 |
| **事实 vs 建议** | 定义、定理、规范需求用确定语气；学习顺序、练习设计、工程取舍必须明标"这是建议"并给理由 |
| **【了解即可】** | 这类内容 AI 已能代劳，只讲底层原理和什么时候调它，不进深度练习清单 |
| **【需理解】/【需背记】** | 前者要能解释"为什么"；后者明确告知"直接记，别深究"，并给记忆锚点（好记的挂钩） |
| **领域专家发现** | 收到学习请求先扫一遍已装 skill 库，看有没有更专业的现成能力可借 |

### 2.2 中文行话（也算术语，一样要解释）

| 行话 | 大白话 |
|---|---|
| **回炉** | 把已经学过的内容再考一遍，不合格就重讲 |
| **进度锚** | 文档里记录"学到哪了"的那一行，下次从这里接 |
| **判据** | 可执行的判定标准——能拿一条输入去跑、能得出"过／不过"的那种 |
| **勾稽** | 两处数字能互相对上（比如日志里的掌握度和画像总览里的必须一致） |
| **幂等** | 同一件事重复做，结果不变（重复运行不产生第二份、也不越界） |
| **落盘** | 把内容写成磁盘上的文件，而不是只在对话里说一遍 |
| **回注** | 把之前存的内容重新塞回 AI 当前能看见的范围里 |
| **探针** | 只检查、不改动东西的小脚本或小问题 |
| **兜底** | 主路径走不通时的备用方案 |
| **悬空引用** | 指着一个已经不存在的行号或文件名，读者点过去什么都找不到 |
| **快照** | 把某个时刻的内容原样留一份，之后改动不影响它 |
| **占位符** | 先留一个明显是空壳的记号（如 `<你的目录>`），用的时候再替换 |
| **喂料** | 给 AI 提供背景资料的动作 |
| **口径** | 大家商量好的统一说法和统计方法，避免各写各的 |

### 2.3 工程与格式词

| 术语 | 大白话 |
|---|---|
| **skill（技能）** | 一个装了说明书的文件夹，AI 读到它就知道该怎么做事；本页讲的就是其中一支 |
| **SKILL.md** | 这个文件夹里那份主说明书，AI 真正读的正文 |
| **frontmatter** | 正文最开头用两条 `---` 夹起来的那块"身份证信息"（名字、描述、版本） |
| **description（描述）** | frontmatter 里那段"什么时候该用我"的话，是 AI 决定要不要加载这支 skill 的唯一依据。本支折叠成一行后实测 **383 个字符**（数法：把 YAML 里折行的 description 拼回单行、按字符计，中文一个字算 1） |
| **渐进披露（Progressive Disclosure）** | 分三层给信息：常驻清单只放名字和一句描述 → 正文按需读 → `references/` 只在要用的时候才打开，目的是不撑爆 AI 的记忆窗口 |
| **references/** | 外挂文档目录，本支有 6 份，正文末尾「资源」一节逐个列了用途 |
| **CHANGELOG** | 升级记录，写清每个版本"做了什么／解决了什么／怎么解决的" |
| **md5 / sha256** | 给文件算一个"指纹串"，改一个字指纹就全变；用来核对两份副本是否逐字相同 |
| **MIT 许可证** | 一种很宽松的开源自带条款，允许你拿去改造成自己的东西，署名即可 |
| **lineage（来源署名）** | 正文最后一节，交代这支 skill 是由哪两支前代 skill 合并提炼来的 |

`[实测]` 附属件数＝7（6 份 references ＋ 1 份 CHANGELOG）。为什么外挂要拆 6 份而不写进正文：正文每次被加载都要吃掉整个记忆窗口，而"讲代码时的橡皮鸭调试技巧"只有真在教代码才用得上——**拆出去等于平时不占预算**。

### 3.2 SKILL.md 的 15 个一级小节，按职能分四区

| 区 | 小节（正文里的原名） | 职能 | 存在的理由 |
|---|---|---|---|
| **A 立规矩区** | 角色与使命 | 定"什么叫成功" | 开篇就把目标从"答对问题"扭到"让人变强"；这一节决定后面所有冲突时往哪边倾斜 |
| | 画像蒸馏原则（本质优先 · 用户 2026-08-23 要求） | 定"怎么记录" | 放在**很靠前**的位置，因为它是所有文档回写的总开关；放后面就等于回写完了才看到规则 |
| | 文档存储 | 定"文件放哪、有哪几份" | 含【存放位置 · 必问】——事故换来的硬规则，必须早于任何写文件动作 |
| **B 流程区** | 工作流程（阶段 0/1/2/3） | 定"按什么顺序做事" | 正文唯一写"严格按阶段顺序推进"的地方，是整个 skill 的骨架 |
| **C 引擎区** | 教学引擎（分层）Layer 1–6 | 定"怎么讲、怎么帮" | 把"讲得好"这种玄学拆成 6 个可分别开关的层 |
| | PEAR 循环 / 主动练习系统 / 跨会话延续 | 定"怎么防遗忘、怎么借 AI" | 三者共同对抗第 1 章的 ③⑤④ 三个故障 |
| | 领域专家发现与调用申请 / 申请调用其他 skill 的协议 | 定"什么时候借力、借力前必须先问" | 让本 skill 既能当教练又能当调度台，但把决定权留在用户手上 |
| | 特殊场景（挫败／考试备战／辩论答辩备战）／语言与交互规则 | 定"说话的样子" | 段落 ≤6 行、一次一个概念、绝不说"你错了"——语气也是机制不是装饰 |
| **D 溯源区** | 资源 | 索引 6 份 references | 让读者知道"细节在哪份外挂里"，正文不必全塞 |
| | 版本记录 / lineage | 自证来源与同步规则 | 声明唯一权威库、副本要 sha256 逐字校验、以及由哪两支前代 skill 合并而来 |

### 3.3 判定顺序（三套，别混）

**（一）加载顺序——什么时候读哪一层**

```
1. 常驻清单（frontmatter 的 name + description，383 字符）
   ↓ 用户说了触发词（教我 / 陪我学 / 帮我制定学习计划 / 我想学 / 导师 /
     学习路线 / 摸底 / 帮我规划 / 检查一下我学得怎么样）
2. SKILL.md 正文 207 行
   ↓ 只在真要用的那一刻
3. references/ 里对应那一份
   · 要判掌握度 → mastery-rubric.md
   · 要出题/纠错/讲解 → teaching-playbook.md
   · 第一次建画像 → profile-template.md
   · 布置项目 → project-patterns.md
   · 要补学习者没给的材料 → source-strategy.md

```

`[推演]` 反例：如果把 6 份 references 全并进正文，一次性加载约 30 KB 文本，AI 会在"学习者只问了一个小知识点"的这一轮也把所有教学技巧读一遍——预算花掉了但用不上，且更容易把后面章节的细则挤出可见范围，结果是**十步循环只记得前 4 步**，退化成普通长篇回答。

**（二）教学时的层触发顺序**（第 7 章详解）

Layer 1 费曼表达 ──── 常开
Layer 2 诊断式靶向 ── 常开

**（三）一轮教学该不该收尾的判定**（`teaching-playbook.md` 「六、何时收尾」）`[实测]`

```

## 第 4 章 阶段 0–2：摸底、对齐、框架与路线

### 4.1 阶段 0 深度诊断：四轴 ＋ 每轮 3–5 问

正文「阶段 0 — 深度诊断（先全方位了解）」原文要求：**结构化提问，每轮 3–5 个，可多轮，覆盖四轴**，并且"每轮拿到新信息，立即回写 `user_profile.md` 的对应字段"。`[实测]`

| 轴 | 要拿到什么（原文列举） | 为什么这一轴不能省 |
|---|---|---|
| **① 实际水平** | 目标领域现在在哪（入门／进阶／？），做过什么、卡在哪 | 决定从哪一站起步；缺了它，路线的第一站会错——错一步后面全歪 |
| **② 性格** | 遇困难是硬刚还是易放弃？需要鼓励还是鞭策？对模糊指令的耐受度？ | 决定**纠错姿态**。同一个"答错了"，对硬刚型可以追问，对易放弃型要先降难度重建信心（正文「特殊场景」第一条） |
| **③ 学习偏好** | 偏看／听／练？先宏观再微观还是反过来？注意力时长？喜欢类比／流程图／实例哪一种？ | 决定讲法。这一轴的产出直接写进画像的「风格」「格式」「工具」三个字段（见 `profile-template.md`） |
| **④ 目标与动机** | 为什么学？要达成什么具体结果？能投入多少时间？有无 deadline（如答辩、考试）？ | 决定**取舍**。有 deadline 才允许触发「降级边界」里的"可给结果但事后必须复盘" |

**为什么是"四轴"而不是"水平＋目标"两轴？** `[推演]` 两轴只能定内容，定不了节奏和语气。具体反例：学习者性格属于"易放弃"，两轴 AI 给他排了个难度陡增的路线，第 3 节就受挫；此后它只会重复讲得更细，而正文的对策是"降低难度、回到已掌握内容重建信心"——**这条对策只能从性格轴推出来**。

**为什么每轮限 3–5 问？** `[推演]` 少于 3 问，一次拿不到能设计框架的信息，得多轮往返；超过 5 问，问题列表在视觉上就变成一张问卷，非技术背景的学习者常常只答前两三个、剩下的整片跳过——**跳过信息后 AI 会去猜**，而猜出来的画像会一路污染后面的回写（因为它看起来"已经记录过了"）。3–5 是"这一屏能一口气答完"的宽度。

### 4.2 停止提问的硬标准（不许凭感觉提前收尾）

原文「**停止提问的硬标准**」：四轴＋动机均已拿到足够信息、能据此设计框架时，才停止诊断进入阶段 1；"明显不足则继续问，不要凭感觉提前收尾"。`[实测]`

这条是把"诊断做够了没"从**主观感觉**变成**可检查清单**：四轴逐个问一遍"我能不能据此写出这一站的起点"。
`[推演]` 典型坏输入：学习者第一句就抛"教我 Python 怎么写爬虫"。AI 很容易顺势开讲——但性格轴、偏好轴、deadline 全空。此时按硬标准必须先问，讲出来的内容就无法控制粒度（该给类比还是给流程图？不知道），最终退化成通用教程。

**若上下文已经清楚则跳过**：`teaching-playbook.md` 「一、诊断提问序列」末尾写"若上下文已清楚，跳过直接教"。它把诊断的 4 个问题列为：想学什么／已经知道做过什么／产出是什么会在哪用／真正的卡点是概念、练习、材料、时间还是反馈。`[实测]`

### 4.3 阶段 1 目标与范围对齐

原文要点：**先与学习者对齐再动手写框架**；若目标过大，拆成**可验证**的阶段。`[实测]`

"可验证"＝每个阶段结束能拿出一个东西或答对一道题。
`[推演]` 不可验证的阶段目标长这样："第 1–2 周：熟悉网络基础"——"熟悉"没有任何判据，做完和没做完在文档上看不出区别，掌握度也就无法回写。写成"能画出一次 HTTP 请求从发起到页面渲染的 4 步并说清每步在干什么"才可验证。

### 4.4 阶段 2 生成框架与路线：两份文档 ＋ 一条取舍原则

产出并**先给学习者看、确认**（不是写完就自动往下教）：

| 文档 | 内容形状 | 独有字段 |
|---|---|---|
| `learning_framework.md` | 知识树总目录：领域 → 模块 → 知识点 | 只回答"这学科有什么"，不含顺序 |
| `learning_roadmap.md` | 分阶段路线：每阶段目标 / 产出 / 检查点 | 必标**"为什么先学这个"**的理由 |

**为什么要两份而不是一份？** `[实测]` 因为**更新触发不同**：框架只在"范畴调整"时改（很少），路线在"掌握度变化导致增删跳过"时每轮都可能改（很频繁）。合成一份的话，每改一次路线都要重排整棵树，且分不清"是地图错了还是我的进度错了"。

**取舍原则（正文标了"关键"）**：只保留"值得学习者亲自学"的内容。对 AI 已能代劳、只需懂底层逻辑的部分（如现在 AI 写代码很强，许多语法细节不必死记），标注 **【了解即可】**，不占深度练习时间，只讲清底层原理与何时调用 AI。其余按"理解 vs 背记"分类标注，供阶段 3 第 4 步使用。`[实测]`

这条原则的学理依据在 `learning-principles.md` 的「AI 辅助风险画像」5 条（该文件末尾自己写了"这正是'AI 已能代劳的部分只需懂底层逻辑'的底层依据——见 SKILL.md 阶段 2 取舍原则与 PEAR 循环"）。

### 4.5 【存放位置 · 必问】：一条被事故逼出来的规则

正文这一节用加粗写着"本技能**绝不写死固定目录、绝不把文档散落父目录根**"，并交代起因：曾经用一个写死的默认目录直接覆盖了用户已有的同名文件。`[实测]`

规则形状（照抄可执行）：

```
生成任何文档之前 → 必须先问，三选一或用户自定：
  1. 用户指定目录："这几个文档你希望放在哪个文件夹？（可给具体路径）"
  2. 当前工作区新建："要不要放在当前工作区 <显示当前工作区路径>，
     我新建一个专用文件夹装它们？"
  3. 其他指定位置：用户给任意路径
确认后 → 创建一个专用子文件夹
        （建议名 `贴身导师定制化文件/`，或按学科命名如 `贴身导师-唱歌/`）
        本技能所有文档统一装入这一个文件夹
        若用户已有该学科的专用文件夹 → 直接沿用，不重复新建
跨学科 / 跨项目时 → 重新询问，不沿用上一个学科的位置
选定后 → 在本次会话开头明确告知："文档将保存在 <最终路径>"
```

`[推演]` 这条规则的必要性可以直接构造：用户在同一个目录下原本有个自己写的 `user_profile.md`（比如健身记录）。AI 按默认路径写学习画像 → 文件被覆盖 → 用户发现时已不可恢复（`CHANGELOG` 的"自记事故"条目就是这件事）。**"专用子文件夹"这个动作把命名冲突的可能性从"很高"降到"接近零"**，因为它把文件名空间从公共目录切成了本 skill 独占。
"跨学科重新询问"同理：`[推演]` 学唱歌的文件被沿用到学代码的会话里，就会出现"代码学习画像里躺着呼吸训练记录"的脏数据，而这种脏数据看起来格式合法、很难被发现。

### 4.6 文档必须中文

原文：「所有文档用中文（学习者看不懂英文）」。`[实测]` 这条不是客套——它是阶段 2 能不能真的"先给学习者看、确认"的前提；文档是英文的话，确认这一步形同虚设。字段名（如 `Never`、`Known Concepts`）保留英文是因为模板本身就是半中英的，正文「语言与交互规则」也写明"默认中文，必要英文术语保留"。

## 第 5 章 阶段 3 十步循环：逐点教学的发动机

正文「阶段 3 — 循环教学（日常核心）」：**每轮严格按以下循环**，并参考 `references/teaching-playbook.md` 的诊断/讲解/纠错模式。`[实测]`

| 步 | 名字 | 干什么 | 关键数值／标注 | 为什么是这个数 |
|---|---|---|---|---|
| 1 | **锚定与目标** | 回顾上次（做检索复盘），定义**本次一个**清晰产出 | "一个"，不是"几个" | 一轮只有一个产出，掌握度判定才有唯一对象；两个产出会互相掩盖（一个会一个不会时说不清整体过没过） |
| 2 | **诊断起点** | 评估当前水平，识别前置缺口；缺前置先补前置，再回主线 | 前置补完**必须回主线** | 只补不返会漂到别的主题上去，路线越拖越长 |
| 3 | **分解能力点** | 拆成 **2–5 个**可验证点，标注【核心】与【了解即可／可延后】 | 2–5 | 少于 2 个＝没拆（一整块没法判掌握度）；超过 5 个＝这一轮讲不完，第 4 步的预算先爆 |
| 4 | **讲解** | 极细极碎，用**学习者的语言水平与类比**讲清；明确打标 | 【需理解】讲透原理（是什么／为什么存在／解决什么问题／与相邻概念的区别），要能解释"为什么"；【需背记】"直接记，不用深究" ＋ 给记忆锚点 | 见第 7.1 节 Layer 1：每块 3–5 句 |
| 5 | **最小示例** | 编程给可运行示例；非编程给迷你案例；**先整体示例再拆解** | 先整体后拆解 | 先给碎片学习者不知道拼成什么；先整体才有"目标形状" |
| 6 | **即时检验** | 讲完**一个小节点**立刻出 **1–2 道**小题确认真懂 | 1–2 题 | 这是"讲到懂"和"讲过了"的分界线；题数超过 2 就变成练习课，第 7 步的微产出预算被吃掉 |
| 7 | **布置作业／产出** | 默认**输出型**任务：微产出 5–20 分钟 → 小项目 1 节 → 阶段项目多节；模板见 `project-patterns.md` | 三档进阶 | 5–20 分钟是"一次坐下就能做完"的长度，做完才有反馈；超这个长度会拖到下次，反馈一延后错误就先固化 |
| 8 | **掌握度检查** | 默认含一次**讲回来**；再加 retelling／纠错／变式／迁移／迷你实现 中**至少 2 类证据**；按 `mastery-rubric.md` 5 级判定。**L3 以下不标记掌握**；失败则回溯缺哪个前置 | 1 次讲回来 ＋ ≥2 类证据，阈值 L3 | 见第 6 章整章 |
| 9 | **回写文档** | 更新 `user_profile.md`（水平变化、新偏好信号）、`learning_journal.md`（过程＋掌握度＋错误日志）、必要时 `learning_roadmap.md`（已掌握 → 标跳过，薄弱 → 加练）；**均按画像蒸馏原则执行** | 先归因再记录 | 见第 9 章整章 |
| 10 | **给出下一步** | 小结、盲点、下次任务、建议时长、检查点 | 五项齐 | 正文「角色与使命」独立规定"**每次回复结尾，简短说明'下一步我们将做什么'**"——这一条比阶段 3 更硬，它约束每一句回复而不只是一轮结束 |

### 5.1 十步为什么是这个顺序（不是随便排的）

```
1 锚定 ── 先定位"我在哪"，否则起点随机
2 诊断 ── 先确认前置在不在；前置不在就跳过 3–8 先去补
3 分解 ── 先划出这一轮的范围与验证对象
4 讲解 ── 内容进入
5 示例 ── 把抽象内容钉在一个具体东西上
6 即时检验 ── 立刻验，别攒到课后（攒到课后＝错误已固化一整节）
7 产出 ── 从"看懂"逼到"做出来"（L2→L3 的唯一通路）
8 掌握度检查 ── 只有此时才能定级：证据已经齐了
9 回写 ── 定级之后才能写，先写就是猜
10 下一步 ── 收尾必须给锚点，否则下次开场没有可复盘的对象
```

`[推演]` 把 8 提到 7 前面（先判掌握再布置作业）会直接坏：判据只剩"讲回来"一类证据，够不到"至少 2 类"，于是只能标 L2；而 L2 的定义恰好是"能照例子完成基础任务、语境一变就崩"——这个"崩"要靠第 7 步的产出才暴露得出来。

### 5.2 讲解块的粒度：3–5 句 / 段落 ≤6 行

Layer 1 原文"每个讲解块控制在 **3–5 句**"，「语言与交互规则」原文"段落不超过 **6 行**；复杂处用图"、"**一次一个概念**，确认后再继续"。`[实测]`
`[推演]` 超粒度的样子：一次回复 15 句讲完"闭包"，中间夹 3 个例子。学习者读到第 10 句已经忘了第 2 句的条件；此时第 6 步出 1 道题，答错的是第 3 句的概念，但他自己说不清错在哪——因为根本没有"块"的边界可以指回去。

### 5.3 非编程学科不例外，但类比要换

「降级与边界」第 4 条：话题与代码无关（纯数学、写作等）时，类比与示例切换到对应领域，**不强行套编程术语**。`[实测]`
`project-patterns.md` 给了两条平行轨道：编程类产出形态是最小可运行 demo／改 bug 重构任务／小任务简报／微项目里程碑；非编程类是短研究报告／演示提纲／读书笔记／案例分析／知识地图／对比表／口播稿／复盘文档。`[实测]`
所以"极细极碎逐点教学"对唱歌、辩论、考试同样成立——第 5 步的最小示例在唱歌课上就是"只听这 4 小节的示范再自己哼"。

### 5.4 纠错矩阵：卡住时不是"再讲一遍"

`teaching-playbook.md` 「三、纠错矩阵（卡住时）」5 行 `[实测]`：

| 卡住类型 | 应对 |
|---|---|
| 概念不沾边 | 换类比、加图、与相似概念对比 |
| 练习不足 | 更小粒度练习、即时反馈 |
| 信息过载 | 删材料，只留当前主线 |
| 任务过大 | 缩到"一个能完成的产出" |
| 反馈滞后 | 提前插入检查点 |

配合 Layer 2 末尾的"**仍卡住则换角度而非重复**"。`[实测]` 两者合起来是一条很硬的纪律：**同一句话不许讲第二遍**，第二遍必须换个载体（类比→图→对比→更小练习）。

## 第 6 章 掌握度量表：把"学会了"变成可判定的东西

来源：`references/mastery-rubric.md`（改编自前代陪学 skill 的同名文件），用于阶段 3 第 8 步。以下逐级引原文含义。`[实测]`

### 6.1 五级逐条详解

| 级 | 名 | 达标的行为 | **不算**掌握的情形（原文自带） |
|---|---|---|---|
| **L1** | Know 知道 | 能复述定义或关键词；认得出相关术语；大致知道它解决什么问题 | 离开定义就讲不清；给不出例子，或分不清相邻概念 |
| **L2** | Use 会用 | 能照例子完成基础任务；在熟悉语境中复用；能做标准题／练习／简单回顾 | **语境一变就崩**；能套模板但讲不清为什么 |
| **L3** | Modify 能改 | 能修改已有的解法／笔记／项目／论证结构；能发现明显错误、缺口、边界；能用自己的话重组 | ——原文称**"这是'跟随'到'独立思考'的分水岭"** |
| **L4** | Design 能设计 | 能从目标反推学习路径／解法／项目计划；能解释"为何这样而不是那样"；能把复杂主题拆成可完成的小块 | 检查题：为什么这么组织？条件变了计划哪里会变？ |
| **L5** | Transfer 能迁移 | 能迁移到新主题／新项目／新表达场景；能抽取通用模式；能教别人、给反馈、做评审 | ——原文称**"这是稳定掌握"** |

### 6.2 为什么 L3「能改」是分水岭

`[实测]` 原文直接写"这是'跟随'到'独立思考'的分水岭"。
`[推演]` 理由可以从 L2 的定义里反推出来：L2 的失败形态是"语境一变就崩"——也就是说 L2 的表现为**照做**，照做时学习者并没有做决策，所有决策都是模板替他做的。而"改"这个动作**强制他做决策**（保留什么、替换什么、为什么这里要动），一做决策就会暴露他不知道的边界。所以 L2→L3 之间不是量的差距，是"有没有参与决策"的质变。这也是为什么第 7 步的"微产出"必须放在第 8 步判级之前。

### 6.3 证据类型：6 类里至少取 2 类

原文「证据类型（至少 2 类）」列出 6 项 `[实测]`：

1. **复述**（Retelling，用自己的话讲一遍）
2. **纠错**（Error correction，给他一个有错的东西让他找出来）
3. **变式题**（Variant problems，同概念换场景）
4. **迷你实现或迷你推导**（Mini-implementation / derivation，动手做出来／推出来）
5. **材料重组**（Material reorganization，把给定的材料重排结构）
6. **应用到学习者自己的项目或语境**（Application to own context）

SKILL.md 阶段 3 第 8 步的写法是"默认含一次'讲回来'；再加 retelling／纠错／变式／迁移／迷你实现 中**至少 2 类**证据"。`[实测]`
**为什么要两类？** `[推演]` 单类证据可以被"背下来"骗过去。具体反例：学习者复述得极流畅（第 1 类满分），但那个月背的就是这段——给他一道变式题就崩。两类**不同性质**的证据（一个提取语言、一个提取操作）同时通过，"只是记住了字面"的解释就站不住了。

### 6.4 5 条判定规则

原文「规则」5 条 `[实测]`：

1. **L1–L2 绝不标记掌握。**（这是"不许自我安慰"的硬闸，也是这张量表最容易被违反的一条）
2. **独立"能改 ＋ 能设计 ＋ 能迁移" ＝ 稳定掌握。**（要三级齐，不是最高级到就算）
3. **评估失败：回溯缺了哪个前置，先补前置。**（失败不是"再练"，而是"往前找缺口"）
4. **一次只推一项能力，不把重 topic 捆绑推进。**
5. **默认阈值：能解释 ＋ 能应用 ＋ 能迁移。**

`[推演]` 规则 4 和"一次只推一项"看起来是同一件事，其实是两道闸：前者管**教学时**（一节课别塞两个大主题），后者若被删掉，**判级时**就会出现"这块整体 L3、那块整体 L2，所以这门课算 L2.5"这种糊在一起的分数——而糊在一起的分数没法指导"下一步该加练什么"。

### 6.5 为什么是 5 级，不是 3 级或 10 级

`[推演]`
- **3 级**（知道／会用／掌握）分不出 L2 与 L3，等于放弃本表最重要的一条界线（第 6.2 节）；实务里的表现就是"会跟着写代码"被记成"掌握"，两个月后独立写还是不会。
- **10 级**的相邻两级没有**可观察的差异**——判级人拿不到"第 6 级和第 7 级分别该看到什么行为"的判据，结果就是每级都由心情定；量表立刻失去可比性，跨会话、跨 AI 老师记录下来的数字互不相关。
- 5 级的成立条件是**每级都有一条能出题验证的行为描述**，本表 5 条描述各自不同（复述／照做／修改／反推／迁移）。

### 6.6 掌握度怎么落到文档里

- `profile-template.md` 的「掌握度总览（动态）」字段格式：`[知识点] → L_（日期）`，注释要求"已掌握知识点 → 量表等级 L1–L5 ＋ 日期；薄弱项标红"。`[实测]`
- 该总览与 `learning_journal.md` 里的过程记录、`learning_roadmap.md` 的"已掌握 → 跳过／薄弱 → 加练"三处必须一致（**勾稽**＝三处能对上）。
`[推演]` 不一致的最早信号：画像总览写"闭包 → L3（某日）"，但日志里那一节只有一条复述证据、没有产出。此时 L3 是虚标，后续路线会把闭包标成"可跳过"，学习者在新场景里再次卡住——而且这次没人知道根因在哪。

## 第 7 章 六层教学引擎：三个常开、三个看情况

来源：SKILL.md「教学引擎（分层）」一节。`[实测]`

### 7.1 Layer 1 费曼表达（始终开启）

原文 5 条动作 ＋ 1 条自检：**每个讲解块 3–5 句**；生活类比先于术语；先大图后细节；先目的后定义；能用图不用纯文字。讲完自问"**一个 12 岁孩子能听懂吗**"。`[实测]`

- "先目的后定义"的用法：讲 HTTP 缓存不是先给"HTTP 缓存是……"，而是先说"服务器同一个文件被反复请求很累，于是让浏览器存一份一段时间不再问"，再给定义。
- "能用图不用纯文字"对应画像模板里的「工具（偏好的教学工具）」字段——图／内嵌图示的选择是要被记录、被复用的偏好，不是每次临场决定。

### 7.2 Layer 2 诊断式靶向（始终开启）

原文流程：**基线（"用自己的话说说这个"）→ 定位缺口（概念／语法／逻辑／信心／练习／过载）→ 只从该缺口教 → 费曼验证 → 仍卡住则换角度而非重复**。`[实测]` 括号里 6 类缺口。

"不盲教，先找真实缺口"是这一层的原话。
`[推演]` 不先定基线的成本：学习者真正的缺口是"语法不熟"，但答错的样子和"概念不懂"一模一样（都说不出下一步）。不测基线就开讲概念，讲了 20 分钟，他的语法缺口一个都没被填上，且这一节的第 8 步判级会因为"他确实能复述概念"被误标——误标直接导致路线里该知识点被划掉。

### 7.3 Layer 3 追问第一性原理（深度时触发）

目的原文一句话：**把背记变成理解**。问句两条："为什么存在？解决什么问题？""为何这样设计、替代方案的成本？"
配套 **未知分级**：`[实测]`

| 级 | 含义 | 处理 |
|---|---|---|
| **P0** | 阻塞全部——不知道它就整段没法理解 | 必须先解决，不许往下走 |
| **P1** | 改变理解——不知道它结论方向会歪 | 讲清，可带不确定性继续 |
| **P2** | 可假设——先按合理假设推进 | 记录假设，以后回头补 |

并且"**记录决策使推理可追溯**"（"可追溯"＝事后能查出当时是凭什么定的）。
`[推演]` 不分级的后果：三个 P0、两个 P2 混着一起追问，一节课全花在"为什么"上，一个可验证点都没推完——学习者会觉得问明白了，但掌握度只能标 L1，因为连一次产出都没有。P0/P1/P2 的作用就是**给"追问"这件事加上预算闸门**。

### 7.4 Layer 4 协作式发散思考（开放／创意／研究类探索时触发，来自 study-cao）

原文动作：面对复杂、模糊或创意类主题，**先问再答**——追踪灵感笔记、不急于给方案、温和挑战假设、跨领域连接；**停留探索模式，不跳到结论**。`[实测]`
`[推演]` 触发条件缺失时会误开：学习者问的是"这个报错什么意思"（明确、单一、有正确答案），AI 进入发散模式开始"我们一起探索一下报错背后的心智模型"——这一轮 0 产出，第 6 步也出不了题。反过来（该开不开）的代价是创意类主题被强行塞进"三点式答案"，学习者拿到的是一堆他没认可的假设。

### 7.5 Layer 5 自适应偏好学习（始终开启）

原文：**新信号出现 → 连续 2 次确认才记录到 `user_profile.md`；"Never" 类条目严格遵循，绝不违反**。`[实测]`

**为什么是 2 次不是 1 次或 3 次？** `[推演]`
- 1 次：学习者某天状态差、恰好说"直接给我例子吧"，画像就永久写上"偏好例子"；此后连他其实更适合看流程图的那些概念也一律用例子教，纠错成本极高，而且没人知道是哪一天写错的。
- 3 次：一次偶然的好信号要再连续两次复现才能被记下，学习者会明显感觉"教法一直不改"。2 次是"偶然被过滤掉、稳定被及时抓住"的最低门槛。
- **Never 项的例外规则是"零次容忍"**：它不是偏好，是禁止项（例如"不要在深夜给我布置长任务""不要在我没写完时打断"），所以不适用"连续 2 次确认"，写进去即刻生效、绝不违反。

### 7.6 Layer 6 苏格拉底脚手架（卡壳时触发，来自 Sensei 导师）

核心：**通过提问引导，不直接给答案**；但帮助量按卡壳程度分 **4 档**（SKILL.md 与 `teaching-playbook.md` 第八节两处表格逐字一致）`[实测]`：

| 卡住程度 | 帮助类型 | 实际给出去的东西 |
|---|---|---|
| 🟢 轻 | 引导问题 ＋ 建议查阅的文档 | 一句话提示 ＋ 一个可查的位置 |
| 🟡 中 | 伪代码或概念图 | 结构骨架，但没有可运行的内容 |
| 🟠 重 | **带空白的不完整代码片段** | 有代码形状，关键处留空让他填 |
| 🔴 严重 | 详细伪代码 ＋ 逐步引导提问 | 接近完整解法，但每一步仍要他回答 |

`[推演]` 为什么 4 档而不是 2 档：只有"提示"和"给答案"两档时，学习者一喊难就直接跳到给答案，中间那些"其实给个骨架就能自己走完"的情况全部被浪费——**🟠 那档（留空的代码）是本表最高杠杆的一档**：它让学习者仍然要亲手做关键决策，但不会因结构问题卡死。2 档会把这一档抹平掉。

### 7.7 降级与边界（正文标了"关键"）——四条

`[实测]`

1. **学习者说"不懂／直接告诉我"** → **停止提问，直接讲解**，随后**温和提供一次**"讲回来"机会。
2. **学习者明显受挫** → 先诊断原因，再给**可执行的小步**，**不硬套苏格拉底**。
3. **学习者明确要直接答案**（赶 deadline、已试多种方法）→ 可给结果，但交付后**必须安排复盘**讲清每一行／每一步。
4. **话题与代码无关**（纯数学、写作等）→ 类比与示例切换到对应领域，不强行套编程术语。

第 1、2 条在 `teaching-playbook.md` 「八、苏格拉底脚手架」的「降级边界」里也重复了一遍（两处措辞一致，属"正文与外挂互为校验"）。

`[推演]` 这三条为什么是硬边界而不是风格建议：苏格拉底式的价值来自"他自己想出来"，前提是**他愿意被这样带**。他开口说"直接告诉我"的那一刻，继续提问的性质就变了——从脚手架变成惩罚。具体坏输入：deadline 前一晚，学习者说"求你直接给我这段代码"，若 AI 坚持反问"你觉得第一步应该是什么"，实际后果是他放弃使用这套学习流程、去问别处，整套机制当场失效。规则 3 的"给完必须复盘"就是给这条裂缝打的补丁：**答案可以先给，理解不能欠**。

### 7.8 代码专项技巧（教编程时才用，`teaching-playbook.md` 第九节）

`[实测]` 6 条：
- **橡皮鸭调试**："把代码一行行讲给我听，就像我是个橡皮鸭"——**讲不清的地方就是没懂的地方**（这是"讲回来"在代码场景的极致版）。
- **最小可复现**："能把问题隔离在 10 行以内的代码里吗？"（"可复现"＝每次都能稳定重现同一个错误，只有先缩小才谈得上定位）
- **红-绿-重构**：先写会失败的测试定义期望行为（红）→ 写最少代码通过（绿）→ 保持测试通过的同时重构。
- **验证四维度**：功能性（边界情况？）、安全性（恶意输入？）、性能（复杂度？）、整洁（半年后别人看得懂？）。
- **安全问题暂停**：发现安全隐患立即停下预警："⚠️ 这里有个关键安全问题，你能发现吗？"（唯一一处允许打断教学节奏的场景）
- **完全卡死升级**：超出导师能力（如需人类资深把关）时建议结对编程／在团队频道提问／开草稿 PR／用 AI 的 explain 搞懂后带着收获回来。

## 第 8 章 主动练习、沉默暂停、PEAR：对抗"AI 生产力陷阱"

来源：SKILL.md「主动练习系统」「PEAR 循环」＋ `references/learning-principles.md` ＋ `references/teaching-playbook.md` 第七节。

### 8.1 沉默暂停规则（正文标了"关键"）

原文逐字 `[实测]`：抛出问题后**彻底停住，不再生成任何后续内容**——不给提示、不给"想想看…"、不给斜体线索、不给参考答案。
**只允许补一句**，两个固定选项之一：

- "(猜错也没关系，错误预测也是有用数据。)"
- "(这题也可以跳过。)"

学习者回应之后，才给"把思考连到实际行为"的反馈。`teaching-playbook.md` 第七节开头把这条**逐字重复**了一遍（两处一致，说明它是刻意加固的规则）。

`[推演]` 为什么"不给斜体线索"要单独点出来：模型在等待回答时最容易做出的动作不是给答案，而是给一句 `*提示：想想上次那个循环*` 这种"看起来不算答案"的斜体提示。它恰好把第 8.4 节的**生成效应**破坏掉——学习者不需要自己生成了，只要接住现成的提示。所以这条规则的强度全在"任何"两个字上。
`[推演]` 只准补那两句的原因：那两句的作用是**降低回答的心理成本**（允许猜错、允许跳过），而不是给信息。若允许自由补一句，模型会补出一句内容线索，边界立刻破防。固定两句是"把一句话的自由度收干净"的做法。

### 8.2 6 种练习类型

SKILL.md「练习类型」与 `teaching-playbook.md` 第七节两处枚举一致，均为 **6 类** `[实测]`：

| 类型 | 原话形状 | 训练的动作 |
|---|---|---|
| **预测 → 观察 → 反思** | "预测 [场景] 会发生什么？" → 一起看实际行为 → "什么让你意外？什么符合预期？" | 提前下注（制造"错得很具体"的机会） |
| **生成 → 对比** | "在我展示怎么处理 X 前，先勾画你的思路。" → 展示实际 → "相似？不同？为何走这个方向？" | 在无范本时自己产出一个方案 |
| **追踪路径**（逐步暂停） | 给具体场景与数值，每步决策前暂停："请求到了中间件，下一步？" 逐步揭示 | 每一步都亲自决策，不给"看懂了就跳过"留缝 |
| **调试此题** | 给一个合理 bug／边界 → "这里会出什么错、为什么？" → "你会怎么修？" | 从"读"翻到"找错"，反向用知识 |
| **讲回来** | "把 [组件] 工作原理讲给新人听。" → 针对性反馈哪里到位、哪里要打磨 | 复述与组织，掌握度第 1 类证据 |
| **检索复盘**（跨会话） | "快速回忆，上次 [主题] 怎么处理 [场景]？" 填空或确认 | 隔一段时间后主动提取，不只在新知上讲 |

### 8.3 何时提供：一个软邀请 ＋ 两个停止条件

原文：讲完核心、或刚完成编程／设计类工作后，**先问"要不要做个 10–15 分钟的快速练习？"**；**本节已拒 1 次**或**已完成 2 次**则不再提供。`[实测]`

**为什么是"拒 1 即停"？** `[推演]` 被拒后再问第二次，性质就从邀请变成推销，学习者会开始敷衍式同意（"行吧"）——敷衍同意产生的练习数据质量很差，还会污染画像（"他练习表现下降"被误读成能力问题，其实是抵触）。
**为什么上限是"完成 2 次"？** `[推演]` 一节的注意力预算有限，3 次以上练习会把第 7 步的微产出挤掉；挤掉产出后就再也拿不到"迷你实现"这一类证据，掌握度判定反而降级（回到只剩复述类证据，见第 6.3 节）。
**10–15 分钟**这个区间：短于 10 分钟做不完"预测→观察→反思"完整三环，长于 15 分钟就要占用本节讲解时间，需要重新排第 3 步的能力点数量。

### 8.4 学理依据：5 条原理对应 5 处机制

`learning-principles.md` 的 5 个小节（该文件共 6 个 `##`，第 6 个是 AI 风险画像）`[实测]`：

| 原理 | 原文"发现" | 原文"应用"→ 对应到本 skill 哪条机制 |
|---|---|---|
| **生成效应**（自己产出的信息比被动读到的记得牢） | 主动产出比被动消费编码更好；测试比被动复习带来更好的延迟记忆 | 预测→观察→反思、生成→对比、讲回来——全部**强制主动提取**（"提取"＝靠自己想出来而不是再看一遍） |
| **预测试**（先答再学，答错也有效） | 学习前先尝试作答，即使错了也能形成更强记忆；错误尝试通过对比让正确答案更难忘 | 追踪代码前先问"你预测会怎样"；展示实现前先问"你会怎么入手"；正对应沉默暂停"错误预测也是有用数据"那句 |
| **间隔效应**（分散练胜过临时灌） | 分散练习远比集中填鸭保留好；掌握度越高，间隔可越长 | 开场做检索复盘；练习分散在多次会话；**掌握度检查放在间隔后而非立刻** |
| **交错**（混合相关主题一起练） | 混合不同但相关主题比按块练更提升长期保留与迁移 | 学完 A 后把 A 与相关 B 一起练；变式练习＝同一概念换不同场景 |
| **元认知**（会监控自己学法的人学得更好） | 能监控并调整自身策略的学习者表现优于不监控者 | 设置反思时刻、引导自评；"什么让你意外？"；留空间让人察觉自己的心智模型与缺口 |

`[推演]` "掌握度检查放在间隔后而非立刻"这条最有意思：立刻检查测的是短时记忆，间隔后检查测的才是真保留。若把第 8 步放在讲完 30 秒内，学习者会稳过 L2–L3，路线于是大面积超前，而他两周后什么都没留下——**这是"看起来在进步、实际在积累假账"的最典型形状**，也是本 skill 用检索复盘开场的原因。

### 8.5 AI 辅助风险画像 5 条（为什么"AI 帮我写完了"仍等于没学）

原文 5 条编号 `[实测]`：

1. **生成效应被破坏**：直接接受生成的代码，跳过了主动加工。
2. **流畅性错觉**（"流畅"＝看着顺）：干净的生成代码让人"感觉懂了"，其实没懂。
3. **间隔被消除**：机器速度把人推向填鸭。
4. **元认知被压制**：高速流程不留监控学习的余地。
5. **测试被少用**：更少机会从提取中受益。

**PEAR 循环**是这 5 条的正面解法（来自 Sensei 导师）`[实测]`：

| 步 | 名 | 动作 | 它专门抵消哪条风险 |
|---|---|---|---|
| **P** | Plan 计划 | 让 AI 生成**前**，先写伪代码／注释，逼自己先思考 | 1（生成）、5（测试） |
| **E** | Explore 探索 | 用 AI 拿到起点或建议 | ——（这是唯一允许"直接用 AI"的一步） |
| **A** | Analyze 分析 | 逐行读懂，不清楚的让 AI 解释每一行 | 2（流畅性错觉） |
| **R** | Rewrite 重写 | 用自己的话／风格重写一遍 | 1、3（重写要花时间，天然把练习拉开） |

正文在 PEAR 之后立刻补了一句：**即使赶 deadline 由 AI 生成了结果，交付后也必须安排复盘讲清每一步**（与第 7.7 节边界 3 是同一件事的两次声明）。`[实测]`

`[推演]` 不跑 PEAR 的具体坏输入：学习者让 AI 生成一个爬虫脚本，跑通了，报告说"我学会 requests 了"。画像会写上"requests → L3"。但整个流程里他没有做过一次决策（P 缺席）、没有读过一行（A 缺席）、没有产出自己的版本（R 缺席）——真实的等级至多是 L1。下一次让他处理"目标站点每页结构不一样"时他完全无从下手，此时路线早已翻篇。

### 8.6 项目模板：两级字段，全部最小化

`project-patterns.md` `[实测]`：
- **选题**：编程类＝构建可运行、可调试、可扩展的东西；非编程类＝可表达、可分析、可迁移的东西；范围一律"**本轮带反馈可完成**"，不要大而全。
- **编程类任务简报最小 5 字段**：目标、输入／输出、约束、验收标准、一个变式挑战。
- **非编程类任务设计最小 5 字段**：主题、产出格式、目标受众、使用场景、评估标准。
- **进阶三档**：微产出 5–20 分钟 → 小项目 1 节会话 → 阶段项目多节会话（形成作品集／系统成果）。
- **检查点必含 4 项**：复述目标／解释关键取舍／指出常见错误／做一个小迁移。

"验收标准"这个词＝**做完拿什么判定合格**（判据）。`[实测]` 每个项目都强制含"指出常见错误"这一项，是因为"能认出错误"是 L3「能改」的必要条件（见 `mastery-rubric.md` L3 的"能发现明显错误／缺口／边界"）。

## 第 9 章 画像蒸馏、四份文档与跨会话状态

### 9.1 蒸馏原则 5 条（正文标题写着"本质优先 · 用户 2026-08-23 要求"）

`[实测]`

1. **先归因，再记录**：每次回写前先问"这条证据指向哪个**不变式**？"，把零散现象归并为同一特征的实例。
   正文自带的示例（全文最说明问题的一段）：**漏答一半／忽略外层 try／算对方向反／贴码结论靠猜**——不是四个独立问题，而是同一个不变式"**局部执行强、闭环校验弱**"的四个实例。
2. **提取最普适精准的特征**：画像优先写 **1–2 个不变量**（正面一条 ＋ 反面一条），每个不变量必须能**预测**学习者下一步会怎么强、怎么错；不能预测的观察只是现象，**降级为证据挂在不变量下**。
3. **证据链要求**：每个不变量**至少挂 2 个独立证据**；单次证据标"**待二次确认**"，不许直接上升为特征。
4. **定期蒸馏**：每 **2–3 次学习**做一次画像蒸馏——重新归并证据、修正或确认不变式、更新"本质一句话"（原文例子：如"前向链路强、校验回路待接通"）。
5. **文档形态分工**：`user_profile.md` 保留"学习本质"小节（本质一句话 ＋ 正面／反面不变量 ＋ 支持性观察）；`learning_journal.md` **记证据与归因，不重复堆现象**。

### 9.2 "归并"到底怎么发生：拿正文那 4 条走一遍

| 表面现象（流水账会各写一行） | 归因方向 | 归并后的不变式 |
|---|---|---|
| 题目漏答了一半 | 没回头检查自己的输出完整性 | **局部执行强、闭环校验弱** |
| 写代码忽略了外层 try（异常保护） | 只想到"正常路径"，不检查失败路径 | 同上 |
| 算对了但方向反了 | 结果出来后没跟预期对照 | 同上 |
| 贴了 AI 生成的代码，结论靠猜 | 拿到产出后没有验证环节 | 同上 |

预测力（不变式的价值全在这里）：拿到"闭环校验弱"这条之后，可以**提前预测**——他大概率会在新知识点上"做出结果但判错好坏"；于是下一节的第 7 步微产出可以刻意要求"给出你的结果，然后说明你凭什么认为它是对的"。流水账做不到这件事，因为它没有一条能贯穿四件事的规律可以拿去预测。

**为什么阈值是"至少 2 个独立证据"** `[推演]`：1 个证据永远是巧合——任何单次错误都能找到第四种解释（那天没睡好、题看错了）。要把它当成"这个人的稳定特征"，最低要求是有两次不相关场景下的复现；这也是为什么"待二次确认"这个标签本身是机制的一部分：它让第一次的观察不丢失，但不许它获得特征的身份。
**为什么蒸馏周期是 2–3 次** `[推演]`：每节都重蒸一次会让画像一天三改、路线跟着抖，学习者不知道按哪个执行；隔 5 节以上再蒸，已经写进去的错判断会先被用来指导好几节教学（且已被固化）。2–3 是"错得还来得及纠正、又不至于一直抖"的窗口。

### 9.3 四份文档：各自记什么，什么时候更新

| 文档 | 记什么（原文） | 更新触发（原文表格第三列） | 关键纪律 |
|---|---|---|---|
| `user_profile.md` | 对学习者持续、动态的评估：水平、性格、学习偏好、认知强弱项、已掌握／未掌握清单；**含"自适应偏好"、"掌握度总览"与"学习本质"** | 每次诊断新信息、每次教学后 | 只留能预测的不变式；现象挂证据 |
| `learning_framework.md` | 学习框架总目录：领域→子模块→知识点树的全局地图 | 阶段 2 生成；**范畴调整时** | 平时不动（很少动） |
| `learning_roadmap.md` | 分阶段、有序、标注"为什么先学这个"及每阶段目标／产出／检查点 | 阶段 2 生成；**掌握度变化导致增删跳过时** | 每轮都可能动 |
| `learning_journal.md` | 每节日期、讲解要点、学习者暴露的水平、作业与作答、导师评价与下一步调整；**内嵌掌握度检查与错误日志** | **每次教学后追加** | 记证据与归因，不重复堆现象 |

`[实测]` **为什么 journal 不许重复画像里的现象**：两处都写＝两处迟早对不上（勾稽断裂）。分工是"画像＝结论（能预测的不变式），日志＝原始证据链（谁在什么时候做了什么、答成什么样）"。结论变了要能查到是哪几条证据支持的；证据攒够了要能重算结论。合成一份的话，要么结论淹没在几十条现象里读不出，要么只有结论、日后无法复核。

### 9.4 画像模板的字段骨架（第一次建画像时照它填）

`profile-template.md` 共 **12 个 `##` 小节**（数法：按文件内以 `## ` 开头的行计数）`[实测]`：

```
基本信息（姓名／称呼、目标领域、当前总水平 入门|进阶|熟练）
风格 ← 怎么讲最容易吸收          格式 ← 类比／流程图／实例
工具 ← 偏好的教学工具            Never ← 严禁做的事，严格遵循
性格与动机（遇困难硬刚／易放弃；需要鼓励还是鞭策；动机与 deadline；可投入时间）
掌握度总览（动态）：[知识点] → L_（日期），薄弱标红

学习本质（蒸馏）：本质一句话 ＋ 正面不变量（证据①②）＋ 反面不变量（证据①②）＋ 支持性观察

模板头部就写着"新偏好信号 → 连续 2 次确认才记录；'Never' 项严格遵循"——和 Layer 5 逐字呼应，**说明这条规则在正文和外挂里互为校验**。

### 9.5 跨会话延续的三条动作

`[实测]`

1. **开场检索复盘**："快速回忆一下，上次 [某主题] 里 [某场景] 是怎么处理的？"——填空或确认。
2. **输出可复制的学习状态卡**：当前阶段、已掌握清单、待补前置、下次任务；"便于随时观看回忆"。
3. **跨 AI 老师延续**（v1.2.0 新增）：学习者可能更换 AI 老师／模型，**每次开场先读画像与日志，用同一套不变式继续教学**，保证跨模型一致。

`[推演]` 状态卡为什么要"可复制"而不只是写在文档里：学习者会把它带去别处（问另一个工具、贴进自己的笔记、贴在日历上安排时间）。只写文档 = 每次要看还得打开文件、让 AI 读一遍；而带出去的那份如果被复制走就会变成"两个版本"，所以正文的做法是**卡片是快照、文档是唯一真相源**（"真相源"＝改动只在这里发生的地方）。

### 9.6 讲授质量的两道外部闸：信源分级 ＋ 事实／建议分离

`source-strategy.md` `[实测]`：
- **信源三级**（学习者未提供材料时按此顺序补充）：① 一手来源＝官方文档、原始论文、规范（spec）、权威标准；② 经典教材／标准著作／权威课程／专业机构；③ 高质量教程／最佳实践／成熟经验。**学习者已提供材料时，优先以其材料为准。**
- **事实 vs 建议必须分清**：事实依据（定义、定理、规范需求、可验证结论）用确定语气陈述；建议／判断（学习顺序、练习设计、工程取舍、路线安排）**明确标注"建议"并说明理由，不伪装成唯一正确答案**。
- 应用：遇到有争议或版本相关的点，指明"这是建议／某版本行为"，**避免学习者记错**。

`[推演]` 这一条对"老师是 AI"这件事格外要紧：AI 讲一个版本相关的行为时若用统一的确信语气，学习者把"某版本的行为"当通用规律记下来，迁移到新场景就撞墙——而且**他记住的是错误知识，比没学更难修**（要先纠再教）。所以"避免学习者记错"是机制性目的，不是文风要求。

### 9.7 语言与交互规则（6 条）＋ 特殊场景（3 个）

正文「语言与交互规则」`[实测]`：默认中文、必要英文术语保留；语气＝温暖、专业、具体，"**耐心的朋友，不是说教的老师**"；一次一个概念，确认后再继续；鼓励绑定具体进展，不空洞夸奖；**错误时说"这个思路有意思，我们换个角度看"，绝不说"你错了"**；卡住先归类为概念／练习／过载／任务错配再回应；段落不超过 6 行，复杂处用图。

「特殊场景」`[实测]`：
- **挫败／泄气**：降低难度、回到已掌握内容重建信心；话术示例"这确实绕，我第一次也卡过。我们退一步。"
- **考试备战**：分阶段里程碑 ＋ 每主题掌握度检查 ＋ 薄弱追踪。
- **辩论／答辩备战**：每概念练"老师若问 X，答：…"；教"我选 X 是因为…"的**设计决策语言**；**核心逻辑 > 逐行背记**；模拟 Q&A。

`[推演]` "绝不说你错了"不是礼貌问题，是信息保全问题：一句"你错了"之后，学习者下一轮倾向于给"他认为老师想听的答案"而不是自己真实的思路——而阶段 3 第 2 步和第 8 步要的全部是**真实思路**。假思路写进 journal 和画像，画像就变成 AI 自己的投射（**投射**＝把希望看到的当成观察到的）。

## 第 10 章 失效与恢复：它怎么坏、怎么发现、发现后怎么退

### 10.1 失效模式总表（按"坏在哪里"分五组）

**A 组：节奏崩坏（最常见）**

| 失效 | 怎么发现（可执行判据） | 怎么退 |
|---|---|---|
| **把十步循环压成一次长回答**：讲完 3 个概念才问第一题 | 「语言与交互规则」的"一次一个概念，确认后再继续"被跳过；回复里能数出 ≥2 个新术语块且末尾只有一句"有问题吗？" | 本轮作废重做：只保留第一个能力点，从第 4 步重新讲；第 3 步的能力点数量按 2–5 重划 |
| **讲解块超粒度** | 数一下段落：任一段 >6 行，或任一讲解块 >5 句 | 拆成"目的句 ＋ 类比句 ＋ 定义句"三块，每块后插一次确认 |
| **一节课推两个重主题** | journal 里同一日期出现两条互不相关知识点的新增 | 违反 `mastery-rubric.md` 规则"一次只推一项能力，不把重 topic 捆绑推进"——拆到下一节 |

**B 组：判级崩坏（最隐蔽）**

| 失效 | 怎么发现 | 怎么退 |
|---|---|---|
| **L2 标成掌握** | 画像总览某条写 L3，但 journal 该节只有"复述"一类证据，无产出／无变式 | 按量表把等级降回 L2（L1–L2 **绝不**标记掌握），并在路线里取消"可跳过"标记 |
| **靠感觉定级** | 判定语句里没有引用任何证据行（作答、表述、作业），只有"看起来懂了" | 回到第 8 步补两类证据；违反「角色与使命」"所有评价基于证据并在画像文档中标注依据" |
| **检查放在立刻而非间隔后** | 每次判级都发生在讲完同一段内，开场检索复盘长期缺失 | 把该知识点的正式判级挪到下次会话开场复盘后（`learning-principles.md` 间隔效应那条应用） |

**C 组：记录崩坏**

| 失效 | 怎么发现 | 怎么退 |
|---|---|---|
| **流水账画像** | `user_profile.md`「学习本质」小节空着，而 journal 已 ≥3 条互不相关的"错误清单" | 触发蒸馏：先归因（第 9.2 节四归一的做法），把现象归并进不变式 |
| **单次证据直接上升为特征** | 某个不变量底下只挂 1 条证据 | 按第 3 条证据链规则打回"待二次确认" |
| **两处结论打架** | 画像说某条已掌握，日志里该条最新一次判定是"未过" | 以**日期最新的证据**为准回改画像；这是 `learning_journal.md` 只记证据不重复结论的原因 |
| **默认位置覆盖用户文件**（真实事故） | 用户已有同名文件被替换 | 见第 4.5 节：生成前必须问位置、必须建专用子文件夹、跨学科重新问 |

**D 组：互动崩坏**

| 失效 | 怎么发现 | 怎么退 |
|---|---|---|
| **苏格拉底不降级** | 学习者已说"直接告诉我"，回复里仍以问句收尾 | 立即停止提问直接讲；随后温和提供一次"讲回来"（第 7.7 节边界 1） |
| **给答案不复盘** | deadline 场景交付了完整代码，journal 没有"复盘讲清每一步"的记录 | 补复盘（边界 3 的"必须"）；否则该节不能判 L2 以上 |
| **提示泄底** | 出题后同一段里出现了"想想看"／斜体线索／参考答案 | 撤回题目重发；把答案挪到学习者回应之后（沉默暂停只准补固定两句） |
| **Never 项被违反** | 画像 Never 栏写了某禁止项，journal 里出现了该行为 | 最高优先级问题：先道歉、改回、把触发条件写进下次开场检查 |
| **空洞夸奖** | 鼓励语句里没有具体进展对象（"真棒！"） | 改写成绑定进展的句式（`teaching-playbook.md` 第四节范例："你现在能区分 A 和 B 了——前置在稳住。"） |

**E 组：调度崩坏**

| 失效 | 怎么发现 | 怎么退 |
|---|---|---|
| **静默加载别的 skill** | 出现了用户没批准的产出或文件写入 | 违反「申请调用其他 skill 的协议」第 4 步"不得跳过此步自行调用"；补做申请，被拒就改用自己的方法 |
| **强推专项 skill** | 用户已表示谨慎，下一轮又提同一个申请 | 协议第 4 步"用户拒绝或表示谨慎→改用自己的方法，不纠缠"；本轮改为纯讲解 |
| **单次问答式辅导没转走** | 用户只是来问一道题的解，却被套进阶段 0 五轮提问 | 正文 frontmatter 已声明"单次问答式解题辅导转 academic-tutor，不在本 skill 范围"——直接给这一题并说明本 skill 不接单题 |

### 10.2 冷启动（什么都不存在时的第一节课）

不存在画像、不存在框架路线时，正文「工作流程」写"严格按阶段顺序推进"，所以冷启动必须从阶段 0 起 `[实测]`；最小可执行顺序：

```
① 确认存放位置（三选一必问）
② 建专用子文件夹（若该学科已有则沿用）
③ 告知"文档将保存在 <最终位置>"（会话开头）
④ 向学习者说明这 4 份文档的存在与用途
⑤ 阶段 0 第一轮 3–5 问（覆盖四轴，缺哪轴补哪轴）
⑥ 每轮拿到信息立刻回写 user_profile.md（按 profile-template.md 的 12 个小节填）
⑦ 达到"停止提问硬标准"后 → 阶段 1 对齐 → 阶段 2 出两份文档 → 给学习者确认
```

`[推演]` 冷启动最容易跳过的是 ④"说明文档的存在与用途"。跳过的后果：学习者不知道自己会被记录什么，日后看到 4 份文件会警觉（"它记了我性格？"），信任一崩，后面的性格轴与 Never 项就再也问不到真话——这两项恰好是第 1 章故障 ② 和 ⑨ 的唯一解药。

### 10.3 三种"文件级"损坏与修法

| 损坏 | 症状 | 修法 |
|---|---|---|
| **文档丢失／路径变了** | 开场读不到画像 | 跨学科重新询问位置（第 4.5 节），不许拿上一个学科的位置猜；重问后如找不到就明说，从 journal 最近日期重建 |
| **画像与日志互相矛盾** | 画像的结论找不到日志里的支持证据 | 以日志证据为准重蒸一次画像（第 9.1 条 4）；不能预测的结论直接删 |
| **路线大面积超前** | 每节都标了"已掌握"，但开场检索复盘连续答不上 | 判据被高估（多半是立刻检查／单类证据）——把 L3 标记批量回退到 L2，加练一轮变式再重判 |

### 12.4 阶段 3：完整一节课的 10 步（可照抄）

**步 1 锚定与目标**

```
检索复盘（上一节）：快速回忆一下——上次那个按钮点了没反应，
你最后是靠哪一行定位到问题的？（填一句就行，想不起来说"想不起"）
```

学习者答"console.log 那行"。→ 记入 journal。本次产出：**一个能双击打开、输入→显示跑通的 15 行文件**。

**步 2 诊断起点**：基线提问"用自己的话说说 `document.getElementById('x')` 在干嘛"。答"从页面里把那个东西抓出来"→ 前置在，不补，直接进主线。

**步 3 分解能力点**（3 个，落在 2–5 区间）：
```
A【核心】拿到输入框里的文字
B【核心】把文字塞进页面的某个位置
C【了解即可/可延后】addEventListener 的第三参数（事件捕获那套）
```

**步 4 讲解**（A 点，4 句，先类比后术语）：

```
把网页想成一间办公室，每个元素门上挂了名牌（就是 id）。
document.getElementById('name') 就是"拿着名牌去叫人"——一次只叫得到这一个。
要它手里的内容，就再加一句 .value，相当于问这个人"你手上拿的纸条写的啥"。
所以「取输入」这件事永远是两步：先按名牌找到人，再问他手上的纸条。
```

标注：**【需理解】**——因为你后面每次出错都要靠这两步去定位。

**步 5 最小示例**（先整体，再拆）：给 6 行可运行 JS，然后逐行问"这行对应刚才类比里的哪一步"。

**步 6 即时检验**（1 题，然后**沉默暂停**）：

```
如果页面同时有两个输入框，都给 id="name"，你猜 .value 会拿到哪一个？
(猜错也没关系，错误预测也是有用数据。)
```

——此处 agent **停止生成**。不给"想想看 id 要唯一"这种提示（第 8.1 节）。学习者答"第一个"后，才继续：答对方向，但要点是"取到第一个，第二个彻底取不到"，并顺手把这个坑挂进 C 之后的加练。

**步 7 布置产出**（微产出，约 12 分钟，在 5–20 分钟区间内）：

```
任务简报
- 目标：一个能双击打开的 html，输入框 + 按钮 + 显示区，跑通"输入→点→显示"
- 输入/输出：输入任意一句话；输出同一句话显示在页面下方
- 约束：JS 不超过 15 行，不引入任何库；两个输入框也要能各自取到值（选做）
- 验收标准：自己双击打开，输入 A 点一下显示 A，输入 B 点一下显示 B，刷新后重来
- 一个变式挑战：把"点按钮才显示"改成"打字的同时就显示"，说说你改了什么
```

（5 字段逐条对应 `project-patterns.md` 的"编程类任务简报最小字段"）

**步 8 掌握度检查**（讲回来 ＋ 变式，共 2 类证据）：
```
讲回来：把"取输入为什么是两步"讲给一个明天要接手你这个文件的同事听，两三句就够。
```
学习者讲清了"按名牌找人 → 问他手上纸条"，并在变式里把按钮事件换成 `input` 事件成功。→ 判定：**A、B 两点 L3（能改）**，因为有"修改已有解法＋能重组表述"两类证据；C 点未测，保持未判。
`[实测]` 依据：`mastery-rubric.md` L3"能修改已有的解法…能用自己的话重组"；"L1–L2 绝不标记掌握"。

**步 9 回写文档**（先归因，再记录）：journal 追加：

```markdown
### [日期] 第 3 节 · 取输入与上页面
- 讲解要点：id 是唯一名牌；取内容要两步（找到元素 → .value）
- 暴露的水平与盲点：两步链路能说清；重复 id 的失败原因靠猜（第 6 步预测错了方向）

- 导师评价与调整：A/B 判 L3（证据＝讲回来 ＋ 变式）；
  新增观察「结论靠猜、不做验证」→ **待二次确认**，暂不入特征
- 下一步：S1 第 2 站，把值存进数组并渲染 3 行的表格
```

画像「掌握度总览」更新 `- id 取值 → L3（日期）`；roadmap 把 S1 第 1 站标"已过"。
**注意"待二次确认"那一行** `[实测]`：它和第 9.2 节的四现象归一同一方向，但本节只出现 1 次，按第 3 条证据链规则**不许直接写成特征**——这条纪律是防止画像变成 AI 的主观投射。

**步 10 给出下一步**：

盲点：重复 id、以及"我以为它行"和"我验过它行"是两件事。

## 第 15 章 工程规范与安全规范

### 15.1 命名与字段规范

| 对象 | 规范 | 理由 |
|---|---|---|
| skill 目录名 | 与库内目录逐字一致（含中文与前缀），docs 页文件名同目录名 | 仓库收录检查按 `docs/<目录名>.md` 找页，改名等于删页 |
| `name` 字段 | `personal-mentor`（英文小写连字符） | 机器可读的标识，与中文目录名分离 |
| 4 份生成文档 | 固定英文名 `user_profile.md` / `learning_framework.md` / `learning_roadmap.md` / `learning_journal.md`，**内容中文** | 英文名便于程序与跨工具引用，内容中文保证学习者读得懂（见第 4.6 节） |
| 子文件夹建议名 | `贴身导师定制化文件/`，或按学科 `贴身导师-唱歌/`、`贴身导师-学代码/` | 独占命名空间防同名冲突；带学科则天然支持"跨学科重问" |
| 掌握度字段格式 | `[知识点] → L_（日期）`，薄弱标红 | 带日期才能做"间隔后重判"的比较，不带日期的等级是死的数字 |
| 证据标签 | 单次证据写「待二次确认」，不写成特征 | 见第 9.1 条 3 |
| 版本记录格式 | CHANGELOG 三字段：做了什么／解决了什么／怎么解决的 | 强制每条改动挂一个故障与一条对策，防止写成流水账 |

### 15.2 frontmatter 与官方规范：三个上限并存，不许合一

- 本支 `description` 折叠成一行后实测 **383 个字符**（数法见第 2.3 节）。
- 关于 description 的长度上限，业内**同时存在三个数字**，本页不合并成一条：
  - **1,024** —— 开放标准与上传校验口径；
  - **1,536** —— 某宿主常驻清单的截断口径；
  - **200** —— 某帮助中心上传口径。
  → 383 字符**超过 200、低于另两个**。哪一条对哪个宿主真正生效，本页**未检索到权威裁定**，因此不下结论；实际影响是：常驻清单可能被截断→触发词落在后文→该 skill 更难被自动选中。`[推演]` 具体可复现的坏输入：用户说"检查一下我学得怎么样"（清单后半段的触发词），若宿主按 200 截断，这句话就命不中，agent 会退化成普通回答而不加载本支。
- **渐进披露三层**（常驻清单 → 正文 → references）是本支已经在用的结构，见第 3.3 节。
- 正文行数 207 行，**远低于常被引用的 500 行建议线**，所以"内容多到要拆分"这件事对本支不是压力；真正把 6 份细节放出去的理由是"按需加载不占预算"，不是超限。

| 段落 ≤6 行、一次一概念 | 语言与交互规则 | 信息过载导致学习失败被误判为能力问题 |
| 事实／建议分离 | source-strategy | 把版本行为当通用规律传授 |
| 评价必须挂证据 | 角色与使命 | 主观臆断写进画像 |
| deadline 给答案后必须复盘 | 降级边界 3 | "AI 写完了"被记成"我学会了" |

### 15.4 隐私规范（🔴 这是公开仓库）

本支的 4 份产出文档天然会写下**学习者的姓名／称呼、性格评估、deadline、卡在哪**——这是全套规则里最敏感的部分，必须守下面几条：

1. **画像文档绝不进公开仓库**。它们是个人数据，应留在本机；若要纳入版本管理，仓库需把 `user_profile.md`、`learning_journal.md` 加进忽略清单（"忽略清单"＝告诉 Git 永远不要提交这些文件）。
2. **示例、文档、提交记录里的路径一律用占位符**（`<你的目录>/贴身导师-学点东西/`），不写真机路径、不写用户名、不写盘符。本页全文遵守此条。
3. **文档里的真人称呼**（画像模板第一项就是"姓名／称呼"）在对外展示时先替换成「学习者」。本支历史上确实出现过这个毛病：`CHANGELOG.md` 记录了某次全库体检点出"正文含真实姓名与私人路径"，随后做了一次 P0 脱敏修复 `[实测]`——这条记录本身就是"这个风险真实发生过"的证据，所以第 1 章 ⑫ 之外还要单列这一条。
4. **凭据与密钥不出现在教学文档里。** 若课程涉及需要密钥的示例（例如调某个 API），一律写 `<你的密钥>` 这种占位形状，绝不允许把真实密钥写进 `learning_journal.md` 或作业文件——**作业文件是会被截图拿去问别人的**。
5. **真实学习项目的本机位置与项目名**属于用户隐私，本页与仓库内任何 docs 页都不得出现；讲机制时用"某个学习项目"代替。

### 15.5 冷启动与未采纳项（诚实留档）

**冷启动**见第 10.2 节（7 步最小顺序）。补充两个已知边界：

- **没有画像也没有别的工具时**：本支完全自足——只靠 Markdown 文件即可运行，零依赖、无外部服务、无脚本。这也是它没有"体检脚本"的原因（第 11 章开头）。
- **多个 agent 并行时**：本支没有做文件锁（"文件锁"＝防止两个进程同时改一份文件的机制）。如果同一个学习目录被两个会话同时写，会互相覆盖。目前的设计假设**一个学习者对一个导师会话**，跨会话靠"每次开场先读"来接力，不靠并发控制。`[推演]` 会出问题的具体输入：两个会话在同一节里都执行第 9 步回写 `learning_journal.md` → 后写的把先写的整节盖掉，且 journal 是追加式文档、丢失的段落不会被任何判据发现。
