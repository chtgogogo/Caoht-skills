# Cao-贴身导师（personal-mentor v1.2.0）

> [← 返回总目录](../README.md#skills-index)

## 一句话

长期陪跑的学习引擎。它不是来回答问题的，是来让人真的变强的。

## 它解决什么问题

- **讲完就当你懂了。** 讲一遍，直接进下一节，没人检验你到底听懂没有。
- **"我学会了"是错觉。** 看懂和会做之间有条沟，但没有机制告诉你站在沟的哪一边。
- **学了三周，AI 对你的了解还是零。** 每次开新会话都要从头自我介绍，然后拿到一份对谁都适用的通用建议。
- **换个 AI 老师，画像和进度全废。**
- **内容堆砌不管消化。** 一口气讲十个知识点，一个都没吃透。

## 核心机制

**阶段 0 · 四轴诊断。** 动手教学之前先摸底：实际水平、性格、学习偏好、目标动机。结构化提问，问到你答不出新东西为止，结果写进画像文档。

**画像蒸馏，本质优先。** 这是 v1.2 新增的、也是最关键的一条。画像禁止记流水账。要把零散现象归因到一到两个"不变式"上——与其记录"这个人第 3 题错了、第 7 题错了、第 12 题错了"，不如归因成"他处理边界情况时会漏"。

每个不变式至少要两个独立证据支撑，而且必须满足一个硬标准：**能预测他下一步会怎么错**。做不到预测的，就不算抓到了本质。

**5 级掌握度量表。** 默认包含"讲回来"这个检验——能用自己的话复述，才算过。另有纠错、变式、迁移、迷你实现等证据类型。L3 以下不标掌握，失败要回溯到前置缺口，而不是硬推下一节。

**PEAR 循环。** 涉及 AI 能代劳的内容（典型是写代码）时走四步：Plan → Explore → Analyze → Rewrite。目的是让 AI 当杠杆，不当拐杖——你自己先规划、先探索，再对照、再重写。

**苏格拉底分档脚手架。** 卡壳时不直接给答案，按卡壳程度给不同量的提示：引导问题 → 伪代码 → 带空缺的代码 → 逐步引导。也划了降级边界——你说"直接告诉我"，它就直讲；你情绪受挫，就先诊断再给小步子。

**主动练习 + 沉默暂停。** 抛出问题之后彻底停住，不给暗示、不抢答。用停顿制造承诺感——你先想，再听。

**跨会话延续。** 画像和日志全部文档化，换一个 AI 老师，读文档接着教。

**调用其他 skill 先申请。** 需要外援时向你说明理由、征得同意，不擅自静默加载。

## 两个来自真实事故的设计

**"存储位置必问"条款。** 早期版本会用一个默认目录存画像和日志。有一次那个目录里正好有同名文件，直接覆盖掉了用户的东西。事故之后这条被写死：**绝不默认写目录，每次都问。**

**掌握度不许自评。** 一开始的判断标准是"学生说懂了就算懂"。实际跑下来发现这个标准完全失效——最有把握说"懂了"的时候，往往是最没懂的时候。于是改成必须提供可检验的证据：讲回来、做变式、纠错、迁移。

## 和同类方案比，差在哪

| 常见做法 | 本 skill |
|---|---|
| 讲完就过 | 5 级掌握度 + 多类型证据，L3 以下不算会 |
| 每次对话从零开始 | 四轴画像 + 动态更新，越教越懂你 |
| 画像记流水账 | 蒸馏成不变式，必须能预测下一步的错 |
| 直接给答案 | 按卡壳程度分档给提示，且划清降级边界 |
| AI 代劳全部 | PEAR 循环，自己先规划再对照 |
| 绑定单一 AI | 画像文档化，跨老师、跨模型延续 |
| 默认写死存储目录 | 存放位置每次必问，绝不覆盖你的文件 |

## 3 分钟上手

1. 把文件夹放进 skills 目录（见[总目录](../README.md#skills-index)）；
2. 说"教我 XX""帮我制定学习计划""陪我学"触发。它面向长期陪跑，一次性的资料查询不会触发；
3. 第一轮它会先诊断提问。耐心答完四轴，之后的教学质量完全不一样；
4. 它会问你文档存哪——这是设计上的硬性要求，不是多此一举。

## 实战绩

2026 年 7 月起在真实学习项目上长期陪跑（编程等学科），画像蒸馏、变式复习、掌握度追踪这些机制全部来自实战迭代，不是纸面设计。

"存放位置必问"直接来自一次覆盖用户文件的事故。技能来源上合并了两套已验证的教学引擎：`study-cao` 的掌握度与自适应能力，以及 Sensei 导师（MIT 许可）的苏格拉底降级与 PEAR 能力。

## 适用 / 不适用

- ✅ 任何学科的系统学习：编程、游戏开发、写作、备考……尤其是"AI 味学习"容易翻车的技术学科
- ❌ 一次性问答、单点资料查询（普通对话就够）
