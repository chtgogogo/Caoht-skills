# Cao-踩坑日志（pitfall-log v1.0.1）

> [← 返回总目录](../README.md#skills-index)

## 一句话

一个省 token 的"踩坑/经验教训"沉淀系统：**极轻索引 + 每条坑一个独立文件**，同一个坑绝不踩第二次，还能跨 Agent 共享。

## 它解决什么问题

- 排了两小时修好的 bug，三个月后同样的问题出现，完全不记得当时怎么解的；
- 教训写在聊天对话里，会话一关就蒸发；
- 把所有教训塞进同一个大文件，每次会话全量加载，越来越贵；
- 团队/多 Agent 场景下，A 踩过的坑 B 接着踩。

## 核心机制

- **渐进披露**：索引文件每行一条（日期/记录者/标签/一句话标题/文件指针），常驻上下文几乎零成本；完整细节（上下文/根因/解法）只在命中时才深读；
- **"能否借鉴"字段**（最有价值的设计）：强制回答"这个问题在别处会不会也遇到？通用规律是什么？"——把一次性的本地修复升级成可迁移经验；
- **索引有界**：条目超 ~50 条自动归档冷条目，索引永不膨胀；
- **跨 Agent 共享**：所有助手共用一个 log-root，谁踩谁记、大家都能查。

## 和同类方案比，差在哪

| 方案 | 问题 | 本 skill |
|---|---|---|
| 教训记在对话里 | 会话结束即丢失 | 文件化沉淀，永久可查 |
| 单文件流水账 | 每次全量加载，token 越滚越大 | 索引+分文件，成本恒定 |
| 只记"怎么修的" | 换个场景又不会了 | "能否借鉴"字段逼出可迁移规律 |

## 与记忆系统的分工（避免记两遍）

- **踩坑日志** = 跨 Agent 共享的原始教训沉淀（不评分、不衰减）；
- **记忆纪律的 PITFALL 层** = 各宿主自己的记忆管理（评分/衰减/升华成铁律）；
- 原始记录进日志；同一个坑反复出现才升华进记忆 CORE。边界清晰，绝不双写。

## 3 分钟上手

1. 复制文件夹到 skills 目录（见[总目录](../README.md#skills-index)）；
2. 首次使用与用户确认存储位置（默认 `D:\Deepseek-ALL\踩坑日志`），建 `pitfall-log.md` + `pitfalls/`；
3. 之后每解决一个棘手问题，说一句"记一条踩坑"即可；想查历史就说"看看踩坑记录里有没有类似的坑"。

## 实战绩

在本仓库宿主的记忆库实跑中产出了真实条目（如"Git Bash 中 python 命令是 WindowsApps 假桩，静默退出码 49，改用 py"），第二次会话直接命中复用，避免了重复排查。

## 适用 / 不适用

- ✅ 任何反复折腾 bug、想积累经验的个人/团队；多 Agent 环境收益最大；
- ❌ 一次性问题且无迁移价值的（比如纯环境偶发故障），记了也是噪音。
