# Cao-GitHub仓库检索提取（github-repo-extract v1.1）

> [← 返回总目录](../README.md#skills-index)

## 先诚实回答一个问题

你"参考"过多少个开源项目？——收藏了几十个，star 了一堆。

再回答：有几个真的变成了**你的东西**？设计学进去了没有？代码合法地用上了没有？上次分析到哪一步还记得吗？

绝大多数人的"参考开源项目"是这样失败的：手动翻 README（信息全是宣传话术）、凭感觉 clone 下来（没看 License，埋雷）、看懂多少算多少（结论散在对话里，下次归零）、想认真分析——GitHub 匿名 API 每小时 60 次请求，翻两个仓库就被掐断。

这个 skill 把"看开源项目"变成一条**标准流水线**：怎么拉（不限流）、值不值得看（5 维打分）、允不允许用（License 红线）、看完沉到哪（落盘成文档）。

## 五个真实的坑，规则里全是它们的尸体

这套流程里的每条规矩，都对应一个真踩过的坑：

1. **匿名限流。** 翻两三个仓库就 403。→ 首选 `gh` CLI 鉴权拉取；域名被 hosts 拦时用 Python `urllib` 绕 DNS 直连兜底。
2. **base64 当源码落盘。** GitHub contents 接口返回的 `content` 是 base64——文件名正常、大小看着也对，打开全是乱码，而且隐蔽到你可能几周后才发现。→ 规则写死：先解码再落盘。
3. **licenseInfo 返回 null ≠ 无 License。** API 的 License 字段经常返回 null，不是因为真没有，而是因为仓库只在根目录放了 `LICENSE` 文件而没在元数据里标。直接判"无 License"会冤枉仓库，判反了会惹麻烦。→ null 时必须额外查根目录的 `LICENSE`/`COPYING` 文件再判定。
4. **中文进管道变问号。** Windows PowerShell 管道传中文，编码一坏文档全废。
5. **分析完没地方放。** 下一轮想接着看，从头再翻。→ 强制沉淀：先确认文档体系（没有就建议建 DOCS_INDEX），结论落盘。

## 两张表，替你做两个容易出事的判断

**5 维价值矩阵**——一个仓库对"当前工程"到底有什么用，五个维度分开打分，不掺习惯觉：

| 维度 | 问的是 |
|---|---|
| 可直接使用 | 资产/组件/模型能拿来就用吗 |
| 可提取转译 | 设计模式能跨语言移植吗（C#→GDScript 这类） |
| 设计提炼 | 核心算法/机制值得学吗 |
| 架构分层 | 目录结构/模块划分可参考吗 |
| 视觉规范 | UI 模式/设计语言可借鉴吗 |

**下载决策矩阵**——License 红线一次判清：

| 条件 | 决策 |
|---|---|
| MIT / Apache / CC0 | 可全量下载自由参考 |
| GPL / AGPL | **只读 README 学方法论，不下载源码不抄码转译** |
| 无 License | 只学方法论，文件标 `_NO_LICENSE`，不可抄码 |
| 作者标 Private/保密 | 只参考公开理念，一个文件都不下载 |
| 仓库 >100MB | 选择性下载，不 clone 全库 |

外加一条硬红线：**禁止商用（CC-BY-NC 等）素材绝不纳入工程**。抄代码一时爽，License 爆雷火葬场——这条矩阵的价值在于把"感觉应该没事"变成查表说话。

## 和"手动翻 + 凭感觉"比，差在哪

| 手动参考 | 这套流水线 |
|---|---|
| 匿名 API 60 次/小时，翻两个仓库被掐 | gh CLI 鉴权，配额不是问题 |
| License 凭印象，雷埋进项目 | 决策矩阵查表说话，null 陷阱已排 |
| base64 落盘、中文变问号，垃圾文件几周后才发现 | 解码/编码的坑规则写死 |
| 看完结论在对话里蒸发 | 强制沉淀进文档体系，下次接着看 |
| 好不好用全凭"感觉很牛" | 5 维分开打分，价值等级从 ★ 到 ☆ 六档 |

## 什么情况别用

- 不是 GitHub 仓库的普通网页抓取——那是另一类活；
- 只是想看个 README 了解概念——在线浏览就行，不用起流水线。
