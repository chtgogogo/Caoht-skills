# Cao-GitHub仓库检索提取（github-repo-extract v1.1）

> [← 返回总目录](../README.md#skills-index)

## 一句话

把"研究一个开源项目"从随手翻翻变成**标准流水线**：查元数据→五维价值判断→按 License 安全下载→沉淀成文档，全程内建版权红线与避坑指令。

## 它解决什么问题

- 匿名调 GitHub API 一小时 60 次就限流，研究到一半被掐断；
- 从 `contents` 接口拿到的 `content` 是 **base64 字符串**，直接落盘得到了一堆乱码还以为下载成功了；
- License 只顾着看 stars，结果把 **CC-BY-NC（禁商用）素材**混进了自己的工程，或把无 License 的代码直接抄了；
- 看完就忘：项目好在哪、能借鉴什么，没有任何沉淀。

## 核心机制

- **gh CLI 优先**：已登录鉴权拉取，绕开匿名限流；hosts 拦截时用 Python 直连兜底；
- **5 维价值矩阵**：可直接使用 / 可提取转译 / 设计提炼 / 架构分层 / 视觉规范——判断"这个仓库对我到底值几星"；
- **License 决策矩阵**：MIT/Apache/CC0 可下；GPL 只读 README 学方法；无 License 只看骨架；**连 API `licenseInfo` 返回 null 但根目录其实有 LICENSE 文件**这个经典陷阱都有专门处理；
- **版权硬红线**：禁商用素材绝不纳入工程（用户铁律内建）；
- **文档沉淀模板**：Stars/License/价值等级/对本工程价值/本地路径，同类仓库自动追加方法对比表；
- **中文编码护栏**：UTF-8 写入 + 写后验证（字符数>0 且问号=0），避免 Windows 管道毁中文。

## 和同类方案比，差在哪

| 方案 | 问题 | 本 skill |
|---|---|---|
| 让 AI 自由发挥去看仓库 | 三坑全踩：限流/base64/License | 每个坑都有明确指令与兜底 |
| 只做"代码解释" | 说不清对**我的**项目有什么用 | 5 维价值矩阵 + 对比表，落到"能用/可学/该抄思路" |
| 版权靠自觉 | 商用素材混入是定时炸弹 | 红线写死在流程里，检查清单强制核对 |

## 3 分钟上手

1. 复制文件夹到 skills 目录（见[总目录](../README.md#skills-index)）；
2. 丢给 Agent 一个 GitHub 链接，说"分析/借鉴/评估这个仓库"即触发；
3. 产出自动沉淀到工程文档（无文档体系时它会先建议建 DOCS_INDEX）。

## 实战绩

长期服务游戏开发（天倾项目）与 AI 应用工程的选型调研：从 shader 素材库到 Agent 框架（mem0/Graphiti/Letta 等）的评估均走此流程，License 决策矩阵在"无 License 仓库能不能抄"这类高危判断上多次兜底。

## 适用 / 不适用

- ✅ 选型调研、找轮子、学习优秀项目结构、评估"能不能抄"；
- ❌ 只是 clone 一个仓库自己慢慢看（杀鸡用牛刀，但也不拦你）。
