# Cao-GitHub仓库检索提取（github-repo-extract v1.1）

> [← 返回总目录](../README.md#skills-index)

先诚实回答两个问题。

你"参考"过多少个开源项目？收藏了几十个，star 了一堆，对吧。

再答，有几个真的变成了你自己的东西？设计学进去了没有，代码合法地用上了没有，上次分析到哪一步还记得吗。

大多数人的参考开源项目是这样失败的。手动翻 README，里面全是宣传话术。凭感觉 clone 下来，没看 License，雷就埋下了。看懂多少算多少，结论散在对话里，下一轮归零。想认真分析，GitHub 匿名 API 每小时 60 次请求，翻两个仓库就被掐断。

这个 skill 把看开源项目变成一条标准流水线。怎么拉，不限流。值不值得看，五个维度打分。允不允许用，License 红线查表。看完沉到哪，落盘成文档。

## 五个真实的坑

流程里的每条规矩，背后都是一个真踩过的坑。

匿名限流。翻两三个仓库就 403。所以首选 gh CLI 鉴权拉取，域名被 hosts 拦的时候用 Python urllib 绕 DNS 直连兜底。

base64 当源码落盘。GitHub contents 接口返回的 content 是 base64 编码，直接写文件的话，文件名正常，大小看着也对，打开全是乱码。而且这事隐蔽，你可能几周后要用那段代码才发现。规则写死了先解码再落盘。

licenseInfo 返回 null 不等于无 License。API 的 License 字段经常返回 null。多数时候仓库其实有 License，只是作者把 LICENSE 文件放在根目录，元数据里没标。直接判无 License 会冤枉仓库，判反了会惹麻烦。规则要求 null 时必须额外查根目录的 LICENSE 或 COPYING 文件再判定。

中文进管道变问号。Windows 上用 PowerShell 管道传中文，编码一坏文档全废。

分析完没地方放。下一轮想接着看，从头再翻。所以强制沉淀，先确认文档体系，没有就建议建一个 DOCS_INDEX，结论落盘。

## 两张表

一张管价值，一张管合法性。

5 维价值矩阵，把"这个仓库对当前工程有没有用"拆成五个独立问题打分。能不能直接用，资产、组件、模型。能不能跨语言转译，比如 C 的思路搬到 GDScript。有没有设计可提炼，核心算法和架构决策。架构分层可不可参考。视觉规范可不可借鉴。打完分从核心参考到无用分六档。

下载决策矩阵，License 红线一次判清。

| 条件 | 决策 |
|---|---|
| MIT、Apache、CC0 | 可全量下载自由参考 |
| GPL、AGPL | 只读 README 学方法论，不下载源码，不抄码转译 |
| 无 License | 只学方法论，文件标 NO_LICENSE，不可抄码 |
| 作者标 Private 或保密 | 只参考公开理念，一个文件都不下载 |
| 仓库超 100MB | 选择性下载，不 clone 全库 |

外加一条硬红线，禁止商用（CC-BY-NC 之类）的素材绝不纳入工程。抄代码一时爽，License 出事是真麻烦。这张表的价值在于把"感觉应该没事"变成查表说话。

## 跟手动翻的区别

| 手动参考 | 这套流水线 |
|---|---|
| 匿名 API 每小时 60 次，翻两个仓库被掐 | gh CLI 鉴权，配额不是问题 |
| License 凭印象，雷埋进项目 | 决策矩阵查表，null 陷阱已排 |
| base64 落盘、中文变问号，几周后才发现垃圾文件 | 解码和编码的坑规则写死 |
| 看完结论在对话里蒸发 | 强制沉淀进文档体系，下次接着看 |
| 好不好用全凭感觉很牛 | 五个维度分开打分，六档价值等级 |

## 什么时候不用

不是 GitHub 仓库的普通网页抓取，那是另一类活。只是想看看 README 了解概念，在线浏览就行，不用起流水线。
