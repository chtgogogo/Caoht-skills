# A-Cao-编码行为准则（coding-behavior v1.1）

> [← 返回总目录](../README.md#skills-index)

## 一句话

给 AI 写代码时套上的一份行为约束。五条，专治那些"省事"的坏习惯。

## 它解决什么问题

- **不问就猜。** 需求模糊，模型自己补一个理解就开始写，写完才发现方向错了。
- **顺手大扫除。** 让它改个 bug，回来发现整个文件被重排了，无关代码也动了。
- **预埋未来功能。** 要一个加法函数，它给你一个支持泛型、可配置、带日志的运算框架。
- **没跑过就说好了。** "应该可以了""这样就没问题了"——一问，其实没运行。
- **同一个错硬磕。** 报错改一行，还报错再改一行，连着试十几次，不回头看看方向对不对。

## 核心机制

五条纪律。v1.1 起全部内联在正文里，换台机器也能直接用，不依赖任何本机路径。

**思考优先。** 不确定先问，禁止猜了继续干。动手前把方案想清楚再落键。

**极简。** 只做明确要求的事。禁止预埋未来功能，禁止顺手大扫除。

**外科修改。** 只改与任务直接相关的代码，不碰无关行，改动面最小化。

**目标驱动。** 动手前先定一个可验证的成功标准——什么现象出现算做成了。

**验证纪律。** 声称完成前必须实际运行、读完整输出和退出码。没验证不许说"应该可以"。同一个问题连着失败 3 次，立刻停下来重新分析，不许硬磕。

触发面故意放得很宽：只要沾代码就触发，拿不准时一律触发。日常闲聊、写作、翻译这类零代码任务才跳过。

## 两个典型场景

**改一个错别字。**

没有约束时：改完那个字，顺手把整段重排了，变量名"优化"两个，还删掉一段它认为没用的注释。你得自己回来 diff，把不想动的地方一个个改回去。

有约束时：只改那一个字，其余原样。因为"外科修改"要求改动面最小化，"极简"禁止顺手大扫除。

**报错 `ModuleNotFoundError`。**

没有约束时：直接 `pip install` 一个包，还报错，再装一个，连着装三个，最后发现根本不是缺包的问题。

有约束时：先读完整报错和 traceback，确认是 import 路径写错还是真的缺包，再动手。因为"验证纪律"要求读完整输出，"思考优先"要求先定位再下手。

## 和同类方案比，差在哪

| 常见做法 | 本 skill |
|---|---|
| 需求模糊就开工 | 不确定先问，不猜 |
| 顺手优化周边代码 | 只改任务直接相关的行 |
| 预埋"以后可能用到"的功能 | 只做明确要求的 |
| "应该可以了" | 实际运行、读退出码，没验证不许说完成 |
| 同一个错反复试 | 连败 3 次停下来重新分析 |
| 规则引用外部文件 | 五条纪律内联正文，换机自足 |

## 3 分钟上手

1. 把文件夹放进 skills 目录（见[总目录](../README.md#skills-index)）；
2. 不用特意触发——任务只要沾代码它就会加载；
3. 觉得约束太紧（比如你就是要做大范围格式整理），在对话里说明即可，它会按你说的放宽；
4. 想更严格，直接说"严格执行编码行为准则"。

## 实战绩

五条纪律都是从真实踩坑里长出来的，不是抄的模板。

"验证纪律"里的"连败 3 次立即停下"，来自一次连续试探十几次都没定位到问题的经历。"极简"里的"禁止顺手大扫除"，来自一次改 bug 顺手改了无关代码、导致返工的事故。

v1.1 的改动是把五条纪律从外部文件搬进正文——之前那份文件挂在某个本机绝对路径下，别人 clone 下来根本读不到，skill 直接失效。

## 适用 / 不适用

- ✅ 所有涉及代码、脚本、配置、SQL、架构设计的任务
- ❌ 纯闲聊、纯写作、纯翻译等零代码任务

## 版本

v1.1：五条纪律内联到正文，消除对本机绝对路径的依赖；明确零代码任务不触发。
