# A-Cao-编码行为准则（coding-behavior v1.1）

> [← 返回总目录](../README.md#skills-index)

## 一句话

一份"只要沾代码就强制加载"的五条铁律，专治 AI 写码三大病：**不问就猜、过度设计、没跑过就说修好了**。

## 它解决什么问题

- AI 拿到模糊需求不提问，猜一个方向闷头写到底，写完才发现全错；
- 让它改一个错字，它顺手"优化"半个项目，改出一堆无关 diff；
- 最危险的：声称"已修复/应该没问题"，但根本没有实际运行验证过。

## 五条纪律

1. **思考优先**：动手前先陈述假设；不确定先问；存在多种理解全部列出让用户选；需求不合理敢反对。
2. **极简**：只做明确要求的，禁止预埋未来功能；单次使用不抽象封装；自检"资深工程师会觉得这是过度设计吗"。
3. **外科修改**：只改任务直接关联的代码；沿用项目现有风格；无关死代码只标注不删；自己产生的孤儿代码必须清掉。
4. **目标驱动**：开工前定可验证的成功标准；多步任务先报"步骤 → 验证项"计划；小步迭代。
5. **验证纪律**：声称完成前必须实际运行、读完整输出与退出码；未验证禁说"应该可以"；同一问题连败 3 次停下重新分析。

## 和同类方案比，差在哪

| 常见做法 | 问题 | 本 skill |
|---|---|---|
| 在提示词里求"请仔细写代码" | 软约束，长对话就漂 | **强制触发加载**的硬规则（宁多触发勿少触发） |
| 规则散落在各项目各对话里 | 换个宿主就变样 | 规则文件**共享一份**，多宿主行为一致 |
| 全有或全无 | 改个错字也要走全流程 | 内置"简单任务豁免"条款，不做形式主义 |

## 3 分钟上手

1. 复制整个文件夹到你所用 Agent 的 skills 目录（见[总目录](../README.md#skills-index)安装说明）；
2. 无需任何操作——只要任务沾代码就会触发；
3. 验证：让 AI 改一个小 bug，看它是否先说假设、改完主动跑验证。

## 实战绩

长期在多宿主常驻运行。本仓库所在的宿主环境中，历次代码任务（含记忆库脚本、体检脚本编写）均在它的约束下完成——"同一问题连败 3 次停下"的条款来自真实教训。

## 适用 / 不适用

- ✅ 任何让 AI 写码/改 bug/重构/做技术设计的场景，个人与团队通用；
- ❌ 纯闲聊、翻译、写作等无代码任务（本来也不会触发）。
