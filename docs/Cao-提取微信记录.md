# Cao-提取微信记录（wechat-chat-export v1.0）

> [← 返回总目录](../README.md#skills-index)

## 一句话

把微信 4.x 电脑版存在本地数据库里的聊天记录，解密、解析、转写成按天归档的 Markdown。全程在本机完成。

## 它解决什么问题

- **记录只活在客户端里。** 换设备、重装、清理缓存，几年的对话说没就没。
- **官方不支持批量导出。** 只能一条条截图或者手动复制。
- **语音消息搜不到。** 重要信息常常是语音说的，但语音没法检索。
- **第三方工具要上传数据。** 聊天记录传出去这件事，本身就不能接受。

## 核心机制

**本地解密。** 微信 4.x 的数据存在 SQLite 数据库里，是加密的。密钥需要在本机抓取，存进 `db_keys.txt`。密钥跟微信版本绑定——微信升级后可能要重新抓，并核对 `config.json` 里的 `codec_cfg_offset` 偏移量。

**合并 WAL。** 微信用了 WAL 日志模式，最新消息可能还在 WAL 里没落主库。脚本会自动合并，避免"导出完了发现最新几条不见了"。

**按天归档。** 输出成 `<输出目录>/微信聊天记录_与<会话名>/YYYY-MM-DD.md`，附带一份 `索引.md`。

**增量更新。** 靠 `_export_state.json` 记录状态，只有某天数据变了才重写当天。改过导出范围或显示名之后，删掉这个状态文件可以强制全量重建。

**本地语音转写。** 用本机跑的 Whisper 转写新语音，模型放 D 盘，增量缓存，不会每次重跑。不想要可以关掉。

**解析引用和转发。** 引用消息显示成 `引用【A/B：原话】 回复`，转发聊天记录会展开，不是简单丢掉。

**一键化。** 首次搭建跑一遍 `安装.bat`，之后日常就是双击 `导出.bat`——解密、更新、打开输出文件夹，一步到位。

## 关于本 skill 的本体

**这个 skill 的本体（脚本、配置）不随本仓库发布。**

原因很直接：它包含解密微信数据库的密钥抓取脚本，处理的是聊天记录这类高度隐私的数据。这种东西不适合放进公开仓库——哪怕脚本本身没问题，误用和误解的风险也足够高。

所以这页只作**能力说明与方法参考**。四个设计判断，如果你也在做类似的事，可以直接借鉴：

**密钥只存本地，不进 git。** `db_keys.txt` 从创建那一刻起就排除在版本控制之外。

**不做云、不做中转。** 所有处理在本机完成，数据不出机器。

**密钥与版本绑定要显式提示。** 微信升级后密钥可能失效，这个前提写在约束里，不让用户在"解密失败"时自己猜。

**只处理本人的数据。** 这条写死在描述里，不是可选项。

## 和同类方案比，差在哪

| 常见做法 | 本 skill |
|---|---|
| 手动截图或复制 | 直接解密数据库，批量导出 |
| 导出时丢最新消息 | 自动合并 WAL 日志 |
| 语音消息无法检索 | 本地 Whisper 转写，带时长标记 |
| 每次全量重导 | 增量更新，只重写变化的天 |
| 云端工具处理聊天记录 | 全本地运行，数据不出机器 |
| 密钥随手存 | 密钥不进 git、不写进记忆、不走中转 |
| 引用/转发丢内容 | 解析成可读格式，转发记录展开 |

## 3 分钟上手

1. 本体不公开，无法直接安装，此页仅作说明；
2. 若要自行实现，链路大致是：定位本机数据目录 → 抓取或填写密钥 → 解密并合并 WAL → 解析引用与转发 → 按天生成 Markdown；
3. 搭建步骤和底层原理文档（`references/使用教程.md`、`references/技术原理.md`）随本体一起，不公开。

## 实战绩

完整链路在实际使用中跑通过：解密、WAL 合并、引用与转发解析、语音转写、增量更新。

它的输出结构和清洗规则后来被抖音版本直接复用了——两套的说话人标记、引用格式、表情和图片标记全部保持一致，这样从不同来源导出的记录可以并排放在一起看。

## 适用 / 不适用

- ✅ 备份自己本机的微信聊天记录；需要把记录转成可检索、可长期保存的格式
- ❌ 他人账号的数据；聊天内容的情感分析或人格推断（那是另一个 skill 的事）

v1.0.0：解密、WAL 合并、引用与转发解析、本地语音转写、增量更新的完整实现。
