# Cao-交付流水线（delivery-pipeline v1.1.0）

> [← 返回总目录](../README.md#skills-index)

## 一句话

从模糊想法到可交付项目的总装调度器：盘问磨设计 → 技术选型分层深选 → PRD → 切任务卡 → 分身执行 → 验收闭环 → 台账断点续传 → 收尾归档，十二步串成一条自动流水线。

## 它解决什么问题

- **想法直接开写。** 聊两句就让 AI 动手，设计没磨清、验收标准没定，写出来的东西返工三轮。
- **计划是一个巨型文件。** 所有任务塞一个 plan.md，AI 读一半丢一半，执行到第 5 步忘了第 2 步。
- **中断即报废。** 会话一断，之前进行到哪、哪些做完了全靠回忆，续不上只能重来。
- **每步都不留产出物。** 这一步的输出没有落盘，下一步的输入就没了，流程变成嘴上说说。
- **一口气全读，上下文炸掉。** 把所有细则、所有依赖一股脑塞进对话，token 全花在噪音上。

## 核心机制

**四选项启动路由。** 轻量（小改动五步）/ 标准（新功能九步）/ 企业（全十二步+双评审+工具箱外挂）/ 跳步优化（已有项目先扫短板再补）；启动先查台账，能续传绝不重开。另外支持**单步直调**——点名某一步（如"帮我切卡"）直接进那一步。

**每步绑产出物。** 磨设计出设计纪要、选型出选型记录、PRD 出 PRD.md、切卡出一卡一文件，产出不落盘 = 这步没做完。

**验收先于实现。** 每张卡开工前"怎么验证"必须已写清（评测基线/测试脚本/肉眼清单形式不限），铁律而非建议。

**台账即断点存档。** 在做/待执行/做完+阻塞三区制，每卡完成立即勾，任何时刻中断任何时刻续传。

**按需加载省 token（铁律 9）。** 启动只读主 SKILL.md 的索引与路由；进哪一步才读哪一步细则，一次只读一个；外部 skill 原文副本（depends/ 20 份 + 附属模板 16 个）只在需要顶替或查原文时才碰。

**依赖自包含。** 方法论来源 obra/superpowers（main @ 5bf4e7801107 全部 12 个相关 skill 原文 + 附属提示词/脚本快照）、用户自有体系（头脑风暴 v1.1、多 Agent 治理 v1.3、评测驱动验收）全部落档 `references/depends/`，换机器不依赖本机其他 skill。

## 凭什么

- 十二步索引表是"指针"不是"正文"——每步细则独立成文件，主文件永远只有八十行；
- 消融自检三级处理（齐全/降级/报错），副本缺失不阻塞，细则缺失才停机；
- 双评审继承 superpowers 实战验证的派遣循环（规格评审 + 代码质量评审分离），提示词模板随附可整篇套用；
- 全库 46 个文件零本机绝对路径，GitHub 直接可用。

## 什么情况下不该用

- 改一两行的小修补——直接改，走流程是杀鸡用牛刀；
- 没有任何验证手段的项目（连肉眼清单都不愿写）——"验收先于实现"会卡死在第一步；
- 纯探索性 prototype（明天就可能全推翻）——台账和卡文件制是给要交付的东西准备的。

## 快速上手

对 Agent 说：「用 Cao-交付流水线，我有个想法：……」——它会先问四个问题推荐档位，你拍板后开跑。
