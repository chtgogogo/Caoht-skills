# Cao-交付流水线（delivery-pipeline v1.3.0）

> [← 返回总目录](../README.md#skills-index)

## 五分钟速览


1. 十四步总装流水线，磨设计→选型→PRD→切卡→派遣→验收→台账→回看→评审→安检→口径→收尾，每步绑产出物。
2. 台账即断点存档。三区制（在做/待执行/做完加阻塞），每卡完成立即勾。任何会话任何时刻断掉，新会话查台账接着干。
3. 验收先于实现。每张卡开工前，怎么验证必须已经写在卡里。顺序反过来是关键。
4. 一卡一文件，拒绝巨型计划文件。派子代理只喂该卡、PRD 相关段、精确文件路径，绝不喂全项目历史。
5. 已有项目友好，跳步优化档先扫十四步找短板，缺哪步跑哪步，不逼你跑全程。
6. 安全基线不可跳过，L1 档有可被直接利用的漏洞，不许收尾。
7. 对外口径不可带病投递，数字没来源、早于最后评测、引用不存在的 commit，任一命中阻断收尾。

一句话概括设计目标，**从模糊想法到可交付的总装流水线，进度不丢、验收不虚、说出去的话站得住**。

## 它在解决什么问题

让 AI 做个项目，常见死法有三种。

| 故障 | 表现 | 对应设计 |
|---|---|---|
| 会话一断进度全丢 | 新会话从头来，谁也说不清做到哪了 | 台账三区制 + 断点续传 |
| 做完没法验收 | 它说完成了，问怎么验证的，没有验证这回事 | 验收先于实现 |
| 过程不可见 | 它热火朝天干两小时，你不知道哪步做完、token 烧在哪 | 每步绑产出物 + 台账即时更新 |
| 安全是漏网之鱼 | 卡内验收全过，上线后被外部拷问出 11 项安全实锤 | 第⑬步安全基线检查 |
| 对外陈述失实 | 简历、README 里的数字经不起追问 | 第⑭步对外口径检查 |

方法论站在 obra/superpowers 的肩上（磨设计的对话方式、切卡的实习生粒度、双评审都来自它），做了完整的中文化和工程化改造。superpowers 全部 12 个相关 skill 的原文快照存在 depends/ 目录里，MIT 协议，版本锚定同一个 commit，复制即用，不存在原 skill 丢了这套就废的问题。

## 四个核心设计详解

**台账即断点存档。** 所有进度记在一个三区台账里，在做、待执行、做完加阻塞，每张卡完成立即勾。它是实时存档，不是事后补记。所以任何会话任何时刻断掉，新会话第一件事查台账，问你是继续上次从第 N 张卡接着来，还是开新的。断点续传的问题从机制上消失了，靠的不是记性，是台账。

**验收先于实现。** 每张卡开工之前，怎么验证必须已经写在卡里，评测基线、测试脚本、肉眼清单，形式不限但必须写。顺序反过来是关键，验证动作在开工前就绪，AI 说完成了的时候，验收标准早就摆在那了，没有争论空间。连测试框架都没有的毕业项目也能用，肉眼清单也是验收。

**一卡一文件 + 派遣上下文最小化。** 每张任务卡是独立文件，不许塞进单个巨型计划文件，巨型文件是 token 黑洞。派子代理执行时只喂三样，该卡、PRD 相关段、精确文件路径，绝不喂全项目历史。token 花在活上，不花在噪音上。

**按需加载。** 主 SKILL.md 永远只有一百来行，十四步索引是指针不是正文，进哪一步才读哪一步细则，一次只读一个。流水线自己得先守省 token 的纪律，才有资格管别人。

## v1.2 与 v1.3 补上的两个盲区

这两步不是凭空设计的，各来自一次真实翻车。

**第⑬步安全基线检查（v1.2）。** 2026-09-23 外部安全拷问在两个已收尾项目实锤 11 项（JWT 弱默认密钥、DEBUG 连坐限流、role 自报、审计裸奔、async 同步阻塞等），全部漏网于卡内验收。根因是每张卡只管自己的验收，安全是全局维度，不属于任何单卡。所以安全检查独立成步，三档分级（L1 必检、L2 上线前、L3 企业级按需），L1 有阻断项不许收尾。

**第⑭步对外陈述口径检查（v1.3）。** 同一天发现，同一批已过安全审查的项目，对外陈述仍全线失实。全量耗时自记 7 分半到 9 分 50 秒，对外写成了「13 秒」；用例数与自家 README 矛盾；评测集号称 49 题实测 52 条；安检报告引用了一个不存在的 commit。根因是⑬和编码准则都只管「东西对不对」，没人管「说出去的话站不站得住」。四条规则，数字四件套（来源命令/样本量/口径含置信区间/生成日期）、过期即禁写（数字日期早于最后一次评测就不许对外写）、引用必须可验证（引用不存在的对象即阻断）、AI 协作必须披露（Agent 署名带 AI 标识，禁用真人化假名）。

**两步的共同教训**，每个维度都要有明确的「检查归属」。不属于任何单卡、也不属于写码纪律的维度（安全、口径），必须独立成步，否则就是三不管地带。

## 对已有项目友好

大多数流水线工具默认你从零开始，可最常见的诉求是手里已经有个项目，只想补某个环节。启动路由有四档，轻量（小改动五步）、标准（新功能九步）、企业（全十四步）、跳步优化（先扫十四步找短板，列缺口清单让你勾，缺哪步跑哪步）。也支持单步直调，你说「帮我切卡」，它直接进步⑤，不逼你跑全程。仅两件事不可省，落盘目录确认加台账登记，保持断点可续。

选型阶段是分层深选，从目标约束到语言到框架到部署，每层五到九个候选，每个候选明说缺陷，选完调和冲突。它不替你拍板，它把拍板需要的信息摆齐。

## 什么时候不用

改一两行的小修补，直接改。纯探索的 demo，明天可能全推翻的那种，台账和卡文件制是给要交付的东西准备的。连肉眼清单都不愿意定的项目，验收先于实现会卡在第一步，这是故意的。
