# 头脑风暴（brainstorm v1.1.0）

> [← 返回总目录](../README.md#skills-index)

让 AI 做项目最大的成本，是它把你随口一句话当圣旨开写。你说了句帮我做个记账 App，它两小时后交付一个完整的记账 App。记什么账，它猜的。给谁用，它猜的。技术栈它挑了自己最熟的，而你其实想借这个项目学 Rust。猜错方向写两千行，比开工前问一句贵一百倍。

所以磨设计是必须的。但磨设计有两个常见的失败形态。一种是 AI 一个问题都不问，直接干。另一种反过来，一口气抛十个问题，目标用户、核心功能、平台、商业策略，你看着就想关窗口。

这个 skill 走的路子是，一次只问一个问题，并且每个问题都带推荐答案。

## 每问带推荐，是整个设计的灵魂

裸问是这样的，目标用户是谁。你答不上来，因为你自己也没想清楚，这正是需要磨的地方。AI 干等，你干瞪眼，一轮对话什么都没推进。

带推荐是这样问的。我推荐先做给自己用，理由是记账需求自己最懂，能最快闭环验证。如果做家庭共享账本，复杂度翻三倍，第一版不划算。同意吗。

你点头，或者说要后者，就锁定了。这个设计同时解决了两个人群的问题。不会表达需求的人，拿到了现成的判断，点头或摇头就能推进。会表达的人，省掉一轮来回。而且推荐必须带理由和备选的代价，AI 不能偷偷替你决定，你保有完整的知情权。

## 其余三个设计

**一次一问。** 问题之间有依赖，前面的答案决定后面问什么。一口气问十个问题，等于放弃了这个依赖链，也放弃了追问的机会。

**强制列缺陷。** 设计文档常见的毛病是只写优点，坑全留给写码阶段爆雷。这里定稿前必须列出已知缺陷和取舍，你不接受某条，退回上一步换方案。丑话必须说在写码之前。

**HARD-GATE 防跑偏。** 磨设计聊着聊着容易滑进实现细节，这里设了硬闸，到点拉回设计层，实现是下一步的事。另有一条 YAGNI 红线，第一版能砍的全砍。

问题数量不写死，简单的想法两三轮收敛，复杂的多磨几轮，轮数跟想法复杂度走。

## 流程和产出

磨需求，做什么、给谁用、核心闭环、明确不做什么。磨方案，核心机制怎么实现。列缺陷，强制过一遍。出设计纪要，落盘一份文档。

这份纪要不是聊天的总结，是下游的原料。交付流水线的 PRD 直接从它生成，磨设计是那条十二步流水线的第一步。提问技巧里融合了 mattpocock 的 grill-me，推荐答案、决策树这些绝活，原文副本已随交付流水线落档，不存在原 skill 丢了这套就废的问题。

## v1.1 是怎么来的

来自一场真实的磨设计。用户提了个游戏想法，旧版裸问，用户只能一句句描述自己的想法，中途还推翻了原方案重来。升级后重跑同类对话，每问必附推荐加理由加备选的代价，用户三次点头一次改选，四轮收敛。定稿时列了三条已知缺陷，用户对其中一条当场说不能接受，回到上一步换了方案。

那条缺陷如果留到写码阶段才发现，代价是一周的返工。

## 什么时候不用

需求已经写成文档并且评审过了，直接进实现。改 bug、调参数，没有设计可磨。你明确说别问了直接做，它尊重，但会坚持至少列一次缺陷清单，这是底线。
