# 头脑风暴（brainstorm v1.1.0）

> [← 返回总目录](../README.md#skills-index)

## AI 最贵的错误

你随口说了一句："帮我做个记账 App。"

AI 当圣旨开写。两小时后给你一个完整的记账 App——记什么账？它猜的。给谁用？它猜的。数据存哪、要不要多端同步？全是它猜的。技术栈？它挑了它最熟的，而你其实想学 Rust。

**猜错方向写两千行，比开工前问一句贵一百倍。** 这就是"没磨设计就动手"的代价。

但反过来，另一个极端也很折磨人：有的 AI 会一口气抛给你十个问题——"目标用户是谁？核心功能是什么？平台是什么？ monetize 策略？"——你看着就想关窗口。

这个 skill 走中间那条路：**一次只问一个问题，而且每个问题都带推荐答案。**

## 它和"让 AI 问清楚再做"的差别

| 让 AI 自己问 | 这套头脑风暴 |
|---|---|
| 一口气十个问题，你看都不想看 | 一次一个，问完等答，下一个问题由上一个的答案决定 |
| 裸问："目标用户是谁？"（你答不上来） | **每问带推荐**："我推荐先做给自己用，因为记账需求自己最懂、能最快闭环；如果做家庭共享账本，复杂度翻三倍。同意吗？" |
| 你说"你看着办"，它就真乱办 | 你说"你看着办"，它给出推荐+理由+备选的代价，你点头就锁定 |
| 设计文档只写优点 | **方案强制列缺陷**——把丑话说在写码之前 |
| 问题数量写死 | 弹性轮数：简单想法两三轮收敛，复杂的多磨几轮 |

**"每问带推荐答案"是整个设计的灵魂。** 不会表达需求的人得到了现成的判断（点头或摇头即可），会表达的人省了一轮对话。它把"盘问"从审讯变成了选择题。

## 流程长什么样

1. **磨需求**：一次一问，逐层收敛——做什么、给谁用、核心闭环是什么、明确不做什么（YAGNI 红线：第一版能砍的全砍）；
2. **磨方案**：核心机制怎么实现，HARD-GATE 挡住跑偏——聊着聊着开始讨论实现细节时拉回设计层；
3. **列缺陷**：定稿前强制列出已知缺陷与取舍，你不接受某条缺陷就回到上一步；
4. **出设计纪要**：落盘一份文档——它不是聊天的总结，是下游的原料：交付流水线的步③ PRD 直接从它生成。

提问技巧融合了 mattpocock 的 grill-me（推荐答案、决策树），原文副本已随交付流水线落档，不存在"原 skill 丢了这套就废了"的问题。

## 一段真实的磨设计记录

这个 skill 的 v1.1 就是在一次真实磨设计中升级的：用户提了个游戏想法，AI 按旧版裸问，用户只能一句句描述自己的想法；中途用户推翻了原方案。升级后的流程变成——AI 每问必附"我推荐 X，因为…；Y 也行，代价是…"，用户三次点头、一次改选，四轮收敛；方案定稿时列了三条已知缺陷，用户对其中一条当场说"这条不能接受"，回到上一步换了方案。**那条缺陷如果留到写码阶段才发现，代价是一周的返工。**

## 什么情况别用

- 需求已经写成文档且评审过——直接进实现；
- 改 bug、调参数——没有"设计"可磨；
- 你明确说"别问了直接做"——它尊重，但会坚持至少列一次缺陷清单，这是底线。
