# A-Cao-记忆纪律（memory-scoring-lifecycle v3.2）

> [← 返回总目录](../README.md#skills-index)

## 一句话

一套跨会话长期记忆的**全生命周期规则**：写入、评分、排序、召回、衰减、升华全都有明确纪律——让 AI"记住该记的、忘掉该忘的"，并且记忆成本恒定可控。

## 它解决什么问题

- AI 的记忆两个极端：要么**全忘**（会话一关清零），要么**全塞**（把历史全堆进上下文，token 爆炸且噪音淹没重点）；
- 重要结论和临时细节混在一起，没有"这条记忆值多少分、还能活多久"的概念；
- 同一个坑踩了三次，AI 还是三次都掉进去——没有"坑升级成铁律"的机制；
- 多个 AI 宿主各记各的，规则漂移、互相不知道对方记了什么。

## 核心机制

- **三记五不记**：本质层必写、细节按需写；密钥/临时过程/可推导信息不写；
- **V/R 评分公式**：写入即打分（影响/复发/成本/稀缺/强调 + 相关/新鲜），排序分决定召回优先级，而不是"最近写的排前面"；
- **三层触发词**（现象/实体/本质 + 同义）：保证未来能通过多种问法召回同一条记忆；
- **O(1) 路由表**：CORE 层常驻 ≤150 行，路由表直达目标库，单次检索预算 ≤2000 token；
- **升华机制**：同一个根因的坑累计 ≥3 次 → 自动升格为铁律进 CORE，从此不再犯；
- **确定性脚本** `memory_maintain.py`：体检（schema/容量/健康度）与衰减由脚本结算，**不靠模型自觉**；
- **规则共享一份、store 各宿主独立**：ZCode/Codex/WorkBuddy 用同一套规则、各自的数据，永不互相污染。

## 和同类方案比，差在哪

| 方案 | 问题 | 本 skill |
|---|---|---|
| 记忆全堆一个文件 | token 随历史线性膨胀，重点被淹没 | 索引常驻+详情懒加载，**成本恒定** |
| 纯向量库记忆 | 不可审计、无生命周期、黑盒召回 | 每条记忆有评分/有效期/证据链，**可人工查阅可修订** |
| 各宿主各建一套规则 | 行为漂移 | 规则单源共享，store 数据分家 |
| 只有写入没有淘汰 | 垃圾记忆越积越多 | 评分衰减 + 升华 + 体检脚本闭环 |

## 3 分钟上手

1. 复制文件夹到你所用 Agent 的 skills 目录（见[总目录](../README.md#skills-index)）；
2. 按 skill 内"冷启动"四步：建 MEMORY.md 放常驻引导卡 → 建各库空索引 → 写第一条 PROFILE → 复制体检脚本；
3. 之后每轮会话：开场读索引 → 按需深读命中详情 → 收尾跑一次 `check`。

## 实战绩

在 `E:\Zcode-memory` 实跑（ZCode 宿主）：本次仓库优化期间发生的"多宿主并行写入 ID 撞车"事故，就是靠这套纪律完成记录、打分、升华为 pit-002 的全过程——记录、复盘、预防建议一条龙，你可以去翻那份记录看实际效果。

## 适用 / 不适用

- ✅ 需要 AI 跨会话延续上下文的任何长期使用场景；多宿主用户尤其受益；
- ❌ 纯一次性问答场景——没必要给一次性对话建记忆库。
