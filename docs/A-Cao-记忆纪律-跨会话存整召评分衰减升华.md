# A-Cao-记忆纪律（memory-scoring-lifecycle v3.5）

> [← 返回总目录](../README.md#skills-index)

## 先摸一下你自己的记忆文件

用 AI 干活超过一个月的人，多半有这么一个文件：名字叫 MEMORY.md 或者别的什么，里面堆着 AI 的"长期记忆"。去数数它多少行了——几百行？上千行？

然后注意一件事：**每次开新会话，这个文件都要整个读一遍。** 它越肥，你每个会话开局烧掉的 token 越多，而且里面 90% 的内容跟这次对话毫无关系。

更难受的还在后面：记了一堆，真出事的时候翻不出来——"AI 好像之前犯过这个错？记在哪了？"想不起来关键词就等于没有。同一个坑，换个场景再踩一遍。

这个 skill 是一套完整的记忆生命周期规则：**什么该记、记了值几分、什么时候衰减、什么条件下升级成铁律**——全部定死，不靠 AI 每次现场发挥。

## 三条底层判断（整套规则都从这三条推出来）

**一、记忆的成本是按"每次会话"重复付的。** 所以关键不是能记多少条，而是**常驻的那部分有多轻**——索引永远压在 2000 token 以内，细节只在你真问到时才展开。

**二、记忆的价值在"取"不在"存"。** 存一万条翻不出来等于零。所以每条记忆挂三层触发词（现象/实体/本质）加同义词，配路由表 O(1) 直达——从任何角度问都能落到那一条。

**三、教训的价值在"不再犯"，不在"记下来"。** 光记录不提炼，同一个根因换个壳再犯一遍。所以有升华机制：同一根因累计 3 次，自动升级成铁律写进 CORE，此后每次会话强制加载。

## 我把市面上 9 个方案研究了一遍，一个都没直接用

mem0、Zep、MemGPT、Generative Agents、MemoryOS……这 9 个主流方案我逐个看了。结论先说：**它们没有一个是为"纯文件 + 人肉维护"设计的**——全部要数据库、要常驻服务。所以策略是抄思想、不抄架构：

| 方案 | 我拿走了什么 |
|---|---|
| Claude Code MEMORY.md | 骨架：纯 MD、容量红线、索引常驻细节按需 |
| Generative Agents | 三维评分改造成 **V/R 双轨评分**；Reflection 改造成**升华** |
| mem0 | supersedes 版本链、冲突软删除 |
| Zep / Graphiti | "失效而非删除"的双时间语义 |
| MemoryBank | 艾宾浩斯时间衰减 |
| MemoryOS | 热度驱动晋升 |
| MemGPT / Letta | 分层按需换入的思想（架构不采纳） |

**明确不抄的四样**（都要额外依赖，个人场景扛不住）：向量库/图数据库、常驻进程定时衰减、多超参调优、全量 Embedding。**多大体量才值得上重武器？超过 200 条才考虑 Embedding——绝大多数人一辈子到不了。**

两处业界普遍做得不好的，这里补上了：**遗忘区归档**（冷记忆移进遗忘区而不是硬删）和**二次判定召回**（不是一次检索定生死）。两处它们先有的（冲突处理、升华），也已补齐。

## 一个真实的评分例子

做技术核查时我犯过两次同一个错：看到数据模型里有某个字段，就断定这个功能真实存在。第一次据此反驳了别人的修改建议；第二次深查才发现那个字段前端根本没调用过——只是预留。

两次根因一模一样：**字段存在 ≠ 功能实现。** 过一遍评分公式：影响 20（对外描述写了不存在的能力）+ 复发 15（犯了两次）+ 成本 15（散落多文档返工贵）+ 稀缺 10（此类陷阱少见），V = 5 + 20 + 15 + 15 + 10 = **65**，进"教训"层。再犯一次就升华成铁律——此后每次核查强制先查调用链末端。

注意这套机制妙在哪：**同一个坑踩满 3 次，它自己长成规则，不需要你记得去整理。**

## 用了之后实际得到什么

- **上下文成本恒定**：索引常驻且永不膨胀（超量归档+压缩），不像"全堆一个文件"成本随条目线性涨；
- **不丢东西**：过时标失效、冷门进遗忘区，都能二次召回捞回来，不是删掉；
- **会自己进化**：同根因踩满 3 次自动升华，规则自己长；
- **换宿主不失效**：规则共享一份，各 agent 各建各的 store，规则里不含任何本机路径——Claude Code、Codex、WorkBuddy 照用；
- **可审计**：每条记忆为什么是这个分，公式能手算，不是黑箱排序。

## 什么情况别用

- 单次会话的临时任务、一次性对话——不需要长期记忆就别建这一套；
- 条目还不到十条——目录表格就够了，别过度工程。
