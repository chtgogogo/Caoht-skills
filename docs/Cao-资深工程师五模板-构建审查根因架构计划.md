# Cao-资深工程师五模板（senior-engineer-playbook v1.0）

> [← 返回总目录](../README.md#skills-index)

## 同一个请求，两种结局

你对 AI 说："帮我做一个待办事项应用。"

**没有结构时**，它给你一个 HTML 文件，里面一个输入框一个列表，能加能删——然后没了。没有数据存储、没有验证、没有部署说明、没有"下一步该做什么"。你拿到了一个 demo，不是产品。

**有结构时**，它先问两个关键问题（给谁用？数据要存吗？），然后按清单交付：技术选型+理由、目录结构、核心实现、数据持久化方案、运行验证结果（贴出真实运行输出）、已知限制、下一步建议。你拿到的是第一版**产品**，而且清楚地知道它现在缺什么。

差的就是一套**结构化交付清单**。这个 skill 给五种最高频的工程任务各配了一套：构建、审查、根因、架构、计划。

## 对号入座

| 你说 | 它走哪套 | 给你什么 |
|---|---|---|
| "帮我做一个……应用/工具" | ① 构建 | 生产就绪清单：选型理由/结构/实现/持久化/验证/限制/下一步 |
| "分析这段代码，帮我改进" | ② 审查 | 逐维审查：正确性/可读性/性能/安全，按严重度分级 |
| "为什么报错/修不好/又出问题" | ③ 根因 | 四阶段排障：复现→定位→假设验证→修复+防复发 |
| "设计一个系统，要扛……用户" | ④ 架构 | 容量估算→瓶颈分析→分层设计→扩展路径，数字分档给 |
| "我有个想法，帮我规划/值不值得做" | ⑤ 计划 | 目标拆解→MVP 边界→里程碑→风险清单 |

命中几个场景读几个模板，只命中一个只读一个——省上下文。五套还能串成完整生命周期：⑤想法 → ①构建 → ③调试 → ②审查。

## 三条内嵌的纪律，比清单本身值钱

**数字不脑补。** 架构题问"能扛多少用户"，用户没给量级，普通 AI 会编一个精确数字显得专业（"支持 5000 QPS！"）。这里明文禁止：占位数字没给就标"未知"，给分档方案（千级/万级/十万级各自怎么设计）。**编造的精确数字是最危险的幻觉——它看起来像知识，其实是谎言。**

**不讨好。** 你的想法有缺陷，直说+给解法，绝不为让你开心而弱化问题。这是"顾问"，不是"捧场王"。

**只问"缺了会白干"的问题。** 给谁用、存不存数据、部署到哪——这种必须问；无关紧要的选型自己定、说一句理由就开工。**把提问的额度花在刀刃上，不拿琐碎问题烦你。**

## 和"网上抄来的提示词模板"比，差在哪

这个 skill 的源头确实是社交平台流传的 5 条资深工程师提示词——但它不是复制粘贴，是**转译**：

| 原版提示词（复制粘贴用） | 这个 skill（Agent 直接执行） |
|---|---|
| 一大段文字，人找场景手动套用 | 触发词自动路由，"帮我做个应用"直接命中①号模板 |
| 模板是"角色扮演指令"（"你现在是资深工程师"） | 模板是**交付清单**（每项产出物可检查、可验收） |
| 放在备忘录里，换个工具就丢 | 与编码行为准则叠加生效，六条纪律一条不少 |
| 没有验证要求 | 交付"完整实现"必须实际跑通，读退出码 |
| 提示词不告诉你该问什么 | 明确"哪些必须问、哪些自己定"，问答边界写死 |

一句话：原版是给人念的咒语，这个是给 Agent 用的作业指导书。

## 什么情况别用

- 纯闲聊、纯写作——零代码任务不触发；
- 明确只需要某一个具体小功能的小改动——上交付流水线的轻量档更合适。
