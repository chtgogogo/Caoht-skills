# Cao-资深工程师五模板（senior-engineer-playbook v1.0）

> [← 返回总目录](../README.md#skills-index)

对 AI 说："帮我做一个待办事项应用。"

没有结构的话，它会给你一个 HTML 文件，一个输入框，一个列表，能加能删。然后没了。没有数据存储，没有验证，没有部署说明，也没有下一步该做什么的提示。你拿到的是一个 demo。

有交付清单的话，它会先问两个问题，给谁用，数据要不要存。然后按清单走，技术选型加理由，目录结构，核心实现，持久化方案，运行验证的结果，已知限制，下一步建议。你拿到的是第一版产品，而且清楚它现在缺什么。

这个 skill 给五种最常见的工程任务各配了一套这样的清单。构建、审查、根因、架构、计划。

## 对号入座

| 你说 | 它走哪套 | 给你什么 |
|---|---|---|
| 帮我做一个应用或工具 | 构建 | 生产就绪清单，选型理由、结构、实现、持久化、验证、限制、下一步 |
| 分析这段代码，帮我改进 | 审查 | 按正确性、可读性、性能、安全逐维过，问题按严重度分级 |
| 为什么报错，修不好，又出问题 | 根因 | 复现、定位、假设验证、修复加防复发，四阶段 |
| 设计一个系统，要扛多少用户 | 架构 | 容量估算、瓶颈分析、分层设计、扩展路径 |
| 我有个想法，值不值得做 | 计划 | 目标拆解、MVP 边界、里程碑、风险清单 |

命中几个场景读几个模板，只命中一个就只读一个，省上下文。五套还能串起来，想法进计划，计划进构建，构建出问题走根因，做完了走审查。

## 三条内嵌的纪律

这三条不写在任何单个模板里，是所有模板生效前都要过的。

**数字不脑补。** 架构题问能扛多少用户，你没给量级的话，AI 倾向于编一个精确数字显得专业，比如张口就是支持 5000 QPS。这里明文禁止。占位数字没给就标未知，给分档方案，千级、万级、十万级各自怎么设计。编造的精确数字是最危险的一类幻觉，它看起来像知识。

**不讨好。** 你的想法有缺陷，直接说，带上解法。不会为了让用户开心把问题说轻。

**只问缺了会白干的问题。** 给谁用、存不存数据、部署到哪，这种必须问。无关紧要的选型自己定，说一句理由就开工。提问的额度有限，得花在刀刃上。

## 跟网上流传的提示词模板的关系

这个 skill 的源头确实是社交平台流传的五条资深工程师提示词，开头就写明了来源。但它们不是被复制过来的，是被转译过来的。

原版是一大段文字，人找场景手动套用。这里是触发词自动路由，你说"帮我做个应用"，它自己命中构建模板。

原版的内容是角色扮演指令，你现在是资深工程师。这里改成了交付清单，每一项产出物可检查可验收。角色扮演依赖 AI 演得像，清单只看东西交没交齐。

原版没有验证要求。这里交付完整实现必须实际跑通，读退出码。

原版不告诉你该问什么。这里把哪些必须问、哪些自己定写死了。

一句话说，原版是给人念的咒语，这个是给 Agent 用的作业指导书。

## 什么时候不用

纯闲聊、纯写作这类零代码任务，不触发。明确只是一个具体小功能的改动，走交付流水线的轻量档更合适，那边有台账和断点续传。
