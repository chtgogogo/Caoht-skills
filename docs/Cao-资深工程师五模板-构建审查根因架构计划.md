# Cao-资深工程师五模板（senior-engineer-playbook v1.0）

> [← 返回总目录](../README.md#skills-index)

让 AI"帮我做一个待办事项应用"，你大概率拿到一个 HTML 文件，一个输入框，一个列表，能加能删，然后没了。没有数据存储，没有验证，没有部署说明，也没有下一步建议。你拿到一个 demo，不是产品。

原因在于请求和交付之间没有结构。原版解决这个问题的思路，是社交平台流传的五条"资深工程师提示词"，让 AI 扮演资深工程师再干活。这个 skill 把它们转译成了 Agent 可执行的工作流，扮演变成了清单，念咒语变成了照单干活。

## 五套清单，各对一个场景

| 你说 | 它走哪套 | 交付什么 |
|---|---|---|
| 帮我做一个应用或工具 | 构建 | 选型加理由、目录结构、核心实现、持久化、验证结果、已知限制、下一步 |
| 分析这段代码，帮我改进 | 审查 | 正确性、可读性、性能、安全逐维过，问题按严重度分级 |
| 为什么报错，修不好 | 根因 | 复现、定位、假设验证、修复加防复发，四阶段 |
| 设计一个系统，要扛多少用户 | 架构 | 容量估算、瓶颈分析、分层设计、扩展路径 |
| 我有个想法，值不值得做 | 计划 | 目标拆解、MVP 边界、里程碑、风险清单 |

命中几个场景读几个模板，只命中一个就只读一个，省上下文。五套还能串成完整生命周期，想法进计划，计划进构建，构建出问题走根因，做完了走审查。

## 三条内嵌纪律，比清单本身还值钱

**数字不脑补。** 架构题问能扛多少用户，你没给量级，AI 倾向于编一个精确数字显得专业，张口就是支持 5000 QPS。这里明文禁止，占位数字没给就标未知，给分档方案，千级、万级、十万级各自怎么设计。编造的精确数字是最危险的一类幻觉，它看起来像知识。

**不讨好。** 你的想法有缺陷，直接说，带上解法，绝不为了让你开心把问题说轻。

**只问缺了会白干的问题。** 给谁用、存不存数据、部署到哪，这种必须问。无关紧要的选型自己定，说一句理由就开工。AI 最招人烦的习惯之一是拿琐碎问题轰炸你，这条把提问额度花在刀刃上。

## 转译和照抄的区别

| 原版提示词 | 这个 skill |
|---|---|
| 一大段文字，人找场景手动套用 | 触发词自动路由，命中场景自动读对应模板 |
| 角色扮演指令，你现在是资深工程师 | 交付清单，每项产出物可检查可验收 |
| 放在备忘录里，换个工具就丢 | 跟编码行为准则叠加生效，纪律一条不少 |
| 没有验证要求 | 交付完整实现必须实际跑通，读退出码 |
| 不告诉你该问什么 | 必须问什么、什么自己定，边界写死 |

角色扮演依赖 AI 演得像，清单只看东西交没交齐。这是转译里最关键的一步。

## 什么时候不用

纯闲聊、纯写作这类零代码任务，不触发。明确只是一个具体小功能的改动，走交付流水线的轻量档更合适，那边有台账和断点续传。
