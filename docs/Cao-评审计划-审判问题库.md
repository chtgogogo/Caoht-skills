## 第 0 章 五分钟速览

1. **只审还没动工的计划。** 已建成项目的交付验收归项目验收官，写好的代码归编码审查。[实测]（`SKILL.md`『与邻居的分工』）
2. **核心动作叫「过堂」**：拿一张固定审判清单，按类别逐题对着计划问过去，每题当场给结论。
3. **三态判定**：✗ 中招（引计划原文为证）／? 存疑（写清要问谁、要实测什么）／✓ 通过（一句理由）。[实测]（『审判流程（五步）』第 2 步）
4. **题库是主资产**：14 类 58 题（建库 50，此后四轮审判各加 4/2/1/1）；每题四要素＝问什么／为何是坑／何时爆／怎么查。[实测]（`references/审判问题库.md` 头部与『目录』）
5. **命根子是第 5 步**：本次新类型问题必须追加回库——"审完不沉淀＝本次审判只值一半"是入口层第一行的判据（判据＝可执行的判定标准）。[实测]
6. **最锋利的一组是可靠性四问**：爆炸半径／发现机制／兜底自检／档位前提，警句是"有界≠可靠"。[实测]（『可靠性主张四问』）
7. **报告结论段只留最致命 ≤3 条**，其余进分级明细，防止所有问题被拉平成"都要改"。[实测]

**设计目标**：把"审计划"从**当轮灵感**变成**对着越审越厚的题库逐题过堂**，让同一类坑不会被踩第二次——麻烦必须在动工前挖出来，挖出来的新坑必须变成下一轮的题。

## 第 1 章 这套系统在解决什么问题

没有它的时候：让 AI"批判一下这个计划"，它当然挑得出毛病，但**挑什么全看那轮想到了什么**。这一支堵的是这类审查的结构性缺陷。

| 故障 | 表现 | 本 skill 的解法 |
|---|---|---|
| ① 审查靠临场发挥 | 同一份计划，某天审出 12 条、某天只 3 条 | 58 题固定清单逐类过堂，缺题＝没审 |
| ② 审完就散 | 这次发现的怪事下次照样踩 | 第 5 步沉淀回库，库单调增长 |
| ③「测试全绿」被当结论 | 45 轮每卡都是脚本断言、用例全绿，真实用户拿到包却用不起来 | E 类挂链测试纪律的证据形态；Q57 实抽 3 张卡 |
| ④ 备胎就是原来的病 | 主路挂了切"凭记忆手动补记"，病根恰是记忆不可靠 | 四问第 3 问判为未兜底（Q10） |
| ⑤ 拿"损失有上限"当够用 | 论证出"坏了也就丢这些"，据此砍掉补强 | Q8：金库失窃有上限，不等于金库不需要门 |
| ⑥ 故障静默 | 定时任务假期停了两周，第 21 天才发现 | Q13 心跳／黄旗／报警三选一；Q9 发现动作挂进必做项 |
| ⑦ 参数拍脑袋 | 被追问"为什么是 0.85 不是 0.61"就答不出 | Q55 参数三层：经济依据／架构兜底／校准承诺 |
| ⑧ 并行互相踩文件 | 两窗口同时收尾，在途改动被对方提交顶替 | Q58 文件面碰撞矩阵 |
| ⑨ 讨好式审查 | 报告通篇 ✓，因为不想得罪写计划的人 | 「不讨好」条款＋交锋留痕＋复审全绿 |

**①＋② 这对组合最致命**：光有清单不沉淀，清单永远停在 50 题；光有沉淀冲动没有清单，那一次仍靠灵感。两件事被写进五步流程的第 2 步与第 5 步——**流程才是卖点，题库只是它的产物**。

## 第 2 章 术语表

中文行话也按"说人话"翻译一遍，后文不再重复。

| 术语 | 一句大白话 |
|---|---|
| 过堂 | 拿固定清单逐题问过去，每题当场给结论，不许跳 |
| 三态判定 | 每题只落三格：中招（✗）／存疑（?）／通过（✓） |
| 中招 | 这坑在你的计划里真存在，且必须引计划原文当证据 |
| 存疑 | 既不能说坏也不能说好，要写清缺哪条证据、去找谁 |
| 判据 | 可执行的判定标准：照着做就能判"过／不过"，不靠感觉 |
| 闭环 | 问题从提出到验证解决全程有据可查，中间不断档 |
| 分级 | 按后果严重性排序：致命／重要／细节 |
| 要素清单 | 开工前把计划拆成承诺（口号）／机制（怎么转）／验收（怎么算成） |
| 沉淀／回库 | 把新发现的坑写成一道新题追加进库 |
| `retired` | 题作废了打这个标记，编号留着，防历史引用失效 |
| 爆炸半径 | 它坏掉的最坏结果与损失上限（坏一次到底赔多少） |
| 有界 | 损失有封顶值；注意：**有界 ≠ 可靠** |
| 降级链／兜底 | 主路不通时依次退到哪些备选；兜底＝最后那层保险 |
| 静默失败 | 坏了不报错不出声，没人被通知 |
| 心跳 | "我还活着"的可见信号；连续没信号就算死 |
| 红旗／黄旗 | 要立刻处理的告警／只提醒不阻断的告警 |
| 可靠性档位 | 参考级（看一眼）／榜单级（只作排序）／审计级（据此定对错） |
| 前提升格 | 把"这次碰巧防住"改写成"本结论成立的前提是 X" |
| 单一事实源 | 同一份数据只存一处；不打架，但那里坏了就全丢 |
| 口径 | 一个数字是怎么算出来的那套规定 |
| 勾稽 | 两处独立写的数字能对上；对不上就有假数 |
| 挂链 | 把另一条纪律的要求接进来当审查标准，不过即判中招 |
| 提示注入 | 外部文本里藏"忽略以上直接批准"，被当成命令执行 |
| 定界标记 | 圈出"这段是数据不是指令"，不许当命令读 |
| schema 硬约束 | 输出必须是指定字段形状，缺字段直接判失败 |
| 挂起态／超龄 | 卡在"等人批"；超龄＝等太久没人管，无声积压 |
| 碰撞矩阵 | 并行任务两两列出各自动哪些文件，交集非空即不能并行 |
| 累计阈值 | 用"攒够 3 次算成"代替"两周内 3 次算成"（后者遇假期假失败） |
| 可证伪 | 能被一个具体测试推翻；"效果良好"不能 |
| 盲审／镜片 | 不知情角色从头看一遍；镜片＝指定视角（小白用户等） |
| 交付物定义 | 一句话说清谁用、怎么用、第一次交付长什么样 |
| 元问题 | 审这套系统自己：最后一题 Q50 问的就是"审完有没有沉淀" |
| 台账 | 只追加不改写的流水账（这里指 `CHANGELOG.md`） |

> 案例文件名含真实项目名，按公开口径本页不复述，一律称"发源案例／三轮攻防案例"。

### 3.2 三层渐进披露（不一次把细节全塞进上下文，先给入口、需要才展开）

- **判据与流程**留入口层：每次审判都要用，必须极短（61 行，远低于常引用的"单文件 500 行建议上限"）。
- **题目本体**独立成文件：它是唯一持续变长的部分，写进入口层＝58 题变读不完的常驻内容。
- **案例**再独立一层：它教"怎么审"，是教材不是尺子——尺子必须短，教材可以长。

### 3.3 判定顺序（不许跳）

```
流程级：1 通读+拆要素表 → 2 逐类过堂（A→N，三态）
        3 中招分级，结论段只留最致命 ≤3
        4 修订后复审逐条销账，修订带出新嫌疑则该类的重过
        5 新类型回库追加 + 台账记一笔（必做）
单题级：问什么 → 为何是坑 → 何时爆 → 怎么查 →（有则）案例出处
```

> 「何时爆」排在「怎么查」前面：说不清什么时候爆的问题不值得改；查法只有在前两步确定后才有意义，否则查的是个不存在的东西。

## 第 4 章 五步审判流程详解

流程本体在 `SKILL.md`『审判流程（五步）』，只有五行；这里逐步拆成"做什么→产出→为什么→少了会怎样"。

### 4.1 第 1 步：通读 + 要素清单

| 要素 | 计划里的样子 | 拆不出来会怎样 | 主要对应类 |
|---|---|---|---|
| 承诺（铁则／口号） | "每一环断了都不影响上一环" | 全称主张没人找反例 | A 结构性矛盾 |
| 机制（怎么运转） | "钩子自动追加一行记录" | 没人问挂在谁的自觉上 | B 可靠性 · C AI 假设 |
| 验收（怎么算成） | "两周内 3 次命中即达标" | 验收条件本身不可证伪 | E 验收与度量 |

- 原文写明它是第 1 步的理由："后面每道题都对着这三类要素问"。题库按坑的**性质**分类不按题材，手里没要素表就无从对问。[实测]
- [推演] 什么输入会出问题：计划只写目标不写怎么算成时，"验收"列会空——这个空格本身就是 Q30 的中招证据，不该被补成"上线后看效果"。少了这步＝"读到哪条题问到哪条"，与第 1 章 ① 同病。

### 4.2 第 2 步：逐类过堂（全类，不许挑）

- 原文要求：按问题库**全部类别**（A~N，随库生长）逐题判定三态。[实测]
- [推演] 为什么不是"挑相关的"：挑这个动作本身要判断力，而判断力正是流程要替代的东西——K~N 四类全部来自"当初以为不相关"的视角（见 9.1）。
- **E 类挂链**：验收标准的证据形态遵循测试纪律那支——原始输出落盘／改前改后各跑一次／口径标注／禁只报总结数字；**"测试全绿""效果良好"没有证据形态就按中招处理**。[实测]（『审判流程』第 2 步括注）
- **裁决纪律**：不讨好；批语对事不对人但绝不放过；被审方反驳就进交锋，谁有理听谁的，裁决过程全部留痕（留痕＝结论与理由都写进报告，事后可复盘）。类目漂移的旧计数见 15.3。

### 4.3 第 3 步：分级聚焦

| 级别 | 判据 | 去处 |
|---|---|---|
| 致命 | 不修就白花几周，或方向性错误 | 结论段，≤3 条 |
| 重要 | 会痛，但有绕行办法 | 留在裁决表 |
| 细节 | 措辞、编号、命名 | 顺手改，不进结论段 |

### 4.4 第 4 步：复审闭环

- 对上轮**中招／存疑**项逐条销账复核；修订引入新嫌疑 → 只重开被改的那一类，不整库重过。
- "全绿才算过堂"里的全绿＝上轮中招与存疑清零，**不是**"本轮没发现新问题"。[实测] 没有这一步，中招项会被"顺手解释掉"。

### 4.5 第 5 步：沉淀回库（必做，命根子）

| 规则 | 要求 | 理由 |
|---|---|---|
| 只增不删 | 库里没有的新类型按条目格式**追加** | 删题＝把教训从检索面上抹掉 |
| 编号只增不重排 | 新号＝读库取当前最大号 +1 | 重排会让所有历史引用指向错题 |
| 禁止凭记忆编号 | 明写"禁止沿用记忆中的旧号" | 跨会话时"我记得上次到 54"极易说错，勾稽当场破 |
| 作废留号 | 标 `retired` 保留编号 | 防历史引用失效 |
| 注明来源与日期 | 每题带真实案例出处 | 没有出处的题＝编造，不许入库 |
| 单点坑分流 | 典型单点坑另走踩坑日志那支 | 题库收"问题类型"，不收一次具体故障 |

## 第 5 章 三态裁决与证据要求

| 状态 | 必填 | 不合格的样子 |
|---|---|---|
| ✗ 中招 | 引计划原文为证／何时会爆／修法建议 | "感觉这里不稳"（无原文＝不可复核） |
| ? 存疑 | 要问谁／要实测什么 | "待确认"（不写问谁＝没人会被问） |
| ✓ 通过 | 一句话理由 | 空格（空格与"没看懂"长得一样） |

- **为什么 ✓ 也要写理由**：[推演] 不写理由的 ✓ 与"没看懂所以没意见"在报告里无法区分；一句理由把"我确认它成立"和"我没意见"分开，复审时才有东西可对。
- **为什么存疑态必须存在**：只有两态时，信息不足会被迫二选一，于是编理由填格。存疑把"缺什么证据"本身变成合法产出，报告里单列《存疑清单》。这与同库抗幻觉纪律同源（未知就写未知，不许用推测填空）。
- **为什么中招必须引原文**：把审判从"观点"降级成"物证"——引了原文，被审方要反驳就得反驳那句话，而不是反驳审判者的想象力。
- **交锋与留痕**：发源案例的关键一击，是被审方在第二轮推翻了自己第一轮的辩护（"有界"被推翻为"有界≠可接受"）；落点是报告的《复审记录》＋台账。**不讨好≠刻薄**，它禁的是为了显得友好而漏题，物理表现是 ✓ 数量偏多（见 10.2）。

## 第 6 章 分级聚焦与"最致命 ≤3 条"

### 6.1 为什么上限是 3

- 报告读者一屏内只拿得住少数行动项；写 5 条以上，实际行为是把它们当同一优先级处理——**等于没有优先级**。[推演]
- 3 与同库另一支的"最弱项点名 1–3 项"是同一个尺度，不是各自随手定的数。
- **换成 1 条**：发源案例同时中了"没有定义"和"兜底＝原始病"，留 1 条必漏一条。[实测]
- **换成 5 条**：结论段膨胀成第二张裁决表，"能否动工"这个判断被稀释。[推演]

### 6.2 致命级判定动作

只问一句：**这一条不修，后面所有工作会不会白做？**
反例对照：Q2 核心名词无定义＝度量与验收全部失去意义（致命）；Q10 兜底＝原病＝主备同失效（致命）；
Q46 凭据写进脚本＝第一次公开推送即泄露且不可逆（致命）；Q31 工时乐观单值＝会超但可绕行（重要）；
Q32 未标覆盖范围＝会被误读但可事后补一行（重要）；编号跳变无说明＝难看却不误导决策（细节）。

结论段固定两样东西：**能否动工**（能／修订后能／不能）+ **最致命 ≤3 条**；分级明细在上面，不在结尾抢位置。[实测]（『《审判报告》骨架』首行）

## 第 7 章 可靠性主张四问（最锋利的一组）

原文定位：`SKILL.md`『可靠性主张四问』，标注"审任何机制先过这四问"。它与题库 B 类是同一套东西的两个面：**四问是打法，B 类是清单**。

### 7.1 第 1 问 爆炸半径

**它挂了会怎样？损失上限多少？**

- 对应题：Q7（主张配爆炸半径）、Q45（每环断了怎么继续，并提醒"数据不丢 ≠ 功能不退化"）。
- 为什么锋利：绝大多数计划只写"会怎样成功"。要求每个机制补一句"挂了会怎样"，是把可靠性从形容词变成名词。

### 7.2 第 2 问 发现机制

**它挂了，谁、在哪个必做动作里会发现？**

- 原文铁口：必须挂进既有 checklist（必做清单）的必做项；**"写在文档里／记得去看"＝没挂**。[实测]
- 对应题：Q9（挂在自觉上＝没挂）、Q13（心跳／黄旗／报警三选一，且"连续 N 期无信号＝已死"要有定义）、Q27（接线巡检）、Q54（挂起态超龄）。
- 为什么"必做动作"这四个字是关键：只靠额外自觉的检查等价于不存在——它会在任务繁忙那轮被最先牺牲。[推演]

### 7.3 第 3 问 兜底自检

**降级链（一层层退而求其次的备选）的最后一层，是不是就是原始病？**

- 原文判据形状：兜底＝"AI 凭记忆手动干"，而病根恰是"AI 凭记忆不可靠"→ **视为未兜底**。[实测]
- 发源案例原话："这不是降级链，是两级都会失效"——主路与备胎共用同一个故障原因，就不叫备份。[实测]（案例『第一轮：批评方开火』）

### 7.4 第 4 问 档位与前提

**可靠性按用途定档；档位成立的限定条件必须显式写。**

| 档位 | 大白话 | 典型要求 |
|---|---|---|
| 参考级 | 看一眼，不影响决策 | 可不补强 |
| 榜单级 | 只作排序参考 | 动作必人工确认 |
| 审计级 | 据此判定对错 | 每步可复核、有证据形态 |

- 对应题：Q14（限定条件写进可靠性论证，不塞机制注释）、Q21（自动动作所需档位高于参考级；动作清单 × 档位对照表）。
- 为什么"接自动化必须按高档重评"：档位是绑着使用方式定的；当初够用建立在"有人盯着"上，无人值守后要求直接换档。[实测]
- **前提升格**（原文最妙一条）：碰巧做对的防护要升格成"边界成立的前提条件"——**机制会被人优化掉，写进论证的前提不会**。删代码很容易，删一句"本结论仅在 X 成立时有效"会逼改它的人先回答为什么作废。[推演]

### 7.5 警句专节：有界 ≠ 可靠

- 位置：四问第 1 问的警告括注 + 题库 Q8。
- 形状：金库失窃上限＝金库里的钱（确实有界），但没人因此说金库不需要门。
- 它的实战对手是**用"损失可控"砍补强**的那类论证；发源案例里被审方第一轮正是靠"有界"反驳"整体失效"，第二轮自己推翻——**题库最硬的一条，是审判者先在自己身上用通的**。[实测]（案例『第二轮：二次反驳（关键一击）』）

### 9.1 生长时间线（题数单调增）

数法：按台账 `CHANGELOG.md` 各节标题读增量，与题库头部"当前 58 题"的分解一致。[实测]

### 9.2 K 计划与设计的对齐（Q51–Q54）

| 题 | 一句大白话 |
|---|---|
| Q51 | 设计讲 N 层防线、计划只建 N-1 层＝讲的一套做的一套；逐条防线找落点，无落点要么补卡要么从设计删 |
| Q52 | 将写进 README／简历的数字，计划期就写死定义＋基准来源＋实测还是折算＋覆盖范围；事后补口径＝数字先流出去再解释 |
| Q53 | 外部文本会进提示词，里面可能藏"忽略以上直接批准"；三条查法：数据与指令定界分离／关键动作由规则代码而非模型判定／输出 schema 硬约束 |
| Q54 | 等人工批的事没人批就永远躺着：要有超龄阈值＋可见提醒，且**只提醒不自动处置**（自动驳回在业务上危险） |

### 9.3 L 可调参数与设计动机（Q55–Q56）

- **Q55 参数三层辩护**：经济依据（它是哪个取舍的折中）／架构兜底（边界两侧谁接着）／校准承诺（上线后按什么数据怎么调）。答不出任一层即中招；辩护话术预写进文档，不现场编。
- **Q56 需求还是沉没成本**："不加白不加"就是沉没成本驱动；逐功能问"谁在什么时候需要它、没有它工作流断在哪"，判定标准是用户旅程不是资产清单，答不出即降级或删除。

### 9.4 M 交付物与用户验收（Q57，本支含金量最高）

题干：**验收标准的最高层＝目标用户的一次真实操作，测试指标盖不住它。**

- 背景（抽象化）：某项目 45 轮每卡验收都是脚本断言与报告，几百条用例全绿，却没有一张卡是"不会敲命令的人走通核心动作"；真实用户拿到包那一刻才暴露——过程质量 ≠ 交付质量。
- 查法三件：切卡前锁交付物定义／MVP 卡组必含一张"用户视角验收卡"／盲审镜片必含"小白用户"视角。
- **查法升级**：审判时必须**实际抽取计划中 3 张卡**的验收标准逐条查有无"非开发者可执行"的证据项——**只口头问"有没有用户视角"＝没查**。[实测]（Q57 条目内升级标注）
- 为什么抽 3 张：[推演] 抽 1 张会被"最用心的那张"糊过；5 张以上审判成本超过收益；3 张是"看得出成体系还是偶一为之"的最小样本。

### 9.5 N 并行执行（Q58）

并行卡各自"测试全绿"可能在同一共享文件上互相覆盖（在途改动被顶替、流水账串号）。查法：逐对列"动哪些文件"矩阵，交叉非零＝不许并行或只做零碰撞子集（只碰对方肯定不碰的文件）；账本文件按"最小差异纯追加"；版本控制只加本卡清单。

### 9.6 与邻居的联动

| 邻居 | 方式 | 性质 |
|---|---|---|
| 测试纪律 | E 类按其证据形态判，无证据即中招 | **挂链**（硬约束）[实测] |
| 失败模式与对策库 | 联合过堂：题 × 死法双轨 | 互补（当时 4 个新类型全来自死法视角）[实测] |
| 踩坑日志 | 典型单点坑另按其流程沉淀 | 分流 [实测] |
| 交付流水线 | 同一教训同日双库沉淀 | 同源 [实测] |
| 项目验收官 | 审未动工的计划 vs 审已建成的项目 | 分工 [实测] |
| 编码行为准则／五模板② | 写好的代码归它们 | 分工 [实测] |

> 台账另记"同期隔壁库新增两条治理类根因（纸面防线／评测集边界）"，是盲审发现的系统性根因沉淀——两个库互相喂料：坑的类型进本库，失职的行为进死法库。

## 第 10 章 失效与恢复：它自己会怎么坏

### 10.1 坏法一：库不生长（最致命）

| 项 | 内容 |
|---|---|
| 怎么坏 | 第 5 步被跳过：审得很爽、报告发出去、库里还是 58 题 |
| 怎么发现 | 台账无新增节；或题库头部计数连续多轮不变 |
| 后果 | 同一个坑第二次照样踩，本支价值归零 |
| 怎么退 | 立刻补写：本轮已裁决而库里没有的中招项按条目格式追加，台账记增量 |
| 依据 | Q50（元问题）+『沉淀纪律』[实测] |

### 10.2 坏法二：讨好式过堂

表现为 ✓ 明显偏多、中招全是"细节"级、修法写成"建议再考虑"。
[推演] 怎么暴露：同一份计划换个不相干的评审方再审，若它挖出的致命项这边全打了 ✓，即讨好实锤。
退法：把 E 类与 Q57 设为强制实抽项——"实抽 3 张卡"这个动作没有可糊弄空间。

### 10.3 坏法三：附属件与正文脱节（已实际发生）

| 现象 | 形状 | 危害 |
|---|---|---|
| 临时件混进 references | `L01 \|` 前缀的题库头部转储 | 按目录遍历读题会读到带伪行号的旧快照，与真库勾稽不上 |
| 入口层旧计数 | 『何时读问题库』仍写"10 类 50 题起步" | 照此只过 A~J，K~N 整段被漏 |
| 报告骨架旧类目 | 仍写"A~J 十类 × 三态" | 照骨架产出的报告天生缺 8 题 |
| 版本戳未 bump | frontmatter `v1.0`，而『版本』节与台账记着 v1.1 的改动 | 按 frontmatter 取版本会低估一级 |

这四条都是"只增不删"的代价：**库在长，入口层的引用文本不会自动跟着长**。发现靠第 11 章的勾稽自检，修法记在 15.3（本页不改权威库）。

## 第 11 章 例行体检：怎么验证它真在生效

这一支没有运行时，"体检"＝**审这套流程自己有没有被照做**。每轮审判后 5 分钟，或每季度一次：

| # | 检查项 | 判据 | 不合格怎么办 |
|---|---|---|---|
| 1 | 题数单调增 | 题库头部计数 ≥ 上次记录值 | 相等→追问本轮是否漏沉淀 |
| 2 | 计数勾稽 | 数行首 `- **Q` 的行数 == 头部声明题数 | 不等→以实数为准并改头部行 |

| 4 | 四要素齐 | 抽 5 题看问什么／为何是坑／何时爆／怎么查 | 缺"怎么查"＝不可执行判据，当场补 |

## 第 12 章 端到端走查：一份计划从输入到闭环

下面这条送审件是为讲透流程**构造**的示例（不含任何真实项目身份，整章标 [推演]），但形状与真实送审件一致，可照抄套用。

### 12.1 输入（逐字）

```
《自动周报计划》v1（待审）
1. 每天 18:00 起定时脚本抓取 3 个来源，写入统一数据文件；
2. 大模型按模板生成周报，直接发布到共享文档；
3. 铁则：每一环断了都不影响上一环；
4. 验收：两周内出现 3 次"采纳"即算成功；预计工时 1 小时；
5. 兜底：脚本报错时由助手凭记忆补记；
6. 抓取凭据写进脚本里，方便改。
```

### 12.2 第 1 步：拆要素

承诺＝第 3 条口号；机制＝第 1／2／5／6 条（定时抓取·生成直发·凭记忆补记·凭据入脚本）；验收＝第 4 条（两周内 3 次采纳；工时 1 小时）。

### 12.6 第 5 步：沉淀回库

"时间语义未声明"库里没有，按条目格式追加：

# 《自动周报计划》审判报告（第 1 轮）

## 第 15 章 工程与安全规范

### 15.1 命名、字段与格式

- 目录名＝中文可读名；frontmatter `name` 字段＝`plan-review`（机器名，短横线小写）。
- description 字段 274 字符／702 字节（数法：取 `description:` 行去键名后按 `wc` 计）。
- 上限口径**三值并存不许合一**：1,024＝开放标准与上传校验／1,536＝某宿主常驻清单截断／200＝某帮助中心上传口径。按前两值未超，按 200 已超，但**未逐宿主核实实现**，故本页只标注事实不判违规。
- 题库条目格式：`**Qxx｜问题？** 为何是坑 ▸ 爆：何时爆 ▸ 查：怎么查 ▸ 案例：出处`。▸ 是固定字段序标记，缺任一要素即视为不可执行判据；`retired` 是行内标记，不删行不改号。
- 引用规则：文件名 + 章节名／规则名／题号，禁行号。

### 15.2 版本与台账分工

版本号只写在入口层『版本』节与 frontmatter；题库与流程的改动记 `CHANGELOG.md`，每节写三件事：优化了什么／新增了什么／解决了什么问题（台账开头即声明遵循此铁律）。

### 15.3 陈旧计数与版本漂移（诚实留档，不代改）
