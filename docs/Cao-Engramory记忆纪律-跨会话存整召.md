## 一句话

文件化长期记忆"**存 · 整 · 召 · 指**"四支柱的初代完整实现，自带 recall/organize/check/doctor 脚本全家桶——记忆纪律 v3.2 的前身与设计源头。

## 它当年解决什么问题（现在由 v3.2 继承）

- 长期记忆越滚越大，每轮全量加载撑爆上下文 → **索引只存指针、详情懒加载**；
- 记忆存了但召不回 → **排序召回 top-K**，按类型亲和/关键词/时效打分；
- 记忆只增不清 → **整理协议**：去重、冷记忆归档、压索引、修断链；
- 全局记忆和项目记忆混放 → **分层架构**：跨项目的进全局 store，仅本项目的随目录走。

## 它仍有的独特价值

- **脚本全家桶**（v3.2 只保留了维护脚本）：`engramory_recall.py`（自动排序召回）、`engramory_organize.py`（半自动整理，默认 dry-run）、`engramory_check.py`（索引上限校验）、`engramory_doctor.py`（全量体检含断链/符号链接逃逸）；
- **多 Agent 共享同一份记忆**的架构设计（含冲突处理原则）——v3.2 走的是"规则共享、store 分家"路线，若你想要"多 Agent 共读写一份记忆"，这里的 §7 仍有参考价值；
- **密钥铁律**的原始表述：绝不写密钥值，只记"它在哪"。

## 和继任者（v3.2）的对比

| 维度 | Engramory v1.0 | 记忆纪律 v3.2 |
|---|---|---|
| 定位 | 存储层四支柱 | 全生命周期（存+评分+衰减+升华） |
| 评分体系 | 无（按相关度排序） | V/R 评分公式 + 排序分 |
| 记忆淘汰 | 归档不删 | 衰减结算 + ≥3 次升华铁律 |
| 脚本 | 全家桶（recall/organize/check/doctor） | memory_maintain.py（check/decay） |
| 推荐度 | 历史参考 | ✅ 新用户首选 |
