# Cao-Engramory记忆纪律（engramory-discipline v1.0）

> [← 返回总目录](../README.md#skills-index)

> ⚠️ **本 skill 已被「记忆纪律 v3.2」取代**，存储层已并入新版。这里保留的是设计原型与可复用的思路，**新项目请直接装 v3.2**。

## 一句话

把 AI 长期记忆做成文件化、可检索、可审计，而且不撑爆上下文的知识库。四根柱子：存得对、理得清、召得准、指得省。

## 它解决什么问题

- **记忆全堆一个文件。** 攒到几百条，每轮对话开头都得整份加载，成本随体量线性上涨。
- **越积越乱。** 重复的、过时的、指向已经删掉文件的指针混在一起，召回质量一路下滑。
- **召回靠猜关键词。** 想不起来当时怎么描述的，就找不到。
- **密钥被写进记忆。** 一旦记忆库泄露或者被同步出去，等于把钥匙一起送出去。

## 核心机制

**索引与正文分离。** `MEMORY.md` 是索引，**只存指针不存正文**，每轮唯一必读的文件。真正的详情拆成 `memory/<type>/<slug>.md`，一条记忆一个文件。

**指针召回协议。** 每轮只做三件事：读索引（成本恒定，≤200 行）→ 按"类型亲和 > 关键词重合 > 时效性"给指针打分，取前 3~5 → 只懒加载命中的那几个文件。**绝不批量打开全部。**

**写入纪律。** 写之前先确认：不在代码、不在 git、不是密钥值。然后检索索引，能更新旧笔记就更新，否则新建。反馈类和项目类的记忆**必须带 `Why:` 和 `How to apply:`**——这是记忆能被正确复用的关键。

**整理协议。** 触发时机是索引用量超限、周期性、或项目收尾。四步：去重合并、归档冷记忆（移到 `archive/` 而不是物理删除，防误伤）、压缩索引行数、修断链。

**密钥铁律。** 绝不把密钥、令牌、密码、Cookie 的值写进记忆，**只记它在哪**。

**索引有硬上限。** 软上限 150 行 / 20KB，硬上限 200 行 / 25KB。超了先压缩再写。改完跑一遍校验脚本。

**分层。** 跨项目通用的进全局 store，只属于当前项目的进项目 store，两者绝不互相污染。项目收尾时把能泛化的提炼进全局，其余随目录一起丢。

**四个配套脚本。** `recall` 排序召回、`organize` 整理归档（默认 dry-run）、`check` 索引大小校验、`doctor` 全量体检（查重复、过时、超大、断链、符号链接逃逸）。

## 一条设计上很值钱的规则

密钥只记位置、不记值。

这条看起来小题大做，实际是整个记忆体系能不能长期活下去的关键。记忆库是要被反复读取、可能被同步、可能被打包分享的东西。只要有一条把真钥匙写进去了，后面所有"共享记忆""多 agent 同步"的设计全部作废——你不敢共享了。

所以定死：**记忆里只出现"密钥在 X 文件里"这种话，永远不出现密钥本身。**

## 和同类方案比，差在哪

| 常见做法 | 本 skill |
|---|---|
| 记忆堆一个文件，全量加载 | 索引只存指针，详情懒加载，成本恒定 |
| 越积越乱 | 定期整理：去重、归档、压索引、修断链 |
| 召回靠关键词硬碰 | 三维打分排序，取 top-K |
| 只记结论 | 反馈/项目类强制带 Why 与 How to apply |
| 密钥写进记忆 | 铁律：只记位置，不记值 |
| 索引无限膨胀 | 软硬双上限 + 校验脚本 |
| 全局项目混杂 | 分层存储，互不污染 |

## 3 分钟上手

1. 把文件夹放进 skills 目录（见[总目录](../README.md#skills-index)）；
2. 在记忆根目录建 `MEMORY.md` 和 `memory/` 目录（含 feedback / project / user / reference 四类）；
3. 四个脚本按需调用：召回、整理、校验、体检；
4. **但更推荐直接装 v3.2**——它把这套存储层和评分层合并了，功能更完整。
