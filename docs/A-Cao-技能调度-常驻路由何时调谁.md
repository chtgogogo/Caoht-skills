# A-Cao-技能调度（useskill v2.4）

> [← 返回总目录](../README.md#skills-index)

## 先看一组数据

给 AI 装上 20 个 skill 之后，三个月里它真正调用过几个？

答案是：翻来覆去那三四个。你精心挑回来装好的那些，绝大多数一次都没被翻开过——不是没用，是 AI **想不起来它们存在**。它凭印象挑工具：哪个名字眼熟用哪个，哪个最近用过用哪个。你库里那个明明更对口的 skill，从生到死没被检索过一次。

这个 skill 干的事就一件：**把"该用哪个 skill"从玄学变成一台固定状态机。**

## 你现在的做法，卡在哪

没有调度器时，一次"帮我做个前端页面"大概会这样发生：

1. 模型扫一眼记忆里的 skill 名字，挑了个名字最像的；
2. 你库里其实有 3 个前端相关 skill——设计规范、组件库、可用性清单——它一个都没碰；
3. 你说"按前端设计的理念来做"，它以为你说的是刚才那个，继续跑；
4. 做完你问"为什么没用那个可用性清单？"——它答不上来，因为它根本不记得库里有。

更隐蔽的失败是**一次消息里的多个指称只消费一个**。你点名了一个 skill，又顺带说了句"参考 XX 的理念"——模型命中第一个就开跑，后半句直接蒸发。你以为是它理解了，其实是它没看见。

## 状态机怎么走

**State 0 · 引用清点（v2.3 新增，硬性前置）。** 开工前先把用户这句话里所有的 skill 指称列成清单——显式路径、点名 name、泛指能力词三类——逐一标注归宿，禁止命中第一个就跳过剩下的。这条规则是被一次真实事故逼出来的（见下）。

**State 1 · 点名直连。** 有明确路径或 name 的，直接读 SKILL.md 执行，不绕路。

**State 2 · 本地检索。** 泛指词走映射表，按中文文件夹名前缀匹配。用户说"前端设计"，映射表一查即中——成本接近零，不用扫全库。

**State 2-EX · 穷举模式（v2.4 新增）。** 你说"全面调用""尽可能用"，它就全库扫描：一次 IO 读全映射表，相关的全挑出来，宁多勿少，按任务阶段排序执行。

**State 3 · 市场兜底。** 本地没有就去 GitHub 找，找到先过安全审计再装；真找不到就明说，不硬凑。

每次调度结束强制输出**调度报告**：候选了哪些、纳入谁、排除谁、为什么。你能逐条复核它这趟脑子是怎么走的。

## 那次漏触发事故

2026-09-11，一个前端风格任务。用户的消息里既有明确点名的 skill，也夹着一句「按前端设计 skill 的理念」。调度命中了点名那个就直接开跑——把后半句当成了同一个东西。库内另外三个前端 skill 一个没触发，用户当场质问。

这次事故直接催生了 State 0，规则里现在的原话是：**State 1 命中只消费一个显式引用，禁止因已命中而跳过对剩余泛指引用的解析。**

一个月后加的穷举模式，起因同样是真实使用——有人问"能不能把相关的 skill 都挑出来"，原来的状态机压根没有这个入口。

## 和"让 AI 自己挑"比，差在哪

| 你现在的做法 | 这套调度 |
|---|---|
| 靠模型印象自动挑，装 20 个用 3 个 | 固定状态机：清点 → 直连 → 检索 → 兜底，每步有据 |
| 命中一个引用就开跑，后半句蒸发 | 一条消息多个指称逐一清点，禁止快路径惯性 |
| 泛指词靠语义猜，猜错就漏 | 映射表按中文文件夹名前缀匹配，一次命中 |
| 调完不吭声，无法复核 | 强制调度报告：候选/纳入/排除理由全列出 |
| 用没用过没记录 | 统计调用次数与最近调用，能回答"哪些 skill 在吃灰" |
| 中文文件夹名 vs 英文调用键对不上 | 双轨制：文件夹用中文说明书名，name 字段是稳定英文键 |

## 什么情况别用

- 纯打招呼、闲聊、单行知识问答——这类任务短路直连，不触发调度，也不该触发；
- 库里只有一两个 skill——调度收益抵不过流程本身，直接说名字更干净。

## 实战绩

2026 年 7 月起在真实项目跑了三个月，v1.0 迭代到 v2.4，库内 skill 上百个。漏触发事故、穷举模式，全部来自实际使用的真实诉求。v2.4 规则同时维护在多宿主副本上，逐字一致。
