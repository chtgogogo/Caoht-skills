# A-Cao-技能调度（useskill v2.1）

> [← 返回总目录](../README.md#skills-index)

## 一句话

给装了一堆 skill 的 Agent 配一个**唯一调度入口**：让每次"该调哪个 skill"从碰运气变成可路由、可降级、可审计的标准流程。

## 它解决什么问题

- skill 装了五六个之后，Agent 经常**想不起来用**，或者**该用 A 却用了 B**；
- 用户说"调用那个微信的 skill"，Agent 不知道"微信的"对应哪个文件夹；
- skill 执行出错时 Agent 要么死循环重试，要么静默装作成功；
- 调用了什么、为什么调用，用户完全看不见，无法审计。

## 核心机制

- **三态状态机**：点名直连（已知名字快路径）→ 本地语义检索（映射表 O(1) 直达 + 目录扫描兜底）→ 市场兜底（本地没有就去找）；
- **按 `name` 字段定位本体**，不依赖文件夹名——文件夹是给人看的中文说明书名，调用键永远稳定；
- **异常三级降级**：参数修正重试 → 同级换备选 → 硬终止上报，绝不静默掩盖；
- **强制透明报告**：每次调度在回复末尾输出标准块（调用了谁/触发原因/检索路径/有无降级）；
- **调用统计**：自动维护 `__usage_stats.md`，谁最常用一目了然。

## 和同类方案比，差在哪

| 常见做法 | 问题 | 本 skill |
|---|---|---|
| 靠 Agent 自觉"想起来" | 触发靠运气，长对话后遗忘 | 常驻规则 + 明确触发条件，不靠记性 |
| 每个 skill 各写一套触发逻辑 | 规则互相打架 | 唯一入口统一路由 |
| 调用失败就硬重试 | 死循环或假成功 | 三级降级 + 强制上报 |

## 3 分钟上手

1. 把 `A-Cao-技能调度-常驻路由何时调谁/` 整个文件夹复制进你所用 Agent 的 skills 目录（目录怎么找见 [总目录的安装说明](../README.md#skills-index)）；
2. 新开会话说一句"调用/使用 skill"验证生效；
3. 之后所有 skill 调用都会走它，每次回复末尾会有调度报告。

## 实战绩

在 ZCode / WorkBuddy / Codex 等多宿主常驻运行，本仓库多次会话（含 skill 评审、跨库检索）均由它完成路由。

## 适用 / 不适用

- ✅ 装了 ≥3 个 skill、经常记不住该用哪个的环境；
- ✅ 需要"调用行为可审计"的团队场景；
- ❌ 只有一两个 skill、任务类型单一——纯属多余。
