# Cao-提取抖音记录（douyin-chat-export v1.0）

> [← 返回总目录](../README.md#skills-index)

## 一句话

把抖音网页版的私信导出成按天 Markdown，清洗规则和微信导出版本完全一致。

## 它解决什么问题

- **私信没有导出功能。** 记录只存在客户端里，客户端没了记录就没了。
- **语音消息无法检索。** 一样的问题：说过的信息，文字搜不到。
- **备份格式各搞各的。** 从不同工具导出来的东西，说话人标记、引用格式、表情写法全不一样，没法合并看。

## 核心机制

**网页版本地采集。** 用 Playwright 驱动浏览器在本地跑，浏览器内核放在非系统盘。不依赖任何第三方服务。

**语音转文字走官方接口。** 免费、不需要本地模型、结果自动转成简体。这一点和微信版不同——微信版是本地跑 Whisper，抖音版直接用官方接口，省掉了模型下载和推理开销。

**清洗规则与微信版对齐。** 这一条是整个设计里最实用的部分。两个 skill 输出的说话人标记、引用格式、表情与图片写法完全一致，所以从微信和抖音导出来的记录可以用同一套方式处理。

**增量更新。** 同样靠 `_export_state.json`，只有某天数据变了才重写当天。

**一键 bat。** 双击 `导出.bat`，自动补语音转写、清洗、按天生成、打开输出文件夹。

## 清洗规则长什么样

这是最能说明问题的一段。原始数据里混着各种富文本，导出后变成这样：

| 原始内容 | 导出结果 |
|---|---|
| 我发的消息 | 说话人标 **B** |
| 对方发的消息 | 说话人标 **A** |
| 引用某条消息后回复 | `引用【A：原话】 回复` |
| 有名字的表情 | `[表情名字]` |
| 没有名字的表情 | `[表情]` |
| 图片 | `[图片]` |
| 语音 | `[语音 12秒] 转写出来的文字` |
| 视频 | `[视频 30秒]` |
| 分享的视频 | `[分享视频] 有效标题`（去掉 #话题、@提及、作者、链接） |
| 系统提示 | 跳过 |
| 转发的聊天记录 | 展开 |

关键是最后两行。系统消息直接跳过，不让"对方撤回了一条消息"这种噪音污染归档；转发的聊天记录会展开，而不是像大多数导出工具那样只留一句 `[聊天记录]`。

分享视频那条也做了取舍：保留有效标题，剥掉话题标签、@提及、作者名和链接——因为那些在归档语境下是噪音，标题才是你要找的东西。

## 登录态与隐私

- 登录态（Cookie）存在 `data/browser_profile`，**不能提交到 git、网盘或任何公开位置**；
- 登录态会过期，失效后跑一次 `login.py` 扫码重新登录；
- 只处理用户自己的账号。

## 和同类方案比，差在哪

| 常见做法 | 本 skill |
|---|---|
| 云端工具处理私信 | 本地运行，登录态和内容不出机器 |
| 语音消息丢失 | 官方接口转写，带时长标记 |
| 系统消息混进归档 | 自动跳过 |
| 转发记录只剩一句"[聊天记录]" | 展开完整内容 |
| 分享视频留一堆话题标签 | 只留有效标题，剥掉噪音 |
| 和微信导出格式不兼容 | 清洗规则完全对齐，可并排处理 |
| 每次全量重导 | 增量更新 |

## 3 分钟上手

1. 把文件夹放进 skills 目录（见[总目录](../README.md#skills-index)）；
2. 首次搭建：建虚拟环境装依赖 → 安装 Playwright 浏览器内核（放非系统盘）→ `python login.py` 扫码登录 → `python extract.py --incremental` 增量采集；
3. 日常使用：双击 `导出.bat`，完成后自动打开输出文件夹；
4. 输出在 `<输出目录>/抖音聊天记录_与A/YYYY-MM-DD.md`，另有 `索引.md` 和增量状态文件。

## 实战绩

采集、转写、清洗、增量更新整条链路已跑通，清洗规则直接沿用了微信版本那一套（改的是数据源适配，不是格式设计），所以两边的产物天然能放在一起。

upstream 的采集能力经过验证，本 skill 主要在清洗和自动化上做了加强。

## 适用 / 不适用

- ✅ 备份自己账号的抖音私信；需要和微信导出记录统一格式归档的场景
- ❌ 他人账号的数据；聊天内容分析（那是分析类 skill 的事）
