# A-Cao-磁盘缓存纪律（disk-cache-discipline v1.0）

> [← 返回总目录](../README.md#skills-index)

## 五分钟速览

1. 它是**环境层**的纪律，管「东西写哪个盘」。下载、克隆、虚拟环境、模型权重、缓存，一律写非系统盘，严禁 `C:\Users\<user>\Downloads` 这类默认路径。
2. 原则一句话，动手前先问「这个工具默认写哪」，而不是装完了才发现 C 盘少了 20G。
3. 缓存重定向三件套，pip 设 `PIP_CACHE_DIR`，npm 设 `npm_config_cache`，HuggingFace 下载模型**前**先设 `HF_HOME`，否则权重直接落 C 盘。
4. 遇到强制写 C 盘固定路径的老旧程序，用目录联接（`mklink /J`）转移，程序以为还在 C 盘，实际数据在别的盘。
5. 迁移前必须做**幂等检测**——先查目标路径是不是已经是链接。这是整套流程里最容易出错的一步，重复挪动会出大事。
6. 自带可执行体检脚本 `disk_check.py`，环境变量、可疑大目录、链接指向、盘空间四项全查。

## 它在解决什么问题

| 故障 | 实际发生的形态 | 对应机制 |
|---|---|---|
| C 盘被吃满 | 模型权重、npm 缓存、pip 缓存默默写进 `C:\Users\...\.cache` | 缓存重定向表 + 动手前自查 |
| 系统盘爆满后整机卡死 | 大文件写入前没人查过剩余空间 | 空间预警，不足立即停 |
| 重复迁移出事故 | 同一个目录被挪了两次、或者给链接又套了一层链接 | 幂等检测（§幂等） |
| 规则存在但无人执行 | 铁律只躺在记忆规则目录里，AI 不会自动触发 | 封装为独立 skill + 触发词 |

## 核心机制详解

**缓存重定向。** 每类工具的缓存位置都能用环境变量指走。pip 用 `PIP_CACHE_DIR`（或安装时加 `--cache-dir`），npm/pnpm 用 `npm_config_cache`/`PNPM_HOME`，HuggingFace 用 `HF_HOME`——注意时机，**下载模型之前**就要设好，装完再挪要多搬几十个 G。兜底原则，任何「默认往用户目录 .cache 写」的工具，先查它的缓存环境变量，指到非系统盘。本机统一目录约定，工程进 `<非系统盘>\AI_Projects`，缓存进 `<非系统盘>\AI_Cache`。

**目录联接（Junction）转移术。** 遇到强制写 C 盘固定路径、改不了配置的老旧程序，四步走。停掉占用进程，把已生成数据移到非系统盘，删除 C 盘原目录（必须已空），管理员执行 `mklink /J "C:\原路径" "<非系统盘>\实际路径"`。效果是程序以为还在读写 C 盘，实际数据已经落非系统盘。`mklink /J`（联接）比 `mklink /D`（符号链接）兼容性好，优先用。

**幂等检测，最容易出错的一步。** 迁移或建链接**之前**，先检测当前状态（`dir` 看有没有 `<JUNCTION>` 标记，或 `fsutil reparsepoint query`）。三种状态三种动作：已是链接且指向正确 → **立即停止，绝不重复移动**；是实体目录且占空间 → 才执行移动加建链；是链接但指向错误 → 先删链接（`rmdir`，**不是 `rmdir /s`**，后者会顺着链接把真实数据全删了）再重建。重复挪动、给链接再套链接，都是真实发生过的险情。

**空间预警。** 大规模写入（几十 GB 的模型、数据集）之前先查各盘剩余空间。目标盘不足 → 立即停、报告用户，禁止未确认的跨盘写入。

**体检脚本。** `disk_check.py` 查四件事，关键环境变量是否已重定向、C 盘常见缓存路径是否异常膨胀、已知路径是否为 junction 且指向正确、各盘剩余空间是否低于阈值。`--scan-user` 附带列出 C 盘可疑大目录（只报告，不删）。

## 跟另外三件纪律的边界

| 管什么 | 归属 |
|---|---|
| **东西写哪个盘、缓存怎么重定向** | **本 skill** |
| 代码怎么写 | 编码行为准则 |
| 测试证据长什么样 | 测试纪律 |
| 结论怎么下 | 抗幻觉纪律 |

## 什么时候不用

纯文本推理、不碰文件系统的任务不触发。往内存里写个临时 DataFrame、没落盘的，不管。
