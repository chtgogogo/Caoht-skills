# incidents — 判例史：本 skill 自己踩过的坑（v1.7.0）

以史为鉴。每例：现象／根因／修法／能否借鉴。判据为什么长这样，看这里就够了——别把已经流过血的教训当成装饰。

## 1. 自杀式 CRUD（v1.0–v1.3 期，已修）
- **现象**：每次写索引整文件重写，头部散文数字反复被吞。
- **根因**：把「插入一行」实现成「全文重新排布」，锚点识别漏一处就静默丢一处。
- **修法**：锚点式插入（分组行前插）、写后读回验收（数字对不上就报错回滚）。
- **借鉴**：改文件＝最小面＋读回验收；「重写整个文件」永远比「插一行」危险。

## 2. 恒真判据家族（v1.5.0 流血，v1.7.0 又见一次）
- **现象**：自检长期 PASS，实际缺陷在场——判据写错向（恒真分支永远命中，反向分支永不执行）。
- **根因**：判据只写了「错了报什么」没写「对了长什么样」，报错分支不可达。
- **修法**：判据先正向种出症状、再断言消失；随包 `selftest` 用 30 个断言把每种症状都种一遍。
- **借鉴**：无牙断言比没断言更糟（给假安全感）；判据没有牙齿=自检骗自己。

## 3. 数字三处漂移（v1.4 定案）
- **现象**：索引、根因文件、案例 frontmatter 各写各的，三个「同一数字」三个值。
- **根因**：多视图同数据却没有唯一尺子，缓存各自为政。
- **修法**：事件记录现扫（derive）为唯一尺子，frontmatter 降级为缓存，`check` 只做对账。
- **借鉴**：同一数字出现在 N 个地方，尺子只能有一把，其余全是缓存。

## 4. 命中数字虚高（v1.5.0 定判据）
- **现象**：早期把「读了之后（无因果）后来才解决」也记命中，数字看着繁荣、实际没人救过谁。
- **根因**：判据没定就先记数，指标激励污染了记账动机。
- **修法**：判据收紧为「独立解决之前被看见且有助力」（全文见 calibration.md）。
- **借鉴**：先定判据再谈数字；宁少勿虚，虚高的指标等于没有指标。

## 5. GBK 管道 UnicodeEncodeError（v1.7.0 加固）
- **现象**：Windows 上从管道消费输出时崩在 emoji 上；本机 Python 3.15 靠 PEP 686 才幸免。
- **根因**：入口没显式编码，赌运行时环境（3.8–3.14 默认 GBK 管道必炸）。
- **修法**：stdout/stderr 入口 `reconfigure(encoding="utf-8", errors="replace")`。
- **借鉴**：与外界的环境契约要显式声明，别赌宿主默认值。

## 6. 阈值抄五处漂移（v1.7.0 收敛）
- **现象**：同一对阈值（同根因案例数轴／单条召回轴）在正文、两个模板、口播、脚本各有一份，版本间已经不同步。
- **根因**：常量抄两处就有两处漂移点，抄五处=五个漂移点。
- **修法**：脚本为唯一权威，模板与正文一律「以工具为准」，不抄数字。
- **借鉴**：常量的家只能有一个。

## 7. 模板与脚本常量不同源（v1.7.0 新防）
- **现象**：改了脚本里的段名常量、没改随包模板，`check R7` 从此按另一套形状检查条目，条目怎么看都不合规。
- **根因**：双源（脚本常量 ↔ 模板）没有对账机制，改一半没人报警。
- **修法**：`check --deep` 新增 R15 跨工件对账（selftest A27/A28 双向验证）。
- **借鉴**：凡是「两处必须一致」契约，要么构建期生成、要么运行期对账，必须择一。

## 8. `py` 启动器不通用（v1.7.0 统一）
- **现象**：跨机器/跨 agent 环境下 `py` 不存在（或指向别的解释器）导致第一行命令就失败。
- **根因**：把本机别名当成了通用写法写进正文。
- **修法**：正文统一 `python`；本机别名等事实降级进 `personal.local.md`。
- **借鉴**：正文写通用名，本机差异进 local 文件——顺序反了就传染。

## 9. 目录名 ≠ `name:`（v1.7.0 登记，不修）
- **现象**：规范要求 frontmatter `name` 与挂载目录名一致；本库挂载键 `pitfall-log`、权威库目录名是本机中文命名。
- **结论**：挂载键与判据键不改（宿主巡检靠它们）；本机目录名属于本机命名规则，发布映射已在 publish_map 第七节统一为英文目录。
- **借鉴**：命名冲突能用发布映射解决的，用映射解决；正文如实登记偏差，不隐瞒、不硬改。

## 10. 候选提升漏根因背书（v1.7.0 selftest 抓出）
- **现象**：按根因攒条数升上来的候选，来源行只列案例 ID ⇒ `promote --apply` 后根因本体没置 `escalated`、根因表没加 ⭐（v1.6.0 口径是两处加星）。
- **根因**：把「RT 号会出现在来源文案里」当成了隐性约定，而它只对「案例命中轴」的候选成立。
- **修法**：候选编号自带确定性 RT 号，`apply` 时补进来源再走统一逻辑（A16 断言守住）。
- **借鉴**：能从确定性形状推导的字段，别依赖文案种入——文案是可变的，形状不是。

## 11. 提前关管道饿死子进程（判据 Family 外溢案例）
- **现象**：外层壳用 `Select-Object -First N` 截取输出，子进程往满管道写时收到 BrokenPipe，退出码非 0，被误判「工具坏了」。
- **根因**：流式截断的宿主行为与子进程全量输出假设不兼容。
- **修法**：消费端先整段捕获（`Out-String`）再过滤；工具端 `errors="replace"` 减少 UI 链路炸点。
- **借鉴**：工具兼容宿主怪癖到「不崩」为止；超出部分写进文档教消费者，不瞎猜库。

## 12. 共享库无版本史（v1.7.0 发现的现役缺口）
- **现象**：log-root 在 git 覆盖之外，回滚依赖单代 `.bak`，一次误写可能永久丢史。
- **根因**：「有备份」被当成了「有历史」。备份只有最后一瞬，历史是每一瞬。
- **修法**：`check` R13 给警＋指引（git init 或挪进已跟踪仓）；误写当场可回退，但**事后审计**与「谁改的」只有 git 能回答。
- **借鉴**：`.bak` 是创可贴，git 是病历本；共享库必须有一个。
