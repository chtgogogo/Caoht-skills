# calibration — 指标口径全表（v1.7.0）

给需要解释「这个数怎么算的」的人，以及要写第三方解析器对接本库的开发者。正文 SKILL.md 只保留判据摘要，这里是全文与唯一出处。

## 三个数字，一把尺子

| 数字 | 定义 | 唯一尺子 |
|---|---|---|
| 案例总数 | `pitfalls/` 在场案例文件数（递归扫，但 `archive/`、`_candidates/`、`_template*.md` 不算） | 文件系统现扫 |
| 命中数 | 「命中记录」表行数（案例层的单列表 ＋ 根因层的场景表），含各自表内去重 | 表行现扫 |
| 挂载数 | 主挂 `root:` ＋ 副挂 `also_root:` 的面数 | frontmatter 现扫 |

铁则：**frontmatter 里的 `cases:`/`hits:` 不是尺子，是缓存**。索引里的数字、根因文件头部自述、案例 frontmatter，全部是同一现扫的缓存视图；`check` 的工作就是把所有缓存视图跟现扫对账（R1–R4、R6、R9）。手填的数字要么跟现扫对得上（那就不必填），要么对不上（那就是填错了）——一律视为可疑。

## 事件记录（幂等的物理基础）

每条案例正文末尾有一行：

```
<!-- pitfall-event: YYYY-MM-DD-slug | fp: 8 位十六进制 -->
```

- 事件 ID＝`日期-slug`，日期取**事件发生当天**（不是记录当天），同一事件全局唯一。
- 指纹 `fp = sha1(date | norm_text(scenario))` 截 8 位：同一次命中的重复提交（同场景又报一次）靠它去重成 no-op；换日期或换场景＝新命中。
- 缺这行的历史条目：现状扫仍能计数（R5 只给警），但对重复提交无幂等保护——新条目必须带，历史条目可补。

## 命中判据（全文版）

**算命中**——问题被独立解决**之前**，记录被看见、且对解决产生实际助力：
- 主动检索 → 找到根因/案例 → 照对策修好；
- 干活途中撞见（比如翻别的库时瞥到）→ 关键提示直接立项会决策；
- 只读根因层、一条通用对策就解决：根因层 +1，案例层不加（没读案例就别虚报）。

**不算命中**：
- 解决完才翻库发现已有记录＝纯归类，加不加都行但**不能算**；
- 读了、但与决策无关（看了没影响）；
- 同一问题在同一情境内的重复看见（同指纹去重）；
- 为了让数字好看而记（判据宁少勿虚）。

**根因层命中**（`hit --root-cause RT-0NN`）：适用于「只看根因层的识别信号＋通用对策就解决、没读下挂案例」的命中；与案例层命中分开记、各 +1，`hit --case` 与 `hit --root-cause` 互斥。

看见的方式不限（主动检索、顺手撞见都算）；判据核心是**因果要件**，不是「碰过就算」。

## check 规则全表（R1–R15）

| 规则 | 级别 | 语义 |
|---|---|---|
| R1 案例无索引行 | 红 | 文件在场、索引缺行（登记一半） |
| R2 索引行指向缺失文件 | 红 | 检索会落到死链 |
| R3 数字/形状漂移 | 红 | 索引案例数、行尾 🔥、根因表数字跟现扫不符；**行尾形状不认识时报错不猜** |
| R4 根因文件 cases/hits 漂移 | 红 | 根因文件头部缓存 ≠ 现扫（hits＝本文件记录＋下挂案例命中） |
| R5 无事件标记 / 同事件重复登记 | 警 / 红 | 缺幂等标记；同一指纹出现多个文件要人裁决 |
| R6 案例 hits 与记录表不符 | 红 | frontmatter 缓存 ≠ 表行数 |
| R7 缺段 / 🔴 用 lite | 警 / 红 | `kind: legacy` 自动豁免（旧条目不追改）；🔴 不可再生损失必须八段 |
| R8 根因编号空缺 | 警 | RT-0NN 断档要写明理由（空号暗示「有东西被抹了」） |
| R9 头部自述漂移 | 警 | 索引头部散文数字 ≠ 现扫（`counts --prose` 可刷） |
| R10 根因表链接断 | 红 | 表行没链到 roots/ 本体、链接与号不符、分组无本体（凭空立族） |
| R11 案例数超界 | 警 | pitfalls/ 超过脚本上限 ⇒ 该退役冷条目了，索引别养成第二个全文 |
| R12 根因缺 YAML 头 | 警 | cases/hits 刷不进去（rewrite 只报不改） |
| R13 无版本史 | 警 | log-root 不在 git 仓内 ／ 索引未被跟踪 ⇒ 回滚只剩单代 .bak |
| R14 复核逾约 | 红 | 已提升候选缺「下次复核日期」／日期非法／**已过期** ⇒ 重验或降级 |
| R15 模板漂移 | 红 | 库内模板或随包 assets 模板与脚本段名常量不同源（仅 `check --deep` 查） |

退出码：绿 0；红至少一条 → 1（行为变化是显式的，不吞不猜）。

## 第三方解析器对接须知

1. 以现扫为准，别信 frontmatter 缓存（那是为了人读快，不保证同步瞬间的正确）。
2. 事件标记是幂等的唯一判据；解析时**原样保留**该注释行，别当垃圾剥掉。
3. 行尾形状解析失败要**报错**，不要「猜」——工具自己也这么守（R3）。
4. 阈值等常量别硬编码进你的解析器：从 `scripts/pitfall_log.py` 读或 prompt 用户，脚本才是唯一权威。
5. `archive/` 与 `_candidates/` 不属于现扫面；把它们当「待裁决区」而非「在册区」。
