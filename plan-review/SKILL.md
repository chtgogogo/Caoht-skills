# 评审计划（plan-review）——计划审判问题库

> 一句话：拿着审判问题库，**按本次项目的画像选题**过堂还没动工的计划，把麻烦在开工前挖出来，并给出「可开工／附条件开工／暂缓」三态结论之一。
>
> **库只增不删，但新题先落候选区**：每次审判发现的新问题类型必须沉淀——**先 `add` 进候选区，验证过适用范围才 `promote` 进正式库**。审完不沉淀=本次审判只值一半；审完直接往正式库里塞没验证的题=把库变成垃圾场（塞之前先想清楚：这道题对哪类计划才成立？）。

## 审判流程（六步，选题制不是全库遍历）

1. **定画像 + 选题**：先说清被审计划是什么类型（新建／存量／对外／常驻／一次性）带哪些特征（AI 自动动作、量化承诺、外部依赖……），再跑
   `py scripts/qbank.py select --type 新建 --trait AI自动动作 --trait 量化承诺`
   （没画像就 `select --profile 通用`＝只取核心题，用于小计划快速过堂）。输出会打印**命中数／总数／跳过数**和每条的**入选原因**——把这三行抄进报告当选题依据。**不再要求逐条遍历全库**：库越长越要按画像取题，否则审判成本压垮审判本身。
2. **通读+要素清单**：把计划里全部「承诺（铁则/口号）／机制（怎么运转）／验收（怎么算成）」列成一张表——每道题都对着这三类要素问。
3. **逐题判定三态**（对选出来的题，不欠没选的）：
   - ✗ **中招**：引计划原文为证 + 何时会爆 + 修法建议
   - ? **存疑**：信息不足，列出要问谁、要实测什么（两项都写，缺一项 `gate` 判红）
   - ✓ **通过**：一句话理由
   **验收与度量类（E 类）过堂时，验收标准的证据形态遵循 `A-Cao-测试纪律`**（原始输出落盘/改前改后各跑/口径标注/禁只报总结数字）——计划里的"测试全绿""效果良好"若无证据形态，按中招处理。
   不讨好：批语对事不对人但绝不放过；被审方反驳就进入交锋，谁有理听谁的，裁决过程全部留痕。
4. **分级聚焦**：中招项分 致命/重要/细节 三级；报告结尾只保留**最致命 ≤3 条**。
5. **出三态结论 + 走出口**（本 skill 的收口动作，见下一节）：结论取 **可开工／附条件开工／暂缓** 之一，逐条阻塞项给出处置。
6. **复审闭环 + 沉淀**：修订后对上轮阻塞项逐条销账（`处置=已解除` 必须附解除证据）；**轮次上限 3**——第 3 轮仍有未解除项只能改判「暂缓」并写重启条件，不许开第 4 轮靠加题续命。新题按 `add` 进候选区；典型单点坑另按其流程沉淀踩坑日志（pitfall-log）。

## 三态结论与两类合法出口（治"全绿才结束"的死循环）

「全绿才算过堂」遇到**外部条件没到位**和**可以接受的风险**只会得出两种坏结果：要么永远开不了工，要么假装全绿。所以每条未解除的阻塞项必须走通一个出口，字段不齐 `gate` 判红：

| 处置 | 含义 | 必填件 |
|---|---|---|
| `未解除` | 真阻塞 | 解除条件 + 责任方 + 时机／期限 + 验证方式 |
| `已解除` | 复审销账 | 上面四件 + **解除证据** |
| `外待` | **外部条件未满足**（等材料／等别人／等额度） | 上面四件 + **等待对象** + **超时后动作** |
| `残险` | **可接受残余风险**（不修了，但要说破） | 上面四件 + **为什么可接受** + **爆炸半径上限** + **发现机制** + **复核日期(YYYY-MM-DD)** |

- **可开工**＝没有阻塞项，或全部 `已解除` 且有证据。
- **附条件开工**＝每条未解除项都走通了合法出口（`外待`／`残险`），件齐，且轮次 ≤ 3。
- **暂缓**＝有阻塞项给不出解除条件，或轮次已超上限——**暂缓必须写重启条件**，否则只是搁置。
- `残险` 那一栏是硬要求：**接受风险不等于看不见风险**，爆炸半径和复核日期缺一即判红；`复核日期` 必须是绝对日期，写"下个月看"三个月后没人解得开。

## 候选区闸门（新题的唯一入口）

- `py scripts/qbank.py add --title … --why … --boom … --check … [--case …] [--type … --trait …] [--personal]`
  → 要素不齐直接拒；**去重闸**先比对问题句指纹（同指纹＝拦下），近似题带「重影待裁决」注记，人工裁决前不许 promote；同题重复提交＝幂等 no-op。
- `py scripts/qbank.py promote --id Cx --cat B --scope "哪类计划需要它、在哪个真实场景验证过"`
  → **必须给验证过的适用范围才分配正式 Q 号**（当前最大号+1，禁止手写、禁止沿用记忆里的旧号）；候选题的 `特征=无` 是占位，promote 时必须用 `--trait` 给验证结果——确认任何计划都要问的才允许标核心。
- 候选题**不参与 select、不进报告模板、不算进正式库容量**，所以在候选区长期躺着不是缺陷，直接塞进正式库才是。

## 生成物纪律（类别清单与报告模板都从条目现扫）

- `py scripts/qbank.py render --apply` 从条目现扫生成四处：题库里的容量块与目录、本文件的容量块、`_题库索引.md`、`审判报告模板.md`。**retired 题自动排除在目录／索引第二节／模板类别行之外**（编号与原文留在库里，防历史引用失效）。
- **散文里再手写第二处数字＝`check` 判红**，写对了也红：第二个数字本身就是下一个漂移点（卡16 同型坑）。历史数字留在 CHANGELOG.md（证词层，不回改）。
- 每次动过条目或候选区，收尾必跑：`py scripts/qbank.py render --apply` 然后 `py scripts/qbank.py check`（红 0 才算这次改动闭合）。
- 报告填完跑 `py scripts/qbank.py gate <报告文件>` 过机械判据（结论合不合法、出口走没走通、轮次超没超、沉淀有没有偷编正式号），退出码 0 才算这份报告成立。

## 与邻居的分工（三角，别互相顶替）

| 拿到的东西 | 用谁 |
|---|---|
| 还没动工的计划/方案/设计，问"能不能开工" | **本 skill**（审计划的自洽与漏洞，产出三态结论） |
| 计划里那条**验收标准本身**好不好（是不是恒真／恒红／没区分度） | acceptance-criterion-audit（判据鉴别力审查，审一条判据，不审整份计划） |
| 已经建成的项目要交付验收（东西做出来了没） | project-acceptance（项目验收官，审交付物，不看计划文本） |
| 写好的代码要审 | coding-behavior / senior-engineer-playbook 模板② |
| 要盘问的是"计划作者本人"（访谈式） | grill-me（深度追问审查；开场自动判走 A 纯对话盘问／B 文档锚定盘问） |
| 要给 skill 打分优化 | skill-quality-auditor |

三者关系一句话：**本 skill 审"计划能不能动工"→ 判据审"计划里那条验收能不能用"→ 验收官审"做完的东西能不能交付"**。同一份材料先后过三道门不重复；反过来，用验收官去审未动工的计划＝拿尺子量错了对象。

## 可靠性主张四问（最锋利的一组，审任何机制先过这四问）

1. **爆炸半径**：它挂了会怎样？损失上限？（警告：**有界≠可靠**——代价可控不等于不用补强，金库损失有上限仍需要门）
2. **发现机制**：它挂了**谁**、在**哪个必做动作**里会发现？（必须挂进既有 checklist 必做项；"写在文档里/记得去看"=没挂）
3. **兜底自检**：降级链的兜底是不是就是原始病？（兜底="AI 凭记忆手动干"而病根恰是"AI 凭记忆不可靠"→视为未兜底）
4. **档位与前提**：可靠性按用途定档（参考级/榜单级/审计级）；**档位成立的限定条件必须显式写**（典型："只作参考+任何动作必人工确认"；未来若接自动化，必须按高档重评）。碰巧做对的防护要升格为"边界成立的前提条件"，机制会被人优化掉，写进论证的前提不会。

## 沉淀纪律

- 问题库**只增不删**；作废把闸门改成 `状态=retired` 保留编号（防历史引用失效），retired 不进任何输出。
- 每条题必有四要素：问什么 / 为何是坑 / 何时爆 / 怎么查；有真实案例的附来源。缺任一项 `check` 判红。
- **新题编号只能由 `promote` 分配**（读库取当前最大号+1）；报告里出现"本轮新增 Qxx"＝`gate` 判红，因为那是绕过候选区闸门。
- 闸门取值只能来自受控词表（状态／核心／项目类型／计划特征），越界判红——词表扩张是设计变更，要走生成物与体检一起改。
- 版本号只在 SKILL.md 顶层；题库与流程的改动记 CHANGELOG。
