# 抖音聊天记录导出 · 技术原理（本地版）

## 工具来源与运行方式

采集与语音转写复用开源项目 [TeamBreakerr/douyin-chat-export](https://github.com/TeamBreakerr/douyin-chat-export)（MIT），以本地 Python 方式运行（不依赖 Docker），源码在 `D:\AI提炼\抖音聊天记录导出\app`。本 skill 只负责“清洗 + 按天 Markdown”这最后一段。

## 采集原理

抖音网页版私信用虚拟列表，滚动只能加载一部分。该工具直接调用抖音 IM 的 protobuf 接口，用服务端 `created_at_us` 单调序号做游标翻页，突破滚动上限，支持完整历史与增量。

登录态是 Playwright 的持久化浏览器 profile（`data/browser_profile`），内含 httpOnly 的 `sessionid` 等 Cookie。语音识别复用抖音网页版自己的接口（`/aweme/v1/web/im/message/audio/recognition/`），不下载本地模型。

## 本地存储

采集结果在 SQLite `data/chat.db`：

- `users(uid, nickname, avatar_url, unique_id)`
- `conversations(conv_id, name, participant_uids, ...)`
- `messages(msg_id, conv_id, sender_uid, sender_name, content, msg_type, media_url, media_local_path, timestamp, seq, raw_data, ref_msg)`
- `voice_transcriptions(msg_id, message_id, text_result, status, ...)`

`msg_type`：1=文本、2=表情、3=图片、4=分享、5=视频、0=其他（语音/系统/转发）。`raw_data` 里的 `content_json` 是完整消息体，含 `aweType`、`text`、`display_name`、`content_title`、`comment`、`resource_url`、`duration` 等。`ref_msg` 是被引用消息（含 server_id、nickname、refmsg_content）。

## 清洗规则

`dy_to_md.py` 直接读 `chat.db`：

1. 说话人：`sender_uid == owner` → B，否则 → A（owner 从 `conv_id` 的 `0:1:<owner>:<peer>` 解析）。
2. 文本：`#话题`、`@提及` 用正则去掉，空白归一。
3. 表情：有 `display_name` 显示 `[名字]`，否则 `[表情]`。
4. 图片 `[图片]`；视频 `[视频 N秒]`；语音 `[语音 N秒] + 转写文字`。
5. 分享视频（aweType=800）：取 `content_title` 清洗后拼 `[分享视频] 标题`；分享评论（aweType=10500）取 `comment`。
6. 系统消息（tips 模板、火星等）跳过；转发聊天记录（`list_content`）逐条展开。
7. 引用：`ref_msg` 的 `server_id` 映射回原消息拿发送者，拼成 `引用【A/B：原话】 回复`。

## 导出与增量

按 `timestamp` 分组到天，生成 `YYYY-MM-DD.md`；当天第一条显示完整时间，其余只显示时分秒。每个会话文件夹有 `_export_state.json` 记录每天 `{count, max_time, last_id}`，只有变化才重写。

## 一键脚本

`dy_export.py`：检查登录态 → `extract.py --transcribe-voices` 补语音 → `dy_to_md.py` 清洗导出 → 打开输出目录。
