# 踩坑日志（Pitfall Log）· 迭代升级记录

> 记录每个版本做了什么、解决了什么问题、用什么方法解决——看清这个 skill 如何一步步被优化成现在的样子。
> 信息来源：SKILL.md 版本注记 + 工作记忆库（E:\Zcode-memory\WORK）。整理日期：2026-09-18。

## v1.3.0（日期未记录）
- **做了什么**：新增「根因层」——索引改为「根因索引表 + 按根因分组的案例清单」；案例 frontmatter 加 `root` 字段；检索流程改为「先根因、后案例」；命中计数收紧为四条件并明确排除"事后发现同源"；升华增加「同根因案例 ≥3 条」触发；目录结构新增 `roots/`。
- **解决了什么**：同一类问题会在毫不相干的场景反复出现（如"中文编码"这个根因，一次是 PowerShell 脚本乱码、一次是 git 命令误删整个目录），只按案例平铺看不出关系，换个场景照样踩。
- **怎么解决的**：把「根因」升级为一级公民——一个根因一个文件（一句话根因/识别信号/通用对策/挂载案例），检索先命中根因拿通用对策，根因层不够用时再往下翻具体案例找灵感。

## v1.2.0（日期未记录）
- **做了什么**：加「命中计数」——检索命中且真正解决问题才 +1，索引 `🔥N` 与条目 frontmatter `hits` 双写；命中 ≥3 次自动升华进记忆 CORE 铁律区（E:\Zcode-memory\CORE.md）；明确「全处同步」铁律；索引格式由竖线行改为表格。
- **解决了什么**：「能否借鉴」里写的规律有没有真救过场，光看记录看不出来——"这条坑有用"只是感觉不是数字；规则/模板/索引格式升级后各副本不同步会埋雷。
- **怎么解决的**：四个条件同时成立才计命中（发生了检索动作/翻看了具体记录/从中获得启发解决问题/问题真的解决），宁可少记不要虚高；升华时索引标 `⭐` + 文件置 `escalated: true` + 同步写入 CORE 铁律区；任一处升级所有副本必须同时改。
