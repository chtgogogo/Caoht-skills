# 磁盘与缓存纪律（禁止落 C 盘 · 缓存重定向）

> **定位**：这是**环境层**的纪律，管"东西写哪个盘"。
> 与它并列的三件：`编码行为准则`、`测试纪律`、`抗幻觉纪律`。**四件互不重叠。**
>
> **平台适用性**：目录联接（junction）、盘符、码页这些是 **Windows 机制**。体检脚本在非 Windows
> 平台仍然执行能执行的部分（容量、环境变量），凡是依赖 Windows 机制的检查项一律输出
> **「未检查（本平台没有该机制）」**，不假装通过，也不报错退出。
>
> 本机适配：若本技能目录存在 `personal.local.md`，读取它并按其中的值覆盖本文件的默认路径 / 盘符 / 偏好；
> 不存在则按本文件写的通用默认值走——缺这个文件不是错误，不要因此停下来询问。

## 0. 核心（每轮必守）

1. 所有**下载 / 克隆 / 虚拟环境 / 模型权重 / 日志 / 解压产物**，默认写**非系统盘**，
   **严禁**系统盘的用户目录默认路径（`<系统盘>:\Users\<user>\Downloads`、`...\.cache`、`...\AppData\...`）。
2. **「非系统盘是哪一块」不预设盘符**：由配置给出，优先级
   **命令行 > `personal.local.md` > 内置默认（`auto` = 枚举本机在场的所有盘）**。
   没有配置就默认 `auto`，脚本自己去看这台机器上有几块盘，不猜 D 也不猜 E。
3. 在非系统盘建统一目录（命名可自定，关键是**与系统盘不同**）：
   工程 `<数据盘>\AI_Projects`、缓存 `<数据盘>\AI_Cache`。
4. 🔴 **动作分级**：体检（默认）只读，不改一个字节；**删除**只走 `--clean` 且必须
   `--target` 显式点名 + `--apply`；**搬迁**只走 `--migrate` 的七步流程。
   任何"顺手清理一下"都不属于本 skill 的授权范围。

## 一、缓存与环境重定向

| 工具 | 环境变量 | 说明 |
|---|---|---|
| pip | `PIP_CACHE_DIR` | 或 `pip install --cache-dir <非系统盘>` |
| npm / pnpm | `npm_config_cache` / `PNPM_HOME` | pnpm 的真实位置**只认 `pnpm store path` 的实查值**，`PNPM_HOME` 只是提示 |
| HuggingFace | `HF_HOME` | **下载模型前**先设，否则权重直落系统盘 |
| 其它 | — | 任何"默认往用户目录 `.cache` 写"的工具，**先查它的缓存环境变量**，指到非系统盘 |

**原则**：动手前先问"这个工具默认写哪"，而不是装完了才发现系统盘少了 20G。

---

## 二、目录联接（Junction / Symlink 转移术）

遇到**强制写系统盘固定路径**的程序：

1. 停掉占用进程；
2. 把已生成数据移到非系统盘；
3. **删除系统盘原目录（必须已空）**；
4. 管理员执行：
   ```cmd
   mklink /J "C:\原路径" "<非系统盘>\实际路径"
   ```
   `mklink /D` = 符号链接；`mklink /J` = 联接（兼容性更好，**优先用 /J**）。

**效果**：程序以为还在读写系统盘，实际数据已落非系统盘。

🔴 **这一整套手工步骤已被 `--migrate` 收进脚本**（占用核查→复制→校验→让位→建链→跨链写测试→删原实体，
见 §六）。手工做漏掉的是「复制校验」和「回退」，而这两步正是数据丢失的位置。

---

## 三、幂等检测（防重复挪动）⚠️ 最容易出错的一步

迁移 / 建链接**之前**，先检测当前状态：

```cmd
dir <目标路径>                    :: 看是否有 <JUNCTION> / <SYMLINK> 标记
fsutil reparsepoint query <路径>  :: 精确查询是否为重解析点（退出码 0 = 是链接）
```

判定与动作：

| 当前状态 | 动作 |
|---|---|
| 已是链接且指向正确目标 | **立即停止，绝不重复移动 / 建链接** |
| 是实体目录且占空间 | 才执行「移动 + 建链」 |
| 是链接但指向错误位置 | 先删链接（`cmd /c rmdir "路径"`，**不带 `/S`**），再重建 |

🔴 **判链的两把尺子都会骗人**（本机 2026-10-11 实测，脚本内部已按此实现）：

- Python `os.path.islink()` 对 junction **恒为 False**——用它判链等于没判；
  要用重解析点属性（`GetFileAttributesW` 的 `0x400` 位）或 `fsutil reparsepoint query` 的退出码。
- `os.readlink()` 对 junction 回的是设备命名空间形式 `\\?\E:\...`，**不剥掉 `\\?\` 前缀，
  "已是指向正确目标的链接"这一条永远匹配不上**，于是每次重跑都当成实体目录再挪一遍。

## 四、临时文件即时清理

- 任务产生的临时解压、中间产物，**完成后主动清理**。
- 解压安装包后无需保留立即删；不在桌面遗留大文件。
- 🔴 删目录前先判它是不是链接：`shutil.rmtree` / `rm -rf` 会**顺着 junction 钻进真实数据**。

---

## 五、空间预警（逐盘独立判定）

- 大规模写入（几十 GB 模型 / 数据集）**前**，先查剩余空间：
  ```powershell
  Get-PSDrive -PSProvider FileSystem | Select-Object Name,@{n='FreeGB';e={[math]::Round($_.Free/1GB,1)}},@{n='UsedGB';e={[math]::Round($_.Used/1GB,1)}}
  ```
- 🔴 **一块盘不达标就是整体不达标**：判据是「对每一块在场的盘分别比阈值」，
  不是「平均还有空间」，也不是「只看系统盘」。任何被点名但**不在场**的盘输出
  **「未检查」**——静默跳过会让人把"没查"读成"没问题"。
- 目标盘不足 → **立即停、报告用户**，禁止未确认的跨盘写入。

## 六、体检脚本 `scripts/disk_check.py`（v1.2）

三种模式，**默认只读**：

| 模式 | 命令 | 会动文件吗 | 前置条件 |
|---|---|---|---|
| 体检 | `py disk_check.py`（可加 `--scan-user`） | 🔴 不会，一个字节都不改 | 无 |
| 清理 | `py disk_check.py --clean --target <目录>` | 干跑不动；加 `--apply` 才删 | 目标必须在允许根内，且定性为「再生缓存」或在白名单里 |
| 迁移 | `py disk_check.py --migrate --from <系统盘目录> --to <非系统盘目录>` | 干跑不动；加 `--apply` 才搬 | 目标盘非系统盘且为空 |

```bash
# 只体检（不动作）；--json 给机器读
py <技能目录>\scripts\disk_check.py
py <技能目录>\scripts\disk_check.py --scan-user

# 清理：先看计划，再对同一个目标放行（两步都要显式点名）
py <技能目录>\scripts\disk_check.py --clean --target "<数据盘>\AI_Cache\某应用缓存"
py <技能目录>\scripts\disk_check.py --clean --target "<数据盘>\AI_Cache\某应用缓存" --apply

# 迁移：七步全过才算成；中断后用登记文件回退
py <技能目录>\scripts\disk_check.py --migrate --from "C:\Users\<user>\某程序数据" --to "<数据盘>\某程序数据"
py <技能目录>\scripts\disk_check.py --migrate --from ... --to ... --apply
py <技能目录>\scripts\disk_check.py --migrate --rollback --journal "<目标目录>.disk_check_migrate.json"

# 临时改判阈范围（不改配置文件）
py <技能目录>\scripts\disk_check.py --data-drives D,E --threshold 15
```

**脚本查六件事**：① 关键环境变量是否已重定向到非系统盘 ② 系统盘用户目录可疑大缓存（`--scan-user`）
③ 已知路径是否为链接且指向非系统盘 ④ **在场每块盘**的剩余空间是否达阈 ⑤ pnpm 真实 store
（`pnpm store path` 实查，装了才查，没装报「未检查」）⑥ 配置层自身读到了什么。

**配置化（全部四项都能覆盖，内置默认不含任何具体盘符）**：

| 键（`personal.local.md` 里写 `键: 值`） | 命令行开关 | 内置默认 |
|---|---|---|
| `system_drive` | `--system-drive` | 探测 `%SystemDrive%`，探不到才回落 `C:` |
| `data_drives` | `--data-drives` | `auto`（枚举本机在场的所有盘） |
| `free_gb_threshold` | `--threshold` | `15`（GB） |
| `clean_roots` | `--clean-root`（可重复） | 用户目录下的 `AppData\Local`、`AppData\Roaming`、`Temp`、`.cache` |
| `user_suspects` / `max_scan_entries` | — | 空 / `4000`（扫描项上限，超限则判「没看完，按需确认」） |

- 不想让它读个人层：`--no-personal-config`（发布仓的访客没有 `personal.local.md`，行为自动走通用默认）。
- 键名写错会**报警并不采用**，不会静默按默认值跑（防止"我明明配了"）。

**定性判据（`--clean` 用）**：不看目录名，看**树里的构成**。`Cache / Code Cache / GPUCache /
Service Worker / Dawn* / GrShaderCache` 等再生件才算可删；出现 `IndexedDB / Local Storage /
*.sqlite / leveldb / 聊天库 / AI 索引` 这类状态与数据件，或者程序本体（`.exe`、模型权重）
→ **需确认，不删**；系统根、盘根、链接本身、允许根之外 → **直接拒绝**。
同名的坑（`Cache` 目录里装的其实是 Service Worker）就是这条判据存在的理由，见 §八 的 `Roaming/uv` 反例。

**退出码**：体检 `0` 全绿 / `1` 有 FAIL / `2` 只有 WARN；`--clean`、`--migrate` `0` 成功 / `1` 被拦或有失败。

**跨平台降级**：非 Windows 时链接类检查（§三、§六③、`--migrate`）一律输出**「未检查」**并说明机制不存在，
容量与环境变量检查照常执行；不会因为"这不是 Windows"而报错。

> 本机解释器**只用 `py`**——`python` / `python3` 可能指向商店占位件，跑了零输出、退出码 49（全队准则 §8.11）。
> 摘链接在 Windows 上**只准 `cmd /c rmdir`**（不带 `/S`）；在 Git Bash 里执行 `cmd /c` 会被 MSYS
> 翻译参数导致**静默空转**，删/建之后必须独立反查一次（§8.16）。

## 八、C盘体检瘦身标准流程（2026-10-06 实战沉淀）

> 触发：用户说「C盘满了 / 瘦身 / 体检 / 清理」。心法八字：**先量后删、钻层定性**。落点会随软件更新漂移，判据不变——吸纳思路，不背路径。

**1. 体检漏斗（三层钻取，禁止只扫一层就下结论）**
- L1 广度：四大主战场各扫一轮 `du -sh <根>/* | sort -rh | head -20`（用户根、AppData/Local、AppData/Roaming、ProgramData）
- L2 定位：对可疑大目录钻一层
- L3 定性：钻到「能判断是缓存还是数据」那层为止（实例：飞书 1.5G → aha/users → profile_explorer → Service Worker 1.1G 才实锤是缓存）

**2. 定性判据（看构成，不看名字）**

| 构成特征 | 定性 | 处置 |
|---|---|---|
| Cache / Code Cache / GPUCache / Service Worker / Dawn* / GrShaderCache | 再生缓存 | 删 |
| installer.exe / patch / pending（更新器目录**内**） | 旧更新包 | 删，留目录 |
| Temp / CrashDumps / node-gyp / 陈旧 MessageBus 日志 | 垃圾 | 删 |
| logs/ | 流水账 | 删或建道 |
| IndexedDB / Local Storage / Screenshot / *.sqlite 聊天库 / 下载历史 / AI 索引(projects) / tools/ / NGX 模型 / Package Cache | 用户数据或本体 | **禁删** |

⚠️ 反例实录（2026-10-06）：`Roaming/uv` 名字像 uv 缓存，钻层实为**已装工具本体**——名字像≠是，先定性再动手。
🔴 这条反例就是 §六「按构成定性、不按名字定性」的来历；`disk_check.py --clean` 的同名陷阱判据直接实现它。

**3. 占用核查前置**：清理前 tasklist 确认程序已关；浏览器分清 `msedge.exe`（本体，可清缓存）与 `msedgewebview2.exe`（被其他软件复用的内核，不代表 Edge 在跑）。
`--migrate` 把这一步做成了**重命名探针**：目录内有未共享删除的句柄时改名必失败，失败即判被占用，不动一个字节就知道有没有活的读者。

**4. 处置三分类**：A=直接清（上表可删类）；B=建道（持续再生的大缓存/日志→junction 搬非系统盘：幂等检测→关进程→删→mklink /J→跨盘写测试）；C=拍板（用户数据/系统件/拿不准的→列清单+建议交用户，禁擅自删）。

**5. 验证收尾**：df 前后对比；联接写测试；报告落盘**必含勿动清单**（防下次误伤）；记忆/账本留痕。

**6. 常见落点族（举一反三）**：Electron 系=Roaming/<app-id>（logs/Cache）+ Local/<app>-updater（installer.exe 堆积）；Chromium 内核应用=User Data/Default/{Cache 族}；国内聊天/办公软件 patch 目录=补丁包堆积；国内版软件路径常不等于国际版（目录名带 CN 等后缀，用 `find -iname` 实测定位）。
