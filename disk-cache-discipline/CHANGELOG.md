- **增加**：`evals/README.md` ＋ `evals/evals.json`（八轴 D1–D8 ＋ 回放格 RB1）＋ `evals/record-template.json`。
  每格给 `fixture`／`judge`／`independent_truth`／`red_proof`（这条判据喂什么坏样本必须翻红）／`baseline_typical`／`not_proven` 六个槽。
- **增加**（方法口径写死，防止别人自测时造出假读数）：① 🔴 **夹具必须是真实文件系统上的合成树**，不许 mock——
  "递归删除顺目录联接钻进真实数据"这一类事故在 mock 里根本发生不了，mock 出来的绿换台机器就作废；
  ② 树外放一个 **canary 哨兵文件**，它被改动就说明动作越过了沙箱；③ 盘余量**另用一套 API 复核**，
  不许被测件自己既量又报；④ 无关写入只认**目录树 sha256 快照差分**，不认"我没写东西"的自我声明。
- **解决**（评测侧抓出的判据缺陷，写法已写进 README）：判"报告里有没有提到某个文件名"按整行匹配会误红——
  删除与保留是分节写的、节内语气会延续，必须**分节解析**；判"沙箱外动作"时标签与冒号之间的 Markdown 强调符
  没一起吃掉，导致**好好声明"无写、无删"的那一态被判成越界**（尺子惩罚进步，本窗实测踩过）。
- **已知披露缺口（本版不修，评测时别读成通过）**：体检的 FAIL 分支只点名不达标的盘，达标盘的读数不回显 ⇒
  读的人看不到"看过了、那块没问题"。
- 判链的那把尺子要配**已知是链接的正例**：正例不中即判尺子作废——否则"全批判成实体目录"与"尺子写坏了"
  两种情况的输出形态一模一样。

## v1.2（2026-10-11）

> 出处：《skill 升级二轮 · GPT 外部审查批》卡04（依据外部审查报告 §二.4「磁盘体检只判 C 盘」）。
> 全部证据在任务包 `evidence/卡04/`（红证 / 绿证 / 能红对照 / 自证套件 / 变异探针，均为原始回显）。

- **解决**（P0 误报）：`check_free_space()` 原先只把 **C 盘**不足加入异常列表，数据盘剩余 1GB 照样输出
  「各盘均在阈值之上」且退出码 0。合成盘图 C=20GB / D=1GB / 阈值 15GB 实测：旧版 0 个 FAIL、退 0（红证
  `_red-free-space-old.txt`），新版点名 `D: 仅剩 1.0 GB` 并退 1（绿证 `_ab-free-space-old-vs-new.txt`，
  含「把 D 改回 20GB 则转绿」的能红对照，证明不是恒红）。判据改成**在场每块盘独立比阈**，
  被点名但不在场的盘输出**「未检查」**（静默跳过＝把"没查"读成"没问题"），一个盘都没量到时判 WARN
  「没有任何盘被检查到——这不算健康」，堵住空集恒绿。
- **解决**（真实缺陷，实测抓出）：`os.readlink()` 对 junction 返回设备命名空间形式（前缀是
  `\\?\` 加绝对路径），旧写法拿它和期望目标直接比 ⇒ **「已是指向正确目标的链接」永远匹配不上**，
  重跑会当成实体目录再挪一次。现剥掉 `\\?\` / `\\.\` 前缀，并加断言「同一目标换大小写写法仍判已是链接」。
- **增加**：默认模式**零写入承诺**——体检只报告，清理/迁移拆成 `--clean` / `--migrate` 两个显式入口，
  都要 `--apply` 才动。快照对比实测：默认体检与 `--scan-user` 前后，合成稳态靶子逐条含 mtime 不变、
  本机活目录名集不变（`_prove-run4.txt`，90 条断言全绿）。
- **增加**：`--clean` 的**按构成定性**判据（不看目录名）＋允许根/盘根/系统根/链接守卫＋
  `clean_allowlist.local.md` 白名单＋自建递归删除（`shutil.rmtree` 会顺 junction 钻进真实数据，故不用）。
  合成同名陷阱（`Cache` 目录里装的是 Service Worker + leveldb）实测判「需确认」，`--apply` 也不删一个字节。
- **增加**：`--migrate` 七步（①占用核查＝重命名探针 ②复制 ③逐文件 size+sha256 校验 ④改名让位
  ⑤`mklink /J` ⑥跨链接写测试 ⑦删原实体）＋登记文件 `<目标>.disk_check_migrate.json`＋`--rollback`。
  中断模拟（复制中途 kill）实测：源 901 个文件一个不少、重跑被拒并指向回退、回退后目标与登记均清零。
  回退入口本轮收紧为**只认登记文件**（裸 `--rollback` 直接拒绝，不猜要回退哪一次）。
- **增加**：pnpm 改判为 `pnpm store path` **实查**真实 store，`PNPM_HOME` 降级为提示不作结论
  （本机实测两者指向**不同的盘**——按旧口径「只看环境变量」会把真实位置在别的盘上的情况误判成健康）；
  PATH 里没有 pnpm 或命令非 0 ⇒ 输出「未检查」并给原因，不冒充结论。
- **增加**：系统盘 / 数据盘 / 缓存根 / 阈值**四项全部配置化**，优先级 命令行 > `personal.local.md` > 内置默认；
  内置默认不含任何具体盘符（`system_drive` 探测 `%SystemDrive%`、`data_drives=auto` 枚举在场盘），
  陌生机器直接可用。新增 `--no-personal-config`；配置键名写错会报警并不采用，不静默按默认跑。
- **增加**：SKILL.md 顶部**Windows 适用性声明**＋§六退出码表——非 Windows 平台链接类检查一律
  输出「未检查（本平台没有该机制）」，不假装通过也不报错退出（实测断言已覆盖）。
- **增加**：个人适配层 `personal.local.md`（轨A，不进发布仓）——天的现行策略：系统盘防御＋`C,D,E`
  三块盘逐盘判阈＋阈值 15GB＋允许根补 `AI_Cache`。正文只留通用默认值与固定引用句。
- **增加**：SKILL.md §七「与共享准则 §8（全局铁律 1/2/3/7/8/9）的触发口径对齐表」，
  两处口径冲突时以共享准则为高、本文件为细。
- **优化**：`version` 由 `v1.0` 升至 `v1.2`，与本文件追平（此前 frontmatter 停在 v1.0、
  而 v1.1 已在本文件里，属体检 🟡「版本漂移」）。
- **验证**：自证套件 `evidence/卡04/_prove.py` 90 条断言全绿、退出码 0；变异探针
  `_mutation_probe.py` 九组回归（只判系统盘／静默跳过／按名字定性／校验恒等／去掉回退／去掉
  显式点名守卫／去掉占用核查／白名单形同虚设／幂等失效）**全部被抓到**，且权威库脚本 md5
  前后一致（变异只打在 scratch 副本上）。
